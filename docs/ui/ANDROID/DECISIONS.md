# DECISIONS.md

현재 적용 기준은 각 명세에 두고 결정 당시의 이유와 대체 관계는 이 문서에 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다. 기존 ID, 날짜, 당시 상태와 근거를 유지한다.
- 상태와 구현 설명은 원본의 기록 시점을 기준으로 해석한다. 현재 적용 여부나 배포 완료를 과거 기록만으로 단정하지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체하는 결정과 적용 범위를 명시한다.
- 원문에 구분되지 않은 배경, 대안과 영향은 추측해서 보충하지 않는다.

<a id="a-071-웹의-앱-열기-링크를-https-대신-전용-스킴으로-받기"></a>

**A-071. 웹의 앱 열기 링크를 https 대신 전용 스킴으로 받기**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-13 |
| 상태 | 확정 |
| 배경 | 웹 앱 안내 배너([웹 W-033](../WEB/DECISIONS.md#w-033))는 패키지를 명시한 `intent://` 링크로 앱을 연다. 받는 쪽을 autoVerify 없는 `https://manyak.app` 필터로 두면 Android 12 이상에서는 다른 앱의 일반 링크가 그대로 브라우저로 가지만, minSdk 24인 이 앱은 Android 11 이하에서 다른 앱(메일, 메신저 등)의 manyak.app 링크마다 앱 선택창을 띄운다. 그래서 https 링크와 겹치지 않는 전용 스킴 `manyak://manyak.app`만 받고, 웹은 `scheme=manyak`으로 연다. 앱이 없을 때 브라우저가 플레이스토어를 여는 동작은 같다. |
| 채택 | 진입은 새 타입을 만들지 않고 기존 `PushEntry`에 `TYPE_APP_LINK`를 더해 보류, 로그인 뒤 소비, 프로세스 복원 경로를 그대로 쓴다. 특정 회원에게 보낸 링크가 아니라 수신자 비교를 건너뛰고, 경로는 https로 옮겨 푸시와 같은 `DeepLink` 해석을 쓴다. https App Links(autoVerify, `assetlinks.json`)는 KNK-927에서 따로 다룬다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 영향 | 원문에 별도 항목으로 구분하지 않음 |
| 범위 | `MainActivity` intent-filter, `PushEntry`의 앱 열기 진입, 웹 앱 안내 배너의 intent 링크 |
