# DECISIONS.md

현재 적용 기준은 각 명세에 두고 결정 당시의 이유와 대체 관계는 이 문서에 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다. 기존 ID, 날짜, 당시 상태와 근거를 유지한다.
- 상태와 구현 설명은 원본의 기록 시점을 기준으로 해석한다. 현재 적용 여부나 배포 완료를 과거 기록만으로 단정하지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체하는 결정과 적용 범위를 명시한다.
- 원문에 구분되지 않은 배경, 대안과 영향은 추측해서 보충하지 않는다.
- 이 세트의 iOS 결정 ID는 I-030부터 I-059까지 쓴다.

**I-030. 앱 열기 링크는 전용 스킴만 받기**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Accepted |
| 관계 | Android [A-071](../ANDROID/DECISIONS.md#a-071)과 같은 스킴과 경로 해석. 목적지 탭은 [I-043](#i-043) |
| 승인 근거 | KNK-2154 작업 대화에서 사용자가 확정했다 |
| 배경 | iOS 앱이 앱 열기 링크를 받는 방식으로 사용자 정의 URL 스킴과 Universal Links(https 링크를 앱이 받는 Apple 방식)를 검토했다. Android가 https를 받지 않은 이유인 Android 11 이하의 앱 선택창은 iOS에 해당하지 않는다. |
| 채택 | `manyak://manyak.app{경로}`만 앱 진입으로 받는다. 경로 해석 표는 Android와 같고 일반 https 링크는 받지 않는다. |
| 대안 | Universal Links |
| 이유 | Universal Links는 웹의 링크 생성과 함께 정해야 해 후속 결정으로 미뤘다. |
| 영향 | 웹 배너와 앱 소개 링크가 iOS 앱을 여는 연결은 [I-053](#i-053)이 정한다. 하네스 Android 화면 문서는 앱 열기 링크의 목적지를 스토리 상세와 공지로 한정하지만 Android 코드는 `/studio`와 `/my/credits`도 연다. iOS는 하네스 문서를 따르며 차이는 별도 티켓으로 기준 문서를 정리한다. |

**I-032. 프로세스 종료 뒤 선택 탭만 복원**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Accepted |
| 관계 | 복원이 적용되는 실행은 [I-045](#i-045), 보류 진입은 [I-044](#i-044) |
| 승인 근거 | KNK-2154 작업 대화에서 사용자가 확정했다 |
| 배경 | Android는 프로세스가 종료돼도 백스택을 직렬화해 복원한다. iOS에는 자동 복원이 없어 직접 저장해야 하고, 경로 복원 뒤 갱신 오류와 백그라운드 전환 시 경로 초기화의 오래된 보고가 있으며 현재 수정 여부는 확인하지 못했다. |
| 채택 | 선택한 하단 탭만 복원한다. 내비게이션 스택은 복원하지 않고 각 탭의 루트에서 시작한다. |
| 대안 | 백스택 전체 복원 |
| 이유 | 대화에서 별도 이유를 남기지 않았다. 배경의 구현 부담과 미확인 버그 보고가 검토 자료였다. |
| 영향 | 시스템 종료 뒤 하위 화면, 열린 시트와 스크롤 위치는 사라진다. 라우트 값을 저장 형식으로 직렬화하지 않는다. |

**I-033. 탭마다 NavigationStack과 전체 화면 라우트의 탭 바 숨김**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Accepted |
| 관계 | Android [A-011](../ANDROID/DECISIONS.md#a-011)의 셸 위 전체 화면 적재와 다른 배치. 화면별 숨김 범위는 [I-042](#i-042) |
| 승인 근거 | KNK-2154 작업 대화에서 사용자가 확정했다 |
| 배경 | Android는 상세와 퍼널을 탭 셸 위 메인 백스택에 쌓고, 홈이 아닌 탭의 뒤로가기는 홈, 홈에서는 앱 밖으로 나간다. iOS에는 시스템 뒤로가기 버튼이 없고 탭 안에서 화면을 쌓는 것이 기본 관례다. |
| 채택 | 탭마다 `NavigationStack`을 두고 탭 안에서 화면을 쌓는다. 채팅방, 퍼널처럼 전체 화면이 필요한 라우트는 탭 바를 숨긴다. 뒤로가기로 홈 탭, 홈에서 종료하는 규칙은 적용하지 않는다. |
| 대안 | 탭 바 바깥에 `NavigationStack` 하나를 두고 전체 화면을 탭 바 위에 덮는 배치 |
| 이유 | iOS 관례를 따른다. |
| 영향 | 같은 화면도 진입한 탭의 스택에 쌓인다. 외부 진입의 목적지 탭은 [I-043](#i-043)에서 정한다. |

**I-053. 웹 배너와 앱 소개 링크는 전용 스킴으로 iOS 앱을 엶**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Accepted |
| 관계 | [I-030](#i-030)의 후속. 웹 배너의 현재 요구는 [WEB 요구사항](../WEB/2-2-REQUIREMENTS.md) |
| 승인 근거 | KNK-2154 작업 대화에서 사용자가 확정했다 |
| 배경 | I-030은 앱 진입을 전용 스킴만 받기로 정하고 웹 배너와 앱 소개 링크가 iOS 앱을 여는 연결을 남겼다. 웹의 iOS 기기 배너는 외부 브라우저 열기와 홈 화면 추가 안내만 제공한다. |

| 대안 | 첫 출시에서 연결하지 않음<br>Universal Links |
| 이유 | 대화에서 별도 이유를 남기지 않았다. |
| 영향 | iOS 앱은 I-030의 진입 처리 외에 바뀌지 않는다. WEB 세트의 iOS 기기 배너 요구와 구현은 별도 티켓으로 갱신한다. |
