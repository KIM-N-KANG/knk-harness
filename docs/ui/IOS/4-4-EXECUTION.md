### 4-4-1 앱 열기 링크와 푸시 진입

앱 타깃은 URL 스킴 `manyak`를 등록하고 받은 URL을 아래 순서로 처리한다. ([I-030](DECISIONS.md#i-030))

1. 로그인 제공자 SDK의 복귀 URL은 해당 SDK에 넘기고 앱 진입으로 해석하지 않는다.
2. 스킴이 `manyak`이고 호스트가 정확히 `manyak.app`일 때만 앱 열기 진입을 만든다. 그 밖의 URL은 버리며 화면을 바꾸지 않는다.
3. 경로만 `https://manyak.app{경로}`로 옮긴다. 쿼리, 조각, 포트와 사용자 정보는 쓰지 않는다.
4. `ManyakNavigation`의 해석기가 [진입 목적지](3-1-INFORMATION-ARCHITECTURE.md#3-1-2-진입-목적지)의 앱 열기 링크 열로 목적지를 고른다. 해석기는 푸시와 같으며 진입 종류별 허용 목적지만 다르다.

푸시 탭 진입은 알림 응답에서 목적지 URL과 수신자 식별자를 읽어 만든다. 푸시 URL은 `manyak.app`과 `www.manyak.app`의 기본 포트만 허용하고 사용자 정보가 있으면 홈으로 해석한다. iOS 페이로드에서 두 값을 읽는 형식은 미정(서버 선행 변경 필요)이다. ([NOTIFICATION 푸시 데이터](../../spec/NOTIFICATION/BACKEND/4-2-CONTRACT.md#4-2-10-푸시-데이터))

| 단계 | 처리 |
|---|---|
| 받기 | 실행 중과 냉시작 모두 같은 진입 값으로 만들어 앱 수준 보류 칸 하나에 둠. 소비 전 새 진입이 이전 값을 대체 |
| 보관 | 메모리에만 둠. 프로세스 종료와 세션 종료에서 폐기 |
| 소비 조건 | 회원 세션, 필수 동의 완료, 프로필 도착, 메인 셸 표시. 신규 가입 온보딩 동안은 대기 |
| 수신자 비교 | 푸시만. 현재 회원 식별자와 다르면 목적지를 홈으로 바꿈 |
| 이동 | 열린 시트, 알림창과 전체 화면 덮개를 닫은 뒤 목적지의 탭을 선택하고 그 탭의 스택을 루트부터 다시 구성. 제작 목적지는 제작 목록 새로고침 요청 |
| 완료 | 보류 칸을 비움. 같은 진입을 다시 소비하지 않음 |

기능 화면은 이동 요청만 보내고 탭 선택과 스택은 앱 타깃의 라우터가 바꾼다. 화면의 Store(`MviStore`)는 직접 이동하지 않고 Effect만 낸다.

### 4-4-2 탭 셸과 복원

| 상태 | 관리 위치와 수명 |
|---|---|
| 선택 탭 | 라우터. 시스템 종료 뒤에는 남고 사용자가 앱 전환기에서 닫으면 지워지는 장면 단위 상태(scene storage)에 저장. UserDefaults에 저장하지 않음 |
| 탭별 스택 | 라우터가 탭마다 라우트 값 배열로 관리. 프로세스 종료 뒤 복원하지 않으므로 라우트를 저장 형식으로 직렬화하지 않음 |
| 탭 바 표시 | 각 라우트가 [하단 탭 표시](3-1-INFORMATION-ARCHITECTURE.md#3-1-1-루트와-셸) 분류를 가짐. 화면마다 따로 판정하지 않음 |
| 루트 화면 | 세션 상태와 동의 결과로 고름. 루트가 바뀌면 탭 스택과 선택 탭을 초기값(홈)으로 되돌림 |

복원한 선택 탭은 저장 세션의 동의 확인이 끝나 메인 셸이 처음 나타날 때 한 번 적용한다. 같은 실행에서 외부 진입이 소비되면 진입 목적지의 탭이 우선한다.

### 4-4-3 테마와 토스트

테마 선택 값은 `ManyakCommon`의 기기 귀속 저장소에 두고 회원 정리 대상에 넣지 않는다. 앱은 첫 화면을 그리기 전에 값을 읽어 앱 창 전체에 적용하며 시트, 알림창, 전체 화면 덮개와 토스트 층도 같은 값을 받는다.

토스트 층은 앱 타깃이 앱 창보다 위의 별도 표시 층으로 관리한다. 표시 요청은 문구와 표시 길이만 받으며 새 요청은 진행 중 토스트의 타이머를 취소하고 바로 바꾼다. 표시할 때 VoiceOver 알림을 한 번 보낸다. Store는 토스트를 Effect로만 내고 표시 층에 직접 접근하지 않는다.
