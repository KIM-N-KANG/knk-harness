## 3-1-1. 문서 목적·범위와 관련 문서

웹·Android 공통의 사용자 동작·입력·상태·오류·데이터 보존과 수용 기준을 정의합니다. 화면·흐름의 규칙과 상태 표가 수용 기준이며 US·FE-SCREEN·FLOW 식별자를 유지합니다.

- 플랫폼 차이: [웹 Spec](3-2-web-spec.md)·[Android Spec](3-3-android-spec.md). 내부 구조·표현 값은 각 Design, 선택 이유는 [공통 ADR](../adr/1-1-client-adr.md)을 따릅니다.
- API 형식·서버 정책은 [백엔드](4-backend-server-spec.md), 이벤트·식별자는 [분석](6-analytics.md), 용어는 [용어집](0-glossary.md)이 정본입니다. 아래 API 경로는 `/api/v1`을 생략합니다.

## 3-1-2. 공통 계약과 플랫폼 경계

회원의 스토리·채팅 목록은 서버가 소유합니다. 생성·삭제 후 화면은 서버 결과와 일치해야 합니다. 익명 체험·브라우저 저장·회원 이관은 웹 전용이며 [웹 사용자 모델](../domain/ACCOUNT/CLIENT/WEB/2-2-REQUIREMENTS.md#2-2-1-게스트와-회원)이 소유합니다. Android는 로그인 후 서비스에 진입합니다.

**오버레이와 뒤로가기.** 바텀 시트, 다이얼로그, 전체 화면 오버레이(이미지 뷰어, 첫 진입 안내, 실시간 이미지 안내)는 기기·브라우저 뒤로가기로 화면을 떠나지 않고 자기만 닫힙니다. 겹쳐 있으면 맨 위부터 하나씩 닫힙니다. 삭제·제출이 진행 중이라 닫을 수 없는 동안은 뒤로가기를 무시합니다. 뒤로가기에 다른 의미를 주는 오버레이(가입 동의 시트의 가입 취소, 게스트 동의 시트의 대기 동작 취소)는 각 절의 계약을 따릅니다. 드롭다운·팝오버·셀렉트는 대상이 아닙니다. 웹의 히스토리 처리는 [웹 화면 전환 규칙](3-2-web-spec.md#화면-전환-규칙)을 따릅니다.

스토리 생성 요청의 복구 식별자, 채팅의 턴·스트림 의미, 서버 정책 수치의 표시, 신고·계정·법적 문서 계약은 공통입니다. URL, 브라우저 이력, SDK, 저장 기술, 모듈·스코프는 이 문서에서 정하지 않습니다.

### FE-SCREEN-011. 서비스 안내

**목적** — AI 콘텐츠 특성·문의·정책 정보를 안내하고 약관·개인정보 처리방침의 상시 열람 경로를 제공합니다. 마이의 기타 섹션에서 피드백 위에 서비스 안내를 둡니다.

**콘텐츠 규칙** — 서비스 안내에는 이프 적립·소모 수치를 복제하지 않습니다. 필요한 화면에서 서버 정책값을 표시합니다. 게스트 이용 안내는 웹에만 적용하고, 그 체험 한도는 서버 정책과 일치해야 합니다. 약관·개인정보 처리방침을 요약할 수 있지만 서로 상충해서는 안 됩니다.

웹 게스트 안내 문구는 다음과 같습니다.

- 로그인 없이도 스토리를 둘러볼 수 있어요. 게스트 이용 안내에 동의하면 체험 한도 안에서 스토리를 만들고 채팅할 수 있어요. 한도를 모두 사용하면 로그인이 필요해요.
- 게스트로 만든 스토리와 채팅은 이 브라우저에 연결돼요. 브라우저 데이터를 지우거나 기기를 바꾸면 다시 불러오기 어려울 수 있어요.
- 처음 로그인한 뒤 회원 필수 동의를 마치면 이 브라우저의 스토리와 채팅을 계정으로 옮겨요. 이관은 계정마다 한 번만 제공해요.

Android 앱도 같은 본문을 보여 주므로 게스트 이용 안내 제목 아래에 "웹 브라우저에서 이용할 때만 적용돼요"를 표시합니다. 문의 섹션은 피드백 화면으로 연결하지 않고 위치만 "서비스 개선 의견은 마이 > 피드백에서 보내주세요."로 안내합니다.

## 3-1-7. API 연동·에러 처리 계약

API 상세 명세는 [백엔드](4-backend-server-spec.md)가 소유합니다. 여기서는 호출 시점과 응답별 사용자 처리를 정합니다. 인증 정보 전달과 호출 창구는 [웹 설계](../design/1-1-web-design.md#1-1-3-bff-프록시토큰-세션)·[Android 설계](../design/1-2-android-design.md#1-2-5-인증과-세션)가 소유합니다.

### 요청 헤더

논리 `device_id`·`session_id`의 의미는 [분석](6-analytics.md#6-2-식별자-정책)이 정본입니다. 플랫폼은 같은 의미의 값을 API 헤더와 분석 SDK에 사용합니다. 초기화·필수 헤더·누락 처리의 플랫폼별 보장은 해당 설계에서 정합니다.

| 헤더                  | 값                     |
| --------------------- | ---------------------- |
| `X-Manyak-Device-Id`  | 논리 `device_id`       |
| `X-Manyak-Session-Id` | 논리 `session_id`      |

두 헤더가 없어도 일반 요청은 거부되지 않습니다(백엔드가 `unknown`으로 채움). 단 **`X-Manyak-Device-Id`가 정책상 필수인 경로**가 있습니다 — 게스트 체험 한도 대상 요청(누락 시 400 — [`4-backend-server-spec.md §4-3-7`](4-backend-server-spec.md)), 첫 로그인의 회원 체험 시드([`4-backend-server-spec.md §4-3-5`](4-backend-server-spec.md)). `X-Manyak-Session-Id`는 모든 경로에서 best-effort입니다.

**요청 식별자** — `X-Manyak-Request-Id`는 백엔드가 생성·응답하는 상관관계 값이며 클라이언트가 만들지 않습니다. 제작 본문의 `requestId`는 멱등·복구용 별개 값입니다.

| 요청 필드 | 전달 기준 |
| --- | --- |
| 채팅 `userSource` | `choice`·`edited_choice`·`typed`. 아래 판정 사용, 허용값 밖은 400 |
| 채팅 `sourceTurnId`·`choiceOrder` | 직전 턴 `turns[].id`와 선택지 인덱스 + 1. 시작 추천·직접 입력에는 보내지 않음. 선택 필드이며 낡거나 범위 밖이면 서버가 연결 기록만 생략 |
| 스토리라인 `parentCreationId` | 최초 `null`, 재생성은 바로 직전 스토리라인 요청 UUID(`trace_creation_id`). `simpleCreationId`·`analytics_creation_id`와 구분. 서버 검증 불일치는 부모 연결만 생략 |

서버 전달 형식은 [백엔드](4-backend-server-spec.md), 분석 식별자 의미는 [분석](6-analytics.md#6-2-식별자-정책)을 따릅니다.

**입력 출처 판정** — 아래 규칙을 따릅니다. 플랫폼별 판정 함수와 QA 연결은 각 설계·QA가 소유합니다.

- 선택지 본문 탭과 무작위 추천 전송(Play 버튼)은 대조 없이 `choice`입니다. 두 경로 모두 전송 전에 사용자가 문장에 손댈 기회가 없습니다.
- "채우기"로 입력창에 넣고 보내는 경로는 전송 시점의 텍스트를 채운 원문과 대조해 가릅니다 — 같으면 `choice`, 다르면 `edited_choice`입니다. 앞뒤 공백 차이는 같은 것으로 보고, **블럭 모드에서 채우면 블럭으로 파싱했다가 다시 직렬화되어 문자열이 달라지므로 그 왕복 결과도 "그대로"로 인정합니다** — 사용자가 손대지 않았는데 `edited_choice`가 되면 선호 신호가 오염됩니다.
- 채운 뒤 모두 지우고 새로 써도 `edited_choice`입니다.
- 채우기를 쓴 적이 없으면 `typed`입니다. 기억해 둔 원문은 전송에 성공하면 비워, 다음 턴 입력이 앞 턴에서 채운 선택지와 대조되지 않게 합니다.

### 화면별 API 사용

호출·성공·실패 처리는 [화면별 계약](#3-1-3-화면별-스펙), [제작](../domain/STORY/CLIENT/2-2-REQUIREMENTS.md#2-2-4-간편-제작-입력), [채팅](../domain/CHAT/CLIENT/AGENTS.md)을 따릅니다. 인증 판정은 플랫폼 세션이 소유하며 `GET /auth/me`는 회원 정보·잔액 조회에 사용합니다.

- 삭제 API의 204는 완료 안내, 404는 무음 성공으로 목록에 반영합니다. 다른 실패는 낙관적 제거를 되돌리고 안내합니다.
- 로그아웃과 탈퇴의 정리 경계는 [ACCOUNT 세션 종료](../domain/ACCOUNT/CLIENT/3-2-INTERACTION-FLOWS.md#3-2-4-로그아웃과-탈퇴)를 따릅니다.
- 수정 API의 403은 "수정 권한이 없어요" 안내 후 상세로 복귀합니다.
- 출석·초대는 `POST /users/me/credits/attendance`, `GET /users/me/invite`, `POST /users/me/invite/redeem`을 사용합니다. 잔액·출석 여부는 `GET /auth/me`의 `creditBalance`·`attendedToday`로 표시합니다.

### 이프 정책 수치 표시

PAYMENT 내용은 도메인 문서에서 관리한다. ([정책과 비용](../domain/PAYMENT/CLIENT/2-2-REQUIREMENTS.md#2-2-2-잔액과-비용))

### 날짜 표시 기준

서버 시각(`createdAt`·`expiresAt`·`updatedAt`)은 ISO 8601 UTC입니다. 이프 내역 발생일·만료일, 스토리 상세·제작 카드의 절대 날짜는 `Asia/Seoul`로 변환한 `YYYY-MM-DD`를 표시합니다. UTC 문자열 앞 10자를 자르거나 기기 시간대를 사용하지 않습니다.

채팅 목록의 상대 시간·오늘·어제는 기기 시간대를 사용합니다. 웹 제작 카드의 당일 상대 시간 예외는 [웹 제작 계약](../domain/STORY/CLIENT/WEB/AGENTS.md)을 따릅니다.

### 응답·에러 처리 정책

- 정상 조회 결과가 비어 있을 때만 빈 상태를 표시합니다. 첫 조회 실패는 오류·재시도, 추가 조회 실패는 기존 목록을 유지한 재시도로 처리합니다.
- 백엔드 에러는 `ApiErrorResponse {timestamp, status, code, message, path, details[]}` 형태이며 `details`는 `{field, message}[]`입니다.
- 읽기 재시도·화면 복귀 재조회는 플랫폼 Design을 따릅니다. [웹 TanStack Query 기본 옵션](../design/1-1-web-design.md#데이터-패칭-기본-옵션-웹)을 공통 플랫폼 계약으로 적용하지 않습니다.
- 서버 원본 메시지·스택은 사용자에게 그대로 노출하지 않습니다. 회원의 인증 실패는 플랫폼의 재발급·세션 종료 절차를 거치며 화면마다 별도 세션 판정을 만들지 않습니다.

### 화면 상태 처리 (로딩·빈·에러)

화면별 상태는 각 화면 스펙([§3-1-3](#3-1-3-화면별-스펙))에 정의하며, 공통 규칙은 다음과 같습니다.

| 상황                 | 처리                                                                                |
| -------------------- | ----------------------------------------------------------------------------------- |
| 목록·상세 최초 로딩  | 지연 로딩(빠른 응답 시 스켈레톤 깜빡임 방지). 지연 전에는 아무것도 표시하지 않음    |
| 버튼 클릭 후 요청 중 | 버튼 비활성화 + 기존 문구 공간을 유지한 중앙 스피너. 버튼의 접근 가능한 이름은 유지 |
| 목록 조회 실패       | 재시도 가능한 에러 안내                                                             |
| 뮤테이션 실패        | 실패 토스트                                                                         |
| 라우트·렌더 오류     | "문제가 발생했어요" + 재시도(루트 오류는 Sentry 보고)                               |
| 존재하지 않는 경로   | "페이지를 찾을 수 없어요" + 홈 링크                                                 |
