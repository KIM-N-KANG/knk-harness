## 3-1-1. 문서 목적·범위와 관련 문서

웹·Android 공통의 사용자 동작·입력·상태·오류·데이터 보존과 수용 기준을 정의합니다. 화면·흐름의 규칙과 상태 표가 수용 기준이며 US·FE-SCREEN·FLOW 식별자를 유지합니다.

- 플랫폼 차이: [웹 Spec](3-2-web-spec.md)·[Android Spec](3-3-android-spec.md). 내부 구조·표현 값은 각 Design, 선택 이유는 [공통 ADR](../adr/1-1-client-adr.md)을 따릅니다.
- API 형식·서버 정책은 [백엔드](4-backend-server-spec.md), 이벤트·식별자는 [분석](6-analytics.md), 용어는 [용어집](0-glossary.md)이 정본입니다. 아래 API 경로는 `/api/v1`을 생략합니다.

## 3-1-2. 공통 계약과 플랫폼 경계

회원의 스토리·채팅 목록은 서버가 소유합니다. 생성·삭제 후 화면은 서버 결과와 일치해야 합니다. 익명 체험·브라우저 저장·회원 이관은 웹 전용이며 [웹 사용자 모델](../domain/ACCOUNT/CLIENT/WEB/2-2-REQUIREMENTS.md#2-2-1-게스트와-회원)이 소유합니다. Android는 로그인 후 서비스에 진입합니다.

**오버레이와 뒤로가기.** 바텀 시트, 다이얼로그, 전체 화면 오버레이(이미지 뷰어, 첫 진입 안내, 실시간 이미지 안내)는 기기·브라우저 뒤로가기로 화면을 떠나지 않고 자기만 닫힙니다. 겹쳐 있으면 맨 위부터 하나씩 닫힙니다. 삭제·제출이 진행 중이라 닫을 수 없는 동안은 뒤로가기를 무시합니다. 뒤로가기에 다른 의미를 주는 오버레이(가입 동의 시트의 가입 취소, 게스트 동의 시트의 대기 동작 취소)는 각 절의 계약을 따릅니다. 드롭다운·팝오버·셀렉트는 대상이 아닙니다. 웹의 히스토리 처리는 [웹 화면 전환 규칙](3-2-web-spec.md#화면-전환-규칙)을 따릅니다.

스토리 생성 요청의 복구 식별자, 채팅의 턴·스트림 의미, 서버 정책 수치의 표시, 신고·계정·법적 문서 계약은 공통입니다. URL, 브라우저 이력, SDK, 저장 기술, 모듈·스코프는 이 문서에서 정하지 않습니다.

### FE-SCREEN-001. 홈 — 공개 스토리 목록

| 항목     | 값                                      |
| -------- | ---------------------------------------------- |
| 관련 API | `GET /stories?filter=&sort=&cursor=`           |
| 관련 US  | US-2-2, US-2-7·2-8             |

**목적** — 발행·공개된 스토리를 필터·정렬해 탐색하고 상세로 진입합니다. 내가 만든 스토리 관리와 제작 진입은 FE-SCREEN-013 제작 탭이 담당합니다.

**진입 조건** — 인증 정책을 충족하면 홈을 기본 화면으로 엽니다. 진입 정책은 각 플랫폼 스펙이 소유합니다.

**화면 구성** — 섹션 제목 없이 필터·정렬 줄과 2열 카드 그리드를 둡니다. 필터·정렬 줄은 목록 맨 위에 두고 스크롤하면 헤더 바로 아래에 붙어 있습니다. 목록을 아래로 스크롤하면 위로 밀려 숨고, 위로 스크롤하거나 목록 맨 위 근처로 돌아오면 다시 내려옵니다. 숨고 나타날 때 목록 위치는 바뀌지 않습니다. 당겨서 새로고침할 때 필터·정렬 줄은 제자리에 있고, 표시자는 줄 아래에 나타나며 목록만 내려갑니다. 왼쪽에 "전체"·"오리지널" 알약형 필터 칩(일반 제작 시작 상황 선택 칩과 같은 모양, 단일 선택, 선택 칩은 primary 채움, 선택된 칩을 다시 눌러도 해제하지 않음, 폭이 모자라면 칩 영역만 좌우 스크롤), 오른쪽 끝에 위치가 고정된 현재 정렬 이름과 펼침 아이콘을 보인 정렬 드롭다운("인기순"·"최신순"·"좋아요순"·"채팅순", 선택 항목에 체크, 고르면 닫힘)을 둡니다. 카드에는 `thumbnailUrlSm`(없으면 기본 심벌), 누적 턴 수(축약 표기), 제목과 제작자 각 1줄을 표시합니다. 좋아요 수는 표시하지 않습니다. 제작자는 `author.nickname` 앞에 `@`를 붙이고 같은 행의 카드 높이와 제작자 줄을 맞춥니다. 카드 탭은 상세로 이동합니다. 내 스토리·제작 CTA·진행 카드는 표시하지 않습니다.

**필터·정렬** — 칩과 드롭다운 값은 `filter`(`all` 전체, `original` 오리지널)·`sort`(`popular` 인기순, `latest` 최신순, `likes` 좋아요순, `chats` 채팅순)에 그대로 대응합니다. 진입 기본값은 서버 기본값과 같은 전체·인기순입니다([C-009](../adr/1-1-client-adr.md#c-009)). 선택을 바꾸면 첫 페이지부터 다시 조회하고, 선택 유지 방식은 플랫폼 스펙이 소유합니다. 클라이언트는 인기 점수를 계산하거나 서버 가중치에 의존하지 않습니다.

**ORIGINAL 태그** — 목록 응답의 `isOriginal`이 참인 카드에만 선택한 필터와 무관하게 표시합니다. 반투명·블러 등 표현 값은 [웹 표현](../design/1-1-web-design.md#웹-표현-값)을 따릅니다.

**카드 옵션** — 홈 카드에는 옵션 버튼을 표시하지 않습니다. 신고는 스토리 상세에서 합니다.

**데이터 소스** — 인증 없이 `GET /stories`를 커서 페이지네이션으로 조회하며 게스트·회원 모두 서버 순서를 그대로 유지합니다. 목록 끝에 닿으면 응답의 `nextCursor`를 같은 `filter`·`sort`와 함께 넘겨 다음 페이지를 이어 붙이고, 페이지 사이에 순위가 바뀌어 이미 받은 스토리가 다시 오면 뒤의 것을 뺍니다. 다음 페이지 실패는 목록 끝의 다시 시도로 복구합니다. `GET /stories/originals`는 폐기 예정이라 홈에서 쓰지 않습니다.

### FE-SCREEN-013. 제작 — 내 스토리 목록

| 항목     | 값                                      |
| -------- | -------------------------------------------------------------------------- |
| 관련 API | `POST /stories/batch`(게스트), `GET /users/me/stories`(회원), `GET /stories/submissions`·`DELETE /stories/submissions/{submissionId}`(회원 검수 제출본) |
| 관련 US  | US-2-1·2-3·2-4·2-6·2-8                                     |

**목적** — 내가 만든 스토리를 확인·관리하고 새 제작 또는 진행 중 제작을 이어갑니다.

**진입 조건** — 하단 제작 탭에서 진입합니다. 제작·편집 화면의 진입 경로는 각 플랫폼 스펙이 소유합니다.

**화면 구성** — 제작 헤더 아래에 별도 섹션 제목 없이 내 스토리 가로 카드 목록과 제작 진행 상태를 표시합니다. 초안·완성 요청의 계약은 §3-1-4가 소유합니다. 완성 스토리가 있으면 새 제작 FAB를, 빈 상태에서는 제작 CTA를 표시합니다. 플랫폼별 진행 카드·배너의 적용 범위는 플랫폼 스펙을 따릅니다.

내 스토리 카드는 전체 폭을 사용하며 패딩 영역까지 탭할 수 있습니다. 표지(없으면 기본 심벌), 제목·소개 최대 2줄, 장르 1줄(초과 `+N`), 공개 범위(`visibility`, "공개"·"비공개")·제작일 순으로 표시합니다. 좋아요 수·누적 턴 수(축약 표기, 누락 값은 0)는 표지 우하단 배지로 왼쪽부터 나란히 오버레이하며, 공개 범위가 없으면 그 항목만 생략합니다. 제작일은 오늘(기기 시간대) 만든 스토리면 "방금 전"(1분 미만)·"N분 전"·"N시간 전"으로, 그 밖에는 KST `YYYY-MM-DD`로 씁니다. 좋아요 수와 누적 턴 수는 목록 카드와 상세 히어로 모두 1,000 미만은 그대로, 이상은 `1K`·`1.2K`·`12.3K`·`1.2M`처럼 소수 첫째 자리까지 버림해 축약합니다. 스켈레톤도 같은 구성을 사용합니다. 좁은 화면·큰 숫자에서는 지표 단위로 줄바꿈해 잘림을 막습니다. 픽셀·호버·아이콘 배치는 [웹 표현](../design/1-1-web-design.md#웹-표현-값)을 따릅니다.

**데이터 소스** — 회원은 `GET /users/me/stories`의 서버 목록을 사용합니다. 익명 체험 목록은 [웹 스펙](../domain/ACCOUNT/CLIENT/WEB/2-2-REQUIREMENTS.md#2-2-1-게스트와-회원)이 소유합니다.

**검수 제출본 카드** — 회원은 `GET /stories/submissions`로 아직 스토리가 없는 일반 제작 신규 등록 제출본(검토 중·반려·실패)을 받아 초안·완성 중 카드와 함께 내 스토리 목록 위에 최신순으로 둡니다. 수정(UPDATE) 제출본은 수정 화면과 함께 다루므로 두지 않습니다. 카드는 초안 카드와 같은 틀(표지·제목·설명·등록을 요청한 KST 시각)에 상태 배지를 붙입니다. 목록 조회가 실패하면 제출본 카드만 두지 않고 내 스토리 목록은 그대로 보입니다.

**썸네일 이미지 뷰어** — 썸네일을 누르면 전체 화면으로 엽니다. 닫기 제어·이미지 밖 배경 탭·뒤로가기로 닫으며, 이미지 자체를 탭해서는 닫지 않습니다. 이미지를 두 번 탭하면 누른 지점을 기준으로 2.5배 확대하고 다시 두 번 탭하면 원래 크기로 돌아오며, 두 손가락으로 1~5배 확대하고 확대 중에는 끌어서 이동합니다. 이동은 이미지가 화면 밖으로 빠져나가지 않는 범위로 제한하고, 뷰어를 닫으면 확대 상태를 초기화합니다. 뒤로가기는 상세 화면을 떠나지 않고 뷰어만 닫아야 합니다. 이미지가 없으면 뷰어를 열지 않습니다.

**페르소나 선택** — 채팅 시작 상황 절의 첫 항목입니다. 소제목 "페르소나" 옆 정보 버튼은 "선택한 페르소나가 되어 스토리를 진행해요. 채팅을 시작하면 바꿀 수 없어요" 안내를 표시합니다.

- Select 목록은 위에서부터 "기본"(기본 주인공), 내 페르소나 이름(`GET /users/me/personas` 응답 순서), 왼쪽에 더하기 아이콘이 있는 "페르소나 생성하기"입니다. 기본값은 기본 주인공이며 이름 없이 "기본"으로만 표시합니다(상세 응답에 기본 주인공 이름이 없음).
- 게스트는 페르소나 목록을 조회하지 않고 기본 주인공만 표시합니다.
- "페르소나 생성하기"는 선택값이 아니라 동작 항목이라 눌러도 선택이 바뀌지 않습니다. 회원은 [페르소나 생성](../domain/ACCOUNT/CLIENT/3-3-LAYOUT.md#3-3-3-페르소나-생성과-수정) 화면으로 이동하며, 내 페르소나가 이미 10개면 이동하지 않고 "페르소나는 10개까지 만들 수 있어요" 토스트를 띄웁니다. 게스트에게는 상세 위에 로그인 필요 시트를 엽니다.
- 이 상세에서 "페르소나 생성하기"로 페르소나를 만들고 돌아오면 새 페르소나가 선택되어 있습니다. 직접 다른 주인공을 고르거나 채팅을 시작하면 이 미리 선택은 사라지고, 앱을 새로 불러와도 남지 않습니다.
- 채팅을 시작할 때 기본 주인공이면 `personaId`를 생략하거나 null로 보내고, 페르소나면 그 `id`를 보냅니다.
- 하단 CTA는 "새 채팅 시작하기"를 14px로 두고 그 아래에 11px, 버튼 글자보다 옅은 색 한 줄로 "{페르소나} 페르소나 · {시작 상황 이름}"을 표시해 무엇으로 시작하는지 보여 줍니다. 페르소나 자리는 고른 페르소나 이름이고 기본 주인공이면 "기본"입니다. 페르소나 이름은 5자, 시작 상황 이름은 10자까지만 보이고 넘치면 각각 말줄임표를 붙이며, 시작 상황이 없으면 페르소나 부분만 표시합니다. 버튼 높이는 그대로 둡니다.
- 문구 정본은 웹 `start-setting-copy.ts`와 `toast-message.ts`입니다.

**스토리 좋아요** — 상세 하단 채팅 시작 CTA 왼쪽의 하트 버튼으로 등록·취소하고, 내 스토리 카드와 상세 썸네일의 좋아요 수 배지로 반응 수를 확인합니다.

- 내가 만든 스토리에는 버튼을 표시하지 않습니다. 회원은 상세 `isOwner`, 게스트는 기기의 제작 스토리 ID로 판별하며 내 스토리로 판별된 때만 숨깁니다. 판별이나 개인화 조회가 끝나기 전에는 버튼을 잠근 채 미리 표시해, 하트가 뒤늦게 나타나며 채팅 시작 CTA 폭이 바뀌지 않게 합니다. 좋아요 수 배지는 소유·로그인·썸네일 유무와 무관하게 표시합니다.
- 기본은 아웃라인 하트, `isLiked`면 빨간 채운 하트입니다. 버튼과 CTA 사이는 16px입니다.
- 회원은 `POST`·`DELETE /stories/{storyId}/like`로 등록·취소합니다. 웹은 응답 전에 버튼 상태와 상세 수를 낙관적으로 반영하고, 204 뒤 상세와 목록 집계를 다시 조회합니다. 요청 중에는 버튼을 비활성화하고, 실패하면 요청 전 상태와 수로 복원한 뒤 실패 토스트를 표시합니다.
- 게스트가 누르면 API를 호출하지 않고 상세 위에 로그인 필요 시트를 엽니다. 로그인 후 해당 상세로 돌아오며, 시트를 닫으면 상세에 머뭅니다.
- 문구 정본은 웹 `story-like.ts`(버튼 "좋아요"·"좋아요 취소", 배지 접근성 이름 "좋아요 수")와 `toast-message.ts`(실패 토스트)입니다.

**스토리 신고** — 상세·채팅·제작 목록·채팅 목록에서 같은 스토리 신고 시트를 엽니다. 채팅에서도 대상은 참조 `storyId`입니다. 회원에게만 제공하며, 참조 스토리가 삭제되어 제목이 없는 채팅에는 표시하지 않습니다. 진입점 배치는 플랫폼 스펙을 따릅니다.

| `worldSetting` | `세계관` | 세계관 | 필수, 5,000자(클라이언트 전용 상한) |
| `ruleSetting` | `전개 규칙` | 전개 방식 | 필수, 1,000자(클라이언트 전용 상한) |
| | `분량 배분` | 분량 배분 | 슬라이더 `묘사 N : 대사 M`(N 1~9, M = 10 − N, 기본 5 : 5) |

- 수정 폼에서는 두 글을 위 절 제목으로 나눠 칸을 채웁니다. 제목은 정해진 순서로 나올 때만 칸을 나누고, 그 밖의 제목 줄(간편 제작 글의 `# 전제`·`# 갈등`·`# 문체 톤` 등)은 앞 칸의 본문으로 두어 다시 저장해도 내용이 사라지지 않습니다. 절 제목이 없는 글은 칸에 통째로 넣고, 분량 배분을 읽지 못하면 5 : 5로 둡니다. 빈 칸은 등록 시 절 제목째 뺍니다.
- 시작 상황 설정 탭은 시작 상황 1개로 시작합니다. 탭 위의 선택 칩 줄(가로 스크롤, 알약 모서리 칩이며 선택한 칩은 프라이머리 배경에 온 프라이머리 라벨, 입력과 함께 스크롤)로 시작 상황을 하나씩 골라 입력하고, "추가" 칩으로 3개까지 늘리고, 3개가 되면 "추가" 칩을 남겨 둔 채 비활성화합니다(주변 인물·엔딩 추가 버튼과 같음). 칩 라벨은 상황 이름이 비어 있으면 "시작 상황 N", 입력하면 앞뒤 공백을 뺀 이름이며 8자를 넘으면 8자 뒤에 줄임표를 붙입니다. 첫 번째를 뺀 칩에는 칩 안 오른쪽에 닫기(x) 버튼을 두어 그 시작 상황을 지우고, 선택 중인 것을 지우면 바로 앞 시작 상황을 고릅니다. 첫 번째 시작 상황은 지울 수 없습니다. 추천 입력 예시는 상황(`*…*`)과 대사를 한 줄로 이어 씁니다. 엔딩은 선택이며 "엔딩 추가"로 시작 상황당 3개까지 넣고(주변 인물 목록처럼 엔딩마다 이름·`N/3`·접기·삭제가 있는 회색 머리 줄 아래에 입력), 최소 턴 수는 빈 칸으로 시작하고 숫자만 받아 50을 넘지 않게 자릅니다.
- 주요 사건 탭은 사건 0개로 시작합니다. 탭 위에 주요 사건 안내를 두고, "사건 추가"로 10개까지 늘리며 10개가 되면 버튼을 남겨 둔 채 비활성화합니다. 사건마다 주변 인물 목록과 같은 회색 머리 줄(이름이 비어 있으면 "주요 사건 N", `N/10`, 접기, 삭제) 아래에 사건 이름(≤ 100자)·사건 설명(≤ 1,000자)·키 문장(≤ 200자)을 받고 세 칸 모두 필수입니다. 사건을 추가하면 새 사건 이름 칸이 보이도록 스크롤하되 초점을 옮기지 않습니다.
- 등록 탭의 장르는 간편 제작과 같은 [장르 검색과 선택](#장르-검색과-선택)을 쓰되 최대 8개까지 고릅니다. 고른 순서대로 `genres`에 담아 첫 번째 장르가 기본 커버 연결의 기준이 됩니다. 주요 내용은 선택 입력(≤ 1,000자)이고, 공개 범위는 "공개" 스위치 하나로 받고(기본 꺼짐, 끄면 비공개), 라벨 아래에 켰을 때의 설명을 둡니다. 등록 탭 맨 아래에는 금지 표현과 이미지가 제재될 수 있다는 안내(경고 아이콘이 붙은 회색 상자)를 둡니다.
- 화면 하단에는 간편 제작처럼 단계 버튼을 둡니다. 스토리 프로필 탭은 "다음" 하나, 등록 탭은 왼쪽 "이전"·오른쪽 "등록하기", 나머지 탭은 "이전"·"다음"입니다. 이전·다음은 앞뒤 탭으로 옮기며 탭을 누른 것과 같이 새 탭을 탭 줄 가운데로 스크롤하고 입력 영역을 맨 위로 올립니다. 가상 키보드가 열리면 하단 버튼을 숨깁니다. 등록하기는 늘 켜 둡니다. 누를 때 필수 입력이 비었거나, 최소 글자 수·이름 중복 오류가 있거나, 장르를 고르지 않았으면 등록하지 않고 오류를 표시합니다. 오류가 있는 탭은 탭 이름을 빨간 글씨로 바꾸고, 각 칸은 설명 자리에 오류와 오류 테두리를 둡니다(빈 글 칸은 "{칸 이름}을(받침이 없으면 를) 입력해 주세요", 빈 추천 입력은 "추천 입력을 모두 채워 주세요", 성별은 "성별을 선택해 주세요", 장르는 "장르를 1개 이상 선택해 주세요", 최소 글자 수·이름 중복은 각 오류 문구). 이름과 성별은 한 설명 자리를 함께 써 이름 오류를 먼저 보입니다. 선택하지 않은 시작 상황에 오류가 있으면 그 칩을 빨간 글씨로 바꿉니다. 누른 뒤에는 탭 순서상 첫 오류 탭으로 옮겨 첫 오류 칸이 화면 가운데에 오도록 스크롤하고(키보드는 열지 않음), 오류가 있는 접힌 주변 인물·엔딩·주요 사건은 펼칩니다. 한 번 누른 뒤에는 입력을 고치는 대로 오류 표시가 바로 갱신됩니다.
- 서버가 이름으로 식별해 중복을 막는 항목은 이름이 앞 항목과 겹치면(앞뒤 공백만 빼고 비교, 서버는 이름을 그대로 비교) 먼저 쓴 항목은 두고 뒤 항목의 이름 칸 설명 자리에 "이미 사용한 이름이에요"를 오류로 표시합니다. 대상은 주요 사건(스토리 전체), 주변 인물(주인공 이름을 맨 앞에 두고 함께 비교), 엔딩(같은 시작 상황 안)입니다. 주인공과 주변 인물의 이름 중복은 서버가 막지 않지만 간편 제작과 같이 클라이언트에서 막습니다.
- 주변 인물·시작 상황·엔딩·주요 사건을 지울 때 입력한 내용(주변 인물은 이미지 포함, 시작 상황은 엔딩 포함)이 있으면 간편 제작 주변 인물과 같은 삭제 확인 다이얼로그를 거치고, 비어 있으면 바로 지웁니다.
- 주변 인물·엔딩·주요 사건의 회색 머리 줄에는 삭제 왼쪽에 간편 제작의 선택한 스토리라인 접기 버튼처럼 글자 오른쪽에 화살표가 붙은 "접기" 버튼을 두어 그 항목의 입력을 높이 애니메이션으로 접고, 접힌 항목은 같은 자리의 "펼치기"로 다시 엽니다(화살표가 위아래로 돌아감). 접힌 상태는 다른 탭이나 다른 시작 상황에 갔다 와도 유지합니다. 접기·삭제 버튼은 높이 32px에 12px 글자입니다. 항목은 펼친 상태로 시작하며, 주변 인물이 1명이라 삭제 버튼이 없을 때도 접기 버튼은 둡니다. 접힌 항목 바로 다음 항목은 목록 간격 없이 머리 줄끼리 붙입니다.
- 스토리 설정 4필드는 탭이 갈려도 요청에서는 `storySettings` 하나로 묶어 보냅니다. 주인공(나)·주변 인물 탭은 간편 제작의 인물 입력처럼 기본 정보(기본 주인공 이름은 선택이며 입력 시 1~30자. 주변 인물 이름 ≤ 30자와 성별 남성/여성은 필수)와 특징(≤ 1,000자, 주인공만 필수)을 받고, 성별에 "랜덤" 선택지는 두지 않습니다. 주변 인물은 1명으로 시작해 최대 5명이며 1명일 때는 삭제할 수 없습니다. 인물을 추가하면 간편 제작처럼 새 이름 입력이 화면 가운데에 오도록 스크롤하되 초점을 옮겨 키보드를 열지 않습니다. 주인공 이미지는 받지 않습니다(상세의 주변 인물 목록이 `characters[]` 전체를 표시하므로). 주변 인물은 기본 정보와 특징 사이에 인물 소개(선택, 토큰 포함 원문 한 줄 ≤ 150자)를 받습니다. 인물 소개는 상세의 주변 인물 이름 아래에 보이는 글이라 설정 글에 합치지 않고 그 인물의 `characters[].description`으로 보내며, 탭·줄바꿈은 공백으로 바꾸고 앞뒤 공백을 뺀 뒤 비면 등록 요청에서 뺍니다. 두 글은 간편 제작과 같은 제목으로 합칩니다.
  - 기본 주인공 이름은 `protagonistName`으로 보냅니다. 일반 제작 등록·수정 모두 선택이며 등록에서 생략·null이면 이름 없이 저장하고 수정에서 생략·null이면 기존 값을 유지합니다. 저장 결과의 텍스트에 이름 토큰이 있으면 기본 주인공 이름도 있어야 합니다. `userRoleSetting`은 이름을 뺀 설명으로 `# 주인공` 아래 `## 성별` 절과 특징 본문을 보냅니다.
  - `characterSetting`: `# 등장인물` 아래 인물마다 `## {이름}` 절, 그 안에 `### 성별` 절과 특징 본문. 이미지의 인물 이름도 같은 이름 칸에서 만들어 설정 글과 어긋나지 않습니다.
  - 주변 인물 이미지는 인물당 1장이며 기본 정보 위에 커버 이미지와 같은 배치(왼쪽 4:3 미리보기, 오른쪽 버튼·안내)로 받습니다. 고르면 4:3으로 자른 뒤 등록 전 presign(`kind: CHARACTER`)으로 올리고, 등록 시 `characters[].images[]`에 `{objectKey, imageName: "{이름}_기본"}`으로 보냅니다(간편 제작 대표 이미지와 같은 접미).
  - 수정 폼의 기본 주인공 이름은 `protagonistName`으로 받습니다. 주인공 설명의 성별 절과 주변 인물의 `## {이름}` 줄만 칸으로 옮기고, 그 밖의 절(간편 제작 글의 `## 역할`·`### 성격`, 이전 글 맨 앞의 `## 호칭` 등)은 특징 본문으로 둡니다. 성별 값이 남성·여성이 아니면 성별 절을 본문에 남깁니다. 주요 사건·엔딩은 저장 후 채팅 런타임(목표 진행·엔딩 판정·선택지 구성)에 반영됩니다([`4-backend-server-spec.md §4-3-10`](4-backend-server-spec.md)) — 런타임 동작 자체는 채팅 화면([§3-1-5](../domain/CHAT/CLIENT/AGENTS.md))의 검수 대상입니다.

- **이미지 입력** — 표지와 주변 인물 이미지를 받습니다. 인물(`characters[]`)은 주변 인물만 담아 최대 5명이며(서버 상한 6명) 이름이 스토리 안에서 유일하고 인물당 이미지 최대 10장입니다. 이미지는 등록 전 presign(`POST /stories/images/presign`)으로 올린 `objectKey`를 보내며, 이미지 이름은 `{인물이름}_{접미}`(접미 1~20자 한글·영문·숫자, 같은 인물 안에서 유일)입니다([`4-backend-server-spec.md §4-3-8`](4-backend-server-spec.md)). 이미지는 고른 뒤 칸의 비율(표지 3:4, 주변 인물 4:3)로 잘라 올리며, 자르기를 취소하면 올리지 않고 기존 이미지를 유지합니다.
- (B14) — 시작 설정은 여러 개(`startSettings[]`, 1개 이상) 등록할 수 있고, 엔딩은 시작 설정별로 입력합니다([`4-backend-server-spec.md §4-3-8`](4-backend-server-spec.md)).

**동작** — 등록: `POST /stories/general`은 검수 제출본만 만들고 202 `{submissionId, status: "PENDING"}`을 반환하며 이때는 스토리 ID가 없습니다([`4-backend-server-spec.md` 스토리 검수 제출 흐름](4-backend-server-spec.md#스토리-검수-제출-흐름)). 등록하기를 누르면 검수 결과가 나올 때까지 등록하기에 스피너를 두고 탭과 입력을 잠그며 "스토리를 검토하고 있어요" 토스트를 띄웁니다. 접수되면 입력의 정본은 서버 제출본이므로 폼의 임시 저장본을 지우고, 그 화면에서는 다시 임시 저장하지 않습니다(이어서 만들기로 같은 입력을 새로 제출하지 않게). 등록과 재제출 요청에는 임시 저장본 ID(`draftId`)를 실어 서버가 접수와 함께 그 임시 저장본을 지웁니다. 이어서 `GET /stories/submissions/{submissionId}`를 1초 간격으로 조회해 결과를 기다립니다. 승인되면 만들어진 스토리의 첫 시작 설정으로 채팅을 만들어 채팅방으로 이동하며, 채팅을 만들지 못하면 "채팅을 시작하지 못했어요" 토스트와 함께 스토리 상세로 이동합니다. 반려·실패하면 입력을 그대로 둔 채 "스토리가 검토를 통과하지 못했어요" 토스트를 띄우고 아래 검수 결과 표시를 보이며, 같은 화면에서 다시 등록하면 그 제출본을 `PUT /stories/submissions/{submissionId}`로 재제출합니다. 요청이 `IMAGES_TOO_LARGE`로 실패하면 "이미지 크기나 장수를 줄여 주세요", `UPLOAD_NOT_FOUND`면 "올린 이미지를 찾지 못했어요. 이미지를 다시 올려 주세요"를 띄웁니다. 60초가 지나도 결과가 없으면(서버의 일시 실패 재시도) 기다리지 않고 제작 탭으로 이동해 "검토가 늦어지고 있어요. 끝나면 제작 탭에 추가돼요" 토스트를 띄웁니다. 검토 중에 화면을 떠나면 조회만 멈추고 서버 검수는 계속됩니다. 요청이 실패하면(400 검증 실패 포함) 입력을 그대로 둔 채 "스토리를 등록하지 못했어요" 토스트를 띄웁니다. 클라이언트 선검증이 서버 규칙보다 엄격해 400의 `details`를 칸별로 되돌려 표시하지 않습니다. 등록은 회원 전용이라(게스트 401) 게스트는 폼에 들이지 않으며, 진입 경로는 플랫폼 스펙이 정합니다. 재제출: 제작 탭 반려·실패 카드의 "수정하기"는 `GET /stories/submissions/{submissionId}`의 입력으로 폼을 채워 엽니다(설정 글은 수정 폼과 같은 규칙으로 칸에 나누고, 장르 이름은 [장르 검색과 선택](#장르-검색과-선택)의 이전 입력 규칙으로, 이미지는 서버 미리보기로, 주변 인물의 이미지와 인물 소개는 이름이 같은(없으면 같은 순서의) 제출본 인물 것으로 둠). 처음부터 접수된 상태라 임시 저장하지 않고 등록하면 PUT으로 재제출합니다. 검토 중이면 제작 탭으로 보내 "아직 검토 중이에요", 승인됐으면 스토리 상세로 보내며, 조회에 실패하면 제작 탭으로 보내 "스토리를 불러오지 못했어요"를 띄웁니다. 검수 결과 표시: 폼 위에 반려면 "검토를 통과하지 못했어요"·"표시된 곳을 고쳐 다시 등록해 주세요", 실패면 "검토를 마치지 못했어요"와 이미지 오류 여부에 따라 "표시된 이미지를 바꿔 다시 등록해 주세요" 또는 "검토 중 문제가 생겼어요. 다시 등록해 주세요"를 둡니다. `issues`·`imageErrors`의 경로를 칸으로 옮겨 등록 오류와 같이 탭 이름을 빨갛게 하고 칸 설명 자리에 사유(AI의 `reason`, 비었으면 "등록할 수 없는 내용이 있어요")나 이미지 오류 안내(`IMAGE_INVALID` "이미지 형식이나 크기를 확인해 주세요", `IMAGE_UNREADABLE` "이미지를 읽을 수 없어요. 다른 이미지로 바꿔 주세요", 그 밖 "이미지를 확인하지 못했어요. 다른 이미지로 바꿔 주세요")를 보이며, 첫 사유가 있는 탭으로 엽니다. `storySettings.characterSetting`처럼 칸 하나로 짚을 수 없는 경로는 탭만 빨갛게 하고 폼 위 안내에 "{탭 이름}: 사유"로, 알 수 없는 경로는 사유만 목록으로 둡니다. 제출한 뒤 그 칸(항목)을 고치거나 지우면 사유를 내립니다. 수정: 진입 시 `GET /stories/{storyId}/edit`로 편집 가능 필드 전체를 조회해 폼을 채웁니다. 설정 글은 위 수정 폼 규칙으로 칸에 나누고, 시작 설정과 주변 인물은 서버 id로 짝지으며(주변 인물은 이름이 같은 서버 인물), 주변 인물 이미지 칸에는 그 인물의 첫 이미지를, 인물 소개 칸에는 그 인물의 `description`을 보이며, 짝지은 서버 인물이 없는 주변 인물은 두 칸을 비웁니다. 저장하면 폼을 연 시점과 달라진 필드만 `PATCH /stories/{storyId}`로 보내 보내지 않은 필드는 그대로 둡니다. 인물을 고쳐 `characters`를 보낼 때는 폼에 없는 서버 인물과 바꾸지 않은 이미지를 id로 함께 실어 지워지지 않게 합니다. 폼의 주변 인물은 인물 소개를 늘 실어 비운 소개는 빈 문자열로 지우고, 폼에 없는 서버 인물은 인물 소개를 싣지 않아 서버가 그대로 둡니다. 바뀐 것이 없으면 요청하지 않고 들어온 화면으로 돌아갑니다. 아래 "들어온 화면"은 수정 화면을 연 상세나 제작 탭입니다. 공개 범위만 바꾸면 검수 없이 반영(200)돼 "스토리를 수정했어요"와 함께 들어온 화면으로 돌아가고, 그 밖의 변경은 202 제출본으로 접수돼 등록과 같이 결과를 1초 간격으로 조회합니다. 관리자가 공개를 중단한 스토리는 공개 범위만 공개로 바꿔도 202로 접수되며, 이때도 접수 뒤 "스토리를 검토하고 있어요"를 띄우고 같은 방식으로 결과를 조회합니다. 승인되면 "스토리를 수정했어요"와 함께 들어온 화면으로 돌아가고, 반려·실패하면 등록과 같은 검수 결과 표시를 보이되 안내의 "다시 등록해 주세요"를 "다시 저장해 주세요"로 바꾸며(반려 "표시된 곳을 고쳐 다시 저장해 주세요", 실패 "표시된 이미지를 바꿔 다시 저장해 주세요" 또는 "검토 중 문제가 생겼어요. 다시 저장해 주세요"), 60초가 지나도 결과가 없으면 "검토가 늦어지고 있어요. 끝나면 스토리에 반영돼요"와 함께 들어온 화면으로 돌아갑니다. 반려·실패한 미승인 수정 제출본이 있으면 수정 폼은 그 입력을 합친 값과 결과 표시로 열리고, 다시 저장하면 같은 제출본을 덮어쓰므로 바뀌지 않은 필드도 모두 보냅니다. 검토 중(PENDING)인 수정 제출본이 있으면 PATCH가 409이므로 폼 위에 "수정 내용을 검토하고 있어요"·"검토가 끝나면 다시 수정할 수 있어요"를 두고 입력과 저장을 잠그며, 탭은 옮겨 볼 수 있습니다. 화면을 떠난 뒤 나온 결과는 다음 수정 진입 때 이 표시로 알립니다. 요청이 실패하면 입력을 그대로 둔 채 "스토리를 수정하지 못했어요"(409면 "아직 검토 중이에요", `IMAGES_TOO_LARGE`·`UPLOAD_NOT_FOUND`는 등록과 같은 안내)를 띄우고, 등록과 같은 이유로 400의 `details`를 칸별로 되돌려 표시하지 않습니다. 수정 화면의 이미지는 일반 제작처럼 표지와 주변 인물 대표(첫) 이미지를 바꾸거나 지울 수 있습니다. 대표 이미지를 바꾸면 새 이미지를 맨 앞에 두고 나머지 이미지는 유지하며, 지우면 대표 이미지만 빼고 나머지 이미지는 유지합니다(인물을 고친 것과 같이 `characters`로 보냄). 표지를 지우면 `PATCH`에 싣지 않고 저장할 때 `DELETE /stories/{storyId}/thumbnail`로 지운 뒤 나머지 변경을 `PATCH`로 보내며, 표지만 지웠으면 검수 없이 "스토리를 수정했어요"와 함께 들어온 화면으로 돌아갑니다. 여러 이미지 관리는 별도 이미지 편집에서 다룹니다. 수정은 회원 소유자만 할 수 있습니다.

**임시 저장** — 일반 제작은 회원 전용이므로 임시 저장본을 회원 계정의 서버 초안(`/users/me/story-drafts`, [`4-backend-server-spec.md` 스토리 제작 임시 저장](4-backend-server-spec.md#story-drafts))에 보관하고, 다른 기기와 브라우저에서도 제작 탭의 "이어서 만들기"로 엽니다. 저장 시점과 이탈 확인은 플랫폼 스펙을 따릅니다.

- 초안 ID는 제작 화면을 열 때 만든 UUID이며 그 화면에서 저장할 때마다 같은 ID를 씁니다. 이어서 만들기는 그 초안의 ID를 그대로 씁니다. 저장 응답의 `version`을 다음 저장의 `baseVersion`으로 보내고, 새 초안은 `baseVersion` 없이 보냅니다.
- 요청은 `mode: "GENERAL"`, `stage: "GENERAL_DRAFT"`, `schemaVersion: 1`입니다. 서버는 `payload`를 해석하지 않으므로 Web과 Android가 같은 형식을 씁니다. `payload`는 폼 전체 입력으로 `texts`(글 칸 이름별 문자열), `cover`, `descriptionRatio`, `protagonist`, `supporting[]`, `startSettings[]`, `mainEvents[]`, `genres`, `description`, `visibility`를 담고, 이미지(`cover`, `supporting[].image`)는 `{objectKey}` 또는 null만 둡니다. 각 필드의 형태는 웹 [일반 제작 스냅숏 타입](../../../manyak-web/src/features/studio/_shared/utils/general-story-draft.ts)과 같습니다. 읽을 때 빠졌거나 타입이 다른 최상위 필드와 항목 안에서 빠진 필드는 새 폼의 기본값으로 채웁니다. `schemaVersion`이 1이 아닌 초안은 열지 않고 불러오기 실패로 처리합니다(모르는 필드를 지운 채 되쓰지 않게). 목록용 요약은 `title`과 `oneLineIntro`(앞뒤 공백을 빼고 비면 null), `thumbnailObjectKey`(표지 객체 키)로 함께 보냅니다.
- 다시 열면 이미지 미리보기는 상세 응답의 `imageUrls`를 씁니다.
- 회원당 5개를 넘겨 새로 저장하면 "임시 저장은 5개까지 할 수 있어요", payload가 64KB를 넘으면 "내용이 길어서 임시 저장하지 못했어요" 토스트를 띄우고 저장하지 않은 상태로 둡니다. 그 밖의 실패는 "작성 내용을 저장하지 못했어요"입니다. 백그라운드 전환 저장의 실패는 알리지 않습니다.
- 다른 기기나 창이 같은 초안을 먼저 저장해 버전이 다르면(409) 제목 "다른 곳에서 먼저 저장한 내용이 있어요", 설명 "지금 내용으로 저장하면 다른 곳에서 저장한 내용은 사라져요" 다이얼로그를 띄웁니다. 보조 버튼 "남겨두기"는 서버 내용을 그대로 두고 닫고, 주 버튼 "저장하기"는 응답의 현재 버전을 기준으로 지금 내용을 덮어씁니다.
- 이어서 만들 초안이 없으면(다른 곳에서 등록하거나 지워 404) "만들던 스토리를 찾지 못했어요"를 띄우고 빈 폼으로 시작합니다. 화면을 연 뒤에 다른 곳에서 초안이 없어져 저장이 거절되면 상세 조회로 없어졌는지 확인하고, 없으면 같은 ID의 새 초안으로 다시 저장해 입력을 남깁니다.

**검수 기준**

- 일반 제작으로 등록한 스토리가 기본 메타·스토리 설정·시작 설정 기준으로 상세·채팅 시작에서 간편 제작 산출물과 동일하게 동작해야 합니다. (US-3-15)
- 제작 화면에서 간편 제작과 일반 제작으로 진입할 수 있어야 합니다. 경로는 플랫폼 스펙을 따릅니다. (US-3-16)
- 수정 전용 조회가 폼 필드를 채울 수 있어야 하고, 수정 후 스토리 상세와 같은 스토리 설정을 참조하는 진행 중 채팅의 다음 턴에 새 설정이 반영돼야 합니다. (US-4-5)
- 폼 작성 중 임시 저장한 뒤 이탈했다가 제작 탭에서 이어서 만들면 임시 저장한 내용이 복원돼야 합니다. 저장 시점은 플랫폼 스펙을 따릅니다.
- 회원이 임시 저장한 일반 제작은 다른 기기에서 같은 계정으로 로그인해도 제작 탭에서 이어서 만들 수 있어야 합니다.
- 타인 소유 스토리와 로컬 서재에 없는 게스트 스토리에는 수정 진입점이 보이지 않아야 합니다.

### FE-SCREEN-011. 서비스 안내

**목적** — AI 콘텐츠 특성·문의·정책 정보를 안내하고 약관·개인정보 처리방침의 상시 열람 경로를 제공합니다. 마이의 기타 섹션에서 피드백 위에 서비스 안내를 둡니다.

**콘텐츠 규칙** — 서비스 안내에는 이프 적립·소모 수치를 복제하지 않습니다. 필요한 화면에서 서버 정책값을 표시합니다. 게스트 이용 안내는 웹에만 적용하고, 그 체험 한도는 서버 정책과 일치해야 합니다. 약관·개인정보 처리방침을 요약할 수 있지만 서로 상충해서는 안 됩니다.

웹 게스트 안내 문구는 다음과 같습니다.

- 로그인 없이도 스토리를 둘러볼 수 있어요. 게스트 이용 안내에 동의하면 체험 한도 안에서 스토리를 만들고 채팅할 수 있어요. 한도를 모두 사용하면 로그인이 필요해요.
- 게스트로 만든 스토리와 채팅은 이 브라우저에 연결돼요. 브라우저 데이터를 지우거나 기기를 바꾸면 다시 불러오기 어려울 수 있어요.
- 처음 로그인한 뒤 회원 필수 동의를 마치면 이 브라우저의 스토리와 채팅을 계정으로 옮겨요. 이관은 계정마다 한 번만 제공해요.

Android 앱도 같은 본문을 보여 주므로 게스트 이용 안내 제목 아래에 "웹 브라우저에서 이용할 때만 적용돼요"를 표시합니다. 문의 섹션은 피드백 화면으로 연결하지 않고 위치만 "서비스 개선 의견은 마이 > 피드백에서 보내주세요."로 안내합니다.

두 응답의 `tag`(`SERVICE`·`UPDATE`·`MAINTENANCE`·`EVENT`·`PROMOTION`)는 "서비스"·"업데이트"·"점검"·"이벤트"·"혜택"으로 표시하며, 점검만 주의색 배지이고 나머지는 보조 배지입니다. 모르는 값은 배지를 그리지 않습니다.

**목적** — 운영자가 관리자 페이지에서 게시한 공지를 사용자가 앱 안에서 확인합니다. 두 API 모두 인증이 필요 없어 게스트와 회원이 같은 화면을 봅니다.

**진입점** — 게스트는 홈·채팅 목록·제작 헤더 오른쪽의 확성기 아이콘 버튼(마이의 공지사항 메뉴와 같은 아이콘, 접근 이름 "공지사항")으로, 게스트와 회원 모두 마이 > 알림 섹션의 "공지사항" 메뉴(확성기 아이콘, 알림 설정 아래)로 목록을 엽니다. 회원의 헤더 종 버튼은 [알림함](#fe-screen-015-알림함)으로 가며, 공지 알림 카드를 탭하면 공지 상세가 열립니다. 마이 헤더에는 두지 않습니다. 알림 섹션은 게스트에게도 보이되 알림 설정 메뉴는 회원에게만 둡니다. 웹의 게스트 로그인 버튼과의 배치는 [웹 상단 헤더](3-2-web-spec.md#화면-전환-규칙)를 따릅니다.

**안 읽은 공지 표시** — 기기마다 "상세를 열어 읽은 공지 ID 목록"(최근 100개)을 보관합니다. 게시된 지 30일 안인데 이 목록에 없는 공지를 안 읽음으로 보며, 안 읽은 공지가 하나라도 있으면 게스트 헤더 버튼 오른쪽 위에 빨간 점을 찍고 접근 이름을 "새 공지사항 있음"으로 바꾸고 마이의 공지사항 메뉴 라벨 오른쪽에 연한 빨간 배경의 "새 공지" 배지를 답니다. 목록에서는 안 읽은 공지의 제목을 굵게 하고 제목 끝에 같은 색의 작은 점(보조 기술 이름 "새 공지")을 붙입니다. 읽음은 상세를 열 때(목록 진입, 주소나 알림으로 바로 진입 모두)만 기록하며 목록만 보는 것은 읽음이 아닙니다. 그래서 상세에서 목록으로 돌아오면 그 줄의 점만 꺼지고, 안 읽은 공지가 남아 있으면 헤더 점과 배지는 유지됩니다. 게시 30일이 지난 공지는 열지 않아도 안 읽음으로 세지 않습니다. 서버에 읽음 기록이 없어 다른 기기·브라우저와 동기화하지 않습니다.

**목록** — "공지사항" 뒤로가기 헤더 아래 게시 최신순으로 줄마다 태그 배지, 제목(최대 두 줄 말줄임, Android는 [한 줄](3-3-android-spec.md#마이법적-문서))과 게시일(`YYYY-MM-DD`, [날짜 표시 기준](#날짜-표시-기준))을 둡니다. 줄 전체가 상세로 이동하며 테두리 없이 화면 좌우를 채우고, 누르는 동안 배경을 바꾸지 않습니다. 목록 끝에 닿으면 응답의 `nextCursor`로 다음 페이지를 이어 붙이고 "더 보기" 버튼은 없습니다. 목록 맨 위에서 아래로 당기면 첫 페이지부터 다시 조회합니다(웹의 당김 동작은 [웹 화면 전환 규칙](3-2-web-spec.md#화면-전환-규칙)).

**상세** — "공지사항" 뒤로가기 헤더 아래 태그 배지, 제목, 게시일("게시 YYYY-MM-DD"), 본문을 둡니다. 게시한 뒤 날짜가 바뀔 만큼 고쳐 썼으면(`updatedAt`이 `publishedAt`보다 늦고 날짜가 다름) 게시일 옆에 "수정 YYYY-MM-DD"를 함께 표시합니다. `body`는 서버가 가공하지 않는 평문(최대 5000자)이라 줄바꿈만 살려 그대로 표시하고 마크다운·HTML로 해석하지 않습니다.

| 빈 상태 | 게시된 공지 없음 | "아직 등록된 공지가 없어요" 한 줄 보조 안내 |

### FE-SCREEN-015. 알림함

| 항목     | 값                                                  |
| -------- | --------------------------------------------------- |
| 관련 API | `GET /users/me/notifications`, `GET /users/me/notifications/unread-count`, `POST /users/me/notifications/{notificationId}/read`, `POST /users/me/notifications/read-all` |
| 관련 US  | US-8-6                                              |

**목적** — 회원이 받은 알림(푸시로 보냈거나 보내지 못한 것 모두)을 앱 안에서 다시 보고, 읽음을 정리하고, 알림이 가리키는 화면으로 갑니다. 네 API 모두 회원 전용(정지 403, 탈퇴 401)이라 게스트는 로그인으로 보냅니다. 알림은 서버가 보낸 시점의 사본이며 공지·스토리가 바뀌어도 갱신하지 않습니다.

**진입점** — 회원의 홈·채팅 목록·제작 헤더 오른쪽 종 아이콘 버튼(접근 이름 "알림")입니다. 안 읽은 알림(`unread-count`의 `total`)이 있으면 아이콘 오른쪽 위에 빨간 점을 찍고 접근 이름을 "새 알림 있음"으로 바꿉니다. 게스트의 같은 자리 버튼은 [공지사항](#fe-screen-014-공지사항)입니다. 마이 메뉴에는 두지 않습니다.

**구성** — "알림" 뒤로가기 헤더(오른쪽 끝에 간편 제작 헤더의 임시 저장과 같은 보조 버튼 "모두 읽음", 그 오른쪽에 [알림 설정](3-2-web-spec.md#pwa-푸시)으로 가는 톱니 아이콘 버튼, 접근 이름 "알림 설정") 아래 "소식"·"활동" 라인 탭을 두고, 처음 열면 소식 탭입니다. 탭은 URL에 남기지 않습니다. 분류에 안 읽은 알림이 있으면 탭 라벨 오른쪽 위에 작은 빨간 점(보조 기술 이름 "안 읽은 알림 있음")을 둡니다.

- 소식(`NEWS`): 공지(`NOTICE`)와 이벤트(`PROMOTION`). 공지 알림은 게시 캠페인 시점의 활성 회원 전원에게, 이벤트 알림은 광고 알림 동의 회원에게 기록되므로 가입 전 게시나 캠페인 없는 게시는 소식에 없습니다. 공지 전체는 공지사항 화면이 맡습니다.
- 활동(`ACTIVITY`): 스토리 완성(`STORY_COMPLETED`), 검토 결과(`STORY_MODERATION_COMPLETED`), 출석 체크(`ATTENDANCE_REMINDER`), 이프 만료(`CREDIT_EXPIRY_REMINDER`), 공개 제한(`STORY_TAKEN_DOWN`).

**카드** — 분류마다 최신순 카드 목록이며 테두리 없이 화면 좌우를 채웁니다. 카드 위 줄 왼쪽에 분류 라벨(공지에서 비롯한 알림은 유형과 무관하게 공지 태그 라벨 "업데이트"·"혜택" 등, 태그가 없으면 유형 라벨 "공지"·"이벤트"·"스토리 완성"·"검토 결과"·"출석 체크"·"이프 만료"·"공개 제한"; 모르는 유형은 라벨 없음), 오른쪽에 `createdAt`의 상대 시각(홈 카드와 같은 규칙)을 두고 아래에 제목(최대 두 줄, Android는 [한 줄](3-3-android-spec.md#마이법적-문서))과 본문(최대 두 줄)을 둡니다. 안 읽은 카드(`readAt` 없음)는 제목을 굵게 하고 제목 끝에 빨간 점(보조 기술 이름 "안 읽음")을 붙이며, 읽은 카드는 제목·본문을 보조색으로 가라앉힙니다. 목록 끝에 닿으면 `nextCursor`로 다음 페이지를 이어 붙이고 맨 위에서 아래로 당기면 첫 페이지부터 다시 조회합니다.

**읽음과 이동** — 카드를 탭하면 그 알림을 읽음으로 기록하고(`read`, 이미 읽은 알림은 요청하지 않음) 갈 곳으로 이동합니다. 갈 곳은 `deepLink`(서비스 origin의 절대 URL만 허용) → `noticeId`(공지 상세) → `storyId`(스토리 상세) 순이며 셋 다 없으면 읽음만 기록합니다. "모두 읽음"은 분류 구분 없이 전체를 읽음 처리하며 안 읽은 알림이 없으면 비활성입니다. 둘 다 카드와 점을 먼저 끄고 요청하며, 한 건 읽음 실패는 조용히 넘기고 모두 읽음 실패는 되돌린 뒤 "알림을 읽음 처리하지 못했어요" 토스트를 띄웁니다. 공지 알림으로 연 공지 상세는 공지사항의 기기 읽음 기록도 함께 남깁니다.

| --- | --- | --- |
| 로딩 | 분류 첫 조회 중 | 카드 구조의 지연 스켈레톤 |
| 빈 상태 | 소식 없음 | "아직 받은 소식이 없어요" + "공지와 이벤트 소식이 여기에 모여요" |
| 빈 상태 | 활동 없음 | "아직 활동 알림이 없어요" + "스토리가 완성되거나 검토가 끝나면 알려 드려요" |

| 1   | 키워드 선택     | 장르·주인공·주변 인물 키워드 수집               | 장르 1개 이상 **그리고** 주인공 1개 이상 |
| 2   | 스토리라인 선택 | AI 생성 스토리라인 3개 중 택1(선택·재생성·평가) | 활성 스토리라인 선택 완료                |

### 키워드 선택 규칙

| 카테고리       | 탭 라벨        | 필수   | 상한                        | 직접 추가 |
| -------------- | -------------- | ------ | --------------------------- | --------- |
| 장르           | 장르           | 예     | 키워드 3개                  | 불가(제공 장르 검색) |
| 주인공 특징    | 주인공 (나)    | 예     | 인물 1명, 특징 3개          | 가능      |
| 주변 인물 특징 | 주변 인물      | 아니오 | 인물 5명, 인물마다 특징 3개 | 가능      |

- 카테고리는 전체 폭의 동일 너비 탭으로 표시하며 별도 설명 문구를 두지 않습니다. 시각 표현 값은 [웹 표현](../design/1-1-web-design.md#웹-표현-값)을 따릅니다.
- 칩 목록 위에는 장르 "장르 (최대 3개)", 인물 "특징 (최대 3개)" 라벨을 표시하고 필수 카테고리에 `*`를 붙입니다.
- 태그 목록은 API로 조회하며, 로딩 시 스켈레톤 칩을 표시합니다. 받지 못하면 칩 자리에 누르면 다시 조회하는 "키워드를 불러오지 못했어요. 다시 시도" 버튼을 표시합니다.
- 상한에 도달하면 미선택 칩과 인물 특징의 "키워드 추가" 트리거를 비활성화합니다(제공 태그·직접 추가 합산). 장르는 [장르 검색과 선택](#장르-검색과-선택)을 따릅니다. 주변 인물이 5명이면 "인물 추가"도 비활성화합니다.
- 필수 카테고리의 "다음" 버튼은 선택 전에도 활성화합니다. 선택 없이 누르면 이동하지 않고 버튼 위 푸터에 "키워드를 하나 이상 선택해주세요"를 표시합니다. 오류가 생길 때만 푸터가 메시지 높이만큼 늘어나며, 해당 카테고리에서 키워드를 선택하면 오류를 제거합니다.
- 커스텀 키워드는 "키워드 추가" 다이얼로그로 입력합니다. "추가하기" 버튼은 빈 입력에서도 활성화하고, 빈 값으로 누르면 입력창 아래에 "키워드를 입력해주세요"를 표시합니다. 유효한 값을 입력하거나 다이얼로그를 닫으면 오류를 제거합니다. 클라이언트 최대 15자(서버 스키마 30자), IME 조합 중 Enter는 제출하지 않습니다. 주인공과 주변 인물 특징에서 직접 추가할 수 있으며, 요청에서 각 인물의 `customTags`로 나갑니다([`4-backend-server-spec.md §4-3-2`](4-backend-server-spec.md)).
- 카테고리 탭은 앞선 필수 카테고리가 완료되어야 잠금 해제됩니다.

#### 장르 검색과 선택

간편 제작 키워드 단계와 일반 제작·수정의 등록 탭이 같은 장르 선택을 씁니다. 장르는 서버 제공 장르만 고르며([`4-backend-server-spec.md` 제공 장르와 검색](4-backend-server-spec.md#genre-catalog)) 장르 직접 입력은 없습니다. 상한은 간편 제작 3개, 일반 제작·수정 8개입니다.

- **구성** — 장르 라벨 아래에 검색 콤보박스("장르 검색 및 선택", 왼쪽 검색 아이콘, 오른쪽 목록 열기 버튼)를 두고 그 아래에 장르 칩을 둡니다. 칩은 대표 장르(`featuredGenres`)를 대표 순서대로 보이고, 대표 밖 장르는 처음 고를 때 칩 목록 끝에 붙어 선택 해제와 재선택에도 그 자리를 지킵니다. 장르 목록을 받는 동안 스켈레톤 칩을, 받지 못하면 칩 자리에 태그 목록과 같은 다시 시도 버튼을 표시합니다.
- **검색** — 콤보박스를 누르면 입력 폭의 목록이 아래에 열리고, 빈 검색어에서는 제공 장르 전체를 보입니다. 입력을 잠시 멈추면 서버에 검색하며(검색어 30자 이하, 대기 시간은 플랫폼 설계를 따름) 초성·별칭·공백·대소문자 처리는 서버 규칙을 따릅니다. 새 결과를 받을 때까지 이전 목록을 유지하고, 요청이 200ms 이상 걸릴 때만 "장르를 불러오고 있어요"를 보입니다(입력 대기 시간은 포함하지 않음). 결과가 없으면 "검색 결과가 없어요"를, 실패하면 누르면 다시 시도하는 "장르를 불러오지 못했어요. 다시 시도"를 보이며, 응답 전에는 결과 없음 문구를 먼저 보이지 않습니다.
- **선택** — 검색 목록과 칩은 같은 장르의 선택 상태를 공유합니다. 고른 항목에는 체크를 표시하고, 항목을 누르면 선택을 토글한 뒤 목록을 닫고 검색어를 비우며 입력 초점을 해제해 키보드를 닫습니다. 상한에 도달하면 고르지 않은 칩과 목록 항목을 비활성화하고 고른 장르의 해제는 허용합니다. 대표 장르는 어느 경로로 골라도 대표 위치를 지킵니다.
- **요청** — 간편 제작은 고른 순서대로 `genreTagIds`에 싣고 `customGenreTags`는 보내지 않습니다. 이미 접수된 생성 요청을 같은 requestId로 다시 보내는 재시도와 복구는 저장한 요청을 그대로 보냅니다. 일반 제작·수정은 고른 순서대로 정식 장르 이름을 `genres`에 싣습니다.
- **이전 입력** — 직접 입력을 받던 때 저장한 장르(간편 제작 키워드 임시 저장본, 일반 제작 임시 저장본, 반려·실패한 등록 제출본)는 정식 장르 이름과 공백·대소문자를 무시하고 같으면 그 제공 장르로 고릅니다. 같지 않은 값은 저장본에 남기되 선택과 요청에서 빼고, 사용자가 장르를 바꿀 때까지 콤보박스 아래에 "이전 직접 입력 장르는 사용할 수 없어요. 제공 장르를 다시 선택해 주세요"를 보입니다. 수정 화면은 서버가 스토리에 이미 저장된 장르를 유지해 주므로([`4-backend-server-spec.md` 장르 입력 검증](4-backend-server-spec.md#genre-validation)) 제공 목록에 없는 기존 장르도 고른 칩으로 보이고 그대로 보냅니다.

#### 인물 단위 입력

주인공과 주변 인물을 특징 태그 묶음이 아니라 인물 단위로 입력받습니다. 두 탭은 같은 폼을 씁니다.

- **폼 구성** — 기본 정보(이름·성별) → 특징(제공 태그·직접 추가) 순서입니다. 기본 정보에는 "비워두면 랜덤으로 설정해요"를 표시합니다. 특징 필수 표시는 주인공만 적용하고 주변 인물에는 "선택하지 않으면 랜덤으로 설정해요"를 안내합니다.
- **이름** — 직접 입력이며 클라이언트·서버 모두 30자 상한입니다. 인풋 오른쪽에 입력 글자 수를 표시합니다.
- **성별** — 셀렉트이고 기본값은 "랜덤 성별"입니다. 랜덤은 고르지 않은 상태와 같아 요청에 `null`로 나가고 AI가 정합니다.
- **주변 인물 목록** — 빈 인물 1명으로 시작하며 이름(빈 값이면 "주변 인물 N")·`N/5` 순번·삭제를 표시합니다. 삭제 왼쪽에는 일반 제작 주변 인물과 같은 "접기"(접힌 뒤 "펼치기") 버튼을 두어 그 인물의 입력을 높이 애니메이션으로 접고 펼치며, 접힌 상태는 다른 탭이나 단계에 갔다 와도 유지합니다. 이름·성별·특징 중 하나라도 입력한 인물을 지우면 채팅 블록 입력과 같은 확인 다이얼로그("작성한 내용을 삭제할까요?" / "삭제하면 작성한 내용이 사라져요", "그대로 두기"·"삭제하기")를 거치고, 빈 인물은 바로 지웁니다. 0~5명을 허용하고 빈 폼도 인원으로 집계합니다. 0명이면 "인물 추가" 위에 "주변 인물이 랜덤으로 생성돼요"를 표시합니다. 추가 시 새 이름 입력이 보이도록 스크롤하되 초점을 옮겨 키보드를 열지 않습니다.
- **이름 중복 금지** — 한 스토리 안에서 주인공과 주변 인물의 이름은 겹칠 수 없습니다. AI가 이름 글자로 인물의 등장 여부를 확인하기 때문입니다. 판정 키는 서버와 같습니다 — NFC 정규화 → 공백 제거 → 소문자([`4-backend-server-spec.md §4-3-2`](4-backend-server-spec.md)). 먼저 쓴 이름을 남기고 뒤에 겹친 인물의 이름 인풋에 "이미 사용한 이름이에요"를 즉시 표시하고, 그 상태에서 "스토리라인 만들기"를 누르면 요청을 보내지 않고 푸터에 "인물 이름이 겹치지 않게 해주세요"를 표시합니다. 비워 둔 이름은 AI가 각각 지어 주므로 판정 대상이 아닙니다. 서버도 400으로 막습니다([`4-backend-server-spec.md §4-3-2`](4-backend-server-spec.md)).

### 스토리라인 생성·평가

- **선택 UI** — "첫 번째"·"두 번째"·"세 번째" 탭으로 전환합니다. 하단 "선택한 키워드 보기"는 제목 "선택한 키워드들이에요"와 설명 "이 키워드들을 이용해서 스토리라인 세 개를 만들었어요" 아래에 카테고리별 선택 키워드를 보여 주는 읽기 전용 키워드 드로어를 열고 "다시 만들기"·"선택하기"로 재생성·확정을 수행합니다. 타이포그래피·배치는 [웹 표현](../design/1-1-web-design.md#웹-표현-값)을 따릅니다.
- **생성** — `POST /stories/simple/storylines {genreTagIds, protagonist, supportingCharacters}`. 인물 객체는 `{name, gender, featureTagIds, customTags}`이고 비워 둔 이름·성별은 `null`로 보냅니다. 클릭 직후 "스토리라인 만들기" 버튼을 비활성화하고 문구 공간을 유지한 중앙 스피너를 표시하며, 동시에 스토리라인 선택 단계로 전환해 로딩 화면을 렌더합니다. 응답은 스토리라인 3개와 생성 ID(`simpleCreationId`)를 포함합니다. 로딩 중에는 순환 문구(글자 단위 캐스케이드 전환·시머, 본문 크기 16px)와 15·30초 시점 힌트를 표시합니다.  — 회원은 무료이고, 게스트의 체험 한도·카운터는 웹 스펙을 따릅니다.
- **재생성** — "다시 만들기"는 저장된 생성 요청을 재호출합니다. 생성 요청 이벤트는 최초 1회만 발화합니다.  익명 체험의 선차단은 웹 스펙을 따릅니다.
- **입력 내용 거절** — 스토리라인 생성·재생성과 스토리 완성이 422 `code: "CONTENT_REJECTED"`(AI가 입력 내용을 이유로 거절)로 끝나면 일반 실패와 구분해 "수위가 높아 만들 수 없어요"를 보입니다. 분기는 응답 `message`가 아니라 `code`로 합니다. 같은 입력은 다시 거절되므로 같은 요청을 다시 보내는 재시도를 두지 않습니다. 스토리라인 생성·재생성 거절은 키워드 단계로 돌려보내 선택을 유지한 채 하단 버튼 위 안내 자리에 이 문구를 보이고, 다시 요청하면 새 `requestId`를 씁니다. 복구 조회가 `FAILED`를 알린 뒤 같은 `requestId`로 다시 보낸 요청이 거절돼도 같습니다. 스토리 완성 거절은 확정 완성 실패와 같이 추가 정보 단계 초안으로 되돌리고 이 문구로 알립니다. 이프 환불과 게스트 횟수 복원은 서버가 합니다.
- **평가** — 스토리라인별 좋아요·별로예요를 토글합니다. 300ms 디바운스 후 설정(`PUT`)·해제(`DELETE`)로 동기화합니다. 동일 평가를 다시 누르면 해제되고, 실패 시 상태를 되돌리고 실패 토스트를 표시합니다. **평가는 보조 신호이며 완성 페이로드에 포함되지 않고 진행을 막지 않습니다.**

### 추가 정보 진입·스토리라인 재선택

- 추가 정보 단계의 선택 스토리라인은 첫 렌더부터 한 줄로 접고 **더보기/접기 토글을 항상 렌더링**합니다. 내용 길이를 측정한 뒤 토글을 제거하지 않아 짧은 스토리라인에서도 첫 렌더 레이아웃이 움직이지 않아야 합니다.
- 자유 입력 제목은 "추가 정보 (최대 10개)"입니다. 처음에는 빈 입력 행 1개를 둡니다. 정보 추가 시 새 행이 보이도록 스크롤하되 초점을 옮겨 키보드를 열지 않습니다. 배치·Tab 이동은 웹 문서를 따릅니다.
- 자유 입력 아래에 제목 "이미지 스타일"로 화풍 선택을 두고, 다른 필수 항목처럼 제목에 `*`를 붙입니다. [제공 화풍](4-backend-server-spec.md#art-style-catalog)을 서버가 준 순서대로 3열 그리드에 놓고, 각 칸은 3:4 미리보기 이미지 아래 가운데에 흐린 배경을 깐 화풍 이름을 얹습니다. 미리보기가 없으면 스토리 썸네일이 없을 때와 같은 기본 심벌을 보입니다. 목록을 받는 동안 자리 표시 칸을, 받지 못하면 "이미지 스타일 목록을 불러오지 못했어요"와 다시 시도 버튼을 보입니다. 화풍은 필수이지만 처음에는 아무것도 고르지 않은 상태로 두고, 고른 칸은 primary 색 테두리로 표시합니다. 고르지 않고 "스토리 완성하기"를 누르면 이동하지 않고 키워드 단계의 선택 안내처럼 푸터에 "이미지 스타일을 선택해주세요"를 보이며, 화풍을 고르면 안내를 지웁니다. 고른 화풍은 스토리라인을 다시 골라도 유지하며 다시 선택하기 경고의 대상이 아닙니다.
- 이미지 스타일 아래에 일반 제작 등록 탭과 같은 공개 스위치(제목 "공개", 설명 "누구나 스토리를 찾아보고 플레이할 수 있어요")를 두고 켜진 상태로 시작합니다. 회원과 게스트 모두 고를 수 있습니다. 게스트가 공개로 만든 스토리가 공개 목록과 검색에 실리는 시점은 서버 계약을 따릅니다. 임시 저장과 재선택 때의 유지 규칙은 [Android 스펙](3-3-android-spec.md#간편-제작-흐름과-보존)과 같습니다.
- 추가 정보 푸터는 CTA 위에 "스토리 완성 비용"과 서버 `storyCreationCost`의 "N 이프"를 표시합니다([이프 정책 수치](../domain/PAYMENT/CLIENT/2-2-REQUIREMENTS.md#2-2-2-잔액과-비용)). 회원·게스트 공통으로 스토리 제작 체험(`GET /users/me/trials`의 `storyCreation`)이 남아 있으면 채팅 비용 배지와 같은 형식으로 정가에 취소선을 긋고 "0 이프"를 보이며, 다 썼으면 취소선 없이 "N 이프"만 보입니다.
- 추가 정보나 추천을 아직 고르지 않은 상태에서 "다시 선택하기"를 누르면 경고 없이 스토리라인 선택 단계로 돌아갑니다. 공백만 있는 자유 입력과 처음부터 놓인 빈 입력 행은 작성한 정보로 보지 않습니다.
- 공백이 아닌 자유 입력 또는 선택한 추천이 하나라도 있으면 `스토리라인을 바꿀까요? / 입력한 추가 정보는 모두 사라져요` 경고를 표시합니다. `닫기`는 단계·스토리라인·입력·추천을 모두 유지합니다. 파괴적 스타일의 `다시 선택하기`를 확정하면 선택 스토리라인, 자유 입력 전부, 추천 선택 전부를 초기화하고 스토리라인 선택 단계로 돌아갑니다.

### 임시 저장

간편 제작 임시 저장본의 서버 보관 계약입니다. Web과 Android가 같은 형식을 씁니다. 저장 시점과 이탈 확인은 플랫폼 스펙을 따르고, 상한, 용량, 충돌, 초안 없음 안내와 문구는 [FE-SCREEN-009 임시 저장](#fe-screen-009-일반-제작스토리-수정)과 같습니다.

- **저장 위치** — 퍼널을 열 때 로그인 상태 확인이 끝난 뒤 세션의 저장 위치를 정하고, 세션 동안에는 세션 재조회로 로그인 판정이 바뀌어도 바꾸지 않습니다. 회원이 새로 시작한 세션, 서버 초안으로 연 세션, 서버 초안을 가리키는 기기 안 기록으로 연 세션은 회원 계정의 서버 초안(`/users/me/story-drafts`, [`4-backend-server-spec.md` 스토리 제작 임시 저장](4-backend-server-spec.md#story-drafts))에 저장합니다. 게스트 세션과, 서버 연동 전이나 게스트 때 만든 기기 안 초안으로 연 세션은 기기 안에 저장합니다. 게스트 때 만든 스토리라인 생성 요청은 서버가 회원 초안에 연결하지 않고, 기존 초안을 한꺼번에 옮기면 회원당 5개 상한이 차므로 기존 기기 안 초안은 서버로 옮기지 않습니다.
- **초안 ID** — 퍼널 세션마다 하나로 고정한 UUID입니다. 키워드 초안에서 스토리라인 초안으로 넘어가도, 다시 만들어도 같은 ID의 서버 초안을 덮어씁니다. 저장 응답의 `version`을 다음 저장의 `baseVersion`으로 보내고 새 초안은 `baseVersion` 없이 보냅니다.
- **진행 기록** — 스토리라인 생성 중과 스토리 완성 중 기록, 생성 결과, 완성 실패로 되돌아온 초안은 요청한 기기 안에 두고 서버 초안 ID와 그때의 기준 버전을 함께 둡니다. 생성 결과는 받자마자 서버에 올리지 않고 그 제작의 다음 저장 때(충돌 확인에서 지금 내용으로 저장한 경우 포함) 서버 초안으로 옮긴 뒤 기기 안 기록을 지웁니다. 결과를 보기만 하고 떠난 제작은 서버 자리를 차지하지 않으며, 다른 기기는 그 전까지 이전 서버 초안을 봅니다.
- **요청** — `mode: "SIMPLE"`, `stage`는 키워드 단계 `KEYWORD_DRAFT`, 스토리라인 선택과 추가 정보 단계 `STORY_DRAFT`, `schemaVersion: 1`입니다. 서버는 `payload`를 해석하지 않습니다. `title`, `thumbnailObjectKey`는 null입니다. 각 필드의 형태는 웹 [간편 제작 payload 변환](../../../manyak-web/src/features/stories/_shared/utils/simple-draft-payload.ts)과 같습니다.
  - `KEYWORD_DRAFT`: `payload`는 키워드 입력 전체 `{selectedGenreTagIds, addedGenreTagIds, customGenreTags[{name, selected}], protagonist, supportingCharacters[]}`이고 인물은 `{name, gender, selectedTagIds, customTags[{name, selected}]}`입니다. `oneLineIntro`, `generationRequestId`는 null입니다.
  - `STORY_DRAFT`: `payload`는 `{step, generationRequest, activeStorylineIndex, selectedStorylineId, additionalInfos, selectedRecommendations, artStyle, visibility, createdStoryId, completionRequest}`입니다. `step`은 `storyline-select` 또는 `additional-info`, `generationRequest`는 지금 보이는 생성 결과를 만든 스토리라인 생성 요청 본문 전체(재생성과 선택한 키워드 보기에 씀. 다시 만들기가 실패해 이전 결과를 보고 있으면 이전 결과의 요청), `selectedStorylineId`는 고른 스토리라인 ID 또는 null이고, `artStyle`, `visibility`(`PUBLIC` 또는 `PRIVATE`), `createdStoryId`, `completionRequest`는 없으면 null입니다. `visibility`가 없는 초안은 공개로 엽니다. 생성 결과 원문은 넣지 않고 최상위 `generationRequestId`에 `generationRequest.requestId`를 넣어 연결합니다. `oneLineIntro`는 추가 정보 단계면 고른 스토리라인 본문, 그 밖에는 null입니다.
- **이어서 만들기** — 스토리라인 초안은 상세 응답의 `generation`이 완료(`COMPLETED`)이고 결과가 있어야 엽니다. 결과가 없으면 초안이 없을 때와 같이 "만들던 스토리를 찾지 못했어요"를 띄우고 새로 시작합니다. 고른 스토리라인을 결과에서 찾지 못하면 스토리라인 선택 단계로 열고, 빠졌거나 null인 선택 필드(키워드 초안의 `addedGenreTagIds` 등)는 빈 배열, 0, 없음으로 채웁니다. `schemaVersion`이 다르거나 `step`, `generationRequest`, 키워드 입력 형태를 읽을 수 없으면 불러오기 실패로 처리합니다.
- **완성** — 완성 요청 `POST /stories/simple`에 세션의 초안 ID를 `draftId`로 넣습니다. 서버가 완성 요청을 기록할 때 그 초안을 지웁니다.
- **제작 탭 카드** — 서버 간편 제작 초안 카드는 제목 "만들고 있는 스토리"이고, 설명 줄은 키워드 초안 "키워드를 선택하고 있었어요", 스토리라인 초안은 `oneLineIntro`(고른 스토리라인 본문, 2줄까지) 또는 없으면 "스토리라인을 선택하고 있었어요"입니다. 같은 제작의 기기 안 진행 기록이 있고 그 기록을 남긴 뒤 서버 초안이 다시 저장되지 않았으면(서버 `version`이 기록의 기준 버전 이하) 서버 카드를 숨겨 한 장으로 보이고, 그 기기 안 카드를 지우면 숨긴 서버 초안도 지웁니다. 기록을 남긴 뒤 다른 기기에서 저장한 서버 초안은 따로 보이고, 기기 안 카드를 지워도 남깁니다.
- 회원이 임시 저장한 간편 제작은 다른 기기에서 같은 계정으로 로그인해도 제작 탭에서 이어서 만들 수 있어야 합니다.

### 완성 제출과 복구

- 키워드·추가 정보의 검증을 통과한 요청만 전송합니다. 같은 요청의 재시도에는 같은 `requestId`와 명령을 사용합니다.
- 생성·완성 요청은 전송 전에 복구 가능한 형태로 저장합니다. 저장 실패를 제출 성공으로 표시하지 않습니다.
- 서버 결과를 받지 못한 경우 확정 실패와 구분하고, 복구 조회로 결과를 확인합니다. 백그라운드에서 화면용 폴링을 계속하지 않습니다.
- 사용자 편집·요청 전환·서버 결과 반영은 오래된 저장이 새 요청을 덮지 않도록 처리합니다. 저장 구조와 직렬화 수단은 플랫폼 설계가 소유합니다.
- 로그아웃·계정 변경 후 이전 계정의 제작 내용을 다른 계정에 표시하거나 이전 작업 결과를 새 세션에 반영하지 않습니다.

### 제작 카드와 다중 완성 진행

이 절은 초안과 완성 요청을 분리하는 계약입니다. Android의 적용 동작은 [Android 제작 계약](3-3-android-spec.md#제작과-데이터-보존), 웹의 적용 동작은 [웹 제작 계약](3-2-web-spec.md#웹-제작-흐름)이 소유합니다.

- 여러 편집 초안과 여러 완성 요청을 독립적으로 표시합니다. 새 제작은 기존 초안을 묻거나 지우지 않고 새 초안을 시작하며, 초안 재개는 진행 카드에서 합니다. 새 제작·초안 삭제는 다른 초안과 완성 요청을 지우지 않습니다.
- 회원은 만들고 있는 스토리 카드가 5장 이상이면 새 제작을 시작하지 않고 "만들고 있는 스토리는 5개까지 둘 수 있어요" 토스트로 안내합니다. 카드는 제작 탭과 같이 서버 초안과 이 기기의 생성 중, 생성 결과, 완성 실패 초안을 같은 제작 한 장으로 세고, 완성 중 카드와 검수 제출본 카드는 세지 않습니다. 새 제작으로 들어오는 모든 경로(제작 FAB, 제작 주소 직접 진입 등)에 적용하고 이어서 만들기는 막지 않으며, 목록을 읽지 못하면 막지 않습니다. 서버 초안은 회원당 5개까지이고 서버 초안 하나는 카드 많아야 한 장이라, 상한 아래에서 시작한 제작은 첫 저장에 서버 자리가 있습니다. 게스트는 서버 초안을 쓰지 않으므로 적용하지 않습니다.
- 제출 요청을 영속화한 뒤에는 완성 응답을 기다리지 않고 제작 탭으로 돌아옵니다. 자동으로 채팅방을 만들거나 채팅 화면에 진입하지 않습니다.
- 저장 실패 시 전송하지 않고 입력을 유지한 채 오류를 안내합니다. 제출 연타로 같은 요청이 중복 생성되지 않습니다.
- 완성 중 요청과 완성 스토리를 구분합니다. 서버 스토리와 같은 `storyId`의 로컬 완료 항목을 이중 표시하지 않습니다.
- 완료된 스토리는 상세 화면을 거쳐 사용자가 채팅을 시작합니다. 서버가 확정한 완성 실패는 완성 요청 카드를 남기지 않고 제출한 입력 그대로 그 초안의 추가 정보 단계 초안으로 되돌린 뒤 알리며, 같은 입력으로 다시 완성하면 같은 `requestId`를 씁니다. 안내 문구와 사유별 안내는 플랫폼 스펙을 따릅니다.

### 검수 기준

- 저장 실패에는 요청을 보내지 않고 입력을 유지합니다.
- 같은 요청의 재전송은 중복 스토리를 만들지 않으며, 불명확한 응답은 복구 조회 결과와 일치시킵니다.
- 초안 삭제·새 제작은 다른 초안과 완성 요청에 영향을 주지 않습니다.
- 플랫폼의 제출 후 목적지·이탈·저장 계약을 충족하고, 계정 변경 뒤 다른 회원의 데이터가 노출되지 않습니다.

### 요청 헤더

논리 `device_id`·`session_id`의 의미는 [분석](6-analytics.md#6-2-식별자-정책)이 정본입니다. 플랫폼은 같은 의미의 값을 API 헤더와 분석 SDK에 사용합니다. 초기화·필수 헤더·누락 처리의 플랫폼별 보장은 해당 설계에서 정합니다.

| 헤더                  | 값                     |
| --------------------- | ---------------------- |
| `X-Manyak-Device-Id`  | 논리 `device_id`       |
| `X-Manyak-Session-Id` | 논리 `session_id`      |

두 헤더가 없어도 일반 요청은 거부되지 않습니다(백엔드가 `unknown`으로 채움). 단 **`X-Manyak-Device-Id`가 정책상 필수인 경로**가 있습니다 — 게스트 체험 한도 대상 요청(누락 시 400 — [`4-backend-server-spec.md §4-3-7`](4-backend-server-spec.md)), 첫 로그인의 회원 체험 시드([`4-backend-server-spec.md §4-3-5`](4-backend-server-spec.md)). `X-Manyak-Session-Id`는 모든 경로에서 best-effort입니다.

**요청 식별자** — `X-Manyak-Request-Id`는 백엔드가 생성·응답하는 상관관계 값이며 클라이언트가 만들지 않습니다. 제작 본문의 `requestId`는 멱등·복구용 별개 값입니다.

| 요청 필드 | 전달 기준 |
| --- | --- |
| 채팅 `userSource` | `choice`·`edited_choice`·`typed`. 아래 판정 사용, 허용값 밖은 400 |
| 채팅 `sourceTurnId`·`choiceOrder` | 직전 턴 `turns[].id`와 선택지 인덱스 + 1. 시작 추천·직접 입력에는 보내지 않음. 선택 필드이며 낡거나 범위 밖이면 서버가 연결 기록만 생략 |
| 스토리라인 `parentCreationId` | 최초 `null`, 재생성은 바로 직전 스토리라인 요청 UUID(`trace_creation_id`). `simpleCreationId`·`analytics_creation_id`와 구분. 서버 검증 불일치는 부모 연결만 생략 |

서버 전달 형식은 [백엔드](4-backend-server-spec.md), 분석 식별자 의미는 [분석](6-analytics.md#6-2-식별자-정책)을 따릅니다.

**입력 출처 판정** — 아래 규칙을 따릅니다. 플랫폼별 판정 함수와 QA 연결은 각 설계·QA가 소유합니다.

- 선택지 본문 탭과 무작위 추천 전송(Play 버튼)은 대조 없이 `choice`입니다. 두 경로 모두 전송 전에 사용자가 문장에 손댈 기회가 없습니다.
- "채우기"로 입력창에 넣고 보내는 경로는 전송 시점의 텍스트를 채운 원문과 대조해 가릅니다 — 같으면 `choice`, 다르면 `edited_choice`입니다. 앞뒤 공백 차이는 같은 것으로 보고, **블럭 모드에서 채우면 블럭으로 파싱했다가 다시 직렬화되어 문자열이 달라지므로 그 왕복 결과도 "그대로"로 인정합니다** — 사용자가 손대지 않았는데 `edited_choice`가 되면 선호 신호가 오염됩니다.
- 채운 뒤 모두 지우고 새로 써도 `edited_choice`입니다.
- 채우기를 쓴 적이 없으면 `typed`입니다. 기억해 둔 원문은 전송에 성공하면 비워, 다음 턴 입력이 앞 턴에서 채운 선택지와 대조되지 않게 합니다.

### 화면별 API 사용

호출·성공·실패 처리는 [화면별 계약](#3-1-3-화면별-스펙), [제작](#3-1-4-스토리-생성-퍼널), [채팅](../domain/CHAT/CLIENT/AGENTS.md)을 따릅니다. 인증 판정은 플랫폼 세션이 소유하며 `GET /auth/me`는 회원 정보·잔액 조회에 사용합니다.

- 삭제 API의 204는 완료 안내, 404는 무음 성공으로 목록에 반영합니다. 다른 실패는 낙관적 제거를 되돌리고 안내합니다.
- 로그아웃과 탈퇴의 정리 경계는 [ACCOUNT 세션 종료](../domain/ACCOUNT/CLIENT/3-2-INTERACTION-FLOWS.md#3-2-4-로그아웃과-탈퇴)를 따릅니다.
- 수정 API의 403은 "수정 권한이 없어요" 안내 후 상세로 복귀합니다.
- 출석·초대는 `POST /users/me/credits/attendance`, `GET /users/me/invite`, `POST /users/me/invite/redeem`을 사용합니다. 잔액·출석 여부는 `GET /auth/me`의 `creditBalance`·`attendedToday`로 표시합니다.

### 이프 정책 수치 표시

PAYMENT 내용은 도메인 문서에서 관리한다. ([정책과 비용](../domain/PAYMENT/CLIENT/2-2-REQUIREMENTS.md#2-2-2-잔액과-비용))

### 날짜 표시 기준

서버 시각(`createdAt`·`expiresAt`·`updatedAt`)은 ISO 8601 UTC입니다. 이프 내역 발생일·만료일, 스토리 상세·제작 카드의 절대 날짜는 `Asia/Seoul`로 변환한 `YYYY-MM-DD`를 표시합니다. UTC 문자열 앞 10자를 자르거나 기기 시간대를 사용하지 않습니다.

채팅 목록의 상대 시간·오늘·어제는 기기 시간대를 사용합니다. 웹 제작 카드의 당일 상대 시간 예외는 [웹 제작 계약](3-2-web-spec.md#웹-제작-흐름)을 따릅니다.

### 응답·에러 처리 정책

- 정상 조회 결과가 비어 있을 때만 빈 상태를 표시합니다. 첫 조회 실패는 오류·재시도, 추가 조회 실패는 기존 목록을 유지한 재시도로 처리합니다.
- 백엔드 에러는 `ApiErrorResponse {timestamp, status, code, message, path, details[]}` 형태이며 `details`는 `{field, message}[]`입니다.
- 읽기 재시도·화면 복귀 재조회는 플랫폼 Design을 따릅니다. [웹 TanStack Query 기본 옵션](../design/1-1-web-design.md#데이터-패칭-기본-옵션-웹)을 공통 플랫폼 계약으로 적용하지 않습니다.
- 서버 원본 메시지·스택은 사용자에게 그대로 노출하지 않습니다. 회원의 인증 실패는 플랫폼의 재발급·세션 종료 절차를 거치며 화면마다 별도 세션 판정을 만들지 않습니다.

### 화면 상태 처리 (로딩·빈·에러)

화면별 상태는 각 화면 스펙([§3-1-3](#3-1-3-화면별-스펙))에 정의하며, 공통 규칙은 다음과 같습니다.

| 상황                 | 처리                                                                                |
| -------------------- | ----------------------------------------------------------------------------------- |
| 목록·상세 최초 로딩  | 지연 로딩(빠른 응답 시 스켈레톤 깜빡임 방지). 지연 전에는 아무것도 표시하지 않음    |
| 버튼 클릭 후 요청 중 | 버튼 비활성화 + 기존 문구 공간을 유지한 중앙 스피너. 버튼의 접근 가능한 이름은 유지 |
| 목록 조회 실패       | 재시도 가능한 에러 안내                                                             |
| 뮤테이션 실패        | 실패 토스트                                                                         |
| 라우트·렌더 오류     | "문제가 발생했어요" + 재시도(루트 오류는 Sentry 보고)                               |
| 존재하지 않는 경로   | "페이지를 찾을 수 없어요" + 홈 링크                                                 |

## 3-1-8. 입력·폼 검증 규칙

피드백·키워드·추가 정보·채팅과 일반 제작·수정의 입력 계약입니다. 소셜 로그인 버튼 자체는 입력 폼 검증 대상이 아닙니다.

### 일반 제작·수정 폼

서버 계약([`4-backend-server-spec.md §4-3-8`](4-backend-server-spec.md))과 동일한 규칙을 클라이언트에서 선검증합니다: 기본 주인공 이름은 선택이며 입력 시 trim 후 1~30자(기본 주인공 이름을 뺀 글 입력 어디에든 `{username}`이 있는데 이름이 비었으면 주인공 이름 칸에 "{username}을 쓰려면 이름을 입력해 주세요"를 표시하고 등록하지 않음), 제목 ≤ 100자, 한 줄 소개 ≤ 255자, 시작 설정 이름 ≤ 100자, 장르 1~8개(각 30자 이내), 주요 내용 ≤ 1,000자(클라이언트 전용 상한), 스토리 설정 4필드·시작 설정 3필드·추천 입력 3개 필수. 주요 사건 ≤ 10개(각 이름·설명·키 문장 필수, 이름 ≤ 100자이며 스토리 안에서 겹치지 않음, 설명 ≤ 1,000자, 키 문장 ≤ 200자). 시작 상황은 1~3개이며 상황 이름 ≤ 100자, 프롤로그·상황 설명 ≤ 1,000자, 추천 입력 각 ≤ 200자(채팅 입력 상한 3,000자 안), 엔딩은 시작 상황당 0~3개로 엔딩 이름 ≤ 100자(같은 시작 상황 안에서 겹치지 않음), 최소 턴 수 0~50(비우면 필수 입력 오류), 달성 조건·에필로그 ≤ 500자입니다(서버 상한은 이름 100자·엔딩 10개뿐이라 나머지는 클라이언트 전용 상한). 주변 인물 1~5명(이름 유일하며 주인공 이름과도 겹치지 않음, 이름 ≤ 30자, 인물 소개는 선택이며 토큰 포함 원문 한 줄 ≤ 150자), 인물당 이미지 ≤ 10장(이름 `{인물이름}_{접미}`, 같은 인물 안에서 유일), 이미지는 jpeg·png·webp 5MB 이하입니다. 필수 항목이 있는 탭은 탭 이름에 `*`를 붙이고, 필수 미충족이면 등록하기를 눌렀을 때 등록하지 않고 탭과 칸에 오류를 표시합니다(FE-SCREEN-009). 기본 주인공 이름을 제외한 모든 글 입력(제목·한 줄 소개·스토리 설정·주변 인물 이름·인물 소개·특징·시작 상황의 글·추천 입력·엔딩의 글·주요 사건의 글)은 클라이언트에서만 앞뒤 공백을 뺀 2자 이상을 요구합니다(서버는 공백이 아닌 1자부터 허용). 1자만 입력하고 칸을 벗어나면 입력 칸 아래 설명 문구 자리에 설명 대신 "{칸 이름}은(받침이 없으면 는) 2자 이상 입력해 주세요"(예: "제목은 2자 이상 입력해 주세요", "프롤로그는 2자 이상 입력해 주세요")를 표시하고, 비어 있는 경우는 필수 검사가 맡습니다. 인물 이름·인물 소개·특징의 칸 이름은 "이름"·"인물 소개"·"특징"이고, 추천 입력 3칸은 한 설명 자리를 함께 써 1자인 칸에 오류 테두리를 둡니다. 숫자 칸인 최소 턴 수는 대상이 아닙니다. 이름 중복 오류가 함께 걸리면 중복 오류를 먼저 표시합니다.

### 키워드·커스텀 키워드 (퍼널)

[키워드 선택 규칙](#키워드-선택-규칙)과 인물 단위 입력의 상한·필수·이름 중복 검증을 따릅니다. 웹의 `]` 제한은 [웹 제작 계약](3-2-web-spec.md#웹-제작-흐름)이 소유합니다.

### 추가 정보 (퍼널)

- 추천 추가 정보 토글 + 자유 텍스트 행(추천 추가 정보 최대 3개, 자유 텍스트 UI 최대 10개, 각 100자). 공백 제거 후 비어 있지 않은 값만 전송합니다.
- 전송 페이로드 `additionalInfos`(추천 추가 정보 + 자유 텍스트)의 서버 검증 상한은 총 13개입니다.
- 완성 요청에는 고른 화풍 코드를 `artStyle`로 함께 보냅니다. 화풍을 고르지 않으면 요청하지 않습니다. 화풍이 다르면 다른 명령이므로 이전 완성 요청의 `requestId`를 재사용하지 않습니다.
- 완성 요청에는 공개 스위치 값을 `visibility`(`PUBLIC` 또는 `PRIVATE`)로 함께 보냅니다. 공개 범위가 다르면 다른 명령이므로 `requestId`를 재사용하지 않습니다. 공개 범위 없이 보낸 이전 요청은 서버가 비공개로 받았으므로 비공개와 같은 명령으로 봅니다. 완성에 실패해 초안으로 되돌릴 때도 이 기준으로 스위치를 되살립니다.

### 검증 표시 원칙

- 필드 단위 오류는 해당 필드 근처에, 폼·요청 단위 오류는 토스트로 표시합니다.
- 오류는 해당 필드와 프로그램적으로 연결해 보조기술에 노출합니다. 구현 수단은 플랫폼 소유입니다(웹: `aria-invalid`·`role=alert` — [3-2-web-spec.md §3-2-5](3-2-web-spec.md#3-2-5-반응형접근성브라우저-지원) / 앱: 접근성 시맨틱 — [Android Spec](3-3-android-spec.md#3-3-4-디바이스접근성상태-복원)).
- 비밀번호·토큰 등 민감 입력은 없으며, 자유 입력 원문은 로그·이벤트에 수집하지 않습니다([`6-analytics.md §6-7`](6-analytics.md)).
