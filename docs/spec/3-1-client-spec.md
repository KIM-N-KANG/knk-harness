## 3-1-1. 문서 목적·범위와 관련 문서

웹·Android 공통의 사용자 동작·입력·상태·오류·데이터 보존과 수용 기준을 정의합니다. 화면·흐름의 규칙과 상태 표가 수용 기준이며 US·FE-SCREEN·FLOW 식별자를 유지합니다.

- 플랫폼 차이: [웹 Spec](3-2-web-spec.md)·[Android Spec](3-3-android-spec.md). 내부 구조·표현 값은 각 Design, 선택 이유는 [공통 ADR](../adr/1-1-client-adr.md)을 따릅니다.
- API 형식·서버 정책은 [백엔드](4-backend-server-spec.md), 이벤트·식별자는 [분석](6-analytics.md), 용어는 [용어집](0-glossary.md)이 정본입니다. 아래 API 경로는 `/api/v1`을 생략합니다.

## 3-1-2. 공통 계약과 플랫폼 경계

회원의 스토리·채팅 목록은 서버가 소유합니다. 생성·삭제 후 화면은 서버 결과와 일치해야 합니다. 익명 체험·브라우저 저장·회원 이관은 웹 전용이며 [웹 사용자 모델](3-2-web-spec.md#웹-사용자-모델)이 소유합니다. Android는 로그인 후 서비스에 진입합니다.

스토리 생성 요청의 복구 식별자, 채팅의 턴·스트림 의미, 서버 정책 수치의 표시, 신고·계정·법적 문서 계약은 공통입니다. URL, 브라우저 이력, SDK, 저장 기술, 모듈·스코프는 이 문서에서 정하지 않습니다.

### FE-SCREEN-001. 홈 — 오리지널 스토리 목록

| 항목     | 값                                      |
| -------- | ---------------------------------------------- |
| 관련 API | `GET /stories/originals`                       |
| 관련 US  | US-2-2, US-2-7·2-8             |

**목적** — 마냑 공식 계정의 오리지널 스토리를 탐색하고 상세로 진입합니다. 내가 만든 스토리 관리와 제작 진입은 FE-SCREEN-013 제작 탭이 담당합니다.

**진입 조건** — 인증·온보딩 정책을 충족하면 홈을 기본 화면으로 엽니다. 진입 정책은 각 플랫폼 스펙이 소유합니다.

**화면 구성** — "오리지널 스토리" 제목과 2열 카드 그리드입니다. 카드에는 `thumbnailUrlSm`(없으면 placeholder), ORIGINAL 태그, 누적 턴 수, 제목·제작자 각 1줄을 표시합니다. 제작자는 `author.nickname` 앞에 `@`를 붙이고 같은 행의 카드 높이와 제작자 줄을 맞춥니다. 카드 탭은 상세로 이동합니다. 내 스토리·제작 CTA·진행 카드는 표시하지 않습니다. 좋아요 UI는 아래 비노출 계약을 따릅니다.

**ORIGINAL 태그** — 오리지널 카드에만 표시합니다. 반투명·블러 등 표현 값은 [웹 표현](../design/1-1-web-design.md#웹-표현-값)을 따릅니다.

**데이터 소스** — 인증 없이 `GET /stories/originals`를 조회하며 게스트·회원 모두 서버 등록순을 그대로 유지합니다. 공식 계정이 설정되지 않은 환경은 빈 목록입니다.

**상태**

| 상태    | 조건                                | UI                                                                                                       |
| ---------- | ---------------------- | -------------------------------------------------------------------------------------- |
| 로딩       | 오리지널 목록 조회 중  | 지연 후 제목 1개 + 오리지널 카드 6개 형태(썸네일·제목·제작자)의 스켈레톤. 지연 전에는 비움 |
| 빈 상태    | 응답이 빈 배열         | 오리지널 섹션을 표시하지 않음                                                        |
| 에러       | 조회 실패              | 제목 유지 + "스토리를 불러오지 못했어요" + 다시 시도                                |
| 기본       | 오리지널 스토리 존재   | 제목 + 2열 오리지널 카드 그리드                                                      |

### FE-SCREEN-013. 제작 — 내 스토리 목록

| 항목     | 값                                      |
| -------- | -------------------------------------------------------------------------- |
| 관련 API | `POST /stories/batch`(게스트), `GET /users/me/stories`(회원)                |
| 관련 US  | US-2-1·2-3·2-4·2-6·2-8                                     |

**목적** — 내가 만든 스토리를 확인·관리하고 새 제작 또는 진행 중 제작을 이어갑니다.

**진입 조건** — 하단 제작 탭에서 진입합니다. 제작·편집 화면의 진입 경로는 각 플랫폼 스펙이 소유합니다.

**화면 구성** — 제작 헤더 아래에 별도 섹션 제목 없이 내 스토리 가로 카드 목록과 제작 진행 상태를 표시합니다. 초안·완성 요청의 계약은 §3-1-4가 소유합니다. 완성 스토리가 있으면 새 제작 FAB를, 빈 상태에서는 제작 CTA를 표시합니다. 플랫폼별 진행 카드·배너의 적용 범위는 플랫폼 스펙을 따릅니다.

내 스토리 카드는 전체 폭을 사용하며 패딩 영역까지 탭할 수 있습니다. 표지(없으면 placeholder), 제목·소개 최대 2줄, 장르 1줄(초과 `+N`), 누적 턴 수·KST 제작일 순으로 표시합니다. 옵션 다이얼로그의 축소판과 스켈레톤도 같은 구성을 사용합니다. 좁은 화면·큰 숫자에서는 지표 단위로 줄바꿈해 잘림을 막습니다. 픽셀·호버·아이콘 배치는 [웹 표현](../design/1-1-web-design.md#웹-표현-값)을 따릅니다.

**데이터 소스** — 회원은 `GET /users/me/stories`의 서버 목록을 사용합니다. 익명 체험 목록은 [웹 스펙](3-2-web-spec.md#웹-사용자-모델)이 소유합니다.

**사용자 액션**

| 액션             | 트리거                    | 결과                                                                                                                                                                                                                                                                                                                                                                                |
| --------- | ----------------------------------- | ------------------------- |
| 상세 이동 | 카드 탭                             | 스토리 상세로 이동    |
| 생성 시작 | FAB 또는 빈 상태 CTA                | 간편 제작으로 이동    |
| 제작 재개 | 진행 카드의 "이어서 만들기"        | 제작 복구 흐름 |
| 신고      | 내가 만든 카드의 옵션 다이얼로그 → "신고하기" | 스토리 신고 시트 열기([FE-SCREEN-003](#fe-screen-003-스토리-상세) **스토리 신고**). 회원에게만 표시 |
| 삭제      | 내가 만든 카드의 옵션 다이얼로그 → "삭제하기" → 확인 | 낙관적으로 카드를 제거하고 현재 제작 목록 화면 유지 |

**카드 옵션 다이얼로그** — 화면 가운데에 선택 카드의 축소판과 "신고하기"(회원만) → "삭제하기"(파괴적 표기)를 표시합니다. 삭제하기를 고르면 같은 다이얼로그를 확인 화면으로 전환합니다.

**스토리 삭제** — 자신의 스토리에서만 삭제를 제공합니다. 오리지널 카드에는 옵션 버튼을 표시하지 않습니다. 서버 실패 시 항목과 사용자 접근 경로가 유실되지 않아야 합니다. 웹 게스트의 로컬 ID 정리는 웹 스펙이 소유합니다.

**상태**

| 상태    | 조건                                | UI                                                                                                       |
| ------- | ------------------------------------- | -------------------------------------------------------------------------------------- |
| 로딩    | 저장 ID·세션 미확정 또는 목록 조회 중 | FAB 숨김 + 지연 스켈레톤. 지연 전에는 목록 영역을 비움       |
| 빈 상태 | 저장된 스토리 없음                    | FAB 숨김 + "아직 만든 스토리가 없어요" + "스토리 만들기" CTA |

| 기본    | 스토리 존재                           | 오른쪽 아래 primary FAB + 1열 가로 카드 목록                 |

### FE-SCREEN-003. 스토리 상세

| 항목     | 값                                      |
| -------- | -------------------------------------------------------------------------------------------------- |
| 관련 API | `GET /stories/{storyId}`, `POST /chats`, `POST /chats/batch`(게스트 본 엔딩 합산) , `POST /stories/{storyId}/reports`  |
| 관련 US  | US-4-1 ~ US-4-4, US-4-6 , US-4-7·4-8                          |

**목적** — 스토리 설정과 가능한 엔딩을 확인하고 바로 채팅을 시작합니다.

**진입 조건** — 목록에서 스토리를 선택하거나 플랫폼이 지원하는 직접 진입 경로로 엽니다. 접근 권한은 서버가 판정합니다.

**화면 구성** — 화면 전체 세로 컬럼입니다. 상단 헤더(back·제목이 화면 밖으로 나가면 나타나는 헤더 제목), 스크롤 본문(하단 페이드), 하단 CTA로 구성합니다. 썸네일이 있으면 헤더를 히어로 위에 겹치고, 첫 위치에서는 투명 배경·흰색 back을 사용합니다. 스크롤이 히어로 하단으로 갈수록 배경은 화면 배경색으로, back·제목은 기본 전경색으로 연속 전환합니다. 헤더 위에 별도 그라데이션은 두지 않습니다. 썸네일이 없거나 로딩·오류 상태이면 처음부터 불투명 배경과 기본 전경색을 사용합니다.

| 본문 영역                     | 내용                                                                                                                                                                            | 표시 조건                   |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| 썸네일 히어로                 | 3:4 비율. `thumbnailUrl`이 있으면 이미지, 없으면 placeholder 아이콘. 우하단에 누적 턴 수(`turnCount`) 배지를 오버레이(천 단위 콤마, 누락 값은 0). 좋아요 수 배지는 현재는 표시하지 않음 — [스토리 좋아요](#fe-screen-003-스토리-상세) 절 참조. 이미지가 있을 때 탭하면 풀스크린 이미지 뷰어 | 항상                        |
| 제목                          | `title`                                                                                                                                                                         | 항상                        |
| 한 줄 소개                    | `oneLineIntro`                                                                                                                                                                  | 항상                        |
| 장르 배지                     | 장르 태그                                                                                                                                                                       | 항상                        |
| 본 엔딩 배지  | 도달한 엔딩 이름을 장르와 같은 보조 배지로 표시. 회원은 상세 응답 `reachedEndings`를 사용합니다. 익명 체험의 합산은 [웹 스펙](3-2-web-spec.md#웹-사용자-모델)을 따릅니다 | 도달한 엔딩이 1개 이상일 때 |
| 주요 내용                     | `description`                                                                                                                                                                   | 값이 있을 때                |
| 주변 인물                     | `characters[]`(저장 순서) — 인물마다 이름을 소제목으로 두고 그 아래 인물 이미지를 채팅 화면과 같은 4:3 카드로 표시합니다. `imageUrl`이 null인 인물(이미지 생성 실패)은 이름만 남깁니다. 인물별 소개 텍스트는 응답에 없습니다([`4-backend-server-spec.md §4-3-1`](4-backend-server-spec.md) 인물 목록의 범위) | 이름 있는 인물이 1개 이상일 때 |
| 채팅 시작 상황 | `startSettings[]` — 상황 이름 Select(첫 번째가 기본 선택)와 선택한 설정의 상황 설명(`startSituation`). 프롤로그는 상세에 표시하지 않고 채팅 화면에서 노출합니다 | 시작 설정이 1개 이상일 때 |
| 시작 상황별 엔딩              | 선택한 시작 설정의 `endings[].name`을 세로 목록으로 표시. 정보 버튼은 "엔딩은 시작 상황마다 달라요" 안내를 표시하며, 달성 조건·에필로그는 노출하지 않습니다                    | 선택 설정에 이름 있는 엔딩이 있을 때 |
| 제작자·생성일 | 본문 끝의 단일 메타 블록. 제작자는 `author.nickname`을 `@` 없이 그대로 표시하고, 생성일은 `createdAt`(KST 기준 YYYY-MM-DD — [§3-1-7 날짜 표시 기준](#날짜-표시-기준))을 표시합니다 | 둘 중 하나라도 값이 있을 때 |

**썸네일 이미지 뷰어** — 썸네일을 누르면 전체 화면으로 엽니다. 닫기 제어·화면 탭·뒤로가기로 닫으며, 뒤로가기는 상세 화면을 떠나지 않고 뷰어만 닫아야 합니다. 이미지가 없으면 뷰어를 열지 않습니다.

**스토리 좋아요** — 좋아요 버튼과 좋아요 수 배지를 표시하지 않습니다.

**스토리 신고** — 상세·채팅·제작 목록·채팅 목록에서 같은 스토리 신고 시트를 엽니다. 채팅에서도 대상은 참조 `storyId`입니다. 회원에게만 제공하며, 참조 스토리가 삭제되어 제목이 없는 채팅에는 표시하지 않습니다. 진입점 배치는 플랫폼 스펙을 따릅니다.

| 조건 | 동작·수용 기준 |
| --- | --- |
| 입력 | 사유 3개(도배·홍보 / 부적절한 내용 / 기타)는 행 전체로 선택. 선택 상세는 최대 500자와 카운터. 빈 상세는 `null` |
| 제출 | 사유 선택 전 비활성. `POST /stories/{storyId}/reports {reason, detail}` 전송 중에는 크기를 유지한 스피너를 표시하고 제출·닫기를 잠금 |
| 성공·실패 | 201이면 시트를 닫고 접수 토스트. 실패면 시트·입력을 유지하고 실패 토스트 |
| 재신고 | 같은 회원의 같은 스토리도 제출 가능. 서버 멱등 처리 사용 |

시트에는 제목·설명·사유·상세·파괴적 "신고하기"·보조 텍스트 "닫기"를 순서대로 표시합니다.

| 액션             | 트리거                    | 결과                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| 삭제하기         | 헤더 오른쪽 더보기 메뉴   | 내가 만든 스토리(회원은 상세 응답 `isOwner`, 게스트는 로컬 서재에 해당 `storyId`가 있을 때)에만 표시. 확인 다이얼로그 확정 시 삭제 후 제작 목록으로 이동. 항목 순서는 신고하기 → 삭제하기(파괴적)                                                                                                                                                                  |

**상태** — 지연 후 실제 본문 구조의 스켈레톤 / 로드 실패 시 인라인 오류와 다시 시도 / 404 시 "스토리를 찾을 수 없어요" / 기본 본문·CTA. 헤더는 항상 유지합니다. 타이밍·크기는 [웹 표현](../design/1-1-web-design.md#웹-표현-값)을 따릅니다.

**추가 수용 기준** — 신고·삭제 중 어느 항목도 제공할 수 없으면 더보기 버튼을 숨깁니다. 404에는 재시도를 두지 않습니다.

### FE-SCREEN-008. 로그인·마이 페이지

| 항목     | 값                                      |
| ------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 관련 US | US-9-1 ~ 9-11, US-10-1 ~ 10-6                                                                                                 |

**목적** — 소셜 계정으로 로그인하고 프로필·연동 계정·이프·친구 초대·로그아웃·탈퇴를 관리합니다. 익명 체험 데이터의 계정 이관은 웹 전용입니다.

**진입점** — 마이 탭에서 회원 정보와 계정 관리 기능을 엽니다. 로그인 전 진입과 인증 후 목적지는 플랫폼 스펙이 소유합니다.

**마이 페이지 회원 상태 구성** — 닉네임·프로필 이미지·연동 계정·이프 잔액·친구 초대·로그아웃·회원 탈퇴를 표시합니다. 이프 카드에는 "충전" 버튼 하나를 두며 출석 체크는 무료 충전 탭에서 제공합니다. 친구 초대 아래 "하고 N 이프 받기"를 표시하고 N은 서버 `inviteReward`를 사용합니다. 계정 섹션은 기본색 로그아웃 → 위험색 탈퇴 순서입니다. 테마·피드백·서비스 안내는 비로그인 상태에서도 제공합니다. 헤더와 하단 네비게이션의 접근 가능한 이름은 "마이"입니다.

**이프 충전**(US-10-6) — 마이의 "충전" 버튼으로 진입합니다. 회원 접근·URL은 플랫폼 스펙을 따릅니다.

- **화면 골격** — "이프 충전" 뒤로가기 헤더 아래 잔액·탭은 고정하고 패널만 스크롤합니다. 구매·무료 충전·내역 세 탭의 기본값은 구매입니다.
- **잔액 박스** — "내 이프" 아래 잔액을 크게, 오른쪽 정렬·천 단위 콤마로 표시합니다. 진입 시 `GET /auth/me`의 `creditBalance`를 다시 읽으며 내역 합계로 계산하지 않습니다.
- **유료 충전** — 구매 탭에 상품을 서버 순서대로 한 줄씩 표시합니다. 한 줄은 왼쪽 기본 이프 라벨("N 이프")과 오른쪽 플랫폼 가격("N원") 강조색 버튼이며, 보너스가 있는 상품만 기본 이프 아래 "+N 이프"를 강조색·굵게 덧붙입니다. 목록 아래에 "구매한 이프는 적립일로부터 5년 동안 사용할 수 있어요"를 안내합니다. 가격 버튼을 누르면 결제 준비 중 스피너와 함께 모든 가격 버튼을 잠그고, 결제 시작에 실패하면 "결제를 시작하지 못했어요" 토스트 후 버튼을 다시 엽니다. 상품 조회 실패는 목록 자리에 "충전 상품을 불러오지 못했어요"와 "다시 시도하기"를 표시합니다. 플랫폼 결제 진입·검증 수단은 각 플랫폼 스펙이 소유합니다. 서버 상품·주문 API는 [백엔드](4-backend-server-spec.md)가 정본입니다.
- **결제 결과** — 결제창에서 돌아온 뒤 주문이 `COMPLETED`가 될 때까지 "결제를 확인하고 있어요"를 표시하고, 복귀 자체를 적립으로 간주하지 않습니다. `COMPLETED`는 "N 이프가 충전됐어요"(N은 주문 `totalCredits`)와 함께 잔액을 다시 읽고, `REFUNDED`는 "환불된 주문이에요", 없는 주문(404)은 "확인할 수 없는 주문이에요"를 표시합니다. 약 60초가 지나도 `PENDING`이면 "아직 결제 확인이 안 됐어요", 조회 오류는 "결제 확인에 실패했어요"를 표시하고 "다시 확인"으로 확인을 재개합니다. 결과 안내는 사용자가 닫거나 화면을 떠날 때까지 유지합니다.

| `reason` | 라벨 |
| --- | --- |
| `SIGNUP_REWARD` | 가입 보상 |
| `ATTENDANCE_REWARD` | 출석 체크 보상 |
| `INVITE_REWARD` | 친구 초대 보상 |
| `REFUND` | 사용 취소 |
| `STORY_CREATION` | 스토리 완성 |
| `CHAT_TURN` | 채팅 전송 |
| `CHAT_IMAGE` | 채팅 실시간 이미지 생성 |
| `EXPIRE` | 기간 만료 |
| `PURCHASE` | 이프 구매 |
| `PURCHASE_REVERSAL` | 구매 환불 |

- **금액 표기** — `type=EARN`은 `+`, `SPEND`·`EXPIRE`는 `-`와 `abs(amount)`의 천 단위 콤마를 사용합니다.
- **제목·날짜** · `title`이 있으면 라벨 아래 한 줄로 표시하고, 소모·사용 취소인데 `title`이 없으면(삭제된 스토리) "삭제된 스토리"로 대체합니다. 보상·소멸 항목은 제목 줄을 그리지 않습니다.  구매·결제 환불 회수도 `title=null`이므로 제목 줄을 그리지 않습니다. 날짜는 `createdAt`(KST 기준 YYYY-MM-DD · [§3-1-7 날짜 표시 기준](#날짜-표시-기준))이며, `expiresAt`이 있으면 "YYYY-MM-DD 만료"를 함께 표시합니다 · 획득은 만료 예정일, 소멸은 회수된 로트의 실제 만료일입니다. **소멸 항목의 `createdAt`을 만료일로 읽지 않습니다**(지연 정리라 실제 만료보다 늦습니다).
- **페이징** — 목록 끝에 닿으면 응답의 `nextCursor`를 그대로 실어 다음 페이지를 이어 붙입니다. 커서는 불투명 문자열이라 파싱하거나 조립하지 않고 받은 값을 되돌려 줍니다. `nextCursor`가 없으면 마지막 페이지입니다.
- **화면 상태** — 첫 조회 중에는 잔액 상자와 내역 목록 자리에 각각 골격을 표시합니다. 항목이 하나도 없으면 "아직 이프 내역이 없어요"를 표시하고, 첫 조회 실패는 "이프 내역을 불러오지 못했어요"와 다시 시도하기를 목록 자리에 둡니다(친구 초대 코드 카드와 같은 처리). 다음 페이지 조회 실패는 **이미 그린 목록을 지우지 않고** 재시도만 제공합니다.

**테마 변경** — 화면 섹션의 테마 변경 메뉴는 탭할 때마다 시스템 설정 → 라이트 모드 → 다크 모드 순으로 순환합니다. 왼쪽 아이콘(모니터·해·달)과 오른쪽 현재 값 문구가 함께 바뀌고 테마는 즉시 적용됩니다. 선택값은 기기 단위로 저장됩니다.

**친구 초대** — 마이에서 회원 전용 친구 초대 화면으로 이동합니다.

- **보상 안내** — 화면 상단에는 "친구가 내 초대 코드를 등록하면 모두 N 이프를 받아요"를 표시합니다(N은 서버 정책의 `inviteReward` — [§3-1-7 이프 정책 수치 표시](#이프-정책-수치-표시)).
- **초대 코드 카드** — `GET /users/me/invite`로 내 코드와 월 보상 횟수를 조회합니다. 별도 카드에 코드 복사와 공유 버튼을 표시합니다. 공유 수단과 사용 가능 판정은 각 플랫폼 스펙·설계가 소유합니다.

**이프 부족 처리** — 서버의 402를 최종 판정으로 사용합니다. 무료인 채팅방 생성에는 잔액 부족 차단을 적용하지 않습니다. 완성·채팅·재생성의 안내 위치는 각 흐름의 계약을 따릅니다. 게스트 사용량 선차단과 로그인 유도는 웹 스펙을 따릅니다.

회원의 채팅 턴 이프 부족 안내와 제작 제출 실패 안내는 각 플랫폼의 해당 흐름을 따릅니다. 서버가 실패를 반환한 요청을 성공으로 표시하거나 잔액을 임의 차감하지 않습니다.

**소셜 로그인** — Google과 Kakao를 제공합니다. 로그인 화면에서는 카카오 버튼을 Google 위에 배치합니다. 한 플랫폼 안에서는 공급자와 무관하게 같은 로그인 완료 흐름을 사용합니다.

- **계정 연동 정적 안내** — "소셜 계정 하나로 먼저 로그인한 뒤 다른 계정을 연동하면, / 어느 계정으로 로그인해도 똑같이 이용할 수 있어요"를 두 버튼 아래에 표시합니다. 별개 계정의 통합은 제공하지 않으며 가입 여부 조회로 안내를 분기하지 않습니다.

**로그인 진행 상태** — 탭한 버튼은 문구 공간을 유지한 중앙 스피너로 바뀌고 두 공급자 버튼이 모두 잠깁니다. 로그인 실패·취소로 화면에 남으면 스피너와 잠금을 해제합니다.

**신규 가입 온보딩(초대 코드 입력)** — 첫 로그인 완료 직후 모달 바텀 시트로 "초대 코드를 등록하면 / N 이프를 받을 수 있어요"(서버 `inviteReward`)와 "지금은 건너뛰고 나중에 등록해도 돼요"를 표시합니다. 초대 입력 아래 "등록하기"·"닫기"를 세로로 둡니다. 초점은 입력란 대신 시트 자체에 둡니다.

| 단계 | 동작·수용 기준 |
| --- | --- |
| 닫기·배경 탭·ESC | 세션 플래그를 소비하고 닫음. 건너뛰어도 계정당 평생 1회 등록 자격은 유지되어 초대 화면에서 등록 가능 |
| 코드 제출 | 초대 화면과 같은 검증·사유별 피드백. 등록·입력·닫기를 잠금 |
| 적립 성공 | 세션 플래그 저장까지 스피너·잠금 유지 |
| 적립 후 플래그 저장 실패 | 보상 재요청 없이 "N 이프는 정상 지급되었지만, 창을 닫는 데 실패했어요" 표시. 같은 크기·정렬의 닫기 재시도로 플래그 저장만 재시도 |

**계정 연동** — 현재 계정에 다른 provider를 추가하며 해제·별개 계정 통합은 제공하지 않습니다. 재인증 → 연동 프로토콜은 [백엔드 계정 연동](4-backend-server-spec.md#4-5-인증과-권한)을 따릅니다.

- **연동된 계정 표시** — `GET /auth/me`의 `linkedProviders`를 google → kakao 순서로 표시합니다. 연동 provider는 로고·이름 Chip, 미연동 provider는 점선 "카카오 연동하기"·"Google 연동하기" 버튼입니다. 모두 연동되면 Chip만 둡니다. 조회 중에는 Chip 스켈레톤 2개, 응답이 비거나 필드가 없으면 섹션을 숨겨 연동 버튼 오노출을 막습니다.
- **연동 시작 확인 다이얼로그** — 혜택(같은 계정으로 이용), 현재 provider 재인증 → 대상 provider 연동 순서, 해제 불가를 각각 안내합니다. "나중에 하기"·"연동하기"를 제공하고 별도 X 버튼은 두지 않습니다.
- **플로우** — 확인 → 현재 provider 재인증 → `POST /auth/links/reauth`로 링크 코드 발급·비공개 보관 → 대상 provider 인증 → `POST /auth/links/{provider}`(`X-Manyak-Link-Code`) → 회원 정보 재조회·성공 토스트입니다. 일반 로그인·세션 교체로 처리하지 않습니다. 서버가 콜백 provider의 연동 상태로 단계를 판정하며 웹 전용 provider·쿠키 구현은 [웹 Design](../design/1-1-web-design.md#소셜-로그인계정-연동-웹-구현)을 따릅니다.
- **에러 처리** — `PROVIDER_ALREADY_LINKED`(409)는 "이미 연동된 계정이에요" 토스트·재조회입니다. `SOCIAL_ACCOUNT_LINKED_TO_OTHER_USER`(409)는 다른 계정 연결과 로그아웃 후 해당 계정 로그인을 다이얼로그로 안내하되 즉시 계정을 전환하는 버튼은 두지 않습니다. `REAUTH_FAILED`·`SOCIAL_TOKEN_INVALID`(403)는 실패 토스트와 코드 만료 전 재시도를 제공합니다. 연동의 403·409를 세션 만료·토큰 재발급으로 처리하지 않습니다.
인앱 브라우저에서의 연동 제한은 [웹 로그인 계약](3-2-web-spec.md#로그인과-회원-이관)을 따릅니다.

**회원 서재** — [데이터 소유 계약](#3-1-2-공통-계약과-플랫폼-경계)을 따릅니다. 같은 계정으로 다른 기기·클라이언트에서 로그인하거나 로그아웃 후 재로그인해도 서버 서재를 유지합니다.

**로그아웃** — 서버 로그아웃과 플랫폼의 세션 종료 절차를 수행합니다. 이전 계정의 토큰·프로필·진행 결과가 다음 계정에 노출되거나 늦은 응답으로 되살아나지 않아야 합니다. 보존할 제작 데이터는 소유 계정에 격리하고, 플랫폼별 정리 범위는 해당 스펙·설계가 소유합니다.

**회원 탈퇴** — 마이 계정 섹션에서 뒤로가기 헤더·확인 목록·하단 위험색 CTA로 구성한 탈퇴 화면을 엽니다.

- **사전 확인** — 제목은 "탈퇴하기 전에 / 아래 내용을 모두 확인해주세요", 설명은 "모든 항목을 확인해야 탈퇴할 수 있어요"입니다. 사용자는 잔여 이프 소멸, 기존 서재 복구·이전 불가, 공개 콘텐츠 잔존 가능성, 같은 소셜 계정으로 재로그인해도 기존 계정이 복구되지 않음을 각각 체크해야 합니다.
- **CTA 상태** — 네 항목을 모두 체크하기 전에는 "회원 탈퇴하기"를 비활성화합니다. 요청 중에는 "회원 탈퇴 중" 스피너를 표시하고 버튼을 잠가 중복 요청을 막습니다.
- **성공** — `DELETE /users/me`가 `204`를 반환하면 계정은 탈퇴 상태가 되고 소셜 연결·프로필이 제거되며 닉네임이 익명화됩니다. 잔여 이프와 비공개 서재는 복구하거나 새 계정으로 옮길 수 없습니다. 공개 스토리는 익명화된 작성자로 남고 공유 채팅은 기존 링크로 계속 열람할 수 있습니다. 클라이언트는 사용자 쿼리 캐시·분석 사용자 식별자를 정리하고 제작 데이터는 플랫폼의 계정 격리·정리 범위를 따르며 플랫폼 세션을 종료하고 해당 플랫폼의 비로그인 화면으로 이동합니다.
- **실패** — 5xx·네트워크 오류면 "회원 탈퇴에 실패했어요" 토스트를 표시하고 체크 상태와 현재 화면을 유지해 재시도를 허용합니다. 401로 세션 만료가 확정되면 플랫폼의 전역 세션 만료 흐름을 따릅니다. 탈퇴 성공 뒤 세션 종료 과정에서 이미 무효화된 refresh 토큰의 백엔드 로그아웃이 실패해도 플랫폼 로컬 세션 정리는 계속합니다.

**추가 수용 기준**

- 회원 서재 조회의 인증 실패는 플랫폼 재발급·세션 만료 흐름을 따릅니다.
- 실패한 소모 요청은 제작 입력을 유지하고 낙관적 채팅 버블을 제거합니다. 회원·게스트 및 제출 경로별 안내는 해당 플랫폼 계약을 따릅니다.
- 같은 날 출석 체크를 두 번 누르면 두 번째 적립은 없고 완료 상태로 비활성화됩니다.
- 초대 코드 제출 중 입력·등록 버튼을 잠그며 신규 가입 시트는 "닫기"도 함께 잠급니다.

| 관련 US | US-3-15, US-3-16, US-4-5                                    |

**목적** — 제작 폼에 스토리 구성 항목을 직접 입력해 등록하고(일반 제작), 같은 폼으로 기존 스토리를 수정합니다.

**폼 구성** — 섹션 아코디언 구조. 필수: 기본 정보(제목·한 줄 소개·장르), 스토리 설정(세계관·등장인물·주인공·규칙 — 섹션별 텍스트 입력을 통글 마크다운으로 조립해 전송), 시작 설정(이름·프롤로그·시작 상황), 추천 입력 3개. 선택: 주요 사건(최대 10 — 이름·설명·키 문장), 엔딩(시작 설정당 최대 10 — 각 이름·조건(`minTurns`+달성 조건)·에필로그). 주요 사건·엔딩은 저장 후 채팅 런타임(목표 진행·엔딩 판정·선택지 구성)에 반영됩니다([`4-backend-server-spec.md §4-3-10`](4-backend-server-spec.md)) — 런타임 동작 자체는 채팅 화면([§3-1-5](#3-1-5-채팅-플레이와-sse-스트리밍))의 검수 대상입니다.

- **이미지 입력은 없습니다**(B10 — [`4-backend-server-spec.md §4-3-9`](4-backend-server-spec.md)). 스토리 이미지는 전부 팀이 사전 제작해 서버가 자동 연결하며, 사용자가 업로드하거나 선택하는 폼 섹션·업로드 API를 두지 않습니다.
- (B14) — 시작 설정은 여러 개(`startSettings[]`, 1개 이상) 등록할 수 있고, 엔딩은 시작 설정별로 입력합니다([`4-backend-server-spec.md §4-3-8`](4-backend-server-spec.md)).

**동작** — 등록: `POST /stories/general` → 성공 시 스토리 상세로 이동("스토리가 등록됐어요" 토스트). 수정: 진입 시 `GET /stories/{storyId}/edit`로 편집 가능 필드 전체를 조회해 폼을 채우고, 변경 필드만 `PATCH /stories/{storyId}`로 전송 → 성공 시 상세로 복귀. 검증 실패(400)는 `details`의 필드별 사유를 해당 섹션에 인라인 표시합니다.

**검수 기준**

- 일반 제작으로 등록한 스토리가 기본 메타·스토리 설정·시작 설정 기준으로 상세·채팅 시작에서 간편 제작 산출물과 동일하게 동작해야 합니다. (US-3-15)
- 제작 화면에서 간편 제작과 일반 제작으로 진입할 수 있어야 합니다. 경로는 플랫폼 스펙을 따릅니다. (US-3-16)
- 수정 전용 조회가 폼 필드를 채울 수 있어야 하고, 수정 후 스토리 상세와 같은 스토리 설정을 참조하는 진행 중 채팅의 다음 턴에 새 설정이 반영돼야 합니다. (US-4-5)
- 폼 작성 중 이탈 후 복귀하면 작성 내용이 복원돼야 합니다.
- 타인 소유 스토리와 로컬 서재에 없는 게스트 스토리에는 수정 진입점이 보이지 않아야 합니다.

### FE-SCREEN-010. 서비스 이용약관·개인정보 처리방침

| 항목     | 값                                      |
| ------- | ----------------------------------------------------------------------------------------------- |
| 관련 US | US-9(로그인·회원 전환)                                                                          |

**목적** — 서비스 이용약관과 개인정보 처리방침 전문을 열람합니다. 서비스 이용 대상은 만 14세 이상이며 두 문서에 같은 제한을 고지합니다.

**콘텐츠 동일성 계약** — 모든 플랫폼에서 같은 시행일·버전·본문을 표시합니다. 로그인 전에도 열람할 수 있으며, 로그인 화면과 서비스 안내에 진입점을 둡니다. 콘텐츠 정본·공급 방식은 [웹 설계](../design/1-1-web-design.md#법적-콘텐츠-소스-웹)가 소유합니다.

**동의 모델** — 로그인 버튼 클릭을 이용약관·개인정보 처리방침 동의로 간주한다는 고지를 표시합니다. 별도 동의 체크박스는 두지 않습니다. 개정 시 재동의 절차는 이 계약에서 정하지 않습니다. 광고성 정보 수신 동의(정보통신망법 제50조)는 이 간주 동의에 포함되지 않으며, 처리방침의 광고성 정보 수신 동의(선택) 절을 고지 정본으로 두고 Android 앱이 [알림 계약](3-3-android-spec.md#3-3-5-알림)에 따라 별도 시트로 받습니다. 웹은 푸시를 보내지 않아 동의를 받지 않습니다.

### FE-SCREEN-011. 서비스 안내

**목적** — AI 콘텐츠 특성·문의·정책 정보를 안내하고 약관·개인정보 처리방침의 상시 열람 경로를 제공합니다. 마이의 기타 섹션에서 피드백 위에 서비스 안내를 둡니다.

**콘텐츠 규칙** — 서비스 안내에는 이프 적립·소모 수치를 복제하지 않습니다. 필요한 화면에서 서버 정책값을 표시합니다. 게스트 이용 안내는 웹에만 적용하고, 그 체험 한도는 서버 정책과 일치해야 합니다. 약관·개인정보 처리방침을 요약할 수 있지만 서로 상충해서는 안 됩니다.

## 3-1-4. 스토리 생성 퍼널

### 단계 구성

단계는 **키워드 선택 → 스토리라인 선택 → 추가 정보**입니다. 세 단계의 진행 표시기를 동일 너비로 표시합니다. 완료는 편집 단계가 아니며 제출 이후의 상태입니다. 제출 이후 이동은 플랫폼별 적용 계약을 따릅니다.

| #   | 단계            | 목적                                            | 진행(다음) 조건                          |
| --- | --------------- | ----------------------------------------------- | ---------------------------------------- |
| 1   | 키워드 선택     | 장르·주인공·주변 인물 키워드 수집               | 장르 1개 이상 **그리고** 주인공 1개 이상 |
| 2   | 스토리라인 선택 | AI 생성 스토리라인 3개 중 택1(선택·재생성·평가) | 활성 스토리라인 선택 완료                |
| 3   | 추가 정보       | 추천 태그·자유 텍스트로 디테일 보강             | 생성 ID와 선택 스토리라인 ID 존재        |

### 키워드 선택 규칙

| 카테고리       | 탭 라벨        | 필수   | 상한                        | 직접 추가 |
| -------------- | -------------- | ------ | --------------------------- | --------- |
| 장르           | 장르           | 예     | 키워드 3개                  | 가능      |
| 주인공 특징    | 주인공 (나)    | 예     | 인물 1명, 특징 3개          | 가능      |
| 주변 인물 특징 | 주변 인물      | 아니오 | 인물 5명, 인물마다 특징 3개 | 가능      |

- 카테고리는 전체 폭의 동일 너비 탭으로 표시하며 별도 설명 문구를 두지 않습니다. 시각 표현 값은 [웹 표현](../design/1-1-web-design.md#웹-표현-값)을 따릅니다.
- 칩 목록 위에는 장르 "장르 (최대 3개)", 인물 "특징 (최대 3개)" 라벨을 표시하고 필수 카테고리에 `*`를 붙입니다.
- 태그 목록은 API로 조회하며, 로딩 시 스켈레톤 칩을 표시합니다.
- 상한에 도달하면 미선택 칩과 "키워드 추가" 트리거를 비활성화합니다(제공 태그·직접 추가 합산). 주변 인물이 5명이면 "인물 추가"도 비활성화합니다.
- 필수 카테고리의 "다음" 버튼은 선택 전에도 활성화합니다. 선택 없이 누르면 이동하지 않고 버튼 위 푸터에 "키워드를 하나 이상 선택해주세요"를 표시합니다. 오류가 생길 때만 푸터가 메시지 높이만큼 늘어나며, 해당 카테고리에서 키워드를 선택하면 오류를 제거합니다.
- 커스텀 키워드는 "키워드 추가" 다이얼로그로 입력합니다. "추가하기" 버튼은 빈 입력에서도 활성화하고, 빈 값으로 누르면 입력창 아래에 "키워드를 입력해주세요"를 표시합니다. 유효한 값을 입력하거나 다이얼로그를 닫으면 오류를 제거합니다. 클라이언트 최대 15자(서버 스키마 30자), IME 조합 중 Enter는 제출하지 않습니다. 세 카테고리 모두 직접 추가할 수 있으며, 요청에서 장르는 `customGenreTags`, 인물은 각 인물의 `customTags`로 나갑니다([`4-backend-server-spec.md §4-3-2`](4-backend-server-spec.md)).
- 카테고리 탭은 앞선 필수 카테고리가 완료되어야 잠금 해제됩니다.

#### 인물 단위 입력

주인공과 주변 인물을 특징 태그 묶음이 아니라 인물 단위로 입력받습니다. 두 탭은 같은 폼을 씁니다.

- **폼 구성** — 기본 정보(이름·성별) → 특징(제공 태그·직접 추가) 순서입니다. 기본 정보에는 "비워두면 랜덤으로 설정해요"를 표시합니다. 특징 필수 표시는 주인공만 적용하고 주변 인물에는 "선택하지 않으면 랜덤으로 설정해요"를 안내합니다.
- **이름** — 직접 입력이며 클라이언트·서버 모두 30자 상한입니다. 인풋 오른쪽에 입력 글자 수를 표시합니다.
- **성별** — 셀렉트이고 기본값은 "랜덤 성별"입니다. 랜덤은 고르지 않은 상태와 같아 요청에 `null`로 나가고 AI가 정합니다.
- **주변 인물 목록** — 빈 인물 1명으로 시작하며 이름(빈 값이면 "주변 인물 N")·`N/5` 순번·삭제를 표시합니다. 0~5명을 허용하고 빈 폼도 인원으로 집계합니다. 0명이면 "인물 추가" 위에 "주변 인물이 랜덤으로 생성돼요"를 표시합니다. 추가 시 새 이름 입력이 보이도록 스크롤하되 초점을 옮겨 키보드를 열지 않습니다.
- **이름 중복 금지** — 한 스토리 안에서 주인공과 주변 인물의 이름은 겹칠 수 없습니다. AI가 이름 글자로 인물의 등장 여부를 확인하기 때문입니다. 판정 키는 서버와 같습니다 — NFC 정규화 → 공백 제거 → 소문자([`4-backend-server-spec.md §4-3-2`](4-backend-server-spec.md)). 먼저 쓴 이름을 남기고 뒤에 겹친 인물의 이름 인풋에 "이미 사용한 이름이에요"를 즉시 표시하고, 그 상태에서 "스토리라인 만들기"를 누르면 요청을 보내지 않고 푸터에 "인물 이름이 겹치지 않게 해주세요"를 표시합니다. 비워 둔 이름은 AI가 각각 지어 주므로 판정 대상이 아닙니다. 서버도 400으로 막습니다([`4-backend-server-spec.md §4-3-2`](4-backend-server-spec.md)).

### 스토리라인 생성·평가

- **선택 UI** — "첫 번째"·"두 번째"·"세 번째" 탭으로 전환합니다. 하단 "선택한 키워드 보기"는 키워드 드로어를 열고 "다시 만들기"·"선택하기"로 재생성·확정을 수행합니다. 타이포그래피·배치는 [웹 표현](../design/1-1-web-design.md#웹-표현-값)을 따릅니다.
- **생성** — `POST /stories/simple/storylines {genreTagIds, customGenreTags, protagonist, supportingCharacters}`. 인물 객체는 `{name, gender, featureTagIds, customTags}`이고 비워 둔 이름·성별은 `null`로 보냅니다. 클릭 직후 "스토리라인 만들기" 버튼을 비활성화하고 문구 공간을 유지한 중앙 스피너를 표시하며, 동시에 스토리라인 선택 단계로 전환해 로딩 화면을 렌더합니다. 응답은 스토리라인 3개와 생성 ID(`simpleCreationId`)를 포함합니다. 로딩 중에는 순환 문구(글자 단위 캐스케이드 전환·시머)와 15·30초 시점 힌트를 표시합니다.  — 회원은 무료이고, 게스트의 체험 한도·카운터는 웹 스펙을 따릅니다.
- **재생성** — "다시 만들기"는 저장된 생성 요청을 재호출합니다. 생성 요청 이벤트는 최초 1회만 발화합니다.  익명 체험의 선차단은 웹 스펙을 따릅니다.
- **평가** — 스토리라인별 좋아요·별로예요를 토글합니다. 300ms 디바운스 후 설정(`PUT`)·해제(`DELETE`)로 동기화합니다. 동일 평가를 다시 누르면 해제되고, 실패 시 상태를 되돌리고 실패 토스트를 표시합니다. **평가는 보조 신호이며 완성 페이로드에 포함되지 않고 진행을 막지 않습니다.**

### 추가 정보 진입·스토리라인 재선택

- 추가 정보 단계의 선택 스토리라인은 첫 렌더부터 한 줄로 접고 **더보기/접기 토글을 항상 렌더링**합니다. 내용 길이를 측정한 뒤 토글을 제거하지 않아 짧은 스토리라인에서도 첫 렌더 레이아웃이 움직이지 않아야 합니다.
- 자유 입력 제목은 "추가 정보 (최대 10개)"입니다. 정보 추가 시 새 행이 보이도록 스크롤하되 초점을 옮겨 키보드를 열지 않습니다. 배치·Tab 이동은 웹 문서를 따릅니다.
- 추가 정보 푸터는 CTA 위에 "스토리 완성 비용"과 서버 `storyCreationCost`의 "N 이프"를 표시합니다([이프 정책 수치](#이프-정책-수치-표시)).
- 추가 정보나 추천을 아직 고르지 않은 상태에서 "다시 선택하기"를 누르면 경고 없이 스토리라인 선택 단계로 돌아갑니다. 공백만 있는 자유 입력과 처음부터 놓인 빈 입력 행은 작성한 정보로 보지 않습니다.
- 공백이 아닌 자유 입력 또는 선택한 추천이 하나라도 있으면 `스토리라인을 바꿀까요? / 입력한 추가 정보는 모두 사라져요` 경고를 표시합니다. `닫기`는 단계·스토리라인·입력·추천을 모두 유지합니다. 파괴적 스타일의 `다시 선택하기`를 확정하면 선택 스토리라인, 자유 입력 전부, 추천 선택 전부를 초기화하고 스토리라인 선택 단계로 돌아갑니다.

### 완성 제출과 복구

- 키워드·추가 정보의 검증을 통과한 요청만 전송합니다. 같은 요청의 재시도에는 같은 `requestId`와 명령을 사용합니다.
- 생성·완성 요청은 전송 전에 복구 가능한 형태로 저장합니다. 저장 실패를 제출 성공으로 표시하지 않습니다.
- 서버 결과를 받지 못한 경우 확정 실패와 구분하고, 복구 조회로 결과를 확인합니다. 백그라운드에서 화면용 폴링을 계속하지 않습니다.
- 사용자 편집·요청 전환·서버 결과 반영은 오래된 저장이 새 요청을 덮지 않도록 처리합니다. 저장 구조와 직렬화 수단은 플랫폼 설계가 소유합니다.
- 로그아웃·계정 변경 후 이전 계정의 제작 내용을 다른 계정에 표시하거나 이전 작업 결과를 새 세션에 반영하지 않습니다.

### 제작 카드와 다중 완성 진행

이 절은 초안과 완성 요청을 분리하는 계약입니다. Android의 적용 동작은 [Android 제작 계약](3-3-android-spec.md#제작과-데이터-보존), 웹 단일 슬롯 흐름의 적용 범위는 [웹 제작 계약](3-2-web-spec.md#웹-제작-흐름)이 소유합니다.

- 편집 중 초안 한 개와 여러 완성 요청을 독립적으로 표시합니다. 새 제작·초안 삭제는 완성 요청을 지우지 않습니다.
- 제출 요청을 영속화한 뒤에는 완성 응답을 기다리지 않고 제작 탭으로 돌아옵니다. 자동으로 채팅방을 만들거나 채팅 화면에 진입하지 않습니다.
- 저장 실패 시 전송하지 않고 입력을 유지한 채 오류를 안내합니다. 제출 연타로 같은 요청이 중복 생성되지 않습니다.
- 완성 중 요청과 완성 스토리를 구분합니다. 서버 스토리와 같은 `storyId`의 로컬 완료 항목을 이중 표시하지 않습니다.
- 완료된 스토리는 상세 화면을 거쳐 사용자가 채팅을 시작합니다. 실패 카드의 재시도·삭제·편집 복귀 정책은 미확정입니다.

### 검수 기준

- 저장 실패에는 요청을 보내지 않고 입력을 유지합니다.
- 같은 요청의 재전송은 중복 스토리를 만들지 않으며, 불명확한 응답은 복구 조회 결과와 일치시킵니다.
- 초안 삭제·새 제작은 다른 완성 요청에 영향을 주지 않습니다.
- 플랫폼의 제출 후 목적지·이탈·저장 계약을 충족하고, 계정 변경 뒤 다른 회원의 데이터가 노출되지 않습니다.

## 3-1-5. 채팅 플레이와 SSE 스트리밍

FE-SCREEN-005의 상세입니다. 턴·스트리밍·이미지·복구의 공통 계약입니다.

### 턴 모델

- 채팅은 스토리 상세(웹 복구 예외는 [웹 제작 계약](3-2-web-spec.md#웹-제작-흐름))에서 `POST /chats {storyId, startSettingId}`로 생성됩니다(`startSettingId`는 상세에서 선택한 시작 설정, 생략 시 첫 번째). 채팅 목록에서는 생성하지 않습니다.
- **턴** = 사용자 입력 + AI 출력 + 다음 선택지입니다. 사용자 입력과 AI 출력은 응답이 완료될 때 한 턴으로 저장됩니다.
- 채팅 화면은 `GET /chats/{id}`로 스토리 제목·프롤로그·턴 목록·추천 입력을 조회합니다.
- 렌더 순서: 프롤로그 버블 → 각 턴(사용자 버블 → AI 버블) → 진행 중 스트리밍 블록.
- 선택지는 **마지막 턴에만** 표시합니다. 턴이 0개면 시작 화면의 추천 입력을 선택지로 표시합니다.

### SSE 스트리밍 계약

채팅 턴은 사용자 입력을 본문에 실은 `POST` 요청의 응답을 SSE로 받습니다([백엔드 계약](4-backend-server-spec.md)). 수신·파싱 수단은 각 플랫폼 설계가 소유합니다.

- **요청** — `POST /chats/{id}/turns/stream`, 헤더 `Accept: text/event-stream` + `X-Manyak-*` 식별자, 본문 `{userInput}`(서버 검증 상한 3000자, 프론트는 별도 차단 없음).
- **이벤트 계약** (원천: [`4-backend-server-spec.md §4-3-3`](4-backend-server-spec.md))

| 이벤트          | 데이터 필드          | 프론트 처리                                                                                                                                   |
| --------------- | -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `started`       | —                    | 수신만(무동작)                                                                                                                                |
| `token`         | `text`               | 현재 위치의 텍스트 조각에 누적해 부분 렌더                                                                                                    |
| `character_image` | `name`, `imageUrl` | 이벤트를 받은 즉시 현재 스트리밍 위치에 인물 이미지 조각을 추가. 같은 이벤트가 다시 오면 이미지도 다시 추가 |
| `completed`     | `chatId`, `turnId`, `aiOutput`, `choices`, `reachedEnding` | 상세 refetch로 확정 턴을 받은 뒤 진행 중 조각 목록과 한 번에 교체. 클라이언트는 `completed`의 별도 이미지 목록에 의존하지 않음 |
| `error`         | `message`            | 실패 토스트                                                                                                                                   |

- `token`은 `data: {"text":"..."}`(JSON) 또는 원문 텍스트를 모두 허용합니다.
- **스트리밍 순서의 정본은 이벤트 도착 순서입니다** 진행 중 AI 출력은 하나의 문자열이 아니라 순서가 있는 `text | character_image` 조각 목록으로 관리합니다. `token`은 마지막 조각이 텍스트면 그 조각에 이어 붙이고, `character_image`는 현재 위치에 새 이미지 조각을 추가하며, 그다음 `token`은 이미지 뒤의 새 텍스트 조각으로 시작합니다. AI 서버는 이미지가 있는 인물의 `이름:` 토큰보다 `character_image`를 먼저 보내므로, 클라이언트는 이미지 → 인물명 → 대사 순서를 그대로 표시합니다. 이름 기준 정렬·중복 제거·완료까지 표시 지연은 금지합니다.
- **인물 이미지가 먼저 나온 뒤 턴이 실패한 경우** 이미지도 텍스트 토큰과 같은 미확정 스트리밍 결과입니다. `error` 이벤트가 오면 낙관적 사용자 버블과 진행 중 텍스트·이미지 조각을 함께 제거합니다. `completed`·`error` 없는 EOF는 서버 저장 여부를 알 수 없으므로 기존 EOF 규칙대로 상세를 refetch하고, 저장된 턴이 있으면 확정 `aiOutput`의 `[[URL]]` 마커로 복원하며 없으면 진행 중 조각을 제거합니다. 실패한 턴의 이미지만 화면에 남겨 확정 이력처럼 보이게 하지 않습니다.
- `completed` 수신 시 진행 중 조각을 즉시 지우지 않습니다. 상세 재조회가 성공한 프레임에 서버 확정 턴의 조각 목록으로 한 번에 교체해, 본문·이미지가 사라졌다 다시 나타나거나 URL 마커가 한 프레임 노출되지 않게 합니다. 완료 후 채팅 목록을 무효화해 미리보기·시각을 갱신합니다.
- 클라이언트와 백엔드 사이의 전달 계층은 SSE 청크를 버퍼링하지 않아야 합니다(웹: BFF 프록시 스트리밍 통과 — [`1-1-web-design.md §1-1-3`](../design/1-1-web-design.md#1-1-3-bff-프록시토큰-세션)).
- **타임아웃** — 백엔드 쪽 상한은 두 층이고 종료 모양이 다릅니다(값·근거의 정본은 [`4-backend-server-spec.md §4-3-3`](4-backend-server-spec.md)): 클라이언트향 SSE **전체 상한**을 넘기면 `error` 이벤트 **없이** 스트림이 닫히고(클라이언트는 EOF로 관측 — 위 예외 처리), 백엔드→AI의 **이벤트 간 idle** 상한을 넘기면 `AI_STREAM_FAILED` `error` 이벤트가 옵니다. 클라이언트의 연결·읽기 제한은 플랫폼 설계를 따릅니다.

### 입력창과 선택지

- **입력 모드** — 일반 텍스트와 블럭(상황·대사) 모드는 같은 전송·추천 규칙을 사용합니다. Tab·키보드 처리는 [웹 입력 계약](3-2-web-spec.md#safari애니메이션입력-ux-검수-기준)을 따릅니다.
- **입력이 있을 때** — 전송 버튼은 위쪽 화살표입니다. 공백 제거 후 1자 이상이고 스트리밍 중이 아닐 때 전송할 수 있습니다.
- **입력이 없을 때** — 현재 추천 입력이 1개 이상이면 전송 버튼을 filled 재생 아이콘으로 표시하고 활성화합니다. 누르면 현재 추천 입력 중 하나를 무작위로 골라 즉시 전송합니다. 추천 입력도 없으면 같은 아이콘을 유지한 채 버튼을 비활성화합니다.
- **채팅 턴 이프 비용** — 회원은 전송 버튼 왼쪽에 "N 이프"를 표시합니다. N은 서버 `chatTurnCost`이며, [실시간 이미지](#채팅-설정-시트와-삭제)가 켜져 있으면 `chatImageCost`를 합산합니다(두 값이 모두 있어야 숫자를 표시). 두 입력 모드와 모든 버튼 상태에서 같은 위치를 유지하며 게스트에는 표시하지 않습니다.
- **응답 대기 스피너** — 스트리밍 중에는 전송 버튼의 아이콘(화살표·재생 공통)을 스피너로 바꿔 응답을 받는 중임을 알립니다(스크린 리더 라벨 "응답을 받는 중"). 두 입력 모드와 응답 재생성에 동일하게 적용하며, 완료·실패로 스트리밍이 끝나면 원래 아이콘으로 돌아옵니다. 버튼은 스피너 표시 중에도 전송 잠금 규칙대로 비활성 상태입니다.
- **추천 입력 소스** — 턴이 0개면 상세 응답의 `suggestedInputs`, 턴이 있으면 마지막 턴의 `choices`를 사용합니다.
- **선택지** — "채우기"는 입력창에 넣어 편집하고 본문 전송은 즉시 제출합니다. 바로 전송도 블럭 입력처럼 상황(`*...*`)과 대사를 빈 줄로 구분합니다. 추천·스켈레톤·실패 안내는 같은 묶음당 한 번만 등장하며 화면 밖에서 돌아왔다는 이유로 재생하지 않습니다. 모션 값은 [웹 표현](../design/1-1-web-design.md#웹-표현-값)을 따릅니다.
- **블럭 순번과 개수 상한** — 블럭 모드의 각 입력 라벨에 종류별 순번을 붙입니다("상황 1", "대사 1"). 순번 자리는 두 자리 폭으로 미리 잡아 한 자리에서 두 자리로 넘어가도 입력 글자의 시작 위치가 밀리지 않습니다. 같은 종류가 여럿일 때 방금 늘어난 칸이 어느 것인지 라벨만 보고 알 수 있게 하는 표시이며, 순번은 화면 표시 전용이라 전송 본문에는 싣지 않습니다. 블럭은 상황·대사를 합쳐 **최대 50개**이고, 상한에 닿으면 두 추가 버튼을 비활성화합니다. 모드 전환·추천 채우기로 파싱된 블럭은 상한을 넘을 수 있습니다 — 문장을 잘라 버리지 않기 위해 파싱 결과는 그대로 두고 추가 버튼만 잠급니다. 칸을 더하면 아래에서 자라 오르고 지우면 같은 변을 붙잡은 채 접히며, **목록이 높이 상한에 걸려 스크롤 중이면 더한 칸이 보이도록 끝까지 따라 내려갑니다** — 접힌 자리에 생기면 추가가 일어났는지 보이지 않습니다. 모드 전환·추천 채우기·전송 뒤 초기화처럼 목록 전체가 갈리는 경로는 칸별 모션 없이 한 번에 교체합니다.
- **강조 삽입** — "상황 추가" 버튼이 선택 영역을 `*...*`로 감쌉니다.
- **전송 잠금** — 스트리밍 중에는 컴포저·입력창·버튼이 모두 비활성화됩니다(전송 버튼은 비활성 상태로 스피너를 표시).
- **추천 입력 토글** — 선택지(추천 입력) 생성을 응답 스트림에서 분리합니다([`4-backend-server-spec.md §4-3-3`](4-backend-server-spec.md)). 토글은 [채팅 설정 시트](#채팅-설정-시트와-삭제)의 "AI 추천 입력" 스위치입니다. 토글 on이면 `completed` 수신·상세 refetch(본문 확정) 후 선택지 생성 API(`POST /chats/{id}/turns/{turnId}/choices`)를 호출합니다(본문 확정과 선택지 도착 사이의 지연은 허용). 응답 200은 저장 완료 신호이며 렌더 소스가 아닙니다 — 상세를 한 번 더 재조회해 마지막 턴 `turns[].choices`로 표시합니다(`completed`의 `choices`는 렌더 소스로 쓰지 않음). 토글 off면 호출하지 않으며, 표시 중이던 마지막 턴 선택지도 숨깁니다(빈 입력의 무작위 추천 전송 대상에서도 제외 — 서버 데이터는 유지되므로 다시 켜면 재호출 없이 재표시). off 상태로 턴이 끝난 뒤 토글을 켜면 같은 API로 마지막 턴의 선택지만 생성합니다. flag 없이 "API를 부르는가"로 on/off를 처리합니다. 토글 기본값은 on이고 변경값은 로컬 저장소에 기기 단위로 기억합니다(저장 수단·키는 플랫폼 소유 — 플랫폼 설계 참조). 선택지 생성은 무료이며 마지막 턴만·턴당 1회 멱등 계약입니다([`4-backend-server-spec.md §4-3-3`](4-backend-server-spec.md)). 선택지 로딩은 선택지 자리의 스켈레톤 칩 3개로 표시하고, 도착하면 교체합니다. 실패하면 선택지 자리에 에러 문구와 재시도 버튼을 표시하고, 재시도는 같은 API를 다시 호출합니다(선택지가 없어도 직접 입력으로 채팅은 계속 진행 가능).

### 첫 진입 안내

처음 채팅을 시작한 사용자에게 입력 영역 사용법을 안내합니다. 안내 대상은 진입 경로와 무관하게 생애 첫 채팅방 진입 사용자 전원이며, 온보딩 경유 여부는 따지지 않습니다.

- **노출 조건** — 기기에 열람 기록이 없고, 턴 0개(프롤로그와 첫 추천만 있는 상태)이며 스트리밍 중이 아닐 때 짧은 지연 뒤 1회 자동 노출합니다. 노출 시점에 열람 기록을 남깁니다. 조건을 만족하지 않는 방(이미 대화가 진행된 방)에서는 노출하지 않고 기록도 남기지 않습니다. 기기 단위 1회이며 **재열람 진입점은 두지 않습니다**. 로컬 저장소 접근이 막힌 환경에서는 기록이 남지 않아 진입마다 다시 노출될 수 있으며, 이는 허용합니다.
- **형태** — 딤·대상 하이라이트·안내 카드로 구성하고 뒤 화면 상호작용을 막습니다. "다음"으로 진행하며 언제든 "건너뛰기"로 닫을 수 있습니다. 웹 포털·좌표 계산은 [웹 Design](../design/1-1-web-design.md#레이아웃-구조)을 따릅니다.
- **카드 배치** — 기본은 하이라이트 중앙 정렬이며 가장자리에서는 그쪽 변을 맞춥니다. 안내 카드가 앱 프레임·화면 위아래를 벗어나지 않아야 합니다.
- **스텝(3개)** — ① 상황·대사 추가 버튼 ② 채팅 설정 버튼 ③ 전송(랜덤) 버튼. 첫 스텝은 입력 모드에 따라 갈립니다 — 블럭 모드는 두 추가 버튼을 함께 잡아 "입력창이 하나 늘어난다"로, 일반 모드는 대사 추가 버튼이 없으므로 상황 추가 버튼만 잡고 강조 마커(`*...*`) 삽입 동작으로 안내합니다. 화면에 대상이 없는 스텝은 건너뛰고, 모든 스텝의 대상이 없으면 투어를 열지 않습니다.
- **추천 입력 안내** — 투어와 별개로 첫 추천 위에 "AI가 추천하는 입력이에요" / "탭하면 바로 전송되고, 연필 버튼으로 고쳐서 보낼 수 있어요" 인라인 힌트를 표시합니다. 턴 0개에서 노출한 순간 기기 기록을 남기고 같은 방에서는 유지하되 재진입부터 숨깁니다.
- **계측** — 투어는 노출·스텝 도달·완주·건너뛰기 4종을 수집합니다([`6-analytics.md §6-4-2-6`](6-analytics.md)). 인라인 힌트는 별도 이벤트를 두지 않습니다.

### 렌더와 스크롤

- **부분 렌더** — `token`이 누적되는 동안 AI 버블에 실시간 텍스트를 표시하고, `character_image`가 오면 같은 버블의 해당 위치에 이미지를 즉시 표시합니다. 첫 표시 가능 이벤트(`token` 또는 `character_image`) 전에는 "다음 내용 준비 중" shimmer 로딩(스크린 리더 라벨 "답변을 작성하고 있어요")을 표시하고, 이미지가 먼저 오면 첫 토큰을 기다리지 않고 로딩을 이미지로 교체합니다. 전송 시점에 [실시간 이미지](#채팅-설정-시트와-삭제)가 켜져 있던 턴은 대신 제작 퍼널 로딩과 같은 순환 문구("어울리는 표정 찾는 중" → "다음 내용 준비 중" → "장면 완성 중" → "다음 대사 고민 중", 스크린 리더 라벨 "다음 장면을 만들고 있어요")를 위에, 20px 아래에 4:3 장면 썸네일 자리(제작 진행 카드의 이미지 생성 로딩과 같은 표현)를 표시합니다. 본문 첫 조각이 도착하면 순환 문구와 썸네일 자리는 그 자리에서 바로 페이드로 사라지고 본문이 같은 자리에 나타납니다. 로딩이 차지하던 높이는 본문이 그만큼 자랄 때까지 최소 높이로 유지해, 상단에 고정된 사용자 입력이 내려앉지 않게 합니다. 응답 재생성도 같습니다.
- **본문 표현** — 프롤로그·사용자 입력·AI 출력·스토리라인은 서사 서체를 공유합니다. [웹 표현](../design/1-1-web-design.md#웹-표현-값)·[Android Design](../design/1-2-android-design.md)을 따릅니다.
- **강조 마크업** — `**볼드**`는 굵게, `*...*`는 서술·독백 강조로 렌더합니다.
- **진입 스크롤 위치** — 턴이 있는 방은 마지막 메시지 위치에서, 턴이 0개인 방은 프롤로그가 보이도록 상단에서 시작합니다.
- **새 턴 앵커** — 전송하면 새 턴(사용자 버블 + 스트리밍 블록)을 뷰포트 상단에 이전 메시지와의 여백 없이 밀착해 앵커하고, 텍스트·이미지 조각이 추가돼도 화면이 끌려 내려가지 않습니다. 스트리밍 중 사용자가 옮긴 스크롤 위치는 완료(상세 refetch) 후에도 유지됩니다.
- **하단 이동 버튼** — 스크롤이 하단에 있지 않으면 "맨 아래로 이동" 버튼을 표시합니다. 스트리밍 중에도 동일하게 동작합니다.
- **헤더 show/hide** — 상단 근처·위로 스크롤 시 표시, 아래로 스크롤 시 숨깁니다. 스크롤된 위치로 진입하면(마지막 메시지 앵커) 등장 없이 처음부터 숨긴 채 시작합니다. 숨긴 헤더는 보조기술·포커스 대상에서도 제외합니다. 헤더 back은 채팅 목록으로 이동합니다.

### 채팅 설정 시트와 삭제

실시간 이미지·추천 입력·입력 모드 설정은 입력 툴바의 설정 버튼이 여는 바텀 시트에 두고, 채팅 삭제는 헤더 우측 옵션 메뉴(⋮)에 둡니다. 헤더 우측은 공유 버튼 + 옵션 메뉴 두 개이며, 공유 발급은 위 [채팅 공유하기](#채팅-공유하기)가 정의합니다.

- **채팅 설정 시트** — 입력 툴바(추가 버튼들 오른쪽)의 설정 아이콘 버튼("채팅 설정")이 바텀 시트 "채팅 설정"을 엽니다. 시트는 마이 화면 메뉴와 같은 배치(아이콘 · 라벨 · 설명, 오른쪽 스위치)로 두 그룹을 순서대로 둡니다 — **채팅 기능**: "실시간 이미지"(대화에 따라 인물 한 명의 표정과 모습이 달라져요 — 회원에게는 라벨 오른쪽에 안내 버튼("실시간 이미지 안내")과 그 옆 보조 배지(이프 마크 + `chatImageCost`의 "N 이프")를 두고, 안내 버튼을 탭하면 팝오버로 "이미지를 만들지 못한 경우 사용된 이프가 자동으로 취소돼요"를 보입니다. 게스트에게는 둘 다 표시하지 않음), "AI 추천 입력"(AI가 다음 전개를 추천해줘요) / **입력 모드**: "블럭 입력"(상황과 대사를 나눠서 입력해요). 스위치를 바꾸면 즉시 반영되며 시트는 열린 채 유지됩니다(블럭 입력을 끄면 시트 뒤 입력창이 일반 입력으로 바뀜). 세 값 모두 기본 on이고 변경값은 로컬 저장소에 기기 단위로 기억합니다(저장 수단·키는 플랫폼 소유 — [웹 Design](../design/1-1-web-design.md#게스트-저장소-키-웹)).
  - **실시간 이미지** — 켜져 있으면 턴 진행·응답 재생성 요청 본문에 `realtimeImage: true`, 꺼져 있으면 `false`를 보냅니다(서버 기본값은 true이므로 항상 명시해 보냄). 켠 상태의 이미지 생성·과금·체험 계약은 서버가 소유합니다([`4-backend-server-spec.md §4-3-9`](4-backend-server-spec.md#채팅-실시간-이미지-생성)). 켜져 있으면 AI 서버가 본문을 확정한 뒤 이미지를 붙여 보내므로 토큰이 실시간으로 흐르지 않고 본문이 한 번에 도착할 수 있습니다 — 그 동안의 로딩 표시는 [부분 렌더](#입력창과-선택지) 규칙을 그대로 따릅니다.
  - **AI 추천 입력** — 상세 계약은 위 [입력창과 선택지](#입력창과-선택지)의 "추천 입력 토글"을 따릅니다.
  - **블럭 입력** — on이면 블럭 입력, off면 일반 입력 모드입니다. 전환 규칙은 위 "입력 모드"를 따릅니다.
- **옵션 메뉴** — 헤더 우측 ⋮ 버튼이 드롭다운을 열고, 항목은 "신고하기"(회원만, [FE-SCREEN-005](#fe-screen-005-채팅-화면)) → destructive "삭제하기" 순서입니다. 게스트에게는 삭제하기 하나만 보입니다.
- **삭제 흐름** — "삭제하기" → 확인 다이얼로그("채팅을 삭제할까요?") 표시 → 확정 시 낙관적 삭제([웹 사용자 모델](3-2-web-spec.md#웹-사용자-모델)과 동일 규칙: 204 완료 토스트, 404 무음 성공) 후 채팅 목록으로 이동합니다. 확정 버튼은 요청 중 문구 공간을 유지한 중앙 스피너("삭제 중")로 잠깁니다.
- 채팅 목록(FE-SCREEN-004)의 카드 옵션 다이얼로그도 같은 삭제 절차를 쓰되, 목록에서는 이동 없이 그 카드만 제거합니다.

### 응답 재생성과 채팅 이미지

**재생성 버튼** — 마지막 턴의 AI 버블 하단에 "다시 생성" 버튼을 둡니다(US-6-10). 마지막 턴에만 표시하고, 스트리밍 중에는 전송 잠금과 같은 조건으로 비활성화합니다. 엔딩 도달 턴(`reachedEnding` 존재)에는 버튼을 표시하지 않습니다 — 서버도 동기 409로 거부합니다([`4-backend-server-spec.md §4-3-9`](4-backend-server-spec.md)).

**재생성 흐름** — 클릭 → `POST /chats/{id}/turns/regenerate/stream {turnId}`(SSE 이벤트 계약은 턴 진행과 동일) → 기존 마지막 AI 버블·선택지를 스트리밍 블록으로 대체 → `completed` 수신 시 상세 refetch로 서버 확정본을 표시합니다. 사용자 입력 버블은 그대로 유지합니다. 서버는 이전 출력을 버전 이력으로 보존하지만([`4-backend-server-spec.md §4-8`](4-backend-server-spec.md) B11) 상세 조회·SSE에는 활성본만 실리므로, 프론트엔드 화면 계약은 변하지 않습니다.

**재생성 실패 처리** — 실패 종류에 따라 다르게 처리합니다.

- **`error` 이벤트 수신** — 서버가 교체하지 않았음이 보장되므로([`4-backend-server-spec.md §4-3-9`](4-backend-server-spec.md)) 기존 본문·선택지를 복원하고 실패 토스트를 표시합니다.
- **네트워크 실패·EOF(`completed`·`error` 없이 종료)** — 서버 교체 성공 후 전달만 끊겼을 수 있어 결과 불명입니다. 기존 본문을 임의로 복원하지 않고 상세 refetch로 서버 확정 상태를 표시합니다(교체됐으면 새 본문, 아니면 기존 본문).
- **402** — 턴 진행과 동일하게 이프 부족(회원)·로그인(게스트) 다이얼로그를 띄우고 기존 본문을 유지합니다.
- **409**(이미 새 턴이 추가된 낡은 화면) — 상세 refetch로 최신 상태를 반영합니다.

**배경 이미지 렌더** — 배경 이미지는 별도 턴 필드가 아니라 **`aiOutput` 본문 안의 이미지 마커**로 옵니다(US-6-11). 어떤 장면에 어떤 이미지를 삽입할지는 AI가 응답 생성 중 결정하고 서버가 마커를 검증하며([`4-backend-server-spec.md §4-3-9`](4-backend-server-spec.md) B10 — 이미지는 전부 팀 제작 자산), 클라이언트는 본문 렌더 시 마커 위치에 이미지를 표시하기만 합니다.

- **마커 포맷은 확정됐습니다** — 본문 인라인 `[[image:<imageKey>]]` 1종이고, 서버가 검증한 목록이 `completed`·상세 응답의 `images[]`(`{imageKey, type, url}`)로 동봉됩니다(정본: [`4-backend-server-spec.md §4-3-9`](4-backend-server-spec.md)).
- **무효 마커는 마커 텍스트째 숨깁니다** — `images[]`에 없는 키의 마커는 이미지를 띄우지 않는 데 그치지 않고 `[[image:…]]` 문자열 자체를 출력하지 않습니다. 사용자에게 마커 원문이 보이는 것은 어떤 경우에도 계약 위반입니다.
- 이미지 로드 실패 시 이미지 영역을 제거하고 본문만 표시합니다.

**인물 이미지 렌더** 위 배경 마커와 별개로, 인물 이미지는 스트리밍 중에는 `character_image` 이벤트로, 저장 뒤에는 `aiOutput` 본문 안의 저장 마커로 전달합니다(정본: [`4-backend-server-spec.md §4-3-9`](4-backend-server-spec.md) · [`5-ai-server-spec.md §5-3-4`](5-ai-server-spec.md)). 클라이언트 렌더 규칙은 다음과 같습니다.

- **적용 경로** — 새 턴 이어쓰기, 마지막 응답 재생성, 채팅 상세와 공유 열람은 같은 조각 렌더 규칙을 사용합니다. 재생성 중에는 기존 AI 본문·이미지를 진행 중 조각 목록으로 대체하고, 완료 시 새 저장 마커 결과로 교체합니다. 명시적 `error`면 기존 확정 본문·이미지를 함께 복원합니다. 공유 열람도 저장 마커를 숨기는 데 그치지 않고 원본 채팅과 같은 위치의 이미지를 표시합니다.
- **진행 중 렌더** — [SSE 이벤트 순서·완료 교체](#sse-스트리밍-계약)를 따릅니다. 같은 인물의 반복 이벤트도 횟수대로 표시합니다. URL은 플랫폼의 인물 이미지 허용 범위 밖이면 요청하지 않습니다([웹 런타임 검사](../design/1-1-web-design.md#원격-이미지-최적화)).
- **저장 마커 `[[URL]]`** — 독립된 한 줄의 마커 뒤 빈 줄 하나와 비어 있지 않은 `인물명:` 대사 라벨이 있어야 하며 URL 허용 검사도 통과해야 합니다. 모두 만족할 때만 마커 위치에 이미지를 표시하고 대사 라벨을 대체 텍스트 이름으로 사용합니다. 그 밖의 마커 모양 문자열은 이미지 요청·제거 없이 일반 본문으로 유지합니다. 유효 마커·URL 원문은 숨기며 반복 마커도 횟수대로 표시합니다. 별도 이미지 목록이나 이전 `[[인물이름:URL]]` 형식에 의존하지 않습니다.
- **스트리밍→확정 교체** — 진행 중 `character_image`와 확정 저장 마커는 같은 위치·순서·횟수를 표현합니다. 상세 refetch가 끝날 때 전체 조각 목록을 원자적으로 교체하며, 이벤트 이미지와 저장 마커 이미지를 동시에 렌더해 중복시키지 않습니다.
- **레이아웃·접근성** — 4:3 이미지 영역을 수신 즉시 예약하고 자르지 않은 원본 전체를 표시합니다. 별도 등장 지연·중복 이름 캡션은 두지 않습니다. 대체 텍스트는 "{name} 인물 이미지", 버튼 이름은 "{name} 인물 이미지 크게 보기"입니다. 탭하면 상세와 같은 풀스크린 뷰어를 열고 X·화면 탭·뒤로가기는 페이지 이동 없이 뷰어만 닫습니다. 패딩·곡률·간격은 플랫폼 Design을 따릅니다.
- **로드 실패** — 깨진 이미지 아이콘·대체 텍스트·URL 원문을 남기지 않고 해당 이미지 블록만 제거합니다. 앞뒤 텍스트와 이후 스트리밍은 계속 표시합니다.

### 엔딩 도달 표시

엔딩 도달 여부는 서버가 판정하고([`4-backend-server-spec.md §4-3-10`](4-backend-server-spec.md) ), 클라이언트는 값 유무로만 렌더합니다 — 채팅 이미지와 같은 원칙입니다.

- **도달 턴 배지** 완료 후 상세 refetch의 턴 항목에 `reachedEnding`이 있으면 해당 AI 응답의 가장 위 왼쪽에 `엔딩 · {엔딩 이름}` 배지를 표시합니다(US-6-13). 스토리 제작의 "임시 저장됨" 배지와 같은 primary 10% 배경·primary 전경색·보조 배지 크기를 사용하고, 긴 이름은 버블 폭 안에서 줄바꿈합니다. 스트리밍 중 임시 응답에는 표시하지 않고 서버가 확정한 턴에만 표시합니다.
- **도달 후 계속 진행** 엔딩 도달이 입력을 잠그지 않습니다. 입력창·선택지는 일반 턴과 동일하게 동작하고(잠금 조건은 스트리밍 여부뿐 — [입력창과 선택지](#입력창과-선택지)의 전송 잠금), 이후 턴은 배지 없는 일반 턴으로 이어집니다(US-6-14). 서버도 도달 후 턴 진행을 계속 허용합니다. **재생성 버튼만 예외로 도달 턴에서 숨깁니다**(위 재생성 절 — 서버가 409로 거부).
- 익명 체험의 본 엔딩 집계는 [웹 스펙](3-2-web-spec.md#웹-사용자-모델)이 소유합니다.

### 채팅 공유하기

공유 시점까지의 채팅을 읽기 전용 링크로 다른 사람에게 보여주는 기능입니다(US-6-17·6-18). 서버 계약은 [`4-backend-server-spec.md §4-3-11`](4-backend-server-spec.md)이 정의합니다.

**발급** — 헤더 우측 옵션 메뉴(⋮) 왼쪽에 share 아이콘 버튼(접근 이름 "채팅 공유하기 버튼")을 둡니다. 클릭하면 바로 발급하지 않고 확인 다이얼로그를 먼저 엽니다 — 링크를 받은 사람은 누구나 대화를 볼 수 있으므로, 공개 범위를 알린 뒤 사용자가 확정하게 합니다.

- **다이얼로그 구성** — "이 채팅을 공유할까요?"와 "이 링크가 있으면 누구든지 내가 지금까지 이어온 채팅을 볼 수 있어요"를 표시합니다. 같은 폭의 "나중에 하기"·"링크 복사하기" 버튼을 두고 X는 두지 않습니다. 취소·배경 탭·ESC는 발급 없이 닫습니다.
- **확정** — "링크 복사하기"를 누르면 `POST /chats/{id}/shares`로 공유를 발급하고, 응답의 공유 식별자로 `{서비스 origin}/share/{shareId}` URL을 만들어 클립보드에 복사한 뒤 "채팅 공개 링크가 복사되었어요" 토스트를 표시하고 다이얼로그를 닫습니다 — 문구는 모든 플랫폼 공통이며 이 문서가 정본입니다.
- **실패** — "공유 링크 생성에 실패했어요" 토스트를 표시하고 다이얼로그를 유지해 재시도할 수 있게 합니다.
- **진행 중** — 확정 버튼은 문구 공간을 유지한 중앙 스피너("복사 중")로 전환되고, 두 버튼과 배경 탭·ESC 닫기가 모두 잠깁니다.
- 턴이 0개인 채팅에서도 발급을 막지 않습니다(프롤로그만 보이는 공유).

**열람 화면(FE-SCREEN-012)** — `GET /shares/{id}` 응답을 채팅 화면과 같은 렌더 규칙으로 표시하되, 상호작용 요소를 모두 제거합니다.

- **유지** — 프롤로그 버블 → 각 턴(사용자 버블 → AI 버블) 렌더 순서, 강조 마크업(`**볼드**`·`*...*`), 엔딩 배지(`reachedEnding`), 하단 이동 버튼, 헤더 show/hide. 배경 이미지 마커 렌더도 채팅 화면과 동일합니다. 유효한 인물 이미지 저장 마커도 채팅 화면과 같은 위치의 이미지로 표시하고, 마커 글자와 URL은 숨깁니다. 인물 이미지 탭 → 풀스크린 뷰어도 채팅 화면과 동일합니다.
- **제거** — 입력창(컴포저), 선택지·추천 입력, 재생성 버튼, 옵션 메뉴, 온보딩, 스트리밍 관련 UI 전부. 열람은 완결된 스냅샷이므로 SSE·refetch가 없습니다.
- **헤더** — 홈 링크 로고와 스토리 제목을 표시합니다.
- **안내 문구** — "친구가 공유한 채팅을 보고 있어요"를 대화 위에 표시합니다.
- **하단 CTA** — "나만의 스토리 만들고 채팅하기"를 고정해 생성 퍼널로 바로 연결합니다. 웹 URL·온보딩 열람 처리는 [웹 Spec](3-2-web-spec.md#문서-열람과-검색-노출)을 따릅니다.
- **진입 스크롤** — 처음부터 읽는 것이 목적이므로 항상 프롤로그가 보이는 상단에서 시작합니다.
- **진입 애니메이션** — 화면 전체가 함께 표시되며 메시지별 순차 등장은 두지 않습니다. 시간 값은 웹 Design을 따릅니다.
- **로드 실패** — 404(삭제된 채팅·잘못된 링크)를 포함한 로드 실패 시 "공유된 채팅을 찾을 수 없어요" 안내와 홈(`/`) 이동 링크를 표시합니다.

**링크 미리보기** — 스토리 제목·프롤로그 발췌·썸네일을 사용합니다. 서버 조회·브랜드 이미지 대체·문서 제목 처리는 [웹 Design](../design/1-1-web-design.md#라우팅-규칙), 색인 범위는 [웹 Spec](3-2-web-spec.md#문서-열람과-검색-노출)을 따릅니다.

공유 URL의 플랫폼 공통 계약은 세 가지입니다: ① 로그인·게스트 구분 없이 누구나 열람할 수 있고, ② 열람은 열람자의 로컬 서재([웹 사용자 모델](3-2-web-spec.md#웹-사용자-모델))에 아무것도 저장하지 않으며, ③ 분석 이벤트·Sentry에 공유 식별자를 싣지 않습니다([`6-analytics.md §6-4-2-14`](6-analytics.md)). 검색 색인 정책(유효 공유본 색인 허용, 조회 불가 URL의 `noindex, nofollow`)은 웹 소유입니다([3-2-web-spec.md §3-2-4](3-2-web-spec.md#3-2-4-라우팅레이아웃공통-셸) 색인 범위).

| 재진입                                      | 서버 재개 스트림은 없음. 상세를 다시 조회해 완료된 턴만 표시                                                                                                                                 |

### 검수 기준

턴·입력·렌더·재생성·이미지·공유는 각 절의 조건별 결과를 검수합니다. 특히 명시적 실패와 결과 불명 EOF, 진행 중 조각과 확정 턴의 교체, 전송·계정 변경 중 잠금을 구분합니다. 웹 사례는 [채팅 QA](../qa/chats.md)를 따릅니다.

- 선택지의 주요 사건 방향은 [AI 계약](5-ai-server-spec.md)이 소유하고 클라이언트는 3개 렌더를 검수합니다. (US-6-12)
- 공유 헤더에는 공유·옵션만 제공하고 홈 버튼을 두지 않습니다. (US-6-17)
- 게스트 체험 한도·온보딩 기록·공유 제작 CTA는 웹 전용 계약을 따릅니다.

## 3-1-7. API 연동·에러 처리 계약

API 상세 명세는 [백엔드](4-backend-server-spec.md)가 소유합니다. 여기서는 호출 시점과 응답별 사용자 처리를 정합니다. 인증 정보 전달과 호출 창구는 [웹 설계](../design/1-1-web-design.md#1-1-3-bff-프록시토큰-세션)·[Android 설계](../design/1-2-android-design.md#1-2-5-인증과-세션)가 소유합니다.

### 요청 헤더

논리 `device_id`·`session_id`의 의미는 [분석](6-analytics.md#6-2-식별자-정책)이 정본입니다. 플랫폼은 같은 의미의 값을 API 헤더와 분석 SDK에 사용합니다. 초기화·필수 헤더·누락 처리의 플랫폼별 보장은 해당 설계에서 정합니다.

| 헤더                  | 값                     |
| --------------------- | ---------------------- |
| `X-Manyak-Device-Id`  | 논리 `device_id`       |
| `X-Manyak-Session-Id` | 논리 `session_id`      |

두 헤더가 없어도 일반 요청은 거부되지 않습니다(백엔드가 `unknown`으로 채움). 단 **`X-Manyak-Device-Id`가 정책상 필수인 경로**가 있습니다 — 게스트 체험 한도 대상 요청(누락 시 400 — [`4-backend-server-spec.md §4-3-7`](4-backend-server-spec.md)), 로그인 핸드오프 생성(`POST /auth/handoffs`), 핸드오프 없는 첫 로그인의 회원 체험 시드([`4-backend-server-spec.md §4-3-5`](4-backend-server-spec.md)). `X-Manyak-Session-Id`는 모든 경로에서 best-effort입니다.

**요청 식별자** — `X-Manyak-Request-Id`는 백엔드가 생성·응답하는 상관관계 값이며 클라이언트가 만들지 않습니다. 제작 본문의 `requestId`는 멱등·복구용 별개 값입니다.

| 요청 필드 | 전달 기준 |
| --- | --- |
| 채팅 `userSource` | `choice`·`edited_choice`·`typed`. 아래 판정 사용, 허용값 밖은 400 |
| 채팅 `sourceTurnId`·`choiceOrder` | 직전 턴 `turns[].id`와 선택지 인덱스 + 1. 시작 추천·직접 입력에는 보내지 않음. 선택 필드이며 낡거나 범위 밖이면 서버가 연결 기록만 생략 |
| 스토리라인 `parentCreationId` | 최초 `null`, 재생성은 바로 직전 스토리라인 요청 UUID(`trace_creation_id`). `simpleCreationId`·`analytics_creation_id`와 구분. 서버 검증 불일치는 부모 연결만 생략 |

서버 전달 형식은 [백엔드](4-backend-server-spec.md), 분석 식별자 의미는 [분석](6-analytics.md#6-2-식별자-정책)을 따릅니다.

**입력 출처 판정** — 아래 규칙을 따릅니다. 플랫폼별 판정 함수와 QA 연결은 각 설계·QA가 소유합니다.

- 선택지 본문 탭과 무작위 추천 전송(Play 버튼)은 대조 없이 `choice`입니다. 두 경로 모두 전송 전에 사용자가 문장에 손댈 기회가 없습니다.
- "채우기"로 입력창에 넣고 보내는 경로는 전송 시점의 텍스트를 채운 원문과 대조해 가릅니다 — 같으면 `choice`, 다르면 `edited_choice`입니다. 앞뒤 공백 차이는 같은 것으로 보고, **블럭 모드에서 채우면 블럭으로 파싱했다가 다시 직렬화되어 문자열이 달라지므로 그 왕복 결과도 "그대로"로 인정합니다** — 사용자가 손대지 않았는데 `edited_choice`가 되면 선호 신호가 오염됩니다.
- 채운 뒤 모두 지우고 새로 써도 `edited_choice`입니다.
- 채우기를 쓴 적이 없으면 `typed`입니다. 기억해 둔 원문은 전송에 성공하면 비워, 다음 턴 입력이 앞 턴에서 채운 선택지와 대조되지 않게 합니다.

### 화면별 API 사용

호출·성공·실패 처리는 [화면별 계약](#3-1-3-화면별-스펙), [제작](#3-1-4-스토리-생성-퍼널), [채팅](#3-1-5-채팅-플레이와-sse-스트리밍)을 따릅니다. 인증 판정은 플랫폼 세션이 소유하며 `GET /auth/me`는 회원 정보·잔액 조회에 사용합니다.

- 삭제 API의 204는 완료 안내, 404는 무음 성공으로 목록에 반영합니다. 다른 실패는 낙관적 제거를 되돌리고 안내합니다.
- 로그아웃 API가 실패해도 로컬 세션 정리는 계속합니다. 탈퇴 정리는 `DELETE /users/me`의 204 이후 수행합니다.
- 수정 API의 403은 "수정 권한이 없어요" 안내 후 상세로 복귀합니다.
- 출석·초대는 `POST /users/me/credits/attendance`, `GET /users/me/invite`, `POST /users/me/invite/redeem`을 사용합니다. 잔액·출석 여부는 `GET /auth/me`의 `creditBalance`·`attendedToday`로 표시합니다.

### 이프 정책 수치 표시

이프 수치는 인증 없이 조회하는 `GET /credits/policies`를 사용합니다. 고정 대체 수치를 두지 않습니다.

| 필드 | 사용 |
| --- | --- |
| `signupReward` | 가입 보상 |
| `inviteReward` | 친구 초대 메뉴·화면·온보딩·성공 토스트·공유 제목 |
| `inviteMonthlyCap` | 초대자 몫의 월 적립 **횟수** |
| `attendanceReward` | 무료 충전 탭 출석 제목 |
| `storyCreationCost` | 추가 정보 단계 완성 비용 |
| `chatTurnCost` | 회원 채팅 입력창 비용 |

응답 전·실패에는 문구를 유지하고 숫자 자리만 쉬머로 표시합니다. 이프 마크는 잔액(마이·이프 충전), 채팅 입력창 비용, 완성 비용, 구매 상품의 기본 수치 앞에 글자 크기에 맞춰 붙이며(보너스 줄은 마크 자리만큼 들여 맞춤) 장식이라 접근성 이름을 두지 않습니다. 토스트·공유 제목은 발생 시점의 서버 값 스냅샷을 사용합니다. 서비스 안내에는 수치를 복제하지 않으며 이벤트 운영도 서버 정책값으로 반영합니다.

### 날짜 표시 기준

서버 시각(`createdAt`·`expiresAt`·`updatedAt`)은 ISO 8601 UTC입니다. 이프 내역 발생일·만료일, 스토리 상세·제작 카드의 절대 날짜는 `Asia/Seoul`로 변환한 `YYYY-MM-DD`를 표시합니다. UTC 문자열 앞 10자를 자르거나 기기 시간대를 사용하지 않습니다.

채팅 목록의 상대 시간·오늘·어제는 기기 시간대를 사용합니다. 웹 제작 카드의 당일 상대 시간 예외는 [웹 제작 계약](3-2-web-spec.md#웹-제작-흐름)을 따릅니다.

### 응답·에러 처리 정책

- 정상 조회 결과가 비어 있을 때만 빈 상태를 표시합니다. 첫 조회 실패는 오류·재시도, 추가 조회 실패는 기존 목록을 유지한 재시도로 처리합니다.
- 백엔드 에러는 `ApiErrorResponse {timestamp, status, code, message, path, details[]}` 형태이며 `details`는 `{field, message}[]`입니다.
- 읽기 재시도·화면 복귀 재조회는 플랫폼 Design을 따릅니다. [웹 TanStack Query 기본 옵션](../design/1-1-web-design.md#데이터-패칭-기본-옵션-웹)을 공통 플랫폼 계약으로 적용하지 않습니다.
- 서버 원본 메시지·스택은 사용자에게 그대로 노출하지 않습니다. 회원의 인증 실패는 플랫폼의 재발급·세션 종료 절차를 거치며 화면마다 별도 세션 판정을 만들지 않습니다.

### 화면 상태 처리 (로딩·빈·에러)

화면별 상태는 각 화면 스펙([§3-1-3](#3-1-3-화면별-스펙))에 정의하며, 공통 규칙은 다음과 같습니다.

| 상황                 | 처리                                                                                |
| -------------------- | ----------------------------------------------------------------------------------- |
| 목록·상세 최초 로딩  | 지연 로딩(빠른 응답 시 스켈레톤 깜빡임 방지). 지연 전에는 아무것도 표시하지 않음    |
| 버튼 클릭 후 요청 중 | 버튼 비활성화 + 기존 문구 공간을 유지한 중앙 스피너. 버튼의 접근 가능한 이름은 유지 |
| 목록 조회 실패       | 재시도 가능한 에러 안내                                                             |
| 뮤테이션 실패        | 실패 토스트                                                                         |
| 라우트·렌더 오류     | "문제가 발생했어요" + 재시도(루트 오류는 Sentry 보고)                               |
| 존재하지 않는 경로   | "페이지를 찾을 수 없어요" + 홈 링크                                                 |

## 3-1-8. 입력·폼 검증 규칙

피드백·키워드·추가 정보·채팅과 일반 제작·수정의 입력 계약입니다. 소셜 로그인 버튼 자체는 입력 폼 검증 대상이 아닙니다.

### 일반 제작·수정 폼

서버 계약([`4-backend-server-spec.md §4-3-8`](4-backend-server-spec.md))과 동일한 규칙을 클라이언트에서 선검증합니다: 제목 ≤ 100자, 한 줄 소개 ≤ 255자, 시작 설정 이름 ≤ 100자, 장르 1~8개(각 30자 이내), 스토리 설정 4필드·시작 설정 3필드·추천 입력 3개 필수. 주요 사건 ≤ 10개(각 이름·키 문장 필수), 엔딩은 시작 설정당 ≤ 10개(각 이름 필수). 이미지 입력은 없습니다(FE-SCREEN-009, B10). 필수 미충족 섹션은 아코디언 헤더에 상태 배지로 표시하고 등록 버튼을 비활성화합니다.

### 피드백 폼

| 필드  | 타입     | 필수   | 제약                                       | 비고                                                                                                                       |
| ----- | -------- | ------ | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| body  | textarea | 예     | 최대 500자(초과 입력 차단), 글자 수 카운터 | 서버 상한은 2,000자 — 의도된 여유이며 표시 상한은 프론트엔드가 유동 조정 |
| email | email    | 아니오 | 최대 320자                                 | 미입력 시 `null` 전송                                                                                                      |

- 제출 버튼은 `body`가 비어 있어도 활성화합니다. 빈 값으로 제출하면 버튼 위에 "피드백 내용을 입력해주세요"를 표시하고 요청하지 않습니다. 유효한 본문을 입력하면 오류를 제거합니다. 이메일은 필수가 아닙니다.
- `platform`은 UI에서 수집하지 않고 자기 플랫폼 값(웹 `WEB`, 안드로이드 `ANDROID`)으로 고정 전송합니다.
- 제출 중에는 입력·버튼을 비활성화하고 버튼 중앙에 `피드백 전송 중` 스피너를 표시합니다.

### 키워드·커스텀 키워드 (퍼널)

[키워드 선택 규칙](#키워드-선택-규칙)과 인물 단위 입력의 상한·필수·이름 중복 검증을 따릅니다. 웹의 `]` 제한은 [웹 제작 계약](3-2-web-spec.md#웹-제작-흐름)이 소유합니다.

### 추가 정보 (퍼널)

- 추천 추가 정보 토글 + 자유 텍스트 행(추천 추가 정보 최대 3개, 자유 텍스트 UI 최대 10개, 각 100자). 공백 제거 후 비어 있지 않은 값만 전송합니다.
- 전송 페이로드 `additionalInfos`(추천 추가 정보 + 자유 텍스트)의 서버 검증 상한은 총 13개입니다.

### 채팅 입력

서버 상한은 3000자이며 클라이언트는 길이 초과 입력을 차단하지 않습니다. 전송 가능 상태·추천 입력·강조·모드 전환은 [입력창과 선택지](#입력창과-선택지)를 따릅니다. Enter·IME는 웹 스펙이 소유합니다.

### 검증 표시 원칙

- 필드 단위 오류는 해당 필드 근처에, 폼·요청 단위 오류는 토스트로 표시합니다.
- 오류는 해당 필드와 프로그램적으로 연결해 보조기술에 노출합니다. 구현 수단은 플랫폼 소유입니다(웹: `aria-invalid`·`role=alert` — [3-2-web-spec.md §3-2-5](3-2-web-spec.md#3-2-5-반응형접근성브라우저-지원) / 앱: 접근성 시맨틱 — [Android Spec](3-3-android-spec.md#3-3-4-디바이스접근성상태-복원)).
- 비밀번호·토큰 등 민감 입력은 없으며, 자유 입력 원문은 로그·이벤트에 수집하지 않습니다([`6-analytics.md §6-7`](6-analytics.md)).
