# DECISIONS.md

현재 적용 기준은 각 명세에 두고 결정 당시의 이유와 대체 관계는 이 문서에 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다. 기존 ID, 날짜, 당시 상태와 근거를 유지한다.
- 상태와 구현 설명은 원본의 기록 시점을 기준으로 해석한다. 현재 적용 여부나 배포 완료를 과거 기록만으로 단정하지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체하는 결정과 적용 범위를 명시한다.
- 원문에 구분되지 않은 배경, 대안과 영향은 추측해서 보충하지 않는다.
- 이 세트의 ID는 I-110부터 I-139까지 쓴다. Android 결정 이력은 옮기지 않고 iOS에서 내린 결정만 기록한다. 사용자가 확인하기 전의 작성 중 결정은 상태를 Proposed로 둔다.

<a id="i-110-제작-데이터베이스는-grdb로-현재-테이블-세-개만-두고-회원-id로-격리"></a>

**I-110. 제작 데이터베이스는 GRDB로 현재 테이블 세 개만 두고 회원 ID로 격리**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Accepted |
| 관계 | [IOS 기반 I-008](../../../../platform/CLIENT/IOS/DECISIONS.md#i-008)의 제작 데이터베이스 부분. 열 구성은 [I-112](#i-112) |
| 승인 근거 | KNK-2154 작업 대화에서 사용자가 확정했다 |
| 배경 | Android는 `feature/create`가 Room 데이터베이스 `manyak.db`(버전 6)를 가지며 테이블은 간편 제작 진행 `pending_story_creation`, 완성 요청 `story_completion_request`, 일반 제작 접수 연결 `general_story_draft` 세 개다. 수동 마이그레이션 다섯 개가 있고 실패 시 데이터를 지우는 대체 동작이 없다. 로그아웃은 행을 지우지 않고 소유 회원 ID로 격리한다. iOS는 새 앱이라 옮길 기존 데이터가 없다. |
| 채택 | 데이터베이스는 GRDB.swift(SQLite)를 쓰고 Android 스키마 버전 6의 현재 테이블 세 개에 대응하는 테이블만 둔다. 과거 마이그레이션은 옮기지 않는다. 행은 소유 회원 ID로 격리하고 로그아웃에서 지우지 않는다. |
| 대안 | SwiftData(Apple의 영속 저장 프레임워크) |
| 이유 | SwiftData의 구획 쿼리, 뷰 밖 관찰과 변경 이력 관찰은 iOS 27 전용이다(2026-11-26 웹 확인). GRDB는 SQL을 직접 다루고 지원 OS 범위가 넓다. 테이블이 셋뿐이고 관계가 단순하다. |
| 영향 | 테이블과 열은 [4-3-2](4-3-STATE-MANAGEMENT.md#4-3-2-제작-데이터베이스), 첫 출시와 이후 변경은 [6-1](6-DEPLOYMENT.md#6-1-저장-호환)에 둔다. 탈퇴한 회원의 행 삭제는 [I-122](#i-122)가 정한다. |
| 근거 | [KNK-2154](https://kimandkang.atlassian.net/browse/KNK-2154), Android 현황과 iOS 대응 정리(2026-11-26, 저장소 미포함) 1-6절, 1-7절, 7절 19번 |

<a id="i-111"></a>
<a id="i-111-완성-요청은-저장된-행에서-다음-포그라운드나-다음-실행에-이어-보냄"></a>

**I-111. 완성 요청은 저장된 행에서 다음 포그라운드나 다음 실행에 이어 보냄**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Accepted |
| 관계 | [IOS 기반 백그라운드와 프로세스 종료](../../../../platform/CLIENT/IOS/2-STATE-MANAGEMENT.md#2-3-백그라운드와-프로세스-종료)의 제작 요청 부분. 채팅 스트림은 CHAT의 iOS 결정 기록 |
| 승인 근거 | KNK-2154 작업 대화에서 사용자가 확정했다 |
| 배경 | Android는 완성 요청을 Room 행에 먼저 저장하고 앱 범위 작업으로 보내 프로세스가 살아 있는 동안 화면을 떠나도 전송이 이어진다. 프로세스 종료 뒤에는 제작 탭 표시, 당겨서 새로고침과 5초 주기 조회가 PENDING 행을 복구 조회하고 404면 같은 requestId로 다시 보낸다. 제작 탭이 보이지 않으면 앱 시작과 포그라운드 복귀에 따로 확인하지 않는다. iOS는 앱이 백그라운드로 가면 곧 실행이 멈춘다. |
| 채택 | 백그라운드로 갈 때 진행 중 완성 요청을 이어 가는 처리를 두지 않는다. 저장된 PENDING 행은 다음 포그라운드 복귀 또는 다음 실행에서 서버 결과를 확인하고 서버가 받지 못했으면 같은 requestId와 명령으로 다시 보낸다. BackgroundTasks 프레임워크는 쓰지 않는다. |
| 대안 | BackgroundTasks 프레임워크로 백그라운드 실행을 예약 |
| 이유 | 원문에 별도 항목으로 구분하지 않음 |
| 영향 | 제작 탭을 열지 않아도 포그라운드 복귀와 다음 실행에서 결과가 반영되며 Android보다 확인 계기가 넓다. 다음 실행의 확인은 회원 ID가 준비된 뒤 시작한다. 앱을 떠난 동안의 완료는 다음 포그라운드까지 반영되지 않는다. 재확인 계기와 결과별 처리는 [4-4-3](4-4-EXECUTION.md#4-4-3-생성과-완성-복구)에 둔다. |
| 근거 | [KNK-2154](https://kimandkang.atlassian.net/browse/KNK-2154), Android 현황과 iOS 대응 정리 1-7절, 7절 22번 |

<a id="i-112-android-이전-형식-값을-옮기지-않고-모든-쓰기에-회원-id-조건"></a>

**I-112. Android 이전 형식 값을 옮기지 않고 모든 쓰기에 회원 ID 조건**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Proposed |
| 관계 | [I-110](#i-110)의 열 구성 |
| 승인 근거 | 작성 중 결정. 사용자 확인 전 |
| 배경 | Android 버전 6에는 이전 형식을 위한 값이 남아 있다. `ownerId`의 빈 문자열은 버전 3 이전 행을 다음 회원에게 귀속하는 값이고, 완성 요청 `status`의 `FAILED`는 현재 코드가 쓰지 않아 이전 버전 행에만 있다. `general_story_draft`의 `snapshot`과 `createdAt`은 서버 이관 전 기기 초안용이며 현재 코드가 쓰는 행은 `snapshot`이 null인 접수 연결뿐이다. 완성 요청의 상태 변경과 삭제는 `requestId`로만 거른다. |
| 채택 | `ownerId`는 빈 값 없이 필수로 두고 소유자 없는 행의 귀속 절차를 두지 않는다. `status`는 `PENDING`과 `COMPLETED`만 쓴다. `general_story_draft`는 `ownerId`, `draftId`, `acceptedSubmissionId`만 둔다. 세 테이블의 모든 읽기와 쓰기에 현재 회원 ID 조건을 건다. |
| 대안 | Android 열과 값을 그대로 옮김: 쓰지 않는 열과 값의 의미를 구현자가 다시 추측해야 한다 |
| 이유 | iOS에는 이전 형식 행이 생길 수 없다. 회원 ID 조건이 빠진 쓰기는 로그아웃 직후 늦은 결과가 다른 회원의 행을 바꿀 여지를 남긴다. |
| 영향 | 늦은 완료와 실패 처리는 현재 회원의 행에만 반영된다. 이전 형식 값이 필요해지면 새 마이그레이션과 새 결정으로 더한다. |
| 근거 | Android 기준 커밋의 [버전 6 스키마](https://github.com/KIM-N-KANG/manyak-android/tree/ccc93f77289fd960def116184c2c86c552e4124e/feature/create/schemas)와 [제작 저장소 코드](https://github.com/KIM-N-KANG/manyak-android/tree/ccc93f77289fd960def116184c2c86c552e4124e/feature/create/src/main/java/app/manyak/create/data) |

<a id="i-113-제작-화면은-복원하지-않고-새-제작은-서버-초안을-조회하지-않음"></a>

**I-113. 제작 화면은 복원하지 않고 새 제작은 서버 초안을 조회하지 않음**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Proposed |
| 관계 | [공통 UI iOS I-032](../../../../ui/IOS/DECISIONS.md#i-032)의 제작 화면 적용 |
| 승인 근거 | 작성 중 결정. 사용자 확인 전 |
| 배경 | Android는 프로세스 종료 뒤 백스택을 복원하므로 새 제작 화면도 라우트의 draftId로 서버 초안 상세를 한 번 조회하고, 오프라인에서는 새 제작이 불러오기 실패와 다시 시도로 열린다. iOS는 프로세스 종료 뒤 선택 탭만 복원하고 각 탭은 루트에서 시작한다. |
| 채택 | 간편 제작, 일반 제작, 재제출과 수정 화면을 프로세스 종료 뒤 복원하지 않고 남은 작업은 제작 탭 카드로 이어 간다. 새 제작은 새 UUID의 서버 세션으로 서버 상세를 조회하지 않고 연다. 카드로 재개할 때만 조회한다. |
| 대안 | 새 제작도 진입 때 서버 상세를 조회: 새 UUID라 결과가 항상 없음이고 오프라인에서 새 제작을 막는다 |
| 이유 | 복원하지 않는 화면을 위해 조회할 이유가 없다. |
| 영향 | 오프라인에서도 새 제작의 입력을 시작할 수 있고 실패는 첫 저장과 생성 요청에서 안내한다. 저장하지 않은 입력은 프로세스 종료에서 사라진다. |
| 근거 | [공통 UI iOS I-032](../../../../ui/IOS/DECISIONS.md#i-032) |

<a id="i-114"></a>
<a id="i-114-일반-제작-이미지는-화면-수명의-임시-파일로만-둠"></a>

**I-114. 일반 제작 이미지는 화면 수명의 임시 파일로만 둠**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Proposed |
| 관계 | [I-113](#i-113) |
| 승인 근거 | 작성 중 결정. 사용자 확인 전 |
| 배경 | Android는 고른 이미지를 앱 파일 영역의 `general-story-images/<회원 ID 해시>/` 아래 고유 이름으로 저장한다. 이 보관은 서버 이관 전 기기 초안이 참조하는 파일을 지키기 위한 것이고, 일반 제작 입력이 서버 초안으로 옮겨진 뒤에는 화면을 닫을 때 후보 파일을 지운다. 자르기 결과는 캐시 영역에 따로 쓰며 지우는 코드는 찾지 못했다. iOS에는 기기 일반 초안과 제작 화면 복원이 없다. |
| 채택 | 자른 JPEG는 앱 임시 디렉터리의 `general-story-images` 아래 고유 이름으로만 쓴다. 업로드 실패와 교체로 쓰지 않게 된 파일은 바로, 나머지는 폼 화면을 닫을 때 지우고 앱 시작 때 디렉터리를 비운다. 회원별 하위 디렉터리를 두지 않는다. 저장과 재개의 기준은 서버 objectKey와 미리보기 URL이다. |
| 대안 | Android처럼 회원별 영구 디렉터리에 보관: 읽을 기기 초안이 없어 지울 시점만 늘어난다 |
| 이유 | 파일을 읽는 곳이 열린 폼 하나뿐이다. 앱 시작 정리로 종료 때 남은 파일이 다음 회원에게 이어지지 않는다. |
| 영향 | 업로드했지만 서버 초안에 저장하지 않은 이미지는 프로세스 종료 뒤 다시 골라야 한다. 저장한 초안은 서버 미리보기 URL로 다시 그린다. |
| 근거 | Android 기준 커밋의 [일반 제작 이미지 코드](https://github.com/KIM-N-KANG/manyak-android/tree/ccc93f77289fd960def116184c2c86c552e4124e/feature/create/src/main/java/app/manyak/create/general) |

<a id="i-115"></a>
<a id="i-115-사진은-시스템-선택기의-호환-형식으로-받고-자르기는-전체-화면-덮개"></a>

**I-115. 사진은 시스템 선택기의 호환 형식으로 받고 자르기는 전체 화면 덮개**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Proposed |
| 관계 | 공통 [일반 제작과 수정 입력](../2-2-REQUIREMENTS.md#2-2-6-일반-제작과-수정-입력)의 이미지 조건 |
| 승인 근거 | 작성 중 결정. 사용자 확인 전 |
| 배경 | 공통 요구는 JPG, PNG, WEBP와 5MB 이하만 받고 표지 3:4, 인물 4:3으로 자른다. Android는 Photo Picker 결과의 실제 형식과 크기를 확인하고 바텀 시트에서 자른다. iPhone 카메라 사진의 기본 저장 형식은 HEIC다. iOS 시스템 시트는 끌어내리면 닫히므로 이미지 이동 제스처와 겹친다. |
| 채택 | 시스템 사진 선택기로 고르고 사진 보관함 접근 권한을 요청하지 않는다. 선택기에 호환 형식 표현을 요청해 HEIC 사진을 JPEG로 받은 뒤 받은 데이터의 실제 형식과 크기를 공통 조건으로 확인한다. 자르기는 전체 화면 덮개에서 한다. |
| 대안 | 원본 표현을 받아 HEIC를 형식 오류로 처리: 카메라 사진 대부분을 올릴 수 없다<br>시트에서 자르기: 끌어내려 닫기와 이미지 이동이 겹친다 |
| 이유 | 고른 사진을 공통 형식 조건 안에서 올릴 수 있게 하고 자르는 동안 실수로 닫히지 않게 한다. |
| 영향 | 호환 형식을 요청하는 선택기 설정의 정확한 API는 이번 작성에서 확인하지 않았다. 변환한 JPEG가 5MB를 넘으면 크기 안내를 한다. 공통 형식 조건은 바꾸지 않는다. |
| 근거 | 작성 중 판단 |

<a id="i-116-제작과-수정-화면은-헤더-닫기로-이탈-확인하고-확인이-필요한-동안만-가장자리-밀기를-끔"></a>

**I-116. 제작과 수정 화면은 헤더 닫기로 이탈 확인하고 확인이 필요한 동안만 가장자리 밀기를 끔**

| 관계 | 공통 UI iOS [I-052](../../../../ui/IOS/DECISIONS.md#i-052) 이탈 확인 규칙의 대상 화면 |
| 승인 근거 | KNK-2154 작업 대화에서 사용자가 확정했다 |
| 배경 | 공통 이탈 조건은 닫기와 뒤로가기 모두 남는 내용과 사라지는 내용을 구분해 확인한다. 공통 UI iOS는 가장자리 밀기와 뒤로 버튼으로 한 화면씩 복귀한다. 시스템 복귀 앞에 확인을 끼워 넣는 SwiftUI 공개 방법은 이번 작성에서 확인하지 못했다. Android는 시스템 뒤로가기도 같은 이탈 확인을 거치고 일반 제작은 입력이 없어도 이미지 업로드나 쓰기 요청 중이면 확인을 유지한다. |
| 채택 | 간편 제작 세 단계, 일반 제작, 재제출과 수정 화면의 헤더에는 시스템 뒤로 버튼 대신 닫기를 둔다. 닫기는 공통 이탈 조건을 거치며 일반 제작의 업로드와 쓰기 요청 중 확인 유지를 iOS에도 적용한다. 가장자리 밀기는 닫기를 누르면 확인이 뜰 상태인 동안에만 끄고, 닫기가 확인 없이 바로 나가는 상태에서는 한 화면 복귀로 둔다. 방식 선택은 시스템 뒤로 복귀를 쓴다. |
| 대안 | 시스템 뒤로 복귀 유지: 확인 없이 입력을 잃거나 접수 안내를 보지 못한다<br>입력이 있을 때만 뒤로 버튼을 숨김: 입력에 따라 헤더 모양이 바뀐다<br>가장자리 밀기를 항상 끔: 아무것도 입력하지 않은 화면에서도 밀기가 막힌다 |
| 이유 | 입력 손실 확인이 밀어서 돌아가는 관례보다 중요하고, 잃을 내용이 없는 동안에는 시스템 관례를 그대로 둔다. |
| 영향 | 공통 요구 [2-2-7](../2-2-REQUIREMENTS.md#2-2-7-저장과-이탈)과 흐름 [3-2-4](../3-2-INTERACTION-FLOWS.md#3-2-4-저장과-이탈-확인)의 Android 일반 제작 문장에 iOS를 더했다. 이 화면들은 공통 UI iOS 이탈 확인 규칙의 대상이다. 가장자리 밀기는 한 화면만 돌아가므로 닫기와 달리 방식 선택이나 수정 화면을 연 화면에 닿는다. SwiftUI는 뒤로 버튼을 숨기면 가장자리 밀기도 함께 끌 수 있어 조건에 따라 켜려면 UIKit 제스처를 따로 다뤄야 할 수 있다. 이번 작성에서 확인하지 않았으며 구현에서 확인한다. |
| 근거 | [KNK-2154](https://kimandkang.atlassian.net/browse/KNK-2154), [공통 UI iOS I-052](../../../../ui/IOS/DECISIONS.md#i-052) |
