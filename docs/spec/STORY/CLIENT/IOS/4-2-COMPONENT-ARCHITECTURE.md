# 4-2 컴포넌트 구조: iOS

기준: [공통 계약](../4-1-CONTRACT.md), [iOS 화면](3-1-INFORMATION-ARCHITECTURE.md).

### 4-2-1 소유권

타깃 사이 허용 의존과 계층 폴더 규칙은 [IOS 기반 구성](../../../../platform/CLIENT/IOS/1-COMPONENT-ARCHITECTURE.md#1-2-모듈과-허용-의존)을 따른다.

| 경계 | 책임 |
|---|---|
| `ManyakHome` | 홈 섹션 조회, 가입 온보딩이 쓰는 인기 오리지널 첫 페이지(`PopularOriginalStories`) 구현, 탐색 목록의 커서 조회와 칸별 전환, 스토리 검색과 기기 최근 검색어 |
| `ManyakOnboarding` | 오리지널 선택, 온보딩 표시 기록과 채팅 시작 |
| `ManyakStory` | 상세 조회, 시작 선택, 채팅 시작 시트, 좋아요와 상세 옵션 |
| `ManyakStudio` | 제작 카드 조합, 완성 중 카드 조회 주기, 서버 제출본 목록과 삭제 |
| `ManyakCreate` | 간편 제작의 입력과 생성, 일반 제작과 수정의 폼 Entity와 순수 변환, 서버 초안 저장, 제작 데이터베이스와 완성 요청 실행, 이미지 업로드 |
| `ManyakNavigation` | 초안 ID와 재개 여부, 제출본 및 스토리 ID를 담는 라우트 |
| 앱 타깃 | 탭과 탐색 탭 진입 판정, 상세와 제작 진입 연결, 제작 흐름 종료 뒤 탭 복귀, 온보딩과 메인 셸 전환, 가입 시 호출 목록과 `UserScopedStore` 등록 |
| `ManyakCommon` | 공유하는 초안 접근, 채팅 시작과 인기 오리지널 조회 계약, 오류 문구, 제작 안내 단계와 진행 기록 계약 및 절차 |
| `ManyakDesignSystem` | 카드, 표지 뱃지와 장르 뱃지 줄, 옵션 시트, 이미지 뷰어와 이미지 요소, 선택 테두리, 마스코트 재료와 순환 문구, 제작 안내 대화창 |

화면 Store는 입력, 화면 상태와 실행 수명을 가지며 `body` 재평가와 화면 재등장에 도메인 조회와 복구를 직접 묶지 않는다. 화면은 보임과 숨김을 Store에 Intent로 알리고 Store는 숨김에서 보임으로 바뀔 때만 조회와 주기 작업을 시작한다. 화면이 스택 아래로 가려지거나 탭이 바뀌어 사라진 것을 앱 백그라운드로 해석하지 않는다.

### 4-2-2 공용 조립

일반 제작과 간편 제작은 헤더, 저장 버튼, 접는 항목과 장르 검색을 함께 쓴다. 방식 선택 일러스트와 분량 슬라이더는 `ManyakCreate`가 가지고 두 번째 사용처가 생기기 전에 `ManyakDesignSystem`으로 올리지 않는다.

간편 제작 세션은 `ManyakCreate`의 앱 수명 객체 하나가 draftId에 묶어 가지며 세 단계 라우트의 Store가 같은 세션을 쓴다. 다른 draftId에 묶으면 앞 생성 실행과 메모리를 정리한다. 완성 요청 실행자와 제작 데이터베이스도 조립 객체가 한 번 만드는 앱 수명 객체다. 제작 탭은 `CreationProgressAccess`로 기기 진행 카드와 완성 실패를 받고 `ManyakCreate`를 직접 참조하지 않는다. ([IOS 기반 공용 포트와 조립](../../../../platform/CLIENT/IOS/1-COMPONENT-ARCHITECTURE.md#1-4-공용-포트와-조립))

폼은 로컬 안정 ID와 서버 ID를 구분한다. 순수 변환이 설정 글, 인물과 장르 및 baseline을 다루며 검수 경로는 제출 시점의 안정 ID로 연결한다. 이미지 업로더는 presign 요청과 공통 헤더 및 인증을 싣지 않는 업로드 요청을 조립하며 업로드 요청은 `ManyakCreate`의 `Data`에만 둔다.

마스코트는 시간에서 자세를 계산하는 안무와 그리기 전용 뷰로 나눈다. 공용 몸과 눈, 붓과 베레모를 쓰고 `ManyakStudio`는 완성 표지 장면만 가진다. API 조회와 주기 작업은 애니메이션이 갖지 않는다.

제작 안내는 간편 제작 세 화면과 제작 탭이 함께 쓰고 두 기능은 서로 참조하지 않는다. 단계와 진행 기록 계약, 여는 판정과 기록 절차는 `ManyakCommon`, 기록 구현은 `ManyakCreate`의 기기 suite 저장소이며 조립 객체가 계약에 넘긴다. 대화창과 말하는 마스코트는 문구와 콜백만 받는 `ManyakDesignSystem` 구성 요소이며 화면이 투명 바탕의 전체 화면 덮개로 띄워 탭 바까지 덮는다. 단계 문구는 그 단계를 여는 기능이 가진다. 각 화면 Store가 안내 받을 화면 조건을 계산해 절차를 만들고 가지며 열린 단계는 화면 상태와 따로 절차가 가진다. 분석 이벤트 전송은 `ManyakAnalytics`가 맡는다.

가입 온보딩 표시는 ACCOUNT의 로그인 결과에서 신규 가입일 때 앱 타깃의 가입 시 호출 목록이 기록하고 `ManyakAuth`는 호출 대상의 종류를 알지 않는다.
