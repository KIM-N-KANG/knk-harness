## 3-3-1. 적용 범위와 사용자 모델

- 서비스 진입은 로그인 필수입니다. 게스트 온보딩·로컬 서재·회원 이관·게스트 체험 선차단은 적용하지 않습니다.
- 약관·개인정보처리방침은 로그인 전에도 열람할 수 있습니다. 닫으면 로그인 화면으로 돌아갑니다. 회원은 마이의 서비스 안내에서도 법적 문서를 열 수 있습니다.
- 소셜 인증은 [공통 동의 모델](3-1-client-spec.md#fe-screen-010-서비스-이용약관개인정보-처리방침)의 가입 대기 흐름을 따릅니다. 현행 필수 동의가 모두 있으면 바로 로그인하고, 동의가 남으면 계정과 세션 없이 필수 동의 바텀 시트를 로그인 화면 위에 표시합니다. 대기 코드는 프로세스 메모리에만 두고 디스크·로그·Crashlytics·분석에 남기지 않으므로, 프로세스가 재시작되면 로그인 화면부터 다시 시작합니다. 새 로그인을 시작하면 이전 대기를 버립니다. 시트는 끌어내리기·바깥 탭으로 닫히지 않으며, "동의하기" 아래의 "로그아웃"과 뒤로가기는 동의하지 않은 것으로 보고 가입을 취소해 로그인 화면에 남깁니다(제출 중에는 무시). 시트의 "보기"는 전문을 시트 위 전체 화면 창으로 열고 닫으면 체크 상태 그대로 시트로 돌아옵니다. 가입 완료의 네트워크 오류와 5xx는 시트를 유지하고 "약관 동의 내역을 저장하지 못했어요"와 다시 시도를 제공합니다. 대기 코드가 만료됐으면 시트를 닫고 로그인 화면에 "로그인 시간이 지났어요. 다시 로그인해주세요", 약관 버전이 바뀌었거나 필요한 항목이 늘었으면 "약관이 갱신되었어요. 다시 로그인해주세요"를 표시하며, 소셜 로그인을 자동으로 다시 시작하지 않습니다. 가입 완료 뒤에는 서버에서 동의 완료를 다시 확인하기 전에는 홈과 회원 화면을 생성하지 않으며, 확인 중에도 로그인 화면에 머물고 소셜 로그인 버튼을 잠급니다. 이 확인 중 뒤로가기는 로그아웃으로 처리합니다. 확인 조회의 네트워크 오류와 5xx에는 같은 시트에서 다시 시도와 "로그아웃"을 제공하며 회원 기능을 열지 않고, 403에는 이용 제한 안내와 로그아웃만 제공합니다(정지 회원도 가입 완료까지는 진행됩니다). 서버에서 필수 동의 완료를 확인하기 전에는 회원 분석 식별, 푸시 토큰 등록, 프로필과 회원 체험 잔여 자동 조회를 시작하지 않습니다. 필수 동의 완료 후 회원 화면에 진입하며 알림 권한 요청, 선택한 광고 동의 처리, 신규 가입 안내, 광고 알림 재질문 순으로 진행합니다. 이미 최신 필수 동의가 있는 회원은 시트 없이 진입합니다.
- 저장된 세션으로 앱을 시작하면 시스템 스플래시 다음의 시작 화면(로고 심벌, 확인이 길어지면 심벌이 튀는 로딩)에서 필수 동의를 확인합니다. 확인이 끝난 회원은 로그인 화면 없이 회원 화면으로 이동합니다. 추가 동의가 필요하면 시작 화면 위에 동의 시트를 표시합니다. 조회의 네트워크 오류와 5xx는 시작 화면에서 재시도를, 403은 이용 제한 안내와 로그아웃만 제공합니다. 시작 화면의 조회 실패에는 공통 계약의 "로그아웃"을 두지 않습니다. 시작 조회 및 오류 화면의 뒤로가기는 앱을 떠나며 세션을 종료하지 않습니다. 이미 로그인한 세션이므로 동의 시트의 "로그아웃"과 뒤로가기는 동의 거절로 로그아웃합니다. 시스템 스플래시를 서버 응답까지 붙잡거나 완료 전 회원 기능을 실행하지 않습니다.
- Google·Kakao 로그인, 계정 연동·탈퇴와 신규 가입 안내는 공통 계약을 따릅니다. 로그인과 필수 동의 확인 후에는 회원 화면, 로그아웃·탈퇴 후에는 인증 화면을 엽니다.
- 저장 세션 판정 전에는 로그인·회원 화면 어느 쪽도 확정하지 않습니다. 종료 정리가 남아 있으면 복구·재시도 화면을 제공하고 새 로그인을 열지 않습니다.
- 세션 복원·재발급의 네트워크 실패만으로 회원 세션을 폐기하지 않습니다. 정지 계정·유효하지 않은 세션 종료는 일반 로그아웃과 구분해 안내합니다.

## 3-3-2. 내비게이션·화면 계약

### 메인 탭 셸

- 홈·채팅·제작·마이의 네 탭을 제공합니다. 탭별 스크롤·화면 상태를 보존합니다.
- 다른 탭의 시스템 뒤로가기는 홈으로, 홈의 뒤로가기는 앱 밖으로 이동합니다. 탭 방문 순서를 화면 이력으로 쌓지 않습니다.
- 헤더·하단 탭은 탭 전환 중 같은 위치를 유지합니다. 아이콘·라벨·주변 터치 영역이 같은 탭을 선택하고 접근성 이름과 선택 여부를 한 번씩 읽어야 합니다.
- 상세는 진입한 탭 위에서 열고 닫으면 그 탭으로 복귀합니다. 상세에서 스토리 삭제에 성공하면 상세를 닫고 제작 탭으로 이동합니다. 상세에서 채팅을 시작하면 뒤로가기로 상세에 돌아오고 다시 뒤로가면 원래 탭으로 돌아갑니다.
- 확인 다이얼로그의 머무르는 왼쪽 버튼은 모두 "닫기"로 표기합니다. 공통 계약의 카드와 채팅 삭제 확인 "남겨두기", 웹 일반 제작 이탈 경고의 "계속 만들기"도 Android에서는 "닫기"로 표시합니다.

### 스토리 목록·상세

- 공통 목록·메타·신고·삭제 계약과 [스토리 좋아요 계약](3-1-client-spec.md#fe-screen-003-스토리-상세)을 따릅니다. 서비스 진입이 로그인 필수라 게스트 판별과 로그인 필요 시트는 적용하지 않고, 좋아요 버튼은 상세 `isOwner`로만 숨깁니다. 제작 카드의 더보기와 길게 누르기는 같은 [카드 옵션 시트](3-1-client-spec.md#fe-screen-013-제작--내-스토리-목록)를 열고, 상세 헤더의 더보기도 같은 시트입니다. 시트에 카드 축소판은 두지 않습니다.
- 홈의 필터·정렬 선택은 홈 탭이 살아 있는 동안 유지하고 저장하지 않습니다. 앱을 다시 시작하면 전체·인기순으로 엽니다. 당겨서 새로고침은 목록을 움직이지 않고 표시자만 필터·정렬 줄 뒤에서 내려오므로 줄도 제자리에 둡니다.
- 상세 헤더의 삭제는 서버 `isOwner`가 참인 경우에만 제공합니다. 제목·서버 권한과 무관하게 클라이언트가 소유권을 추측하지 않습니다.
- 카드 옵션에서 삭제하면 확인을 거치고 해당 항목만 제거합니다. 실패 시 항목과 화면을 유지합니다.
- 상세의 썸네일·주변 인물 이미지 뷰어는 시스템 뒤로가기로 뷰어만 닫습니다. 이미지가 없으면 뷰어를 열지 않습니다.
- 좋아요는 요청 즉시 상세의 상태와 수를 반영하고 실패하면 요청 직전 값으로 복원하며 실패 토스트를 표시합니다. 요청 중 잠금과 응답 뒤 0.5초 쿨다운을 유지합니다. 성공한 수는 홈의 같은 카드에도 반영하되 목록 순서와 스크롤 위치를 유지합니다. 다음 목록 조회는 서버 값을 사용하고, 조회 중 성공한 좋아요는 늦게 도착한 응답이 덮지 않습니다.
- 상세의 채팅 시작 실패는 토스트로 안내합니다.
- 상세의 채팅 시작 연타는 채팅 하나만 생성합니다. 돌아온 상세는 턴 수 등을 갱신하되 첫 로딩 스켈레톤으로 되돌리지 않습니다.
- [페르소나 선택](3-1-client-spec.md#fe-screen-003-스토리-상세)은 공통 계약을 따르며, 로그인 필수라 게스트의 목록 미조회와 로그인 필요 시트는 적용하지 않습니다. 상세에서 만든 페르소나의 미리 선택은 프로세스 메모리에만 있어 앱을 다시 시작하면 남지 않습니다. 채팅을 시작하면 미리 선택은 사라지지만, 상세가 백스택에 남아 채팅방에서 돌아오면 시작한 주인공이 그대로 선택되어 있습니다. 고른 페르소나가 마이에서 삭제되면 상세로 돌아왔을 때 기본 주인공으로 돌아갑니다. 셀렉트 선택은 구성 변경에서 유지합니다.

### 채팅 목록과 채팅방

- 채팅 헤더는 공통 헤더 show/hide(메시지 영역 빈 곳 탭 전환)를 따르며 스크롤로는 숨기지 않습니다. 앱 채팅에는 텍스트 선택이 없으므로 제외 조건은 버튼·선택지·인물 이미지 탭과 키보드가 떠 있을 때의 탭이고, 안내 투어 중에는 숨겨 둔 헤더도 표시합니다. 숨김 여부는 구성 변경에서 유지하고, 방을 열기 전(로딩·실패)에는 항상 표시합니다.
- [첫 진입 안내 투어](3-1-client-spec.md#첫-진입-안내)는 공통 계약을 따르며, 로그인 필수라 게스트 동의 시트 조건은 적용하지 않습니다. 시스템 뒤로가기는 채팅방을 떠나지 않고 건너뛰기와 같이 투어를 닫고 건너뛰기 이벤트를 보냅니다. 보고 있던 스텝은 구성 변경에서 유지하고, 딤 뒤 화면은 보조기술에서도 가립니다. 열람 기록은 기기 단위이며 로그아웃·계정 전환에 지우지 않습니다.

- 실시간 이미지 기본값과 두 번째 턴 완료 안내는 [공통 채팅 설정 계약](3-1-client-spec.md#채팅-설정-시트와-메뉴-시트)을 따릅니다. 설정값이 없는 기존 설치도 기본 off이며 명시적으로 저장한 값은 유지합니다. 누적 완료 횟수는 기기 단위로 보존하고 로그아웃과 계정 전환에 지우지 않습니다. 기록을 읽거나 저장하지 못하면 안내를 열지 않습니다.
- 실시간 이미지 안내 중 스위치를 켜면 딤과 안내 카드가 사라지고 켜진 설정과 설정 시트는 유지합니다. 안내 중 시스템 뒤로가기는 안내만 닫고 설정 시트는 남깁니다. 안내를 닫은 뒤의 뒤로가기는 시트를 닫습니다. 시트가 닫히면 안내도 함께 닫습니다. 딤 뒤 화면과 시트의 나머지 항목은 보조기술에서 가리고, 밝게 남은 실시간 이미지 스위치와 안내 카드만 조작할 수 있습니다.
- 안내 예약과 표시 중인 안내, 설정 시트 열림은 회전, 다크 모드, 글자 크기 변경에서 유지합니다. 하이라이트는 다시 측정하며 장식 애니메이션은 재개를 보장하지 않습니다. 채팅방 이탈과 프로세스 종료 뒤에는 예약이나 표시 상태를 복원하지 않습니다. 두 번째 완료 때 이미 판단한 기기 기록으로 재진입 시 다시 안내하지 않습니다.
- 전송 잠금 중에도 설정 버튼을 누를 수 있습니다. 설정 변경은 다음 요청부터 적용하고 이미 진행 중인 턴의 요청 값과 표현은 전송 시점 스냅샷을 유지합니다.

- 서버의 최근 활동순을 유지하고 완료 턴이 없는 새 채팅도 표시합니다. 빈 미리보기에는 안내 문구를, 삭제된 참조 스토리에는 '삭제된 스토리'를 표시합니다.
- 채팅이 없는 화면은 "아직 진행중인 채팅이 없어요" 안내만 표시하며 별도 제작 CTA를 두지 않습니다.
- 목록을 당겨 새로고침할 때 기존 목록을 유지합니다. 실패 시 목록 아래 또는 토스트로 안내하고 첫 로딩·빈·오류 상태에서 불필요한 당김을 허용하지 않습니다.
- 카드의 더보기·길게 누르기는 카드 옵션 시트로 공유·신고·삭제를 엽니다(공유하기는 채팅방 메뉴와 같은 발급·전달). 채팅방 헤더의 더보기는 [메뉴 시트](3-1-client-spec.md#채팅-설정-시트와-메뉴-시트)를 엽니다. 공유하기는 클립보드에 복사하지 않고 발급한 웹 열람 링크를 Android 공유 시트로 바로 보내며, 성공 토스트 없이 메뉴 시트를 닫습니다. 실패 안내와 진행 표시는 공통 계약을 따릅니다. 참조 스토리 ID가 없거나 제목이 비어 있는 채팅에는 신고 및 새 채팅 시작하기를 제공하지 않습니다. 제목이 공백뿐인 경우도 같습니다. 메뉴 시트의 새 채팅 시작하기는 시작 설정 없이 채팅을 만들고 현재 방을 새 방으로 교체해 뒤로가기가 이전 방으로 돌아가지 않습니다. 채팅방에서 삭제하면 채팅 탭으로 돌아가고 삭제한 방은 복원되지 않습니다.
- [플레이 중인 페르소나](3-1-client-spec.md#fe-screen-005-채팅-화면) 표시는 공통 계약을 따릅니다. 채팅방 메뉴 시트의 새 채팅 시작하기는 기본 주인공으로 시작합니다.
- 텍스트·강조·인물 이미지·블럭 입력·추천·재생성 의미는 공통 계약을 따릅니다. 확정 턴·스트리밍 턴의 인물 이미지는 같은 풀스크린 뷰어로 열며 시스템 뒤로가기는 채팅방을 떠나지 않고 뷰어만 닫습니다.
- 채팅 작성 중 상황·대사 추가, 강조 삽입, 입력 삭제 등 작성 버튼의 탭은 입력 포커스를 해제하지 않습니다. 작성 버튼 밖의 빈 영역·채팅 본문 탭은 키보드를 닫습니다. 현재 입력칸을 삭제하면 남은 다음 칸, 없으면 이전 칸으로 포커스를 옮깁니다. 마지막 입력칸 삭제·입력 모드 교체·전송 후 입력 잠금처럼 편집 대상이 없어지는 경우와 별도 다이얼로그의 창 처리는 기존 동작을 따릅니다.
- 스트리밍 중 구성 변경에도 입력 잠금·누적 응답·스크롤 앵커를 유지합니다. 정상 종료 이벤트 없이 끊겨도 잠금을 풀고 서버 결과로 복구합니다.

### 마이·법적 문서

- 회원 프로필·계정 연동·이프·출석·초대·탈퇴는 공통 계약을 따릅니다. API 응답 전에는 정책 수치를 임의 기본값으로 표시하지 않습니다.
- 법적 문서와 서비스 안내는 앱 안의 문서 화면에서 엽니다. 웹 본문과 시행일·버전이 같아야 하며 게스트 이용 안내는 웹 브라우저 전용이라는 안내와 함께 표시합니다. 문서 외 같은 호스트의 새 페이지 로드는 차단하고 외부 HTTP(S) 링크는 외부 브라우저로 엽니다.
- 초대 코드 복사·공유는 시스템 기능으로 제공하며, 공유에 사용하는 보상 수치는 서버 정책을 따릅니다.
- [페르소나 생성과 관리](3-1-client-spec.md#fe-screen-008-로그인마이-페이지)는 공통 계약을 따르고, 마이의 "페르소나" 섹션은 이프 카드 아래 이벤트 섹션 위에 둡니다. 생성과 수정은 저장하면 들어온 화면(스토리 상세 또는 관리 목록)으로 돌아갑니다. 조회 실패의 재시도 버튼은 앱의 다른 목록과 같은 "다시 시도"입니다. 생성과 수정 입력은 구성 변경에서 유지하고 프로세스 종료 뒤에는 복원하지 않습니다.
- 신규 가입 초대 안내의 닫기 기록을 저장하지 못해도 현재 실행에서는 시트를 닫습니다. 보상 지급에 성공했다면 지급 성공과 닫기 기록 실패를 구분해 안내하며, 보상 수치는 서버 정책을 사용합니다. 다음 실행에서 안내가 다시 표시될 수 있고, 닫힌 시트의 이전 제출을 재실행하지 않습니다.

## 3-3-3. 제작과 데이터 보존

### 일반 제작과 스토리 수정

- 제작 탭의 FAB는 제작 방식 선택을 엽니다. 간편 제작과 일반 제작을 선택하면 해당 입력 화면으로 이동하고, 닫으면 제작 탭으로 돌아옵니다. 두 제작 화면은 다른 쌓이는 화면과 같은 수평 이동으로 들어오고 나갑니다. 간편 제작의 헤더는 "스토리 간편 제작"입니다.
- 일반 제작과 수정의 필드, 검증, 이미지 삭제 및 검수 사유는 [공통 폼 계약](3-1-client-spec.md#fe-screen-009-일반-제작스토리-수정)을 따릅니다. 일반 제작 장르는 제공 장르만 선택하며 기존 스토리 수정은 저장되어 있던 장르도 유지할 수 있습니다.
- 기존 스토리 수정은 변경되어 전송되는 필드만 검증합니다. 수정하지 않은 기존 값은 그대로 보존하며 신규 등록과 반려 후 전체 재제출은 전체 폼을 검증합니다.
- 일반 제작은 임시 저장 버튼과 실제 앱 백그라운드 전환에서 저장합니다. 탭 이동, 회전, 테마 변경과 이미지 선택기 왕복은 저장 계기가 아닙니다. 성공 시 버튼 모양은 유지하고 토스트로 안내하며 2초 동안 다시 누르지 못합니다.
- 일반 제작 초안은 계정별로 여러 개 보관하며 간편 제작 초안과 처음 저장한 시각의 최신순으로 표시합니다. 제목과 한 줄 소개 및 표지를 카드에 표시하고, 값이 없으면 "만들고 있는 스토리", "일반 제작으로 만들고 있었어요" 및 기본 심벌을 사용합니다. 이어서 만들기는 스토리 프로필 탭부터 엽니다.
- 신규 등록을 접수하면 해당 초안을 목록에서 제거하고 같은 폼을 다시 임시 저장하지 않습니다. 서버 제출본이 입력의 정본이며 반려와 실패 카드의 수정하기로 같은 제출본을 다시 제출합니다. 등록 응답을 확인하지 못한 경우 자동으로 재전송하지 않고 제작 탭에서 확인하도록 안내합니다.
- 일반 제작은 입력한 것도 저장하거나 등록을 요청한 것도 없으면 확인 없이 닫습니다. 그 밖의 닫기는 저장본이 없는 입력, 저장 후 편집, 저장된 초안, 접수 후 수정 여부에 따라 사라지는 내용을 안내합니다. 수정 화면은 변경한 내용이 있을 때만 "저장하지 않은 내용이 있어요"와 "지금 나가면 수정한 내용이 사라져요"로 확인합니다.
- Photo Picker로 고른 이미지의 실제 형식과 크기를 검사하고, 표지는 3:4와 인물 이미지는 4:3으로 자릅니다. 자르기 화면은 이동과 확대를 지원하고 구성 변경에서 선택 범위를 유지합니다. 취소와 업로드 실패는 이전 이미지를 유지하며 업로드 중 등록과 임시 저장을 막습니다.
- 일반 제작 승인 후 폼을 닫고 상세 위에 채팅방을 엽니다. 채팅 생성 실패는 상세로 이동합니다. 수정하기는 내 스토리 카드와 소유한 상세의 옵션 시트에서 제공하며 완료 후 진입했던 화면으로 돌아가 최신 값을 조회합니다.
- 입력과 탭, 접기 및 삭제 확인과 이미지 자르기 상태, 진행 중 요청은 구성 변경에서 유지합니다. 프로세스 종료 후에는 마지막 저장 초안 또는 접수한 서버 제출본으로 복구합니다. 검수 조회는 화면이 보이는 동안만 수행하고, 대기 상한은 구성 변경으로 다시 시작하지 않습니다.

### 장르 검색과 선택

- 간편 제작의 장르는 서버 제공 장르만 선택합니다. 장르 직접 입력 버튼은 없으며 주인공과 주변 인물의 특징 직접 입력은 유지합니다.
- 대표 장르를 기본 칩으로 보여주고 그 위의 검색 가능한 콤보박스를 누르면 제공 목록을 엽니다. 빈 검색어에서는 전체 목록을 보여주며 검색은 서버의 초성, 별칭, 공백과 대소문자 처리 규칙을 따릅니다.
- 검색 목록과 칩은 같은 장르의 선택 상태를 공유합니다. 검색 항목을 누르면 선택 상태를 토글한 뒤 콤보박스와 키보드를 닫고 검색어를 비웁니다. 대표 장르는 선택 경로와 무관하게 원래 칩 순서를 유지합니다. 대표 목록 밖의 장르는 처음 선택할 때 칩 목록 마지막에 추가하며 선택 해제와 재선택에도 칩과 그 순서를 유지합니다. 최대 3개에서는 새 선택만 제한하고 기존 선택 해제는 허용합니다.
- 검색 대기, 검색 결과 없음, 조회 실패와 재시도를 구분합니다. 이미 받은 전체 목록과 같은 화면에서 성공한 검색 결과는 재사용합니다. 캐시가 없는 검색은 기존 목록을 유지하며 실제 요청이 200ms 이상 걸릴 때만 로딩 문구를 표시합니다. 입력 대기 시간은 이 기준에 포함하지 않으며 응답 전에는 결과 없음 문구를 먼저 표시하지 않습니다. 오래된 검색 응답이 최신 검색어나 닫힌 메뉴를 바꾸지 않습니다.
- 선택 ID와 추가 칩 순서는 초안에 보존합니다. 이전 직접 입력 중 정식 장르명과 일치하는 값만 제공 ID로 복원합니다. 일치하지 않는 원문은 저장본에 유지하지만 선택과 새 생성 요청에서는 제외하고 제공 장르 재선택을 안내합니다. 기존 진행 중 요청의 복구 페이로드는 변경하지 않습니다.

### 간편 제작 흐름과 보존

- 공통의 초안·다중 완성 요청 분리 계약을 적용합니다. 제출 요청의 저장 성공 뒤 제작 탭으로 돌아오며 자동 채팅 생성·완성 전용 로딩 화면은 두지 않습니다.
- 완성 중 카드는 로고 마스코트가 키워드와 스토리라인을 고르고, 꾸벅 졸다 에너지 드링크를 마시고 원고를 빠르게 쓰고, 베레모를 쓰고 붓을 집어 주인공 인물화를 그린 뒤 베레모와 붓을 하늘로 던지고 뛰어다니는 애니메이션 표지와 시머 제목을 표시하며, "스토리가 완성되면 알림으로 알려드려요" 안내를 유지합니다. 그림은 아이콘처럼 보이지 않게 달을 등진 옆얼굴, 바람에 날리는 머리, 목도리로 그리고, 마스코트는 웃는 눈, 윙크, 별 눈, 졸린 눈, 힘주는 눈, 어지러운 눈으로 막마다 표정을 바꿉니다. 스토리라인 생성은 공통의 순환 문구·시머·15·30초 힌트, 주변 인물 0명은 공통의 랜덤 생성 안내를 따릅니다.
- 추가 정보 편집 중 정보 추가·삭제, 추천 정보 선택·해제, 선택한 스토리라인 더보기·접기는 키보드를 유지합니다. 현재 입력칸을 삭제하면 남은 다음 칸, 없으면 이전 칸으로 포커스를 옮깁니다. 빈 영역·본문 탭과 마지막 입력칸 삭제는 키보드를 닫습니다.
- 키워드·스토리라인·추가 정보는 각 목적지입니다. 스토리라인으로 진행하면 키워드 목적지를 대체합니다. 추가 정보의 '다시 선택하기'만 스토리라인으로 복귀하고, 헤더 닫기·시스템 뒤로가기는 퍼널 이탈입니다.
- 임시 저장 버튼과 실제 백그라운드 전환에서 편집을 저장합니다. 회전·테마 변경으로 인한 재생성은 자동 저장 계기로 취급하지 않습니다. 생성 요청과 결과는 복구를 위해 즉시 보관합니다.
- 저장 요청 중과 성공 뒤 2초 동안 저장 버튼을 잠급니다. 그 사이에 편집해도 잠금을 유지합니다. 버튼으로 저장에 성공하면 버튼 모양은 바꾸지 않고 '임시 저장했어요' 토스트를 띄우며, 백그라운드 전환 저장은 알리지 않습니다. 실패는 미저장 상태를 유지합니다.
- 미저장 편집이 있으면 미저장 경고, 저장본·진행만 있으면 재개 가능 안내로 닫기를 확인합니다. 입력한 것도 저장본·진행도 없으면 확인 없이 닫습니다. 키워드 입력의 저장본이 없으면 "지금 나가면 입력한 내용이 사라져요", 저장본이 있으면 "지금 나가면 임시 저장한 뒤에 만든 내용은 사라져요"를 표시합니다. 이탈은 마지막 저장 이후의 편집을 저장하지 않습니다.
- 버리는 동작은 오른쪽 위험 버튼, 머무르는 동작은 왼쪽 '닫기'로 둡니다. 추가 정보 재선택은 해당 자유 입력·추천 선택·선택 순번을 함께 초기화합니다.
- 주변 인물의 접기와 삭제 확인은 공통 인물 입력 계약을 따릅니다. 접기 상태와 삭제 확인 대상은 카테고리 탭 및 이전/다음 이동과 구성 변경에서 유지합니다. 접기만 바꾸는 것은 임시 저장할 편집으로 세지 않습니다. 스토리라인으로 진행한 뒤에는 키워드 단계로 돌아가는 경로를 제공하지 않으며, 별도 초안 재개 시에는 인물 입력을 펼쳐서 시작합니다.
- 키워드 입력도 저장합니다. 빈 주변 인물 초기 행만으로 입력이 있다고 보지 않으며, 입력을 모두 지운 뒤 저장하면 키워드 초안을 삭제합니다. 활성 카테고리는 재개 시 첫 탭에서 시작합니다.
- 활성 스토리라인 탭 변경은 저장 버튼의 변경 판정에는 포함하지만 미저장 이탈 경고의 내용 변경에는 포함하지 않습니다.
- 제작 탭에서 로컬 진행 카드가 없으면 서버 목록 로딩 및 오류 상태의 FAB를 숨깁니다. 로컬 초안이나 완성 요청 카드가 있으면 서버 목록 조회 상태와 무관하게 카드와 새 제작 FAB를 유지합니다.
- 초안을 여러 개 보관합니다. 새 제작(FAB)은 확인 없이 새 초안으로 시작하고, 기존 초안은 제작 탭 초안 카드의 "이어서 만들기"로만 재개하며 퍼널은 그 초안만 복원합니다. 초안 카드에는 바로 폐기하는 X를 두지 않고 더보기의 삭제 확인으로 그 초안만 지웁니다.
- 초안 카드 설명은 멈춘 단계를 씁니다: 키워드 초안 "키워드를 선택하고 있었어요", 스토리라인 생성 중 "스토리라인을 만들고 있어요", 스토리라인 선택 초안 "스토리라인을 선택하고 있었어요", 추가 정보 초안 "추가 정보를 입력하고 있었어요".
- 진행 카드는 처음 임시 저장한 시각을 내 스토리 카드의 제작일 줄과 같은 모양으로 KST `yyyy-MM-dd HH:mm`에 표시합니다. 초안·실패 카드는 버튼 위, 완성 중 카드는 본문 아래입니다. 이 시각은 초안을 처음 저장할 때 정하고 단계 전환·재생성·완성 제출에도 바뀌지 않으며, 이 기능 전에 저장된 카드는 날짜 줄을 두지 않습니다.
- 초안과 생성 중 카드 묶음, 완성 요청 카드 묶음은 각각 처음 임시 저장한 시각이 최신인 것이 위입니다. 시각이 없는 이전 카드는 각 묶음의 맨 뒤입니다.
- 검수 제출본은 [공통 검수 제출본 카드 계약](3-1-client-spec.md#fe-screen-013-제작--내-스토리-목록)을 따릅니다. 초안 다음, 완성 요청과 내 스토리 앞에 신규 등록 제출본을 등록 요청 최신순으로 표시합니다. 등록 취소와 삭제를 제공하며 반려 또는 실패한 제출본은 수정하기로 같은 제출본을 다시 제출할 수 있습니다. 제출본 카드만 있는 경우에도 목록과 새 제작 FAB를 유지합니다.
- 검토 중인 제출본이 있는 동안 제작 탭이 보이는 STARTED 상태에서만 5초마다 제출본 목록을 조회합니다. 탭 복귀, 당겨서 새로고침, 검수 완료 알림 진입에서는 즉시 다시 조회하며, 목록에서 사라진 제출본이 있으면 내 스토리도 다시 조회합니다. 조회 실패는 제출본 카드만 숨기고 내 스토리를 유지하며, 직전 성공 응답에 검토 중인 제출본이 있었다면 화면이 보이는 동안 다음 주기에서 복구를 시도합니다.
- 스토리라인 복구는 해당 단계가 보일 때 3초 간격, 완성 요청은 제작 탭 복귀·당겨서 새로고침과 완성 중 카드가 보이는 동안 5초 간격으로 조회합니다. 백그라운드 폴링을 하지 않습니다.
- 로그아웃 시 제작 데이터를 즉시 전량 삭제하지 않고 소유 계정에 격리합니다. 같은 계정 재로그인 시 접근할 수 있습니다. 초안은 계정별로 따로 보관되어 다른 계정의 새 초안이 덮지 않으며, 기기 간 동기화는 보장하지 않습니다.
- 복구 가능한 요청을 오래된 편집 저장이 덮지 않습니다. 초안 삭제·새 제작으로 다른 초안과 완성 요청을 지우지 않습니다. 확정 실패 카드의 제품 정책은 미확정입니다.

<a id="3-3-5-디바이스접근성상태-복원"></a>

## 3-3-4. 디바이스·접근성·상태 복원

- 지원 OS·빌드 버전은 Android 빌드 설정을 기준으로 확인합니다. 화면은 제스처·3버튼 내비게이션과 시스템 바의 안전 영역을 확보합니다.
- 하단 탭의 터치 타깃은 48dp 이상입니다. 화면은 한 열로 구성하고 세로 스크롤과 넓은 창의 본문 폭 상한을 제공합니다. 전체 접근성·글자 크기 지원 범위는 별도 확정이 필요합니다.
- 회전·테마 변경 시 편집 중 입력·선택·입력 확인 다이얼로그·탭·목록 스크롤과 진행 중 요청 표시를 유지합니다. 사용자 입력이 필요한 시트의 입력도 보존합니다.
- 구성 변경 시 옵션·메뉴 시트는 열린 채 유지하고, 말풍선(팝오버)은 닫히며 포커스·키보드·장식 애니메이션은 재개를 보장하지 않습니다.
- 앱 재시작 시 복원 가능한 식별자로 화면 데이터를 다시 읽습니다. 제작은 마지막 저장본·진행 요청에서 복구하며 저장되지 않은 편집의 프로세스 종료 복원은 보장하지 않습니다.
- 법적 문서는 구성 변경 시 열람 위치를 유지합니다. 상세·채팅의 이미지 뷰어는 구성 변경 시 열린 이미지를 유지하며 프로세스 재시작 복원 대상이 아닙니다. 확대·이동 상태는 구성 변경 또는 뷰어를 닫을 때 초기화합니다.

<a id="알림"></a>

## 3-3-5. 알림

- 알림 권한과 수신 동의는 구분합니다. OS 권한이 없거나 동의가 꺼진 경우 알림 표시를 강제하지 않습니다.
- 광고 알림 수신 동의는 필수 동의 시트의 가장 아래 "[선택] 광고성 알림 수신 동의" 항목으로 먼저 묻습니다. OS 권한과 별개의 동의라 알림 권한 요청 전에 이 항목을 싣습니다. 체크한 채 동의하기를 누르면 필수 동의 저장(로그인 중이면 가입 완료)과 알림 권한 응답 뒤 세션에서 광고 동의를 저장하고 처리 결과를 통지하며, 체크하지 않으면 첫 거절로 기록합니다. 기기 알림이 꺼진 채 동의했으면 통지를 닫을 때 "기기 알림이 꺼져 있어 알림 설정에서 켜야 받을 수 있어요" 토스트로 알립니다. 광고 동의 저장 실패는 필수 동의 완료를 막지 않고 실패 토스트만 띄웁니다(설정 화면에서 다시 켤 수 있습니다).
- 첫 거절 뒤에는 세 번째 재진입에서 광고 알림 동의 바텀 시트로 한 번 더 묻고, 그때도 거절하면 다시 묻지 않습니다. 재진입은 회원 화면이 처음 그려지는 프로세스 실행 단위로 셉니다. 재질문 시트는 알림 권한 응답과 신규 가입 안내가 끝난 뒤에 뜨고, 제목·한 줄 설명·버튼만 두며 전송자·이용 항목·보유 기간 고지는 개인정보 처리방침에 맡깁니다. 야간(21:00~08:00) 수신은 별도 동의라 시트에서 받지 않고 설정 화면에서만 켭니다. 기기 알림이 꺼져 있거나 서버가 이미 동의 상태이면 묻지 않습니다. "닫기" 버튼과 스크림 탭·끌어내리기는 같은 거절 처리입니다. 허용 뒤에는 묻지 않으며 동의는 설정 화면의 토글로 언제든 바꿉니다. 거절 기록은 회원 귀속이라 로그아웃에 지워집니다.
- 광고·야간 동의를 켜거나 끌 때마다 전송자·의사 표시 일시·처리 내용을 담은 처리 결과 다이얼로그를 즉시 표시합니다(정보통신망법 제50조). 서비스 알림 토글과 저장 실패는 통지하지 않습니다. 알림 설정의 광고 행에서 개인정보 처리방침을 엽니다. 설정 화면의 토글은 줄이 아니라 스위치가 받고, 야간 광고 허용 줄은 광고 알림이 켜져 있을 때만 표시합니다.
- 수신 대상 회원과 현재 회원을 확인한 알림만 표시합니다. 알림을 눌렀을 때도 수신자를 다시 확인하며 다른 계정이면 홈으로 보냅니다.
- 알림의 `deepLink`는 허용한 호스트·경로만 앱 화면으로 열고, 허용하지 않는 URL은 홈을 엽니다. `deepLink`가 없는 알림은 `type`으로 목적지를 정합니다. 링크만으로 출석 처리나 보상 지급을 실행하지 않습니다.
- 허용한 HTTPS 호스트 `manyak.app`, `www.manyak.app`의 `/studio`는 제작 탭을 선택합니다. 검수 완료 알림은 이미 제작 탭에 있어도 목록을 즉시 갱신하고, 뒤로가기로 알림 전의 상세 화면을 다시 열지 않습니다.
- `STORY_MODERATION_COMPLETED`는 서비스 알림이며 서버의 `title`과 `body`를 그대로 표시합니다. 서로 다른 제출본 알림은 따로 남고 같은 제출본의 재발송은 기존 알림을 교체합니다. 잠금 화면 공개 표시는 제목 줄만 남깁니다. 일반 제작과 스토리 수정 화면이 보이며 그 제출본의 검수 결과를 기다리는 동안, 또는 화면이 같은 결과를 보여 준 뒤 2분 안에 도착한 같은 제출본의 알림은 표시하지 않습니다. 화면이 결과를 기다리지 않거나 대기 상한을 넘겨 닫힌 뒤에는 그대로 표시합니다.
- 로그인 전 탭 진입은 목적지를 보류하고 로그인 뒤 확인합니다. 외부 인증 중 프로세스가 종료되어도 보류 목적지를 복원합니다.
- 로그아웃·탈퇴·세션 종료 시 이전 계정의 표시 알림과 보류 진입을 정리합니다. 잘못된 payload나 존재하지 않는 목적지를 정상 화면으로 추정하지 않습니다.
- 푸시 등록·수신·탭의 내부 검증·재시도·수명은 [알림 설계](../design/1-2-android-design.md#푸시-토큰-등록)가 소유합니다.

<a id="유료-충전"></a>

## 3-3-6. 유료 충전

상품은 `GET /credits/products`의 Android 가격으로 표시합니다. 선택한 상품의 Play 결제를 실행한 뒤 `POST /users/me/credits/purchases/google`에 productId·purchaseToken을 보내 서버 적립을 확인하며 성공 응답 뒤 consume합니다. orderId·balance로 완료·잔액을 반영하고 필요한 경우 같은 주문 조회로 재확인합니다. 공통 결제 결과 계약을 따릅니다.

## 3-3-7. 검수

공통 수용 기준과 이 문서의 플랫폼 계약을 확인합니다. 상세 절차는 [Android 설계의 검수 연결](../design/1-2-android-design.md#1-2-9-검증-방법)을 따릅니다. 테스트·에뮬레이터·실기기 증거와 미검증 범위는 해당 기능 계획·PR에 남깁니다.
