## 3-3-1. 적용 범위와 사용자 모델

- 서비스 진입은 로그인 필수입니다. 게스트 온보딩·로컬 서재·회원 이관·게스트 체험 선차단은 적용하지 않습니다.
- 약관·개인정보처리방침은 로그인 전에도 열람할 수 있습니다. 닫으면 로그인 화면으로 돌아갑니다. 회원은 마이의 서비스 안내에서도 법적 문서를 열 수 있습니다.
- 로그인 직후 [공통 동의 모델](3-1-client-spec.md#fe-screen-010-서비스-이용약관개인정보-처리방침)의 필수 동의 바텀 시트를 회원 화면 위에 표시합니다. 시트는 끌어내리기·바깥 탭으로 닫히지 않으며, 뒤로가기는 동의하지 않은 것으로 보고 로그아웃합니다. 시트의 "보기"는 전문을 시트 위 전체 화면 창으로 열고 닫으면 체크 상태 그대로 시트로 돌아옵니다. 동의 상태 조회에 실패하면 같은 시트에 실패 안내와 다시 시도만 두고 회원 기능을 열지 않습니다. 시트는 알림 권한 요청이 끝난 뒤에 표시하고, 필수 동의가 끝나기 전에는 신규 가입 안내·광고 알림 재질문을 시작하지 않습니다.
- Google·Kakao 로그인, 계정 연동·탈퇴와 신규 가입 안내는 공통 계약을 따릅니다. 로그인 후에는 회원 화면, 로그아웃·탈퇴 후에는 인증 화면을 엽니다.
- 저장 세션 판정 전에는 로그인·회원 화면 어느 쪽도 확정하지 않습니다. 종료 정리가 남아 있으면 복구·재시도 화면을 제공하고 새 로그인을 열지 않습니다.
- 세션 복원·재발급의 네트워크 실패만으로 회원 세션을 폐기하지 않습니다. 정지 계정·유효하지 않은 세션 종료는 일반 로그아웃과 구분해 안내합니다.

## 3-3-2. 내비게이션·화면 계약

### 메인 탭 셸

- 홈·채팅·제작·마이의 네 탭을 제공합니다. 탭별 스크롤·화면 상태를 보존합니다.
- 다른 탭의 시스템 뒤로가기는 홈으로, 홈의 뒤로가기는 앱 밖으로 이동합니다. 탭 방문 순서를 화면 이력으로 쌓지 않습니다.
- 헤더·하단 탭은 탭 전환 중 같은 위치를 유지합니다. 아이콘·라벨·주변 터치 영역이 같은 탭을 선택하고 접근성 이름과 선택 여부를 한 번씩 읽어야 합니다.
- 상세는 진입한 탭 위에서 열고 닫으면 그 탭으로 복귀합니다. 상세에서 채팅을 시작하면 뒤로가기로 상세에 돌아오고 다시 뒤로가면 원래 탭으로 돌아갑니다.

### 스토리 목록·상세

- 공통 목록·메타·신고·삭제 계약과 [스토리 좋아요 비노출 계약](3-1-client-spec.md#fe-screen-003-스토리-상세)을 따릅니다. 제작 카드의 더보기와 길게 누르기는 같은 [카드 옵션 시트](3-1-client-spec.md#fe-screen-013-제작--내-스토리-목록)를 열고, 상세 헤더의 더보기도 같은 시트입니다. 시트에 카드 축소판은 두지 않습니다.
- 홈의 필터·정렬 선택은 홈 탭이 살아 있는 동안 유지하고 저장하지 않습니다. 앱을 다시 시작하면 전체·인기순으로 엽니다. 당겨서 새로고침은 목록을 움직이지 않고 표시자만 필터·정렬 줄 뒤에서 내려오므로 줄도 제자리에 둡니다.
- 상세 헤더의 삭제는 서버 `isOwner`가 참인 경우에만 제공합니다. 제목·서버 권한과 무관하게 클라이언트가 소유권을 추측하지 않습니다.
- 카드 옵션에서 삭제하면 확인을 거치고 해당 항목만 제거합니다. 실패 시 항목과 화면을 유지합니다.
- 상세의 썸네일·주변 인물 이미지 뷰어는 시스템 뒤로가기로 뷰어만 닫습니다. 이미지가 없으면 뷰어를 열지 않습니다.
- 상세의 채팅 시작 연타는 채팅 하나만 생성합니다. 돌아온 상세는 턴 수 등을 갱신하되 첫 로딩 스켈레톤으로 되돌리지 않습니다.

### 채팅 목록과 채팅방

- 채팅 헤더는 고정하며 공통 스크롤 헤더 숨김 규칙을 적용하지 않습니다.

- 서버의 최근 활동순을 유지하고 완료 턴이 없는 새 채팅도 표시합니다. 빈 미리보기에는 안내 문구를, 삭제된 참조 스토리에는 '삭제된 스토리예요'를 표시합니다.
- 채팅이 없는 화면의 제작 버튼은 스토리 보유 여부와 무관하게 제작 탭을 선택합니다.
- 목록을 당겨 새로고침할 때 기존 목록을 유지합니다. 실패 시 목록 아래 또는 토스트로 안내하고 첫 로딩·빈·오류 상태에서 불필요한 당김을 허용하지 않습니다.
- 카드의 더보기·길게 누르기는 카드 옵션 시트로 공유·신고·삭제를 엽니다(공유하기는 채팅방 메뉴와 같은 발급·전달). 채팅방 헤더의 더보기는 [메뉴 시트](3-1-client-spec.md#채팅-설정-시트와-메뉴-시트)를 엽니다. 공유하기는 클립보드에 복사하지 않고 발급한 웹 열람 링크를 Android 공유 시트로 바로 보내며, 성공 토스트 없이 메뉴 시트를 닫습니다. 실패 안내와 진행 표시는 공통 계약을 따릅니다. 삭제된 스토리를 참조하는 채팅에는 신고·새 채팅 시작하기를 제공하지 않습니다. 메뉴 시트의 새 채팅 시작하기는 시작 설정 없이 채팅을 만들고 현재 방을 새 방으로 교체해 뒤로가기가 이전 방으로 돌아가지 않습니다. 채팅방에서 삭제하면 채팅 탭으로 돌아가고 삭제한 방은 복원되지 않습니다.
- 텍스트·강조·인물 이미지·블럭 입력·추천·재생성 의미는 공통 계약을 따릅니다. 확정 턴·스트리밍 턴의 인물 이미지는 같은 풀스크린 뷰어로 열며 시스템 뒤로가기는 채팅방을 떠나지 않고 뷰어만 닫습니다.
- 채팅 작성 중 상황·대사 추가, 강조 삽입, 입력 삭제 등 작성 버튼의 탭은 입력 포커스를 해제하지 않습니다. 작성 버튼 밖의 빈 영역·채팅 본문 탭은 키보드를 닫습니다. 현재 입력칸을 삭제하면 남은 다음 칸, 없으면 이전 칸으로 포커스를 옮깁니다. 마지막 입력칸 삭제·입력 모드 교체·전송 후 입력 잠금처럼 편집 대상이 없어지는 경우와 별도 다이얼로그의 창 처리는 기존 동작을 따릅니다.
- 스트리밍 중 구성 변경에도 입력 잠금·누적 응답·스크롤 앵커를 유지합니다. 정상 종료 이벤트 없이 끊겨도 잠금을 풀고 서버 결과로 복구합니다.

### 마이·법적 문서

- 회원 프로필·계정 연동·이프·출석·초대·탈퇴는 공통 계약을 따릅니다. API 응답 전에는 정책 수치를 임의 기본값으로 표시하지 않습니다.
- 법적 문서와 서비스 안내는 앱 안의 문서 화면에서 엽니다. 웹 본문과 시행일·버전이 같아야 하며 앱에는 게스트 이용 안내를 표시하지 않습니다.
- 초대 코드 복사·공유는 시스템 기능으로 제공하며, 공유에 사용하는 보상 수치는 서버 정책을 따릅니다.

## 3-3-3. 제작과 데이터 보존

- 공통의 초안·다중 완성 요청 분리 계약을 적용합니다. 제출 요청의 저장 성공 뒤 제작 탭으로 돌아오며 자동 채팅 생성·완성 전용 로딩 화면은 두지 않습니다.
- 완성 중 카드는 이미지 생성 로딩 표지와 시머 제목을 표시하며, "스토리가 완성되면 알림으로 알려드려요" 안내를 유지합니다. 스토리라인 생성은 공통의 순환 문구·시머·15·30초 힌트, 주변 인물 0명은 공통의 랜덤 생성 안내를 따릅니다.
- 추가 정보 편집 중 정보 추가·삭제, 추천 정보 선택·해제, 선택한 스토리라인 더보기·접기는 키보드를 유지합니다. 현재 입력칸을 삭제하면 남은 다음 칸, 없으면 이전 칸으로 포커스를 옮깁니다. 빈 영역·본문 탭과 마지막 입력칸 삭제는 키보드를 닫습니다.
- 키워드·스토리라인·추가 정보는 각 목적지입니다. 스토리라인으로 진행하면 키워드 목적지를 대체합니다. 추가 정보의 '다시 선택하기'만 스토리라인으로 복귀하고, 헤더 닫기·시스템 뒤로가기는 퍼널 이탈입니다.
- 임시 저장 버튼과 실제 백그라운드 전환에서 편집을 저장합니다. 회전·테마 변경으로 인한 재생성은 자동 저장 계기로 취급하지 않습니다. 생성 요청과 결과는 복구를 위해 즉시 보관합니다.
- 저장 요청 중·성공 표시 중에는 저장 버튼을 잠급니다. 성공은 체크와 '임시 저장됨'을 2초 표시하고, 실패는 성공 표시 없이 미저장 상태를 유지합니다. 다시 편집하면 성공 표시를 거둡니다.
- 닫기는 항상 확인합니다. 미저장 편집이 있으면 미저장 경고, 저장본·진행만 있으면 재개 가능 안내, 아무것도 없으면 소실 경고로 구분합니다. 이탈은 마지막 저장 이후의 편집을 저장하지 않습니다.
- 버리는 동작은 오른쪽 위험 버튼, 머무르는 동작은 왼쪽 '닫기'로 둡니다. 추가 정보 재선택은 해당 자유 입력·추천 선택·선택 순번을 함께 초기화합니다.
- 키워드 입력도 저장합니다. 빈 주변 인물 초기 행만으로 입력이 있다고 보지 않으며, 입력을 모두 지운 뒤 저장하면 키워드 초안을 삭제합니다. 활성 카테고리는 재개 시 첫 탭에서 시작합니다.
- 활성 스토리라인 탭 변경은 저장 버튼의 변경 판정에는 포함하지만 미저장 이탈 경고의 내용 변경에는 포함하지 않습니다.
- 초안을 여러 개 보관합니다. 새 제작(FAB)은 확인 없이 새 초안으로 시작하고, 기존 초안은 제작 탭 초안 카드의 "이어서 만들기"로만 재개하며 퍼널은 그 초안만 복원합니다. 초안 카드에는 바로 폐기하는 X를 두지 않고 더보기의 삭제 확인으로 그 초안만 지웁니다.
- 초안 카드 설명은 멈춘 단계를 씁니다: 키워드 초안 "키워드를 선택하고 있었어요", 스토리라인 생성 중 "스토리라인을 만들고 있어요", 스토리라인 선택 초안 "스토리라인을 선택하고 있었어요", 추가 정보 초안 "추가 정보를 입력하고 있었어요".
- 진행 카드는 처음 임시 저장한 시각을 내 스토리 카드의 제작일 줄과 같은 모양으로 KST `yyyy-MM-dd HH:mm`에 표시합니다. 초안·실패 카드는 버튼 위, 완성 중 카드는 본문 아래입니다. 이 시각은 초안을 처음 저장할 때 정하고 단계 전환·재생성·완성 제출에도 바뀌지 않으며, 이 기능 전에 저장된 카드는 날짜 줄을 두지 않습니다.
- 초안·생성 중 카드를 먼저, 완성 요청 카드를 그다음에 두고 각 묶음은 처음 임시 저장한 시각이 최신인 것이 위입니다. 시각이 없는 이전 카드는 맨 뒤입니다.
- 스토리라인 복구는 해당 단계가 보일 때 3초 간격, 완성 요청은 제작 탭 복귀·당겨서 새로고침과 완성 중 카드가 보이는 동안 5초 간격으로 조회합니다. 백그라운드 폴링을 하지 않습니다.
- 로그아웃 시 제작 데이터를 즉시 전량 삭제하지 않고 소유 계정에 격리합니다. 같은 계정 재로그인 시 접근할 수 있습니다. 초안은 계정별로 따로 보관되어 다른 계정의 새 초안이 덮지 않으며, 기기 간 동기화는 보장하지 않습니다.
- 복구 가능한 요청을 오래된 편집 저장이 덮지 않습니다. 초안 삭제·새 제작으로 다른 초안과 완성 요청을 지우지 않습니다. 확정 실패 카드의 제품 정책은 미확정입니다.

<a id="3-3-5-디바이스접근성상태-복원"></a>

## 3-3-4. 디바이스·접근성·상태 복원

- 지원 OS·빌드 버전은 Android 빌드 설정을 기준으로 확인합니다. 화면은 제스처·3버튼 내비게이션과 시스템 바의 안전 영역을 확보합니다.
- 하단 탭의 터치 타깃은 48dp 이상입니다. 화면은 한 열로 구성하고 세로 스크롤과 넓은 창의 본문 폭 상한을 제공합니다. 전체 접근성·글자 크기 지원 범위는 별도 확정이 필요합니다.
- 회전·테마 변경 시 편집 중 입력·선택·입력 확인 다이얼로그·탭·목록 스크롤과 진행 중 요청 표시를 유지합니다. 사용자 입력이 필요한 시트의 입력도 보존합니다.
- 구성 변경 시 옵션·메뉴 시트는 열린 채 유지하고, 말풍선(팝오버)은 닫히며 포커스·키보드·장식 애니메이션은 재개를 보장하지 않습니다.
- 앱 재시작 시 복원 가능한 식별자로 화면 데이터를 다시 읽습니다. 제작은 마지막 저장본·진행 요청에서 복구하며 저장되지 않은 편집의 프로세스 종료 복원은 보장하지 않습니다.
- 법적 문서는 구성 변경 시 열람 위치를 유지합니다. 상세·채팅의 이미지 뷰어는 구성 변경 시 열린 이미지를 유지하며 프로세스 재시작 복원 대상이 아닙니다. 확대·이동 상태는 구성 변경 또는 뷰어를 닫을 때 초기화합니다.

<a id="알림"></a>

## 3-3-5. 알림

- 알림 권한과 수신 동의는 구분합니다. OS 권한이 없거나 동의가 꺼진 경우 알림 표시를 강제하지 않습니다.
- 광고 알림 수신 동의는 필수 동의 시트의 가장 아래 "[선택] 광고성 알림 수신 동의" 항목으로 먼저 묻습니다. 알림 권한 응답이 시트보다 앞서지만, OS 권한과 별개의 동의라 권한을 거부했어도 이 항목을 싣습니다. 체크한 채 동의하기를 누르면 필수 동의 저장 뒤 광고 동의를 저장하고 처리 결과를 통지하며, 체크하지 않으면 첫 거절로 기록합니다. 기기 알림이 꺼진 채 동의했으면 통지를 닫을 때 "기기 알림이 꺼져 있어 알림 설정에서 켜야 받을 수 있어요" 토스트로 알립니다. 광고 동의 저장 실패는 필수 동의 완료를 막지 않고 실패 토스트만 띄웁니다(설정 화면에서 다시 켤 수 있습니다).
- 첫 거절 뒤에는 세 번째 재진입에서 광고 알림 동의 바텀 시트로 한 번 더 묻고, 그때도 거절하면 다시 묻지 않습니다. 재진입은 회원 화면이 처음 그려지는 프로세스 실행 단위로 셉니다. 재질문 시트는 알림 권한 응답과 신규 가입 안내가 끝난 뒤에 뜨고, 제목·한 줄 설명·버튼만 두며 전송자·이용 항목·보유 기간 고지는 개인정보 처리방침에 맡깁니다. 야간(21:00~08:00) 수신은 별도 동의라 시트에서 받지 않고 설정 화면에서만 켭니다. 기기 알림이 꺼져 있거나 서버가 이미 동의 상태이면 묻지 않습니다. "닫기" 버튼과 스크림 탭·끌어내리기는 같은 거절 처리입니다. 허용 뒤에는 묻지 않으며 동의는 설정 화면의 토글로 언제든 바꿉니다. 거절 기록은 회원 귀속이라 로그아웃에 지워집니다.
- 광고·야간 동의를 켜거나 끌 때마다 전송자·의사 표시 일시·처리 내용을 담은 처리 결과 다이얼로그를 즉시 표시합니다(정보통신망법 제50조). 서비스 알림 토글과 저장 실패는 통지하지 않습니다. 알림 설정의 광고 행에서 개인정보 처리방침을 엽니다. 설정 화면의 토글은 줄이 아니라 스위치가 받고, 야간 광고 허용 줄은 광고 알림이 켜져 있을 때만 표시합니다.
- 수신 대상 회원과 현재 회원을 확인한 알림만 표시합니다. 알림을 눌렀을 때도 수신자를 다시 확인하며 다른 계정이면 홈으로 보냅니다.
- 알림의 `deepLink`는 허용한 호스트·경로만 앱 화면으로 열고, 허용하지 않는 URL은 홈을 엽니다. `deepLink`가 없는 알림은 `type`으로 목적지를 정합니다. 링크만으로 출석 처리나 보상 지급을 실행하지 않습니다.
- 로그인 전 탭 진입은 목적지를 보류하고 로그인 뒤 확인합니다. 외부 인증 중 프로세스가 종료되어도 보류 목적지를 복원합니다.
- 로그아웃·탈퇴·세션 종료 시 이전 계정의 표시 알림과 보류 진입을 정리합니다. 잘못된 payload나 존재하지 않는 목적지를 정상 화면으로 추정하지 않습니다.
- 푸시 등록·수신·탭의 내부 검증·재시도·수명은 [알림 설계](../design/1-2-android-design.md#푸시-토큰-등록)가 소유합니다.

<a id="유료-충전"></a>

## 3-3-6. 유료 충전

상품은 `GET /credits/products`의 Android 가격으로 표시합니다. 선택한 상품의 Play 결제를 실행한 뒤 `POST /users/me/credits/purchases/google`에 productId·purchaseToken을 보내 서버 적립을 확인하며 성공 응답 뒤 consume합니다. orderId·balance로 완료·잔액을 반영하고 필요한 경우 같은 주문 조회로 재확인합니다. 공통 결제 결과 계약을 따릅니다.
