# 4-4 실행: iOS

<br>

### 4-4-1 조회와 출석

| 작업 | 실행 |
|---|---|
| 정책 | 앱 시작 때 한 번 조회. 화면마다 재요청하지 않음 |
| 체험 | 회원 세션과 필수 동의가 완료될 때 조회. 채팅 턴 완료와 스토리 완성 확정 뒤 재조회 |
| 회원 정보 | 충전 Store의 첫 로드, 충전 화면이 보이는 중의 포그라운드 복귀, 출석 성공 뒤 재조회. 진행 중이면 새로 보내지 않음. 첫 로드와 포그라운드 복귀는 직전 조회 성공 뒤 5초 안이면 생략 ([I-084](DECISIONS.md#i-084)). 위에 쌓은 화면에서 돌아오는 것만으로는 요청하지 않음 |
| 내역 최초 조회 | 충전 화면은 첫 로드에서 보유 항목이 없으면 첫 페이지 요청. 채팅 메뉴는 들어올 때마다 첫 페이지 요청 |
| 무료 충전 새로고침 | 회원 정보만 다시 읽음 |
| 내역 다시 읽기 | 내역 탭의 당겨서 새로고침과 채팅 메뉴의 새로고침. 첫 조회 중에는 요청하지 않고 진행 중 다시 읽기는 취소 뒤 새로 시작. 읽던 다음 페이지를 취소하고 커서 없이 첫 페이지 요청. 충전 화면은 회원 정보도 함께 읽음 |
| 다시 읽기 결과 | 성공하면 첫 페이지 하나로 교체. 실패하면 보던 목록 유지와 실패 Effect. 채팅 메뉴의 실패 표시는 CHAT |
| 다음 페이지 | 커서가 있고 첫 페이지와 다음 페이지가 조회 중이 아닐 때 요청. 실패 뒤 자동 재요청 중단 |
| 화면 이탈 | 충전 화면이 스택에서 빠지거나 채팅 메뉴의 내역을 떠나면 진행 중인 조회 취소. 늦은 응답 미반영 |
| 출석 | 중복 요청 차단, 지급 또는 이미 출석 결과 안내, 회원 정보 재조회 |
| 출석 실패 | 잠금 해제와 오류 Effect. 응답 전에 연결이 끊겼으면 다시 누를 때 서버가 이미 출석한 결과로 답할 수 있음 |
| 백그라운드 전환 | 진행 중 출석과 조회를 따로 취소하지 않음. 중단으로 실패하면 `Network`로 처리 |

실행 계기와 취소는 IOS 기반을 따른다. ([IOS 기반 3-1](../../../../platform/CLIENT/IOS/3-EXECUTION.md#3-1-요청과-취소), [I-084](DECISIONS.md#i-084))

### 4-4-2 부족 시트

1. 동작의 Store가 잔액, 비용과 체험을 모두 아는지 확인한다. 간편 제작은 체험 소진과 잔액 부족을 모두 확인할 때만 요청 전에 막는다.
2. 공용 절차가 시트를 열고 회원 정보를 재조회한다. 당일 출석 여부를 모르거나 이미 출석했으면 출석 버튼을 숨긴다.
3. 출석 요청은 공용 포트로 실행한다. 지급과 이미 출석한 결과 모두 시트를 닫고 회원 정보를 갱신하며 실패하면 시트를 유지한다.
4. 출석과 충전 이동 동안 중복 요청, 끌어내리기와 바깥 탭 닫기를 잠근다. 채팅은 시트를 닫은 뒤 같은 탭 스택에서 채팅방 위에 충전을 쌓고 채팅방과 그 Store는 스택에 남는다.
5. 간편 제작은 저장 완료를 기다리고 성공한 경우에만 시트를 닫는다. 앱 타깃 라우터가 제작 탭 스택에서 퍼널을 걷어 내고 루트 위에 충전을 쌓는다. 실패하면 잠금을 풀고 시트와 퍼널을 유지한다.

동작을 아는 Store가 부족 안내와 출석 및 충전 버튼 분석 이벤트를 보낸다. 공용 절차는 `ManyakAnalytics`에 의존하지 않는다. ([4-2 구성](4-2-COMPONENT-ARCHITECTURE.md), [2-2-2](2-2-REQUIREMENTS.md#2-2-2-부족-안내와-수명), [I-083](DECISIONS.md#i-083))
