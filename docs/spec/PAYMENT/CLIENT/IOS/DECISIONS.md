# DECISIONS.md

현재 적용 기준은 각 명세에 두고 결정 당시의 이유와 대체 관계는 이 문서에 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다. 기존 ID, 날짜, 당시 상태와 근거를 유지한다.
- 상태와 구현 설명은 원본의 기록 시점을 기준으로 해석한다. 현재 적용 여부나 배포 완료를 과거 기록만으로 단정하지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체하는 결정과 적용 범위를 명시한다.
- 원문에 구분되지 않은 배경, 대안과 영향은 추측해서 보충하지 않는다.
- 이 세트의 ID는 I-080부터 I-089까지 쓴다. 사용자가 확인하기 전의 작성 중 결정은 상태를 Proposed로 둔다.

**I-080. 이프 구매 없이 무료 충전과 내역만 제공**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Accepted |
| 관계 | Android의 웹 구매 안내와 다른 범위. 세부 적용은 [I-081](#i-081), [I-082](#i-082) |
| 승인 근거 | KNK-2154 작업 대화에서 사용자가 확정했다 |
| 배경 | Android 앱은 구매 탭과 Play 결제 없이 무료 충전과 내역을 제공하고, 이프 충전 헤더의 "이프 구매 안내" 툴팁으로 "이프 구매는 웹에서 할 수 있어요"와 "앱 구매 기능도 준비하고 있어요"를 보인다. 툴팁에 링크와 외부 이동은 없다. App Store는 앱에서 쓰는 디지털 재화에 인앱 결제를 요구하고 외부 구매 안내를 제한한다고 조사됐으나(심사 지침 3.1.1, 3.1.3) 2026년 지침 원문은 확인하지 못했다. 한국 스토어 전용 앱은 StoreKit External Purchase Entitlement로 제3자 결제를 쓸 수 있으나 별도 바이너리와 조건이 있다(2026-11-26 웹 확인). |
| 채택 | iOS에는 구매 화면, 구매 탭, StoreKit 결제와 웹 구매 안내가 모두 없다. 무료 충전(출석 등)과 내역만 제공한다. 앱 안 어디에서도 웹 결제로 유도하는 문구, 버튼, 링크를 두지 않는다. |
| 대안 | StoreKit 인앱 결제<br>한국 스토어 전용 제3자 결제 자격(StoreKit External Purchase Entitlement)<br>Android의 웹 구매 안내를 그대로 둠 |
| 이유 | 대화에서 별도 이유를 남기지 않았다. 배경의 심사 지침 조사가 검토 자료였다. |
| 영향 | PAYMENT-US-007은 iOS에 적용하지 않는다. 이프 충전 헤더에는 오른쪽 요소가 없고 Android 툴팁의 두 문장은 모두 구매 안내라 남길 부분이 없다. 부족 시트의 "이프를 충전하면 이어서 할 수 있어요"와 "이프 충전하기", 마이와 채팅 메뉴 이프 카드의 "충전"은 무료 충전 화면으로 가는 공통 문구라 그대로 둔다. 오늘 출석했으면 이프가 부족해도 앱 안에서 늘릴 수단은 친구 초대뿐이고 다음 출석은 KST 자정 뒤다([2-2-3](2-2-REQUIREMENTS.md#2-2-3-출석-후-이프-부족)). 웹에서 구매한 이프도 같은 계정 잔액이라 iOS에서 소모되며 이 상태의 심사 판단은 확인하지 않았다. 어느 타깃도 StoreKit을 링크하지 않고 상품 목록과 웹 충전 주문 API를 부르지 않는다. |
| 근거 | [KNK-2154](https://kimandkang.atlassian.net/browse/KNK-2154), Android 현황과 iOS 대응 정리(2026-11-26, 저장소 미포함) 2절, 7절 2번, [Android 이프 충전 문구](https://github.com/KIM-N-KANG/manyak-android/blob/ccc93f77289fd960def116184c2c86c552e4124e/feature/credit/src/main/res/values/strings.xml) |

<a id="i-081-이프-충전의-처음-탭은-tab-history만-내역"></a>

**I-081. 이프 충전의 처음 탭은 tab history만 내역**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Accepted |
| 관계 | [I-080](#i-080)의 적용. Android [A-080](../ANDROID/DECISIONS.md#a-080)과 같은 탭 해석. 앱 열기 링크의 목적지는 공통 UI [I-030](../../../../ui/IOS/DECISIONS.md#i-030) |
| 승인 근거 | KNK-2154 작업 대화에서 사용자가 확정했다 |
| 배경 | 푸시와 알림함의 이프 알림은 출석 리마인드에 `/my/credits?tab=free`, 이프 만료 예정에 `/my/credits?tab=history`를 보내고 웹은 `purchase`도 쓴다. iOS 이프 충전에는 구매 탭이 없다. 공통 UI는 `/my/credits`의 처음 탭을 PAYMENT가 정하게 했다. |
| 채택 | `tab` 값이 정확히 `history`일 때만 내역 탭으로 연다. `purchase`, `free`, 모르는 값, 대소문자가 다른 값과 값 없음은 무료 충전 탭이다. 같은 키가 여러 번이면 첫 값만 보고 다른 쿼리는 무시한다. 처음 탭은 라우트 값의 내역 여부로만 받고 이후 선택은 충전 Store 상태이며 라우트에 다시 쓰지 않는다. |
| 대안 | `purchase`를 받으면 구매 안내를 띄움: I-080에 어긋난다<br>모르는 값을 홈으로 보냄: 구매 탭 링크나 나중에 생길 값이 이프 충전에 도착하지 못한다 |
| 이유 | 구매 탭으로 가려던 링크도 오류 없이 무료 충전에 도착하고 출석과 만료 알림의 목적이 지켜진다. 탭은 목적지가 아니라 화면 상태라 처음 값만 받는다. |
| 영향 | 프로세스 종료 뒤에는 충전 화면이 복원되지 않아 고른 탭도 사라진다. iOS 푸시 페이로드에서 URL을 읽는 형식은 미정(서버 선행 변경 필요)이다. |
| 근거 | [NOTIFICATION 푸시 데이터](../../../NOTIFICATION/BACKEND/4-2-CONTRACT.md#4-2-10-푸시-데이터), [공통 UI IOS 진입 목적지](../../../../ui/IOS/3-1-INFORMATION-ARCHITECTURE.md#3-1-2-진입-목적지) |

<a id="i-083-간편-제작의-충전-이동은-제작-탭-스택을-루트와-충전으로-구성"></a>

**I-083. 간편 제작의 충전 이동은 제작 탭 스택을 루트와 충전으로 구성**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Accepted |
| 관계 | 공통 UI [I-033](../../../../ui/IOS/DECISIONS.md#i-033)의 탭 스택 배치. Android [A-081](../ANDROID/DECISIONS.md#a-081)의 퍼널 걷어 내기에 대응 |
| 승인 근거 | KNK-2154 작업 대화에서 사용자가 확정했다 |
| 배경 | 공통 요구는 간편 제작에서 충전할 때 초안 저장 성공 뒤 이동하게 한다. 간편 제작은 제작 탭의 제작 버튼과 초안 카드에서 들어가므로 제작 탭 스택에 쌓인다([STORY 화면과 진입](../../../STORY/CLIENT/3-1-INFORMATION-ARCHITECTURE.md#3-1-1-화면과-진입)). iOS에는 탭 셸 위에 덮는 백스택이 없다. |
| 채택 | 저장이 성공하면 시트를 닫고 앱 타깃 라우터가 제작 탭 스택에서 퍼널 화면을 걷어 내 루트 위에 이프 충전 하나를 쌓는다. 뒤로가기는 초안 카드가 있는 제작 탭 루트다. 저장이 실패하거나 충돌하면 스택을 바꾸지 않는다. |
| 대안 | 퍼널을 스택에 남긴 채 위에 충전을 쌓음: 돌아와 같은 퍼널을 다시 여는 동작이 생기고 초안 카드로만 이어서 만드는 공통 흐름과 갈라진다<br>마이 탭으로 옮겨 충전을 엶: 충전 뒤 제작으로 돌아오는 길이 끊긴다 |
| 이유 | 저장 뒤 이동과 초안 카드 복귀를 iOS 탭 스택에서 한 탭 안에 둔다. |
| 영향 | 충전으로 떠나면 퍼널의 편집 상태는 사라지고 저장한 초안만 남는다. 다른 탭에서 간편 제작을 여는 진입이 생기면 이 결정을 다시 본다. |
| 근거 | [공통 2-2-5](../2-2-REQUIREMENTS.md#2-2-5-이프-부족과-입력-보존) |

<a id="i-084-충전-화면의-회원-정보-재조회-계기"></a>

**I-084. 충전 화면의 회원 정보 재조회 계기**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Accepted |
| 관계 | IOS 기반의 [실행 계기 규칙](../../../../platform/CLIENT/IOS/3-EXECUTION.md#3-1-요청과-취소)과 [백그라운드 복귀](../../../../platform/CLIENT/IOS/2-STATE-MANAGEMENT.md#2-3-백그라운드와-프로세스-종료) |
| 승인 근거 | KNK-2154 작업 대화에서 사용자가 확정했다 |
| 배경 | Android 충전 화면은 화면이 보일 때마다 회원 정보를 다시 읽고 구성 변경의 반복 요청을 5초 간격으로 제한한다. iOS에는 구성 변경이 없고 IOS 기반은 반복되는 `onAppear`와 `.task` 시작을 도메인 호출의 계기로 쓰지 않는다. 출석 여부는 KST 자정에 바뀌므로 앱을 오래 백그라운드에 두었다 돌아오면 보이던 값이 지난 날의 값일 수 있다. |
| 채택 | 회원 정보는 충전 Store의 첫 로드, 충전 화면이 보이는 중의 포그라운드 복귀, 당겨서 새로고침, 출석 성공 뒤에 다시 읽는다. 첫 로드와 포그라운드 복귀는 진행 중 조회가 있으면 새로 보내지 않고 직전 조회 성공 뒤 5초 안이면 생략한다. 당겨서 새로고침과 출석 성공 뒤의 재조회에는 간격을 적용하지 않는다. 위에 쌓은 화면(친구 초대)에서 돌아올 때는 다시 읽지 않는다. |
| 대안 | 화면이 다시 나타날 때마다 재조회: IOS 기반의 실행 계기 규칙에 어긋난다<br>최소 간격 없음: 충전 화면을 닫았다 바로 다시 열 때 같은 조회가 반복된다 |
| 이유 | 자정이 지난 뒤 돌아온 회원이 지난 날의 "출석 완료"를 보지 않게 하면서 호출 계기를 Store가 정한 시점으로 한정한다. 자동 재조회의 최소 간격은 Android와 같은 5초로 맞춘다. |
| 영향 | 친구 초대 화면에서 돌아온 직후의 잔액은 직전 값이다. 초대 보상은 친구가 코드를 등록할 때 지급되므로 당겨서 새로고침이나 다음 진입에서 반영된다. |
| 근거 | [공통 2-2-4](../2-2-REQUIREMENTS.md#2-2-4-보상과-내역) |

<a id="i-085-출석-버튼의-미확인과-요청-중-표시"></a>

**I-085. 출석 버튼의 미확인과 요청 중 표시**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Accepted |
| 관계 | 공통 [3-3-1](../3-3-LAYOUT.md#3-3-1-잔액과-무료-충전)의 출석 버튼 표현을 iOS에 적용 |
| 승인 근거 | KNK-2154 작업 대화에서 사용자가 확정했다 |
| 배경 | 공통 표현은 무료 충전 탭의 출석 버튼을 요청 중 "출석 체크 중"과 잠금, 완료 뒤 "출석 완료" 비활성으로 정하고 출석 여부를 모를 때의 표시는 정하지 않는다. Android 코드는 무료 충전 탭에서 요청 중 문구 대신 스피너를 보이고 출석 여부를 모르면 "출석 하기"를 비활성으로 두며, 부족 시트는 요청 중 "출석 체크 중"을 보인다. 공통 UI IOS의 요청 버튼은 문구 자리에 스피너를 둔다. |
| 채택 | 무료 충전 탭과 부족 시트의 출석 버튼은 요청 중 문구를 "출석 체크 중"으로 바꾸고 잠근다. 출석 여부를 모르면 무료 충전 탭은 "출석 하기"를 비활성으로 두고 부족 시트는 출석 버튼을 숨긴다. |
| 대안 | 공통 UI의 요청 버튼처럼 스피너 표시: PAYMENT 공통 표현의 문구와 다르다 |
