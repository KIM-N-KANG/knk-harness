## 3-2-1. 적용 범위

브라우저 진입·URL·히스토리, 익명 체험과 회원 이관, 웹 전용 제작 흐름, 검색 노출·지원·접근성을 정의합니다. 공통 화면의 본문·입력 상한·오류 의미를 복제하지 않습니다.

## 3-2-2. 웹 사용자 모델

- 게스트는 공개 콘텐츠를 열람하고 채팅방을 만들어 입력을 준비할 수 있습니다. 제작과 채팅 전송은 아래 게스트 이용 동의 후 체험 한도 안에서 제공합니다. 로그인했지만 필수 동의가 남은 사용자는 공통 회원 동의 완료 전까지 회원 기능과 로그인 직후 부수 효과를 시작하지 않습니다.
- 제작 FAB, 초안 재개, 온보딩과 공유 열람 CTA, 직접 제작 URL 진입은 게스트 동의 없이 제작 입력 화면을 엽니다. 입력 검증을 통과한 "스토리라인 만들기" 버튼을 누르면 생성 요청 직전에 게스트 이용 동의를 확인합니다. 채팅은 전송과 재생성 직전에 확인합니다. 로그인은 체험 한도 도달 또는 회원 전용 기능 이용 시 안내합니다.
- 게스트가 만든 스토리와 채팅은 브라우저의 지속 저장소에 공개 ID를 보관하고 게스트 목록에 표시합니다. 로그인 안내를 열 때의 채팅 입력 초안은 같은 탭에서 복원합니다. 이전 버전의 탭 저장소에 남은 채팅 ID도 회원 동의 후 이관 대상에 포함하며, 이관이 닫힌 계정에서는 ID를 보존합니다.
- 게스트로 만든 스토리와 채팅은 그 브라우저의 로컬 ID로 계속 열람·삭제·공유할 수 있고, 첫 로그인의 이관 대상으로 남습니다. 세션 상태 표시·로그인 버튼 배치는 아래 마이·헤더 규칙을 따릅니다.
- 마이의 게스트 상태에는 로그인 버튼, 회원 상태에는 프로필·연동 계정·이프·로그아웃·탈퇴를 표시합니다.
- 회원의 목록은 서버가 정본입니다. 익명 상태에서 만든 콘텐츠는 해당 브라우저에 보관한 공개 ID로 접근합니다. 저장소 삭제·기기 변경 시 접근할 수 없음을 안내합니다.
- 스토리·채팅 ID는 각각 중복 없이 최신 생성순으로 최대 100개를 보관합니다. 오래된 ID가 목록에서 밀려도 서버 레코드를 삭제하지 않습니다. 토큰·민감 정보는 이 목록에 넣지 않습니다.
- 저장소를 읽기 전에는 빈 목록이 아니라 로딩으로 표시합니다. 손상된 배열은 빈 목록으로 처리합니다.
- 비어 있지 않은 ID 목록만 배치 조회합니다. 스토리는 로컬 순서, 채팅은 서버 최근 활동순을 사용합니다. 삭제는 먼저 목록에서 빼되 실패 시 되돌리며 404는 삭제된 상태로 처리합니다.
- 게스트의 본 엔딩 배지는 로컬 채팅 배치 응답의 `reachedEndings`를 스토리별로 합산합니다. 로컬 서재에 없는 채팅은 집계하지 않습니다.
- 체험 사용량·한도는 서버 `GET /users/me/trials`가 정본이며 브라우저에 카운터를 두지 않습니다. 잔여는 `limit - used`로 계산하고, 채팅 턴 완료·스토리라인 생성 성공·스토리 완성 뒤 다시 조회합니다. 로그인·로그아웃으로 세션이 바뀌면 다시 조회해 게스트·회원 값을 섞지 않습니다. 게스트의 스토리라인 생성과 재생성, 스토리 완성, 채팅 전송과 재생성은 해당 잔여가 0이면 로그인 시트로 안내하며 요청하지 않습니다. 잔여를 받기 전에는 서버 402를 최종 판정으로 사용합니다. 무료인 채팅방 생성과 제작 화면 진입은 한도로 선차단하지 않습니다.
- 소유 스토리는 로컬 제작 ID로 판정하며 판정 전 좋아요 버튼을 숨깁니다(좋아요 UI는 현재 전면 비노출 — [`3-1-client-spec.md §3-1-3`](3-1-client-spec.md#fe-screen-003-스토리-상세) 스토리 좋아요). 게스트에게 신고하기 메뉴는 표시하지 않습니다.

### 게스트 이용 동의

- 공개 콘텐츠 열람, 채팅방 생성, 프롤로그 열람, 제작 화면 진입과 키워드 입력 및 초안 재개에는 동의를 요구하지 않습니다. "스토리라인 만들기"를 누르면 입력 검증 후 서버 생성 요청 전에 동의를 확인합니다. 취소하면 선택한 키워드와 현재 입력 단계를 유지하고, 동의하면 같은 입력으로 한 번만 생성합니다. 스토리라인 재생성, 스토리 완성, 채팅 전송, 추천 입력 전송, 응답 재생성과 추천 입력 생성 및 재시도도 같은 동의를 확인합니다.
- 체크박스 없이 서비스 이용약관, 개인정보 수집 및 이용, 만 14세 이상 확인을 함께 고지하고 하단의 단일 "동의하기" 버튼으로 명시 동의를 받습니다. 광고성 정보 수신 동의는 포함하지 않습니다.
- 제목은 "시작하기 전에 확인해주세요" 한 줄입니다. 안내 카드 문구는 다음과 같습니다.
  1. "AI가 만든 내용은 직접 확인해주세요" / "사실과 다르거나 부적절한 내용이 있을 수 있어요"
  2. "개인정보와 민감한 정보는 입력하지 마세요" / "다른 사람의 권리를 침해하는 내용도 입력하거나 공유하지 마세요"
  3. "이용에 필요한 동의를 확인해주세요" / "‘동의하기’를 누르면 만 14세 이상임을 확인하고, 서비스 이용약관과 개인정보 수집 및 이용에 동의해요"
- 안내 카드 제목은 16px 볼드, 보조 설명은 기존 14px 일반 굵기와 보조 전경색을 유지하고 끝 마침표를 쓰지 않습니다. 마지막 카드의 "자세히 보기"는 밑줄 없이 제목 행 오른쪽 끝에 두고 버튼 높이는 제목 한 줄 높이인 24px에 맞춥니다.
- 안내 화면의 시트 제목과 카드 묶음 사이, 카드 묶음과 동의 버튼 사이는 각각 32px이며 카드 사이는 8px입니다. 상세 화면의 간격은 별도로 유지합니다.
- "자세히 보기"는 같은 시트에서 "게스트 이용 동의" 상세를 엽니다. 시트 높이는 콘텐츠에 따라 늘어나되 화면 높이에서 6rem을 뺀 높이를 넘지 않습니다. 제목과 동의 버튼을 유지하고 본문만 스크롤합니다. 상세에는 게스트 이용 조건, 수집 목적, 항목, 보유기간, 거부 권리와 제한, AI 처리, 권리 행사와 만 14세 이상 확인을 표시합니다. 전체 문서는 새 탭으로 열고 상세에서 안내로 돌아올 수 있습니다. 동의 버튼은 본문 스크롤과 분리합니다.
- 매 대상 동작 직전에 `GET /api/v1/guests/consents`로 기기별 `guestPrivacy.requiredVersion`과 `needsConsent`를 조회합니다. 유효한 버전과 `needsConsent: false`가 확인되면 시트 없이 진행하고, `true`이면 시트에서 동의받습니다. 기존 브라우저 동의 플래그는 사용하지 않습니다. 조회 중에는 원래 요청을 보류합니다.
- 동의 버튼은 조회한 버전을 `POST /api/v1/guests/consents`의 `guestPrivacy`로 전송합니다. 저장 응답이 같은 버전과 `needsConsent: false`를 확인한 뒤 기다리던 동작 한 개만 재개합니다. 저장 중 중복 제출을 막습니다. 바깥 영역, Escape, 브라우저 뒤로가기는 대기 동작을 취소하고 입력을 유지합니다. 화면이나 인증 상태가 바뀌어도 취소하며 늦게 도착한 성공 응답으로 원래 동작을 실행하지 않습니다. 취소 전에 이미 서버에 저장된 동의는 취소만으로 철회되지 않습니다.
- 조회 실패나 응답 필드 누락은 "동의 상태를 확인하지 못했어요"와 "다시 시도"를 표시합니다. 저장 실패는 "동의를 저장하지 못했어요. 잠시 후 다시 시도해주세요"를 표시하고 재시도를 허용합니다. 실패를 로컬 기록으로 대체하지 않습니다. `CONSENT_VERSION_MISMATCH`는 최신 상태를 다시 조회하고 상세와 "약관이 갱신되어 최신 내용으로 다시 확인해주세요"를 표시하며 사용자가 다시 동의해야 저장합니다. 자동 재전송하지 않습니다.
- 제작과 채팅은 같은 기기 식별자의 서버 동의를 공유합니다. 새로고침, 다른 탭과 재방문도 다음 동작의 서버 조회로 판단합니다. 서버가 재동의를 요구하거나 사이트 데이터 삭제 및 새로운 시크릿 세션으로 기기 식별자가 바뀌면 다시 묻습니다. 같은 시크릿 세션은 식별자를 공유할 수 있으며 시크릿 모드를 탐지하지 않습니다. 식별자 전달이나 서버 확인에 실패하면 이용 요청을 진행하지 않습니다.
- 게스트 동의 API는 `guestPrivacy`만 기록하며 회원의 `terms`, `privacy`, `age14`와 별개입니다. 게스트 기록을 회원 동의로 이관하지 않습니다. 브라우저 데이터 삭제는 서버 동의 기록 삭제가 아니며, 이 프런트엔드 확인은 다른 게스트 API의 서버 권한 검사를 대신하지 않습니다.

### FE-SCREEN-007. 온보딩 페이지

- 비로그인·저장된 스토리와 채팅 0개·온보딩 미열람을 모두 만족하면 메인 탭 진입보다 온보딩을 먼저 표시합니다. 저장소를 읽기 전에는 노출을 판정하지 않습니다.
- 조건을 만족하지 않는 사용자가 직접 접근하면 열람 처리 후 원래 메인 탭으로 이동합니다. 반환 목적지는 메인 탭만 허용하고 기본은 홈입니다.
- 헤더는 로고와 '둘러보기'·'바로 시작하기'로 구성합니다. 로고는 본문 맨 위로 스크롤하며 화면 이동이나 열람 처리를 하지 않습니다.
- 본문은 단계별 스크린샷·설명으로 구성합니다. '바로 시작하기'는 간편 제작, '둘러보기'는 홈으로 이동합니다. 둘 다 열람을 저장하고 히스토리를 교체합니다.
- 소개 순서는 키워드 선택(3장) → 스토리라인 선택·추가 정보(2장) → 채팅 시작(2장) → 실시간 이미지 생성(2장) → AI 추천 입력(1장) → 채팅 공유(1장)입니다. 입력 방식 변경은 별도 소개 섹션으로 두지 않습니다.
- 실시간 이미지 생성 섹션 제목은 "장면이 바뀌면, 이미지도 함께", 설명은 "대화의 흐름에 맞춰 AI가 이미지를 새로 만들어요. 달라지는 표정과 배경으로 이야기에 더 몰입해보세요."입니다.
- 스크린샷은 현재 적용된 테마에 맞춰 라이트·다크 원본을 표시합니다. 저장한 테마를 시스템 테마보다 우선하며, 시스템 설정을 따를 때는 시스템 테마 변경을 즉시 반영합니다. 카드 크기·배치·가로 스냅·점 인디케이터·등장 애니메이션은 동일하게 유지합니다.
- 푸터의 서비스 안내·약관·개인정보처리방침은 새 탭으로 열고 원래 온보딩을 유지합니다. 법적 문서 열람만으로 온보딩을 열람 처리하지 않습니다.
- 제작 퍼널을 떠나면 온보딩 경유 여부와 무관하게 제작 탭으로 돌아갑니다.

### 로그인과 회원 이관

- 로그인 화면에는 이관 안내·약관 동의 고지·링크를 두지 않습니다. 동의는 로그인 직후 동의 시트에서 받고, 이관은 동의 완료 뒤 자동으로 진행합니다(2026-09-19).
- **동의 전 세션 유지.** OAuth를 시작하기 전에 현재 탭의 `sessionStorage`에 로그인 진행 표시를 남깁니다. OAuth 복귀와 같은 탭 새로고침에서는 표시가 남아 동의 절차를 이어 가고, 인증 상태인데 필수 동의가 남았고 표시가 없는 일반 진입은 이전 탭에서 끝내지 않은 로그인으로 판정해 로그아웃합니다(fail-closed). 이때 페이지를 다시 불러오지 않고 같은 화면을 그 자리에서 비로그인 상태로 바꿉니다. 동의 완료·명시적 로그아웃에서 표시를 지웁니다. `localStorage`에는 진행 표시나 동의 완료 여부를 두지 않으며 정본은 항상 동의 조회 API입니다. 서비스 이용약관·개인정보 처리방침 경로에서는 이 판정으로 로그아웃하지 않아 동의 시트에서 연 문서 탭이 원래 탭을 로그아웃시키지 않습니다. 브라우저의 닫은 탭 복원·탭 복제·`noopener` 없는 새 창은 `sessionStorage`를 복사·복원할 수 있으므로 이 표시는 보안 경계가 아니라 앱 수준 보조 장치입니다.
- 로그인 성공 후 필수 동의까지 마친 뒤에 보관 ID를 이관하고 실제 이관 수만 완료 안내합니다. 신규 가입 초대 코드 온보딩·회원 분석 식별·회원 전용 자동 조회도 동의 완료 뒤에 시작합니다. 서버가 평가한 ID(`MIGRATED`·`ALREADY_OWNED`·`CONFLICT`·`NOT_FOUND`)는 정리합니다. `migrationClosed`이면 ID를 보존하고 계정별 재시도를 중단합니다. 네트워크 등 평가 전 실패에는 ID를 남겨 다음 방문에서 재시도합니다. 게스트 사용량은 이관 대상 ID 유무와 무관하게 인증 확정 후 정리합니다.
- 이관 실패가 로그인 완료를 막지 않습니다. 400이면 UUID 형식이 유효한 ID만 한 번 재제출하고 손상 ID를 폐기합니다. 실패 목록을 무한 재시도하지 않습니다.
- 신규 가입 안내·소셜 계정 연동·탈퇴 확인은 공통 계약을 따릅니다. 인앱에서 계정 연동은 시작하지 않고 "계정 연동은 외부 브라우저에서만 할 수 있어요"를 안내합니다. 로그인 핸드오프를 연동에 재사용하지 않습니다. 인증 콜백·쿠키는 웹 Design을 따릅니다.
- 로그아웃·탈퇴 후 로컬 세션을 정리하고 게스트 상태로 돌아갑니다. 제작 단일 슬롯도 정리합니다. 게스트에서 회원으로 로그인할 때는 복구할 제작 슬롯을 유지합니다.

<a id="웹-제작-흐름"></a>

## 3-2-3. 웹 제작 흐름

웹은 편집 초안·스토리라인 생성을 `requestId`별 편집 초안 목록에, 완성 요청을 `requestId`별 완성 목록에 따로 보관합니다. 초안이 있어도, 완성 중에도 새 제작을 시작할 수 있고 초안 카드·완성 중 카드는 각각 건수만큼 표시합니다(공통 [제작 카드와 다중 완성 진행](3-1-client-spec.md#제작-카드와-다중-완성-진행)).

| 상태·진입 | 동작·수용 기준 |
| --- | --- |
| 편집 | 키워드·스토리라인·추가 정보를 같은 URL에서 전환. 300ms 자동 저장, 숨김·이탈 때 예약 저장 반영. 쓰기 실패는 저장 성공으로 표시하지 않음 |
| 완성 제출 | 완성 레코드를 목록에 저장하고 제출한 세션의 초안만 제거한 뒤 응답을 기다리지 않고 제작 탭 복귀. 다른 초안은 유지. 저장 실패는 퍼널 완성 로딩에서 결과를 기다리고 성공 시 채팅을 만들어 채팅방으로 replace |
| 퍼널 직접 진입·새로고침·FAB | 항상 새 세션으로 키워드 입력을 시작. 기존 초안·생성 진행·완성 요청은 퍼널이 복원하지 않고 그대로 두며, 결과는 제작 탭 카드가 반영 |
| 진행 카드 "이어서 만들기" | 그 카드의 레코드만 복원. 초안은 저장 단계로, 스토리라인 생성 중이면 로딩 화면과 복구 조회로 진입 |
| 제작 카드의 스토리라인 완료 | 선택 단계 초안으로 바꿔 이어서 만들기에서 결과로 진입. 실패·404는 카드 조회만 멈추고 재진입 퍼널의 재시도 화면 사용 |
| 제작 카드의 완성 완료 | 회원 목록 재조회 또는 게스트 ID·카운터 반영. 새 스토리의 목록 데이터가 준비될 때까지 진행 카드와 기존 목록을 유지하고 전체 로딩·스켈레톤으로 되돌리지 않음. 데이터가 준비되면 해당 카드 자리에서 완성 카드로 교체하고 그 요청만 목록에서 제거. 다른 완성 중 카드는 유지. 같은 스토리를 중복 표시하거나 채팅을 자동 생성하지 않음 |
| 제작 탭 복귀 뒤 확정 완성 실패·404 | 실패 요청을 목록에서 빼고 추가 정보 단계 초안 카드로 되돌린 뒤 토스트. 다른 초안·생성 진행은 그대로 둠. 이프 부족·게스트 한도는 사유별 안내, 그 밖에는 "스토리를 완성하지 못했어요". 이 경로는 로그인 시트를 열지 않음 |
| 네트워크 오류·동일 요청 409 | 진행 레코드를 유지하고 복구 조회로 판정 |
| 폴링 | 화면이 보일 때 퍼널 3초, 제작 진행 카드 5초. 같은 브라우저 실행에서 동일 요청의 원 POST가 진행 중이면 화면 이동·퍼널 재진입 후에도 조회와 결과 판정을 보류하고 진행 상태를 유지. 원 POST가 끝난 뒤 레코드가 남으면 즉시 조회. 백그라운드에서는 중지 |

- 제작 FAB은 목록 조회 실패를 제외한 모든 상태(빈 목록 포함)에 표시하고 목록이 화면보다 길어도 스크롤 위치와 무관하게 오른쪽 아래에 머무르며, 빈 목록 안내는 스토리·진행 카드(초안·완성 중)가 하나도 없을 때만 표시합니다. 첫 스토리 완성을 기다리는 동안에는 목록 스켈레톤을 함께 표시하지 않습니다. 목록 조회 실패는 기존 오류·재시도 안내를 유지하고 완료 레코드를 보존합니다. 완료 전환은 짧은 페이드로 연결하고 기존 카드의 위치·스크롤을 불필요하게 초기화하지 않습니다. 동작 줄이기에서는 즉시 교체합니다.
- 스토리라인 생성·스토리 완성 로딩 화면의 문구는 4초마다 전환하며, 텍스트 쉬머도 4초 주기로 표시합니다. 제작 카드의 완성 중 제목 쉬머도 같은 주기를 사용합니다.
- 추가 정보 행 X는 Tab 순서에서 제외합니다. 인물 이름 `]`는 필드·푸터 오류로 생성 차단합니다. 키보드가 입력을 가리면 하단 단계 CTA를 숨겼다가 같은 입력 상태로 복원합니다.
- 진행 카드의 초안·스토리라인 상태는 "만들고 있는 스토리"·"이어서 만들기"와 더보기 삭제를 표시하고, 설명 줄에 멈춘 단계를 씁니다: 키워드 초안 "키워드를 선택하고 있었어요", 스토리라인 생성 중 "스토리라인을 만들고 있어요", 스토리라인 선택 초안 "스토리라인을 선택하고 있었어요", 추가 정보 초안 "추가 정보를 입력하고 있었어요". 초안 카드의 "이어서 만들기" 버튼 위와 완성 중 카드의 본문 아래에는 내 스토리 카드의 날짜 줄과 같은 스타일로 처음 임시 저장한 시각을 KST `yyyy-MM-dd HH:mm`으로 표시하며, 키워드 초안에서 생성·선택·추가 정보·완성 제출로 넘어가거나 완성 실패로 초안에 되돌아와도 이 시각은 바뀌지 않습니다. 이 기능 전에 저장된 레코드는 날짜 줄을 두지 않습니다. 완성 중에는 "스토리를 완성 중이에요"·"조금만 기다리면 완성된 스토리를 볼 수 있어요"와 대기 애니메이션을 표시하고 버튼·더보기를 두지 않습니다. 완성 중 제목에는 텍스트 쉬머를 적용하며 동작 줄이기에서는 쉬머를 정지합니다. 마우스·트랙패드 환경에서 표지 안의 점 무리는 포인터를 따라 움직이며, 표지를 벗어나면 자동 움직임으로 돌아갑니다. 터치 환경에서는 자동 움직임을 유지하고 동작 줄이기에서는 정지합니다.
- 초안·스토리라인 삭제는 "만들던 스토리를 삭제할까요?" 확인 후 그 레코드만 제거합니다. 바로 삭제하는 X는 두지 않습니다. 이어서 만들기는 저장본을 소비하지 않고 복원합니다.
- 초안·생성 중 카드를 먼저, 완성 중 카드를 그다음에 두고 각 묶음은 처음 임시 저장한 시각이 최신인 것이 위입니다(시각이 없는 구 레코드는 저장 순서로 맨 아래). 단계 전환·재생성으로 순서가 바뀌지 않습니다. 새 제작·초안 삭제는 다른 초안과 완성 요청을 지우지 않습니다.
- 새 제작은 기존 초안을 묻지 않습니다. 이어서/새로 만들기 다이얼로그는 두지 않으며, 재개는 진행 카드에서만 합니다. 퍼널 한 세션은 자기 초안 한 건만 갱신하고 오래된 편집 저장이 다른 세션의 초안이나 진행 요청을 덮지 않습니다. 저장·이탈 구현은 [웹 Design](../design/1-1-web-design.md#게스트-저장소-키-웹)을 따릅니다.
- 제작 카드 날짜는 당일(기기 시간대) 경과 시간, 이후 KST `yyyy-MM-dd`입니다. 상세 날짜는 공통 계약을 따릅니다.

## 3-2-4. 라우팅·레이아웃·공통 셸

### 라우팅 테이블

| 목적지 | URL | 접근 |
| --- | --- | --- |
| 홈·채팅 목록·제작·마이 | `/`·`/chats`·`/studio`·`/my` | 게스트·회원 |
| 간편 제작 | `/studio/story/simple` | 동의를 마친 회원 또는 게스트. 게스트 동의는 스토리라인 생성 요청 직전에 확인 |
| 일반 제작·수정 | `/studio/story/general`·`/stories/[id]/edit` | 공통 계약의 작성·소유 조건 |
| 스토리 상세·채팅방 | `/stories/[id]`·`/chats/[id]` | 서버 권한 판정 |
| 로그인·로그인 이어가기 | `/login`·`/login/continue` | 인증 진입 |
| 친구 초대·이프 충전·회원 탈퇴 | `/my/invite`·`/my/credits`·`/my/account-deletion` | 회원 |
| 피드백·서비스 안내 | `/my/feedback`·`/about` | 게스트·회원 |
| 약관·개인정보처리방침 | `/terms`·`/privacy` | 로그인 전에도 허용 |
| 공유 열람 | `/share/[shareId]` | 링크 보유자 |
| 온보딩 | `/onboarding` | 위 온보딩 노출 조건 |

위 표는 라우팅 계약이며 실제 제공 경로는 [웹 라우팅 구조](../design/1-1-web-design.md#1-1-2-라우팅레이아웃공통-셸)에서 확인합니다.

### 화면 전환 규칙

- 메인 탭은 홈·채팅·제작·마이이며 선택 상태를 표시합니다. 회원의 `/login` 직접 접근 자체를 차단하지 않습니다.
- 회원 전용 경로의 게스트는 로그인으로 보냅니다. 게스트 제작과 채팅은 [게스트 이용 동의](#게스트-이용-동의)를 먼저 확인하고, 체험 한도 소진 또는 회원 전용 기능에만 로그인 필요 시트를 엽니다. 없는 경로(FE-SCREEN-999)는 Not Found와 홈 복귀 링크를 제공합니다.
- 스토리 상세의 채팅 시작은 채팅방으로 교체합니다. 채팅방의 헤더 뒤로가기는 채팅 목록으로 이동합니다. 삭제된 화면이 뒤로가기로 되살아나지 않아야 합니다.
- 이프 충전의 선택 탭은 URL에 저장하지 않습니다.
- 홈의 필터·정렬 선택은 URL 쿼리 `filter`·`sort`에 저장해 상세에서 뒤로 돌아오거나 새로고침·공유해도 유지합니다. 기본값(전체·인기순)은 쿼리에서 생략해 기본 홈 URL을 `/`로 두고, 알 수 없는 값은 기본값으로 대체합니다. 선택 변경은 히스토리를 쌓지 않고 현재 항목을 교체하며 스크롤 위치를 옮기지 않습니다.
- 홈·채팅·제작 목록과 이프 충전의 무료 충전·내역 탭은 맨 위에서 아래로 당겨 새로고침합니다. 당김은 터치에서만 동작하고 마우스·펜 드래그로는 당기지 않으며 커서 모양도 바꾸지 않습니다. 그 화면이 구독 중인 데이터만 다시 읽고 기존 목록은 응답이 올 때까지 유지하며, 실패는 각 목록의 기존 오류 안내가 맡습니다. 표시자 문구는 "당겨서 새로고침" → "놓으면 새로고침" → "새로고침 중"이고 마이 탭에는 두지 않습니다.
- 로그인 성공 후 검증된 callback 경로로 돌아가며 기본 목적지는 홈입니다. 로그인 필요 시트·인앱 직행에서 시작한 로그인은 시작 당시 화면의 경로·쿼리·해시를 모두 복귀 경로로 보존합니다. 외부 URL과 `//`로 시작하는 값은 거부하고, 일반 브라우저·Instagram·Threads·KakaoTalk이 같은 복귀 경로 정규화를 사용합니다.
- 이전 `/create` 계열 URL의 호환 처리와 라우트 그룹은 [웹 설계](../design/1-1-web-design.md#1-1-2-라우팅레이아웃공통-셸)가 소유합니다.

### 문서 열람과 검색 노출

- 약관·개인정보처리방침·서비스 안내는 로고 홈 링크 헤더와 스크롤 본문으로 표시합니다. 시행일·버전은 본문에 표시하고 공통 콘텐츠 동일성 계약을 따릅니다.
- 서비스 안내는 마이에서 새 탭으로 엽니다. Android에서 사용하는 법적 문서 공급 경로도 같은 본문을 사용합니다.
- 문서 제목은 `제목 - 마냑`입니다. 기본 제목·법적 콘텐츠 문구는 웹 코드의 정본을 사용합니다.
- 검색 크롤러·링크 미리보기 스크래퍼에는 온보딩 게이트만 우회하며 별도 콘텐츠를 만들지 않습니다.
- 공개 홈·서비스 안내·법적 문서·오리지널 스토리 상세를 사이트맵에 싣습니다. 유효한 공유본은 색인을 허용하되 사이트맵에 나열하지 않습니다.
- 개인화·인증·제작 화면과 API는 수집에서 제외합니다. 로그인 이어가기 URL과 조회 불가 공유본, 사용자 스토리 상세는 `noindex, nofollow`입니다.
- 오리지널 여부를 판정하지 못하면 상세 색인을 허용하지 않습니다. robots.txt가 상세 메타데이터 판독을 막아서는 안 됩니다.
- 공유 열람은 로컬 서재를 변경하지 않습니다. 하단 제작 CTA는 간편 제작으로 바로 연결하고 온보딩을 열람 처리합니다.

## 3-2-5. 반응형·접근성·브라우저 지원
### 반응형: 모바일 전용

- 레이아웃은 폭 상한이 있는 단일 컬럼 모바일 셸입니다. 데스크톱 다단 레이아웃을 제공하지 않습니다.
- 노치·홈 인디케이터의 안전 영역을 확보합니다. 구체 CSS·viewport 값은 [웹 Design](../design/1-1-web-design.md#레이아웃-구조)을 따릅니다.

### 모바일 검수 기준

- 주요 CTA가 첫 화면에서 확인 가능해야 합니다.
- 가로 스크롤이 발생하지 않아야 합니다.
- 입력 폼 사용 중 화면이 깨지지 않아야 합니다.

### 접근성 기준

- 클릭 가능한 요소는 키보드로 접근 가능하고 focus가 시각적으로 확인되어야 합니다.
- 폼 입력에 label을 연결하고 오류는 `aria-invalid`·오류 메시지(`role=alert`)로 노출합니다.
- 다이얼로그와 모달 바텀 시트는 열릴 때 포커스를 내부로 이동하되, 첫 버튼·입력란이 아니라 **팝업 자체에 두는 것을 기본**으로 합니다. 특정 요소의 초점이 필요한 경우만 예외로 둡니다. 게스트 한도·신규 가입 안내는 모달 바텀 시트로 표시합니다.
- 로딩·상태 영역은 `role=status`와 `aria-label`로 안내합니다.
- 색상만으로 상태를 구분하지 않습니다.

### 테마·서체

- 테마는 시스템 설정(OS 다크 모드)이 기본이며, 마이 페이지의 테마 변경 메뉴로 시스템 설정·라이트·다크를 선택할 수 있습니다(FE-SCREEN-008). 선택값은 기기 단위로 저장됩니다.
- 서체·타이포그래피 값은 [웹 표현](../design/1-1-web-design.md#웹-표현-값)을 따릅니다.

### PWA 푸시

웹은 PWA 매니페스트(`/manifest.webmanifest`, 홈 화면 설치·standalone)와 FCM 서비스 워커로 회원의 웹 푸시를 받습니다. 서버 계약은 [디바이스 푸시 토큰·발송 모듈](4-backend-server-spec.md#4-3-api-계약)을 따르고 알림 종류·동의 요건은 [푸시 수신 동의](4-backend-server-spec.md#4-3-api-계약)와 같습니다. 게스트는 토큰을 등록하지 않아 푸시를 받지 않습니다.

- **지원 범위.** 데스크톱·Android 브라우저는 일반 탭에서, iOS 16.4+는 홈 화면에 추가한 설치본에서만 받습니다. Firebase 설정이 없는 빌드(CI E2E·Preview)는 서비스 워커 등록·토큰 발급·프롬프트를 모두 하지 않습니다.
- **토큰 등록.** 회원(필수 동의 완료)이고 브라우저 알림 권한이 허용이면 앱 시작마다 `PUT /users/me/push-tokens`(`platform: WEB`)로 갱신합니다. 로그아웃·탈퇴·세션 만료 정리에서 이 기기의 토큰만 `DELETE`하고 브라우저 토큰을 폐기하며, 실패해도 로그아웃을 막지 않습니다.
- **알림 권한과 광고 동의.** Android [알림 계약](3-3-android-spec.md#3-3-5-알림)과 같은 순서입니다. 브라우저 알림 권한은 회원 화면이 처음 열릴 때(페이지 로드 단위, 로그인 직후 포함) 권한이 미결정이면 이 기기에서 한 번 자동으로 요청하고, 신규 회원은 필수 동의 시트의 "동의하기" 클릭(사용자 제스처) 직전에 요청합니다. 브라우저가 제스처 없는 요청을 무시하면(Safari) 알림 설정 화면의 "알림 켜기"가 보조 경로입니다. 권한 거부는 반복 요청하지 않으며 iOS 비설치본은 요청하지 않습니다. 광고성 알림 수신 동의는 필수 동의 시트의 가장 아래 "[선택] 광고성 알림 수신 동의" 항목으로 먼저 묻습니다("전체 동의"에는 포함되고 완료 조건에는 포함하지 않음). 체크한 채 동의하면 필수 동의 저장 뒤 광고 동의를 저장하고 처리 결과를 통지하며, 체크하지 않으면 첫 거절로 기록합니다. 저장 실패는 토스트만 띄웁니다. 첫 거절 뒤 세 번째 회원 재진입(페이지 로드)에서 광고 알림 동의 바텀 시트("이벤트·혜택 소식을 알림으로 받아 볼까요?", "광고 알림 받기"/"닫기")로 한 번 더 묻고, 그때도 거절하거나 한 번 허용하면 다시 묻지 않습니다. 재질문 시트는 신규 가입 초대 코드 안내가 끝난 뒤, 브라우저 권한이 허용이고 서버가 광고 미동의 상태일 때만 뜨며 스크림 탭·뒤로가기는 "닫기"와 같습니다. 야간 동의는 시트에서 받지 않고 알림 설정에서만 켭니다. 처리 결과 통지를 닫을 때 브라우저 알림이 꺼져 있으면 "브라우저 알림이 꺼져 있어 알림 설정에서 켜야 받을 수 있어요" 토스트를 띄웁니다. 기록은 회원 귀속입니다.
- **알림 설정 화면.** 마이 > 알림 섹션(회원만, 화면과 기타 사이)의 "알림 설정"(`/my/notifications`, 회원 전용·게스트는 로그인으로 이동)은 [Android 알림 설정](3-3-android-spec.md#3-3-5-알림)과 같은 구성입니다. 브라우저 알림을 받을 수 없으면 목록 위 배너로 상태를 알립니다: 권한을 아직 묻지 않았으면 "알림 켜기" 버튼으로 브라우저 권한을 요청하고(거부하면 "브라우저 알림이 차단되어 있어요" 토스트), 차단됐으면 브라우저가 다시 묻지 않으므로 "방법 보기" 버튼으로 사이트 설정에서 허용하는 방법을 다이얼로그로 안내하며, iOS 비설치본은 홈 화면 추가 안내, 미지원 브라우저는 미지원 안내만 둡니다. 권한이 허용이면 배너가 없습니다. 아래에 서비스 알림·광고 알림·야간 광고 허용 스위치 줄(라벨·설명·오른쪽 스위치, 조회 중에는 스위치 자리에 골격)을 두며 광고 라벨 옆 외부 링크 아이콘으로 개인정보 처리방침을 새 탭에서 엽니다. 이 브라우저가 알림을 받을 수 없는 상태(권한 미결정·차단·iOS 비설치본)에서는 줄을 비활성으로 그립니다. 미지원 브라우저에서는 계정 단위 설정이라 줄을 활성으로 두어 다른 기기의 수신 동의를 관리·철회할 수 있게 합니다. 야간 줄은 광고가 켜져 있을 때만 표시하고, 광고를 끄면 야간도 함께 꺼집니다. 저장은 `PUT /users/me/push-settings` 전체 교체이며 실패하면 토스트와 함께 원래 값으로 돌아갑니다. 조회 실패는 안내와 "다시 시도하기"로 대체합니다. 광고·야간을 켜거나 끌 때마다 "전송자: …"·"일시: …"·"처리 내용: …" 세 줄(일시는 의사 표시 시점의 기기 시각)을 담은 처리 결과 다이얼로그를 즉시 표시합니다(정보통신망법 제50조, Android와 같은 구성). 서비스 알림 토글은 통지하지 않습니다.
- **표시.** 백그라운드 알림은 서버가 실은 제목·본문·아이콘·클릭 링크로 브라우저가 표시하고, 클릭하면 링크(`deepLink`, 운영 origin)를 엽니다. 페이지가 열려 있을 때 도착한 메시지는 토스트로 보여주며 `recipientId`가 현재 회원과 다르면 버립니다. 백그라운드 표시는 브라우저가 맡아 수신자를 대조할 수 없으므로 로그아웃 시 토큰 삭제가 방어선입니다.

### 인앱 브라우저와 로그인 핸드오프

US-9-8(인앱 체험)·US-9-9(핸드오프)의 웹 계약입니다.

- 인앱 브라우저에서도 열람과 동의 후 게스트 제작 및 채팅을 허용합니다. 체험 한도 소진 시 일반 브라우저와 같은 로그인 필요 시트를 엽니다. 홈과 마이 페이지의 로그인 링크는 브라우저 종류와 관계없이 일반 로그인 화면을 엽니다. 로그인 시작 시 외부 브라우저 전환 안내로 보내거나 핸드오프를 새로 만들지 않습니다.
- 감지 대상 인앱의 Google 로그인은 원래 페이지를 유지하고 Auth.js 인증 팝업을 시도합니다. Kakao 로그인은 같은 탭에서 시작합니다. 앱이 인증 화면을 여는 방식과 실제 인증 허용 여부는 실기기로 확인합니다.
- 이미 발급된 핸드오프 링크의 외부 전환 안내, 코드 수령과 이관 결과 정리는 복구용으로 유지합니다. 코드와 토큰 및 공유 식별자는 분석이나 오류 수집에 기록하지 않으며, 수령 또는 소비 실패를 로그인 성공으로 처리하지 않습니다.
- 기존 핸드오프의 외부 로그인은 검증된 원래 URL로 돌아오고 회원 필수 동의를 받은 뒤 기존 이관 결과 처리를 이어갑니다.

| 브라우저 | Google | Kakao |
| --- | --- | --- |
| 카카오톡 인앱, iOS와 Android | Auth.js 인증 팝업 시도 → 원래 탭의 세션 확인 | 같은 탭에서 로그인 시작 |
| Instagram 인앱, iOS와 Android | Auth.js 인증 팝업 시도 → 원래 탭의 세션 확인 | 같은 탭에서 로그인 시작 |
| Threads 인앱, iOS와 Android | Auth.js 인증 팝업 시도 → 원래 탭의 세션 확인 | 같은 탭에서 로그인 시작 |
| 일반 브라우저 | 일반 로그인 | 일반 로그인 |

- Google 팝업이 성공했더라도 원래 탭의 Auth.js 세션과 인증 API가 같은 회원을 확인해야 성공으로 처리합니다. 새로 고침과 다음 페이지에서도 로그인 상태를 유지해야 합니다.
- Google 로그인과 계정 연동은 동일하게 PKCE, state, nonce를 검증합니다. 팝업과 원래 탭 사이에는 토큰이나 회원 정보를 전달하지 않습니다. 인증 확인용 회원 조회는 로그인 검증에만 사용합니다. 원래 탭에서 서버의 필수 동의를 확인하고 필요한 동의를 마친 뒤 회원 온보딩과 자동 이관을 시작합니다. 로그인 전 시도한 소모 요청을 자동 재실행하지 않습니다.
- 팝업 차단, 명시적인 인증 실패, 세션 확인 실패 또는 5분 초과 시 원래 화면과 입력을 유지하고 기존 로그인 실패 안내와 재시도를 제공합니다. 창 참조 단절은 취소로 단정하지 않고 원래 탭에 돌아왔을 때 세션을 다시 확인합니다. 다른 브라우저의 인증 완료만으로 성공을 표시하지 않습니다.
- 5분 대기 만료는 원래 화면의 대기와 잠금만 해제하며 진행 중인 인증창을 강제로 닫지 않습니다. 이전 시도의 늦은 메시지나 조회 응답으로 화면을 이동하지 않습니다. 사용자가 재시도하면 제어 가능한 이전 팝업을 정리하고 새 인증을 시작합니다. 이전 인증 시작 요청이 응답하지 않은 동안에는 새 인증 시작 요청을 겹쳐 보내지 않습니다.
- 팝업 완료 화면의 제목은 "Google 로그인", 인증 확인 시 안내는 "인증 처리가 끝났어요. 원래 화면으로 돌아가 주세요.", 실패 안내는 "로그인을 완료하지 못했어요. 원래 화면에서 다시 시도해 주세요."입니다. 원래 창을 제어할 수 없을 때도 이 안내를 표시합니다.
- 이 분기는 인증 팝업 시도 범위이며 Google의 WebView 공식 지원을 뜻하지 않습니다. 각 인앱과 OS의 인증 허용, 창 연결, 쿠키 저장소 공유와 원래 탭 세션 유지는 [인증 QA](../qa/auth.md#auth-popup--google-인증-팝업)로 별도 확인합니다. 팝업이 별도 쿠키 저장소에서 열리면 현재 방식으로 세션을 전달하지 못합니다.

### Safari·애니메이션·입력 UX 검수 기준
주소창·키보드 변화에도 CTA·입력창·마지막 메시지가 가려지거나 이중 스크롤·위치 튐이 생기지 않아야 합니다. 전환·스트리밍에 렌더 잔상·입력 차단이 없어야 하며 동작 줄이기에서는 장식 모션을 끕니다.

채팅은 Enter(Shift 없이, IME 조합 아님)·폼 제출·버튼으로 전송합니다. 전송 후 입력을 비우고 포커스를 유지하며 스트리밍 중 전송 잠금을 표시합니다. 블럭·추가 정보 행의 삭제 X는 Tab 순서에서 제외하되 클릭·터치 삭제는 제공합니다. 수동·자동 검수 경계는 [QA 공통 항목](../qa/AGENTS.md#크로스커팅-항목)을 따릅니다.

## 3-2-6. 유료 충전

상품은 `GET /credits/products`의 웹 가격(`webPriceKrw`)으로 표시하며 앱 가격은 노출하지 않습니다. 상품 선택 후 `POST /users/me/credits/orders`로 주문을 만들고 반환된 paymentUrl로 전체 이동(외부 결제창)합니다. 주문 생성이 201이 아니거나 paymentUrl이 없으면 이동하지 않고 실패 토스트를 띄웁니다. 결제창의 구매 완료 후 이동 페이지는 `/my/credits`이며 주문 ID를 실어 오지 않으므로, 이동 직전 `orderId`를 기기(localStorage)에 남기고 복귀 시 그 주문을 `GET /users/me/credits/orders/{orderId}`로 2초 간격 최대 30회 조회합니다. 화면 상태·문구는 [공통 결제 결과](3-1-client-spec.md#fe-screen-008-로그인마이-페이지)를 따르며 잔액 상자 아래 확인 카드로 표시합니다. 대기 주문 기록은 24시간이 지나면 무시합니다. 결과가 확정(`COMPLETED`·`REFUNDED`·404)되면 기록을 즉시 지우고 카드는 닫거나 화면을 떠날 때까지만 표시하므로 새로고침·재진입에서 다시 묻지 않습니다. 결과 없이 떠난 주문(확인 중·60초 초과·조회 오류)은 기록을 남겨 재진입 시 다시 확인합니다. 결제창에서 뒤로가기로 문서가 복원(bfcache)되면 가격 버튼 잠금을 풉니다. 로그아웃·세션 만료·탈퇴 시 기록을 지웁니다.
