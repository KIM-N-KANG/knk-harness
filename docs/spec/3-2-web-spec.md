## 3-2-3. 웹 제작 흐름

웹은 편집 초안·스토리라인 생성을 `requestId`별 편집 초안 목록에, 완성 요청을 `requestId`별 완성 목록에 따로 보관합니다. 초안이 있어도, 완성 중에도 새 제작을 시작할 수 있고 초안 카드·완성 중 카드는 각각 건수만큼 표시합니다(공통 [제작 카드와 다중 완성 진행](3-1-client-spec.md#제작-카드와-다중-완성-진행)).

| 상태·진입 | 동작·수용 기준 |
| --- | --- |
| 편집 | 키워드·스토리라인·추가 정보를 같은 URL에서 전환. 편집은 "임시 저장" 버튼과 화면 숨김 때만 저장하고 단계 이동은 저장하지 않음(아래 간편 제작 헤더). 명시적 이탈은 저장하지 않고 확인 다이얼로그로 남는 내용을 알림. 숨김 시 저장을 시작하되 브라우저 강제 종료 시 완료는 보장하지 않음 |
| 완성 제출 | 완성 레코드를 목록에 저장하고 제출한 세션의 초안만 제거한 뒤 응답을 기다리지 않고 제작 탭 복귀. 다른 초안은 유지. 저장 실패는 요청을 보내지 않고 입력과 현재 화면을 유지하며 저장 실패 안내 |
| 퍼널 직접 진입·새로고침·FAB의 간편 제작 선택 | 항상 새 세션으로 키워드 입력을 시작. 기존 초안·생성 진행·완성 요청은 퍼널이 복원하지 않고 그대로 두며, 결과는 제작 탭 카드가 반영. 회원의 만들고 있는 스토리 카드가 5장 이상이면 새 세션을 열지 않고 상한 토스트 뒤 제작 탭으로 보냄([새 제작 상한](3-1-client-spec.md#제작-카드와-다중-완성-진행)) |
| 진행 카드 "이어서 만들기" | 그 카드의 레코드만 복원. 초안은 저장 단계로, 스토리라인 생성 중이면 로딩 화면과 복구 조회로 진입 |
| 제작 카드의 스토리라인 완료 | 선택 단계 초안으로 바꿔 이어서 만들기에서 결과로 진입. 실패·404는 카드 조회만 멈추고 재진입 퍼널의 재시도 화면 사용 |
| 제작 카드의 완성 완료 | 회원 목록 재조회 또는 게스트 ID·카운터 반영. 새 스토리의 목록 데이터가 준비될 때까지 진행 카드와 기존 목록을 유지하고 전체 로딩·스켈레톤으로 되돌리지 않음. 데이터가 준비되면 해당 카드 자리에서 완성 카드로 교체하고 그 요청만 목록에서 제거. 다른 완성 중 카드는 유지. 같은 스토리를 중복 표시하거나 채팅을 자동 생성하지 않음 |
| 제작 탭 복귀 뒤 확정 완성 실패·404 | 실패 요청을 목록에서 빼고 추가 정보 단계 초안 카드로 되돌린 뒤 토스트. 다른 초안·생성 진행은 그대로 둠. 이프 부족·게스트 한도·입력 내용 거절([§3-1-4 입력 내용 거절](3-1-client-spec.md#3-1-4-스토리-생성-퍼널))은 사유별 안내, 그 밖에는 "스토리를 완성하지 못했어요". 이 경로는 로그인 시트를 열지 않음 |
| 네트워크 오류·동일 요청 409 | 진행 레코드를 유지하고 복구 조회로 판정 |
| 폴링 | 화면이 보일 때 퍼널 3초, 제작 진행 카드 5초. 같은 브라우저 실행에서 동일 요청의 원 POST가 진행 중이면 화면 이동·퍼널 재진입 후에도 조회와 결과 판정을 보류하고 진행 상태를 유지. 원 POST가 끝난 뒤 레코드가 남으면 즉시 조회. 백그라운드에서는 중지 |

- 제작 초안과 생성 및 완성 기록은 IndexedDB에 보관합니다. 회원의 일반 제작 임시 저장본과 회원 간편 제작 서버 세션의 키워드 초안, 스토리라인 초안은 예외로 서버 초안에 보관합니다([FE-SCREEN-009 임시 저장](3-1-client-spec.md#fe-screen-009-일반-제작스토리-수정), [간편 제작 임시 저장](3-1-client-spec.md#임시-저장)). 이관과 최초 조회가 끝나기 전에는 초안이 없다고 판단하지 않습니다. 재개 조회와 새 제작 상한 확인 중에는 채팅방에 들어갈 때처럼 헤더 없이 가운데 스피너만 보여 편집과 제출을 막고, 조회 실패 시 "작성 내용을 불러오지 못했어요"와 재시도를 표시하며 재개 의도를 보존합니다. 제작 목록 조회 실패도 기존 오류와 재시도를 사용합니다.
- 구 localStorage의 단일 초안과 배열 초안은 최초 저장 시각, 입력, 요청 ID 및 저장 순서를 보존하여 이관합니다. DB 반영 성공 전에 원본을 지우지 않으며 손상된 원본은 보존합니다. 이관 후 같은 원본을 다시 읽어 삭제한 초안을 되살리지 않습니다.
- 임시 저장 또는 생성 제출의 저장 실패 안내는 "작성 내용을 저장하지 못했어요"입니다. 임시 저장에 실패하면 저장 토스트 없이 저장하지 않은 상태로 두어 다음 버튼 저장이나 화면 숨김에서 다시 시도합니다. 상태 전환 실패는 기존 초안을 유지합니다.
- 서버 연동 전에 기기에 남은 일반 제작 임시 저장본은 회원이 제작 탭에 들어올 때 같은 ID로 서버에 옮기고, 옮겨지면(이미 있는 경우 포함) 기기에서 지웁니다. 5개 상한에 걸린 것은 기기에 남아 기존 카드와 이어서 만들기로 보이며, 이어서 만들어 저장에 성공하면 그때 서버로 옮겨집니다. 옮긴 초안의 처음 저장 시각은 옮긴 시각입니다. 서버 초안 목록 조회가 실패하면 서버 초안 카드만 숨기고 다른 목록과 오류 표시는 그대로 둡니다.
- 간편 제작은 퍼널을 열 때 저장 위치를 정합니다([간편 제작 임시 저장](3-1-client-spec.md#임시-저장)). 서버 연동 전이나 게스트 때 만든 기기 안 간편 제작 초안은 서버로 옮기지 않고, 그 초안으로 연 세션은 계속 기기 안에 저장해 그 기기에서만 이어서 만듭니다. 회원 서버 세션의 생성 중, 생성 결과, 완성 중, 완성 실패 기록은 기기 안에 두고 서버 초안을 가리키며, 그 기록을 남긴 뒤 다시 저장되지 않은 같은 제작의 서버 초안 카드는 숨깁니다. 이 기기 안 카드를 지우면 숨긴 서버 초안도 지우고, 서버 삭제가 실패하면 삭제 실패 토스트를 띄웁니다. 기록을 남긴 뒤 다른 기기에서 저장한 서버 초안은 카드를 따로 보이고 기기 안 카드를 지워도 남깁니다.
- 로그아웃, 탈퇴, 세션 만료는 제작 저장 세대를 변경하고 초안 및 완성 기록을 함께 정리합니다. 이전 세대의 지연 저장과 결과 반영을 거부합니다. 저장소 정리 실패 시 다음 접근에서 정리를 먼저 재시도하고 이전 회원의 내용을 표시하지 않습니다.

- 제작 FAB은 제작 방식 선택 화면(`/studio/story`)으로 이동합니다. 뒤로가기 헤더(제목 "스토리 제작") 아래에 간편 제작("키워드만 고르면 AI가 이미지까지 담긴 스토리를 완성해드려요")·일반 제작("스토리 설정, 엔딩 등 스토리에 필요한 내용을 직접 입력해요") 선택지를 세로로 둡니다. 각 선택지는 위쪽을 일러스트가 채우고 아래에 제목·설명을 두는 테두리 카드이며, 두 카드는 헤더 아래 높이를 나눠 작은 화면에서도 스크롤 없이 보이게 하고 제목과 설명을 접근 가능한 이름으로 갖는 링크 하나입니다. 간편 제작은 `/studio/story/simple`, 일반 제작은 `/studio/story/general`로 이동합니다. 고른 제작 화면은 선택 화면을 바꿔 열어, 제작을 나가거나 마친 뒤 뒤로가기로 선택 화면이 다시 열리지 않습니다. 일반 제작은 회원 전용이라 게스트가 일반 제작을 고르면 이동하지 않고 로그인 필요 시트를 엽니다(로그인하면 선택 화면으로 돌아옴). 일러스트는 각 제작 흐름을 반복 재생하는 장식이라 보조 기술에 노출하지 않고, 화면을 떠나거나 탭이 가려지면 재생을 멈추며 동작 줄이기에서는 완성된 정지 화면만 표시합니다.
- 간편 제작 화면 헤더는 왼쪽에 제목 "스토리 간편 제작", 오른쪽에 일반 제작과 같은 "임시 저장" 버튼과 닫기(X) 버튼을 둡니다. 버튼 상태·토스트·연타 처리, 저장 실패 안내, 닫기·뒤로가기 확인 다이얼로그의 기준(등록 요청 뒤의 두 종류 제외)과 문구, 잃을 것이 없으면 묻지 않고 나가는 처리, 새로고침 확인창은 아래 일반 제작과 같습니다. 저장 시점은 버튼과 화면 숨김이며, 단계 이동(스토리라인을 골라 추가 정보로 가거나 "다시 선택하기"로 돌아올 때)과 키워드 단계 안의 카테고리 탭 이동은 저장하지 않습니다. Android도 같습니다([Android 제작과 데이터 보존](3-3-android-spec.md#3-3-3-제작과-데이터-보존)). 입력은 키워드 단계의 키워드·인물 입력과, 스토리라인 결과가 있는 단계의 활성 순번·선택·추가 정보·추천 선택·화풍입니다. 스토리라인 생성 요청과 그 결과는 비용이 드는 서버 결과이고 복구 조회에 필요해 버튼과 무관하게 바로 저장하므로, 생성 중이거나 결과를 받은 직후 나가면 임시 저장본만 남은 경우의 안내이고, 키워드 단계에서 입력이 없거나 생성이 실패해 남은 것이 없으면 묻지 않고 제작 탭으로 나갑니다.
- 일반 제작 화면 헤더는 왼쪽에 제목 "스토리 일반 제작", 오른쪽에 높이 40px "임시 저장" 버튼과 닫기(X) 버튼을 둡니다. 일반 제작은 입력을 자동 저장하지 않고 "임시 저장" 버튼을 누르거나 다른 탭으로 옮길 때(탭 누르기·이전·다음·등록하기 오류 이동), 그리고 화면이 가려질 때(탭 전환·앱 전환·화면 잠금·탭 닫기와 새로고침 직전, Android의 백그라운드 전환 저장에 대응)만 저장합니다. 나가기 확인 뒤 제작 탭으로 가는 앱 안 이동은 저장하지 않습니다. 입력(글·이미지·성별·장르 중 하나. 기본값이 있는 분량 배분·공개 범위는 제외)이 없으면 저장하지 않고 버튼을 비활성화하며, 마지막 임시 저장 뒤 바뀐 것이 없으면 다시 쓰지 않습니다. 버튼은 입력이 있으면 늘 켜 두고 저장 중에만 문구 자리에 스피너를 두어 잠급니다. 버튼으로 저장하면(바뀐 것이 없어 다시 쓰지 않은 경우도) "임시 저장했어요" 토스트를 1.5초 동안 띄우고(위쪽 토스트가 헤더의 저장·닫기 버튼을 가리는 시간을 줄이기 위함), 연타해도 토스트는 새로 쌓지 않고 이전 토스트를 대신합니다. 버튼은 첫 누름을 바로 처리하고 이후 1초 안의 누름은 무시합니다. 탭 이동·화면 숨김 저장은 성공을 알리지 않습니다. 버튼과 탭 이동 저장이 실패하면 [FE-SCREEN-009 임시 저장](3-1-client-spec.md#fe-screen-009-일반-제작스토리-수정)의 안내(5개 상한, 용량 초과, 그 밖의 실패 토스트와 다른 곳의 먼저 저장 확인 다이얼로그)를 띄우고, 화면 숨김 저장의 실패는 알리지 않고 저장하지 않은 상태로 둡니다. 임시 저장본은 회원 계정의 서버 초안에 한 제작당 한 건으로 덮어쓰고, 이미지는 올린 객체 키만 보내 다시 열면 서버가 준 미리보기 URL로 보입니다. 화면 숨김 저장은 페이지가 내려가도 요청이 이어지도록 `keepalive`로 보냅니다. 닫기와 브라우저·마우스 뒤로가기는 같은 확인 다이얼로그를 거치며(다이얼로그가 열린 채 뒤로가기를 하면 다이얼로그를 닫음) Android 간편 제작의 이탈 경고와 같은 기준으로 문구가 갈립니다: 임시 저장한 적 없이 입력만 있으면 "임시 저장하지 않은 내용이 있어요"·"지금 나가면 입력한 내용이 사라져요"(닫기·나가기), 임시 저장 뒤 편집이 남으면 "임시 저장하지 않은 내용이 있어요"·"지금 나가면 임시 저장한 뒤에 만든 내용은 사라져요"(닫기·나가기), 임시 저장본만 남으면 "스토리 만들기를 그만둘까요?"·"만들던 내용은 제작 탭의 이어서 만들기에서 계속할 수 있어요"(계속 만들기·나가기). 저장한 것도 저장할 것도 없으면 잃을 것이 없으므로 묻지 않고 제작 탭으로 나갑니다. 등록을 요청한 뒤에는(입력이 서버 제출본에 있고 임시 저장본은 지움) 임시 저장 버튼을 끄고, 요청 뒤 고친 것이 없으면 "스토리 만들기를 그만둘까요?"·"등록을 요청한 내용은 제작 탭에서 확인할 수 있어요"(계속 만들기·나가기), 고친 것이 있으면 "등록하지 않은 수정 내용이 있어요"·"지금 나가면 등록을 요청한 뒤에 고친 내용은 사라져요"(닫기·나가기)입니다. 나가기를 확정하면 제작 탭으로 이동합니다. 새로고침·탭 닫기·주소창 이동은 저장하지 않은 변경이 있을 때만 브라우저 기본 확인창을 띄웁니다(브라우저 정책상 문구를 바꿀 수 없음). 이때의 화면 숨김 저장은 페이지가 내려가며 끝나지 않을 수 있어 확인창을 대신하지 않습니다. 직접 진입·새로고침·FAB의 일반 제작 선택은 늘 새 제작으로 시작하고, 임시 저장본은 제작 탭 진행 카드의 "이어서 만들기"로만 열며 스토리 프로필 탭에서 시작합니다.
- 일반 제작 입력은 헤더 아래 탭 7개로 나눕니다: 스토리 프로필(커버 이미지·제목·한 줄 소개), 스토리 설정(세계관·전개 방식·분량 배분), 주인공(나)(이름·성별·특징), 주변 인물(인물별 4:3 이미지 1장·이름·성별·인물 소개·특징), 시작 상황 설정(시작 설정별 이름·프롤로그·시작 상황·추천 입력 3개·엔딩), 주요 사건(사건별 이름·설명·키 문장), 등록(장르·주요 내용·공개 범위, 기본 비공개). 필수 항목이 있는 탭(주요 사건 제외)은 탭 이름에 `*`를 붙입니다. 탭 줄은 한 줄 가로 스크롤이며 누른 탭을 가운데로 스크롤하고, 탭을 바꾸면 입력 영역을 맨 위로 올립니다. 필수 글 항목(제목 100자·한 줄 소개 255자는 글자 수 표시)은 라벨에 `*`를 붙입니다. 제목 도움말은 "스토리 목록과 상세에 보이는 제목이에요. 스토리의 특징이 드러나게 지어주세요", 한 줄 소개 도움말은 "스토리 상세에 보이는 소개 글이에요. 스토리의 핵심을 한 문장으로 적어주세요"입니다. 스토리 프로필의 커버 이미지(요청의 표지)는 선택 항목으로, 제작 탭 카드와 같은 3:4 미리보기 오른쪽에 세로 가운데로 "이미지 추가"(고른 뒤에는 "이미지 변경"과 "삭제") 버튼과, 그 아래 "3:4 비율의 이미지를 추천해요"와 다음 줄 "(JPG, PNG, WEBP / 최대 5MB)" 안내를 둡니다. 미리보기 칸을 눌러도 파일을 고를 수 있지만 같은 동작의 버튼이 있어 보조 기술과 키보드 초점에서는 뺍니다. 파일을 고르면 형식·크기를 먼저 검사해 어긋나면 토스트("JPG, PNG, WEBP 이미지만 올릴 수 있어요"·"5MB 이하 이미지만 올릴 수 있어요")만 띄우고, 통과하면 하단 시트에서 칸 비율(커버 3:4, 주변 인물 4:3)의 프레임에 맞춰 이미지를 끌어 옮기고 핀치나 아래 "확대" 슬라이더(1~3배)로 키워 보일 부분을 고릅니다. 프레임은 처음에 가운데를 맞춰 두고, 시트 아래에는 다른 시트처럼 "자르기" 버튼과 그 아래 "닫기" 버튼을 세로로 둡니다. "자르기"를 누르면 고른 영역을 잘라 등록 전 presign과 업로드를 진행해 미리보기 위에 스피너를 표시하고, "닫기"를 누르거나 시트를 내려 닫으면 아무것도 바꾸지 않습니다. 업로드에 실패하면 "이미지를 올리지 못했어요" 토스트를 띄우고 이전 커버 이미지를 유지합니다. 스토리 설정의 세계관·전개 방식 칸은 필수이고 각 칸 아래에 설명을 두며, 전개 방식 칸의 플레이스홀더 예시는 간편 제작 글의 절 제목 `# 문체 톤`을 쓴 형태로 보여 문체를 전개 방식에 함께 적게 합니다. 간편 제작의 전제와 갈등은 시작 상황과 주요 사건, 엔딩이 받으므로 세계관 예시에는 절 제목 없이 세계 설정만 둡니다. 분량 배분은 왼쪽에 "묘사 N", 오른쪽에 "대사 M"을 보이는 한 줄 슬라이더(1~9, 기본 5)입니다. 주인공(나)의 기본 정보 아래에는 "스토리 속에서 기본으로 쓰이는 이름과 성별이에요. {username}을 넣은 곳은 이 이름으로 바뀌고, 페르소나로 플레이할 때는 페르소나 이름으로 바뀌어요", 특징 아래에는 "내가 어떤 사람인지에 따라 주변 인물들의 반응이 달라져요"를 둡니다. 시작 상황의 프롤로그 아래에는 "채팅을 시작하면 첫 화면에 보이는 도입 글이에요. {username}을 쓰면 사용자의 페르소나 이름으로 바뀌어요"를 두고, 플레이스홀더 예시는 실제 프롤로그처럼 서술을 `*…*` 단락으로, 대사를 `이름: 대사` 줄로 쓰고, 안내 방송이 `{username}`으로 주인공을 부르는 줄("안내 방송: {username} 님, 종점입니다.")을 넣어 쓰임을 보여 줍니다. 주변 인물의 기본 정보 아래에는 "이 이름과 성별로 스토리에 등장해요", 특징 아래에는 "인물의 성격이 대화와 행동에 드러나요"를 둡니다. 주변 인물의 기본 정보와 특징 사이에는 글자 수(n/150)를 표시하는 한 줄 "인물 소개" 칸을 두고, 플레이스홀더 예시는 "예: 유실물 보관소를 지키는 무뚝뚝한 관리인. 맡긴 것 없이는 아무것도 내주지 않는다.", 칸 아래에는 "스토리 상세에서 이름 아래에 보이는 소개 글이에요. 어떤 인물인지 한 문장으로 적어주세요"를 둡니다. 주변 인물 이미지는 미리보기 오른쪽 버튼 아래에 "4:3 비율의 이미지를 추천해요"와 파일 안내를 두고, 다른 입력처럼 미리보기 줄 아래에 "이 이미지를 바탕으로 상황에 맞게 인물의 모습이 실시간으로 바뀌어요"를 둡니다. 주요 사건 탭 맨 위에는 "채팅이 엔딩을 향하도록 이야기의 방향을 잡아 주는 사건이에요. 모든 시작 상황에 함께 쓰이며, 주인공(나)이 겪을 큰 위기나 전환점을 적어주세요"를 둡니다. 사건 이름 아래에는 "채팅과 스토리 상세에는 보이지 않고, AI가 사건을 구분할 때 쓰는 이름이에요", 사건 설명 아래에는 "AI가 이 사건을 장면으로 풀어낼 때 참고하는 내용이에요. 무슨 일이 벌어지고 어떤 방향으로 풀릴 수 있는지 적어주세요", 키 문장 아래에는 "주인공(나)의 행동이 이 사건과 관련되는지 AI가 판단하는 기준 문장이에요. 할 법한 행동을 한 문장으로 적어주세요"를 둡니다. 주요 사건 플레이스홀더 예시는 다른 탭과 같은 유실역 설정을 잇고, 키 문장 예시는 "{username}이(가) ~한다" 형태로 씁니다. 등록 탭의 장르 라벨은 "장르 (최대 8개)"이고 칩 아래에 "스토리 목록과 상세에 보이는 장르예요"를, 주요 내용 아래에 "스토리 상세의 주요 내용에 보이는 글이에요. 한 줄 소개보다 자세한 줄거리와 볼거리를 적어주세요"를 둡니다. 주요 내용 플레이스홀더도 유실역 설정을 잇습니다. 플레이스홀더 예시는 다음 규칙으로 맞춥니다. 한 줄 예시는 "예: 본문", 여러 줄 예시는 "예:" 다음 줄부터 씁니다. 문장은 마침표로 끝내고 이름(제목, 상황 이름, 엔딩 이름, 사건 이름, 인물 이름)에는 붙이지 않습니다. 주인공은 AI만 읽는 설정 칸(세계관, 전개 방식, 특징, 사건 설명, 키 문장, 달성 조건, 에필로그)과 프롤로그, 추천 입력에서 `{username}`과 조사 표기로 부르고, 한 줄 소개, 주요 내용, 상황 설명에서는 "주인공"으로 부릅니다. 추천 입력은 주인공 본인의 행동과 말이므로 지문에 주어를 쓰지 않고 `{username}`은 자기소개에만 씁니다. 사용자에게 그대로 보이는 여러 줄 예시(프롤로그, 상황 설명, 주요 내용)는 실제 스토리처럼 문단 사이에 빈 줄을 둡니다. 공개 범위는 오른쪽에 스위치를 둔 "공개" 한 줄이며 라벨 아래 설명은 "누구나 스토리를 찾아보고 플레이할 수 있어요"입니다. 등록 탭 맨 아래 안내는 "노골적인 성적 표현, 지나치게 잔혹한 묘사, 혐오를 부추기는 내용은 등록할 수 없어요. 이런 내용을 올리면 이용이 제한될 수 있어요"입니다. 하단 버튼 문구는 "이전"·"다음"·"등록하기"입니다.
- 스토리 수정 화면(`/stories/[id]/edit`)은 일반 제작과 같은 폼을 쓰고, 스토리 상세 헤더 더보기 시트와 제작 탭 내 스토리 카드 옵션 시트 맨 위의 "수정하기"(회원이 만든 스토리)로 들어옵니다. 헤더는 왼쪽에 제목 "스토리 수정", 오른쪽에 닫기(X) 버튼만 두며 임시 저장 버튼과 로컬 저장은 없습니다. 등록 탭의 마지막 버튼은 "저장하기"(진행 중 "저장하는 중")입니다. 닫기와 브라우저·마우스 뒤로가기는 마지막으로 저장한 뒤(처음에는 폼을 연 뒤) 고친 내용이 있을 때만 "저장하지 않은 내용이 있어요"·"지금 나가면 수정한 내용이 사라져요"(닫기·나가기) 확인을 거치고, 없으면 묻지 않고 나갑니다. 나가거나 저장을 마치면 앱 안 이동으로 들어온 경우 이전 화면(상세나 제작 탭)으로 돌아가고, 주소로 바로 연 경우 상세로 바꿔 엽니다. 표지와 주변 인물 이미지 칸에는 일반 제작처럼 "이미지 변경"과 "삭제"를 둡니다. 저장과 검수 결과 처리는 [공통 FE-SCREEN-009](3-1-client-spec.md#fe-screen-009-일반-제작스토리-수정)를 따릅니다.
- 제작 FAB은 목록 조회 실패를 제외한 모든 상태(빈 목록 포함)에 표시하고 목록이 화면보다 길어도 스크롤 위치와 무관하게 오른쪽 아래에 머무르며, 빈 목록 안내는 스토리·진행 카드(초안·완성 중)가 하나도 없을 때만 표시합니다. 첫 스토리 완성을 기다리는 동안에는 목록 스켈레톤을 함께 표시하지 않습니다. 목록 조회 실패는 기존 오류·재시도 안내를 유지하고 완료 레코드를 보존합니다. 완료 전환은 짧은 페이드로 연결하고 기존 카드의 위치·스크롤을 불필요하게 초기화하지 않습니다. 동작 줄이기에서는 즉시 교체합니다.
- 스토리라인 생성·스토리 완성 로딩 화면의 문구는 4초마다 전환하며, 텍스트 쉬머도 4초 주기로 표시합니다. 제작 카드의 완성 중 제목 쉬머도 같은 주기를 사용합니다.
- 추가 정보 행 X는 Tab 순서에서 제외합니다. 인물 이름 `]`는 필드·푸터 오류로 생성 차단합니다. 키보드가 입력을 가리면 하단 단계 CTA를 숨겼다가 같은 입력 상태로 복원합니다.
- 진행 카드의 초안·스토리라인 상태는 "만들고 있는 스토리"·"이어서 만들기"와 더보기 삭제를 표시하고, 설명 줄에 멈춘 단계를 씁니다: 키워드 초안 "키워드를 선택하고 있었어요", 스토리라인 생성 중 "스토리라인을 만들고 있어요", 스토리라인 선택 초안 "스토리라인을 선택하고 있었어요", 추가 정보 초안 "추가 정보를 입력하고 있었어요". 서버 스토리라인 초안 카드는 두 단계를 구분하지 않고 고른 스토리라인 본문(없으면 "스토리라인을 선택하고 있었어요")을 씁니다. 초안 카드의 "이어서 만들기" 버튼 위와 완성 중 카드의 본문 아래에는 내 스토리 카드의 날짜 줄과 같은 스타일로 처음 임시 저장한 시각을 KST `yyyy-MM-dd HH:mm`으로 표시하며, 키워드 초안에서 생성·선택·추가 정보·완성 제출로 넘어가거나 완성 실패로 초안에 되돌아와도 이 시각은 바뀌지 않습니다(회원 서버 세션은 서버 초안의 처음 저장 시각을 따르며, 완성 요청 때 서버가 지운 초안을 실패 뒤 다시 저장하면 그 시각으로 바뀝니다). 이 기능 전에 저장된 레코드는 날짜 줄을 두지 않습니다. 일반 제작 초안 카드는 같은 배치·글자색·버튼·날짜 줄을 쓰되, 제목 자리에 입력한 제목(없으면 "만들고 있는 스토리"), 설명 줄에 한 줄 소개(없으면 "일반 제작으로 만들고 있었어요", 2줄까지), 표지 자리에 커버 이미지(없으면 기본 심벌)를 표시하고 "이어서 만들기"는 일반 제작 화면으로 엽니다. 완성 중에는 "스토리를 완성 중이에요"·"조금만 기다리면 완성된 스토리를 볼 수 있어요"와 대기 애니메이션을 표시하고 버튼·더보기를 두지 않습니다. 완성 중 제목에는 텍스트 쉬머를 적용하며 동작 줄이기에서는 쉬머를 정지합니다. 대기 애니메이션은 Android와 같은 로고 마스코트 표지로, 마스코트가 키워드와 스토리라인을 고르고, 꾸벅 졸다 에너지 드링크를 마시고 원고를 빠르게 쓰고, 베레모를 쓰고 붓을 집어 주인공 인물화를 그린 뒤 베레모와 붓을 하늘로 던지고 뛰어다니는 막을 사이사이 쉬어 가며 이어 갑니다. 그림은 아이콘처럼 보이지 않게 달을 등진 옆얼굴, 바람에 날리는 머리, 목도리로 그립니다. 마스코트는 웃는 눈, 윙크, 별 눈, 졸린 눈, 힘주는 눈, 어지러운 눈으로 막마다 표정을 바꿉니다. 마우스·트랙패드 환경에서는 마스코트가 표지 위의 포인터를 바라보고, 표지를 벗어나면 안무대로 돌아갑니다. 동작 줄이기에서는 바닥 가운데에 선 마스코트 한 장면으로 정지합니다.
- 초안·스토리라인 삭제는 "만들던 스토리를 삭제할까요?" 확인 후 그 레코드만 제거합니다. 바로 삭제하는 X는 두지 않습니다. 이어서 만들기는 저장본을 소비하지 않고 복원합니다.
- 초안·생성 중 카드를 먼저, 완성 중 카드를 그다음에 두고 각 묶음은 처음 임시 저장한 시각이 최신인 것이 위입니다(시각이 없는 구 레코드는 저장 순서로 맨 아래). 단계 전환·재생성으로 순서가 바뀌지 않습니다. 새 제작·초안 삭제는 다른 초안과 완성 요청을 지우지 않습니다.
- 회원의 만들고 있는 스토리 카드가 5장 이상이면([새 제작 상한](3-1-client-spec.md#제작-카드와-다중-완성-진행)) 제작 FAB은 제작 방식 선택 화면으로 이동하지 않고 "만들고 있는 스토리는 5개까지 둘 수 있어요" 토스트를 띄웁니다. 제작 탭의 카드 목록을 아직 읽는 중이면 이동하고, 간편 제작과 일반 제작 화면이 새 세션을 열 때 다시 세어 같은 토스트 뒤 제작 탭으로 보냅니다(공유 열람 CTA, 직접 주소 진입 포함). 이어서 만들기는 막지 않습니다.
- 새 제작은 기존 초안을 묻지 않습니다. 이어서/새로 만들기 다이얼로그는 두지 않으며, 재개는 진행 카드에서만 합니다. 퍼널 한 세션은 자기 초안 한 건만 갱신하고 오래된 편집 저장이 다른 세션의 초안이나 진행 요청을 덮지 않습니다. 저장·이탈 구현은 [웹 Design](../design/1-1-web-design.md#게스트-저장소-키-웹)을 따릅니다.
- 제작 카드 날짜는 당일(기기 시간대) 경과 시간, 이후 KST `yyyy-MM-dd`입니다. 상세 날짜는 공통 계약을 따릅니다.

### 간편 제작 첫 진입 안내

간편 제작을 처음 쓰는 사용자에게 마냑 캐릭터가 화면 하단 대화창으로 단계마다 쓰는 법을 알려 줍니다. 이 기기에서 안내를 끝까지 보거나 건너뛰지 않은 사용자 전원이 대상이며 로그인 여부와 제작 이력은 따지지 않습니다. 첫 방문자를 메인 탭보다 먼저 보내는 별도 온보딩 페이지는 두지 않습니다.

| 단계 | 여는 시점 | 문구 | 버튼(왼쪽, 오른쪽) |
| --- | --- | --- | --- |
| 1 인사 | 간편 제작 키워드 단계가 보일 때 | "반가워요! 키워드만 고르면" / "세계관과 인물을 만들어 드려요." | 건너뛰기, 시작하기 |
| 2 키워드 | 1단계에서 "시작하기"를 누른 직후 | "장르와 인물을 골라 주세요." / "내가 주인공인 1인칭 스토리예요." | 확인 |
| 3 스토리라인 | 스토리라인 3개가 생성되어 선택 화면이 보일 때 | "{장르}로 만든 스토리라인 3개예요." / "마음에 드는 하나를 골라 주세요." | 확인 |
| 4 추가 정보 | 스토리라인을 골라 추가 정보 단계가 보일 때 | "마지막이에요!" / "원하는 설정을 더하면 완성돼요." | 확인 |
| 5 완성 중 | 완성을 제출하고 돌아온 제작 탭에 완성 중 카드가 보일 때 | "곧 스토리가 완성돼요." / "그동안 오리지널 스토리 어때요?" | 닫기, 오리지널 스토리 보기 |

- **형태.** 앱 프레임 전체를 딤으로 덮어 뒤 화면 조작을 막고, 화면 하단에 떠 있는 둥근 카드로 말을 건넵니다. 카드 좌상단의 둥근 프로필에서 마냑 캐릭터가 말하는 듯 움직이며 모션 감소 설정이면 멈춰 있습니다. 프로필 오른쪽에 말하는 이 이름 "마냑"과 대사를 두고, 대사는 글자를 차례로 찍지 않고 바로 모두 보입니다. 버튼은 카드 오른쪽 아래에 기본 크기로 두며, 채팅 첫 진입 안내와 같이 보조 버튼은 배경 없는 글자 버튼이고 주 버튼이 오른쪽 끝입니다. 열리면 초점을 버튼이 아닌 카드에 둡니다.
- **장르 문구.** 3단계의 `{장르}`는 스토리라인 생성 요청에 담은 장르 이름을 고른 순서대로 쉼표로 잇고, 마지막 장르의 받침에 맞춰 "으로" 또는 "로"(받침이 없거나 ㄹ 받침)를 붙입니다.
- **진행 순서.** 다음 단계는 바로 앞 단계를 마쳤을 때만 엽니다. 초안 이어하기로 스토리라인 선택이나 추가 정보 단계에 바로 들어오면 앞 단계를 마칠 때까지 열지 않습니다. 스토리라인 생성 중이거나 생성에 실패했을 때, 로그인 필요 시트, 임시 저장 충돌 확인, 신규 가입 초대 코드 시트가 떠 있을 때는 열지 않습니다. 화면이 준비되고 약 200ms 뒤에 엽니다.
- **기록.** 버튼이나 뒤로가기로 대화창을 닫을 때 마친 단계를 기기에 기록합니다. 대화창이 열린 채 화면을 떠나면 다음 진입에서 같은 단계를 다시 엽니다. "건너뛰기"와 5단계의 두 버튼은 남은 안내를 모두 끝냅니다. 다시 보는 진입점은 두지 않습니다. 로컬 저장소 접근이 막힌 환경에서는 진입마다 다시 열 수 있으며 이를 허용합니다.
- **뒤로가기.** 버튼이 둘인 단계는 왼쪽 버튼과, 나머지는 "확인"과 같습니다. 히스토리 항목은 [화면 전환 규칙](#화면-전환-규칙)의 오버레이 규칙을 따릅니다.
- **오리지널 스토리 보기.** 하단 탭을 누른 것처럼 홈 탭으로 바꿉니다.

| 페르소나 관리·생성·수정 | `/my/personas`·`/my/personas/new`·`/my/personas/[personaId]/edit` | 회원. 게스트는 로그인 화면으로 보냄 |
| 프로필 수정 | `/my/profile/edit` | 회원. 게스트는 로그인 화면으로 보냄 |
| 이프 충전 결제 복귀 | `/my/credits/return` | 그로블 결제창 복귀 전용. 화면 없이 결제 전 충전 화면으로 되감거나 `/my/credits`로 바꿔 끼움([유료 충전](#유료-충전)) |
| 피드백·서비스 안내 | `/my/feedback`·`/about` | 게스트·회원 |
| 공지사항 목록·상세 | `/notices`·`/notices/[noticeId]` | 게스트·회원. 상세 경로는 공지 게시 푸시의 딥링크(`https://manyak.app/notices/{noticeId}`)와 같음 |
| 알림함 | `/notifications` | 회원. 게스트는 로그인 화면으로 보냄 |
| 약관·개인정보처리방침 | `/terms`·`/privacy` | 로그인 전에도 허용 |
| 공유 열람 | `/share/[shareId]` | 링크 보유자 |
| 앱 공유 링크 | `/app` | 누구나. 메신저 공유용 미리보기를 내고 열면 앱·플레이스토어·웹 홈으로 보냄([앱 공유 링크](#앱-공유-링크)) |

위 표는 라우팅 계약이며 실제 제공 경로는 [웹 라우팅 구조](../design/1-1-web-design.md#1-1-2-라우팅레이아웃공통-셸)에서 확인합니다.

### 화면 전환 규칙

- 메인 탭은 홈·채팅·제작·마이이며 선택 상태를 표시합니다. 회원의 `/login` 직접 접근 자체를 차단하지 않습니다.
- 홈·채팅·제작의 상단 헤더 오른쪽에는 게스트에게 로그인 버튼을 왼쪽, [공지사항](3-1-client-spec.md#fe-screen-014-공지사항) 확성기 아이콘 버튼을 그 오른쪽에 나란히 두고, 회원에게는 [알림함](3-1-client-spec.md#fe-screen-015-알림함) 종 아이콘 버튼만 둡니다. 회원인지 게스트인지 판정이 끝나기 전에는 그 자리를 비워 두고(공간은 유지), 확성기가 보였다가 종으로 바뀌지 않게 합니다. 마이 헤더에는 두지 않습니다. 게스트의 새 공지 판정 기준(읽은 공지 ID 목록)은 그 브라우저의 지속 저장소에 보관하고, 회원의 안 읽은 알림 수는 서버에서 받습니다.
- 회원 전용 경로의 게스트는 로그인으로 보냅니다. 게스트 제작과 채팅은 [게스트 이용 동의](../domain/ACCOUNT/CLIENT/WEB/3-2-INTERACTION-FLOWS.md#3-2-1-게스트-이용-동의)를 먼저 확인하고, 체험 한도 소진 또는 회원 전용 기능에만 로그인 필요 시트를 엽니다. 없는 경로(FE-SCREEN-999)는 Not Found와 홈 복귀 링크를 제공하고, 같은 사이트의 이전 기록이 있으면 "이전 화면으로" 버튼도 둡니다(없는 경로는 늘 새 문서로 열리므로 앱 안 이동 여부가 아니라 기록 유무로 봅니다).
- 스토리 상세의 채팅 시작은 상세 위에 채팅방을 쌓아, 뒤로가기로 상세에 돌아오고 다시 뒤로가면 상세에 들어오기 전 화면으로 돌아갑니다(Android와 같음). 채팅방 메뉴의 새 채팅 시작하기는 지금 방을 새 방으로 교체해 뒤로가기가 이전 방으로 돌아가지 않습니다. 채팅방의 헤더 뒤로가기는 앱 안에서 이동해 왔으면 히스토리를 뒤로 이동하고, 알림이나 주소로 채팅방에 바로 들어왔으면 채팅 목록(`/chats`)으로 교체 이동합니다. 일반 제작 승인 뒤 여는 채팅방은 제작 화면 자리를 새 스토리 상세로 바꾼 위에 쌓아, 뒤로가기가 끝난 제작 선택과 폼이 아니라 상세, 그다음 제작 탭으로 돌아갑니다(Android와 같음). 삭제된 화면이 뒤로가기로 되살아나지 않아야 합니다.
- 제작 화면을 나가거나 제출본을 열 수 없어 제작 탭으로 갈 때, 채팅방이나 상세에서 삭제한 뒤 채팅 탭이나 제작 탭으로 갈 때는 Android가 쌓인 화면을 걷어내고 하단 탭을 여는 것처럼 가장 가까운 아래 탭 기록까지 되돌아갑니다. 그 탭이 갈 탭이면 거기서 멈추고, 다른 탭이면 그 위에 갈 탭을 쌓습니다. 그래서 같은 탭이 기록에 두 번 남지 않고, 상세에서 시작한 채팅방을 삭제하면 상세도 함께 걷힙니다. 아래 기록을 알 수 없거나(Navigation API 미지원, 주소로 바로 진입) 탭 기록이 새로고침 전 문서에 있으면 지금 화면을 갈 탭으로 교체해, 떠나며 띄운 안내 토스트가 사라지지 않게 합니다. 하단 탭끼리의 이동은 기록을 교체해 쌓지 않으므로 탭 화면에서의 뒤로가기는 Android와 달리 홈으로 가지 않습니다.
- 뒤로가기 헤더는 앱 안에서 이동해 왔으면 히스토리를 뒤로 이동합니다. "앱 안에서 이동해 왔다"는 현재 화면 바로 아래 기록이 같은 문서의 클라이언트 이동인 경우이며, 주소·알림으로 바로 열었거나 그 화면을 교체한 경우(알림으로 연 채팅방에서 새 채팅을 연 경우 등)는 아닙니다. 주소나 알림으로 바로 들어왔으면 마이 하위 화면은 마이 탭(`/my`), 페르소나 생성은 페르소나 관리, 공지사항 목록과 알림함은 홈(`/`), 공지 상세는 공지사항 목록으로 교체 이동합니다. 이프 충전은 결제 복귀 되감기 뒤 문서가 새로 열려도 충전 화면에 들어오기 전 화면으로 돌아가야 하므로, 아래에 기록이 전혀 없을 때(알림·주소로 바로 진입)만 마이 탭으로 교체하고 다른 문서의 기록이라도 아래에 있으면 히스토리를 뒤로 이동합니다.
- 스토리 상세의 헤더 뒤로가기는 앱 안에서 이동해 왔으면 히스토리를 뒤로 이동하고, 공유·외부 링크로 상세에 바로 들어왔으면 홈(`/`)으로 교체 이동합니다. 브라우저 자체 뒤로가기는 바꾸지 않습니다.
- 오버레이(바텀 시트·다이얼로그·이미지 뷰어·첫 진입 안내·실시간 이미지 안내)는 열릴 때 같은 주소의 히스토리 항목을 한 개 쌓아 뒤로가기를 받습니다. UI로 닫으면 그 항목을 소비해 앞으로가기에 빈 항목이 남지 않습니다. 사용자 조작 없이 자동으로 열린 오버레이(초대 온보딩, 광고 알림 재질문, 알림 거부 안내, 연동 결과, 첫 진입 안내)는 항목을 쌓지 않으며 이때 뒤로가기는 화면을 떠납니다. 오버레이 안의 동작으로 다른 화면에 갈 때(수정하기, 새 채팅, 로그인, 이프 충전, 삭제 뒤 탭 복귀)는 쌓은 항목을 먼저 소비한 뒤 이동해, 돌아올 때 뒤로가기 한 번으로 들어온 화면에 갑니다. 제작 화면의 이탈 확인은 같은 방식의 항목을 유지하며, 제작 화면 위에 열린 시트는 시트만 닫히고 이탈 확인이 뜨지 않습니다. 주소로 바로 연 제작 화면은 첫 입력부터 이탈 확인 항목을 쌓습니다.
- 이프 부족 시트의 "이프 충전하기"는 채팅방에서는 이프 충전을 위에 쌓아 뒤로가기로 채팅방에 돌아오고, 간편 제작에서는 초안을 저장한 뒤 퍼널 칸을 이프 충전으로 교체해 뒤로가기가 퍼널에 들어오기 전 화면으로 갑니다. 저장한 초안은 제작 탭에서 이어서 만듭니다.
- 이프 충전의 선택 탭은 URL에 저장하지 않습니다. 진입 주소의 `tab` 쿼리가 `purchase`, `free`, `history`면 각각 구매, 무료 충전, 내역 탭을 처음 열고, 값이 없거나 모르는 값이면 구매 탭을 엽니다. 알림 딥링크가 이 쿼리로 갈 탭을 정합니다. 읽은 `tab`은 다른 쿼리(UTM 등)를 남기고 주소에서 지워, 다른 탭에서 결제하고 되감겨 오거나 새로고침해도 쿼리 탭이 다시 열리지 않게 합니다.
- 홈의 필터·정렬 선택은 URL 쿼리 `filter`·`sort`에 저장해 상세에서 뒤로 돌아오거나 새로고침·공유해도 유지합니다. 기본값(전체·인기순)은 쿼리에서 생략해 기본 홈 URL을 `/`로 두고, 알 수 없는 값은 기본값으로 대체합니다. 선택 변경은 히스토리를 쌓지 않고 현재 항목을 교체하며 스크롤 위치를 옮기지 않습니다.
- 홈·채팅·제작·마이 탭의 스크롤 위치는 탭을 오가거나 상세·채팅방·하위 화면에서 돌아올 때 떠날 때의 위치로 되돌립니다. 위치는 문서 단위로 기억해 새로고침과 새 탭에서는 맨 위부터 시작합니다. 목록이 아직 짧아 닿지 못하면 내용이 자라는 동안 다시 맞춥니다.
- 홈·채팅·제작 목록, 공지사항 목록, 알림함의 소식·활동 탭과 이프 충전의 무료 충전·내역 탭은 맨 위에서 아래로 당겨 새로고침합니다. 당김은 터치에서만 동작하고 마우스·펜 드래그로는 당기지 않으며 커서 모양도 바꾸지 않습니다. 그 화면이 구독 중인 데이터만 다시 읽고 기존 목록은 응답이 올 때까지 유지하며, 실패는 각 목록의 기존 오류 안내가 맡습니다. 표시자 문구는 "당겨서 새로고침" → "놓으면 새로고침" → "새로고침 중"이고 마이 탭에는 두지 않습니다. 새로고침 중에는 마냑 마스코트가 살짝 뛰어올라 한 바퀴 도는 동작을 반복하며, 응답이 빨리 와도 이 동작을 최소 한 번은 끝까지 보여 준 뒤 표시자를 닫습니다. 동작 줄이기 설정에서는 회전 없이 깜빡임으로 대신합니다.

ACCOUNT 내용은 다음 문서에서 관리한다. ([3-2-2 로그인과 회원 이관](../domain/ACCOUNT/CLIENT/WEB/3-2-INTERACTION-FLOWS.md#3-2-2-로그인과-회원-이관))

- 이전 `/create` 계열 URL의 호환 처리와 라우트 그룹은 [웹 설계](../design/1-1-web-design.md#1-1-2-라우팅레이아웃공통-셸)가 소유합니다.

### 문서 열람과 검색 노출


ACCOUNT 내용은 다음 문서에서 관리한다. ([3-1-2 마이와 문서](../domain/ACCOUNT/CLIENT/WEB/3-1-INFORMATION-ARCHITECTURE.md#3-1-2-마이와-문서))

- 알림함, 공지사항 목록과 상세는 직접 진입하거나 앱 안에서 이동해도 홈과 같은 기본 문서 제목을 유지합니다.
- 공개 홈·서비스 안내·법적 문서·오리지널 스토리 상세를 사이트맵에 싣습니다. 유효한 공유본은 색인을 허용하되 사이트맵에 나열하지 않습니다.
- 개인화·인증·제작 화면과 API는 수집에서 제외합니다. 로그인 이어가기 URL과 조회 불가 공유본, 사용자 스토리 상세는 `noindex, nofollow`입니다.
- 오리지널 여부를 판정하지 못하거나 현재 공개 상세를 읽지 못하면 상세 색인을 허용하지 않습니다. robots.txt가 상세 메타데이터 판독을 막아서는 안 됩니다.
- 홈의 대표 URL(canonical)은 `https://manyak.app/`입니다. 홈 검색 설명과 Open Graph 및 Twitter 설명은 다음 문구를 사용합니다: "키워드를 골라 스토리를 만들면 주변 인물 이미지까지 한 번에 완성되는 AI 스토리챗, 마냑. 채팅으로 스토리를 이어가 보세요. 실시간 이미지를 켜면 대화에 따라 인물의 표정과 행동, 스토리 속 장소가 달라져요. 생생한 장면을 보며 스토리에 푹 빠져보세요."
- 공개 오리지널 상세의 첫 HTML에는 기존 화면의 제목, 한 줄 소개, 주요 내용, 장르와 공개 시작 상황 및 인물 소개를 싣습니다. 서버에서 확인한 공개 내용으로 동일한 화면을 먼저 보여 주며, 엔딩 달성 조건과 에필로그, 프롤로그, 숨겨진 설정, 개인별 본 엔딩과 권한은 싣지 않습니다. 좋아요와 소유자 기능은 클라이언트 조회로 확인하고, 확인 전에는 채팅 시작을 비활성화합니다.
- 공개 오리지널의 문서 제목, description, Open Graph 및 Twitter는 같은 작품의 제목과 한 줄 소개를 사용하고 canonical은 해당 상세 URL입니다. 홈 카드에는 작품 제목을 링크 텍스트로 넣으며 카드 전체 선택과 분석 동작은 유지합니다. 스니펫의 길이나 사이트링크의 작품 선택, 순서와 노출은 검색엔진이 결정합니다.
- 익명 상세 404는 삭제와 비공개를 구분하지 못하므로 페이지 전체를 미존재로 확정하지 않습니다. 서버 조회 실패 시 공개 본문을 싣지 않고 기존 클라이언트 조회를 유지합니다. 클라이언트 404는 기존 미존재 안내, 일시적 실패는 기존 재시도 안내를 사용하며, 소유자의 비공개 스토리 열람을 막지 않습니다.
- 공유 열람은 로컬 서재를 변경하지 않습니다. 하단 제작 CTA는 간편 제작으로 바로 연결합니다.

## 3-2-5. 반응형·접근성·브라우저 지원
### 반응형: 모바일 전용

- 레이아웃은 폭 상한이 있는 단일 컬럼 모바일 셸입니다. 데스크톱 다단 레이아웃을 제공하지 않습니다.
- 앱 셸 높이는 브라우저 도구 막대의 표시 상태에 따른 동적 뷰포트 높이에 맞춥니다. 하단 탭과 푸터는 앱 셸 안에 유지하며 본문만 스크롤합니다. 루트 오류 화면도 같은 높이 기준을 따릅니다.
- 문서 배경은 현재 테마의 앱 배경과 같은 색을 사용합니다. 화면이 셸보다 넓으면 좌우 여백만 별도 배경으로 구분하며, 루트 오류 화면에도 같은 규칙을 적용합니다. 브라우저 자체 툴바의 반투명 효과와 그림자는 제어 대상이 아닙니다.
- 노치·홈 인디케이터의 안전 영역을 확보합니다. 구체 CSS·viewport 값은 [웹 Design](../design/1-1-web-design.md#레이아웃-구조)을 따릅니다.
- 가로로 넘기는 영역(홈 필터 칩 줄, 일반 제작 탭 줄·시작 상황 칩 줄)은 스크롤바를 표시하지 않습니다. 터치는 스와이프로 넘기고, 데스크톱 마우스는 영역을 끌어서 넘깁니다. 마우스 커서는 넘칠 때만 영역 위에서 잡기 모양, 끄는 동안 잡는 중 모양이며, 누를 수 있는 칩·탭 위에서는 기존 커서를 유지합니다. 끌어서 넘긴 뒤 손을 떼도 그 자리의 칩·탭을 누른 것으로 처리하지 않으며, 카드 단위로 스냅하는 영역은 놓은 위치에서 가장 가까운 카드에 맞춥니다.

### 모바일 검수 기준

- 주요 CTA가 첫 화면에서 확인 가능해야 합니다.
- 가로 스크롤이 발생하지 않아야 합니다.
- 입력 폼 사용 중 화면이 깨지지 않아야 합니다.

### 접근성 기준

- 클릭 가능한 요소는 키보드로 접근 가능하고 focus가 시각적으로 확인되어야 합니다.
- 폼 입력에 label을 연결하고 오류는 `aria-invalid`·오류 메시지(`role=alert`)로 노출합니다.
- 다이얼로그와 모달 바텀 시트는 열릴 때 포커스를 내부로 이동하되, 첫 버튼·입력란이 아니라 **팝업 자체에 두는 것을 기본**으로 합니다. 특정 요소의 초점이 필요한 경우만 예외로 둡니다. 게스트 한도·신규 가입 안내는 모달 바텀 시트로 표시합니다.
- 로딩·상태 영역은 `role=status`와 `aria-label`로 안내합니다.
- 색상만으로 상태를 구분하지 않습니다.

### 테마·서체

- 테마는 시스템 설정(OS 다크 모드)이 기본이며, 마이 페이지의 테마 변경 메뉴로 시스템 설정·라이트·다크를 선택할 수 있습니다(FE-SCREEN-008). 선택값은 기기 단위로 저장됩니다.
- 서체·타이포그래피 값은 [웹 표현](../design/1-1-web-design.md#웹-표현-값)을 따릅니다.

### PWA 푸시

웹은 PWA 매니페스트(`/manifest.webmanifest`, 홈 화면 설치·standalone)와 FCM 서비스 워커로 회원의 웹 푸시를 받습니다. 서버 계약은 [디바이스 푸시 토큰·발송 모듈](4-backend-server-spec.md#4-3-api-계약)을 따르고 알림 종류·동의 요건은 [푸시 수신 동의](4-backend-server-spec.md#4-3-api-계약)와 같습니다. 게스트는 토큰을 등록하지 않아 푸시를 받지 않습니다.

- **지원 범위.** 데스크톱·Android 브라우저는 일반 탭에서, iOS 16.4+는 홈 화면에 추가한 설치본에서만 받습니다. Firebase 설정이 없는 빌드(CI E2E·Preview)는 서비스 워커 등록·토큰 발급·프롬프트를 모두 하지 않습니다.
- **토큰 등록.** 회원(필수 동의 완료)이고 브라우저 알림 권한이 허용이면 앱 시작마다 `PUT /users/me/push-tokens`(`platform: WEB`)로 갱신합니다. 브라우저가 오프라인이면 토큰 발급을 건너뛰고, 연결 복구 시 회원 상태와 알림 권한을 다시 확인해 자동으로 등록을 재시도합니다. 로그아웃·탈퇴·세션 만료 정리에서 이 기기의 토큰만 `DELETE`하고 브라우저 토큰을 폐기하며, 실패해도 로그아웃을 막지 않습니다.
- **알림 권한과 광고 동의.** Android [알림 계약](3-3-android-spec.md#3-3-5-알림)과 같은 순서입니다. 브라우저 알림 권한은 회원 화면이 처음 열릴 때(페이지 로드 단위, 로그인 직후 포함) 권한이 미결정이면 이 기기에서 한 번 자동으로 요청하고, 신규 회원은 필수 동의 시트의 "동의하기" 클릭(사용자 제스처) 직전에 요청합니다. 브라우저가 제스처 없는 요청을 무시하면(Safari) 알림 설정 화면의 "알림 켜기"가 보조 경로입니다. 권한 거부는 반복 요청하지 않으며 iOS 비설치본은 요청하지 않습니다. 광고성 알림 수신 동의는 필수 동의 시트의 가장 아래 "[선택] 광고성 알림 수신 동의" 항목으로 먼저 묻습니다("전체 동의"에는 포함되고 완료 조건에는 포함하지 않음). 체크한 채 동의하면 필수 동의 저장 뒤 광고 동의를 저장하고 처리 결과를 통지하며, 체크하지 않으면 첫 거절로 기록합니다. 저장 실패는 토스트만 띄웁니다. 첫 거절 뒤 세 번째 회원 재진입(페이지 로드)에서 광고 알림 동의 바텀 시트("이벤트·혜택 소식을 알림으로 받아 볼까요?", "광고 알림 받기"/"닫기")로 한 번 더 묻고, 그때도 거절하거나 한 번 허용하면 다시 묻지 않습니다. 재질문 시트는 신규 가입 초대 코드 안내가 이번 접속에 뜰 차례면 그 안내가 끝난 뒤, 브라우저 권한이 허용이고 서버가 광고 미동의 상태일 때만 뜨며 스크림 탭·뒤로가기는 "닫기"와 같습니다. 야간 동의는 시트에서 받지 않고 알림 설정에서만 켭니다. 처리 결과 통지를 닫을 때 브라우저 알림이 꺼져 있으면 "브라우저 알림이 꺼져 있어 알림 설정에서 켜야 받을 수 있어요" 토스트를 띄웁니다. 기록은 회원 귀속입니다.

ACCOUNT 내용은 다음 문서에서 관리한다. ([3-1-2 마이와 문서](../domain/ACCOUNT/CLIENT/WEB/3-1-INFORMATION-ARCHITECTURE.md#3-1-2-마이와-문서))

- **알림 설정 화면.** 마이 > 알림 섹션(화면과 기타 사이, 섹션 자체는 게스트에게도 보이며 아래에 [공지사항](3-1-client-spec.md#fe-screen-014-공지사항) 메뉴를 둠)의 회원 전용 "알림 설정"(`/my/notifications`, 회원 전용·게스트는 로그인으로 이동)은 [Android 알림 설정](3-3-android-spec.md#3-3-5-알림)과 같은 구성입니다. 브라우저 알림을 받을 수 없으면 목록 위 배너로 상태를 알립니다: 권한을 아직 묻지 않았으면 "알림 켜기" 버튼으로 브라우저 권한을 요청하고(거부하면 "브라우저 알림이 차단되어 있어요" 토스트), 차단됐으면 브라우저가 다시 묻지 않으므로 "방법 보기" 버튼으로 사이트 설정에서 허용하는 방법을 다이얼로그로 안내하며, iOS 비설치본은 홈 화면 추가 안내, 미지원 브라우저는 미지원 안내만 둡니다. 권한이 허용이면 배너가 없습니다. 아래에 서비스 알림·광고 알림·야간 광고 허용 스위치 줄(라벨·설명·오른쪽 스위치, 조회 중에는 스위치 자리에 골격)을 두며 광고 라벨 옆 외부 링크 아이콘으로 개인정보 처리방침을 새 탭에서 엽니다. 이 브라우저가 알림을 받을 수 없는 상태(권한 미결정·차단·iOS 비설치본)에서는 줄을 비활성으로 그립니다. 미지원 브라우저에서는 계정 단위 설정이라 줄을 활성으로 두어 다른 기기의 수신 동의를 관리·철회할 수 있게 합니다. 야간 줄은 광고가 켜져 있을 때만 표시하고, 광고를 끄면 야간도 함께 꺼집니다. 저장은 `PUT /users/me/push-settings` 전체 교체이며 실패하면 토스트와 함께 원래 값으로 돌아갑니다. 조회 실패는 안내와 "다시 시도하기"로 대체합니다. 광고·야간을 켜거나 끌 때마다 "전송자: …"·"일시: …"·"처리 내용: …" 세 줄(일시는 의사 표시 시점의 기기 시각)을 담은 처리 결과 다이얼로그를 즉시 표시합니다(정보통신망법 제50조, Android와 같은 구성). 서비스 알림 토글은 통지하지 않습니다.
- **표시.** 백그라운드 알림은 서버가 실은 제목·본문·아이콘·클릭 링크로 브라우저가 표시하고, 클릭하면 링크(`deepLink`, 운영 origin)를 엽니다. 앱 창이 이미 열려 있으면(iOS 홈 화면 설치본 포함) 새 창 대신 그 창을 링크로 이동시킨 뒤 앞으로 가져오고, 링크의 쿼리(`utm_*`)는 유지합니다. 링크가 없거나 운영 origin이 아니면 앱 홈을 엽니다. 페이지가 열려 있을 때 도착한 메시지는 토스트로 보여주며 `recipientId`가 현재 회원과 다르면 버립니다. 백그라운드 표시는 브라우저가 맡아 수신자를 대조할 수 없으므로 로그아웃 시 토큰 삭제가 방어선입니다.

### 앱 안내 배너

모바일 웹 방문자를 Android 앱이나 iOS 홈 화면 설치본으로 안내하는 배너입니다. 앱 프레임 맨 위, 각 화면 헤더보다 위에 표시합니다. 왼쪽에 앱 아이콘, 그 옆에 앱 이름 "마냑"과 아래 표의 문구를 두 줄로 두고, 오른쪽 끝에 버튼과 닫기(X)를 둡니다.

| 대상 | 노출 빈도 | 문구 | 버튼 | 버튼 동작 |
| --- | --- | --- | --- | --- |
| Android 인앱 브라우저 | 매 접속 | 앱에서 이어서 볼 수 있어요 | 앱 열기 | 앱이 설치돼 있으면 앱을, 없으면 플레이스토어를 엽니다 |
| Android 브라우저 | 첫 번째와 세 번째 접속 | 앱에서 이어서 볼 수 있어요 | 앱 열기 | 위와 같습니다 |
| iOS 인앱 브라우저 | 매 접속 | 외부 브라우저에서 이어서 봐요 | 열기 | 현재 화면을 외부 브라우저로 엽니다. 1.5초 뒤에도 화면이 그대로면 메뉴로 여는 방법과 링크 복사를 안내하는 시트를 엽니다 |
| iOS Safari, iOS Chrome | 첫 번째와 세 번째 접속 | 홈 화면에 추가해 앱처럼 열어요 | 추가하기 | 홈 화면에 추가하는 방법을 안내하는 시트를 엽니다 |

- 앱 열기는 스토리 상세(`/stories/{id}`)에서 앱의 같은 스토리를, 그 밖의 화면에서 앱 홈을 엽니다.
- 앱 이름과 문구는 각각 한 줄로만 표시합니다. 문구는 375px 너비(iPhone SE)에서도 줄바꿈 없이 들어가는 길이로 두고, 넘치면 말줄임합니다.
- 접속은 새 탭(새로 연 인앱 브라우저 포함)에서 배너를 처음 판정한 때를 1회로 셉니다. 같은 탭의 새로고침과 화면 이동은 같은 접속입니다. 닫기는 그 접속 동안만 숨기며, 첫 접속에서 닫아도 세 번째 접속에는 다시 표시합니다.
- 표시하지 않는 경우: 서비스 안내와 법적 문서 화면(Android 앱이 WebView로 엽니다), 데스크톱, 홈 화면 설치본, 검색 크롤러, iOS의 그 밖의 브라우저. 표시하지 않는 화면만 본 접속은 세지 않습니다.
- 홈 화면 추가 안내 시트의 제목은 "홈 화면에 추가하기"입니다. iPhone의 Safari 26 이상에서는 실제 화면 스크린샷 4장을 단계 번호와 함께 가로로 넘겨 보여주고, 아래 점 표시로 현재 장을 알려줍니다(1. 하단 ⋯ 누르고 "공유" 누르기, 2. "더 보기" 누르기, 3. "홈 화면에 추가" 누르기, 4. "추가" 누르기). 스크린샷의 연락처와 기기 이름은 가립니다. iOS Chrome, 이전 Safari, iPad에서는 텍스트 단계 "공유 버튼 누르기", "\"홈 화면에 추가\" 누르기"와 "공유 버튼이 안 보이면 ⋯를 먼저 눌러주세요"를 보여줍니다.
- 외부 브라우저 안내 시트는 제목 "외부 브라우저로 열어주세요", 본문 "⋯ 메뉴에서 \"브라우저로 열기\"를 눌러주세요", 버튼 "링크 복사하기"입니다. 복사 결과는 "링크를 복사했어요" 또는 "링크를 복사하지 못했어요" 토스트로 알립니다.
- 닫기를 누르면 포커스를 배너 아래 화면으로 옮깁니다. 버튼과 닫기의 접근성 이름은 "앱 열기", "외부 브라우저로 열기", "홈 화면에 추가하기", "닫기"이며 배너 영역 이름은 "앱 안내"입니다. 동작 줄이기에서는 애니메이션 없이 표시하고 숨깁니다.
- 앱 설치 뒤 원래 보던 화면으로 보내는 기능(디퍼드 딥링크)은 제공하지 않습니다.

### 앱 공유 링크

플레이스토어 페이지는 카카오톡 링크 스크래퍼에 Open Graph를 주지 않아 메신저에서 "미리보기가 없습니다"로 뜹니다. 앱을 소개할 때는 플레이스토어 주소 대신 `https://manyak.app/app`을 공유합니다.

- 미리보기는 제목 "마냑", 홈과 같은 설명([문서 열람과 검색 노출](#문서-열람과-검색-노출)), 루트 브랜드 이미지, 대표 URL `https://manyak.app/app`이며 문서 제목은 기본 문서 제목입니다. 검색 색인은 허용하지 않습니다(`noindex, follow`).
- 열면 탭마다 한 번 자동으로 이동합니다. Android는 앱 홈을 여는 앱 열기 링크로 가고 0.7초 안에 화면이 그대로면 플레이스토어로 교체 이동합니다. 카카오톡 인앱은 그 전에 외부 브라우저로 플레이스토어를 여는 단계를 한 번 거칩니다. Android가 아니면 웹 홈(`/`)으로 교체 이동합니다. 플레이스토어 설치 귀속값은 `utm_source=manyak_web&utm_medium=share_link`로 배너 설치(`utm_medium=app_banner`)와 구분합니다.
- 교체 이동이라 뒤로가기는 이 화면이 아니라 공유 링크를 연 곳으로 돌아갑니다. 앱에서 돌아오거나 같은 탭에서 새로고침·복원되면 다시 보내지 않고 화면에 머뭅니다.
- 화면은 링크 없는 로고 헤더 아래에 앱 아이콘, 제목 "마냑 앱으로 이동하고 있어요", 안내 "앱이 열리지 않으면 아래에서 받을 수 있어요", 소개 세 줄("키워드만 고르면 스토리가 완성돼요", "채팅으로 스토리를 이어가요", "실시간 이미지로 장면이 살아나요")을 두고, 하단에 플레이스토어를 여는 버튼 "Google Play에서 받기"와 웹 홈으로 교체 이동하는 보조 버튼 "웹에서 먼저 둘러보기"를 둡니다. 앱 안내 배너는 이 화면에 표시하지 않습니다.

### Safari·애니메이션·입력 UX 검수 기준
주소창·키보드 변화에도 CTA·입력창·마지막 메시지가 가려지거나 이중 스크롤·위치 튐이 생기지 않아야 합니다. 전환·스트리밍에 렌더 잔상·입력 차단이 없어야 하며 동작 줄이기에서는 장식 모션을 끕니다.

채팅은 Enter(Shift 없이, IME 조합 아님)·폼 제출·버튼으로 전송합니다. 전송 후 입력을 비우고 포커스를 유지하며 스트리밍 중 전송 잠금을 표시합니다. 블럭·추가 정보 행의 삭제 X는 Tab 순서에서 제외하되 클릭·터치 삭제는 제공합니다. 수동·자동 검수 경계는 [QA 공통 항목](../qa/AGENTS.md#크로스커팅-항목)을 따릅니다.

## 3-2-6. 유료 충전

상품은 `GET /credits/products`의 웹 가격(`webPriceKrw`)으로 표시하며 앱 가격은 노출하지 않습니다. 상품 선택 후 `POST /users/me/credits/orders`로 주문을 만들고 반환된 paymentUrl로 전체 이동(외부 결제창)합니다. 주문 생성이 201이 아니거나 paymentUrl이 없으면 이동하지 않고 실패 토스트를 띄웁니다. 결제창의 구매 완료 후 이동 페이지와 진입 페이지(결제 완료 화면을 닫을 때 돌아가는 주소)는 복귀 화면 `/my/credits/return`입니다. 복귀 화면은 결제 전 충전 화면까지 히스토리를 되감아 결제창 항목을 앞으로 쪽에 두므로, 결제 후 앱 바·브라우저·기기의 뒤로가기는 결제창이 아니라 충전 화면에 들어오기 전 화면으로 갑니다. 되감을 수 없으면(결제를 시작한 탭이 아님, 히스토리가 브라우저 상한에 닿음) `/my/credits`로 바꿔 끼우며, 이때 뒤로가기는 결제창으로 갈 수 있습니다. 복귀 주소는 주문 ID를 실어 오지 않으므로, 이동 직전 `orderId`를 기기(localStorage)에 남기고 복귀 시 그 주문을 `GET /users/me/credits/orders/{orderId}`로 2초 간격 최대 30회 조회합니다. 화면 상태·문구는 [공통 결제 결과](3-1-client-spec.md#fe-screen-008-로그인마이-페이지)를 따르며 잔액 상자 아래 확인 카드로 표시합니다. 대기 주문 기록은 24시간이 지나면 무시합니다. 결과가 확정(`COMPLETED`·`REFUNDED`·404)되면 기록을 즉시 지우고 카드는 닫거나 화면을 떠날 때까지만 표시하므로 새로고침·재진입에서 다시 묻지 않습니다. 결과 없이 떠난 주문(확인 중·60초 초과·조회 오류)은 기록을 남겨 재진입 시 다시 확인합니다. 결제창에서 뒤로가기로 문서가 복원(bfcache)되면 가격 버튼 잠금을 풉니다. 로그아웃·세션 만료·탈퇴 시 기록을 지웁니다.
