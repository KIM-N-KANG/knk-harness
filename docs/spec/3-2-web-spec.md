## 3-2-1. 적용 범위

브라우저 진입·URL·히스토리, 익명 체험과 회원 이관, 웹 전용 제작 흐름, 검색 노출·지원·접근성을 정의합니다. 공통 화면의 본문·입력 상한·오류 의미를 복제하지 않습니다.

<a id="웹-사용자-모델"></a>

## 3-2-2. 웹 사용자 모델

- 로그인 없이 오리지널 스토리와 체험 기능을 사용할 수 있습니다. 회원 전용 기능은 인증으로 연결합니다.
- 마이의 게스트 상태에는 로그인 버튼, 회원 상태에는 프로필·연동 계정·이프·로그아웃·탈퇴를 표시합니다.
- 회원의 목록은 서버가 정본입니다. 익명 상태에서 만든 콘텐츠는 해당 브라우저에 보관한 공개 ID로 접근합니다. 저장소 삭제·기기 변경 시 접근할 수 없음을 안내합니다.
- 스토리·채팅 ID는 각각 중복 없이 최신 생성순으로 최대 100개를 보관합니다. 오래된 ID가 목록에서 밀려도 서버 레코드를 삭제하지 않습니다. 토큰·민감 정보는 이 목록에 넣지 않습니다.
- 저장소를 읽기 전에는 빈 목록이 아니라 로딩으로 표시합니다. 손상된 배열은 빈 목록, 사용량의 누락·손상 값은 0으로 처리하고 0 이상 정수만 인정합니다.
- 비어 있지 않은 ID 목록만 배치 조회합니다. 스토리는 로컬 순서, 채팅은 서버 최근 활동순을 사용합니다. 삭제는 먼저 목록에서 빼되 실패 시 되돌리며 404는 삭제된 상태로 처리합니다.
- 게스트의 본 엔딩 배지는 로컬 채팅 배치 응답의 `reachedEndings`를 스토리별로 합산합니다. 로컬 서재에 없는 채팅은 집계하지 않습니다.
- 스토리라인 생성·재생성은 디바이스 ID별 합산 5회이며 201 성공 시에만 누적 카운터를 올립니다.
- 게스트 사용량으로 체험 한도를 선차단하고 서버 402를 최종 판정으로 사용합니다. 한도 도달에는 로그인 유도 시트를 엽니다. 표시할 한도와 서버 정책은 일치해야 합니다.
- 소유 스토리는 로컬 제작 ID로 판정하며 판정 전 좋아요 버튼을 숨깁니다(좋아요 UI는 현재 전면 비노출 — [`3-1-client-spec.md §3-1-3`](3-1-client-spec.md#fe-screen-003-스토리-상세) 스토리 좋아요). 게스트에게 신고하기 메뉴는 표시하지 않습니다.

### FE-SCREEN-007. 온보딩 페이지

- 비로그인·저장된 스토리와 채팅 0개·온보딩 미열람을 모두 만족하면 메인 탭 진입보다 온보딩을 먼저 표시합니다. 저장소를 읽기 전에는 노출을 판정하지 않습니다.
- 조건을 만족하지 않는 사용자가 직접 접근하면 열람 처리 후 원래 메인 탭으로 이동합니다. 반환 목적지는 메인 탭만 허용하고 기본은 홈입니다.
- 헤더는 로고와 '둘러보기'·'바로 시작하기'로 구성합니다. 로고는 본문 맨 위로 스크롤하며 화면 이동이나 열람 처리를 하지 않습니다.
- 본문은 단계별 스크린샷·설명으로 구성합니다. '바로 시작하기'는 간편 제작, '둘러보기'는 홈으로 이동합니다. 둘 다 열람을 저장하고 히스토리를 교체합니다.
- 푸터의 서비스 안내·약관·개인정보처리방침은 새 탭으로 열고 원래 온보딩을 유지합니다. 법적 문서 열람만으로 온보딩을 열람 처리하지 않습니다.
- 제작 퍼널을 떠나면 온보딩 경유 여부와 무관하게 제작 탭으로 돌아갑니다.

### 로그인과 회원 이관

- 로그인 화면에 최초 로그인 시 기기의 스토리·채팅을 계정으로 한 번만 이관한다는 안내를 둡니다. 약관·개인정보처리방침 링크는 새 탭으로 엽니다.
- 로그인 성공 후 보관된 ID를 이관하고 서버 결과에 반영된 수만 완료 안내합니다. 회원 서재로 전환한 뒤 이관 제출 결과와 무관하게 게스트 ID 배열·사용량을 정리합니다.
- 이관 실패가 로그인 완료를 막지 않습니다. 400이면 UUID 형식이 유효한 ID만 한 번 재제출하고 손상 ID를 폐기합니다. 실패 목록을 무한 재시도하지 않습니다.
- 신규 가입 안내·소셜 계정 연동·탈퇴 확인의 공통 사용자 계약을 따릅니다. 인증 콜백과 쿠키 처리는 웹 설계가 소유합니다.
- 로그아웃·탈퇴 후 로컬 세션을 정리하고 게스트 상태로 돌아갑니다. 제작 단일 슬롯도 정리합니다. 게스트에서 회원으로 로그인할 때는 복구할 제작 슬롯을 유지합니다.

<a id="웹-제작-흐름"></a>

## 3-2-3. 웹 제작 흐름

이 절은 웹 단일 슬롯 흐름의 적용 계약입니다. 공통의 초안·다중 완성 요청 분리 계약과의 전환은 [추적 문서](../planning/client-tracking.md#제작-계약의-플랫폼-적용)를 따릅니다.

- 키워드·스토리라인·추가 정보를 한 퍼널에서 전환하고 URL에 단계별 쿼리를 두지 않습니다. 완료 중에는 별도 종료 로딩 상태를 표시합니다.
- 키워드 입력과 생성 결과·편집본을 같은 진행 슬롯에 보관합니다. 편집 후 300ms 자동 저장하며, 문서가 숨겨지거나 페이지를 떠나면 예약 저장을 반영합니다. 저장 중·저장됨을 표시하되 쓰기 실패를 성공으로 표시하지 않습니다.
- 추가 정보 행의 X 삭제 버튼은 Tab 순서에서 제외해 다음 입력 행으로 이동합니다.
- 인물 이름에 `]`가 있으면 필드·푸터 오류를 표시하고 생성을 차단합니다. 다른 입력 제약은 공통 스펙을 따릅니다.
- 키보드가 열리면 이름·키워드·추가 정보 입력을 가리지 않도록 하단 단계 CTA를 숨기고 닫히면 같은 입력 상태로 복원합니다.
- 스토리 완성 후 채팅을 만들고 채팅방으로 히스토리를 교체합니다. 채팅 생성만 실패하면 이미 완성된 `storyId`를 보존하고 채팅 생성만 재시도합니다.
- 진행 요청이 편집본보다 우선합니다. 네트워크 오류·동일 요청의 409에는 진행 레코드를 유지하고 복구 조회로 판정합니다. 화면이 보일 때만 3초 간격으로 복구 조회합니다.
- 제작 배너의 이어서 만들기는 저장본을 소비하지 않고 복원합니다. 배너에는 삭제 버튼을 두지 않습니다. 새 제작은 제작 화면에서 이어서/새로 만들기를 먼저 묻습니다.
- 재개 다이얼로그는 이어서 만들기를 오른쪽 primary, 새로 만들기를 왼쪽 secondary로 둡니다. 제작 화면에서는 바깥 영역·Escape로 닫을 수 있고 이동·저장본 삭제가 없어야 합니다. 퍼널 직접 진입에서는 선택 전에 닫을 수 없습니다.
- 새로 만들기는 다이얼로그가 대상으로 삼은 요청과 현재 저장본이 같은 경우에만 기존 초안을 버립니다. 페이지 종료 이탈 가드와 브라우저 히스토리 처리는 웹 설계가 소유합니다.

## 3-2-4. 라우팅·레이아웃·공통 셸

### 라우팅 테이블

| 목적지 | URL | 접근 |
| --- | --- | --- |
| 홈·채팅 목록·제작·마이 | `/`·`/chats`·`/studio`·`/my` | 게스트·회원 |
| 간편 제작 | `/studio/story/simple` | 게스트·회원 |
| 일반 제작·수정 | `/studio/story/general`·`/stories/[id]/edit` | 공통 계약의 작성·소유 조건 |
| 스토리 상세·채팅방 | `/stories/[id]`·`/chats/[id]` | 서버 권한 판정 |
| 로그인·로그인 이어가기 | `/login`·`/login/continue` | 인증 진입 |
| 친구 초대·이프 충전·회원 탈퇴 | `/my/invite`·`/my/credits`·`/my/account-deletion` | 회원 |
| 피드백·서비스 안내 | `/feedback`·`/about` | 게스트·회원 |
| 약관·개인정보처리방침 | `/terms`·`/privacy` | 로그인 전에도 허용 |
| 공유 열람 | `/share/[shareId]` | 링크 보유자 |
| 온보딩 | `/onboarding` | 위 온보딩 노출 조건 |

계약의 승인·적용과 라우트 제공 여부는 [추적 문서](../planning/client-tracking.md)에서 구분합니다. 적용을 유예한 경로도 제공 여부와 구분하여 추적합니다.

### 화면 전환 규칙

- 메인 탭은 홈·채팅·제작·마이이며 선택 상태를 표시합니다. 회원의 `/login` 직접 접근 자체를 차단하지 않습니다.
- 회원 전용 경로의 게스트는 로그인으로 보냅니다. 없는 경로는 Not Found와 홈 복귀 링크를 제공합니다.
- 스토리 상세의 채팅 시작은 채팅방으로 교체합니다. 채팅방의 헤더 뒤로가기는 채팅 목록으로 이동합니다. 삭제된 화면이 뒤로가기로 되살아나지 않아야 합니다.
- 이전 `/create` 계열 URL의 호환 처리와 라우트 그룹은 [웹 설계](../design/1-1-web-design.md#1-1-2-라우팅레이아웃공통-셸)가 소유합니다.

### 문서 열람과 검색 노출

- 약관·개인정보처리방침·서비스 안내는 로고 홈 링크 헤더와 스크롤 본문으로 표시합니다. 시행일·버전은 본문에 표시하고 공통 콘텐츠 동일성 계약을 따릅니다.
- 서비스 안내는 마이에서 새 탭으로 엽니다. Android에서 사용하는 법적 문서 공급 경로도 같은 본문을 사용합니다.
- 문서 제목은 `제목 - 마냑`입니다. 기본 제목·법적 콘텐츠 문구는 웹 코드의 정본을 사용합니다.
- 검색 크롤러·링크 미리보기 스크래퍼에는 온보딩 게이트만 우회하며 별도 콘텐츠를 만들지 않습니다.
- 공개 홈·서비스 안내·법적 문서·오리지널 스토리 상세를 사이트맵에 싣습니다. 유효한 공유본은 색인을 허용하되 사이트맵에 나열하지 않습니다.
- 개인화·인증·제작 화면과 API는 수집에서 제외합니다. 로그인 이어가기 URL과 조회 불가 공유본, 사용자 스토리 상세는 `noindex, nofollow`입니다.
- 오리지널 여부를 판정하지 못하면 상세 색인을 허용하지 않습니다. robots.txt가 상세 메타데이터 판독을 막아서는 안 됩니다.
- 공유 열람은 로컬 서재를 변경하지 않습니다. 하단 제작 CTA는 간편 제작으로 바로 연결하고 온보딩을 열람 처리합니다.

## 3-2-5. 반응형·접근성·브라우저 지원
### 반응형: 모바일 전용

- 레이아웃은 `max-w-md` 단일 컬럼으로 고정한 모바일 전용입니다. 데스크톱 다단 레이아웃을 제공하지 않습니다.
- 안전 영역(`env(safe-area-inset-bottom)`)과 `viewportFit: cover`를 사용합니다.

### 모바일 검수 기준

- 주요 CTA가 첫 화면에서 확인 가능해야 합니다.
- 가로 스크롤이 발생하지 않아야 합니다.
- 입력 폼 사용 중 화면이 깨지지 않아야 합니다(`interactiveWidget: resizes-content`).

### 접근성 기준

- 클릭 가능한 요소는 키보드로 접근 가능하고 focus가 시각적으로 확인되어야 합니다.
- 폼 입력에 label을 연결하고 오류는 `aria-invalid`·오류 메시지(`role=alert`)로 노출합니다.
- 다이얼로그와 모달 바텀 시트는 열릴 때 포커스를 내부로 이동하되, 첫 버튼·입력란이 아니라 **팝업 자체에 두는 것을 기본**으로 합니다. 특정 요소에 초점이 필요한 오버레이만 `initialFocus`로 덮어씁니다. 게스트 한도와 신규 가입 초대 코드 안내는 공용 Drawer를 앱 프레임 컨테이너에 포털해 화면 아래에서 올라오는 모달 바텀 시트로 렌더합니다.
- 로딩·상태 영역은 `role=status`와 `aria-label`로 안내합니다.
- 색상만으로 상태를 구분하지 않습니다.

### 테마·서체

- 테마는 시스템 설정(OS 다크 모드)이 기본이며, 마이 페이지의 테마 변경 메뉴로 시스템 설정·라이트·다크를 선택할 수 있습니다(FE-SCREEN-008). 선택값은 기기 단위로 저장됩니다.
- 기본 서체는 Pretendard, 서사 텍스트(프롤로그·대화·스토리라인·추천 입력)는 자간 `-2%`(`letter-spacing: -0.02em`)·행간 `175%`(`line-height: 1.75`)의 MaruBuri를 적용합니다. 웹은 두 값을 공통 `.font-maruburi` 스타일 한 곳에서 관리해 사용 위치마다 행간 유틸리티가 갈리지 않게 합니다.

### PWA 푸시

`Phase 3 · 계획`(KNK-1271). 2026-09-11 요청에 따른 웹 담당의 후속 설계·검증 항목입니다.

- 로그인 완료와 브라우저 알림 권한 허용을 모두 확인한 뒤 FCM 토큰을 `PUT /users/me/push-tokens`에 `platform: "WEB"`으로 등록할 계획입니다. 삭제는 `DELETE /users/me/push-tokens`에 `token`만 전달하는 기존 계약을 따릅니다.
- 광고성 수신 동의 UI를 `GET·PUT /users/me/push-settings`에 연결할 계획입니다. 브라우저 알림 권한을 광고 수신 동의로 대체하지 않습니다.
- data의 `recipientId`와 현재 로그인 회원 ID를 대조해 다른 회원 대상 알림을 걸러낼 계획입니다. 값이 없거나 일치하지 않는 알림의 표시·클릭을 차단하는 방식은 서비스 워커 및 브라우저 자동 표시 경로를 포함해 웹 담당이 설계하고 검증해야 합니다.
- 같은 Firebase 프로젝트 등록과 VAPID 키·서비스 워커 구성이 전제입니다. 지원 브라우저별 동작과 구체적인 UI는 웹 담당이 후속 확정합니다. 서버의 플랫폼별 발송 계약은 [백엔드 푸시 절](4-backend-server-spec.md#4-3-api-계약)을 따릅니다.

### 인앱 브라우저와 로그인 핸드오프

- 인앱 브라우저에서도 게스트 체험을 허용합니다. 카카오톡 인앱의 Kakao 로그인은 그 브라우저에서 진행합니다. Google 로그인 및 외부 브라우저 전환이 필요한 경로는 핸드오프로 로그인과 이관을 이어갑니다. 지원 조합은 웹 설계의 브라우저별 로그인 표를 따릅니다.
- 외부 브라우저로 보낼 때 일회용 핸드오프 코드를 사용합니다. 코드·토큰·공유 식별자를 분석·오류 수집에 기록하지 않습니다.
- 전달할 게스트 ID·체험 상태는 서버 계약에 따라 교환하고, 발급·열람·소비 실패를 로그인 성공으로 처리하지 않습니다.
- 핸드오프가 실패하면 외부 브라우저에서 다시 로그인할 수 있는 안내를 제공합니다. 감지·탈출 스킴·쿠키·코드 소비 순서는 웹 설계가 소유합니다.

### Safari·애니메이션·입력 UX 검수 기준
퀄리티 개선 범위의 사용감 개선입니다. Playwright의 Mobile Safari(iPhone 13) 프로젝트는 `e2e/smoke/`의 핵심 진입·이동만 자동 검증합니다. 주소창·가상 키보드·안전 영역처럼 에뮬레이션으로 재현하기 어려운 항목은 실기기(iOS Safari 최신) 수동 검수가 기준입니다. 구현 상세(속성·라이브러리)는 프론트엔드 코드가 소유하고, 이 절은 검수 기준만 고정합니다.

**Safari 렌더링**

- 채팅 스트리밍 중 토큰 누적·하단 고정 스크롤([3-1-client-spec.md §3-1-5](3-1-client-spec.md#3-1-5-채팅-플레이와-sse-스트리밍))이 iOS Safari에서 Chrome과 동일하게 동작해야 합니다(렌더 밀림·잔상·깜빡임 없음).
- 주소창·툴바 확장/축소에 따른 뷰포트 변화에서 하단 고정 CTA·입력창이 가려지거나 이중 스크롤이 생기지 않아야 합니다(`svh`·`dvh` 기준 유지).
- 안전 영역(노치·홈 인디케이터)에서 하단 네비게이션·컴포저가 겹치지 않아야 합니다.

**애니메이션**

- 화면 전환([§3-2-4](#3-2-4-라우팅레이아웃공통-셸))과 채팅 버블 등장이 스크롤·스트리밍 성능을 떨어뜨리지 않아야 합니다(전환 중 입력 차단 없음).
- OS의 동작 줄이기(`prefers-reduced-motion`) 설정 시 장식성 애니메이션이 비활성화돼야 합니다.

**채팅 입력 UX**

- 모바일 키보드가 열릴 때 입력창과 마지막 메시지가 함께 보여야 하고(`interactiveWidget: resizes-content` 유지), 키보드가 닫힐 때 스크롤 위치가 튀지 않아야 합니다.
- 전송 직후 입력창이 비워지고 포커스가 유지돼야 하며, 스트리밍 중 전송 잠금([3-1-client-spec.md §3-1-5](3-1-client-spec.md#3-1-5-채팅-플레이와-sse-스트리밍))이 시각적으로 구분돼야 합니다.
- IME 조합 중 `Enter`가 전송으로 오인되지 않아야 합니다(iOS·Android 공통).

## 3-2-6. 유료 충전

상품은 `GET /credits/products`의 웹 가격으로 표시합니다. 상품 선택 후 `POST /users/me/credits/orders`로 주문을 만들고 반환된 paymentUrl로 이동합니다. 복귀 후 `GET /users/me/credits/orders/{orderId}`를 조회하며 공통 결제 결과 계약을 따릅니다. 계약 적용과 제공·검증 근거는 추적 문서에서 확인합니다.
