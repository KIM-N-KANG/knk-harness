# 4-1 연동 계약: iOS

기준: [공통 연동 계약](../4-1-CONTRACT.md), [iOS 요구사항](2-2-REQUIREMENTS.md).

<br>

### 4-1-1 서버 선행 변경

현재 서버 계약의 토큰 등록 `platform`은 `ANDROID`와 `WEB`만 받고 Android에는 데이터만 있는 메시지를 보낸다. ([토큰 등록](../../BACKEND/4-2-CONTRACT.md#4-2-2-토큰-등록), [푸시 데이터](../../BACKEND/4-2-CONTRACT.md#4-2-10-푸시-데이터)) iOS는 앱이 백그라운드이거나 종료된 동안 앱 코드 없이 시스템이 알림을 표시하므로 표시할 내용이 서버 메시지에 있어야 한다. 아래는 앱이 요구하는 정보이며 값 이름, 필드와 페이로드 형식은 모두 미정(서버 선행 변경 필요)이다. ([I-140](DECISIONS.md#i-140))

| 대상 | 앱이 요구하는 정보 |
|---|---|
| 토큰 등록 | 같은 등록 요청에서 iOS를 구분하는 `platform` 값. 토큰은 Firebase Messaging이 준 FCM 등록 토큰 |
| 표시 제목과 본문 | 모든 시나리오의 표시 제목과 본문. 시스템이 그대로 표시 |
| 탭 데이터 | 알림을 눌렀을 때 앱이 읽을 수 있는 `type`, `recipientId`, `deepLink`. 의미는 푸시 데이터의 공통 필드와 같음 |
| 같은 대상 재발송 | 같은 제출본 검수 결과의 재발송이 알림 센터의 앞 알림을 교체 |
| 유효 기한 | 유효 기한이 있는 시나리오는 기한 뒤 기기에 전달하지 않음 |
| 소리 | 시스템 기본 소리 |
| 쓰지 않는 구성 | 앱 아이콘 배지 숫자, 무음 푸시와 백그라운드 실행 요청, 표시 직전 내용 변경 요청, 중요도 상향 |

토큰 삭제 요청은 `platform` 없이 토큰만 보내므로 현재 계약을 그대로 쓴다. ([토큰 삭제](../../BACKEND/4-2-CONTRACT.md#4-2-3-토큰-삭제)) `platform` 값이 정해지기 전에는 등록 요청을 보내지 않는다.
