# 4-2 컴포넌트 구조: iOS

<br>

### 4-2-1 책임과 경계

| 구성 | 책임 |
|---|---|
| `ManyakChat` Data | DTO와 Repository 구현. SSE 요청을 열고 바이트를 이벤트로 해석해 수신 결과로 바꿈. 완료와 포크 성공 시 목록 변경 신호 |
| `ManyakChat` Domain | 상세, 턴, 진행 중 생성과 Repository 계약. 생성 따라가기는 스트림을 하나씩 여는 계약과 주입한 시계로 재연결 차례와 결과를 만듦 |
| 채팅방 Store | 생성 단계 하나와 그 작업, 백그라운드 중단과 복귀, 확정, 입력 수정 편집, 재생성과 입력 수정 및 포크 확인, 포크 요청, 설정과 안내 상태, 메뉴의 이프 내역 상태, 분석 이벤트 |
| 턴 표시 | 확정 턴, 대상 턴 자리의 진행 블록, 입력 수정 중 뒤 턴 숨김과 흐림, 턴 버튼과 편집기 |
| 채팅방 헤더 | 겹침 헤더의 표시 전환과 높이 측정. 가장자리 밀기 뒤로가기를 막지 않음 |
| 채팅 메뉴 | 메뉴와 이프 내역 화면 전환, 시트 높이 전환. 내역 조회와 행 표현은 PAYMENT 공용 구현 사용 |
| 목록 Store | 활동 변경 신호, 당겨 새로고침, 포그라운드 복귀 조회 |
| 컴포저 | 커서와 선택 영역, 강조 삽입, 블럭별 초점, 키보드 위 배치. 변경은 Intent로 전달 |
| `ManyakDesignSystem` | 텍스트와 이미지 조각 파서, 인물 이미지와 허용 주소 검사, 전체 화면 뷰어, 마스코트와 순환 문구 |
| `ManyakReport` | 메뉴와 목록 옵션의 참조 스토리 신고 시트 |
| `ManyakMy` | 피드백 API와 폼, 입력 검증과 제출 |
| 앱 타깃 | 채팅방 라우트 쌓기와 교체, 포크한 방 쌓기, 삭제 뒤 채팅 탭 복귀, 장면 단계 변화를 보이는 채팅방 Store와 목록 Store에 전달 |

`ManyakChat`은 `ManyakCredit`과 `ManyakMy`에 의존하지 않는다. 이프 부족 안내와 내역은 기반 타깃의 공용 계약으로 쓰고 상태는 채팅방 Store가 가진다. 목록과 채팅방은 같은 참조 스토리 유효 조건을 사용한다. 화면의 `body` 재평가와 반복되는 `.task` 시작으로 도메인 호출과 복구를 시작하지 않는다. 파서는 스토리 상세의 상황 설명에서도 재사용한다.
