# 2-2 운영 요구사항

이 문서는 진단 에이전트의 품질, 시간, 비용 목표와 운영 제약을 정한다.

운영자의 기대는 2-1 유저 스토리에 있고 실행 환경은 4-2 소프트웨어 설계에 있다. ([2-1-2 품질에 대한 기대](2-1-USER-STORY.md#2-1-2-품질에-대한-기대)와 [4-2-2 실행 환경](4-2-DESIGN-SOFTWARE-ARCHITECTURE.md#4-2-2-실행-환경))

<br>

### 2-2-1 태스크의 유저

운영 관점의 유저는 에이전트를 운영하는 개발자다. 진단에 필요한 성능은 갖춘다. 다만 서비스 본체가 아닌 부가 도구이므로 시간과 모델 비용은 작은 한도 안에 둔다.

<br>

### 2-2-2 품질

| 항목 | 목표값 | 측정 방법 |
|---|---|---|
| 근거 검증 통과율 | 100% | 검증을 통과한 근거 수 / 장애로 판정한 보고의 전체 근거 수<br>조회 근거와 코드 근거를 함께 셈 |

<br>

### 2-2-3 시간

| 항목 | 목표값 | 측정 방법 |
|---|---|---|
| 탐지 지연 | 장애마다 5분 이하 | 장애의 첫 이상 시각부터 이상 후보를 연 시각까지 |
| 진단 시간 | 진단 요청 1건당 3분 이하 | 진단 요청부터 보고 기록까지의 실제 경과 시간<br>앞 진단을 기다린 시간은 제외 |

<br>

### 2-2-4 비용

| 항목 | 목표값 | 측정 방법 |
|---|---|---|
| 진단 비용 | 진단 요청 1건당 $0.50 이하 | 진단 턴의 모델 호출 |
| 세션 비용 | 세션 1건당 $2.00 이하 | 진단 턴과 그 뒤 대화 턴의 모델 호출 |
| 하루 비용 | 하루 $5.00 이하 | UTC 하루 동안 끝난 진단 턴과 대화 턴의 모델 호출 |
| 전체 예산 | Claude API 크레딧 $100 | |

판단 불가와 실행 실패로 끝난 진단의 비용도 넣는다. 관측 저장소 조회 비용은 넣지 않는다.

<br>

### 2-2-5 운영 제약

| 제약 | 내용 |
|---|---|
| 실행 위치 | 상시 실행되는 프로세스<br>외부에서 요청을 받는 엔드포인트를 두지 않음 |
| 읽기 권한 | 관측 저장소와 코드 저장소를 읽기만 함<br>설정, 태스크 수, 데이터를 바꾸는 권한과 push, PR 생성 권한이 없음 |
| 도구 범위 | 모델에 읽기 도구만 노출함<br>파일 수정, 파일 생성, 명령 실행 도구를 노출하지 않음 |
| 모델에 보내는 자료 | 관측 저장소의 조회 결과와 코드 사본의 내용만 보냄 <br> 운영 로그의 메시지 원문과 식별자 필드는 보내지 않음 |
| 자격 증명 분리 | OpenSearch와 Prometheus 비밀번호, AWS 자격 증명은 에이전트 코드와 그 자격 증명을 쓰는 공식 MCP 프로세스에만 둠 <br> 모델이 쓰는 도구 중 프로세스 환경이나 사본 밖 파일을 읽는 도구가 없음 |
| 비밀 정보 | 설정 파일, 보고, 스레드, 로그에 저장하지 않음 |

<br>

### 2-2-6 운영 특성과 한계

| 항목 | 내용 |
|---|---|
| 운영 트래픽 | 운영 트래픽이 적어 요청이 분당 20건을 넘는 일이 드묾<br>이 때문에 이상 후보가 거의 열리지 않을 수 있음<br>그때는 운영자가 멘션으로 진단을 직접 요청함 |
