# 2-1 유저 스토리

이 문서는 운영자가 진단 보고와 슬랙 대화에 기대하는 품질을 정한다.

목적과 범위는 1 배경에 있고 정량 목표는 2-2 운영 요구사항에 있다. ([1-3 목적과 범위](1-BACKGROUND.md#1-3-목적과-범위)와 [2-2 운영 요구사항](2-2-OPERATION-REQUIREMENTS.md))

<br>

### 2-1-1 태스크의 유저

유저는 운영자다. 운영자는 슬랙으로 장애 보고를 받고 슬랙 대화로 무엇이 왜 안 되는지 물어본다. 다른 일을 하다가 보고를 받으므로 보고 하나로 조치를 정할 수 있어야 한다.

<br>

### 2-1-2 품질에 대한 기대

#### 탐지

| 기대 |
|---|
| 장애가 나면 운영자가 대시보드를 열기 전에 알려 줌 |
| 오류 없이 느려지기만 한 장애도 잡음 |
| 오토스케일링과 경보가 동작하지 않은 장애도 잡음 |
| 부하가 높아도 지연 기준 안이면 장애로 보고하지 않음 |
| 궁금할 때 에이전트를 멘션해 바로 진단을 요청할 수 있음 |

<br>

#### 진단

| 기대 |
|---|
| 의심 구성 요소를 서비스 지도의 이름으로 지목함 |
| "큐 대기가 길다" 같은 증상이 아니라 왜 큐가 찼는지 메커니즘을 설명함 |
| 근거마다 어떤 조회에서 어떤 값을 봤는지 적어 운영자가 다시 확인할 수 있음 |
| 원인이 코드나 설정에 있으면 저장소, 경로, 줄과 그 줄의 문장을 적음 |
| 영향을 받은 요청 경로와 첫 이상 시각을 적음 |
| 자료가 부족하면 지어내지 않고 판단 불가로 보고함 |
| 슬랙 메시지를 한눈에 읽음<br>수치는 초나 %로, 시각은 운영자의 시간대로 적힘 |

<br>

#### 조치 제안

| 기대 |
|---|
| 지금 영향을 줄이는 즉시 조치와 원인을 고치는 근본 조치를 나눠 제안함 |
| 제안만 하고 조치는 운영자가 정하고 실행함 |

<br>

#### 대화

| 기대 |
|---|
| 스레드에서 되물으면 그 진단의 조회와 보고를 기억한 채 답함 |
| 바꿔 달라고 해도 바꾸지 않고 어느 파일에서 무엇을 어떻게 바꿀지 알려 줌 |
