**OBS-AI-020. 자료 접근은 공식 MCP**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-24 |
| 배경 | 모니터링 도구가 제공하는 공식 MCP를 연결해 빠르게 시험하라는 멘토 피드백이 있었다. 에이전트 코드가 직접 만든 조회 도구 4개는 질의, 결과 변환, 식별자 제거를 모두 맡았다. |
| 채택 | 로그와 스팬은 OpenSearch MCP, 인프라 메트릭과 경보는 CloudWatch MCP, 앱 메트릭은 Prometheus MCP로 읽고 읽기 도구만 켠다. CloudWatch MCP에 없는 확장 이력과 보고 제출은 직접 둔 도구로 남긴다. 2026-11-17부터 관측 서버 Prometheus는 같은 도구 이름의 자체 도구로 읽고 AMP를 쓸 때만 Prometheus MCP를 띄운다. 2026-11-24 운영이 AWS를 떠나 CloudWatch MCP와 확장 이력 도구는 지표 차원을 설정한 구성 요소가 있을 때만 쓴다.<br>시스템 프롬프트에 집계 질의를 먼저 쓰는 조회 규칙을 둔다. 운영 진단 6건에서 통째로 돌려받은 스팬 문서가 모델 비용의 36%였기 때문이다. |
| 대안 | 직접 만든 조회 도구를 유지하는 안. 결과 형식을 코드가 통제하는 이점이 있지만 만들고 유지하는 부담이 커 채택하지 않았다. |
| 영향 | 모델이 질의를 직접 쓰므로 도구 결과의 크기와 형식을 코드가 정하지 못한다. 코드가 식별자를 빼는 방식도 쓸 수 없다(OBS-AI-023). |

**OBS-AI-028. Haiku 탐색 분리 대신 Sonnet 단독**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-27<br>2026-11-16 다시 측정함 |
| 배경 | 탐색과 읽기는 Haiku에 맡기고 결론만 Sonnet이 내도록 나눠 보라는 멘토 피드백이 있었다.<br>첫 측정에서는 Sonnet이 도구 정의를 그대로 받아 이득이 작았다. 그래서 Sonnet이 조회 도구 정의를 받지 않게 바꿔 다시 쟀다.<br>2026-11-23 멘토도 진단이 드물게 돌아 건당 약 $0.03 차이는 크지 않다고 봤다. |
| 채택 | 진단 턴은 `claude-sonnet-5-5` 하나가 조회와 코드 읽기까지 직접 한다. |
| 대안 | 조회를 전부 Haiku에게 맡기는 안과 공식 MCP 조회만 Haiku에게 맡기는 안. 비용은 약 25% 줄지만 진단 시간이 두 배 넘게 늘고 DB 사례의 정확도가 떨어져 채택하지 않았다. |
| 영향 | 실험 경로는 설정으로 남기고 기본은 꺼 둔다. |
| 측정 | 2026-10-27 같은 질문 두 개를 방식마다 한 번씩 실행했다.
