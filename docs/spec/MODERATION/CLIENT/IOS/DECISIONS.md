# DECISIONS.md

현재 적용 기준은 각 명세에 두고 결정 당시의 이유와 대체 관계는 이 문서에 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다. 기존 ID, 날짜, 당시 상태와 근거를 유지한다.
- 상태와 구현 설명은 원본의 기록 시점을 기준으로 해석한다. 현재 적용 여부나 배포 완료를 과거 기록만으로 단정하지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체하는 결정과 적용 범위를 명시한다.
- 원문에 구분되지 않은 배경, 대안과 영향은 추측해서 보충하지 않는다.
- 이 세트의 iOS 결정 ID는 I-160부터 I-169까지 쓴다. 사용자가 확인하기 전의 작성 중 결정은 상태를 Proposed로 둔다.

<br>

<a id="i-160-신고-상세는-utf-16-단위로-세고-공백뿐이면-null로-보냄"></a>

**I-160. 신고 상세는 UTF-16 단위로 세고 공백뿐이면 null로 보냄**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Proposed |
| 관계 | 없음 |
| 승인 근거 | 작성 중 결정. 사용자 확인 전 |
| 배경 | 공통 계약은 상세를 최대 500자로 정하고 웹은 앞뒤 공백을 제거한 뒤 빈 값을 null로, Android는 공백뿐인 값만 null로 보낸다. 서버는 상세 길이를 문자열의 UTF-16 코드 단위 수로 검사한다(`manyak-server` 커밋 `ec1e3e4b`의 `StoryDtos.kt` `@Size(max = 500)`, 2026-11-28 확인). Swift 문자열의 기본 글자 수는 화면에 보이는 글자 단위라 이모지나 결합 문자가 섞이면 서버 기준 500을 넘을 수 있다. Android는 UTF-16 단위로 세고 500에서 잘라 코드상 이모지 하나가 둘로 나뉠 수 있다. |
| 채택 | 상세 길이와 글자 수 표시는 UTF-16 단위로 센다. 500을 넘는 입력은 오류 없이 마지막 온전한 글자 뒤에서 자르고 한글 조합 중인 글자를 깨지 않는다. 전송할 때 공백과 줄바꿈뿐인 상세는 null, 그 밖의 문자열은 그대로 보낸다. |
| 대안 | 화면에 보이는 글자 단위로 세기: 이모지가 섞인 입력이 서버에서 400으로 거절될 수 있다<br>웹처럼 앞뒤 공백을 제거한 뒤 전송 |
| 이유 | 화면의 상한과 서버 검사가 같은 단위여야 상한 안에서 쓴 신고가 길이로 거절되지 않는다. 전송 변환은 사용자가 쓴 상세를 바꾸지 않는 쪽을 골랐다. |
| 영향 | 이모지 하나는 글자 수 표시에서 2 이상으로 센다. STORY 백엔드 계약의 “500자 이하”에는 세는 단위가 적혀 있지 않다. 별도 티켓으로 기준 문서 정리 |
| 근거 | [STORY 신고 계약](../../../STORY/BACKEND/4-2-CONTRACT.md#4-2-22-신고), [공통 신고 API](../4-1-CONTRACT.md#4-1-1-신고-api) |

**I-161. 전송 중 신고 시트 닫기는 공통 흐름대로 막음**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-28 |
| 상태 | Accepted |
| 관계 | IOS 기반 [I-017](../../../../platform/CLIENT/IOS/DECISIONS.md#i-017)의 MODERATION 해당분 |
| 승인 근거 | KNK-2154 작업 대화에서 사용자가 확정했다. |
| 배경 | 하네스 문서와 Android 코드가 다른 곳은 iOS 본문에서 하네스 기준을 따른다. 공통 화면 흐름은 전송 중 바깥 탭이나 닫기 조작으로 시트를 닫지 않는다고 정한다. Android 코드(조사 커밋 `ccc93f77`)는 전송 중 닫기 버튼, 사유와 입력만 잠그고 시트의 끌어내리기와 바깥 탭 닫기를 막지 않아 코드상 신고 상태가 열림인 채 시트가 사라질 수 있다. |
| 채택 | iOS는 공통 흐름대로 전송 중 시트의 끌어내리기와 바깥 탭 닫기를 막는다. 기존 Android와 공통 본문은 고치지 않는다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 대화에서 별도 이유를 남기지 않았다. |
| 영향 | Android 신고 시트의 전송 중 닫기 잠금이 공통 흐름과 다르다. 별도 티켓으로 기준 문서 정리 |
| 근거 | [공통 신고 흐름](../3-2-INTERACTION-FLOWS.md#3-2-1-신고), [Android 신고 코드 기준](https://github.com/KIM-N-KANG/manyak-android/tree/ccc93f77289fd960def116184c2c86c552e4124e/core/report/src/main/java/app/manyak/report) |
