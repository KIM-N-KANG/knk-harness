# 5-1 검증: iOS

변경 범위에 맞춰 swift-format 검사, SwiftLint, 단위 테스트와 시뮬레이터용 Debug 빌드를 사용한다. 기기 검증은 백그라운드 복귀, 시스템의 프로세스 종료와 재설치를 구분하고 카카오톡 앱 전환은 앱을 설치한 실기기에서 확인한다. 이 문서는 검증 절차이며 실행 결과는 PR과 CI에 기록한다. ([IOS 기반 검증](../../../../platform/CLIENT/IOS/4-VERIFICATION.md))

<br>

### 5-1-1 단위 테스트 경계

| 경계 | 필수 확인 |
|---|---|
| 인증 | 동시 401 단일 재발급, 이미 교체된 토큰의 401 재전송, 회전 토큰 저장 실패, 재발급 5xx의 세션 유지, 벽시계 변경과 단조 시계 경과, 늦은 응답 세대 차단 |
| 시작 | 보호 데이터 접근 불가 보류, Keychain 손상과 읽기 실패, 설치 표시 없음과 남은 토큰, 저널 재개 |
| 로그아웃 | 각 단계 실패와 3회 시도, 저널 기록 실패, 프로세스 종료 후 저널 재개, 제공자 정리 실패 시 새 로그인 차단, 등록 배열 전 항목 실행 |
| 제공자 | 설정 누락의 `ProviderNotConfigured`, 취소의 `ProviderCancelled`와 카카오 폴백 없음, ID 토큰 없는 성공 |

HTTP는 `URLProtocol` 대역, Keychain과 저널은 저장 계약의 대역, 시간은 조작 가능한 시계로 확인한다.
