# 제품 Spec 작성 가이드

기술 스택의 구분 없이, 제품 명세를 읽기 쉽고 모호하지 않게 쓰기 위한 공통 규칙이다. 문서에 담을 항목, 목차와 기술적 결정은 담당자가 정한다.

<br>

## 1. 개요
문서 작성은 **워터풀 방식**을 차용한다. 앞 단계의 결정을 바탕으로 다음 단계를 구체화하며, 변경은 해당 단계와 이후 단계에만 반영한다. 예를 들어 5번이 바뀌면 1~4번은 유지하고, 5번과 영향을 받는 이후 문서만 수정한다.

결정한 내용과 적용 조건을 명확하게 작성한다. 결정의 의도를 이해하는 데 필요한 근거와 맥락을 짧게 설명하거나 참조한다. 예시는 설명만으로 의미가 분명하지 않을 때 사용한다.

<br>

## 2. 작성 원칙
- **명세 우선:** 현재 적용되는 명세와 구현이 어긋나면 명세가 기준이다. 불일치를 기록하고 구현에 맞추려고 명세를 임의로 바꾸지 않는다. 변경이 필요하면 이유를 밝히고 정해진 절차로 반영한다.
- **정확성:** 용어, 필드명, 다이어그램, 참조 문서가 정확한지 확인한다. 명세가 틀리면 이후 설계나 구현, 의사 결정이 반복해서 망가진다.
- **완결성:** 해당 범위를 구현하는 데 필요한 결정을 빠뜨리지 않는다. 없는 것은 없다고 쓰고 미정, 비적용, 미구현을 구분한다. 빈 항목을 채우려고 불필요한 내용을 추가하지 않는다.
- **무모순:** 문서 안팎의 용어, 조건, 결정과 예시가 서로 맞아야 한다. 같은 사실은 한 곳에서 정의하고 다른 문서에서는 참조한다. 변경할 때는 관련 설명과 예시도 함께 확인한다.
- **간결함:** 같은 뜻의 반복, 관련 없는 배경과 불필요한 예시는 삭제한다. 이해와 구현에 필요한 이유와 조건은 남긴다. 이미 전달한 결론을 장 끝마다 다시 요약하지 않는다.
- **생성 품질:** 문서는 코드를 만드는 재료이다. 동작뿐 아니라 **컴포넌트 경계와 책임, 구현 컨벤션, 금지 패턴, 품질 임계**를 구체적으로 적는다. 반드시 지킬 결정과 구현자가 선택할 수 있는 부분을 명확히 구분한다.
- **서브에이전트 금지:** 명세의 작성, 수정과 검토를 서브에이전트에 위임하지 않는다. 작성자가 자료를 직접 확인하고 문서 전체의 일관성을 검토한다.

<br>

## 3. 문장과 표현

### 3-1 문장과 기호
- 본문은 ‘한다’체로 작성하고 주체, 조건과 동작을 분명히 쓴다.
- “적절히 처리한다”처럼 해석을 독자에게 넘기는 표현은 피한다.
- 본문에서 em dash와 원문자를 쓰지 않는다.
- 가운뎃점 대신 쉼표나 와/과를 쓰고 연결어미 뒤의 불필요한 쉼표는 제거한다.
- 구획선은 사용하지 않고, 제목과 문단 간격으로 구분한다.
- 각 장과 절 앞에는 빈 줄을 사이에 두고 `<br>`을 넣는다.
- 문서 참조는 설명 문장을 마침표로 끝낸 뒤 괄호 안에 링크를 넣는다. 형식은 `~. ([문서명](경로))`이다.
- 참조 예시: `백엔드가 헤더로 보낸 식별자로 요청과 제품 데이터를 연결한다. ([5-5 식별과 전달](5-CONTRACT.md#5-5-식별과-전달))`
- 불필요한 접속사와 번역체를 줄이고 아첨과 과장은 쓰지 않는다. 비교가 필요하지 않으면 결론을 바로 쓴다.
- 표는 항목 대조에, 체크리스트는 누락이나 완료 여부 확인에 사용한다.
- 문장 길이와 불릿 수를 기계적으로 맞추지 않는다.
- 코드, 직접 인용과 고유명사는 원문을 유지한다. 표현 규칙을 적용하려고 실제 식별자나 외부 파일명을 바꾸지 않는다.

<br>

## 4. 파일명과 제목 번호

### 4-1 파일명
파일 이름은 영문 대문자로 쓰고 단어 사이는 하이픈으로 연결한다. 확장자는 `.md`로 유지하고 번호 앞에 `0`을 붙이지 않는다.
한 단계에 한 파일이면 단계 번호를, 여러 파일이면 단계 번호 뒤에 문서 번호를 붙인다. 같은 단계의 파일은 같은 폴더에 나란히 둔다.

```text
1-BACKGROUND.md
2-1-USER-STORY.md
2-2-OPERATION-REQUIREMENTS.md
5-CONTRACT.md
```

번호 없는 안내 문서는 `DECISIONS.md`, `CLAUDE.md`처럼 작성한다. 이 규칙은 소스 코드나 폴더 이름에는 적용하지 않는다.

<br>

### 4-2 소제목의 범위와 번호
소제목은 독립적인 큰 주제를 나눌 때만 사용한다. 작성 원칙처럼 같은 주제에 속하는 개별 규칙, 조건과 예시는 불릿이나 문단으로 묶는다.
문서 제목은 `#`, 소제목은 `###`로 작성한다. 문서 제목은 파일 번호 전체를 사용하고 소제목은 그 뒤에 순번을 붙인다. **제목 번호는 파일 번호를 포함해 숫자 세 묶음까지만 사용한다.** 그 아래 내용은 제목을 더 나누지 않고 불릿이나 문단으로 작성한다.

`2-1-USER-STORY.md`:

```markdown
# 2-1 유저 스토리

<br>

### 2-1-1 <소제목>
- <세부 항목>
- <세부 항목>

<br>

### 2-1-2 <소제목>
```

`2-2-OPERATION-REQUIREMENTS.md`:

```markdown
# 2-2 운영 요구사항

<br>

### 2-2-1 <소제목>
- <세부 항목>
- <세부 항목>

<br>

### 2-2-2 <소제목>
```

번호 없는 안내 문서의 본문도 `1`, `1-1`, `1-1-1`까지만 사용한다. 같은 상위 제목 아래에서는 순서대로 번호를 매긴다. 다른 문서를 참조할 때는 파일 경로와 소제목 번호를 적고 파일명이나 번호를 바꾸면 목차와 링크도 갱신한다.
