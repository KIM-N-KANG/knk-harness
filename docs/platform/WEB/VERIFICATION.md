# 웹 기반 검증

기준: [실행](EXECUTION.md).

<br>

### 검증 수단

| 범위 | 수단과 판정 |
|---|---|
| 순수 로직 | Vitest로 파싱, 상태와 기록 처리 확인 |
| 브라우저 흐름 | Pixel 5 전체 E2E, 설정의 iPhone 13 Mobile Safari. Safari 설정 통과를 iOS 실기기 통과로 표시하지 않음 |
| Safari 실기기 | 주소창과 도구 막대, 키보드, 안전 영역, CTA와 컴포저 및 마지막 메시지 가림, 이중 스크롤과 위치 튐 |
| 입력과 스트림 | IME Enter 오전송, 전송 뒤 포커스와 잠금, 토큰과 이미지 누적의 깜빡임 및 앵커 |
| 모션과 접근성 | 동작 줄이기, 전환 중 입력, 키보드와 포커스, 오류 연결과 상태 읽기 |
| 다크 모드 | 채팅방, 목록, 상세와 회원 마이 비주얼 회귀. 나머지 화면 수동 |
| 인앱 | 카카오톡, Instagram, Threads와 iOS 및 Android 실기기의 로그인 및 게스트 진입. 내린 목록을 위로 올릴 때 호스트 닫기와 위치 튐 없음 |
| 인증 팝업 | COOP 검증은 Chromium 범위, Mobile Safari와 동일하게 간주하지 않음 |
| 비주얼 | Linux 기준. macOS 결과를 같은 기준의 통과로 사용하지 않음 |
| SSR | E2E_SEO=1의 별도 모의 서버로 첫 HTML 검증. 기본 API_BASE_URL 빈 값에서 SSR 검증은 생략됨 |

API fixture의 정책값을 기대값으로 사용하고 홈 SSR과 브라우저 mock이 섞이지 않도록 API_BASE_URL 및 서버 재사용을 확인한다. 실제 환경에서는 서버 응답과 화면을 비교한다. Safari 뒤로가기는 URL과 목적지 DOM을 함께 확인한다.
