### 4-2 계약 테스트와 구조

단위 테스트는 Swift Testing, UI 테스트는 XCTest의 XCUITest로 작성한다. ([I-012](DECISIONS.md#i-012)) `MviStore` 계약은 `ManyakCommon`의 단위 테스트로 확인한다.

| 계약 | 절차 | 기대 결과 |
|---|---|---|
| 순서 보존 | 여러 작업에서 Event를 동시에 보냄 | 한 소비자가 도착 순서대로 reduce |
| 포화 시 유실 없음 | 소비 전에 Intent와 Event를 대량으로 연속 전송 | 모두 처리되고 버린 값 없음 |
| 재수집 시 효과 재생 없음 | 효과를 받은 뒤 수집을 끊고 다시 수집 | 이미 받은 효과가 다시 오지 않음 |
| reducer 단일 쓰기 | Store가 시작한 여러 작업이 동시에 결과 Event를 보냄 | 모든 결과가 reduce 순서대로 반영되고 덮어써 잃는 값 없음 |
| 꺼내기 전 수집 취소 | 수집 스트림에 효과가 남은 채 수집을 취소한 뒤 다시 수집 | 남은 효과를 순서대로 한 번 받고 이미 꺼낸 효과는 다시 오지 않음 |
| 수집 중단 동안 보관 | 수집을 취소한 뒤 효과를 내고 다시 수집 | 보관한 효과를 순서대로 한 번 받음 |

HTTP는 `URLProtocol` 대역으로 공통 헤더, 상태별 기본 변환, `URLError` 취소의 전파와 응답 request ID 보관을 확인한다. 서버 시각 해석은 소수 초가 있는 값과 없는 값을 모두 단위 테스트로 확인한다. 시간에 의존하는 동작은 `ManyakTesting`의 조작 가능한 시계로 확인한다.

모듈 변경은 `Package.swift`의 의존 선언이 [1-2 모듈과 허용 의존](1-COMPONENT-ARCHITECTURE.md#1-2-모듈과-허용-의존)과 같은지, 계층 폴더 규칙과 저장 식별자 호환을 리뷰로 확인한다. 기기 ID 주입 전 이벤트와 `setOnce`의 순서, 로그아웃 뒤 사용자 해제와 기기 ID 교체, `screen_name`과 행동 기록, 민감 정보 제외를 확인한다. Release의 Crashlytics 수집과 dSYM 기호화는 해당 빌드의 실제 보고로 확인한다.

자동화와 실제 기기 결과를 구분하며 신규 시나리오는 실행 완료 표시가 아니다. 시뮬레이터 결과를 실기기 통과로 표시하지 않는다. 실제 명령과 실행 결과는 구현 저장소와 PR 및 CI를 기준으로 한다.

### 4-3 PR 전 리뷰와 화면 검사

| 범위 | 수단과 판정 |
|---|---|
| 머지 조건 | PR CI의 swift-format 검사, SwiftLint, 단위 테스트와 시뮬레이터용 Debug 빌드 |
| 코드 리뷰 | 모든 새 PR 전에 수행. diff로 정확성, 보안과 개인정보, 디자인 토큰과 문구 위치, MVI와 라우트 규칙, 계층 폴더 규칙과 허용 의존, 동시성 격리, 테스트와 명세 동기화 점검<br>남은 문제는 PR 리뷰 참고에 기록. CI 판정과 머지 조건에 포함되지 않음 |
| 화면 검사 | UI를 바꾼 PR 전에 수행. Debug 빌드를 시뮬레이터에 설치하고 바뀐 화면의 캡처와 접근성 계층으로 라이트와 다크, 접근성 크기를 포함한 큰 글자, 이름 없는 조작 요소와 작은 터치 대상, 백그라운드 복귀 뒤 상태, 크래시 로그 확인. 공용 코드를 바꿨으면 홈, 스토리 상세, 채팅방, 제작 탭, 마이를 함께 확인<br>결과는 PR 화면 절에 기록. CI 판정과 머지 조건에 포함되지 않음 |
| UI 테스트 | XCUITest는 로컬에서 실행. CI에서 돌리지 않음 |

화면 검사는 시뮬레이터에 이미 로그인된 상태를 쓰며 앱 데이터를 지우거나 소셜 로그인을 하지 않는다. 로그아웃 상태라 회원 화면을 보지 못했거나 접근성 계층을 확인할 도구가 없었으면 확인하지 못한 범위로 기록한다. 바꾼 시뮬레이터 설정은 검사 뒤 되돌린다. 변경 전 화면과의 비교는 요청한 경우에만 별도 worktree의 기준 빌드로 수행한다.

### 4-4 에이전트 스킬

| 구분 | 구성 |
|---|---|
| 저장 위치 | 원본은 `.agents/skills/`, `.claude/skills/`에는 같은 이름의 심볼릭 링크. 서브에이전트 정의는 코드 리뷰와 화면 검사 두 개 |
| 하네스 공통 연결 | `create-branch`, `create-commit`, `create-pr`. iOS 저장소의 커밋 형식, 필수 검사 명령과 PR 전 리뷰만 더함 |
| 저장소 절차 | `merge-pr`, `pr-review`, `ui-review`. `ui-review`는 시뮬레이터 도구 기준으로 다시 작성 |
| 플랫폼 지식 | `feature-planning`, `release-ops`, `session-data-cleanup`은 iOS 도구에 맞춰 고쳐 씀. `compose-development`는 SwiftUI판으로, `room-migration`은 GRDB 마이그레이션 스킬로 새로 작성. `configuration-changes`는 비적용 |
| Xcode 제공 스킬 | 저장소에 커밋하지 않고 개인 환경에만 둠. 설치한 Xcode에서 `xcrun agent skills export`로 내보내며 Xcode 버전마다 목록이 바뀜 |

저장소 스킬은 개인 환경의 Xcode 제공 스킬이 없어도 끝까지 실행되게 작성한다. `ui-review`의 설치, 실행과 캡처는 `xcrun simctl`로 하고 Xcode 제공 스킬은 있으면 레이아웃과 접근성 계층 확인에 보조로 쓴다. ([I-016](DECISIONS.md#i-016))
