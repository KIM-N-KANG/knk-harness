### 4-2 구조와 관측

모듈 변경은 checkModuleArchitecture와 루트 check를 실행하고 허용 의존, PSI 참조, Hilt 생성, Manifest, 경로 직렬화와 저장 식별자 호환을 확인한다. PSI 검사는 import alias, 완전 수식 이름과 typealias를 포함하지만 reflection이나 완전한 의미 분석을 보장하지 않는다.

device ID 주입 전 이벤트와 setOnce의 순서, 설치 귀속 재시도와 완료 키, 로그아웃 후 귀속 재발화 방지, screen_name과 breadcrumb 및 민감 정보 제외를 확인한다. release의 Crashlytics 수집과 mapping은 해당 빌드 증거로 검증한다.

자동화와 실제 기기 결과를 구분하며 신규 시나리오는 실행 완료 표시가 아니다. 실제 명령과 실행 결과는 구현 저장소와 PR 및 CI를 기준으로 한다.

<br>

### 4-3 PR 전 리뷰와 화면 검사

| 범위 | 수단과 판정 |
|---|---|
| 머지 조건 | PR CI의 `./gradlew check`(모듈과 계층 검사, ktlint, detekt, Android lint, 단위 테스트)와 `./gradlew assembleDebug` |
| 코드 리뷰 | 모든 새 PR 전에 수행. diff로 정확성, 보안과 개인정보, 디자인 토큰과 문구 위치, MVI와 라우트 규칙, 구성 변경, 모듈 동기화, 테스트와 명세 동기화 점검<br>남은 문제는 PR 리뷰 참고에 기록. CI 판정과 머지 조건에 포함되지 않음 |
| 화면 검사 | UI를 바꾼 PR 전에 수행. debug 빌드를 에뮬레이터에 설치하고 바뀐 화면의 캡처와 레이아웃 트리로 라이트와 다크, 큰 글자, 회전 뒤 상태, 이름 없는 조작 요소와 작은 터치 대상, 크래시 로그 확인. 공용 코드를 바꿨으면 홈, 스토리 상세, 채팅방, 제작 탭, 마이를 함께 확인<br>결과는 PR 화면 절에 기록. CI 판정과 머지 조건에 포함되지 않음 |

화면 검사는 에뮬레이터에 이미 로그인된 상태를 쓰며 앱 데이터를 지우거나 소셜 로그인을 하지 않는다. 로그아웃 상태라 회원 화면을 보지 못했으면 확인하지 못한 범위로 기록한다. 바꾼 기기 설정은 검사 뒤 되돌린다. 변경 전 화면과의 비교는 요청한 경우에만 별도 worktree의 기준 빌드로 수행한다. ([A-097](DECISIONS.md#a-097))
