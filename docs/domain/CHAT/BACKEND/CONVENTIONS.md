# 구현 컨벤션

이 문서는 CHAT 도메인 코드를 작성하거나 수정할 때 반드시 지킬 규칙과 구현자가 선택할 수 있는 사항을 정한다.

트랜잭션과 잠금은 동시성에, 로그 이벤트 규칙은 관측에, 이름 토큰 치환과 후보 이름 구분은 처리 흐름에, 구현 위치는 AGENTS.md에 있다. ([동시성](CONCURRENCY.md), [구조화 로그 이벤트](OBSERVABILITY.md#구조화-로그-이벤트), [후보 이름 구분](PIPELINES.md#후보-이름-구분), [AGENTS.md](AGENTS.md))

<br>

### 이름과 용어

| 대상 | 규칙 |
|---|---|
| 패키지 | 채팅 패키지 아래에 API, 서비스, 저장, 모델, 전송 객체, AI 호출, 설정을 나눔<br>피드백은 별도 패키지 |
| 모델 이름 | 테이블의 단수형 |
| 전송 객체 | 요청은 `Request`, 응답은 `Response`, SSE 이벤트는 `Event`를 접미사로 사용<br>와이어 필드는 camelCase<br>AI 요청 필드는 snake_case, AI 완료 이벤트는 camelCase<br>DB 컬럼은 snake_case |
| AI 응답 역직렬화 | 알 수 없는 필드는 무시함<br>누락된 선택지 배열은 빈 배열로 처리 |
| 용어 | 용어집을 따름<br>턴 ID는 AI 응답 메시지의 PK |

<br>

### 계층 책임

| 계층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| API 계층 | 형식 검증, 요청자 식별, 상태 코드 지정, SSE 응답의 문자 집합 지정, 잔액 부족 예외의 거절 응답 변환 | 비즈니스 판정, 저장 계층 호출 |
| 서비스 | 처리 순서 관리, 소유권 판정, 과금과 환불, AI 요청 구성, 스트림 중계, 응답 직전 이름 토큰 치환 | HTTP 세부 규칙, 직렬화 |
| 턴 저장 | 저장 트랜잭션 경계 관리, 채팅 행 잠금, 판정 반영 | AI 호출, 과금 |
| 저장 계층 | 쿼리 실행<br>잠금이 필요한 조회 메서드는 이름에 잠금 여부 표시 | 비즈니스 판정 |
| 외부 호출 | 호출과 변환<br>AI 호출과 S3 호출은 DB 트랜잭션 밖에서 수행<br>객체 존재 확인만 저장 트랜잭션 안에서 수행 | 재시도 정책 결정 |

<br>

### 요청 검증과 오류

| 대상 | 규칙 |
|---|---|
| 개별 필드의 길이, 필수 여부, 허용값 | 요청 객체의 필드에 애너테이션으로 선언 |
| 선택 기록 필드 | 형식 검증을 선언하지 않음<br>잘못된 값은 기록만 건너뛰고 턴은 진행 |
| 모델 코드 | 허용값을 애너테이션에 두지 않음<br>서비스가 모델 표의 노출 중인 행으로 검증 |
| 스트림 시작 전 실패 | 일반 오류 응답<br>스트림 시작 후 실패는 `error` 이벤트 |
| AI 오류 | AI 서버가 보낸 코드와 메시지를 그대로 중계<br>백엔드 자체 실패는 고정된 코드와 문구 사용 |

<br>

### 비동기와 이벤트

| 대상 | 규칙 |
|---|---|
| 턴 작업 | 검증, 모델 판정, 과금, AI 요청 구성은 요청 스레드에서 동기로 완료<br>모델 표는 턴당 1회 읽고 차감 트랜잭션 안에서 다시 읽지 않음<br>AI 호출, 중계, 저장은 전용 실행기에서 수행 |
| 실행기 포화 | 작업 제출이나 첫 POST의 수신 연결이 거부되면 즉시 환불하고 스트림을 열지 않은 채 서버 오류로 응답 |
| 연결과 작업 수명 | SSE 완료와 연결 종료 콜백은 생성 작업을 취소하거나 환불하지 않음<br>생성 작업에는 연결과 독립된 생성 마감 적용 |
| 환불 판정 | 실행된 작업의 환불은 종료 시 저장 성공 여부로 한 번만 판정 |
| 이벤트 기록과 읽기 | 생성 작업은 클라이언트용 SSE 이벤트 전부를 Redis Streams에 기록<br>처음 연결과 재연결은 같은 스트림을 처음부터 읽음<br>블로킹 읽기는 공유 연결과 분리한 전용 Redis 연결 사용 |
| 피드백 전달 | 애플리케이션 이벤트로 발행하고 리스너가 커밋 후 비동기 발송<br>발송 실패는 WARN과 Sentry 메시지로 남김 |
| 대화 요약 | 이어쓰기 턴 저장이 커밋된 뒤 비동기로 요청<br>저장 트랜잭션 안에서 AI를 호출하지 않음<br>요약 응답을 기다리는 동안 턴 실행기와 다른 커밋 후 작업의 스레드를 점유하지 않음 |

<br>

### 테스트와 검증 도구

| 대상 | 규칙 |
|---|---|
| 작성 순서 | 동작을 바꾸는 작업은 실패하는 테스트를 먼저 작성 |
| 엔드포인트 변경 | 통합 테스트와 수동 호출 파일을 함께 갱신 |
| 동시성 | 잠금과 환불 규칙을 바꾸면 동시 요청 테스트로 검증 |

<br>

### 구현자가 선택할 수 있는 것

| 선택 가능 | 조건 |
|---|---|
| 서비스 내부의 메서드 분할과 이름 | 없음 |
| 테스트 픽스처와 스텁의 구성 | 없음 |
| 조회 쿼리의 작성 방식 | 없음 |
| 로그 필드 추가 | 사용자 입력과 AI 본문 원문을 넣지 않음 |
