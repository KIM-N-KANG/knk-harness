# 2. 요구사항

이 문서는 CHAT 도메인의 백엔드가 수행해야 하는 동작, 요구 주체, AI 서버와의 역할 분담, 제품 제약과 데이터 보존 기준을 정한다.

요청과 응답의 필드는 계약에, 처리 순서는 처리 흐름에, 대기 한도와 복구는 오류 처리에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도))

<br>

### 2-1 요구 주체

백엔드는 클라이언트와 AI 서버 사이에서 턴을 중계하고 기록한다. 각 주체의 역할과 백엔드에 기대하는 동작은 다음과 같다.

| 주체 | 하는 일 | 백엔드에 기대하는 것 |
|---|---|---|
| 클라이언트 | 입력을 보내고 스트림을 표시<br>본문의 이미지 마커 위치에 이미지를 표시<br>게스트가 만든 채팅의 식별자를 로컬에 보관 | 게스트와 회원이 같은 계약으로 호출할 수 있는 엔드포인트<br>응답 수신 중 토큰과 이미지를 순서대로 받음<br>완료 시점에 저장된 본문 전체와 턴 식별자<br>연결이 끊겨도 생성 중 상태와 완료 결과를 상세로 확인하고 생성 이벤트를 처음부터 다시 받을 수 있음 |
| AI 서버 | 본문 생성과 스트리밍, 사건과 엔딩 판정, 인물 이미지 선택, 실시간 이미지 생성, 선택지 생성<br>요청 사이에 상태를 남기지 않음 | 스토리 설정, 대화 내역, 진행 상태, 인물 이미지, 업로드 위치를 요청마다 빠짐없이 전달<br>판정 결과의 검증과 저장은 백엔드가 맡음 |
| 스토리 | 스토리 설정과 공개본, 시작 설정, 엔딩, 주요 사건, 인물 이미지 제공 | 채팅별 누적 턴 수와 회원의 엔딩 도달 집계 |
| 이프 | 지갑 차감과 환불 처리, 체험 한도 카운터와 정책값 관리 | 턴과 이미지 단위의 소모와 환불 요청 |
| 계정 | 회원 식별, 페르소나 관리, 게스트 이관 | 이관 시 채팅 소유권 이전과 도달 집계 보정 |

<br>

### 2-2 기능 요구사항

| 기능 | 백엔드가 보장하는 것 |
|---|---|
| 채팅 생성 | 읽을 수 있는 스토리에서만 시작<br>시작 설정을 고르지 않으면 첫 시작 설정으로 시작<br>프롤로그와 추천 입력을 플레이 이름으로 치환해 제공<br>회원은 페르소나를 골라 시작하고 이후 원본 페르소나를 바꿔도 채팅에는 반영하지 않음 |
| 이어쓰기 | 사용자 입력과 AI 응답을 한 턴으로 저장하고 완료 이벤트로 저장된 본문 전체를 전달<br>턴 저장 전에 끝난 요청은 과금하지 않음<br>저장이 끝난 뒤의 전달 실패는 성공으로 정산<br>AI 서버가 응답하지 않거나 오류를 반환하면 스트림 안에서 실패를 알림<br>연결 종료와 무관하게 생성을 계속하고 저장된 턴은 과금<br>같은 채팅의 이어쓰기와 재생성은 하나만 실행하고 생성 중 추가 요청은 거절<br>클라이언트가 보낸 마지막 턴이 서버와 다르면 거절 |
| 재생성 | 마지막 턴만 대상<br>클라이언트가 본 턴이 마지막 턴이 아니면 거절<br>엔딩에 도달한 채팅은 거절<br>이전 응답과 선택지는 이력으로 보존하고 활성본만 교체<br>턴 수와 사용자 입력은 변하지 않음 |
| 선택지 | 마지막 턴의 본문을 기준으로 선택지를 생성해 저장<br>이미 선택지가 있으면 다시 생성하지 않고 저장된 값을 반환<br>무료이며 체험 한도도 소모하지 않음 |
| 이어받기 | 생성 중 상태를 상세에서 제공<br>처음 연결과 재연결 모두 같은 생성의 이벤트를 처음부터 제공하고 이후 이벤트를 이어서 전달<br>재연결로 생성과 과금을 반복하지 않음 |
| 선택 기록 | 사용자가 고른 선택지와 수정 여부를 기록<br>기록 조건이 맞지 않아도 턴 진행을 막지 않음 |
| 진행 상태 | 목표 사건, 거쳐온 사건, 도달 엔딩을 채팅 단위로 보관하고 매 턴 AI에 다시 전달<br>최소 턴 수를 채운 엔딩만 후보로 전달<br>엔딩 도달은 채팅당 최초 1회만 인정하고 도달 뒤에도 이어쓰기는 허용 |
| 엔딩 도달 집계 | 회원의 도달을 사용자와 스토리 단위로 집계<br>같은 엔딩에 다시 도달해도 한 번으로 집계<br>동시 도달의 중복 기록이 턴 저장을 되돌리지 않음 |
| 인물 이미지 | 스토리에 저장된 인물 이미지를 AI에 전달하고 AI가 고른 이미지를 실시간으로 중계<br>저장된 본문의 이미지 마커를 바꾸지 않음 |
| 실시간 이미지 | 턴당 업로드 위치 1개를 발급<br>발급한 위치에 실제로 업로드된 이미지만 기록하고 그 외 실시간 URL은 본문에서 제거<br>이미지 처리에 실패해도 턴은 실패로 처리하지 않음 |
| 과금과 한도 | 회원은 턴마다 이프를 선차감하고 게스트는 체험 횟수를 예약<br>이미지는 턴과 별개의 체험 횟수와 비용을 적용<br>잔액 부족과 한도 소진은 스트림을 열기 전에 거절<br>환불은 차감 건마다 정확히 1회 |
| 목록 | 클라이언트가 보관한 식별자 목록으로 카드를 조회<br>최근 활동순으로 정렬<br>열람할 수 없는 채팅은 오류 없이 제외<br>카드에는 마지막 AI 응답 전문, 턴 수, 도달 엔딩 이름, 스토리 표지 포함 |
| 상세 | 프롤로그, 턴 목록, 선택지, 도달 엔딩과 생성 중 상태를 제공<br>턴이 없을 때만 추천 입력을 제공<br>스토리를 읽을 수 없게 되면 제목, 프롤로그, 추천 입력은 마지막 공개본에서 가져옴 |
| 삭제 | 소유자만 삭제<br>삭제 후 목록, 상세, 공유에서 제외<br>이미 삭제된 채팅은 없는 것으로 응답 |
| 공유 | 소유자가 발급하며 발급 시점의 턴 수를 고정<br>같은 시점에 재발급하면 같은 링크 반환<br>링크를 가진 누구나 로그인 없이 열람<br>원본이 진행돼도 열람 내용은 변하지 않음<br>공유 범위에 포함된 턴의 재생성 결과는 반영<br>해지 수단은 채팅 삭제 |
| 피드백 | 본문만으로 접수<br>저장 후 운영 채널 전달<br>전달 실패가 접수 결과를 바꾸지 않음 |

<br>

### 2-3 AI 서버와의 역할 분담

| 판단과 작업 | 담당 |
|---|---|
| 입력 길이와 입력 출처 값 검증 | 백엔드 |
| 사용자 입력의 프롬프트 인젝션 등 AI 입력 검증 | AI 서버 |
| 본문 생성, 인물 이미지 선택, 실시간 이미지 생성, 선택지 생성 | AI 서버 |
| 주요 사건 관련성, 완결, 진행 턴 수 판정 | AI 서버 |
| 엔딩 달성 조건 판정 | AI 서버<br>자연어 조건의 정성 판정 |
| 엔딩 최소 턴 수 판정 | 백엔드<br>충족한 엔딩만 후보로 전달하고 저장 시 재확인 |
| 후보 이름의 유일성 | 백엔드<br>치환 뒤 같은 이름이 생기면 구분 표시를 붙여 전달하고 저장할 때는 원문 이름 사용 |
| 판정 결과의 저장과 되돌려 전달 | 백엔드<br>AI에 보낸 후보에 없는 이름은 무시 |
| 실시간 이미지의 저장 위치 발급과 결과 검증 | 백엔드 |
| 이름 토큰을 플레이 이름으로 치환 | 백엔드<br>AI 요청과 응답에서만 치환하고 저장된 원문은 유지 |

<br>

### 2-4 제품 제약

**1. 입력**

| 항목 | 상한 |
|---|---|
| 사용자 입력 | 3,000자, 공백만 있는 입력 불가 |
| 입력 출처 | `choice`, `edited_choice`, `typed` |
| 피드백 본문 | 2,000자 |
| 피드백 이메일 | 320자, 이메일 형식 |
| 피드백 앱 버전 | 50자 |

<br>

**2. 조회와 한도**

| 항목 | 값 |
|---|---|
| 일괄 조회 | 100개 |
| 내 채팅 목록 | 최대 100개 |
| 실시간 이미지 | 턴당 1장 |
| 게스트 체험 | 턴 5회, 이미지 5회<br>모든 채팅 합산, 재생성 포함 |
| 회원 체험 | 게스트와 같은 횟수를 회원 단위로 적용 |
| 엔딩 도달 | 채팅당 1회 |

<br>

### 2-5 데이터 보존

| 대상 | 요구사항 |
|---|---|
| 채팅과 메시지 | 삭제해도 기록을 보존하고 조회에서만 제외 |
| 재생성 이전 응답 | 버전 이력으로 보존 |
| 실시간 이미지 객체 | 채팅 삭제 뒤에도 보존 |
| 공유 | 원본 채팅이 삭제되면 열람 불가<br>공유 자체는 삭제하지 않음 |
| 엔딩 도달 집계 | 제작자가 엔딩을 수정해도 회원의 도달 기록 유지 |
| 프롤로그와 도달 엔딩 이름 | 원본 시작 설정이나 엔딩이 삭제돼도 채팅에 보관한 값으로 표시<br>프롤로그는 스토리를 읽을 수 없을 때만 |
| 피드백 | 보존 |
