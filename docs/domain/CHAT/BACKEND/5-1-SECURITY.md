# 5-1 보안

이 문서는 CHAT 도메인 백엔드의 인증과 권한 판정, 입력과 이미지 검증, 식별자와 개인정보 취급 규칙, 수용한 한계를 정한다.

경로별 허용 규칙과 실패 응답은 계약에, 로그와 지표에 싣지 않는 데이터는 관측에 있다. ([4-2-1 공통 규칙과 헤더](4-2-CONTRACT.md#4-2-1-공통-규칙과-헤더), [5-4-10 수집 조건과 실패 처리](5-4-OBSERVABILITY.md#5-4-10-수집-조건과-실패-처리))

<br>

### 5-1-1 인증 수준

| 항목 | 처리 |
|---|---|
| 인증 선택 경로 | 모든 경로<br>유효한 토큰이 있으면 회원으로 처리<br>토큰이 없거나 무효이면 익명으로 처리 |
| 공유 열람 | 회원 정보는 스토리 읽기 권한 판정에만 사용<br>채팅 소유권은 판정하지 않음 |

<br>

### 5-1-2 소유권 판정

| 판정 | 규칙 |
|---|---|
| 판정 순서 | 채팅 존재 여부를 먼저 확인한 뒤 소유권 판정 |
| 존재 확인 실패 | 채팅 없음, 삭제, 식별자 형식 오류를 같은 응답으로 처리 |
| 소유권 위반 | 회원 소유 채팅에 타인이나 익명이 접근하면 거절<br>토큰을 빼고 익명으로 위장해 소유 채팅을 무료로 이어쓰는 경로를 막음<br>모델 등급 변경도 같은 판정을 거쳐 타인이 가격을 바꿀 수 없음 |
| 소유자 없는 채팅 | 익명 요청만 허용<br>회원과 게스트 사이의 교차 접근은 양방향으로 거절 |
| 채팅 생성 | 스토리 읽기 판정을 통과해야 함<br>소유자 없는 스토리에는 회원이 시작할 수 없음 |
| 생성 스트림 재연결 | 상세와 같은 인증, 동의 게이트, 소유권 검사 적용<br>채팅 접근 판정 후 그 채팅에 속한 생성 스트림만 조회<br>생성 ID만으로 타인의 이벤트에 접근할 수 없음 |
| 일괄 조회 | 열람할 수 없는 항목은 존재를 드러내지 않고 제외 |
| 공유 | 채팅 소유자만 발급하고 토큰 보유자만 열람<br>채팅 식별자로는 열람할 수 없음 |
| 스토리 데이터 | 채팅 소유자가 스토리를 읽을 수 없으면 현재 값 대신 마지막 공개본<br>비공개로 전환한 뒤 수정한 내용이 AI 요청, 상세, 목록, 공유에 노출되지 않음 |

<br>

### 5-1-3 계정 상태와 동의

| 상태 | 처리 |
|---|---|
| 정지 계정 | 채팅 생성, 이어쓰기, 재생성, 선택지 생성, 모델 등급 변경은 처리 시작 시 거절<br>정지 사유는 노출하지 않음 |
| 탈퇴 계정 | 유효한 토큰이 남아 있어도 인증 단계에서 거절 |
| 게스트 | 계정 상태 판정의 대상 아님 |
| 미동의 회원 | 동의 게이트가 켜진 환경에서 현행 필수 동의가 없으면 거절 |

<br>

### 5-1-4 입력 검증

| 대상 | 규칙 |
|---|---|
| 길이, 필수, 허용값 | 요청 객체에 선언한 제약으로 검증하고 위반 시 거절 |
| 입력 출처 | 허용값 밖이면 거절<br>정의되지 않은 값이 AI 프롬프트에 포함되지 않게 함 |
| 모델 등급 코드 | 등급 표의 노출 중인 행과 정확히 일치할 때만 저장<br>AI에는 등급 표에 있는 코드만 전달하고 클라이언트 입력을 그대로 넘기지 않음 |
| 선택 기록 | 형식 검증 없음<br>기록 조건이 맞지 않으면 기록만 생략 |
| 시작 설정, 페르소나 | 시작 설정은 해당 스토리, 페르소나는 해당 회원에 속하는지 확인하고 아니면 없는 것으로 처리 |
| AI 판정 결과 | 신뢰 경계 밖의 값<br>AI에 보낸 후보 목록에 없는 이름은 무시<br>엔딩의 최소 턴 수를 저장 시 재확인<br>진행 턴 수는 0 이상으로 보정 |
| AI 본문 | 그대로 저장<br>실시간 이미지 URL만 검증 |

<br>

### 5-1-5 실시간 이미지 검증

| 대상 | 규칙 |
|---|---|
| 객체 키 | 서버가 채팅 공개 ID와 턴 번호, UUID로 발급<br>AI와 클라이언트가 정하지 않음 |
| 서명 | PUT 전용, 10분 뒤 만료 |
| 마커 검증 | 실시간 경로의 URL은 이 턴에 발급한 URL과 정확히 일치해야 함<br>일치하면 객체 존재를 HEAD로 확인<br>발급하지 않은 URL이나 객체가 없는 URL은 본문과 이미지 목록에서 제거 |
| HEAD 범위 | 발급한 키만 확인<br>임의 URL은 요청하지 않음 |
| 인물 이미지 URL | 백엔드가 보낸 값이라 검증 없이 통과 |

<br>

### 5-1-6 식별자와 개인정보

| 대상 | 규칙 |
|---|---|
| 외부 식별자 | 채팅과 공유는 무작위 UUID<br>자동 증가 PK는 응답에 싣지 않음<br>로그는 환불 실패와 선택 기록 생략의 채팅 PK, 분석 이벤트는 `ending_id`만 예외 |
| 턴 ID | 메시지 PK를 그대로 노출<br>채팅 소유권 검사 안에서만 의미가 있어 열거로 타인의 턴에 접근할 수 없음 |
| 공유 토큰 | 토큰을 보유하면 접근 가능<br>분석 이벤트에 싣지 않음<br>열람 응답에 원본 채팅 식별자를 싣지 않음 |
| 디바이스 ID | 원문은 저장하지 않음<br>해시로 바꿔 MDC와 체험 카운터 키에 쓰고 AI 서버에는 해시만 전달 |
| 회원 식별자 | AI 서버에는 공개 UUID만 전달<br>내부 PK와 디바이스 식별자는 AI 요청의 `user_id`에 쓰지 않음 |
| 페르소나 | 응답에는 이름만 포함<br>설명과 원본 페르소나 ID는 싣지 않음 |
| 피드백 | 이메일과 User-Agent는 저장하되 로그에는 길이와 유무만 기록 |

<br>

### 5-1-7 수용한 한계

| 한계 | 수용 이유 |
|---|---|
| 게스트끼리 채팅 UUID를 알면 다른 게스트의 채팅을 읽거나 이어쓰거나 삭제할 수 있음 | 콘텐츠에 디바이스 식별자를 저장하면 개인정보 취급 범위를 벗어남<br>차단할 수 있는 회원과 게스트 간 교차 접근만 양방향으로 막음 |
| 디바이스 헤더를 바꾸거나 기기를 바꿔 체험 한도를 우회할 수 있음 | 디바이스 식별자 외에 게스트를 구분할 수단이 없음<br>우회 징후는 호출량과 카운터 키의 증가 추이로 확인 |
| 피드백에 요청량 제한이 없음 | 현재 등록량에서는 요청량 제한의 이점이 운영 비용보다 작음<br>등록량 급증은 관측으로 추적 |
| 요청 시작 전에 끝난 재생성을 선택 기록이 구분하지 못함 | 정확한 판정에는 클라이언트가 본 선택지 세대 식별자가 필요해 와이어 계약이 바뀜 |
| 이탈 중 이어쓰기 실패로 입력이 사라진 것처럼 보임 | 생성 중 키가 사라지고 새 턴도 남지 않음<br>차감은 환불<br>실패 이력을 상세에 보관하지 않음 |
| 이탈 중 재생성 결과를 상세만으로 구분하지 못함 | 재생성은 턴 ID와 턴 수 유지<br>1단계는 성공과 실패 구분 불가<br>2단계는 클라이언트가 생성 ID를 받아 보관한 경우(`started` 또는 생성 중 상세에서 수신)에만 보관된 스트림의 `completed` 또는 `error`로 재생성의 성공과 실패를 구분한다.<br>`started` 전에 이탈하고 생성이 끝난 뒤 돌아와 생성 ID를 모르면 1단계와 같은 한계가 남는다. |
| 장시간 저장 중 스트림이 먼저 만료되면 재생할 이벤트가 없음 | 생성 시 TTL 150초를 연장하지 않음<br>수신 연결 종료 후 상세 재조회로 복구<br>턴과 과금은 DB의 저장 결과가 기준 |
| 공유 토큰이 요청 로그와 Sentry의 경로 필드에 남음 | 경로 마스킹이 없음<br>로그 저장소의 접근 권한으로 통제 |
| 게스트가 발급한 공유는 기기 저장소를 잃으면 해지할 수 없음 | 해지 기능 자체가 없어 실질적인 차이가 없음 |
