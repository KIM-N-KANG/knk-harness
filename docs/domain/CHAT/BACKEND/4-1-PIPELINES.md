# 4-1 처리 흐름

이 문서는 CHAT 도메인의 요청 수신부터 응답까지의 처리 단계를 정한다.

요청 필드, 응답 필드와 실패 응답은 계약에, 대기 한도와 복구 규칙은 오류 처리에, 멱등, 잠금, 생성 중 키의 해제 순서는 동시성에, 수신 연결 상한과 이벤트 보관 기간은 배포에 있다. ([4-2 계약](4-2-CONTRACT.md), [5-3 오류 처리](5-3-ERROR-HANDLING.md), [5-2 동시성](5-2-CONCURRENCY.md), [6-3 환경 변수와 시크릿](6-DEPLOYMENT.md#6-3-환경-변수와-시크릿))

<br>

### 4-1-1 공통 처리

모든 요청은 상관관계 필터에서 요청 ID를 받는다. 이어서 보안 필터가 인증 수준을 판정한다. 검사를 마친 요청을 API 계층으로 전달한다.

채팅을 식별자로 찾을 때 식별자 형식이 잘못됐거나 채팅이 없거나 삭제됐으면 같은 결과로 처리한다. 존재를 확인한 뒤 소유권을 판정한다. 회원 소유 채팅은 그 회원만, 소유자 없는 채팅은 익명 요청만 통과한다.

응답과 AI 요청에 포함할 스토리 데이터는 요청자가 스토리를 읽을 수 있으면 현재 값을 쓴다. 턴 요청의 요청자는 채팅 소유자이고 공유 열람의 요청자는 열람자다. 읽을 수 없으면 그 스토리의 마지막 공개본을 쓴다. 두 경우 모두 같은 형식으로 변환해 동일한 방식으로 응답과 AI 요청을 구성한다. 이름 토큰은 플레이 이름으로 치환한다.

흐름도에서 AI 서버나 외부 저장소를 호출하는 단계는 주황색이다.

<br>

**AI 호출**

턴 본문은 SSE로 받고 선택지는 동기 HTTP로 받는다. 대화 요약은 턴 저장 커밋 후 비동기로 요청한다. 백엔드는 재시도하지 않는다. 요청 필드 이름은 snake_case이고 완료 이벤트의 필드 이름은 camelCase다. 스텁 설정이 켜진 환경에서는 AI를 호출하지 않고 정해진 더미 응답을 반환한다.

| 요청 | 방식 | 성공 | 실패 |
|---|---|---|---|
| 턴 | `POST /api/v1/chat/turns` | 200, SSE<br>`token`, `character_image`, `ping`, `completed` | 4xx, 5xx, SSE `error`, 시간 초과 |
| 선택지 | `POST /api/v1/chat/choices` | 200, JSON<br>선택지 3개 | 4xx, 5xx, 시간 초과 |
| 대화 요약 | `POST /api/v1/chat/compact` | 200, JSON<br>갱신된 `summary` | 4xx, 5xx, 시간 초과 |

요청 헤더는 값이 없으면 생략한다.

| 요청 헤더 | 값 | 턴 | 선택지 | 요약 |
|---|---|---|---|---|
| `X-Manyak-Request-Id`, `X-Manyak-Session-Id` | 클라이언트 요청 헤더를 전달<br>`unknown`이면 생략<br>요약은 요약을 일으킨 이어쓰기 요청의 값 | 보냄 | 보냄 | 보냄 |
| `X-Manyak-Device-Id-Hash` | `X-Manyak-Device-Id`의 해시 | 보냄 | 보냄 | 보냄 |
| `X-Manyak-Creation-Id` | 채팅에 저장한 간편 제작의 스토리라인 생성 요청 ID<br>일반 제작 스토리는 생략 | 보냄 | 보냄 | 보냄 |
| `X-Manyak-Story-Id` | 스토리 공개 ID | 보냄 | 보냄 | 보냄 |
| `X-Manyak-Chat-Id` | 채팅 공개 ID | 보냄 | 보냄 | 보냄 |
| `X-Manyak-Start-Setting-Id` | 시작 설정 공개 ID<br>참조가 끊겼으면 생략 | 보냄 | 보냄 | 보냄 |
| `X-Manyak-Turn-Number` | 이어쓰기는 `current_turn + 1`의 예측치<br>재생성과 선택지는 `current_turn`<br>요약은 이번 요약 범위의 끝 턴 | 보냄 | 보냄 | 보냄 |
| `X-Manyak-Is-Regenerated` | 재생성이면 `true`, 그 외 `false` | 보냄 | 보냄 | 생략 |
| `traceparent` | 추적이 켜진 환경의 현재 스팬 | 보냄 | 보냄 | 보냄 |

응답의 `meta`는 AI 호출 기록에 적재한다. 턴은 완료 이벤트의 camelCase 필드, 선택지는 응답 본문의 snake_case 필드다. 대화 요약 응답에는 `meta`가 없다.

| `meta` 필드명 | 타입 | 처리 |
|---|---|---|
| `model`, `provider` | `string` | 실제 모델과 공급자<br>스텁 환경은 둘 다 `stub` |
| `promptVersions` | `map<string, integer>` | 템플릿별 버전 |
| `inputTokenCount`, `outputTokenCount` | `integer / null` | 이미지 호출을 제외한 토큰 합계 |
| `retryCount` | `integer` | AI 내부 보완 호출 횟수 |

```mermaid
    D --> E["`**채팅 저장**

```

- 게스트가 페르소나를 지정하면 스토리를 조회하기 전에 거절한다.
- 모델은 요청에서 받지 않는다. 모델 표의 기본 모델 코드를 명시해 저장하고 컬럼의 DB 기본값에 맡기지 않는다. 기본 모델 행이 없으면 서버 오류로 응답한다.
- 출력 분량도 요청에서 받지 않는다. 새 채팅은 짧은 응답(`false`)으로 저장한다.
- 소유자 없는 스토리에는 회원이 채팅을 시작할 수 없다.
- 지정한 시작 설정이 이 스토리에 속하지 않으면 거절한다. 임의로 첫 시작 설정으로 바꾸지 않는다.
- 시작 설정이 없는 스토리는 프롤로그와 추천 입력이 빈 값이다.
- 스토리가 간편 제작으로 만들어졌으면 그 스토리라인 생성 요청 ID를 채팅에 저장한다. 이후 턴마다 AI 호출 헤더로 보낸다.
- 페르소나 이름과 설명은 같은 시점에 함께 복사한다. 이후 원본이 바뀌어도 채팅에는 반영하지 않는다.

### 4-1-3 일괄 조회

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 40}}}%%
flowchart LR
    A["`**식별자 정리**

미삭제, 열람 가능만`"]
    B --> C["`**카드 데이터 조회**
스토리, 마지막 AI 응답, 엔딩 이름, 공개본`"]
    C --> D["`**정렬과 응답**

    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D
    class A,B,C,D comp
```

- 유효한 식별자가 없으면 DB를 조회하지 않고 빈 배열을 반환한다.
- 열람할 수 없는 채팅은 오류 없이 제외한다.
- 갱신 시각이 같으면 내부 ID 내림차순으로 정렬한다.
- 스토리 제목, 표지, 도달 엔딩 이름은 요청자가 스토리를 읽을 수 있으면 현재 값, 아니면 마지막 공개본이다. 공개본은 읽을 수 없는 스토리에 대해서만 조회한다.
- 마지막 AI 응답은 채팅당 최신 1건을 한 번의 쿼리로 가져온다.
- 도달 엔딩 이름은 현재 행이나 공개본에서 찾는다. 참조가 끊겼으면 채팅에 보관한 이름을 쓴다.
- 전체 조회를 하나의 `REPEATABLE_READ` 읽기 전용 트랜잭션에서 수행한다.

- 턴은 사용자 입력 직후의 AI 응답을 짝지어 만든다. 짝이 없는 사용자 입력과 시스템 메시지는 제외한다.
- 추천 입력은 턴이 없을 때만 채운다. 턴이 있으면 빈 배열이다.
- 스토리를 읽을 수 없으면 제목, 프롤로그, 추천 입력을 마지막 공개본에서 가져온다. 시작 설정 참조가 끊겼으면 프롤로그는 채팅에 보관한 값이고 추천 입력은 빈 배열이다.
- 턴의 도달 엔딩 이름은 현재 행이나 공개본에서 찾는다. 참조가 끊겼으면 메시지에 보관한 이름을 쓴다.
- 응답의 모델은 유효 모델이다. 보관한 모델이 노출 중이면 그 코드, 아니면 기본 모델 코드를 싣는다. 조회는 채팅 행을 고치지 않는다.
- 조회는 `REPEATABLE_READ` 읽기 전용 트랜잭션에서 수행한다.

- 요청 접수 시각을 기록한다. 생성 마감과 선택 기록의 세대 판정 기준이다.
- 검증과 AI 요청 구성은 요청 스레드에서 동기로 완료한다. AI 요청을 구성할 때는 짧은 `REPEATABLE_READ` 읽기 전용 트랜잭션에서 스토리와 하위 데이터를 하나의 스냅샷으로 읽는다. 커밋 후 AI를 호출한다.
- 청구 모델은 턴마다 한 번 정한다. 게스트 턴은 채팅에 보관한 모델과 무관하게 라이트(`LITE`)이다. 회원 턴은 요청 시점에 읽은 유효 모델이다. 모델 표는 이때 한 번 읽고 그 시각 기준의 적용 가격을 차감과 환불에 쓴다. 턴이 진행되는 동안 채팅의 모델, 모델 표, 프로모션 기간이 바뀌어도 이 턴에는 반영하지 않는다.
- 출력 분량은 생성 중 키를 획득한 뒤 채팅을 읽는 시점의 값을 쓴다. 청구 모델을 확정하는 시점과 같다. 게스트 턴과 회원의 체험 턴도 채팅에 보관한 값을 그대로 쓴다. 턴이 진행되는 동안 채팅의 출력 분량이 바뀌어도 이 턴에는 반영하지 않는다.
- 회원 턴의 가격은 적용 가격이다. 적용 가격이 0이면 턴 체험을 예약하지 않고 턴 차감 항목도 만들지 않는다. 적용 가격이 0보다 크고 청구 모델이 라이트(`LITE`)이며 턴 체험 잔여가 있으면 체험으로 처리한다. 체험 잔여가 없거나 청구 모델이 라이트가 아니면 턴 체험을 예약하지 않고 적용 가격을 선차감한다. 턴 차감 항목과 그 환불의 참조 종류는 `CHAT_TURN`이다. 이 참조 종류가 저장 시 연결을 기록하는 코드가 만든 차감이라는 표시이고 선차감 대사가 행 단위 판정의 대상을 고르는 기준이다. 이미지는 별도 체험 잔여를 먼저 쓴다. 이미지 체험 잔여가 없으면 이미지 비용을 더한다. 유료 항목은 한 트랜잭션에서 지갑을 한 번 잠그고 합계로 잔액을 판정한 뒤 항목별 원장 행을 만든다. 부족하면 요청 전체를 거절하고 예약한 체험을 복원한다.
- 게스트는 디바이스 헤더가 필수다. 턴 체험이 소진되면 거절한다. 이미지 체험이 소진되면 업로드 위치 발급만 생략하고 턴은 진행한다.
- 이미지 업로드 위치는 과금이 끝난 뒤 발급한다. 발급에 실패하면 업로드 위치 없이 진행하고 이미지 체험을 복원한다.
- 백그라운드 작업 제출이나 수신 연결 열기가 거부되면 즉시 환불과 복원을 하고 스트림을 열지 않은 채 서버 오류로 응답한다.
- 백그라운드 작업은 `started`를 기록한 뒤 AI 스트림을 소비한다. 클라이언트용 이벤트 전부를 생성 순서대로 Redis Streams에 기록한다. 토큰과 인물 이미지 이벤트의 본문은 가공하지 않는다. AI의 `ping`은 클라이언트용 이벤트가 아니므로 기록하지 않는다.
- 완료 결과의 선택지는 항상 비운다. 선택지는 별도 요청으로 생성한다.
- 이미지 검증과 턴 저장은 같은 트랜잭션에서 수행한다. 검증에 실패하면 이미지 비용만 환불하고 턴은 저장한다.
- 저장이 확정되면 과금을 확정한다. 이후 `completed` 전송이 실패하거나 연결이 끊겨도 환불하지 않는다.
- 저장 전에 어떤 이유로든 백그라운드 작업이 끝나면 턴과 이미지의 차감을 환불하고 체험을 복원한다. 판정은 백그라운드 작업 종료 시 한 번만 한다.
- 연결이 끊겨도 큐 대기와 실행 중인 생성을 유지한다. 생성 마감이 저장 진입보다 먼저면 실패로 끝내고 환불한다. 늦은 AI 결과는 저장하지 않는다. 저장에 먼저 진입했다면 마감이 지나도 저장을 끝까지 마친다.

`realtimeImage`에 따라 다음이 달라진다.

|---|---|---|

- 동기 검증 순서는 정지 계정, 채팅 존재, 소유, 엔딩 도달 여부, 턴 존재, `turnId` 일치, 생성 중 키 선점, 시작 상태 재확인, 과금이다. 실패가 확정된 요청에는 선차감과 환불을 수행하지 않는다.

- 대상 턴이 요약 범위에 들어 있었으면 같은 저장에서 요약을 비운다. 그 범위는 다음 요약 경계에서 다시 요약한다.

- 마지막 턴 검증을 멱등 검사보다 먼저 한다. 다른 채팅의 턴이나 마지막이 아닌 턴에 대한 선택지 요청이 성공하지 않도록 한다.
- 요청 본문은 턴 요청과 같은 데이터에 저장된 AI 응답을 `ai_output`으로 더한 것이다. `history`는 이번 턴을 제외해 같은 장면이 두 번 실리지 않게 한다.
- `summary`와 `history`는 재생성과 같은 기준으로 정한다. 대상 턴이 요약 범위에 들면 요약 없이 원문으로 보낸다. 선택지 생성은 저장된 요약을 바꾸지 않는다.
- 비용을 부과하거나 체험 한도를 소모하지 않는다. 이어쓰기와 재생성의 생성 중 키를 사용하지 않는다.
- 저장 시 마지막 턴이 바뀌었거나 본문이 재생성으로 달라졌으면 결과를 폐기하고 충돌로 응답한다. 그 사이 다른 요청이 선택지를 채웠으면 저장된 값을 반환한다.
- AI 호출 기록의 턴 번호는 저장 시 확정된 값으로 기록해 턴 본문 기록과 조인할 수 있게 한다.
- AI 호출 실패는 AI 실패로 응답한다. 본문과 판정은 이미 저장돼 있어 영향이 없다.

### 4-1-12 턴 저장과 판정 반영

- 이어쓰기와 재생성은 같은 채팅 행 잠금을 쓴다. 두 경로의 저장이 채팅 단위로 직렬화된다. 잠금 안에서 생성 시작 시점의 마지막 턴과 교체 상태를 재확인하고 다르면 결과를 폐기한다.
- 유료 턴은 채팅 행 잠금 다음에 이 턴의 `CHAT_TURN` 차감 행을 잠그고 그 행의 환불(`refund:charge:{차감 행 ID}`)이 없는지 확인한다. 환불이 이미 있으면 선차감 대사가 먼저 돌려준 것이므로 결과를 폐기하고 `AI_STREAM_FAILED`로 끝낸다. 종료 시 환불 시도는 같은 멱등 키라 중복 기록되지 않는다. 체험 턴과 게스트 턴은 이 단계가 없다.
- 저장하는 AI 응답 메시지에 차감 행 ID를 기록한다. 체험 턴과 게스트 턴은 `NULL`이다. 선차감 대사는 이 연결로 저장된 턴의 차감을 식별한다.
- 판정 후보는 AI에 실제로 보낸 목록이다. 목록에 없는 이름은 무시한다. 현재 행은 FK 값을 얻을 때만 이름으로 다시 찾는다.
- 이미 엔딩에 도달한 채팅이면 도달 엔딩 판정을 무시한다. 후보의 최소 턴 수가 이번 턴 번호보다 크면 무시한다. 현재 행이 없으면 ID 없이 이름만 기록한다.
- 선택 기록은 새 메시지를 넣기 전에 한다. `sourceTurnId`가 현재 마지막 턴을 가리키고 `choiceOrder`가 그 턴의 선택지에 있으며 그 선택지가 요청 진입 시각 이전에 만들어졌을 때만 기록한다. 조건이 맞지 않으면 건너뛰고 `sourceTurnId`를 보낸 요청만 사유를 WARN으로 남긴다. 수정 여부는 선택지 원문과 입력에 NFC 정규화, 앞뒤 공백 제거, 내부 공백 축약을 적용한 뒤 비교해 정한다. 구두점은 보존한다.
- 거쳐온 사건은 이름 스냅샷에 먼저 추가한다. 현재 행이 있으면 조인 행도 만든다. 목표 사건은 현재 행이 있을 때만 FK로 저장하고 없으면 해제한다.
- 도달하면 채팅에 엔딩 ID와 이름을 기록하고 상태를 `ENDED`로 바꾼다. 회원이면 도달 집계를 독립 트랜잭션에서 기록한다. 유니크 위반은 이미 기록된 것으로 보고 무시한다.
- AI 응답 행에는 그 턴의 청구 모델 코드를 `model_code`로 함께 저장한다. 게스트 턴은 채팅에 보관한 모델과 무관하게 `LITE`다. 채팅의 현재 모델이 아니라 이 턴을 실제로 생성한 등급이다.
- 재생성으로 교체할 때는 같은 잠금 안에서 마지막 턴을 재확인한 뒤 이전 응답과 선택지를 버전 이력으로 보관한다. 이전 활성본의 차감 행 ID도 버전 행으로 옮기고 메시지 행에는 이번 재생성의 차감 행 ID를 기록한다. 기존 선택지를 지우고 새 선택지를 넣는다. 재생성 횟수를 1 올린다. AI 응답 행의 `model_code`는 그 재생성의 청구 모델로 바꾼다. 요약 끝 턴이 교체한 턴 이상이면 `summary`는 `NULL`로 바꾸고 `summary_through_turn`은 0으로 바꾼다.
- 선택지를 채울 때는 같은 잠금 안에서 마지막 턴과 본문이 일치하는지 재확인한다. 이미 선택지가 있으면 저장된 값을 반환한다.

### 4-1-14 후보 이름 구분

엔딩과 주요 사건의 이름은 플레이 이름으로 치환한 뒤 AI에 보낸다. 치환 결과가 같은 후보가 생기면 AI가 구분할 수 없으므로 전달 이름을 유일하게 만든다.

- 후보 배열 순서에서 같은 치환 이름의 첫 후보는 그대로 쓰고 두 번째부터 ` (2)`, ` (3)` 순으로 구분 표시를 붙인다.
- 붙인 이름이 다른 후보의 치환 이름이나 이미 배정한 전달 이름과 같으면 번호를 올려 유일해질 때까지 반복한다. 아직 처리하지 않은 후보의 치환 이름도 충돌 검사에 포함한다.
- 대응표는 AI에 전달한 이름과 토큰 원문 이름을 연결한다. 목표 사건과 거쳐온 사건 이름에도 같은 대응표를 쓴다. 턴, 재생성, 선택지 요청에 같은 규칙을 적용한다.
- AI가 돌려준 이름은 대응표에서 그대로 찾는다. 찾지 못하면 무시한다. 구분 표시는 저장값과 표시값에 넣지 않는다.

```mermaid
    class A,B,C,S,K,X,Q,R,D,N,E,G,T,F,P,M,H comp
```

- 생성 작업과 이벤트를 전달하는 연결은 독립적이다. 수신 연결이 끊겨도 생성은 계속된다.
- 생성 작업은 `started`, `token`, `character_image`, `completed`, `error` 등 클라이언트용 SSE 이벤트 전부를 생성별 Redis Streams에 기록한다. 처음 연결과 재연결은 같은 스트림을 읽는다.
- 첫 연결인 이어쓰기와 재생성 POST는 자기 생성의 스트림을 기다리며 없는 것으로 판정하지 않는다. 큐 대기 중 아직 이벤트가 없어도 기다린다. 상세 조회 직후 재연결 GET에서도 생성 중 키가 해당 생성 ID를 담고 있으면 스트림을 기다린다.
- 수신 연결마다 수신 스레드 1개와 전용 Redis 연결 1개를 쓴다. 상한을 넘으면 대기 없이 즉시 거부한다. 블로킹 읽기를 전용 연결로 수행해 공유 연결을 점유하지 않는다.
- 재연결 GET은 스트림 존재 확인이나 생성 중 키 확인에서 Redis 오류가 나면 사용 불가로 응답한다. 수신 중 Redis 읽기 오류는 종료 이벤트 없이 연결을 닫는다. 두 경우 모두 생성과 과금에 영향이 없다.
- 생성 도중 이벤트 기록에 실패해도 생성과 저장을 계속한다. 생성 작업은 종료 이벤트(`completed`, `error`)를 기록한 뒤 생성 중 키를 해제하므로 키가 해당 생성 ID가 아님을 확인한 뒤 남은 이벤트를 끝까지 읽으면 빈 읽기 직후에 기록된 종료 이벤트를 놓치지 않는다. 남은 이벤트에도 종료 이벤트가 없으면 종료 이벤트 없이 연결을 닫는다. 기록 실패, 서버 강제 종료, 스트림 만료가 이 경우다. 읽기 대기의 확인 주기 5초는 코드 상수다.
- 저장 진입 뒤 저장이 길어져 스트림이 생성 시 TTL 150초로 먼저 만료되면 재생할 이벤트가 없다. TTL 연장 장치는 두지 않는다. 수신 연결은 같은 종료 조건으로 닫히고 클라이언트는 상세 재조회로 복구한다. 턴과 과금은 DB의 저장 결과가 기준이다.
- 종료한 생성의 이벤트는 보관 기간 뒤 만료된다. 재연결은 새 AI 호출이나 과금을 일으키지 않는다.
