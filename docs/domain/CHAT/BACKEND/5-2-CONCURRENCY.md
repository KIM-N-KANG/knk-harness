# 5-2 동시성

이 문서는 CHAT 도메인의 동시 요청 처리 규칙을 정한다. 채팅 행 잠금, 환불의 단일 판정, 유니크 제약 위반, 읽기 격리, 선택 기록의 세대 판정, 생성 중 키, 채팅 설정 변경과 진행 중 턴의 관계, 대화 요약의 저장과 무효화를 다룬다.

흐름별 단계와 트랜잭션 경계는 처리 흐름에, 시간 한도는 오류 처리에 있다. ([4-1-12 턴 저장과 판정 반영](4-1-PIPELINES.md#4-1-12-턴-저장과-판정-반영), [5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도))

<br>

### 5-2-1 채팅 행 잠금

다음 경로는 채팅 행에 비관적 쓰기 잠금을 걸어 채팅 단위로 직렬화한다. 잠금은 저장 트랜잭션 안에서만 획득한다. AI 호출과 스트리밍 중에는 잠금을 유지하지 않는다.

| 경로 | 막는 경쟁 조건 |
|---|---|
| 이어쓰기 저장 | 시작 시점과 마지막 턴이 달라진 결과를 같은 위치의 새 턴으로 저장하는 경쟁 조건<br>잠금 안에서 마지막 턴을 재확인하고 다르면 저장 없이 폐기하고 환불 |
| 재생성 저장 | 동시에 들어온 재생성 요청 두 건이 같은 마지막 턴 검사를 통과해 중복 과금하고 재생성 횟수 증가가 유실되는 경쟁 조건<br>잠금 안에서 마지막 턴을 재확인하고 다르면 폐기<br>대상 턴을 담은 저장된 요약은 같은 잠금 안에서 비움 |
| 선택지 저장 | 이어쓰기로 마지막 턴이 바뀌었거나 재생성으로 본문이 바뀐 뒤 이전 본문에 맞춰 생성한 선택지를 저장하는 경쟁 조건<br>동시 호출은 먼저 커밋한 값을 반환 |
| 대화 요약 저장 | 늦게 끝난 이전 범위의 요약이 새 요약을 덮거나 요약 시작 뒤 재생성된 턴을 담은 요약을 저장하는 경쟁 조건<br>잠금 안에서 삭제 여부, 재생성 횟수, 요약 끝 턴을 확인하고 조건을 통과할 때만 저장 |
| 삭제, 공유 발급 | 소유권 검사와 기록 사이에 게스트 이관이 `user_id`를 채우는 경쟁 조건<br>동시 발급은 같은 잠금으로 직렬화해 멱등성 보장 |
| 유료 턴 저장의 차감 행 잠금 | 채팅 행 잠금 다음에 이 턴의 `CHAT_TURN` 차감 행을 잠그고 환불 유무를 확인한 뒤 메시지에 연결<br>선차감 대사가 같은 차감을 환불하는 것과 턴을 저장하는 것이 동시에 성립하는 경쟁 조건을 막음<br>잠금 순서는 채팅 행, 차감 행이고 지갑은 잠그지 않음 |

스트림 진행 중에 삭제나 이관이 끼어들어도 저장은 내부 ID로 이어지므로 턴이 저장되고 과금이 유지된다. 선택 기록은 이어쓰기 저장과 같은 트랜잭션에서 새 메시지를 넣기 전에 한다. 별도 트랜잭션으로 먼저 커밋하면 그 사이에 재생성이 방금 기록한 선택지를 지울 수 있다.

### 5-2-2 환불의 단일 판정

| 상황 | 처리 |
|---|---|
| 백그라운드 작업 종료 | 저장 성공 여부로 환불을 한 번만 판정<br>저장 전 실패는 턴과 이미지 모두 환불하고 체험 복원 |
| 연결 종료와 SSE 완료 콜백 | 큐 대기 중과 실행 중 모두 생성 유지<br>작업 취소와 환불 판정에 관여하지 않음 |
| 생성 마감과 저장 진입의 경쟁 | CAS로 생성 마감과 저장 진입 중 하나만 선점<br>마감이 먼저면 `CANCELLED`로 전이하고 실패 종료와 환불<br>늦게 도착한 AI 완료 결과는 저장하지 않음<br>저장 진입이 먼저면 마감이 지나도 저장을 끝까지 마치고 저장 결과로 정산 |
| 저장 확정 후 전달 실패 | 성공으로 정산하고 과금 유지 |
| 실행기 거부 | 백그라운드 작업이 생성되지 않으므로 거부 지점에서 환불 |
| 중복 방어 | 요청 단위 게이트로 환불을 1회로 제한<br>회원 환불은 차감 행별 멱등 키로 원장에 환불 행을 정확히 1건 기록 |
| 이미지 체험 복원 | 검증 탈락, 실패 종료, 거부가 겹쳐도 한 번만 복원 |
| 선차감 대사와 저장의 경쟁 | 대사는 기준 시각(15분)보다 오래된 차감만 다루고 생성 마감은 120초라 평소에는 겹치지 않음<br>저장 진입 뒤 저장이 길어져 겹치면 차감 행 잠금이 둘을 직렬화<br>대사가 먼저면 저장이 환불 행을 보고 결과를 폐기하고 저장이 먼저면 대사가 연결을 보고 환불하지 않음<br>저장 폐기 뒤 종료 시 환불은 같은 멱등 키 `refund:charge:{차감 행 ID}`라 두 번 기록되지 않음<br>연결을 기록하지 않는 구버전 태스크가 만든 차감은 참조 종류가 `CHAT`이라 행 단위 대사가 다루지 않고, 구버전 대사는 참조 종류 `CHAT_TURN`을 환불하지 않으므로 혼재 배포와 롤백 중에도 같은 차감이 두 번 환불되거나 성공한 턴이 환불되지 않음 |

### 5-2-3 유니크 위반 처리

| 대상 | 처리 |
|---|---|
| 메시지 순서 | `(chat_id, message_order)` 유니크 제약으로 잠금 외에도 중복 방지 |
| 회원 도달 집계 | 독립 트랜잭션에서 기록<br>동시 도달의 유니크 위반은 그 트랜잭션만 롤백하고 턴 저장은 유지 |
| 거쳐온 사건 | `(chat_id, main_event_id)` 유니크<br>존재 확인 뒤 삽입 |
| 공유 | `(chat_id, turn_cutoff)` 유니크 제약으로 잠금 외에도 중복 방지 |
| 재생성 선택지 교체 | 기존 행을 지우고 flush한 뒤 삽입해 `(message_id, choice_order)` 충돌 회피 |

### 5-2-4 읽기 격리

| 대상 | 규칙 |
|---|---|
| AI 요청 구성 | `REPEATABLE_READ` 읽기 전용 트랜잭션에서 스토리와 하위 데이터를 하나의 스냅샷으로 읽음<br>쿼리 사이에 제작자가 비공개로 전환하고 내용을 수정해도 이전 공개 판정에 따라 새 내용이 포함되지 않음<br>요청 구성이 끝나면 커밋하고 AI를 호출 |
| 상세, 일괄 조회, 공유 열람 | 같은 격리 수준의 읽기 전용 트랜잭션에서 조회 |
| 대화 요약 범위 고정 | 같은 격리 수준의 읽기 전용 트랜잭션에서 저장한 요약, 요약 끝 턴, 재생성 횟수, 원문을 하나의 스냅샷으로 읽음<br>원문과 재생성 횟수가 같은 시점의 값이라 저장 시 비교가 성립 |
| 상세 읽기 순서 | 공개 ID 형식 검증 후 첫 DB 조회 전에 생성 중 키 읽기<br>형식 오류는 Redis 조회 없이 없는 것으로 응답<br>PostgreSQL의 `REPEATABLE_READ` 스냅샷은 첫 SQL 실행 시 확정<br>[5-2-6 해제 순서](#5-2-6-생성-중-키와-저장-시-재확인)와 결합해 키가 없다고 읽었다면 같은 응답의 대화 기록에 커밋된 턴 포함 보장<br>키가 있다고 읽었어도 새 턴이 보이면 클라이언트는 새 턴으로 완료 판단<br>생성 중 상태는 존재와 소유권 확인을 통과한 뒤 응답에 포함 |

<br>

### 5-2-5 선택 기록의 세대 판정

| 상황 | 처리 |
|---|---|
| AI 호출 중 재생성 커밋 | 요청 진입 시각 이후에 만들어진 선택지는 사용자가 본 세대가 아니므로 기록하지 않음 |
| 재생성 뒤 새 선택지에서 고른 요청 | 새 요청의 진입 시각이 새 선택지 생성 시각보다 늦으므로 정상 기록 |
| 요청 시작 전에 끝난 재생성 | 구분하지 못하고 같은 순번의 새 세대 행이 기록될 수 있음<br>수용한 한계 |

<br>

### 5-2-6 생성 중 키와 저장 시 재확인

| 단계 | 규칙 |
|---|---|
| 생성 선점 | 이어쓰기와 재생성은 같은 채팅의 생성 중 키 `chat:{chatId}:generating`을 Redis `SET NX`로 획득<br>이미 키가 있으면 생성 중으로 거절하고 과금하지 않음<br>Redis 오류로 획득하지 못하면 일시 장애로 거절하고 과금하지 않음<br>선택지 생성은 이 키를 사용하지 않음 |
| 시작 상태 | 키를 획득한 요청은 마지막 턴과 재생성 상태를 읽어 생성의 기준으로 보관<br>이어쓰기의 `lastTurnId`가 제공됐으면 서버의 마지막 턴과 비교<br>불일치는 AI 호출과 과금 전에 거절 |
| 키 내용 | 생성 종류, 사용자 입력, 시작 시각, 재생성 대상 턴 ID, 생성 ID<br>상세 응답은 키가 있을 때만 생성 중 상태 제공 |
| 해제 | 성공 종료는 턴 커밋 후 자신의 생성 중 키 삭제<br>종료 이벤트가 있는 종료는 `completed`나 `error`를 스트림에 기록한 뒤 해제<br>검증 실패에서도 해제<br>선차감 단계 실패, 생성 실패, 실행기 거부는 턴 환불, 이미지 환불, 체험 복원 시도 후 해제<br>큐 대기 중 생성 마감도 환불과 복원 시도 후 해제<br>환불이나 복원 실패에도 해제<br>키 해제 직후 재요청이 환불 전 잔액이나 소진된 체험 한도를 보지 않도록 정산 시도까지 키 유지<br>만료 뒤 다른 생성이 획득한 키는 삭제하지 않음 |
| 비정상 종료 | TTL 만료로 키 해제<br>키의 만료가 턴 저장 성공이나 환불 완료를 의미하지 않음 |
| 저장 시 재확인 | 이어쓰기와 재생성 모두 채팅 행 잠금 안에서 시작 시점의 마지막 턴과 일치하는지 확인<br>턴 ID가 유지되는 재생성도 구분하도록 기존 재생성 횟수 등 교체 상태를 함께 비교<br>달라졌으면 메시지와 이력을 변경하지 않고 결과 폐기와 환불<br>스트림에는 `CHAT_TURN_STALE` 오류 기록 |
| 최종 방어 | Redis 키 부재나 만료와 무관하게 저장 시 재확인 수행<br>같은 시작 상태에서 만들어진 결과 두 개가 같은 위치에 저장되지 않음 |

<br>

### 5-2-7 채팅 설정 변경과 진행 중 턴

| 상황 | 처리 |
|---|---|
| 생성 중 설정 변경 | 채팅 설정 변경은 생성 중 키를 확인하지 않고 채팅 행을 잠그지 않음<br>진행 중인 턴은 시작 시점에 정한 청구 모델과 가격으로 AI 호출, 저장, 환불을 끝냄<br>진행 중인 턴의 AI 요청은 시작 시점의 출력 분량을 유지<br>바꾼 모델과 출력 분량은 다음 요청부터 적용 |
| 턴 시작과 설정 변경의 경쟁 조건 | 턴 시작은 생성 중 키 획득 뒤 채팅을 읽는 시점의 모델을 청구 모델로, 같은 시점의 출력 분량을 AI 요청 값으로 확정<br>그 뒤 들어온 변경은 이 턴에 반영되지 않음 |
| 동시 설정 변경 | 설정 변경은 보낸 필드의 컬럼만 갱신<br>다른 필드의 동시 변경이나 턴 저장과 서로의 값을 덮지 않음 |
| 환불액 | 차감 행의 금액 그대로<br>환불 시점의 모델이나 가격을 다시 읽지 않음 |
| 모델 표 변경 중 턴 | 가격 변경과 노출 중단은 그 뒤에 시작하는 턴부터 적용<br>진행 중인 턴은 시작 시점에 읽은 값 유지 |
| 기본 모델 교체 | 기본 모델은 유니크 제약으로 하나만 존재<br>교체는 기존 기본 해제와 새 기본 지정을 한 트랜잭션에서 수행 |

<br>

### 5-2-8 대화 요약과 진행 중 요청

| 상황 | 처리 |
|---|---|
| 요약 중 이어쓰기 | 요약 범위는 시작 시점에 고정<br>그 사이 저장된 턴은 원문으로 남고 다음 요약 범위에 들어감 |
| 요약 시작 전에 끝난 재생성 | 요약 범위를 고정하는 읽기에 바뀐 턴과 재생성 횟수가 함께 반영돼 결과를 저장 |
| 요약 중 재생성 | 재생성 저장이 재생성 횟수를 올리므로 요약 저장의 비교에서 결과를 버림<br>바뀐 턴이 요약 범위 밖이어도 버리는 단순화를 수용<br>그 범위는 다음 요약 경계에서 다시 요약 |
| 저장된 요약 범위의 재생성 | 재생성 요청은 시작할 때부터 요약 없이 원문으로 AI에 보냄<br>재생성 저장과 같은 트랜잭션에서 요약과 요약 끝 턴을 비움<br>재생성 결과를 폐기하면 요약은 그대로 둠 |
| 요약 저장과 재생성 저장의 순서 | 같은 채팅 행 잠금으로 직렬화<br>요약이 먼저 저장되면 뒤이은 재생성 저장이 그 요약을 비움<br>재생성이 먼저 저장되면 요약 저장이 바뀐 재생성 횟수를 보고 결과를 버림 |
| 요약 중 채팅 삭제 | 저장할 때 채팅 행 잠금 안에서 삭제 여부를 확인하고 삭제됐으면 결과를 버림<br>폐기 사유는 `CHAT_DELETED` |
