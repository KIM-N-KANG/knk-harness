# 5-2 동시성

이 문서는 CHAT 도메인의 동시 요청 처리 규칙을 정한다. 채팅 행 잠금, 환불의 단일 판정, 유니크 제약 위반, 읽기 격리, 선택 기록의 세대 판정을 다룬다.

흐름별 단계와 트랜잭션 경계는 처리 흐름에, 시간 한도는 오류 처리에 있다. ([4-1-12 턴 저장과 판정 반영](4-1-PIPELINES.md#4-1-12-턴-저장과-판정-반영), [5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도))

<br>

### 5-2-1 채팅 행 잠금

다음 경로는 채팅 행에 비관적 쓰기 잠금을 걸어 채팅 단위로 직렬화한다. 잠금은 저장 트랜잭션 안에서만 잡고 AI 호출과 스트리밍 동안에는 잡지 않는다.

| 경로 | 막는 경쟁 조건 |
|---|---|
| 이어쓰기 저장 | 동시 재생성이 아직 커밋되지 않은 새 턴을 보지 못하고 낡은 마지막 턴을 교체하는 경쟁 조건 |
| 재생성 저장 | 동시 재생성 둘이 같은 마지막 턴 검사를 통과해 중복 과금하고 재생성 횟수 증가가 유실되는 경쟁 조건<br>잠금 안에서 마지막 턴을 재확인하고 다르면 폐기 |
| 선택지 저장 | 이어쓰기로 마지막 턴이 바뀌었거나 재생성으로 본문이 바뀐 뒤 낡은 선택지를 붙이는 경쟁 조건<br>동시 호출은 먼저 커밋한 값을 반환 |
| 삭제, 공유 발급 | 소유권 검사와 기록 사이에 게스트 이관이 `user_id`를 채우는 경쟁 조건<br>동시 발급은 같은 잠금으로 직렬화되어 멱등 |

선택 기록은 이어쓰기 저장과 같은 트랜잭션에서 새 메시지를 넣기 전에 한다. 별도 트랜잭션으로 먼저 커밋하면 그 틈에 재생성이 방금 기록한 선택지를 지울 수 있다.

<br>

### 5-2-2 환불의 단일 판정

| 상황 | 처리 |
|---|---|
| 워커 종료 | 저장 성공 여부로 환불을 한 번만 판정<br>저장 전 종료는 턴과 이미지 모두 환불 |
| 스트림 완료 콜백 | 환불하지 않음<br>시작 전 취소만 처리 |
| 시작 전 취소 | 워커 진입과 취소가 상태 값을 원자적으로 선점<br>취소가 선점하면 AI 호출 없이 환불 |
| 실행기 거부 | 워커가 만들어지지 않으므로 거부 지점에서 환불 |
| 중복 방어 | 요청 단위 게이트로 1회<br>회원 환불은 차감 행별 멱등 키로 원장에 환불 행이 정확히 1건 |
| 이미지 체험 복원 | 검증 탈락, 실패 종료, 거부가 겹쳐도 한 번만 복원 |

<br>

### 5-2-3 유니크 위반 처리

| 대상 | 처리 |
|---|---|
| 메시지 순서 | `(chat_id, message_order)` 유니크가 잠금의 최후 방어 |
| 회원 도달 집계 | 독립 트랜잭션에서 기록<br>동시 도달의 유니크 위반은 그 트랜잭션만 롤백하고 턴 저장은 유지 |
| 거쳐온 사건 | `(chat_id, main_event_id)` 유니크<br>존재 확인 뒤 삽입 |
| 공유 | `(chat_id, turn_cutoff)` 유니크가 잠금의 최후 방어 |
| 재생성 선택지 교체 | 기존 행을 지우고 flush한 뒤 삽입해 `(message_id, choice_order)` 충돌 회피 |

<br>

### 5-2-4 읽기 격리

| 대상 | 규칙 |
|---|---|
| AI 요청 조립 | `REPEATABLE_READ` 읽기 전용 트랜잭션에서 스토리와 하위 데이터를 한 스냅샷으로 읽음<br>쿼리 사이에 제작자의 비공개 전환과 수정이 끼어도 옛 공개 판정으로 새 내용이 실리지 않음<br>조립이 끝나면 커밋하고 AI를 부름 |
| 상세, 일괄 조회, 공유 열람 | 같은 격리의 읽기 전용 트랜잭션 |

<br>

### 5-2-5 선택 기록의 세대 판정

| 상황 | 처리 |
|---|---|
| AI 호출 중 재생성 커밋 | 요청 진입 시각 이후에 만들어진 선택지는 사용자가 본 세대가 아니므로 기록하지 않음 |
| 재생성 뒤 새 선택지에서 고른 요청 | 새 요청의 진입 시각이 새 선택지보다 뒤라 정상 기록 |
| 요청 시작 전에 끝난 재생성 | 구분하지 못하고 같은 순번의 새 세대 행이 기록될 수 있음<br>수용한 한계 |
