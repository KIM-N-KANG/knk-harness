# 5-3 오류 처리

이 문서는 CHAT 도메인의 응답 규칙, 앱 코드, 오류 분류, 복구 규칙, 재시도와 시간 한도, 전달 실패 처리, 오류 로그 기준을 정한다.

엔드포인트별 실패 조건과 응답 형식은 계약에, 흐름별 환불 처리는 처리 흐름에, 환불의 단일 판정은 동시성에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1-6 이어쓰기](4-1-PIPELINES.md#4-1-6-이어쓰기), [5-2-2 환불의 단일 판정](5-2-CONCURRENCY.md#5-2-2-환불의-단일-판정))

<br>

### 5-3-1 응답 규칙

| 항목 | 규칙 |
|---|---|
| `code` | HTTP 상태 이름이 기본<br>사유를 구분해야 할 때만 앱 코드 사용 |
| `message` | 사용자 안내 문구<br>스택트레이스와 내부 구현 정보는 포함하지 않음<br>500은 고정 안내 문구 사용 |
| `details` | 필드 검증 실패에만 채움<br>서비스에서 판정한 400은 `details` 없이 `message`에 사유 기록 |
| 스트림 시작 전 | 일반 오류 응답 JSON<br>잔액 부족과 한도 소진도 스트림을 열기 전에 판정 |
| 스트림 시작 후 | `error` 이벤트<br>AI 서버의 `code`와 `message`는 그대로 중계<br>백엔드 자체 실패는 `AI_STREAM_FAILED`와 고정 문구 사용 |

<br>

### 5-3-2 앱 코드

코드 문자열은 API 계약이므로 유지한다.

| 상태 | `code` | 의미 |
|---|---|---|
| 402 | `INSUFFICIENT_CREDIT` | 회원의 이프 부족, 이어쓰기와 재생성 |
| 402 | `GUEST_TRIAL_LIMIT_EXCEEDED` | 게스트 턴 체험 소진, 이어쓰기와 재생성 |
| 403 | `CONSENT_REQUIRED` | 동의 게이트가 켜진 환경에서 미동의 회원의 허용 목록 밖 요청 |
| SSE | `AI_STREAM_FAILED` | AI 이벤트 밖의 스트림 실패<br>연결 실패, 이벤트 간 시간 초과, 완료 이벤트 없는 종료, 저장 실패, 마지막 턴 변경 |
| SSE | AI 서버의 코드 | AI가 `error` 이벤트로 보낸 코드를 그대로 중계 |

<br>

### 5-3-3 오류 분류

| 오류 | 발생 위치 | 처리 |
|---|---|---|
| 입력 오류 | API 계층의 선언적 검증과 본문 파싱 | 400으로 변환<br>선언적 검증은 필드별 `details`, 본문 파싱 실패는 빈 배열 |
| 상태 코드 오류 | 각 서비스의 판정 | 401, 403, 404, 409, 502<br>`code`는 상태 이름 |
| 잔액 부족 | PAYMENT 도메인 | API 계층이 예외를 처리해 402 `INSUFFICIENT_CREDIT`으로 변환 |
| 게스트 한도 소진과 디바이스 헤더 누락 | PAYMENT 도메인 | 402 `GUEST_TRIAL_LIMIT_EXCEEDED`, 400 |
| AI 구조화 오류 | AI 서버의 `error` 이벤트 | `error` 이벤트로 중계<br>Sentry에 보내지 않음 |
| AI 스트림 오류 | AI 호출 구성 요소<br>연결 실패, 이벤트 간 시간 초과, `completed` 없는 종료 | `AI_STREAM_FAILED`로 분류하고 Sentry 전송 |
| 저장 오류 | 턴 저장<br>DB 오류, 마지막 턴 변경 | `AI_STREAM_FAILED`로 분류<br>마지막 턴 변경은 결과 폐기 |
| 선택지 AI 오류 | AI 호출 구성 요소 | 502로 변환<br>본문과 판정은 이미 저장됨 |
| 실행기 거부 | 스트림 실행기 포화 | 환불 뒤 스트림을 오류로 닫음 |
| 예상하지 못한 오류 | 어디서든 | 전역 핸들러가 500 고정 문구로 응답하고 Sentry 전송<br>백그라운드 작업 중 오류는 `error` 이벤트 |

<br>

### 5-3-4 오류별 처리

- 저장 전에 백그라운드 작업이 끝나면 턴과 이미지의 차감을 환불하고 체험을 복원한다. 저장이 확정되면 그 뒤의 전송 실패는 환불하지 않는다.
- 이미지 검증에만 실패하면 이미지 차감만 환불하고 턴은 저장한다.
- 재생성 결과를 폐기할 때는 활성본을 유지한다. 활성본 교체는 성공 시점에만 일어난다.
- 환불과 복원 실패는 스트림 종료를 막지 않는다. 실패를 지표와 로그에 기록한다. 회원의 소모 내역은 원장에 남으므로 사후 정산으로 복구한다.
- 선택 기록, 도달 집계, 지표, 분석 이벤트의 실패는 턴 저장을 되돌리지 않는다.
- 피드백 전달 실패는 접수 결과를 바꾸지 않는다.

<br>

### 5-3-5 재시도와 시간 한도

**1. 재시도**

- 백엔드는 AI 호출을 재시도하지 않는다. AI 서버 내부의 보완 호출 횟수는 `meta`의 재시도 횟수로 받는다.
- 호출 실패 시 다른 모델이나 AI 서버로 전환하지 않는다. 스텁 클라이언트는 환경 설정이며 폴백이 아니다.
- 턴의 재실행은 클라이언트가 같은 입력으로 다시 보낼 때만 일어난다. 같은 입력의 재전송은 새 턴이다.
- 선택지 생성에 실패하면 클라이언트가 같은 요청을 다시 보내 재시도한다.
- 실시간 이미지 처리에 실패하면 재시도하지 않고 그 턴만 이미지 없이 저장한다.

<br>

**2. 시간 한도**

| 단계 | 제한 시간 | 적용 범위 |
|---|---|---|
| AI 연결 | 5초 | 턴과 선택지 공통<br>운영은 1초 |
| AI 스트림 이벤트 간격 | 60초 | 이벤트가 없으면 `AI_STREAM_FAILED`<br>읽기 전체 제한은 두지 않음 |
| 스트림 전체 | 120초 | 초과하면 백그라운드 작업을 취소하고 이벤트 없이 스트림을 닫음 |
| 선택지 호출 | 90초 | 초과 시 502 |
| 실시간 이미지 서명 | 10분 | presigned PUT 만료 |

<br>

### 5-3-6 최종 실패와 부분 완료

- 실시간 이미지 실패는 부분 완료다. 턴은 정상 저장된다. 본문에서는 해당 이미지 마커만 제외된다.
- `completed` 전송 실패는 서비스 밖에서 일어나므로 성공 경로로 정산된다.

| 결과 | 처리 |
|---|---|
| 최종 실패 | `error` 이벤트, 턴과 이미지 환불, 체험 복원<br>이미 있는 턴과 활성본은 변하지 않음 |
| 부분 완료 | 이미지 환불, 턴 저장, `completed` 전송 |

<br>

### 5-3-7 전달 실패 처리

백엔드는 `completed` 전송 전에 턴을 저장하므로 전달에 실패해도 상세 조회로 결과를 되찾을 수 있다.

| 상황 | 백엔드 | 클라이언트와의 경계 |
|---|---|---|
| AI 대기 중 클라이언트 연결 종료 | 백그라운드 작업을 취소하고 저장 전이면 환불 | 클라이언트는 상세를 다시 조회 |
| 저장 완료 후 `completed` 전송 실패 | 성공으로 정산 | 상세 재조회에 새 턴이 있음 |
| `completed`와 `error` 없이 종료 | 저장 여부를 클라이언트가 알 수 없음 | 결과를 알 수 없는 것으로 보고 상세 재조회 |
| 선택지 응답 유실 | 저장된 선택지 유지 | 다시 요청하면 저장된 값 반환 |
| 공유 발급 응답 유실 | 같은 턴 수의 공유 유지 | 다시 요청하면 같은 토큰 반환 |

<br>

### 5-3-8 로그와 Sentry

| 대상 | 규칙 |
|---|---|
| 5xx | 스택트레이스와 함께 ERROR로 기록 |
| SSE 실패 | HTTP는 200이라 5xx 필터에 잡히지 않음<br>AI 스트림 오류와 저장 오류는 백그라운드 작업에서 직접 Sentry에 보냄<br>AI 구조화 오류는 보내지 않음 |
| 예상 가능한 4xx | Sentry 미전송<br>원인 예외가 있으면 클래스와 메시지를 한 줄로 WARN에 기록<br>원인 예외가 없으면 DEBUG에 기록 |
| 환불 실패 | 지표와 구조화 로그로 기록 |
