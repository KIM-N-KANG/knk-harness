# DECISIONS.md

현재 적용 기준은 각 명세에 두고 결정 당시의 이유와 대체 관계는 이 문서에 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다. 기존 ID, 날짜, 당시 상태와 근거를 유지한다.
- 상태와 구현 설명은 원본의 기록 시점을 기준으로 해석한다. 현재 적용 여부나 배포 완료를 과거 기록만으로 단정하지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체하는 결정과 적용 범위를 명시한다.
- 원문에 구분되지 않은 배경, 대안과 영향은 추측해서 보충하지 않는다.

<br>

**C-001. 인물 이미지를 수신 위치에 즉시 표시**

| 항목 | 내용 |
|---|---|
| 날짜 | 원문 미기재 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 인물 이미지가 스트리밍 도중 도착하지만 완료 이벤트에서 한꺼번에 표시하는 선택지가 있었다. |
| 채택 | `character_image`는 수신 위치에 즉시 표시하고 저장된 턴은 마커로 복원한다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 완료까지 기다리면 이미지가 한꺼번에 나타나 읽는 위치와 순서가 바뀐다. |
| 영향 | 진행 중 조각과 확정 본문은 같은 순서를 유지하고 오류 후에도 수신된 이미지를 임의로 재배치하지 않는다. |
| 근거 | [이관 원문 C:965](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-1-client.md#L965-L999) |

<a id="c-002-입력-수정은-버블-자리에서-고치고-입력-수정과-포크-버튼을-모든-턴에-둔다"></a>

**C-002. 입력 수정은 버블 자리에서 고치고 입력 수정과 포크 버튼을 모든 턴에 둔다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-03 |
| 상태 | Accepted |
| 배경 | 서버 v0.14.0이 완료된 모든 턴의 입력 수정과 포크를 허용했다. 진입 위치, 편집 위치와 포크 흐름을 정해야 했다. |
| 채택 | 모든 확정 턴의 사용자 입력 배경 안 오른쪽 아래에 AI 응답 아래 버튼과 같은 간격으로 입력 수정 버튼, AI 응답 아래에 포크 버튼을 두고 마지막 턴은 다시 생성 옆에 포크를 둔다. 입력 수정은 그 사용자 입력 자리의 편집기에서 고친다. 포크는 확인 뒤 새 채팅방으로 이동한다. |
| 대안 | 하단 입력창을 편집 모드로 바꿔 원문을 채우는 방식, 마지막 턴에만 버튼을 두는 방식, 버블을 길게 눌러 메뉴를 여는 방식, 포크를 확인 없이 바로 만드는 방식 |
| 이유 | 2026-11-03 사용자가 진입 UI, 편집 방식과 포크 흐름을 선택했다. 서버가 모든 완료 턴을 허용하므로 버튼도 모든 턴에 둔다. |
| 영향 | 턴마다 AI 응답 아래 버튼 행과 사용자 입력 안 버튼 줄이 생겨 세로 길이가 늘어난다. 편집기는 일반 글 입력이며 블럭 입력과 추천 채우기를 쓰지 않는다. |
| 근거 | [2-2-8 입력 수정과 포크](2-2-REQUIREMENTS.md#2-2-8-입력-수정과-포크), [3-3-7 재생성, 입력 수정과 포크](3-3-LAYOUT.md#3-3-7-재생성-입력-수정과-포크) |

**C-003. 응답 재생성도 확인 창을 거친다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-04 |
| 상태 | Accepted |
| 배경 | 재생성은 버튼을 누르면 바로 요청해 지금 응답이 바뀌고 이프를 썼다. 입력 수정과 포크에 확인 창을 두면서 사용자가 재생성에도 확인 창을 요청했다. |
| 채택 | 다시 생성 버튼을 누르면 동의와 사용 가능 여부를 확인한 뒤 "응답을 다시 생성할까요?" 확인 창을 띄우고, "다시 생성하기"를 골라야 요청한다. 확인 버튼은 위험색이 아닌 기본색이다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 2026-11-04 사용자 요청. |
| 영향 | 재생성 한 번에 조작이 하나 늘어난다. `client_chat_regenerateButton_clicked`는 확인 전 버튼 클릭이라 요청 수와 같지 않다. |
| 근거 | [2-2-4 읽기, 이미지와 엔딩](2-2-REQUIREMENTS.md#2-2-4-읽기-이미지와-엔딩), [3-3-7 재생성, 입력 수정과 포크](3-3-LAYOUT.md#3-3-7-재생성-입력-수정과-포크) |

**C-004. 마지막 턴의 입력 수정도 확인 창을 거친다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-04 |
| 상태 | Accepted |
| 배경 | 입력 수정 확인 창은 사라질 뒤 턴이 있을 때만 떴다. [C-003](#c-003)으로 재생성이 확인 창을 거치게 되자, 응답이 바뀌고 이프를 쓰는 점이 같은 마지막 턴 수정만 바로 보내졌다. |
| 채택 | 입력 수정은 항상 확인 창을 띄운다. 뒤 턴이 있으면 사라질 턴 수와 위험색 "수정하기", 마지막 턴이면 "지금 응답은 새 응답으로 바뀌어요"와 기본색 "수정하기"를 보인다. |
| 대안 | 뒤 턴이 있을 때만 확인 |
| 이유 | 2026-11-04 사용자가 항상 띄우기로 정했다. |
| 영향 | 마지막 턴 수정도 조작이 하나 늘어난다. 확인 버튼 색은 뒤 턴이 사라지는지에 따라 달라진다. |
