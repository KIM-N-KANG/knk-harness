# DECISIONS.md

현재 적용 기준은 각 명세에 두고 결정 당시의 이유와 대체 관계는 이 문서에 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다. 기존 ID, 날짜, 당시 상태와 근거를 유지한다.
- 상태와 구현 설명은 원본의 기록 시점을 기준으로 해석한다. 현재 적용 여부나 배포 완료를 과거 기록만으로 단정하지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체하는 결정과 적용 범위를 명시한다.
- 원문에 구분되지 않은 배경, 대안과 영향은 추측해서 보충하지 않는다.

<br>

**W-001. SSE를 fetch와 ReadableStream으로 수신**

| 항목 | 내용 |
|---|---|
| 날짜 | 원문 미기재 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 채팅 턴은 사용자 입력을 POST 본문에 실어 보내고 SSE로 응답받는다. |
| 채택 | `fetch`와 `ReadableStream`으로 수신한다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 표준 EventSource는 GET만 지원해 해당 POST 본문 계약을 충족하지 못한다. |
| 영향 | 이벤트 파싱, EOF 처리를 직접 소유하고 일반 요청 타임아웃과 스트림 수명을 구분한다. |

**W-006. 공유 진입을 헤더 버튼으로 표시**

| 항목 | 내용 |
|---|---|
| 날짜 | 원문 미기재 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 공유 진입이 옵션 메뉴에 있으면 발견하기 어려웠다. |

| 대안 | 원문에 별도 항목으로 구분하지 않음 |

<a id="w-025"></a>
<a id="w-025-채팅-실시간-이미지-대기를-마스코트가-인물을-그리는-애니메이션으로-바꿈"></a>

**W-025. 채팅 실시간 이미지 대기를 마스코트가 인물을 그리는 애니메이션으로 바꿈**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-06 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 실시간 이미지를 켠 턴은 응답까지 약 15초가 걸리는데, 그동안 썸네일 자리의 점 로딩은 무엇을 만드는지 보여 주지 않았다. 사용자 요청에 따라 인물 이미지를 그리는 중이라는 것이 전해지도록 완성 중 표지와 같은 마스코트 표현으로 바꾼다. |
| 채택 | 썸네일 자리에 완성 중 표지와 같은 방식(시간 → 자세 순수 함수 안무, Canvas 2D)으로 새 안무를 그린다. 마스코트는 처음 한 번 화가 베레모를 쓰고 붓을 집어 든 뒤, 힘을 모으고 그 붓의 털 끝으로 크로키, 수채, 검은 종이 별자리처럼 분위기가 다른 인물 세 장을 그리며 사이사이 안도와 딴짓을 연기한다. 준비를 포함해 약 15초 안에 세 장을 마치고, 응답이 더 늦으면 준비 없이 힘을 모으는 막부터 반복한다. 인물은 사람 아이콘처럼 보이지 않게 옆선, 머리카락, 표정으로 그린다. 낱동작, 막 실행기, 마스코트 그리기, 캔버스 프레임 루프는 완성 중 표지와 함께 쓰는 공용 모듈로 옮긴다. Android는 같은 안무 값으로 뒤따른다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 완성 중 표지에서 쓴 순수 함수 안무는 순간이동 없음, 무대 안 유지 같은 같은 테스트로 검증되고 Android로 값을 옮기기 쉽다. 채팅이 스튜디오 내부를 직접 가져오지 않도록 공용 부분을 도메인 밖으로 옮겼다. 그림의 붓길을 SVG path 문자열로 적으면 그려지는 선과 붓끝이 같은 길을 따르고, 인물 모양을 고칠 때 좌표만 바꾸면 된다. 완성 중 표지처럼 발을 붓 끝으로 쓰면 몸이 그림을 가려, 붓을 몸 옆에 들려 붓털 끝을 붓길에 붙잡고 몸 자리를 거꾸로 구한다. |
| 영향 | 채팅 로딩은 `ImageGeneration`을 쓰지 않는다. 완성 중 표지의 컴포넌트가 공용 `MascotStage`로 바뀌지만 값과 화면은 같다. 웹이 먼저 바뀌어 Android가 같은 안무로 따라오기 전까지 두 플랫폼의 대기 표현이 다르다. 같은 요청으로 두 무대의 바탕 점을 더 옅게(불투명도 0.45 → 0.25) 바꿔, Android가 따라오기 전까지 완성 중 표지의 바탕 점 진하기도 다르다. 안무를 바꿀 때는 Android 구현과 함께 고친다. |
| 근거 | [부분 렌더](../3-3-LAYOUT.md#3-3-4-생성-대기와-이미지), [채팅 스트림 로딩](4-3-STATE-MANAGEMENT.md#4-3-1-저장과-수명), [W-024](../../../STORY/CLIENT/WEB/DECISIONS.md#w-024) |
| 대체 관계 | W-024의 "채팅 장면 썸네일 자리는 점 로딩을 유지합니다"를 부분 대체한다. 완성 중 표지에 관한 W-024의 나머지 결정은 그대로이다. |

<a id="w-027"></a>
<a id="w-027-채팅-실시간-이미지-대기-그림을-창가-인물화-한-장으로-바꾸고-붓을-몸과-따로-움직임"></a>

**W-027. 채팅 실시간 이미지 대기 그림을 창가 인물화 한 장으로 바꾸고 붓을 몸과 따로 움직임**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-07 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 세 장을 15초 안에 그리느라 획이 빠르고 그림마다 짧게 끝나, 한 장의 그림이 완성되어 가는 느낌이 약했다. 붓은 몸에 고정되어 몸 전체만 움직였다. 사용자 요청에 따라 4:3 가로 종이에 인물과 배경이 있는 그림 한 장을 15초 동안 천천히 끝까지 그리고, 쉬는 동작은 유지하며, 붓도 함께 움직이게 한다. 첫 시안은 획이 20번 남짓이라 움직임이 빨라 정신없다는 피드백을 받아, 힘을 모으는 막을 빼고 그림을 단순하게 줄였다. |
| 채택 | 밤 창가에서 달을 보는 인물 한 장을 밑그림, 밑칠, 인물, 마무리 순서로 층을 쌓아 그리고, 사이에 휴와 딴짓을 둔다. 그림은 창틀, 초승달과 밤 창, 옆모습, 달빛, 볼터치, 사인의 11획으로 줄이고 모든 획을 초당 격자 160칸보다 느리게 긋는다. 준비 막 뒤에는 힘을 모으지 않고 바로 밑그림을 시작한다. 무대 시작부터 15초에 사인을 마치고, 응답이 더 늦으면 완성 그림을 감상한 뒤 종이를 넘겨 밑그림부터 같은 그림을 다시 그린다. 빨랫줄과 세 그림은 뺀다. 공용 자세에 몸 기준 붓 회전과 붓털 누름을 더해 그을 때 끌림, 밑칠의 누름, 획 끝 튕김, 물그릇 헹굼, 쉬는 막의 붓 연기를 표현하고, 붓 회전까지 넣어 붓털 끝을 붓길에 붙잡는다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 층을 쌓는 순서는 응답이 어느 순간에 와도 그 순간의 종이가 그리는 중인 그림으로 읽히고, 한 장에 쓰는 시간이 늘어 획이 천천히 이어진다. 능선과 해는 흔한 이미지 아이콘처럼 보였고(W-026 맥락), 동그란 머리와 대칭 어깨는 사람 아이콘처럼 보여, 창과 달을 배경으로 두고 인물은 비대칭 옆선으로 잡았다. 달을 종이 색으로 남기는 수채 표현은 회색 위주 색 규칙 안에서도 그림을 밝게 한다. 붓 회전과 누름을 기본 0인 자세 값으로 두면 완성 중 표지는 바뀌지 않고, 그리기와 같은 순서로 붓털 끝을 계산하면 붓이 기울어도 선과 붓끝이 어긋나지 않는다. |
| 영향 | 한 바퀴가 15.25초에서 16.43초로 늘어난다. 동작 줄이기 정지 장면이 첫 그림을 마친 장면에서 완성 그림을 올려다보는 장면으로 바뀐다. 웹이 먼저 바뀌어 Android가 같은 안무로 따라오기 전까지 두 플랫폼의 대기 표현이 다르다. |
| 근거 | [부분 렌더](../3-3-LAYOUT.md#3-3-4-생성-대기와-이미지), [채팅 스트림 로딩](4-3-STATE-MANAGEMENT.md#4-3-1-저장과-수명), [W-025](DECISIONS.md#w-025), [W-026](../../../STORY/CLIENT/WEB/DECISIONS.md#w-026) |
| 대체 관계 | W-025의 "힘을 모으고", "크로키, 수채, 검은 종이 별자리처럼 분위기가 다른 인물 세 장을 그리며", "약 15초 안에 세 장을 마치고", "준비 없이 힘을 모으는 막부터 반복"을 대체한다. 순수 함수 안무, 공용 모듈, 붓털 끝 고정 그리기, Android가 같은 값으로 따라온다는 W-025의 나머지 결정은 그대로이다. |
