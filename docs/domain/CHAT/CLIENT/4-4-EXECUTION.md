# 4-4 CHAT 공통 실행

<br>

### 4-4-1 완료와 선택지

1. 진입마다 상세를 새로 조회한다. 생성 중이면 해당 생성에 붙고, 아니면 확정 턴을 표시한다.
2. 이어쓰기 또는 재생성을 시작할 때 입력과 설정을 고정하고 전송을 잠근다.
3. 이벤트를 순서대로 반영한다. completed를 받아도 상세 성공 전에는 진행 블록을 지우지 않는다.
4. 상세 성공 프레임에 확정 턴으로 교체하고 채팅 목록을 갱신한다.
5. 추천이 켜져 있고 마지막 턴에 추천이 없으면 선택지를 요청한다. 성공하면 상세를 다시 조회해 저장된 choices를 표시한다.
6. 추천 실패는 추천 영역에서 재시도하고 직접 입력을 막지 않는다.

<br>

### 4-4-2 이어받기와 종료

| 상황 | 실행 |
|---|---|
| 종료 사건 없는 EOF 또는 읽기 오류 | started의 생성 ID로 같은 스트림 재연결 |
| ID 없음 또는 재연결 불가 | 상세의 진행 중 생성 조회. 상세 실패를 생성 완료로 해석하지 않음 |
| 재연결 시작 | 처음부터 오는 이벤트로 진행 조각 재구성 |
| 시도 소진 | 상세를 다시 읽어 다른 생성이면 이어받고, 같은 생성이나 완료 상태는 요구사항의 결과로 종료 |
| 명시적 error | 상세 조회 후 실패 처리. EOF와 같은 결과 불명으로 섞지 않음 |
| 사용자 이탈과 취소 | 수신만 중단하고 실패 토스트 없음 |
| 다음 진입 | 진행 중이면 다시 이어받고 끝났으면 저장된 턴 표시 |

연결 횟수와 대기 간격은 플랫폼 실행 문서가 구체화한다. 서버 저장 결과를 우선하며 복구를 위해 새 이어쓰기나 과금을 임의 시작하지 않는다. ([2-2-3](2-2-REQUIREMENTS.md#2-2-3-생성-실패와-복구), [4-1-2](4-1-CONTRACT.md#4-1-2-sse-이벤트))


<br>

### 4-4-3 관측 경계

| 상황 | 기준 |
|---|---|
| 투어 | 노출, 스텝 도달, 완주와 건너뛰기 네 종류. 인라인 추천 힌트는 별도 이벤트 없음 |
| 복구한 응답 | 이어받았거나 저장 턴을 확인했으면 클라이언트 스트림 실패로 기록하지 않음 |
| 사용자 취소 | 화면 이탈에 따른 수신 취소는 실패 계측에서 제외 |
| 재생성 | 메시지 전송과 별개 조작. 새 메시지 제출로 집계하지 않음 |
| 원문과 공유 ID | 자유 입력, 대화 원문과 공유 식별자를 분석 또는 오류 수집에 넣지 않음 |

이벤트 이름과 필드는 분석 계약을 사용한다. ([채팅 분석](../../../reference/ANALYTICS.md))
