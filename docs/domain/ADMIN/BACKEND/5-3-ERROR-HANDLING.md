# 5-3 오류 처리

이 문서는 ADMIN 도메인의 응답 규칙, 앱 코드, 오류 분류, 복구 규칙, 재시도와 시간 한도, 전달 실패 처리, 오류 로그 기준을 정한다.

엔드포인트별 실패 조건과 응답 형식은 계약에, 흐름별 처리 순서는 처리 흐름에, 감사 기록의 트랜잭션은 동시성에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-2-1 감사 기록의 트랜잭션](5-2-CONCURRENCY.md#5-2-1-감사-기록의-트랜잭션))

<br>

### 5-3-1 응답 규칙

| 항목 | 규칙 |
|---|---|
| `code` | HTTP 상태 이름이 기본<br>관리자 페이지 안내가 달라질 때만 앱 코드 사용 |
| `message` | 안내 문구<br>관리자 거절은 사유를 구분하지 않는 고정 문구<br>500은 고정 안내 문구 |
| `details` | 선언적 필드 검증 실패나 쿼리와 경로 변수의 타입 변환 실패 시 채움<br>서비스에서 판정한 400은 `details`를 빈 배열로 두고 `message`에 사유 기록 |
| 다른 도메인의 관리자 API | 상태 코드와 앱 코드는 그 도메인의 계약<br>인증과 권한 거절만 이 세트의 공통 실패 |

<br>

### 5-3-2 앱 코드

코드 문자열은 API 계약이므로 유지한다. ADMIN 고유의 앱 코드는 없다. 관리자 거절은 상태 이름 `UNAUTHORIZED`와 `FORBIDDEN`으로 응답한다. 다른 도메인의 관리자 API가 쓰는 앱 코드는 각 세트의 앱 코드 목록에 있다.

<br>

### 5-3-3 오류 분류

| 오류 | 발생 위치 | 처리 |
|---|---|---|
| 입력 오류 | API 계층의 선언적 검증과 본문 파싱 | 400으로 변환 |
| 신원 증명 검증 실패 | 계정 도메인의 검증기 | 401 고정 문구 |
| 자격 없음 | 로그인 서비스 | 회원 없음, 역할 없음, 정지, 탈퇴는 모두 403 고정 문구 |
| 토큰 오류 | 관리자 판정 필터 | 누락, 만료, 위조, 표식 없음은 401<br>표식이 있지만 역할이나 상태 조건을 충족하지 못하면 403 |
| 앱 경로의 관리자 토큰 | 앱 토큰 검증 보강 | 인증 필수 경로는 401, 선택 인증 경로는 익명 처리 |
| 대상 없음 | 회원, 스토리, 채팅, 주문 상세, 스토리 설정과 회원 하위 목록 | 404<br>대기 주문도 404<br>삭제된 스토리와 채팅은 404가 아니라 삭제 시각과 함께 응답<br>형식 오류는 400 |
| 페이지와 정렬 오류 | 모든 관리자 목록 | 400 |
| 검색어와 필터 오류 | 목록과 차트 | 400 |
| 감사 기록 실패 | 감사 기록 | 호출 도메인의 트랜잭션과 함께 롤백되어 변경도 취소<br>500 |
| 접속 기록 실패 | 회원 검색, 상세, 이프 내역, 출석 기록 | 조회 응답 대신 500 |
| 집계 조회 실패 | 대시보드 요약과 차트, DB 분석 지표 | 부분 응답 없이 500 |
| 분석 도구 실패 | 분석 지표<br>캠페인 분석<br>사용자, 전환, 기능 지표 | 자격 증명 미설정, 호출 실패, 한도 초과, 비용 예산 부족, 시간 초과, 쿨다운 중, 갱신 중, 요청 대기 10초 초과면 만료된 것이라도 저장 값으로 200<br>일별 지표는 저장 값이 없는 날짜를 `pendingDates`로 알리는 부분 응답<br>준비된 날짜가 하나도 없으면 503<br>신규 가입자, 채팅 턴 도달률, 채팅 옵션 비중은 준비된 날짜가 없어도 DB 값으로 200이고 플랫폼 값만 `null`<br>범위 지표는 그 범위의 저장 값이 없으면 503 |
| 분석 값 저장 실패 | Amplitude 조회 값 저장 | 10초 안에 끝난 갱신을 기다린 요청은 받은 값으로 200 응답<br>WARN 기록 뒤 다음 요청이 시작한 갱신에서 그 날짜를 다시 받음 |
| 분석 값 갱신 예외 | 백그라운드 갱신 | Amplitude 호출 실패가 아닌 예상 밖 예외(저장소 읽기 실패 등)면 그 갱신을 기다리던 요청은 예상하지 못한 오류와 같이 500<br>기다리지 않은 요청은 영향 없음 |
| 분석 값 배치 실패 | 새벽 배치와 초기 백필 | 응답이 없어 사용자 노출 없음<br>키 하나의 조회 실패는 그 키에 쿨다운을 걸고 다음 키로 진행<br>Amplitude 호출 한도 초과, 배치 몫 소진, 자격 증명 미설정이면 그 실행의 Amplitude 단계를 끝내고 AI 비용 단계는 그대로 실행<br>AI 비용 단계는 Langfuse 대기나 쿨다운 중이면 건너뛰고 다음 5분 실행에서 이어 받음<br>Redis 장애로 슬롯을 잡지 못하면 그 슬롯을 건너뜀<br>예외는 스케줄러 밖으로 내보내지 않아 다음 실행이 계속 돎 |
| 캠페인 미지정 | 캠페인 분석 | 쿼리에 없고 캠페인 목록에 종료일 없는 항목도 없으면 400<br>상세 진입 퍼널은 대상 스토리가 쿼리와 목록 모두에 없으면 400 |
| 설치 보고서 실패 | 설치 지표 | 서비스 계정 키 미설정은 호출 없이 503<br>저장소 호출 실패, 보고서 없음, 해석 실패, 시간 초과, 쿨다운 중, 갱신 중은 만료된 것이라도 캐시가 있으면 200이고 없으면 503 |
| 인프라 지표 조회 실패 | 인프라 지표 | 리소스 설정이 모두 비면 호출 없이 503<br>호출 실패, 권한 거부, 호출 제한, 불완전하거나 오류인 질의 결과, 시간 초과, 쿨다운 중, 갱신 중은 만료된 것이라도 그 범위의 캐시가 있으면 200이고 없으면 503 |
| AI 비용 조회 실패 | AI 비용 | 범위의 모든 날짜가 보관 시작일 전이면 호출 없이 200이고 저장 값이 없는 날짜는 보관 기간 밖<br>그 밖에 키나 환경 설정이 비면 호출 없이 503<br>Langfuse 호출 실패, 400, 호출 제한, 시간 초과, 형식 오류는 범위에 저장 값(보관 기간 밖 날짜 포함)이 있으면 그 날짜만 채우고 보관 기간 안의 나머지는 준비 중, 밖의 나머지는 보관 기간 밖이며 저장 값이 하나도 없으면 503 |
| 예상하지 못한 오류 | 모든 위치 | 전역 핸들러가 500 고정 문구로 응답하고 Sentry 전송 |

<br>

### 5-3-4 오류별 처리

- 감사 기록이 실패한 변경은 커밋되지 않는다. 관리자는 같은 요청을 다시 보낸다. 변경의 멱등은 그 도메인이 정한다.
- 접속 기록이 실패한 조회는 응답을 돌려주지 않는다. 기록 없는 개인정보 조회가 생기지 않게 한다.
- 대시보드의 집계 하나가 실패하면 그 엔드포인트 전체를 실패로 응답한다. 일부 지표만 채운 응답은 기준 시각이 섞여 해석을 그르친다. 요약과 차트는 별도 요청이라 한쪽 실패가 다른 쪽에 영향을 주지 않는다.

<br>

### 5-3-5 재시도와 시간 한도

**1. 재시도**

- 백엔드의 자동 재시도는 없다. 관리자 페이지가 같은 요청을 다시 보낸다. 분석 도구와 설치 보고서 호출은 실패 뒤 60초 동안 다시 부르지 않는다.
- 신원 증명 공개 키 조회는 라이브러리 기본 동작에 맡기고 추가로 재시도하지 않는다.

<br>

**2. 시간 한도**

| 대상 | 제한 시간 | 적용 범위 |
|---|---|---|
| 관리자 토큰 | 2시간 | 만료 후 재로그인 |
| 신원 증명 만료 | 시계 오차 60초 | 관리자 로그인 |
| 분석 도구 호출 | 백그라운드 갱신 한 번의 조회 전부 5초 | 분석 지표<br>신규 가입자, 채팅 턴 도달률, 채팅 옵션 비중의 플랫폼 조회 |
| 캠페인 분석 호출 | 조회 하나당 10초, 백그라운드 갱신 한 번의 조회 전부 60초 | 캠페인 추이, 퍼널, 누적 도달, 광고 소재, 유입 소스, 앱 유입, 사용자, 전환, 기능 지표 |
| 분석 도구 갱신의 요청 대기 | 10초 | 관리자 웹 서버 측 처리기의 15초 시간 한도 안에 응답하도록 정함<br>대기 조건과 응답은 [4-1-20 Amplitude 조회 공통](4-1-PIPELINES.md#4-1-20-amplitude-조회-공통) |
| 분석 도구 지표 저장 값 | 오늘 값 10분<br>어제 값은 어제가 된 뒤 하루 한 번<br>확정일 값은 영구<br>리텐션 코호트는 D30까지 끝날 때까지 하루 한 번<br>범위 지표는 `to`가 오늘이나 어제면 10분, 확정일이면 영구 | 분석 지표, 캠페인 분석, 사용자, 전환, 기능 지표<br>만료 뒤 첫 요청 하나가 백그라운드 갱신을 시작 |
| 분석 도구 비용 예산 | 태스크마다 최근 5분 500<br>그 가운데 배치와 백필 몫 300 | 모든 분석 도구 호출<br>설정값 |
| 분석 값 배치 | 5분마다 실행, 새벽 배치는 KST 03:00부터 | 슬롯 키 TTL 10분 |
| 분석 도구 실패 쿨다운 | 60초 | 실패와 예산 부족 뒤 그 키의 재호출 금지 |
| 설치 보고서 내려받기 | 목록과 파일 전부 합쳐 10초 | 설치 지표 |
| CloudWatch와 ECS 호출 | 두 호출 합쳐 5초 | 인프라 지표 |
| Langfuse Metrics API 호출 | 10초 | AI 비용 |
| 설치 지표 캐시 | 1시간 | 만료 뒤 첫 요청 하나가 갱신 |
| 인프라 지표 캐시 | 60초 | 범위마다 만료 뒤 첫 요청 하나가 갱신 |
| DB 테이블 크기 캐시 | 5분 | 만료 뒤 다음 요청이 다시 조회 |
| 설치 보고서 실패 쿨다운 | 60초 | 실패 뒤 재호출 금지 |

- 분석 도구 호출의 백그라운드 갱신 한도(5초, 60초)는 갱신 작업을 실행기에 넣은 시각부터 잰다. 실행기 차례 대기와 다른 갱신의 호출을 기다리는 차례 대기도 포함한다.

### 5-3-6 최종 실패와 부분 완료

| 결과 | 처리 |
|---|---|
| 변경은 되고 감사 로그만 실패 | 발생하지 않음<br>같은 트랜잭션 |
| 역할 회수 뒤 토큰이 남음 | 다음 요청부터 거절<br>진행 중 요청 1건은 처리됨 |
| 대시보드 일부 집계 실패 | 전체 실패로 응답 |
| 한 갱신의 분석 도구 조회 중 일부만 성공 | 성공한 조회의 값은 저장하고 실패한 조회의 날짜는 저장하지 않음<br>일별 지표는 모든 조회 값이 있는 날짜만 응답하고 나머지는 `pendingDates`<br>범위 지표는 필요한 조회 값이 모두 있어야 새 값으로 응답하고 아니면 이전 저장 값으로 응답하거나 사용 불가 |
| 예산이 모자라 일부 날짜만 받음 | 받은 날짜는 저장하고 나머지는 `pendingDates`<br>다음 요청에서 남은 날짜만 받음 |
| 기능 사용과 안정성의 Amplitude 값이 한 날짜도 준비되지 않음 | 503으로 응답하고 같은 응답의 서버 DB 간편 제작 실패율도 보내지 않음<br>준비된 날짜가 하나라도 있으면 실패율은 범위의 모든 날짜를 보냄 |
| 설치 보고서 월별 파일 중 하나만 실패 | 캐시를 갱신하지 않고 실패로 처리<br>일부 달만 더한 값을 주지 않음 |

<br>

### 5-3-7 전달 실패 처리

| 상황 | 백엔드 | 관리자 페이지와의 경계 |
|---|---|---|
| 로그인 응답 유실 | 토큰 발급됨<br>서버 상태 없음 | 다시 로그인하면 새 토큰 |
| 변경 요청 응답 유실 | 변경과 감사 로그가 커밋됐을 수 있음 | 재요청의 결과는 그 도메인의 멱등 규칙<br>감사 로그 조회로 확인 |
| 조회 응답 유실 | 접속 기록은 남음 | 재조회 |

### 5-3-8 로그와 Sentry

경고 로그의 이름과 기록 내용은 관측에 있다. ([5-4-3 구조화 로그 이벤트](5-4-OBSERVABILITY.md#5-4-3-구조화-로그-이벤트))

| 대상 | 규칙 |
|---|---|
| 5xx | 스택트레이스와 함께 ERROR로 기록하고 Sentry 전송<br>분석 도구 지표, 설치 지표, 인프라 지표, AI 비용의 503은 WARN이고 Sentry 미전송 |
| 예상 가능한 4xx | Sentry 미전송<br>원인 예외가 있으면 클래스와 메시지를 한 줄로 WARN<br>없으면 DEBUG |
| 신원 증명과 토큰 검증 실패 | 검증 라이브러리의 원인 메시지와 체인을 기록하지 않음<br>클래스 이름만 |
| 관리자 거절 | 사유 분류를 구조화 로그에 기록<br>응답에는 넣지 않음 |
