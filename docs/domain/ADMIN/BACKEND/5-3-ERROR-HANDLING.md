# 5-3 오류 처리

이 문서는 ADMIN 도메인의 응답 규칙, 앱 코드, 오류 분류, 복구 규칙, 재시도와 시간 한도, 전달 실패 처리, 오류 로그 기준을 정한다.

엔드포인트별 실패 조건과 응답 형식은 계약에, 흐름별 처리 순서는 처리 흐름에, 감사 기록의 트랜잭션은 동시성에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-2-1 감사 기록의 트랜잭션](5-2-CONCURRENCY.md#5-2-1-감사-기록의-트랜잭션))

<br>

### 5-3-1 응답 규칙

| 항목 | 규칙 |
|---|---|
| `code` | HTTP 상태 이름이 기본<br>관리자 페이지 안내가 달라질 때만 앱 코드 사용 |
| `message` | 안내 문구<br>관리자 거절은 사유를 구분하지 않는 고정 문구<br>500은 고정 안내 문구 |
| `details` | 선언적 필드 검증 실패나 쿼리와 경로 변수의 타입 변환 실패 시 채움<br>서비스에서 판정한 400은 `details`를 빈 배열로 두고 `message`에 사유 기록 |
| 다른 도메인의 관리자 API | 상태 코드와 앱 코드는 그 도메인의 계약<br>인증과 권한 거절만 이 세트의 공통 실패 |

<br>

### 5-3-2 앱 코드

코드 문자열은 API 계약이므로 유지한다. ADMIN 고유의 앱 코드는 없다. 관리자 거절은 상태 이름 `UNAUTHORIZED`와 `FORBIDDEN`으로 응답한다. 다른 도메인의 관리자 API가 쓰는 앱 코드는 각 세트의 앱 코드 목록에 있다.

<br>

### 5-3-3 오류 분류

| 오류 | 발생 위치 | 처리 |
|---|---|---|
| 입력 오류 | API 계층의 선언적 검증과 본문 파싱 | 400으로 변환 |
| 신원 증명 검증 실패 | 계정 도메인의 검증기 | 401 고정 문구 |
| 자격 없음 | 로그인 서비스 | 회원 없음, 역할 없음, 정지, 탈퇴는 모두 403 고정 문구 |
| 토큰 오류 | 관리자 판정 필터 | 누락, 만료, 위조, 표식 없음은 401<br>표식이 있지만 역할이나 상태 조건을 충족하지 못하면 403 |
| 앱 경로의 관리자 토큰 | 앱 토큰 검증 보강 | 인증 필수 경로는 401, 선택 인증 경로는 익명 처리 |
| 대상 없음 | 회원, 스토리, 채팅, 주문 상세와 회원 하위 목록 | 404<br>삭제된 스토리와 채팅, 대기 주문도 404<br>형식 오류는 400 |
| 페이지와 정렬 오류 | 모든 관리자 목록 | 400 |
| 검색어와 필터 오류 | 목록과 차트 | 400 |
| 감사 기록 실패 | 감사 기록 | 호출 도메인의 트랜잭션과 함께 롤백되어 변경도 취소<br>500 |
| 접속 기록 실패 | 회원 검색, 상세, 이프 내역, 출석 기록 | 조회 응답 대신 500 |
| 집계 조회 실패 | 대시보드 요약과 차트 | 부분 응답 없이 500 |
| 분석 도구 실패 | 분석 지표 | 자격 증명 미설정은 호출 없이 503<br>호출 실패, 한도 초과, 시간 초과, 쿨다운 중, 갱신 중은 만료된 것이라도 캐시가 있으면 200이고 없으면 503 |
| 설치 보고서 실패 | 설치 지표 | 서비스 계정 키 미설정은 호출 없이 503<br>저장소 호출 실패, 보고서 없음, 해석 실패, 시간 초과, 쿨다운 중, 갱신 중은 만료된 것이라도 캐시가 있으면 200이고 없으면 503 |
| 예상하지 못한 오류 | 모든 위치 | 전역 핸들러가 500 고정 문구로 응답하고 Sentry 전송 |

<br>

### 5-3-4 오류별 처리

- 감사 기록이 실패한 변경은 커밋되지 않는다. 관리자는 같은 요청을 다시 보낸다. 변경의 멱등은 그 도메인이 정한다.
- 접속 기록이 실패한 조회는 응답을 돌려주지 않는다. 기록 없는 개인정보 조회가 생기지 않게 한다.
- 대시보드의 집계 하나가 실패하면 그 엔드포인트 전체를 실패로 응답한다. 일부 지표만 채운 응답은 기준 시각이 섞여 해석을 그르친다. 요약과 차트는 별도 요청이라 한쪽 실패가 다른 쪽에 영향을 주지 않는다.

<br>

### 5-3-5 재시도와 시간 한도

**1. 재시도**

- 백엔드의 자동 재시도는 없다. 관리자 페이지가 같은 요청을 다시 보낸다. 분석 도구와 설치 보고서 호출은 실패 뒤 60초 동안 다시 부르지 않는다.
- 신원 증명 공개 키 조회는 라이브러리 기본 동작에 맡기고 추가로 재시도하지 않는다.

<br>

**2. 시간 한도**

| 대상 | 제한 시간 | 적용 범위 |
|---|---|---|
| 관리자 토큰 | 2시간 | 만료 후 재로그인 |
| 신원 증명 만료 | 시계 오차 60초 | 관리자 로그인 |
| 분석 도구 호출 | 연결과 응답 합쳐 5초 | 분석 지표 |
| 분석 지표 캐시 | 10분 | 만료 뒤 첫 요청 하나가 갱신 |
| 분석 도구 실패 쿨다운 | 60초 | 실패 뒤 재호출 금지 |
| 설치 보고서 내려받기 | 목록과 파일 전부 합쳐 10초 | 설치 지표 |
| 설치 지표 캐시 | 1시간 | 만료 뒤 첫 요청 하나가 갱신 |
| 설치 보고서 실패 쿨다운 | 60초 | 실패 뒤 재호출 금지 |

<br>

### 5-3-6 최종 실패와 부분 완료

| 결과 | 처리 |
|---|---|
| 변경은 되고 감사 로그만 실패 | 발생하지 않음<br>같은 트랜잭션 |
| 역할 회수 뒤 토큰이 남음 | 다음 요청부터 거절<br>진행 중 요청 1건은 처리됨 |
| 대시보드 일부 집계 실패 | 전체 실패로 응답 |
| 그 요청에 필요한 분석 도구 조회 중 하나라도 실패 | 캐시를 갱신하지 않고 실패로 처리 |
| 설치 보고서 월별 파일 중 하나만 실패 | 캐시를 갱신하지 않고 실패로 처리<br>일부 달만 더한 값을 주지 않음 |

<br>

### 5-3-7 전달 실패 처리

| 상황 | 백엔드 | 관리자 페이지와의 경계 |
|---|---|---|
| 로그인 응답 유실 | 토큰 발급됨<br>서버 상태 없음 | 다시 로그인하면 새 토큰 |
| 변경 요청 응답 유실 | 변경과 감사 로그가 커밋됐을 수 있음 | 재요청의 결과는 그 도메인의 멱등 규칙<br>감사 로그 조회로 확인 |
| 조회 응답 유실 | 접속 기록은 남음 | 재조회 |

<br>

### 5-3-8 로그와 Sentry

경고 로그의 이름과 기록 내용은 관측에 있다. ([5-4-3 구조화 로그 이벤트](5-4-OBSERVABILITY.md#5-4-3-구조화-로그-이벤트))

| 대상 | 규칙 |
|---|---|
| 5xx | 스택트레이스와 함께 ERROR로 기록하고 Sentry 전송<br>분석 지표와 설치 지표의 503은 WARN이고 Sentry 미전송 |
| 예상 가능한 4xx | Sentry 미전송<br>원인 예외가 있으면 클래스와 메시지를 한 줄로 WARN<br>없으면 DEBUG |
| 신원 증명과 토큰 검증 실패 | 검증 라이브러리의 원인 메시지와 체인을 기록하지 않음<br>클래스 이름만 |
| 관리자 거절 | 사유 분류를 구조화 로그에 기록<br>응답에는 넣지 않음 |
