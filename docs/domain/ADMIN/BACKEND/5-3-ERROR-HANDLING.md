# 5-3 오류 처리

이 문서는 ADMIN 도메인의 응답 규칙, 앱 코드, 오류 분류, 복구 규칙, 재시도와 시간 한도, 전달 실패 처리, 오류 로그 기준을 정한다.

엔드포인트별 실패 조건과 응답 형식은 계약에, 흐름별 처리 순서는 처리 흐름에, 감사 기록의 트랜잭션은 동시성에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-2-1 감사 기록의 트랜잭션](5-2-CONCURRENCY.md#5-2-1-감사-기록의-트랜잭션))

<br>

### 5-3-1 응답 규칙

| 항목 | 규칙 |
|---|---|
| `code` | HTTP 상태 이름이 기본<br>관리자 페이지 안내가 달라질 때만 앱 코드 사용 |
| `message` | 안내 문구<br>관리자 거절은 사유를 구분하지 않는 고정 문구<br>500은 고정 안내 문구 |
| `details` | 선언적 필드 검증, 쿼리와 경로 변수의 타입 변환 실패 시 채움<br>서비스에서 판정한 400은 `details` 없이 `message`에 사유 기록 |
| 다른 도메인의 관리자 API | 상태 코드와 앱 코드는 그 도메인의 계약<br>인증과 권한 거절만 이 세트의 공통 실패 |

<br>

### 5-3-2 앱 코드

코드 문자열은 API 계약이므로 유지한다. ADMIN 고유의 앱 코드는 없다. 관리자 거절은 상태 이름 `UNAUTHORIZED`와 `FORBIDDEN`으로 응답한다. 다른 도메인의 관리자 API가 쓰는 앱 코드는 각 세트의 앱 코드 목록에 있다.

<br>

### 5-3-3 오류 분류

| 오류 | 발생 위치 | 처리 |
|---|---|---|
| 입력 오류 | API 계층의 선언적 검증과 본문 파싱 | 400으로 변환 |
| 신원 증명 검증 실패 | 계정 도메인의 검증기 | 401 고정 문구 |
| 자격 없음 | 로그인 서비스 | 회원 없음, 역할 없음, 정지, 탈퇴를 모두 403 고정 문구 |
| 토큰 오류 | 관리자 판정 필터 | 누락, 만료, 위조, 표식 없음은 401<br>표식 있음이지만 역할이나 상태 미달은 403 |
| 앱 경로의 관리자 토큰 | 앱 토큰 검증 보강 | 401 |
| 회원 없음 | 회원 상세 | 404, 형식 오류는 400 |
| 커서 오류 | 결제 내역과 감사 로그 조회 | 400 |
| 감사 기록 실패 | 감사 기록 | 호출 도메인의 트랜잭션과 함께 롤백되어 변경도 취소<br>500 |
| 접속 기록 실패 | 회원 검색과 상세 | 조회 응답 대신 500 |
| 집계 조회 실패 | 대시보드 | 부분 응답 없이 500 |
| 예상하지 못한 오류 | 모든 위치 | 전역 핸들러가 500 고정 문구로 응답하고 Sentry 전송 |

<br>

### 5-3-4 오류별 처리

- 감사 기록이 실패한 변경은 커밋되지 않는다. 관리자는 같은 요청을 다시 보낸다. 변경의 멱등은 그 도메인이 정한다.
- 접속 기록이 실패한 조회는 응답을 돌려주지 않는다. 기록 없는 개인정보 조회가 생기지 않게 한다.
- 대시보드의 집계 하나가 실패하면 전체를 실패로 응답한다. 일부 지표만 채운 응답은 기준 시각이 섞여 해석을 그르친다.

<br>

### 5-3-5 재시도와 시간 한도

**1. 재시도**

- 백엔드의 자동 재시도는 없다. 관리자 페이지가 같은 요청을 다시 보낸다.
- 신원 증명 공개 키 조회는 라이브러리 기본 동작에 맡기고 추가로 재시도하지 않는다.

<br>

**2. 시간 한도**

| 대상 | 제한 시간 | 적용 범위 |
|---|---|---|
| 관리자 토큰 | 1시간 | 만료 후 재로그인 |
| 신원 증명 만료 | 시계 오차 60초 | 관리자 로그인 |

<br>

### 5-3-6 최종 실패와 부분 완료

| 결과 | 처리 |
|---|---|
| 변경은 되고 감사 로그만 실패 | 발생하지 않음<br>같은 트랜잭션 |
| 역할 회수 뒤 토큰이 남음 | 다음 요청부터 거절<br>진행 중 요청 1건은 처리됨 |
| 대시보드 일부 집계 실패 | 전체 실패로 응답 |

<br>

### 5-3-7 전달 실패 처리

| 상황 | 백엔드 | 관리자 페이지와의 경계 |
|---|---|---|
| 로그인 응답 유실 | 토큰 발급됨, 서버 상태 없음 | 다시 로그인하면 새 토큰 |
| 변경 요청 응답 유실 | 변경과 감사 로그가 커밋됐을 수 있음 | 재요청의 결과는 그 도메인의 멱등 규칙<br>감사 로그 조회로 확인 |
| 조회 응답 유실 | 접속 기록은 남음 | 재조회 |

<br>

### 5-3-8 로그와 Sentry

경고 로그의 이름과 기록 내용은 관측에 있다. ([5-4-3 구조화 로그 이벤트](5-4-OBSERVABILITY.md#5-4-3-구조화-로그-이벤트))

| 대상 | 규칙 |
|---|---|
| 5xx | 스택트레이스와 함께 ERROR로 기록하고 Sentry 전송 |
| 예상 가능한 4xx | Sentry 미전송<br>원인 예외가 있으면 클래스와 메시지를 한 줄로 WARN, 없으면 DEBUG |
| 신원 증명과 토큰 검증 실패 | 검증 라이브러리의 원인 메시지와 체인을 기록하지 않음<br>클래스 이름만 |
| 관리자 거절 | 사유 분류를 구조화 로그에 기록<br>응답에는 넣지 않음 |
