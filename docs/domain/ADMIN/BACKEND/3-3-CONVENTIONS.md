# 3-3 구현 컨벤션

이 문서는 ADMIN 도메인 코드를 작성하거나 수정할 때 반드시 지킬 규칙과 구현자가 선택할 수 있는 사항을 정한다.

트랜잭션 규칙은 동시성에, 로그 이벤트 규칙은 관측에, 토큰과 개인정보 취급은 보안에, 구현 위치는 AGENTS.md에 있다. ([5-2 동시성](5-2-CONCURRENCY.md), [5-4-3 구조화 로그 이벤트](5-4-OBSERVABILITY.md#5-4-3-구조화-로그-이벤트), [5-1-6 비밀값과 개인정보](5-1-SECURITY.md#5-1-6-비밀값과-개인정보), [AGENTS.md](AGENTS.md))

<br>

### 3-3-1 이름과 용어

| 대상 | 규칙 |
|---|---|
| 패키지 | 관리자 패키지 아래에 설정, API 계층, 전송 객체, 모델, 저장 계층, 서비스, 보안을 나눔<br>다른 도메인의 관리자 API는 그 도메인 패키지 안에 두고 API 계층 이름에 관리자임을 드러냄 |
| 경로 | 관리자 API는 모두 `/api/v1/admin/` 아래<br>다른 도메인의 관리자 API도 같은 접두를 씀 |
| 모델 이름 | 테이블의 단수형 |
| 전송 객체 | 요청은 `Request`, 응답은 `Response`를 접미사로 사용<br>와이어 필드는 camelCase<br>DB 컬럼은 snake_case |
| 작업 이름 | 대문자 snake_case enum<br>저장 값과 응답 값이 같음 |
| 용어 | 용어집을 따름 |

<br>

### 3-3-2 계층 책임

| 계층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| API 계층 | 형식 검증, 관리자 요청자 식별, 상태 코드 지정 | 비즈니스 판정, 저장 계층 호출 |
| 관리자 판정 필터 | 토큰 표식 확인, 역할과 상태 재확인, 요청자 확정 | 운영 작업의 권한 세분화 |
| 로그인 서비스 | 검증기 호출, 자격 판정, 토큰 발급 | 계정 생성, 세션 저장 |
| 감사 기록 | 호출 트랜잭션 안에서 행 추가 | 트랜잭션 시작, 변경 자체 |
| 대시보드와 회원 조회 | 집계와 조회 조립 | 다른 도메인 테이블의 쓰기 |
| 저장 계층 | 쿼리 실행 | 비즈니스 판정 |

<br>

### 3-3-3 요청 검증과 오류

| 대상 | 규칙 |
|---|---|
| 개별 필드의 길이, 필수 여부 | 요청 객체의 필드에 애너테이션으로 선언 |
| 사유 | 공백만인 값은 선언적 검증으로 거절 |
| 관리자 거절 | 로그인과 판정 필터는 사유를 구분하지 않는 고정 문구로 응답 |
| 다른 도메인의 관리자 API | 입력 검증과 상태 거절은 그 도메인의 규칙<br>감사 기록은 변경을 적용한 뒤 같은 트랜잭션에서 호출 |

<br>

### 3-3-4 이벤트와 비동기

| 대상 | 규칙 |
|---|---|
| 감사 기록 | 동기 기록<br>비동기 발행이나 큐를 쓰지 않음 |
| 대시보드 집계 | 요청 스레드에서 동기 조회 |

<br>

### 3-3-5 테스트와 검증 도구

| 대상 | 규칙 |
|---|---|
| 작성 순서 | 동작을 바꾸는 작업은 실패하는 테스트를 먼저 작성 |
| 엔드포인트 변경 | 통합 테스트와 수동 호출 파일을 함께 갱신 |
| 관리자 경로 추가 | 등록된 핸들러를 자동으로 수집하는 회귀 테스트가 새 경로를 포함하는지 확인<br>핸들러별 예외 목록을 두지 않음 |
| 감사 기록 | 변경 API의 통합 테스트는 감사 로그 행을 함께 검증 |
| 시각 | KST 자정 경계와 토큰 만료는 주입한 시계로 검증 |

<br>

### 3-3-6 구현자가 선택할 수 있는 것

| 선택 가능 | 조건 |
|---|---|
| 서비스 내부의 메서드 분할과 이름 | 없음 |
| 테스트 픽스처의 구성 | 없음 |
| 집계 쿼리의 작성 방식 | 지표 정의와 KST 오늘 범위를 유지 |
| 로그 필드 추가 | 신원 증명, 관리자 토큰, 사유 원문을 넣지 않음 |
