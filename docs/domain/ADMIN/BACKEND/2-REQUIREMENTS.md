# 2. 요구사항

이 문서는 ADMIN 도메인의 백엔드가 처리해야 하는 동작, 요구 주체, 다른 주체와의 역할 분담, 제품 제약과 데이터 보존 기준을 정한다.

요청과 응답의 필드는 계약에, 처리 순서는 처리 흐름에, 토큰 수명은 오류 처리에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도))

<br>

### 2-1 요구 주체

백엔드는 관리자를 판정하고 관리자의 행위를 기록한다. 각 주체의 역할과 백엔드에 기대하는 동작은 다음과 같다.

| 주체 | 하는 일 | 백엔드에 기대하는 것 |
|---|---|---|
| 관리자 페이지 | Google 로그인으로 받은 신원 증명을 서버 측 처리기로 전달<br>관리자 토큰을 자기 호스트 전용 httpOnly 쿠키에 보관<br>백엔드 호출은 서버 측 처리기가 수행 | 신원 증명으로 관리자 토큰을 받는 엔드포인트<br>만료를 알 수 있는 응답<br>브라우저가 백엔드를 직접 호출하지 않으므로 CORS 허용 목록 변경 없음 |
| 관리자 | 대시보드와 사용자, 전환, 캠페인, 기능과 품질 지표 확인, 콘텐츠와 회원 조회, 운영 작업 | 누가 무엇을 바꿨는지 사후에 확인할 수 있는 기록<br>잘못된 요청을 저장 전에 거절<br>차트에서 목록으로 이어지는 같은 조건 |
| 이프, 알림, 공지, 계정, 검수 | 관리자 API로 운영 작업을 처리 | 요청자가 관리자인지 판정한 결과<br>같은 트랜잭션에 감사 로그를 남기는 연산 |
| 역할 관리 운영자 | DB에서 관리자 역할을 부여하고 회수 | 회수 즉시 그 계정의 관리자 요청 거절 |

<br>

### 2-2 기능 요구사항

| 기능 | 백엔드가 보장하는 것 |
|---|---|
| 관리자 로그인 | Google 신원 증명을 앱 로그인과 같은 검증기로 검증<br>해당 신원의 회원이 관리자 역할을 보유하고 활성 상태일 때만 관리자 토큰 발급<br>역할 없음, 회원 없음, 정지, 탈퇴를 구분하지 않고 거절<br>로그인은 계정을 만들지 않음 |
| 관리자 토큰 | 앱 접근 토큰과 다른 표식을 가짐<br>갱신 없이 짧은 수명만 가지며 만료되면 다시 로그인 |
| 토큰 구분 | 앱 접근 토큰은 관리자 API에서 거절하고 관리자 토큰은 앱 API에서 거절 |
| 권한 판정 | 관리자 API 전체가 대상<br>요청마다 토큰 주체의 관리자 역할과 계정 상태를 저장소에서 다시 확인<br>정지와 탈퇴 계정은 역할이 있어도 거절 |
| 역할 관리 | 부여와 회수 API 없음<br>저장소의 역할 행 추가와 삭제로만 바뀌며 다음 요청부터 반영 |
| 감사 로그 | 관리자의 모든 변경 작업을 그 변경과 같은 트랜잭션에 기록<br>처리자, 작업 분류와 작업 이름, 대상, 사유, 변경 전후 값, 요청 ID, 시각<br>회원 검색과 상세 조회도 접속 기록으로 남김<br>삭제 경로 없음 |
| 감사 로그 조회 | 번호 페이지 조회<br>처리자, 작업 분류, 작업 이름, 대상으로 필터 |
| 대시보드 요약 | 서버 DB에서 집계한 오늘과 누적 지표를 한 번에 응답<br>오늘은 KST 자정 기준<br>팀 계정 제외 목록의 회원은 모든 지표에서 제외 |
| 대시보드 차트 | 요청한 KST 날짜 범위의 일별 추이와 분포 차트 8개를 한 번에 응답<br>빠른 범위 7, 30, 90일과 시작일과 종료일 지정을 모두 받음<br>막대마다 같은 조건의 목록 쿼리를 함께 응답 |
| 분석 지표 | 분석 도구에서 요청한 범위의 일별 활성과 신규 사용자, 오늘 활성 사용자를 합계와 Web, Android로 받아 응답<br>사용자 속성 `country`가 `South Korea` 또는 `(none)`이고 `platform`이 `Web` 또는 `Android`인 사용자만 셈<br>팀 계정 코호트 제외<br>지난 날짜 값은 DB에 저장해 다시 받지 않고 비어 있는 날짜만 비용 예산 안에서 받음<br>예산을 넘는 날짜는 준비 중으로 알리고 다음 요청에서 이어 받음<br>분석 도구 장애는 이 응답만 사용 불가이고 DB 지표는 정상 |
| 설치 지표 | Play Console 일괄 보고서를 읽어 Android 누적 기기 설치, 활성 기기, 전체 기간의 일별 설치와 삭제와 누계와 활성 기기를 응답<br>1시간 캐시<br>키 미설정과 저장소 장애는 이 응답만 사용 불가 |
| 인프라 지표 | CloudWatch에서 ECS 서비스별 CPU와 메모리 사용률, ALB 요청 수와 5xx와 대상 응답 시간 p95, RDS CPU와 여유 스토리지와 연결 수와 읽기와 쓰기 지연, Redis 노드별 CPU와 메모리 사용률과 연결 수, OpenSearch 여유 스토리지와 JVM 메모리 압박을 응답<br>ECS에서 서비스별 실행, 목표, 시작 중 태스크 수를 응답<br>기간은 최대 31일이고 길이에 따라 5분, 15분, 1시간 간격<br>60초 캐시<br>권한 없음과 AWS 장애는 이 응답만 사용 불가 |
| DB 테이블 크기 | 데이터베이스 크기와 테이블별 전체, 본 테이블, 인덱스 크기와 추정 행 수를 큰 순서로 응답<br>5분 캐시 |
| 사용자 지표 | 분석 도구에서 플랫폼별 DAU, 신규 방문자와 누계, 사용자당 채팅 전송 수, 신규 사용자의 1일, 7일, 30일 리텐션, 평균 세션 길이, 전체 MAU를 응답<br>서버 DB에서 가입 경로별 신규 가입자와 누계, 게스트 이관 수를 응답 |
| 전환 지표 | 분석 도구에서 웹과 Android 첫 접속, 간편 제작, 상세 진입 채팅, 게스트 한도 로그인 퍼널을 퍼널마다 응답<br>서버 DB에서 기준 턴 1, 2, 3, 4, 5, 6, 7, 10, 15, 20, 30, 50의 채팅 턴 도달률과 게스트에서 회원으로 이어 간 채팅 비율을 응답 |
| 기능과 품질 지표 | 분석 도구에서 채팅 입력 방식 비중, 스트림 오류율, 오류와 이프 부족과 충전 화면과 초대 성공 사용자 수를 응답<br>서버 DB에서 페르소나와 채팅 모델 비중, 모델별 턴 수, 기능과 모델별 AI 토큰 비용, 턴당 원가와 스토리당 원가를 응답 |
| 캠페인 분석 | 설정 파일의 캠페인 목록(차수, 캠페인 값, 기간, 대상 스토리)을 제공<br>분석 도구에서 캠페인 값과 기간으로 웹 DAU, 신규 방문자, 소스별 신규 방문자, 신규 가입자와 누계, 이용 횟수의 추이, 간편 제작 퍼널, 상세 진입 퍼널, 유입 소스별 신규 방문자와 게시글별 방문자를 계산해 응답<br>저장된 차트가 아니라 명세의 정의로 계산<br>분석 지표와 같은 값 저장과 비용 예산<br>분석 도구 장애는 이 응답만 사용 불가 |
| 푸시 열람 | 관리자 캠페인과 서비스 알림 종류마다 도달 회원 수, 웹 푸시 열람 수와 열람률, 알림 내역 열람 수를 응답<br>도달은 서버 발송 결과, 열람은 분석 도구<br>분석 지표와 같은 값 저장과 비용 예산<br>분석 도구 장애는 이 응답만 사용 불가 |
| 스토리 조회 | 범위, 장르, 공개 상태, 보류, 소유자, 기간, 제작 세션, AI 호출로 필터하고 검색, 정렬, 번호 페이지<br>상세는 기준 턴 도달률과 최근 채팅 포함 |
| 채팅 조회 | 스토리, 회원, 게스트 여부, 턴 구간, 첫 메시지, 기간, AI 호출로 필터하고 검색, 정렬, 번호 페이지<br>메시지 원문은 어떤 응답에도 없음 |
| 결제 내역 | 완료와 환불된 주문을 상태, 회원, 완료일로 필터하고 검색, 정렬, 번호 페이지<br>상세는 첫 결제 전후의 턴, 제작, 소모 비교 |
| 이프 내역 | 전체 회원의 원장 행을 최신순 번호 페이지로 조회<br>적립과 소모 방향, 기록일로 필터<br>팀 계정 제외 없음 |
| 회원 조회 | 닉네임 부분 일치, 공개 식별자, 이메일 정확 일치로 검색하고 상태, 가입일, 채팅, 원장, 출석으로 필터<br>상세는 상태, 가입 시각, 최근 활동, 잔액, 소모, 결제액, 소유 콘텐츠 수, 누적 턴 수 포함<br>이프 내역과 출석은 별도 페이지 조회<br>이메일과 소셜 식별자는 응답에 없음 |

### 2-3 다른 주체와의 역할 분담

| 판단과 작업 | 담당 |
|---|---|
| 관리자 역할 부여와 회수 | 역할 관리 운영자가 DB에서 직접 변경 |
| Google 신원 증명 검증 | 계정 도메인의 검증기<br>백엔드는 결과만 사용 |
| 관리자 토큰 보관과 만료 뒤 재로그인 안내 | 관리자 페이지 |
| 운영 작업의 입력 검증과 적용 | 데이터를 관리하는 도메인<br>백엔드는 관리자 판정과 감사 기록 연산 제공 |
| 활성과 신규 사용자 수 | 분석 도구가 집계<br>서버는 받아서 전달만 하고 세지 않음 |
| 팀 계정 코호트 유지 | 관리자가 분석 도구에서 코호트에 팀 계정을 추가하고 삭제 |
| Android 설치 집계 | Play Console이 일괄 보고서로 집계<br>서버는 읽어 더하기만 하고 설치를 세지 않음 |
| AWS 리소스 지표 집계 | CloudWatch가 집계<br>서버는 받아 단위만 바꾸고 다시 세지 않음 |
| 앱 지표, 로그, 트레이스 | OpenSearch UI<br>관리자 페이지에 넣지 않음 |
| 캠페인 이벤트 수집 | 클라이언트와 서버의 분석 이벤트 발행<br>관리자 백엔드는 분석 도구의 집계값만 받음 |
| 지표의 원본 구분 | 가입, 채팅 턴, 결제, 이프, AI 호출처럼 로그인 사용자의 사실은 서버 DB<br>게스트와 방문, 유입, 클라이언트 화면 행동은 분석 도구 |
| AI 모델 단가와 비용 계산 | Langfuse 모델 설정<br>서버는 Langfuse가 계산한 비용을 받아 원화로 바꾸고 기능으로 묶음 |
| 실시간 이미지 장당 원가, 환율, 추적 이름 매핑 | 설정 파일 고정값<br>바꾸려면 배포 |
| 오류와 AI 호출 기록 | 오류 추적 도구와 AI 관측 도구<br>관리자 페이지가 링크만 둠 |

### 2-4 제품 제약

**1. 입력**

| 항목 | 규칙 |
|---|---|
| 사유 | 1~500자<br>공백만으로 구성된 값은 불가 |
| 목록 검색어 | 1~50자<br>정규화 뒤 비교<br>목록별 부분 일치와 정확 일치 대상은 계약 |
| 목록 날짜 필터 | KST 달력 날짜<br>양 끝 포함 |
| 차트 기간 | 시작과 끝 KST 날짜<br>끝은 오늘 이하, 길이 1~366일<br>빠른 범위 7, 30, 90일 |
| 분석 지표 기간 | 차트와 같은 날짜 규칙<br>길이 1~366일<br>빠른 범위 7, 30, 90일 |
| 캠페인 추이 기간 | 1~366일<br>빠른 범위 7, 30일 |
| 캠페인 퍼널 기간 | 간편 제작 퍼널 1~20일, 빠른 범위 7일<br>상세 진입 퍼널 1~31일, 빠른 범위 7, 30일 |
| 캠페인 유입 소스 기간 | 1~10일<br>빠른 범위 7일 |
| 캠페인 값 | 1~100자 |
| 푸시 열람 기간 | 1~366일<br>빠른 범위 7, 30일 |
| 사용자 활동 기간 | 1~366일 |
| 사용자 세션 기간 | 1~366일<br>빠른 범위 7, 14일 |
| 사용자 리텐션 기간 | 1~366일<br>끝은 어제 이하<br>빠른 범위 7일 |
| 전환 퍼널 기간 | 퍼널마다 1~31일 |
| 기능 사용 기간 | 1~366일 |
| DB 지표 기간 | 1~366일 |
| 페이지 번호 | 1 이상의 정수<br>기본 1 |
| 페이지 크기 | 1~100<br>기본 20 |
| 정렬 | 각 목록이 허용한 열과 `asc`, `desc`<br>그 외는 거절 |

- 분석 도구의 일별 지표는 비어 있는 날짜를 비용 예산 안에서 나눠 받으므로 DB 지표와 같은 366일까지 받는다. 퍼널과 유입 소스처럼 범위 전체가 한 값인 지표는 한 번의 조회 비용이 예산 안에 들도록 상한을 정했다. ([4-1-20 Amplitude 조회 공통](4-1-PIPELINES.md#4-1-20-amplitude-조회-공통))

**3. 대시보드 지표**

모든 지표는 팀 계정 제외 목록의 행을 제외한다. 팀 계정 제외 목록은 설정값의 회원 내부 ID 목록이며 기본 목록은 운영 Terraform의 Grafana 서비스 통계 대시보드가 소비 활동에서 제외하는 팀 계정과 같다. 회원은 그 회원 행을, 채팅과 턴과 스토리와 이프와 결제는 소유 회원이 팀 계정인 행을 뺀다. 소유자가 없는 게스트 행은 포함한다. 제작 세션 차트만 공식 계정의 세션을 포함한다. 팀 계정 제외는 대시보드와 AI 비용을 뺀 DB 분석 지표에만 적용하고 목록, 상세, 감사 로그에는 적용하지 않는다.

| 지표 | 정의 | 오늘과 일별 |
|---|---|---|
| 누적 가입자 수 | 탈퇴한 회원을 포함한 전체 회원 행 수<br>현재 회원 수(탈퇴하지 않은 회원)와 누적 탈퇴 수(`status`가 `DELETED`인 회원)를 함께 셈 | 그날 생성된 회원 행 수 |
| 채팅 시작 수 | 삭제 여부와 무관한 채팅 행 수 | 그날 생성된 채팅 행 수 |
| 채팅 턴 수 | 채팅의 AI 응답 메시지 수<br>재생성은 같은 메시지의 판본이라 세지 않음 | 그날 생성된 AI 응답 메시지 수 |
| 스토리 수 | 삭제 여부와 무관한 스토리 행 수 | 그날 생성된 스토리 행 수 |
| 이프 적립 | 원장의 양수 행 합계<br>사유는 가입, 초대, 출석 보상, 구매, 관리자 지급 | 그날 기록된 행만 |
| 이프 소모 | 원장의 소모 사유 행 합계의 절댓값<br>사유는 간편 제작, 채팅 턴, 채팅 이미지 | 그날 기록된 행만 |
| 결제 건수와 금액 | 완료 시각이 있는 주문의 수와 가격 합계<br>환불된 주문도 포함 | 그날 완료된 주문만 |
| 출석 회원 수 | 없음 | 그날 출석 보상 행이 있는 고유 회원 수 |

분포 차트는 기간 안의 행만 센다. 기간의 기준 시각은 차트마다 다르다.

| 차트 | 기간 기준 | 값 |
|---|---|---|
| 장르별 평균 턴 수 | 채팅 생성 시각 | 스토리 장르 문자열을 나눈 장르마다 그 장르 채팅의 현재 턴 수의 평균<br>장르가 여럿인 스토리의 채팅은 장르마다 셈<br>장르마다 채팅 수와 현재 턴 합을 함께 응답하고 채팅 수가 적은 장르도 빼지 않고 응답 |
| 턴 수 분포 | 채팅 생성 시각 | 현재 턴을 0, 1, 2, 3, 4, 5, 6, 7~9, 10~14, 15~19, 20~29, 30~49, 50 이상의 13구간으로 나눈 채팅 수 |
| 게스트와 회원 비율 | 채팅 생성 시각 | 소유 회원이 없는 채팅과 있는 채팅의 백분율 |
| 회원별 채팅 생성 횟수 | 채팅 생성 시각 | 기간에 채팅을 만든 회원을 채팅 수 1, 2, 3~4, 5~9, 10 이상의 5구간으로 나눈 회원 수 |
| 첫 사용자 입력까지 걸린 시간 | 채팅 생성 시각 | 채팅 생성부터 첫 사용자 메시지까지 걸린 초의 평균, 중앙값, 75백분위수, 90백분위수<br>900초 초과와 메시지 없는 채팅은 제외하고 그 수를 설명에 적음 |
| 기능별 AI 평균 호출 시간 | AI 호출 기록 생성 시각 | 채팅 응답, 선택지 생성, 실시간 이미지 생성, 스토리라인 생성, 간편 제작 5종의 성공 호출 중 지연 값이 있는 호출의 평균 초 |
| 기능별 AI 성공률 | AI 호출 기록 생성 시각 | 평균 호출 시간과 같은 5종마다 성공과 실패를 더한 호출 중 성공의 백분율<br>진행 중 호출 제외<br>실시간 이미지는 업로드 위치를 발급한 턴만 셈 |
| 간편 제작별 입력 주변 인물 수 | 제작 세션 생성 시각 | 사용자가 직접 입력한 주변 인물 수 0~5마다의 세션 수<br>입력한 인물은 주변 인물 역할 행 중 이름, 성별, 그 인물에 연결된 특징 태그 중 하나라도 있는 행<br>셋 다 비면 AI가 채우는 빈 자리라 제외 |

AI 호출 기록의 팀 계정 판정은 채팅 기능(`chat_response`, `choice_generation`, `chat_image`)은 기록의 채팅 ID가 가리키는 채팅의 소유 회원, 제작 기능은 기록의 스토리 ID가 가리키는 스토리의 소유 회원으로 한다. 스토리 ID가 없는 제작 기록은 포함한다.

<br>

**4. 캠페인 분석 지표**

캠페인 분석은 분석 도구의 이벤트로 계산하며 팀 계정을 제외하지 않는다. 모든 지표는 사용자 속성 `country`가 `South Korea` 또는 `(none)`인 사용자만 세고 신규 가입자를 뺀 지표는 `platform`이 `Web`인 사용자만 센다. 광고 유입은 사용자 속성 `gp:initial_utm_campaign`이 캠페인 값인 사용자이고 광고 외 유입은 전체에서 광고 유입을 뺀 값이다. 페이지 조회 이벤트 속성 `utm_campaign`으로 광고를 판정하지 않는다. 날짜는 분석 도구 프로젝트 시간대인 KST다.

| 지표 | 정의 |
|---|---|
| 웹 DAU | 그날 활성 이벤트가 있는 고유 사용자 수 |
| 신규 방문자 | 그날 처음 이벤트가 있었던 고유 사용자 수<br>전체, 광고, 광고 외 |
| 유입 소스별 신규 방문자 | 광고 유입, 그리고 캠페인이 아니면서 사용자 속성 `gp:initial_utm_source`가 인스타그램(`ig`), 쓰레드(`th`, `threads`), 디시인사이드(`dc`), 그 밖인 신규 방문자 |
| 소스별 신규 방문자 | `_new` 고유 사용자를 사용자 속성 `gp:initial_utm_source` 값마다 셈<br>캠페인 조건 없음 |
| 게시글별 방문자 | 이벤트 속성 `utm_medium`이 `community` 또는 `social`인 페이지 조회 이벤트의 고유 사용자를 이벤트 속성 `utm_content` 값마다 셈 |
| 신규 가입자 | 구글 로그인 성공과 카카오 로그인 성공 이벤트 중 이벤트 속성 `is_new_user`가 `true`인 고유 사용자 수의 합<br>서버 이벤트라 플랫폼 조건 없음<br>같은 날 두 경로로 가입한 사용자는 두 번 셈 |
| 누적 신규 가입자 | 범위 첫날부터 그날까지 신규 가입자 합 |
| 이용 횟수 | 스토리라인 생성 요청, 간편 제작 요청, 채팅 메시지 전송 이벤트의 발생 횟수 |
| 간편 제작 퍼널 | 환영 다이얼로그 조회, 제작 버튼 클릭, 스토리라인 생성 요청, 스토리라인 선택, 간편 제작 요청, 채팅 메시지 전송의 6단계를 1일 안에 순서대로 거친 고유 사용자 수<br>전체, 광고, 광고 외 |
| 상세 진입 퍼널 | 대상 스토리의 상세 조회(현재 UTM 캠페인이 캠페인 값), 채팅 시작 클릭, 턴 1~5의 채팅 메시지 전송 7단계를 1일 안에 순서대로 거친 고유 사용자 수<br>전체만 |

<br>

**5. 푸시 열람 지표**

푸시 열람은 이미 가입한 회원이 알림을 눌러 연 웹 페이지 조회로 센다. 첫 유입 속성을 쓰지 않고 국가, 플랫폼, 팀 계정 조건을 두지 않는다. 날짜는 분석 도구 프로젝트 시간대인 KST다.

| 지표 | 정의 |
|---|---|
| 푸시 열람 | 페이지 조회 이벤트 `[Amplitude] Page Viewed` 가운데 이벤트 속성 `utm_source`가 `push`이고 `utm_campaign`이 그 캠페인의 공개 식별자이거나 그 서비스 알림의 종류 코드인 고유 사용자 수<br>날짜마다 세어 범위 안에서 더함 |
| 알림 내역 열람 | 같은 정의에서 `utm_source`가 `inbox` |
| 도달 회원 수 | 발송 결과에서 도달 기기가 하나 이상인 회원 수<br>서비스 알림은 날짜별 값의 합 |
| 열람률 | 푸시 열람 수를 도달 회원 수로 나눈 값 |

| 서비스 알림 | 종류 코드 |
|---|---|
| `STORY_COMPLETED` | `story_completed` |
| `STORY_MODERATION_COMPLETED` | `story_moderation_completed` |
| `ATTENDANCE_REMINDER` | `attendance_reminder` |

- 페이지 조회의 UTM 이벤트 속성은 그 페이지를 연 주소의 쿼리 값이다. 웹 푸시를 누르면 브라우저가 딥링크 주소를 연다. 웹 화면이 열려 있을 때 뜨는 알림 안내도 딥링크의 경로와 쿼리로 이동한다.
- Android 앱은 페이지 조회 이벤트를 보내지 않아 Android에서 연 알림은 열람에 들지 않는다. 도달 회원 수에는 Android 기기만 있는 회원도 들어 있다.

<br>

**6. 사용자, 전환, 기능과 품질 지표**

분석 도구 지표는 사용자 속성 `country`가 `South Korea` 또는 `(none)`인 사용자만 세고 팀 계정을 제외하지 않는다. 플랫폼은 사용자 속성 `platform`의 `Web`, `Android`이며 속성이 없는 사용자는 전체와 플랫폼 없음에 든다. 전체와 플랫폼별 값은 따로 세므로 같은 날 여러 플랫폼에서 활동한 사용자 때문에 플랫폼별 합이 전체보다 클 수 있다. 서버 DB 지표는 팀 계정 제외 목록을 적용하며 AI 비용만 적용하지 않는다.

| 지표 | 원본 | 정의 |
|---|---|---|
| DAU, MAU | 분석 도구 | 그날 활성 이벤트가 있는 고유 사용자 수<br>MAU는 `to`로 끝나는 30일 창이며 플랫폼별 값 없이 전체만 |
| 신규 방문자 | 분석 도구 | 그날 처음 이벤트가 있었던 고유 사용자 수 |
| 사용자당 채팅 전송 수 | 분석 도구 | 그날 채팅 메시지 전송 이벤트 수를 그 이벤트가 있는 사용자 수로 나눔 |
| 신규 사용자 리텐션 | 분석 도구 | 어느 날 처음 방문한 사용자 중 1일, 7일, 30일 뒤에 활성 이벤트가 있는 비율 |
| 평균 세션 길이 | 분석 도구 | 분석 도구의 기본 세션 정의 |
| 신규 가입자 | 서버 DB | 그날 생성된 회원 수<br>가입 경로는 첫 소셜 연동의 제공자 |
| 누적 가입자 | 서버 DB | 그날까지 생성된 회원 수<br>범위 첫날과 무관한 전체 누계이고 탈퇴 회원 포함<br>범위 끝이 오늘이면 마지막 값이 대시보드 요약의 누적 가입자 수와 같음 |
| 첫 접속 퍼널 | 분석 도구 | 웹은 환영 다이얼로그 조회부터 첫 채팅 전송까지 6단계, Android는 로그인 화면 조회에서 첫 채팅 전송까지 2단계 |
| 간편 제작 퍼널 | 분석 도구 | 스토리라인 생성 요청, 스토리라인 선택, 간편 제작 요청, 간편 제작 완료의 4단계 |
| 상세 진입 채팅 퍼널 | 분석 도구 | 스토리 상세 조회, 채팅 시작 클릭, 턴 1~5 채팅 메시지 전송의 7단계<br>대상 스토리를 고르면 앞 두 단계를 그 스토리로 한정 |
| 게스트 한도 로그인 퍼널 | 분석 도구 | 게스트 한도 안내 표시, 로그인 버튼 클릭, 로그인 성공의 3단계<br>로그인 성공은 구글과 카카오 경로의 퍼널 결과를 더한 근사치라 두 경로를 모두 거친 사용자는 두 번 셈 |
| 채팅 턴 도달률 | 서버 DB | 범위 안에 생성된 삭제되지 않은 채팅 중 현재 턴이 기준 턴 이상인 비율<br>기준 턴은 턴 수 분포 13구간에서 0을 뺀 구간 시작 턴 1, 2, 3, 4, 5, 6, 7, 10, 15, 20, 30, 50<br>스토리 상세의 기준 턴 도달률도 같은 기준 턴<br>게스트와 회원은 현재 소유자 기준 |
| 게스트에서 회원으로 | 서버 DB | 소유 회원의 게스트 이관 전에 만든 채팅 중 5턴 이상인 것 가운데 6턴 이상의 비율 |
| 채팅 입력 방식 비중 | 분석 도구 | 채팅 메시지 전송 이벤트 수를 이벤트 속성 `input_mode`의 `choice`, `plain`, `block`으로 나눔 |
| 스트림 오류율 | 분석 도구 | 스트림 오류 표시 이벤트 수를 채팅 메시지 전송 이벤트 수로 나눔<br>전송과 오류를 짝짓지 않은 건수 비율이라 1을 넘을 수 있음 |
| 오류와 이프 신호 사용자 수 | 분석 도구 | 채팅 불러오기 오류, 스토리 목록 불러오기 오류, 간편 제작 오류, 이프 부족 안내, 충전 화면 조회, 충전 화면 출석 버튼 클릭, 초대 코드 입력 성공 이벤트별 고유 사용자 수 |
| 페르소나와 모델 비중 | 서버 DB | 범위 안에 생성된 삭제되지 않은 채팅 중 페르소나 이름 스냅샷이 있는 수와 채팅의 현재 선택 모델 코드별 수<br>모델별 턴 수는 그날 생성된 AI 응답 메시지를 메시지에 기록한 청구 모델 코드(그 턴을 실제로 만든 등급)로 묶은 수이며 대시보드 채팅 턴 수와 같은 정의(재생성 판본 제외, 채팅 삭제와 무관)<br>모델 기록 전의 메시지는 `UNRECORDED`로 묶음 |
| AI 비용 | Langfuse와 서버 DB | 금액은 Langfuse가 모델 설정의 단가로 계산한 관측 비용(입력, 출력, 캐시 입력 토큰 반영)을 추적 이름과 모델로 묶어 KST 날짜별로 더하고 설정 환율로 원화로 바꾼 값<br>금액은 실패한 호출 과정의 관측 비용도 포함<br>호출 수와 토큰 수, 토큰 수가 없는 호출 수, 원가의 분모는 성공한 AI 호출 기록<br>실시간 이미지(`chat_image`)는 성공 호출 수에 장당 원가(설정값, 초기 48원)를 곱하고 Langfuse의 실시간 이미지 관측은 뺌<br>턴당 원가는 채팅 응답과 선택지 생성 비용을 채팅 응답 호출 수로, 스토리당 원가는 스토리라인 생성과 간편 제작 비용을 간편 제작 호출 수로 나누며 실시간 이미지 비용은 둘 다에 넣지 않음 |
