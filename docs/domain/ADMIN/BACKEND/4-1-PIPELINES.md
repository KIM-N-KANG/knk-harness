# 4-1 처리 흐름

이 문서는 ADMIN 도메인의 요청 수신부터 응답까지의 처리 단계와 다른 도메인의 관리자 API가 쓰는 판정과 감사 기록의 단계를 정한다.

요청 필드, 응답 필드와 실패 응답은 계약에, 토큰 수명과 복구 규칙은 오류 처리에, 트랜잭션 규칙은 동시성에 있다. ([4-2 계약](4-2-CONTRACT.md), [5-3 오류 처리](5-3-ERROR-HANDLING.md), [5-2 동시성](5-2-CONCURRENCY.md))

<br>

### 4-1-1 공통 처리

모든 요청은 상관관계 필터에서 요청 ID를 받는다. 관리자 로그인은 토큰을 읽지 않는다. 그 밖의 관리자 경로는 관리자 판정 필터가 요청자를 정한다. 앱 경로의 토큰 검증은 관리자 표식이 있는 토큰을 거절한다.

관리자 경로는 `/api/v1/admin/` 아래 전체다. 다른 도메인의 관리자 API도 같은 접두 아래에 두어 같은 필터를 거친다. 필터를 거치지 않는 관리자 경로는 없다.

관리자 판정은 토큰의 값으로 끝내지 않는다. 요청마다 토큰 주체의 회원 행을 읽어 관리자 역할과 계정 상태를 다시 확인한다.

흐름도에서 Google과 다른 도메인을 호출하는 단계는 주황색이다.

<br>

- 계정을 만들지 않고 가입 보상, 체험 스냅샷, 세션 생성, 로그인 분석 이벤트도 수행하지 않는다.
- 로그인 결과는 구조화 로그로 남긴다. 성공은 회원 공개 식별자를 기록하고 실패는 사유 분류만 기록한다.

관리자 판정 필터는 `/api/v1/admin/` 아래에서 로그인을 제외한 모든 요청에 실행된다.

- 앱 접근 토큰은 표식이 없어 첫 단계에서 거절된다. 유효한 관리자 토큰이라도 그 사이 역할이 회수되거나 계정이 정지되면 두 번째 단계에서 거절된다.
- 요청자는 회원 내부 ID로 확정해 핸들러와 감사 기록에 전달한다.

<br>

### 4-1-4 감사 기록

다른 도메인의 관리자 API가 변경을 적용한 뒤 같은 트랜잭션에서 호출한다. ADMIN의 회원 검색과 상세는 조회 뒤 접속 기록으로 호출한다.

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 40}}}%%
flowchart LR
    A["`**변경 적용**
호출 도메인의 트랜잭션`"] --> B["`**변경 전후 값 조립**
호출 도메인`"]
    B --> C["`**감사 로그 행 추가**
같은 트랜잭션`"]
    C --> D{"`**커밋**`"}
    D -->|성공| E["`**변경과 로그 확정**`"]
    D -->|실패| F["`**변경과 로그 모두 롤백**`"]
    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D
    class A,B,C,D,E,F comp
```

- 변경 전후 값은 호출 도메인이 응답 구조와 같은 필드로 조립한다. 생성은 변경 전 값이 없고 삭제는 변경 후 값이 없다.
- 대상은 외부 식별자로 기록한다. 순차 PK를 넣지 않는다.
- 접속 기록은 조회 응답을 만든 뒤 독립 트랜잭션으로 기록한다. 기록에 실패하면 조회 응답도 실패로 바꾼다.

### 4-1-5 목록 공통 처리

스토리, 채팅방, 회원, 결제, 감사 로그 목록은 같은 순서로 처리한다.

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 40}}}%%
flowchart LR
    A["`**쿼리 해석**
검색어 정규화, 날짜 범위, enum, 페이지와 정렬`"] --> B["`**조건 조립**
검색어, 필터, 정렬을 AND`"]
    B --> C["`**전체 건수 조회**`"]
    C --> D["`**현재 페이지 조회**
다른 도메인 테이블`"]
    D --> E["`**표시 조립**
회원 요약, 스토리 요약`"]
    E --> F["`**응답**
페이지 구조`"]
    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D
    classDef task fill:#F5D9C9,stroke:#B97450,color:#452B1D
    class A,B,C,E,F comp
    class D task
```

| 항목 | 규칙 |
|---|---|
| 검색어 | 앞뒤 공백 제거, 연속 공백 하나로, 소문자화<br>부분 일치는 대상 문자열을 같은 규칙으로 정규화한 뒤 포함 여부<br>정확 일치는 정규화한 값이 같은지<br>UUID 형식이면 정확 일치 대상에만 비교 |
| 날짜 범위 | KST 달력 날짜를 `[from 자정, to 다음 날 자정)`의 UTC 구간으로 바꿔 시각 컬럼과 비교 |
| 정렬 | 요청 열과 방향 뒤에 공개 식별자 오름차순을 항상 덧붙임<br>`null`은 마지막 |
| 페이지 | 건너뛸 행 수는 `(page - 1) × size`<br>전체 건수와 현재 페이지는 별도 쿼리 |
| 팀 계정 | 목록과 상세에는 제외 목록을 적용하지 않음 |
| 삭제 행 | 삭제된 스토리와 채팅방은 목록과 상세에서 제외<br>탈퇴 회원은 `excludeDeleted`가 없으면 포함 |

### 4-1-6 대시보드 요약

```mermaid

```

- 지표 정의는 제품 제약을 따른다. ([2-4 제품 제약](2-REQUIREMENTS.md#2-4-제품-제약))
- 오늘 범위는 요청 시작 때 한 번 계산해 모든 집계에 같은 값을 쓴다. 자정을 걸치는 요청에서 지표끼리 기준이 어긋나지 않게 한다.
- 집계는 읽기 전용이며 캐시하지 않는다.
- 팀 계정 제외 목록은 설정에서 읽어 모든 집계의 소유 회원 조건에 적용한다.

| 캐시 | 없음<br>기간 상한 90일이 집계 범위를 제한 |

| 최근 활동 | 삭제되지 않은 채팅방의 마지막 갱신 시각, 원장 기록 시각, 스토리 생성 시각 중 최댓값 |
| 채팅방 구간 | 채팅방 수를 회원별 채팅방 생성 횟수 차트의 5구간에 대응<br>`chatFrom`과 `chatTo`가 있으면 그 기간의 채팅방 수로 판정 |
| 원장 필터 | `creditDirection`은 지급 사유의 양수 행 또는 소모 사유의 음수 행<br>`creditDate`는 그 행의 기록일 |
| 출석 필터 | 출석 보상 사유의 행이 그 KST 날짜에 있는 회원 |
| 상세 | 목록 항목에 잔액, 소유 스토리 수, 탈퇴 시각을 더함<br>잔액은 PAYMENT의 잔액 연산 |
| 거래 내역 | 회원의 원장 행을 기록 시각과 내부 ID 순으로 조회<br>누계는 그 순서의 수량 합 |
| 출석 기록 | 출석 보상 행을 KST 날짜로 묶음 |
| 접속 기록 | 검색어가 있는 목록은 정규화한 검색어를 대상으로 `MEMBER_SEARCHED`<br>상세, 거래 내역, 출석 기록은 회원 공개 식별자를 대상으로 `MEMBER_VIEWED`<br>검색어 없는 목록은 기록하지 않음 |

### 4-1-12 감사 로그 조회

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 40}}}%%

    B --> C["`**처리자 표시 조립**

    C --> D["`**응답**
페이지 구조`"]
    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D
    classDef task fill:#F5D9C9,stroke:#B97450,color:#452B1D

```

- 검색어는 처리자 닉네임, 작업 이름, 사유의 부분 일치와 공개 식별자, 대상 식별자의 정확 일치다. 사유에 대한 부분 일치는 전체 스캔이라 다른 필터와 함께 쓰는 것을 전제로 한다.
- 정렬은 요청 열이며 같으면 감사 로그 공개 식별자 오름차순이다. 처리자 닉네임 정렬은 회원 테이블과 결합한다.
- 감사 로그 조회 자체는 접속 기록을 남기지 않는다.

    classDef task fill:#F5D9C9,stroke:#B97450,color:#452B1D

| 항목 | 규칙 |
|---|---|
| 호출 대상 | Amplitude Dashboard REST API의 이벤트 세분화 조회<br>US 데이터 센터 주소<br>API 키와 시크릿 키의 기본 인증 |
| 조회 | 활성 사용자는 모든 활성 이벤트의 고유 사용자 수, 신규 사용자는 신규 사용자 이벤트의 고유 사용자 수<br>일 단위, 오늘을 포함한 최근 90일<br>두 지표를 요청 2회로 받음 |
| 팀 계정 제외 | 세분화 조회의 사용자 조건에 팀 계정 코호트를 제외 조건으로 넣음<br>코호트 ID 설정이 비어 있으면 제외 없이 조회 |
| 날짜 | 분석 도구 프로젝트의 시간대가 KST라 날짜를 그대로 씀 |
| 캐시 | 90일 결과를 프로세스 안에 10분 보관<br>`days`가 달라도 같은 캐시를 잘라 응답<br>태스크마다 따로 보관 |
| 실패 | 응답 오류, 시간 초과 5초, 호출 한도 초과는 캐시가 10분 안이면 캐시로 응답하고 아니면 사용 불가로 응답<br>자격 증명이 비어 있으면 호출 없이 사용 불가 |
| 집계와의 분리 | 대시보드 요약과 차트와 다른 엔드포인트라 분석 도구 장애가 DB 지표에 영향을 주지 않음 |
