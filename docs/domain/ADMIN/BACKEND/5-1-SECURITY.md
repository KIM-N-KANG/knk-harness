# 5-1 보안

이 문서는 ADMIN 도메인 백엔드의 인증 수준과 토큰, 권한 판정, 계정 상태, 감사와 접속 기록, 입력 검증, 비밀값과 개인정보 취급 규칙, 수용한 한계를 정한다.

경로별 인증 수준과 계정 상태별 응답은 계약에, 로그에 기록하지 않는 데이터는 관측에, 감사 기록의 트랜잭션은 동시성에 있다. ([4-2-1 공통 규칙과 헤더](4-2-CONTRACT.md#4-2-1-공통-규칙과-헤더), [5-4-8 수집 조건과 실패 처리](5-4-OBSERVABILITY.md#5-4-8-수집-조건과-실패-처리), [5-2 동시성](5-2-CONCURRENCY.md))

<br>

### 5-1-1 인증 수준과 토큰

| 항목 | 처리 |
|---|---|
| 불필요 경로 | 관리자 로그인<br>토큰을 읽지 않음 |
| 관리자 경로 | `/api/v1/admin/` 아래 로그인 외 전체<br>관리자 표식이 있는 유효한 토큰만 통과시킨 뒤 역할과 상태를 재확인 |
| 앱 경로 | 관리자 표식이 있는 토큰은 유효해도 인증 실패<br>관리자가 앱을 쓰려면 앱 로그인으로 받은 접근 토큰을 씀 |

| 토큰 | 규칙 |
|---|---|
| 관리자 토큰 | HS256 JWT<br>앱 접근 토큰과 같은 대칭키와 발급자<br>대상 클레임 `manyak-admin`이 표식<br>검증은 서명, 만료, 발급자, 대상<br>만료 판정은 시계 오차 60초 허용 |
| 수명 | 1시간<br>갱신 토큰 없음<br>만료 뒤 요청은 인증 실패이고 관리자 페이지가 다시 로그인하게 함 |
| 폐기 | 서버에 세션이 없어 개별 토큰을 폐기할 수 없음<br>즉시 차단은 역할 회수나 계정 정지로 함 |

<br>

### 5-1-2 권한 판정

| 판정 | 규칙 |
|---|---|
| 역할 | 토큰의 어떤 값도 역할의 근거로 쓰지 않음<br>요청마다 역할 행의 존재를 저장소에서 확인 |
| 적용 범위 | 경로 접두로 판정해 새 관리자 엔드포인트가 자동으로 대상에 포함<br>핸들러별 허용 목록 없음 |
| 세분화 | 관리자 사이의 권한 차이 없음<br>모든 관리자가 모든 관리자 API를 호출 |
| 역할 변경 | API 없음<br>관리자 토큰으로는 역할을 부여하거나 회수할 수 없음 |
| 관리자끼리 | 관리자 역할이 있는 회원은 계정 정지의 대상이 될 수 없음<br>정지하려면 운영자가 먼저 역할을 회수 |

<br>

### 5-1-3 계정 상태

| 상태 | 처리 |
|---|---|
| 정지 계정 | 역할이 있어도 로그인과 관리자 경로를 거절 |
| 탈퇴 계정 | 역할 행은 함께 삭제되지 않지만 로그인과 관리자 경로를 거절<br>재가입 계정은 새 회원이라 역할이 없음 |
| 회원 없음 | 관리자 로그인에서 계정을 만들지 않고 거절 |
| 거절 사유 | 로그인과 판정 필터 모두 역할 없음, 정지, 탈퇴, 회원 없음을 구분하지 않음 |

<br>

### 5-1-4 감사와 접속 기록

| 대상 | 규칙 |
|---|---|
| 변경 작업 | 다른 도메인의 관리자 API를 포함한 모든 변경을 변경과 같은 트랜잭션에 기록<br>기록할 수 없으면 변경도 커밋하지 않음 |
| 개인정보 조회 | 회원 검색과 상세를 접속 기록으로 남김<br>검색은 검색어를 대상으로 기록하고 상세는 회원 공개 식별자를 대상으로 기록 |
| 처리자 | 관리자 판정 필터가 확정한 회원<br>요청 본문의 값으로 바꿀 수 없음 |
| 변경 전후 값 | 응답 구조와 같은 필드만<br>이메일, 소셜 식별자, 토큰, 신원 증명은 넣지 않음 |
| 불변 | 수정과 삭제 API 없음<br>저장소 제약으로 갱신과 삭제를 막지는 않음 |
| 보존 | 영구<br>개인정보 처리 시스템 접속 기록의 법정 최소 보존 기간을 상회 |

<br>

### 5-1-5 입력 검증

| 대상 | 규칙 |
|---|---|
| 사유 | 1~500자<br>공백만으로 구성된 값은 거절 |
| 회원 식별자 | UUID 형식 |
| 검색어 | 1~50자<br>닉네임 검색은 정규화 키와 부분 일치하는지 확인하므로 와일드카드 문자를 해석하지 않음 |
| 커서 | 복호화 성공 여부만 판정<br>형식 오류와 변조를 구분하지 않고 같은 응답 |
| 감사 로그 필터 | `targetId`는 `targetType`과 함께만 허용 |

<br>

### 5-1-6 비밀값과 개인정보

| 대상 | 규칙 |
|---|---|
| 신원 증명 | 저장하지 않음<br>검증 실패의 원인 메시지는 응답과 로그에 넣지 않음 |
| 관리자 토큰 | 서버에 저장하지 않고 로그에 기록하지 않음<br>관리자 페이지는 자기 호스트 전용 httpOnly 쿠키에 보관 |
| 대칭키 | 앱과 같은 환경 변수<br>바꾸면 관리자 토큰도 전부 무효 |
| 회원 조회 응답 | 이메일과 소셜 식별자 없음<br>탈퇴 계정은 익명화된 닉네임 |
| 감사 로그 | 대상은 외부 식별자<br>순차 PK는 처리자 FK 컬럼에만 있고 응답에 노출하지 않음 |
| 사유 | 관리자가 적는 자유 문장이라 회원 개인정보를 적지 않도록 관리자 페이지가 안내<br>서버는 길이만 검증 |

<br>

### 5-1-7 수용한 한계

| 한계 | 수용 이유 |
|---|---|
| 발급된 관리자 토큰을 만료 전에 개별 폐기할 수 없음 | 수명이 1시간이고 역할 회수와 계정 정지로 즉시 차단 가능<br>세션 저장소를 두면 앱과 같은 회전 복잡도가 생김 |
| 감사 로그의 불변이 애플리케이션 규칙에만 의존 | DB에 직접 접근하는 운영자는 고칠 수 있음<br>DB 접근 자체가 소수로 제한됨 |
| 관리자 사이에 권한 차이가 없음 | 팀 구성원이 소수이고 전원이 운영 작업을 함 |
| 사유에 개인정보가 들어갈 수 있음 | 서버가 내용을 판정할 수 없음<br>관리자 페이지의 안내와 감사 로그 열람 권한이 관리자뿐인 점으로 수용 |
