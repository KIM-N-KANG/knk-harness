# DECISIONS.md

ADMIN 도메인 웹의 중요한 결정을 날짜, 상태, 배경, 채택, 대안과 영향으로 정리한다. 현재 적용 기준은 각 명세에 둔다. 여기에는 결정 당시의 이유와 변경 이력을 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다.
- 상태는 결정 당시 기준이다. 결정이 바뀌면 이전 기록을 지우지 않고 후속 결정에 대체 범위와 근거를 적는다.

<br>

### 2. 화면 구성

**1. 지표 화면 네 개를 대시보드 그룹에 두고 탭으로 나눈다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 상태 | 채택 |
| 배경 | 서버가 캠페인 분석과 사용자, 전환, 기능과 품질 지표 엔드포인트 14개를 제공하게 됐다(BACKEND 결정 12, 13). 웹 화면 명세가 없어 구현이 멈췄고 웹 작업자가 메뉴와 탭 구성안을 냈다. 사용자가 구성안을 승인했다. |
| 채택 | 사이드바의 대시보드 구역에 캠페인, 사용자, 전환, 기능과 품질 메뉴를 더하고 경로는 `/analytics/campaigns`, `/analytics/users`, `/analytics/conversion`, `/analytics/quality`로 둔다. 화면마다 서버 엔드포인트 단위의 탭을 두고 현재 탭의 요청만 보낸다. 기존 개요와 분석 화면은 그대로 둔다. 캠페인 분석 화면 제목은 알림 구역의 푸시 캠페인과 구분되게 "캠페인 분석"으로 한다. |
| 대안 | 모든 지표를 개요나 분석 화면에 더하는 안은 화면이 길어지고 Amplitude 비용 예산을 한 번에 많이 쓴다. 메뉴를 엔드포인트마다 두는 안은 메뉴가 열네 개가 된다. 별도 "지표" 구역을 두는 안은 개요와 분석과 같은 대시보드 성격의 화면이 두 구역으로 나뉜다. |
| 영향 | 메뉴 이름 "캠페인"이 대시보드와 알림 두 구역에 있다. 탭 상태가 URL에 들어가 링크로 공유할 수 있다. 화면마다 탭 하나의 실패가 다른 탭을 가리지 않는다. |

**2. 기간은 화면 단위로 공유하고 탭 상한을 넘으면 자르지 않고 오류로 알린다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 상태 | 채택 |
| 배경 | 서버의 기간 상한이 탭마다 다르다. 일별 지표는 366일, 캠페인 간편 제작 퍼널은 20일, 상세 진입 퍼널과 전환 퍼널은 31일, 유입 소스는 10일이고 리텐션은 끝 날짜가 어제 이하다. 사용자는 고른 기간이 조용히 바뀌지 않기를 원했다. |
| 채택 | URL에 기간이 있으면 그 화면의 모든 탭에 같은 기간을 쓰고 없으면 탭마다 서버의 기본 기간을 쓴다. 고른 기간이 현재 탭의 상한이나 끝 날짜 제한을 넘으면 기간을 바꾸지 않고 기간 오류를 보이며 요청하지 않는다. 오류 상자의 맞추기 버튼을 누를 때만 기간을 바꾼다. 서버에는 `from`과 `to`만 보낸다. 캠페인을 바꾸면 기간 쿼리를 지워 캠페인 기간을 기본으로 쓴다. |
| 대안 | 탭마다 기간을 따로 두는 안은 탭을 오갈 때 같은 기간을 다시 골라야 한다. 상한에 맞춰 기간을 자동으로 자르는 안은 관리자가 본 값의 범위를 착각하게 한다. 서버에 `days`를 보내는 안은 탭마다 허용 값이 달라 오류가 늘어난다. |
| 영향 | 캠페인 기간이 탭 상한보다 길면 퍼널과 유입 소스 탭이 기간 오류부터 보인다. |

### 3. 값 표시

**3. 서버가 준 합계와 평균을 쓰고 준비 중과 값 없음을 0과 구분한다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 상태 | 채택 |
| 배경 | 서버는 지난 날짜의 Amplitude 값을 나눠 받아 준비 중 날짜를 응답에 알리고(BACKEND 결정 16) 고유 사용자 수, MAU, 가중 평균, 비율의 분모가 0인 경우를 `null`로 준다. 일별 고유 사용자 수는 더하면 같은 사람을 여러 번 센다. |
| 채택 | 요약 카드는 서버가 준 합계, 평균, MAU, 가중 평균만 쓰고 일별 값이나 플랫폼별 값으로 다시 계산하지 않는다. 준비 중 날짜는 0으로 채우지 않고 차트 선을 끊는다. `null`과 분모 0은 의미에 맞는 문구로 표시한다. 준비 중 날짜나 준비 중 값이 있으면 60초 간격으로 같은 요청을 다시 보낸다. 퍼널 전환율과 스트림 오류율은 100%를 넘어도 자르지 않는다. |
| 대안 | 빈 날짜를 0으로 채우는 안은 실제 0과 구분되지 않는다. 일별 DAU 합으로 기간 사용자 수를 보이는 안은 같은 사람을 여러 번 센다. 100%로 자르는 안은 근사치나 건수 비율이라는 사실을 가린다. |
| 영향 | 일부 요약 카드는 고유 사용자 수의 기간 합 대신 마지막 날 값이나 누계를 쓴다. 고정 데이터에 준비 중 응답과 `null` 응답이 필요하다. |

**4. 계열 순서와 색과 선 모양을 묶음마다 고정한다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 상태 | 채택 |
| 배경 | 지표 화면에는 플랫폼, 광고 구분, 유입 소스, 가입 경로, 입력 방식처럼 계열 묶음이 많다. 관리자 웹의 차트는 마냑 초록 주색과 회색 비교 계열을 쓰고 이중 축을 쓰지 않는다. |
| 채택 | 묶음마다 계열 순서, 색, 선 모양을 하나로 정하고 모든 화면이 같은 표를 쓴다. 단위가 다른 값은 차트를 나누고 겹치는 전체와 부분 계열은 쌓지 않는다. 차트마다 같은 값을 담은 수치 표를 둔다. |

| 영향 | 새 묶음을 더할 때는 계열 순서 표를 먼저 고친다. 모델 코드처럼 값이 정해지지 않은 묶음은 글자 순서와 기본 색 순서를 쓴다. |

**6. 웹 구성안의 세부 판단과 채팅 모델 표시 이름을 확정한다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 상태 | 채택 |
| 배경 | 웹 명세를 쓰면서 구성안에 없던 세부를 판단으로 채웠다. 사용자가 판단 전체를 제안대로 승인했다. 채팅 모델 코드는 명세에 한국어 이름이 없어 코드가 그대로 보였다. |

| 대안 | 대상 스토리를 검색으로 고르는 안은 스토리 검색 연동이 필요하다. 모르는 모델 코드를 "알 수 없는 모델"로 묶는 안은 새 모델이 생겼을 때 어느 모델인지 알 수 없다. |

**7. 화면 제목 아래 설명 문장을 두지 않는다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 상태 | 채택 |
| 배경 | 화면마다 제목 아래에 "서비스의 흐름과 이용 현황을 확인해 주세요."처럼 화면 이름을 풀어 쓴 설명 문장이 있었다. 사용자가 이런 문장을 모두 빼기로 결정했다. |
| 채택 | 화면 제목 아래 설명 문장을 두지 않는다. 발송 동의와 야간 조건, 위험 작업 확인, 오류와 빈 상태, 기간 상한 안내처럼 기능상 필요한 안내만 둔다. |
| 대안 | 화면마다 설명을 다듬는 안은 제목과 메뉴 이름으로 알 수 있는 내용을 되풀이한다. |
| 영향 | 정보 구조의 화면별 문구 표에서 설명 행이 빠졌다. 웹 구현의 페이지 머리에서 설명 문장을 지운다. |
| 보완 | 2026-10-23 사용자 결정 반영. 화면에 늘 보이는 설명 문장은 두지 않고 꼭 필요한 설명은 그 대상의 제목 옆 "?" 버튼의 툴팁으로 둔다. 툴팁은 마우스를 올리거나 키보드 초점을 두면 열린다. 분포 카드의 응답 설명, 이프 내역의 원장 범위 안내, 앱 설치 안내, 리텐션 안내, 게스트 한도 로그인의 근사치 안내를 툴팁으로 옮겼다. 출처 안내는 이미 출처 이름의 툴팁이라 그대로 둔다. Amplitude 범위와 분석 범위는 날짜 범위만 보인다. 집계 지연 문장은 출처 툴팁과 겹쳐 뺐고 분석 범위의 목록 이동 안내도 뺐다. 기능상 필요한 안내와 값이 있을 때만 보이는 준비 중 알림과 누락 안내는 화면에 둔다. |

**8. 개요는 요약 카드 10개와 서버 DB 일별 그래프 8개만 둔다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 상태 | 채택<br>결정 1의 "기존 개요는 그대로 둔다"를 대체 |
| 배경 | 개요는 서버 DB 요약 카드 8개, 지표를 골라 보는 일별 추이 차트 하나, "Amplitude 사용자 지표" 구역(오늘 활성 사용자, 일별 활성과 신규 사용자 차트), 앱 설치 카드(대표 숫자와 펼친 설치 차트)로 이루어져 있었다. 일별 활성과 신규 사용자 차트는 사용자 화면의 사용자 활동 탭과 겹쳤다. 사용자가 DAU 그래프나 리텐션 같은 것은 유입이나 사용자 화면에 있어야 한다고 보았다. 지표 선택형 차트는 한 번에 한 지표만 보여 여러 지표의 흐름을 함께 비교할 수 없었다. |
| 채택 | 개요에는 요약 카드 10개와 일별 추이 카드만 둔다. 서버 DB 카드 8개 뒤에 오늘 활성 사용자 카드(큰 숫자는 오늘 합계, 작은 줄은 Web과 Android)와 앱 설치(Android) 카드(큰 숫자는 누적 기기 설치 수, 작은 줄은 가장 최근 보고일과 그날 기기 설치 수)를 두고 넓은 화면에서 5열 2행으로 놓는다. 두 카드의 출처와 지연 안내는 "?" 툴팁이며 카드를 누르면 각각 사용자 화면의 사용자 활동 탭과 유입 분석의 앱 설치 탭으로 간다. 오늘 활성 사용자 카드는 분석 지표를 오늘 하루로 요청한다. 일별 추이는 지표 선택을 없애고 가입, 채팅 시작, 턴, 스토리 생성, 이프 적립, 이프 소모, 결제 건수, 결제 금액의 작은 선 그래프 8개를 4열 2행으로 둔다. 그래프는 기간 선택기의 범위를 같은 날짜 축으로 쓰고 그래프마다 세로 축 하나에 일별 선과 기간 평균 점선을 그린다. 마우스를 올리면 툴팁이 열리고 점을 누르면 그 목록으로 간다. 수치 표는 접힌 표 하나다. Amplitude 일별 차트는 개요에서 빼고 Play 설치 차트는 유입 분석의 새 탭 "앱 설치"(`tab=installs`)로 옮긴다. 이 탭은 기간을 받지 않아 기간 선택기를 비활성으로 두고 "전체 기간"으로 표시하며 광고 캠페인 선택을 숨긴다. |
| 대안 | Amplitude 일별 차트와 Play 설치 차트를 카드 아래 추이 영역에 남기는 안은 사용자 활동 탭과 겹치고 개요가 길어진다. 앱 설치 탭에서 기간 선택기를 숨기는 안은 탭을 바꿀 때 페이지 머리의 배치가 흔들린다. 지표 8개를 한 차트에 겹쳐 그리는 안은 단위가 달라 세로 축이 여럿 필요하다. |
| 영향 | 개요의 "Amplitude에서 보기" 외부 링크와 활성 기기 수 대표 숫자가 없어진다. 활성 기기 수는 앱 설치 탭에서 본다. 출석 회원 수는 개요에 표시하지 않고 차트 응답의 값은 쓰지 않는다. URL의 `metric` 쿼리는 쓰지 않는다. 오늘 활성 사용자 카드의 분석 지표 요청은 하루치라 Amplitude 비용이 줄어든다. 서버 계약은 바뀌지 않는다. |
| 보완 | 2026-10-24 사용자 결정 반영(BACKEND 결정 19). 회원 카드를 "가입자"로 바꾸고 큰 숫자를 탈퇴 회원을 포함한 누적 가입자 수로 한다. 현재 회원 수와 누적 탈퇴 수는 카드 제목 옆 "?" 툴팁에 두고 카드는 탈퇴 회원을 포함한 회원 목록에 잇는다. 사용자 화면의 누적 가입자 차트는 서비스 시작부터의 누계라 끝 날짜가 오늘이면 마지막 값이 카드와 같다. |

| 대안 | 초록 농도를 더 벌리는 안은 다섯 계열에서 여전히 구분이 어렵다. 회색을 둘째 색으로 두는 안은 비활성처럼 읽힌다. |
| 영향 | 관리자 저장소의 디자인 문서와 `--chart-*` 토큰 값을 이 표로 바꾼다. 다크 모드는 없어 값을 두지 않는다. |
| 보완 | 2026-10-24 검수 반영. 그 밖의 모델 코드를 글자 순서로 셋째 색부터 배정하면 기간마다 등장하는 코드에 따라 같은 모델의 색이 바뀐다. 모델 색은 코드별 고정 매핑(`AURORA` `--chart-1`, `LITE` `--chart-2`)으로 정하고 매핑이 없는 코드와 기록 전(`UNRECORDED`)은 `--muted-foreground`로 둔다. 글자 순서는 표시 순서에만 쓴다. 채팅 옵션 비중 표는 채팅과 턴의 빈 상태를 각각 판단한다. |
