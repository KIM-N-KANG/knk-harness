# 2-1 정보 구조

이 문서는 관리자 웹의 메뉴와 경로, 화면별 탭과 요약 수치와 차트, 기본 선택, 화면 문구를 정한다.

차트 모양과 계열 순서는 디자인 시스템에, 불러오는 중과 실패와 준비 중의 표시는 오류 처리에, 서버 응답 필드는 계약에 있다. ([2-3 UI 디자인 시스템](2-3-UI-DESIGN-SYSTEM.md), [4-1 오류 처리](4-1-ERROR-HANDLING.md), [3-1 계약](3-1-CONTRACT.md))

### 2-1-2 분석 화면 공통 요소

개요, 분석, 지표 화면 다섯 개에 함께 적용한다.

**1. 화면 구성 요소**

| 요소 | 내용 |
|---|---|
| 페이지 머리 | 화면 제목, 오른쪽에 기간 선택기<br>지표 화면은 기간 선택기 옆에 플랫폼과 대상 선택 |
| 탭 막대 | 지표 화면에만 있음<br>페이지 머리 아래에 탭 이름을 나란히 표시 |
| 조건 선택 | 탭이 받는 조건(캠페인, 광고 구분, 대상 스토리, 시작 집단)<br>탭 막대 아래 한 줄 |
| 출처 표시 | 탭 제목 옆에 "Amplitude", "서버 DB", "Google Play", "CloudWatch", "Langfuse" 중 하나<br>마우스를 올리거나 초점을 두면 집계 기준 안내를 툴팁으로 표시<br>서버 DB 탭 안의 Amplitude 값 카드, 차트, 표는 그 제목 옆에 "Amplitude"를 따로 표시 |
| 도움말 | 꼭 필요한 설명은 그 대상의 제목 옆 "?" 버튼에 둠<br>마우스를 올리거나 초점을 두면 툴팁으로 표시하고 본문에는 표시하지 않음 |
| 지표 정의 | 지표 화면의 요약 카드, 차트, 표 제목과 지표 열 머리 옆 "?" 툴팁에 그 지표의 정의<br>출처, 대상, 계산, 날짜를 이 순서로 한 줄씩 항목 이름과 함께 보이고 문구는 지표 정의 표에만 둠 ([2-1-17 지표 정의](#2-1-17-지표-정의))<br>그 대상에 다른 도움말이 있으면 정의 아래에 이어 보임 |
| 준비 중 알림 | 응답에 준비 중 날짜가 있을 때 요약 카드 위 |
| 요약 카드 | 기간 전체를 한 숫자로 보여 주는 카드 |
| 차트 카드 | 차트 하나와 제목, 단위 |
| 전체 수치 표 | 탭 맨 아래 접힌 표<br>차트에 그린 모든 값과 날짜 |

- 화면 문구 표에서 위치 이름이 "도움말"로 끝나는 문구는 그 대상의 제목 옆 "?" 툴팁에만 보인다. 이프 내역도 같은 방식을 쓴다.

**2. 기간**

| 항목 | 규칙 |
|---|---|
| 빠른 범위 | 오늘, 어제, 최근 7일, 최근 14일, 최근 30일, 최근 90일, 이번 주, 지난주, 이번 달, 지난달, 최근 6개월, 최근 1년 |

| 기본 기간 | URL에 기간이 없으면 화면이나 탭마다 정한 기본 기간 |
| 공유 | 기간을 고르면 그 화면의 모든 탭에 같은 기간을 적용 |
| 탭 상한 | 선택기는 현재 탭의 기간 상한을 넘는 빠른 범위를 비활성으로 표시하고 상한을 안내 |
| 상한 초과 | 다른 탭에서 고른 기간이 현재 탭의 상한을 넘으면 기간을 바꾸지 않고 탭 본문에 기간 오류를 표시<br>그 탭의 요청은 보내지 않음 |
| 끝 날짜 제한 | 리텐션 탭은 끝 날짜가 어제 이하<br>오늘이 포함된 기간이면 같은 방식으로 기간 오류 표시 |

**3. 값의 해석**

| 항목 | 규칙 |
|---|---|
| 재계산 금지 | 서버가 준 합계, 평균, 가중 평균, MAU, 전체 값을 쓰고 일별 값이나 플랫폼 값으로 다시 계산하지 않음<br>일별 고유 사용자 수는 여러 날을 더하지 않음 |

| 플랫폼 값 | 전체는 서버의 `all`, 웹은 `web`, 앱은 `android`를 그대로 표시하고 플랫폼 값끼리 더하거나 다시 계산하지 않음<br>`unknown`(플랫폼 없음)은 따로 표시하지 않고 `all`에만 들어감 |

### 2-1-3 개요

서비스의 오늘과 누적 현황, 선택 기간의 추이를 한 화면에서 본다. 기본 기간은 최근 30일이다.

**1. 요약 카드**

카드는 10개이고 순서는 오늘 활성 사용자, 아래 표 순서의 서버 DB 카드 8개, 앱 설치(Android)다. 서버 DB 카드 8개는 누적을 큰 숫자로, 오늘을 작은 줄로, 선택 기간 합계를 맨 아래 줄로 표시하며 카드를 누르면 관련 목록으로 이동한다.

| 카드 | 누적 | 오늘 | 기간 합계 | 단위 | 이동 |
|---|---|---|---|---|---|
| 가입자 | 누적 가입자 수(탈퇴 포함) | 오늘 가입 | 일별 가입 합 | 명 | 탈퇴 회원을 포함한 회원 목록 |
| 채팅 시작 | 채팅 시작 수 | 오늘 채팅 시작 | 일별 채팅 시작 합 | 개 | 채팅 목록 |
| 턴 | 턴 수 | 오늘 턴 | 일별 턴 합 | 턴 | 턴 수 순 채팅 목록 |
| 스토리 | 스토리 수 | 오늘 생성 | 일별 스토리 생성 합 | 개 | 스토리 목록 |
| 이프 적립 | 누적 적립 | 오늘 적립 | 일별 적립 합 | 이프 | 적립 이프 내역 |
| 이프 소모 | 누적 소모 | 오늘 소모 | 일별 소모 합 | 이프 | 소모 이프 내역 |
| 결제 건수 | 완료 주문 수 | 오늘 완료 | 일별 결제 건수 합 | 건 | 결제 목록 |
| 결제 금액 (환불 포함) | 완료 주문 금액 | 오늘 완료 금액 | 일별 결제 금액 합 | 원 | 결제 목록 |

- 가입자 카드 제목 옆 "?" 툴팁에 현재 회원 수(`members.active`)와 누적 탈퇴 수(`members.withdrawn`)를 둔다.

다음 두 카드 가운데 오늘 활성 사용자는 맨 앞에, 앱 설치(Android)는 맨 뒤에 둔다.

| 카드 | 큰 숫자 | 작은 줄 | 단위 | 이동 |
|---|---|---|---|---|
| 오늘 활성 사용자 | 분석 지표의 `todayActiveUsers.total` | 웹과 앱의 오늘 값 | 명 | 사용자 화면의 사용자 활동 탭 |
| 앱 설치(Android) | 설치 지표의 `totalInstalls` | `daily` 가운데 선택 기간 안 날짜의 `installs` 합<br>기간이 오늘 하루면 없음 | 대 | 유입 분석의 앱 설치 탭 |

- 오늘 활성 사용자 카드는 페이지의 기간을 적용하지 않아 기간 합계 줄이 없다. 분석 지표를 `from`과 `to` 모두 KST 오늘로 요청하고 페이지의 기간을 보내지 않는다.
- 앱 설치 카드는 큰 숫자에 페이지의 기간을 적용하지 않고 작은 줄에만 적용한다. 설치 요청에는 기간을 보내지 않고 받은 `daily`에서 `date`가 시작 날짜 이상이고 끝 날짜 이하인 항목의 `installs`를 더한다. 날짜는 `YYYY-MM-DD` 문자열로 비교하고 Play 기준 태평양 시간 날짜를 KST 기간과 그대로 맞춰 생기는 시간대 차이는 수용한다.
- 기간의 끝 날짜가 보고서의 마지막 날짜(`asOf`)보다 늦어도 `daily`에 있는 날짜만 더한다.
- 오늘 하루는 시작 날짜와 끝 날짜가 모두 KST 오늘인 기간이다. Play 보고서가 며칠 늦게 반영되어 그 기간에는 더할 날짜가 없다.
- 두 카드의 출처와 지연 안내는 카드 제목 옆 "?" 툴팁에 둔다.

| AI 비용 출처 안내 | Langfuse 출처 지표이며 {받은 시각} KST에 받은 값입니다. 금액은 Langfuse가 모델 단가로 계산한 비용을 1달러 {환율}원으로 바꾼 값이고 호출 수와 토큰 수는 서버 DB 기록입니다. 팀 계정의 호출도 포함합니다. 금액은 실패한 호출 과정의 비용도 포함하고 호출 수와 토큰 수는 성공한 호출만 셉니다. 실시간 이미지는 장당 {장당 원가}원으로 계산하며 턴당 원가와 스토리당 원가에는 넣지 않습니다. 간편 제작에는 표지와 인물 이미지 비용이 포함됩니다. |
| 비용 0 모델 안내 | 사용량은 있으나 비용이 0원인 모델: {모델 목록}. Langfuse 모델 단가 설정을 확인해 주세요. |
| 연결되지 않은 추적 안내 | 기능에 연결되지 않은 Langfuse 추적: {추적 이름과 비용}. 이 비용은 총 AI 비용에만 들어갑니다. |
| 토큰 없음 안내 | 토큰 수가 기록되지 않은 호출 {N}회가 있어 토큰 합이 실제보다 작을 수 있습니다. |
| 보관 기간 안내 | Langfuse 보관 기간({보관 일수}일)이 지나 비용 기록이 없는 날짜가 {N}일 있습니다. 해당 날짜는 턴당 원가와 스토리당 원가 계산에서 제외했습니다. 실시간 이미지 비용은 해당 날짜도 총 AI 비용에 포함합니다. |

**2. 서비스와 요청 탭**

| 요약 카드 | 값 | 단위 |
|---|---|---|

### 2-1-13 공지의 태그와 알림 문구

공지 화면은 이 세트 밖이고 이 절은 그 화면의 태그 선택과 표시, 알림 문구 입력, 게시 알림 선택의 제거만 정한다. 태그의 의미와 알림 성격은 NOTICE 세트가 정한다. ([NOTICE 4-1-4 게시](../../NOTICE/BACKEND/4-1-PIPELINES.md#4-1-4-게시))

| 위치 | 규칙 |
|---|---|
| 작성 | 제목 위에 태그 선택<br>다섯 태그를 표 순서대로 한 줄에 둔 단일 선택이며 기본 선택 없음<br>고르지 않으면 저장 버튼 비활성 |
| 알림 문구 | 공지 본문 아래에 "알림" 묶음으로 알림 제목 한 줄 입력 칸과 알림 본문 여러 줄 입력 칸<br>입력 칸 오른쪽 아래에 "{글자 수}/100", "{글자 수}/300"<br>상한을 넘는 입력은 받지 않음<br>알림 제목 칸의 자리 표시 "예: 새로운 점검 안내가 도착했어요"<br>작성과 `notifiedAt`이 없는 공지의 수정에서 알림 제목이나 알림 본문이 비었거나 공백뿐이면 저장 버튼 비활성 |
| 수정 | 현재 태그가 선택된 상태로 표시하고 바꿀 수 있음<br>`notifiedAt`이 있으면 알림 문구 칸은 읽기 전용이고 필수 검증에서 빼며 요청에 싣지 않음<br>이때 알림 문구가 `null`이어도 제목, 본문, 태그는 저장할 수 있음<br>`notifiedAt`이 없고 알림 문구가 `null`이면 빈 칸으로 두고 둘 다 입력해야 저장 |
| 목록 | 제목 앞에 태그 표시 이름을 배지로 표시 |
| 상세 | 제목 옆에 태그 배지 |
| 게시 | 알림 체크박스와 알림 유형 선택을 두지 않음<br>게시하면 태그에 따라 알림이 항상 감 |

| 태그 | 표시 이름 | 알림 성격 |
|---|---|---|
| `SERVICE` | 공지사항 | 정보성 |
| `UPDATE` | 업데이트 | 정보성 |
| `MAINTENANCE` | 점검 | 정보성 |
| `EVENT` | 이벤트 | 광고성 |
| `PROMOTION` | 홍보 | 광고성 |

| 위치 | 문구 |
|---|---|
| 알림 문구 도움말 | 푸시와 알림 내역에 보이는 제목과 본문입니다. 공지 제목, 본문과 따로 쓰며 게시할 때 한 번만 보냅니다. 이벤트와 홍보는 알림 제목 앞에 (광고)가 자동으로 붙어 따로 쓰지 않아도 됩니다. |
| 알림 문구 잠김 | 이미 알림을 요청한 공지라 알림 문구를 바꿀 수 없습니다. |
| 태그 도움말 | 공지사항, 업데이트, 점검은 활성 회원 전체의 알림 내역에 표시됩니다. 푸시는 서비스 알림 설정과 기기 수신 가능 여부에 따라 발송됩니다. 이벤트와 홍보는 광고성 알림으로 광고 수신에 동의한 활성 회원의 알림 내역에 표시되고 알림 제목 앞에 (광고)가 자동으로 붙습니다. 푸시는 광고 수신 동의, 야간 수신 동의, 기기 수신 가능 여부에 따라 발송됩니다. |
| 게시 확인, 정보성 | 게시하면 회원에게 알림이 갑니다. 게시할까요? |
| 게시 확인, 광고성 | 게시하면 광고 수신에 동의한 회원에게 광고 알림이 갑니다. 게시할까요? |
| 게시 확인, 알림 요청 이력 있음 | 이미 알림을 요청한 공지입니다. 다시 게시해도 알림을 다시 요청하지 않습니다. 게시할까요? |

- 태그 도움말은 작성 화면의 태그 라벨 옆 "?" 툴팁이다. 알림 문구 도움말은 "알림" 묶음 제목 옆 "?" 툴팁이다.
- 알림 문구 잠김은 읽기 전용 알림 문구 칸 아래에 표시한다.
- 공지의 `notifiedAt`이 있으면 태그와 무관하게 알림 요청 이력 있음 문구로 게시를 확인한다.
- 배지는 태그와 무관하게 같은 중립 모양이다. 응답의 모르는 태그는 값을 그대로 배지에 쓴다.

- 제목, 장르, 공개 범위는 상세 요약에 있어 이 구역에 다시 두지 않는다.

### 2-1-16 스토리 공개 중단

스토리 목록과 상세 화면은 이 세트 밖이고 이 절은 그 화면의 공개 중단 동작과 공개 중단 표시만 정한다. 대상 판정과 처리, 실패 조건은 MODERATION 세트에, 공개 중단 표시 필드는 BACKEND 세트에 있다. ([MODERATION 4-2-10 공개 중단](../../MODERATION/BACKEND/4-2-CONTRACT.md#4-2-10-공개-중단), [BACKEND 4-2-5 스토리 목록](../BACKEND/4-2-CONTRACT.md#4-2-5-스토리-목록))

| 항목 | 내용 |
|---|---|
| 버튼 | 스토리 상세 머리의 오른쪽<br>`scope`가 `user`이고 `owner`가 있으며 `deletedAt`과 `takenDownAt`이 모두 `null`일 때만 둠<br>누르면 확인 대화상자를 엶 |
| 확인 대화상자 | 제목 "스토리 공개 중단"과 위험 작업 확인 문구<br>사유 분류 단일 선택(필수, 아래 표 순서, 기본 선택 없음)<br>기타를 고르면 사유 분류 아래에 입력 사유 한 줄 칸(필수, 칸 오른쪽 아래 "{글자 수}/100", 100자를 넘는 입력은 받지 않음)과 입력 사유 라벨 옆 "?" 툴팁<br>다른 분류로 바꾸면 입력 사유 칸과 입력한 값이 사라짐<br>메모 여러 줄 입력 칸(선택, 칸 오른쪽 아래 "{글자 수}/500", 500자를 넘는 입력은 받지 않음)<br>메모 라벨 옆 "?" 툴팁에 메모 도움말<br>취소와 확인 버튼 |
| 확인 버튼 | 사유 분류를 고르기 전에는 비활성<br>기타인데 입력 사유가 비었거나 공백뿐이면 비활성이고 입력 사유 칸 아래에 누락 문구 |
| 확인 | `POST /api/moderation/stories/{storyId}/takedown`에 `reasonCode`와 앞뒤 공백을 지운 `memo`<br>지운 뒤 메모가 비면 `memo`를 싣지 않음<br>기타면 앞뒤 공백을 지운 `reasonDetail`을 싣고 그 밖의 분류는 싣지 않음<br>처리 중에는 버튼, 선택, 입력 칸을 비활성으로 두고 확인 버튼에 "처리 중…" |
| 성공 | 대화상자를 닫고 그 스토리 상세와 스토리 목록의 캐시를 무효화한 뒤 상세를 다시 요청<br>"공개 중단 조치를 적용했습니다." 성공 알림을 4초 보임 |
| 실패 | 대화상자를 열어 둔 채 입력 칸 아래에 오류 문구<br>409는 상세도 다시 요청<br>404는 스토리 목록의 캐시만 무효화하고 상세는 다시 요청하지 않음 |
| 목록 표시 | `takenDownAt`이 있는 행은 상세로 가는 링크 옆에 "공개 중단됨" 배지<br>"삭제됨" 배지와 함께면 그 뒤 |
| 상세 머리 | `takenDownAt`이 있으면 제목 옆에 "공개 중단됨" 배지, 공개 중단 시각 라벨과 `takenDownAt`의 KST 날짜와 시분, 공개 중단 사유 라벨과 사유 분류 표시 이름<br>`takedownReason`이 `ETC`면 "기타 ({takedownReasonDetail})" |
| 배지 | 삭제 배지와 같은 모양 ([2-1-15 삭제된 스토리와 채팅](#2-1-15-삭제된-스토리와-채팅)) |
