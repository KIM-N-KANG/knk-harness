# 5-2 배포

이 문서는 관리자 웹의 빌드와 배포 경로, 환경 변수, 배포 조건, 되돌리기를 정한다.

서버 쪽 배포 조건은 BACKEND 배포에, 데이터 모드의 동작은 데이터 연동에 있다. ([BACKEND 6 배포](../BACKEND/6-DEPLOYMENT.md), [3-2-4 데이터 모드](3-2-DATA-INTEGRATION.md#3-2-4-데이터-모드))

<br>

### 5-2-1 배포 경로

| 단계 | 내용 |
|---|---|
| 검사 | PR과 `dev` push마다 린트, 타입 검사, 테스트, 빌드 |
| 빌드와 배포 | Vercel이 저장소 연결로 빌드하고 배포 |
| 운영 주소 | `https://admin.manyak.app` |
| 서버 계약 반영 | 개발 서버 OpenAPI에서 관리자 경로를 추출해 스냅샷으로 저장하고 생성 스키마와 연산 목록을 다시 만듦 |

<br>

### 5-2-2 환경 변수

| 이름 | 기본값 | 주입 출처 | 비고 |
|---|---|---|---|
| `API_BASE_URL` | 빈 값 | Vercel 환경 변수 | manyak-server 기본 URL<br>브라우저에 노출하지 않음 |
| `ADMIN_DATA_SOURCE` | 빈 값 | Vercel 환경 변수 | `server` 또는 `fixture`<br>빈 값은 `fixture`<br>운영은 `server` |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | 빈 값 | Vercel 환경 변수 | Google OAuth 웹 클라이언트 ID<br>빌드 때 브라우저 코드에 포함 |

<br>

### 5-2-3 배포 조건

| 확인 항목 | 기준 |
|---|---|
| 서버 선행 | 화면이 부르는 서버 API가 운영 서버에 먼저 배포됨<br>공개 중단 버튼은 서버의 공개 중단 API와 스토리 응답의 `takenDownAt`이 배포된 뒤에 보임 |
| OpenAPI 스냅샷 | 새 서버 API가 관리자 OpenAPI 스냅샷과 생성 스키마에 들어 있음<br>없으면 서버 모드에서 없는 경로로 응답 |
| 고정 데이터 | 새 BFF 경로마다 고정 데이터 응답이 있음 |
| 계약 동반 | 서버 응답 필드가 바뀌면 웹과 서버를 함께 배포 |
| 코드 검사 | 린트, 타입 검사, 테스트, 빌드 통과 |
| 운영 데이터 모드 | `ADMIN_DATA_SOURCE=server` |
| Google 클라이언트 | 관리자 주소가 Google 클라이언트의 승인된 JavaScript 원본에 있고 같은 클라이언트 ID가 서버 허용 목록에 있음 |

<br>

### 5-2-4 배포 후 확인

| 확인 항목 | 기준 |
|---|---|
| 로그인 | 관리자 계정으로 로그인하면 개요가 열림 |
| 개요 | 요약 카드 10개와 일별 추이가 각각 값을 보임 |
| 인프라 | 서비스와 요청 탭의 태스크 카드 3개와 차트, 저장소 탭의 세 구역, DB 테이블 탭의 표가 값을 보임 |
| 지표 화면 | 유입 분석, 사용자, 전환, 기능과 품질의 기본 탭이 값을 보임<br>준비 중 날짜가 있으면 60초 뒤 같은 요청을 다시 보냄<br>서버의 비용 예산이 남아 조회에 성공하면 준비 중 날짜가 줄어듦 |
| 이프 내역 | 첫 페이지 20행 |
| 검수 제출 | 목록 첫 페이지와 반려 행의 상세<br>운영에서는 해제를 시험하지 않음 |
| 스토리 공개 중단 | 회원 스토리 상세에 공개 중단 버튼이 있고 오리지널 상세에는 없음<br>운영에서는 공개 중단을 시험하지 않음 |

<br>

### 5-2-5 되돌리기

| 상황 | 방법 | 확인 |
|---|---|---|
| 화면 오류 | Vercel에서 직전 운영 배포로 되돌림 | 되돌린 배포의 화면이 서버 계약과 맞는지 |
| 서버 API 미배포 | 웹을 직전 배포로 되돌리거나 서버를 먼저 배포 | 새 화면 요청이 없는 경로로 응답하지 않는지 |
| 환경 변수 오류 | Vercel 환경 변수를 고친 뒤 다시 배포 | 데이터 요청이 "서버 연결 설정 필요"로 응답하지 않는지 |
