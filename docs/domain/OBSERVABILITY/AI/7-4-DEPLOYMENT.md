# 7-4 배포

이 문서는 에이전트의 실행 단위, 운영 태스크와 운영 설정의 주입, 실행 조건, 환경 변수와 비밀 정보, 설정 변경과 복구, 운영 준비를 정한다.

운영 제약과 임시 저장의 한계는 2-2 운영 요구사항에, 설정 항목과 덮어쓰기 규칙은 5 계약에 있다. ([2-2-6 운영 제약](2-2-OPERATION-REQUIREMENTS.md#2-2-6-운영-제약), [2-2-7 운영 특성과 한계](2-2-OPERATION-REQUIREMENTS.md#2-2-7-운영-특성과-한계), [5-2 설정 파일](5-CONTRACT.md#5-2-설정-파일))

<br>

### 7-4-1 실행 단위

| 항목 | 구성 |
|---|---|
| 형태 | `manyak-diagnosis` 저장소의 Python 패키지와 그 컨테이너 이미지. 저장소는 공개를 전제로 함 |
| 재생 모드 | 운영자 PC에서 명령줄로 실행 |
| 실시간 모드 | 운영 ECS 클러스터의 Fargate 서비스 하나 |
| 포함 | 에이전트 코드, 프롬프트, 채점기, 재적재 스크립트, 예시 설정 파일, 재생 구간별 시스템 설명서 |
| 제외 | 운영 설정 파일, 운영 시스템 설명서, 벤치마크 보관 자료, 정답 파일, 실행 폴더, 세션 파일, 비밀값 |
| 배포 파이프라인 | 없음. 재생은 저장소를 받아 의존성을 설치하면 실행 가능. 실시간은 운영자가 이미지를 빌드해 올리고 서비스를 새로 배포함 |

| 의존 대상 | 연결 실패 시 동작 |
|---|---|
| 재생용 OpenSearch | 시작 검사 실패로 종료 |
| 운영 OpenSearch, CloudWatch | 실시간 모드 시작 검사 실패로 종료 |
| Parameter Store | 설정 위치가 Parameter Store인 실행의 시작 검사 실패로 종료 |
| Secrets Manager와 비밀 파일 | 시작 검사 실패로 종료 |
| 슬랙 | 슬랙을 켠 실행의 시작 검사 실패로 종료. 실행 중 전송 실패는 실행 실패 기록 |
| 코드 저장소 | 시작 때 받지 못하면 시작 검사 실패로 종료. 실행 중 갱신 실패는 받아 둔 커밋으로 계속 |
| 모델 API | 키 누락은 시작 검사 실패. 호출 실패는 실행 실패 기록 |

실시간 모드에서 프로세스가 끝나면 ECS가 태스크를 다시 띄운다.

### 7-4-2 운영 태스크

운영 태스크의 인프라는 manyak-terraform 저장소의 운영 환경 정의가 소유한다. 적용(terraform apply)은 사람이 한다.

| 항목 | 값 |
|---|---|
| 클러스터 | 운영 ECS 클러스터 `manyak-prod` |
| 서비스 | Fargate 서비스 하나. 원하는 태스크 수 1. 오토스케일링 없음 |
| 태스크 크기 | 1 vCPU와 메모리 2048MB. Agent SDK 문서가 권하는 출발점(에이전트당 메모리 1GiB, CPU 1, 디스크 5GiB) 이상으로 잡음 |
| 임시 저장소 | Fargate 태스크의 기본 임시 저장소 20GiB. 세션 파일, 실행 폴더, 코드 사본, 조치 작업 공간을 둠 |
| 배포 방식 | 이전 태스크를 멈춘 뒤 새 태스크를 띄움(최소 정상 비율 0%, 최대 비율 100%). 슬랙 소켓 연결과 감시가 두 태스크에서 함께 돌지 않게 함 |
| 네트워크 | 운영 앱 사설 서브넷. 공개 IP 없음. 보안 그룹은 들어오는 규칙 없이 HTTPS 나가는 연결만 허용 |
| 이미지 | ECR 저장소 `manyak-diagnosis`의 `:latest`. 같은 이미지에 커밋 해시 태그를 함께 붙임 |
| 설정 | 운영 설정 파일과 운영 시스템 설명서는 manyak-terraform 저장소에 두고 terraform이 Parameter Store 파라미터 `/manyak/prod/diagnosis/config`, `/manyak/prod/diagnosis/system-description`으로 올림<br>태스크 정의의 `DIAG_CONFIG`가 앞 파라미터를 `ssm:` 위치로 가리킴<br>운영 설정 변경도 운영 정의처럼 PR 검토와 적용 이력을 남기려고 manyak-terraform이 관리함 |
| 실행 인자 | 실시간 모드, 실행 폴더 상위 경로 |
| 로그 | 표준 출력과 표준 오류를 CloudWatch Logs 로그 그룹 `/ecs/manyak-prod-diagnosis`로 보냄. 보관 7일 |
| 헬스 체크 | 없음 |

| 역할 | 권한 |
|---|---|
| 태스크 역할 | `cloudwatch:GetMetricData`(지표 읽기)<br>`application-autoscaling:DescribeScalingActivities`(확장 이력 읽기)<br>`cloudwatch:DescribeAlarmHistory`(경보 이력 읽기)<br>진단 비밀 하나의 `secretsmanager:GetSecretValue`<br>진단 설정 파라미터 둘의 `ssm:GetParameter` |
| 실행 역할 | ECS 기본 실행 정책. 이미지 받기와 로그 쓰기 |

로그는 FireLens로 OpenSearch에 보내지 않는다. FireLens는 태스크 역할에 OpenSearch 쓰기 권한을 붙여야 해서 관측 저장소를 읽기만 한다는 제약을 어긴다.

운영 설정 파일은 예시 설정 파일과 아래 값이 다르다. 나머지는 같다.

| 키 | 운영 값 |
|---|---|
| `system_description` | `ssm:/manyak/prod/diagnosis/system-description` |
| `opensearch.url` | 운영 OpenSearch 주소 |
| `opensearch.user` | 운영 OpenSearch의 읽기 전용 사용자 |
| `opensearch.log_index` | `manyak-logs-prod-*` |
| `log_samples` | `false` |
| `session_dir` | 태스크 임시 저장소의 폴더 |
| `slack.channel` | 운영 알림 채널 ID |

### 7-4-4 환경 변수와 비밀 정보

설정 파일 위치와 비밀값 출처는 환경 변수로만 받는다. 설정 파일 위치는 설정 파일보다 먼저 알아야 한다. 비밀값 출처는 그 비밀을 읽는 권한과 같은 곳(운영자 PC, 태스크 정의)에서 정한다.

| 이름 | 기본값 | 주입 출처 | 비고 |
|---|---|---|---|
| `DIAG_CONFIG` | 없음 | 운영자 셸과 태스크 정의 | 설정 파일 위치. 파일 경로이거나 `ssm:` 뒤에 Parameter Store 파라미터 이름 |
| `DIAG_SECRET_ID` | 빈 값 | 태스크 정의 | Secrets Manager 비밀 이름 |
| `DIAG_SECRETS_FILE` | 빈 값 | 운영자 셸 | 비밀 파일 경로 |

`DIAG_SECRET_ID`와 `DIAG_SECRETS_FILE`은 하나만 둔다. 그 밖의 `DIAG_` 환경 변수는 설정 파일 값의 덮어쓰기다. 실행 모드, 슬랙 연결 여부, 재생 구간, 구간 당시 커밋, 지표 파일 경로, 실행 폴더 상위 경로는 실행 인자로 준다.

Secrets Manager 비밀과 비밀 파일은 같은 키를 담는다. 마냑의 실시간 모드는 비밀 `manyak/prod/diagnosis`를, 재생 모드는 운영자 PC의 비밀 파일을 쓴다. 슬랙을 켜지 않은 재생은 슬랙 키와 GitHub 키를 비워 둘 수 있다.

| 키 | 담는 값 | 쓰는 곳 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 모델 API 키 | SDK 하위 프로세스 환경 |
| `SLACK_BOT_TOKEN` | 슬랙 봇 토큰 | 슬랙 연결기 |
| `SLACK_APP_TOKEN` | 슬랙 앱 토큰. 소켓 모드 연결 | 슬랙 연결기 |
| `GITHUB_TOKEN` | 코드 저장소 토큰 | 저장소 작업 공간과 SDK 하위 프로세스 환경 |
| `OPENSEARCH_PASSWORD` | `opensearch.user`의 비밀번호 | 자료 접근기 |

실시간 모드는 코드가 시작 때 Secrets Manager를 직접 읽는다. 태스크 정의의 비밀 주입은 값을 컨테이너 환경 변수로 넣는다. 그러면 코드가 지우기 전까지 값이 프로세스 환경에 남고 지우기를 빠뜨리면 SDK 하위 프로세스가 물려받는다. 같은 이유로 환경 변수에서 비밀값을 직접 받는 출처는 두지 않는다. 읽은 직후 `os.environ`에서 지워도 지우기를 빠뜨린 경로 하나로 `Bash`가 물려받는다. 같은 일은 비밀 파일 출처로 할 수 있다. 비밀값은 저장소, 실행 폴더, 스레드, 로그에 쓰지 않는다.

### 7-4-5 설정 변경과 복구

| 변경 | 방법 | 확인 |
|---|---|---|
| 설정 값(모델, 추론 강도, 한도, 탐지 기준값, 필드 대응표, 저장소, 채널) | 재생: 설정 파일이나 `DIAG_` 환경 변수<br>실시간: manyak-terraform의 운영 설정 파일이나 태스크 정의 환경 변수를 고쳐 적용한 뒤 서비스를 새로 배포 | `run.json`과 시작 로그에 남은 적용 값<br>모델, 추론 강도, 탐지 기준값은 6-4 재평가 |
| 프롬프트 | 코드의 프롬프트 파일과 6-1 동시 수정 | 6-4 재평가. 조율 규칙만 바꿔도 같은 프롬프트 해시가 바뀌므로 재평가함 |
| 시스템 설명서 | 재생: 구간별 파일<br>실시간: manyak-terraform의 운영 시스템 설명서를 고쳐 적용한 뒤 서비스를 새로 배포 | 구간별 파일은 구간 표와 대조<br>운영 파일은 manyak-terraform의 운영 설정과 대조 |
| 비밀값 | Secrets Manager 비밀의 기존 키를 보존해 합친 값으로 덮어쓴 뒤 서비스를 새로 배포 | 시작 검사 통과 |
| 태스크 크기, 권한, 네트워크 | manyak-terraform의 운영 정의를 고쳐 머지한 뒤 적용 | 서비스가 새 태스크 정의로 돎 |

실시간 모드의 코드 변경은 이미지를 빌드해 ECR에 커밋 해시 태그와 `:latest`로 올린 뒤 서비스를 새로 배포해 반영한다. 되돌리기는 이전 커밋 해시 태그를 `:latest`로 다시 붙이고 새로 배포하는 것이다.

### 7-4-6 운영 준비

사람이 아래 순서로 준비한다.

| 순서 | 할 일 | 확인 |
|---|---|---|
| 1 | 모델 API 키, 슬랙 앱(소켓 모드, 알림 채널 하나에 봇 초대), GitHub 토큰(7-4-3의 범위)을 준비함 | 7-4-3 토큰 범위 |
| 2 | 운영 OpenSearch에 읽기 전용 내부 사용자를 만들고 운영 설정 파일의 로그 인덱스와 스팬 인덱스 패턴의 검색만 허용하는 역할에 매핑함 | 그 사용자로 다른 인덱스를 검색하면 거부됨 |
| 3 | manyak-terraform에 ECR 저장소, 태스크 역할과 실행 역할, 보안 그룹, 로그 그룹, 진단 비밀, 운영 설정 파일과 운영 시스템 설명서와 그 두 파라미터, 태스크 정의, 원하는 태스크 수 0인 서비스를 더하는 PR을 머지하고 운영에 적용함 | 적용 계획에 기존 운영 서비스의 변경이 없음 |
| 4 | 진단 비밀에 7-4-4의 다섯 키를 넣음 | 태스크 역할로만 읽힘 |
| 5 | 이미지를 빌드해 ECR에 올림 | 커밋 해시 태그와 `:latest`가 같은 이미지 |
| 6 | 원하는 태스크 수를 1로 바꿔 적용함 | 7-2-7의 운영 연결 |
