# 7-4 배포

이 문서는 에이전트의 실행 단위, 운영 태스크와 운영 설정의 주입, 실행 조건과 단계 전환, 환경 변수와 비밀 정보, 설정 변경과 복구, 운영 준비를 정한다.

운영 제약과 임시 저장의 한계는 2-2 운영 요구사항에 있고 설정 항목과 덮어쓰기 규칙은 5 계약에 있다. ([2-2-6 운영 제약](2-2-OPERATION-REQUIREMENTS.md#2-2-6-운영-제약), [2-2-7 운영 특성과 한계](2-2-OPERATION-REQUIREMENTS.md#2-2-7-운영-특성과-한계), [5-2 설정 파일](5-CONTRACT.md#5-2-설정-파일), [5-3 자료 원천](5-CONTRACT.md#5-3-자료-원천))

<br>

### 7-4-1 실행 단위

| 항목 | 구성 |
|---|---|
| 형태 | `manyak-diagnosis` 저장소의 Python 패키지와 그 컨테이너 이미지. 저장소는 공개를 전제로 함 |
| 1단계 | 운영자 PC에서 상주 실행 |
| 2단계 | 운영 ECS 클러스터의 Fargate 서비스 하나 |
| 포함 | 에이전트 코드, 프롬프트, 예시 설정 파일. 외부 MCP 서버 패키지는 에이전트 의존성에 고정 버전으로 넣어 에이전트와 같은 환경에 설치함. 이미지에도 그 버전을 미리 설치함 |
| 제외 | 운영 설정 파일, 실행 폴더, 세션 파일, 비밀값 |
| 배포 파이프라인 | 없음. 1단계는 저장소를 받아 의존성을 설치하면 실행 가능. 2단계는 운영자가 이미지를 빌드해 올리고 서비스를 새로 배포함 |

| 의존 대상 | 연결 실패 시 동작 |
|---|---|
| 운영 OpenSearch와 CloudWatch | 시작 검사 실패로 종료 |
| 외부 MCP 서버 | 실행 파일이 없으면 시작 검사 실패로 종료. 세션을 열 때 연결하지 못하면 그 진단의 실행 실패 기록 |
| AMP | `prometheus.workspace_url`을 채운 실행에서 연결하지 못하면 그 진단의 실행 실패 기록 |
| Parameter Store | 설정 위치가 Parameter Store인 실행의 시작 검사 실패로 종료 |
| Secrets Manager와 비밀 파일 | 시작 검사 실패로 종료 |
| 슬랙 | 시작 검사 실패로 종료. 실행 중 전송 실패는 실행 실패 기록 |
| 코드 저장소 | 시작 때 받지 못하면 시작 검사 실패로 종료. 실행 중 갱신 실패는 받아 둔 커밋으로 계속 |
| 모델 API | 키 누락은 시작 검사 실패. 호출 실패는 실행 실패 기록 |

2단계에서 프로세스가 끝나면 ECS가 태스크를 다시 띄운다.

### 7-4-2 운영 태스크

2단계 운영 태스크의 인프라는 manyak-terraform 저장소의 운영 환경 정의에서 관리한다. 적용(terraform apply)은 사람이 한다.

| 항목 | 값 |
|---|---|
| 클러스터 | 운영 ECS 클러스터 `manyak-prod` |
| 서비스 | Fargate 서비스 하나. 원하는 태스크 수 1. 오토스케일링 없음 |
| 태스크 크기 | 1 vCPU와 메모리 2048MB. Agent SDK 문서가 권하는 출발점(에이전트당 메모리 1GiB, CPU 1, 디스크 5GiB) 이상으로 잡음 |
| 임시 저장소 | Fargate 태스크의 기본 임시 저장소 20GiB. 세션 파일, 실행 폴더, 코드 사본을 둠 |
| 배포 방식 | 이전 태스크를 멈춘 뒤 새 태스크를 띄움(최소 정상 비율 0%와 최대 비율 100%). 슬랙 소켓 연결과 감시가 두 태스크에서 동시에 실행되지 않게 함 |
| 네트워크 | 운영 앱 사설 서브넷. 공개 IP 없음. 보안 그룹은 인바운드 규칙 없이 HTTPS 아웃바운드 연결만 허용 |
| 이미지 | ECR 저장소 `manyak-diagnosis`의 `:latest`. 같은 이미지에 커밋 해시 태그를 함께 붙임 |
| 설정 | 운영 설정 파일은 manyak-terraform 저장소에 두고 terraform이 Parameter Store 파라미터 `/manyak/prod/diagnosis/config`로 올림<br>태스크 정의의 `DIAG_CONFIG`가 그 파라미터를 `ssm:` 위치로 가리킴 |
| 실행 인자 | 실행 폴더 상위 경로 |
| 로그 | 표준 출력과 표준 오류를 CloudWatch Logs 로그 그룹 `/ecs/manyak-prod-diagnosis`로 보냄. 보관 7일 |
| 헬스 체크 | 없음 |

| 역할 | 권한 |
|---|---|
| 태스크 역할 | `cloudwatch:GetMetricData`와 `cloudwatch:ListMetrics`(지표 읽기)<br>`cloudwatch:DescribeAlarms`와 `cloudwatch:DescribeAlarmHistory`(경보 읽기)<br>`application-autoscaling:DescribeScalingActivities`(확장 이력 읽기)<br>운영 AMP 작업 공간의 질의 권한<br>진단 비밀 하나의 `secretsmanager:GetSecretValue`<br>진단 설정 파라미터 하나의 `ssm:GetParameter` |
| 실행 역할 | ECS 기본 실행 정책. 이미지 받기와 로그 쓰기 |

태스크 역할에는 CloudWatch Logs 읽기 권한을 주지 않는다. 로그 원문은 FLS를 거치는 OpenSearch로만 읽는다. 로그는 FireLens로 OpenSearch에 보내지 않는다. FireLens는 태스크 역할에 OpenSearch 쓰기 권한을 부여해야 해서 관측 저장소를 읽기만 한다는 제약을 어긴다.

운영 설정 파일은 예시 설정 파일과 아래 값이 다르다. 나머지는 같다.

| 키 | 운영 값 |
|---|---|
| `aws.profile` | 빈 값 |
| `opensearch.url` | 운영 OpenSearch 주소 |
| `opensearch.user` | 운영 OpenSearch의 에이전트용 읽기 전용 사용자 |
| `prometheus.workspace_url` | 운영 AMP 작업 공간 주소 |
| `session_dir` | 태스크 임시 저장소의 폴더 |
| `slack.channel` | 운영 알림 채널 ID |
| `slack.timezone` | `Asia/Seoul` |

1단계 설정 파일은 운영자 PC에 둔다. `aws.profile`은 운영자 PC의 읽기 전용 프로필 이름이고 `session_dir`은 운영자 PC의 폴더다. 나머지 값은 운영 설정 파일과 같다.

### 7-4-4 환경 변수와 비밀 정보

설정 파일 위치와 비밀값 출처는 환경 변수로만 받는다. 설정 파일 위치는 설정 파일보다 먼저 알아야 한다. 비밀값 출처는 그 비밀을 읽는 권한과 같은 곳(운영자 PC와 태스크 정의)에서 정한다.

| 이름 | 기본값 | 주입 출처 | 비고 |
|---|---|---|---|
| `DIAG_CONFIG` | 없음 | 운영자 셸과 태스크 정의 | 설정 파일 위치. 파일 경로이거나 `ssm:` 뒤에 Parameter Store 파라미터 이름 |
| `DIAG_SECRET_ID` | 빈 값 | 태스크 정의 | Secrets Manager 비밀 이름 |
| `DIAG_SECRETS_FILE` | 빈 값 | 운영자 셸 | 비밀 파일 경로 |

`DIAG_SECRET_ID`와 `DIAG_SECRETS_FILE`은 하나만 둔다. 그 밖의 `DIAG_` 환경 변수는 설정 파일 값의 덮어쓰기다. 실행 폴더 상위 경로는 실행 인자로 준다.

Secrets Manager 비밀과 비밀 파일은 같은 키를 담는다. 마냑의 2단계는 비밀 `manyak/prod/diagnosis`를 쓰고 1단계는 운영자 PC의 비밀 파일을 쓴다.

| 키 | 담는 값 | 쓰는 곳 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 모델 API 키 | SDK 하위 프로세스 환경 |
| `SLACK_BOT_TOKEN` | 슬랙 봇 토큰 | 슬랙 연결기 |
| `SLACK_APP_TOKEN` | 슬랙 앱 토큰. 소켓 모드 연결 | 슬랙 연결기 |
| `OPENSEARCH_PASSWORD` | `opensearch.user`의 비밀번호 | 자료 접근기와 `opensearch` MCP 서버 환경 |
| `GITHUB_READ_TOKEN` | 비공개 저장소의 내용 읽기만 가진 토큰. 비공개 저장소가 없으면 비워 둠 | 저장소 사본 관리자의 git 자격 |

`GITHUB_READ_TOKEN`은 manyak-terraform이 비공개 저장소라서 둔다. 코드 사본을 이미지에 넣지 않고 시작 때 받는 이유는 진단 세션마다 운영 반영 브랜치의 최신 커밋으로 맞추기 위해서다.

2단계는 코드가 시작할 때 Secrets Manager를 직접 읽는다. 태스크 정의의 비밀 주입은 값을 컨테이너 환경 변수로 넣어 모든 하위 프로세스가 물려받게 한다. 코드가 직접 읽으면 값마다 그 값을 쓰는 프로세스에만 넘길 수 있다. 같은 이유로 환경 변수에서 비밀값을 직접 받는 출처는 두지 않는다. 비밀값은 저장소, 실행 폴더, 스레드, 로그에 쓰지 않는다.

### 7-4-5 설정 변경과 복구

| 변경 | 방법 | 확인 |
|---|---|---|
| 설정값(모델, 추론 강도, 한도, 탐지 기준값, 필드 대응표, 서비스 지도, 저장소, 채널) | 1단계: 설정 파일이나 `DIAG_` 환경 변수를 고쳐 다시 시작<br>2단계: manyak-terraform의 운영 설정 파일이나 태스크 정의 환경 변수를 고쳐 적용한 뒤 서비스를 새로 배포 | `run.json`과 시작 로그에 남은 적용 값 |
| 프롬프트 | 코드의 프롬프트 파일과 6-1 동시 수정 | `run.json`의 프롬프트 해시 |
| MCP 서버 패키지 버전 | 고정 버전을 올림 | 7-2-6의 노출 도구 케이스. 활성화한 도구 이름이 6-1-5와 같음 |
| 비밀값 | Secrets Manager 비밀의 기존 키를 보존해 합친 값으로 덮어쓴 뒤 서비스를 새로 배포 | 시작 검사 통과 |
| 태스크 크기, 권한, 네트워크 | manyak-terraform의 운영 정의를 고쳐 머지한 뒤 적용 | 서비스가 새 태스크 정의로 실행됨 |

2단계의 코드 변경은 이미지를 빌드해 ECR에 커밋 해시 태그와 `:latest`로 올린 뒤 서비스를 새로 배포해 반영한다. 되돌리려면 이전 커밋 해시 태그를 `:latest`로 다시 붙이고 새로 배포한다.

### 7-4-6 운영 준비

사람이 아래 순서로 준비한다.

| 순서 | 할 일 | 확인 |
|---|---|---|
| 1 | 모델 API 키를 준비함. Anthropic 콘솔에 전체 예산 $100에 맞춘 지출 한도와 지출 알림을 둬서 전체 예산 소진에 대응함 | 콘솔에 지출 한도와 알림이 있음 |
| 2 | 슬랙 앱(소켓 모드, 봇 멘션과 채널 메시지 이벤트 구독, 반응 쓰기 `reactions:write` 범위, 알림 채널 하나에 봇 초대)과 저장소 읽기 토큰을 준비함 | 7-4-3 토큰 범위 |
| 3 | 운영 OpenSearch에 에이전트용 읽기 전용 내부 사용자를 만들고 5-3-3의 역할에 매핑함. 역할에 두 인덱스 패턴의 읽기만 허용하고 FLS 제외 필드 목록을 `redact_fields`와 같게 둠 | 그 사용자로 다른 인덱스를 검색하면 거부됨. 두 인덱스의 검색 결과에 제외 필드가 없음 |
| 4 | 운영 계정에 7-4-2 태스크 역할과 같은 읽기 권한만 가진 역할을 만들고 운영자 PC에 그 역할의 AWS 프로필을 둠 | 그 프로필로 쓰기 API를 부르면 거부됨 |
| 5 | 운영자 PC에 1단계 설정 파일과 비밀 파일을 두고 상주 실행을 시작함 | 7-2-8의 1단계 운영 연결 |
| 6 | 2단계 전환 조건을 확인한 뒤 manyak-terraform에 ECR 저장소, 태스크 역할과 실행 역할, 보안 그룹, 로그 그룹, 진단 비밀, 운영 설정 파일과 그 파라미터, 태스크 정의, 원하는 태스크 수 0인 서비스를 더하는 PR을 머지하고 운영에 적용함 | 적용 계획에 기존 운영 서비스의 변경이 없음 |
| 7 | 진단 비밀에 7-4-4의 키를 넣음 | 태스크 역할로만 읽힘 |
| 8 | 이미지를 빌드해 ECR에 올림 | 커밋 해시 태그와 `:latest`가 같은 이미지 |
| 9 | 1단계 실행을 멈추고 원하는 태스크 수를 1로 바꿔 적용함 | 7-2-8의 2단계 운영 연결. 슬랙에 보고가 두 번 올라오지 않음 |
