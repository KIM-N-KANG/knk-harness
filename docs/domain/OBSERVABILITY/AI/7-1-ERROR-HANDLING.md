# 7-1 오류 처리

이 문서는 실행 단계별 오류의 조건, 처리 위치, 재시도와 한도, 최종 기록을 정한다.

실행 실패 기록의 필드는 5 계약에, 루프와 검사 순서는 6-1 AI 실행에 있다. ([5-6 실행 폴더](5-CONTRACT.md#5-6-실행-폴더), [6-1-6 응답 검사와 최종 출력](6-1-AI-EXECUTION.md#6-1-6-응답-검사와-최종-출력), [6-1-7 조율 턴](6-1-AI-EXECUTION.md#6-1-7-조율-턴))

<br>

### 7-1-1 오류 분류

| 단계 | 오류 | 탐지 |
|---|---|---|
| 시작 | 설명서 파일 없음, 필수 필드 누락, 환경 변수 누락, 비밀값 읽기 실패 | 시작 검사 |
| 시작 | 코드 사본이나 조치 작업 공간을 받지 못함 | 시작 검사 |
| 시작 | 재생 자료의 인덱스나 지표 파일이 없음 | 시작 검사 |
| 감시 | 조회 실패(연결, 인증, 시간 초과) | 자료 접근기 |
| 진단 | 실시간 모드의 하루 비용 상한 초과 | 후보 관리자 |
| 진단 | 코드 사본을 최신으로 맞추지 못함 | 저장소 작업 공간 |
| 진단 | 조회 실패 | 도구 함수 |
| 진단 | 모델 호출 실패(연결, 한도, 서버 오류, 시간 초과) | SDK |
| 진단 | 모델이 거절(`refusal`)하거나 출력 토큰 한도에 닿음 | 루프 |
| 진단 | 제출 없이 글만 돌려줌 | 루프 |
| 진단 | 출력 간 조건 위반, 제출 입력 스키마 위반 | 보고 검사기 |
| 진단 | 조회 25회나 5분 소진 | 진단 실행기 |
| 진단 | 진단 턴 비용 한도 도달 | SDK |
| 진단 | 보고 제출 전 수정 도구 호출, 명령 도구 호출, 코드 사본 밖 읽기 | 턴 전 훅 |

| 조율 | 조치 작업 공간을 최신으로 맞추지 못함 | 저장소 작업 공간 |
| 조율 | 조율 턴 모델 호출 실패 | SDK |
| 조율 | 승인 응답 없음 | 승인 관문 |
| 조율 | 세션 비용 $2.00 초과 | 진단 실행기 |
| 조치 | PR 생성 실패(push 거부, API 오류) | 저장소 작업 공간 |
| 기록 | 실행 폴더 쓰기 실패 | 보고 기록기 |

### 7-1-2 오류별 처리

| 오류 | 처리 위치 | 복구 | 최종 결과 |
|---|---|---|---|
| 시작 검사 실패 | 시작 | 없음 | 프로세스 종료. 실행 폴더를 만들지 않음 |
| 감시 중 조회 실패 | 자료 접근기 | 30초 뒤 1회 재시도 | 그 분의 신호 판정을 건너뜀. 실시간 모드는 다음 분에 계속, 재생 모드는 종료 |
| 하루 비용 상한 초과 | 후보 관리자 | 없음 | 진단을 부르지 않고 후보에 `skip_reason`을 남김. 그날 첫 생략이면 채널에 안내. 실행 실패가 아님 |
| 코드 사본 갱신 실패 | 저장소 작업 공간 | 30초 뒤 1회 재시도 | 받아 둔 커밋으로 진단을 계속함. 표준 출력에 사유를 남김 |
| 진단 중 조회 실패 | 도구 함수 | 30초 뒤 1회 재시도 | 실행 실패 `query` |
| 모델 호출 연결, 한도, 서버 오류 | SDK | SDK 자동 재시도 2회 | 실행 실패 `model` |
| 모델 호출 시간 초과 | SDK | 자동 재시도에 포함 | 실행 실패 `model` |
| 거절 | 루프 | 없음 | 실행 실패 `model`. 사유 범주를 `reason`에 남김 |
| 출력 토큰 한도 도달 | 루프 | 없음 | 실행 실패 `model` |
| 제출 없이 글만 돌려줌 | 루프 | 제출 요청 1회 | 두 번째도 미제출이면 실행 실패 `budget` |
| 출력 간 조건 위반 | 보고 검사기 | 위반 회신 1회 | 두 번째 위반이면 실행 실패 `report` |
| 제출 입력 스키마 위반 | 보고 검사기 | 없음 | 실행 실패 `report` |
| 같은 후보의 보고가 이미 있음 | 보고 기록기 | 없음 | 실행 실패 `report`. 기존 파일 유지 |
| 근거 검증 실패 | 보고 검사기 | 없음 | 보고는 기록하고 해당 근거만 `verified` 거짓 |
| 조회 25회 소진 | 진단 실행기 | 제출 요청 1회 | 미제출이면 실행 실패 `budget` |
| 5분 소진 | 진단 실행기 | 없음 | 진행 중 호출을 끊고 실행 실패 `budget` |
| 진단 턴 비용 한도 도달 | SDK | 없음 | 실행 실패 `budget` |
| 제출 전 수정 도구 호출, 명령 도구 호출, 사본 밖 읽기 | 턴 전 훅 | 거부를 도구 결과로 돌려줌 | 턴 계속. 실패 아님 |
| 슬랙 알림 전송 실패 | 슬랙 연결기 | 30초 뒤 1회 재시도 | 실행 실패 `notify`. 보고는 실행 폴더에 남고 세션은 스레드 없이 끝남 |
| 세션 없음 | 세션 관리자 | 없음 | 종료 안내 1회. 기록 없음 |
| 세션 파일을 못 읽음 | 세션 관리자 | 없음 | 실행 실패 `session`. 스레드에 안내하고 `closed_at`을 씀 |
| 조치 작업 공간 갱신 실패 | 저장소 작업 공간 | 30초 뒤 1회 재시도 | 받아 둔 커밋으로 조율 턴을 계속함. 표준 출력에 사유를 남김 |
| 조율 턴 모델 호출 실패 | SDK | SDK 자동 재시도 2회 | 실행 실패 `session`. 스레드에 안내. 세션은 열어 둠 |
| 승인 응답 없음 | 승인 관문 | 없음 | 2시간 뒤 거부로 처리. `approvals.jsonl`에 `timeout` |
| 세션 비용 초과 | 진단 실행기 | 없음 | 턴이 끝날 때 확인함. 실행 실패 `session`. 스레드에 안내하고 `closed_at`을 씀 |
| PR 생성 실패 | 저장소 작업 공간 | 명령 1회 재실행 | 실행 실패 `action`. 브랜치 이름과 사유를 스레드에 안내. `actions.jsonl`에 쓰지 않음 |
| 실행 폴더 쓰기 실패 | 보고 기록기 | 없음 | 프로세스 종료. 표준 오류에 사유 출력 |

실행 실패는 `failures.jsonl`에 한 줄로 남기고 이상 후보는 열린 채 둔다. 같은 이상 후보를 다시 진단하지 않는다. 조율 턴의 실패는 세션을 끝내는 경우만 `closed_at`을 쓰고 나머지는 다음 운영자 메시지를 기다린다.

| 복구 | 대상 | 한도 | 대기 |

| SDK 자동 재시도 | 모델 호출 전송 오류 | 2회 | SDK 기본 |
| 조회 재시도 | OpenSearch, CloudWatch 조회 실패 | 1회 | 30초 |
| 제출 요청 | 미제출, 조회 소진 | 1회 | 없음 |
| 위반 회신 | 출력 간 조건 위반 | 1회 | 없음 |
| 슬랙 재전송 | 알림 전송 실패 | 1회 | 30초 |
| 저장소 갱신 재시도 | 코드 사본과 조치 작업 공간의 갱신 실패 | 1회 | 30초 |
| PR 명령 재실행 | PR 생성 실패 | 1회 | 없음 |

| 진단 턴 비용 | $0.20 | SDK 비용 추정 기준 |
| 승인 대기 | 2시간 | 승인 메시지를 올린 뒤 |
| 세션 비용 | $2.00 | 진단 턴과 조율 턴의 합. 턴이 끝날 때 확인하므로 마지막 턴만큼 넘을 수 있음 |
| 하루 비용 | $5.00 | 실시간 모드 |
| 세션 수명 | 실시간: 이상 후보를 닫은 뒤 24시간<br>재생: 프로세스를 멈출 때까지 | 열린 이상 후보의 세션은 끝나지 않음 |

### 7-1-4 최종 실패와 전달

실행 실패에 대체 모델이나 수동 진단 경로는 없다. 운영자는 `failures.jsonl`과 `queries/`를 보고 같은 이상 후보를 다시 돌릴지 정한다. 다시 돌릴 때는 새 실행으로 하며 실패한 실행 폴더를 고치지 않는다. 세션이 끝난 뒤의 조치는 운영자가 PR을 직접 만든다.

`reason`에는 예외 종류와 요약만 넣는다. 자격 증명, 요청 본문, 식별자는 넣지 않는다.
