# 7-1 오류 처리

이 문서는 실행 단계별 오류의 조건, 처리 위치, 재시도와 한도, 최종 기록을 정한다.

설정 항목과 실행 실패 기록의 필드는 5 계약에, 시작 검사 순서는 6-2 소프트웨어 구현에, 루프와 응답 검사 순서는 6-1 AI 실행에 있다. ([5-2 설정 파일](5-CONTRACT.md#5-2-설정-파일), [5-8 실행 폴더](5-CONTRACT.md#5-8-실행-폴더), [6-2-2 설정 읽기와 시작 검사](6-2-SOFTWARE-IMPLEMENTATION.md#6-2-2-설정-읽기와-시작-검사), [6-1-6 응답 검사와 최종 출력](6-1-AI-EXECUTION.md#6-1-6-응답-검사와-최종-출력), [6-1-7 대화 턴](6-1-AI-EXECUTION.md#6-1-7-대화-턴))

### 7-1-2 오류별 처리

| 오류 | 처리 위치 | 복구 | 최종 결과 |
|---|---|---|---|
| 시작 검사 실패 | 시작 | 없음 | 프로세스 종료. 실행 폴더를 만들지 않음<br>설정 검사는 걸린 단계에서 찾은 문제를 모두 표준 오류에 한 줄씩 씀. 키나 환경 변수 이름과 이유만 쓰고 값은 쓰지 않음 |
| 탐지 조회 실패 | 자료 접근기 | 30초 뒤 1회 재시도 | 그 분의 신호 판정을 건너뛰고 다음 분에 계속함 |
| 하루 비용 상한 초과 | 후보 관리자, 슬랙 연결기 | 없음 | 진단을 부르지 않고 요청에 `skip_reason`을 남김. 5-9의 생략 안내를 올림. 실행 실패가 아님 |
| 코드 사본 갱신 실패 | 저장소 사본 관리자 | 30초 뒤 1회 재시도 | 받아 둔 커밋으로 진단을 계속함. 표준 출력에 사유를 남김 |
| MCP 서버 연결 실패 | 진단 실행기 | 없음 | 진단을 시작하지 않고 실행 실패 `query`. 사유에 서버 키를 남김 |
| 도구 오류 | 도구 | 없음 | 오류가 도구 결과로 모델에 돌아감. 모델이 다른 조회를 고르거나 판단 불가로 보고함 |
| 모델 호출 연결, 한도, 서버 오류 | SDK | SDK 자동 재시도 2회 | 실행 실패 `model` |
| 모델 호출 시간 초과 | SDK | 자동 재시도에 포함 | 실행 실패 `model` |
| 거절 | 루프 | 없음 | 실행 실패 `model`. 사유 범주를 `reason`에 남김 |
| 출력 토큰 한도 도달 | 루프 | 없음 | 실행 실패 `model` |
| 제출 없이 글만 돌려줌 | 루프 | 제출 요청 1회 | 두 번째도 미제출이면 실행 실패 `budget` |
| 출력 간 조건 위반 | 보고 검사기 | 위반 회신 1회 | 두 번째 위반이면 실행 실패 `report` |
| 제출 입력 스키마 위반 | 보고 검사기 | 없음 | 실행 실패 `report` |
| 같은 요청의 보고가 이미 있음 | 보고 기록기 | 없음 | 실행 실패 `report`. 기존 파일 유지 |
| 근거 검증 실패 | 보고 검사기 | 없음 | 보고는 기록하고 해당 근거만 `verified` 거짓 |
| 조회 25회 소진 | 진단 실행기 | 제출 요청 1회 | 미제출이면 실행 실패 `budget` |
| 5분 소진 | 진단 실행기 | 없음 | 진행 중 호출을 끊고 실행 실패 `budget` |
| 진단 턴 비용 한도 도달 | SDK | 없음 | 실행 실패 `budget` |
| 사본 밖 읽기, 연결 인자 사용 | 도구 호출 전 훅 | 거부를 도구 결과로 돌려줌 | 턴 계속. 실패 아님 |
| 슬랙 게시 실패 | 슬랙 연결기 | 30초 뒤 1회 재시도 | 실행 실패 `notify`. 보고는 실행 폴더에 남고 세션은 스레드 없이 끝남 |
| 슬랙 반응 실패 | 슬랙 연결기 | 없음 | 표준 출력에 사유를 남기고 진단과 보고를 계속함. 실행 실패가 아니고 `failures.jsonl`에 쓰지 않음 |
| 끝난 세션 | 세션 관리자 | 없음 | 종료 안내 1회. 기록 없음 |
| 세션 파일을 못 읽음 | 세션 관리자 | 없음 | 실행 실패 `session`. 스레드에 안내하고 `closed_at`을 씀 |
| 대화 턴 모델 호출 실패 | SDK | SDK 자동 재시도 2회 | 실행 실패 `session`. 스레드에 안내. 세션은 열어 둠 |
| 세션 비용 초과 | 진단 실행기 | 없음 | 턴이 끝날 때 확인함. 실행 실패 `session`. 스레드에 안내하고 `closed_at`을 씀 |
| 실행 폴더 쓰기 실패 | 보고 기록기 | 없음 | 프로세스 종료. 표준 오류에 사유 출력 |

실행 실패는 `failures.jsonl`에 한 줄로 남기고 이상 후보는 열린 채 둔다. 같은 진단 요청을 다시 진단하지 않는다. 대화 턴의 실패는 세션을 끝내는 경우만 `closed_at`을 쓰고 나머지는 다음 운영자 메시지를 기다린다.

### 7-1-3 재시도와 한도

| 복구 | 대상 | 한도 | 대기 |
|---|---|---|---|
| SDK 자동 재시도 | 모델 호출 전송 오류 | 2회 | SDK 기본 |
| 탐지 조회 재시도 | 탐지기의 OpenSearch와 CloudWatch 조회 실패 | 1회 | 30초 |
| 제출 요청 | 미제출, 조회 소진 | 1회 | 없음 |
| 위반 회신 | 출력 간 조건 위반 | 1회 | 없음 |

| 저장소 갱신 재시도 | 코드 사본의 갱신 실패 | 1회 | 30초 |

| 턴 수 | 진단 턴 30, 대화 턴 20 | 도구 호출 왕복 수 |
| 진단 턴 비용 | $0.20 | SDK 비용 추정 기준 |
| 세션 비용 | $2.00 | 진단 턴과 대화 턴의 합. 턴이 끝날 때 확인하므로 마지막 턴만큼 넘을 수 있음 |
| 하루 비용 | $5.00 | UTC 하루 |
| 세션 수명 | 이상 후보는 닫은 뒤 24시간<br>운영자 요청은 보고를 올린 뒤 24시간 | 열린 이상 후보의 세션은 끝나지 않음 |

### 7-1-4 최종 실패와 전달

실행 실패에 대체 모델이나 대체 진단 경로는 없다. 운영자는 `failures.jsonl`과 `queries/`를 보고 다시 진단할지 정한다. 다시 진단하려면 슬랙에서 봇을 멘션해 운영자 요청으로 보낸다. 실패한 기록은 고치지 않는다.

`reason`에는 예외 종류와 요약만 넣는다. 자격 증명, 요청 본문, 식별자는 넣지 않는다.
