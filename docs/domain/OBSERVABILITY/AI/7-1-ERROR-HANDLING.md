# 7-1 오류 처리

이 문서는 실행 단계별 오류의 조건, 처리 위치, 재시도와 한도, 최종 기록을 정한다.

실행 실패 기록의 필드는 5 계약에, 루프와 검사 순서는 6-1 AI 실행에 있다. ([5-6 실행 폴더](5-CONTRACT.md#5-6-실행-폴더), [6-1-6 응답 검사와 최종 출력](6-1-AI-EXECUTION.md#6-1-6-응답-검사와-최종-출력))

<br>

### 7-1-1 오류 분류

| 단계 | 오류 | 탐지 |
|---|---|---|
| 시작 | 설명서 파일 없음, 필수 필드 누락, 환경 변수 누락 | 시작 검사 |
| 시작 | 재생 자료의 인덱스나 지표 파일이 없음 | 시작 검사 |
| 감시 | 조회 실패(연결, 인증, 시간 초과) | 자료 접근기 |
| 진단 | 조회 실패 | 도구 함수 |
| 진단 | 모델 호출 실패(연결, 한도, 서버 오류, 시간 초과) | SDK |
| 진단 | 모델이 거절(`refusal`)하거나 출력 토큰 한도에 닿음 | 루프 |
| 진단 | 제출 없이 글만 돌려줌 | 루프 |
| 진단 | 출력 간 조건 위반, 제출 입력 스키마 위반 | 보고 검사기 |
| 진단 | 조회 25회나 5분 소진 | 진단 실행기 |
| 기록 | 실행 폴더 쓰기 실패 | 보고 기록기 |

<br>

### 7-1-2 오류별 처리

| 오류 | 처리 위치 | 복구 | 최종 결과 |
|---|---|---|---|
| 시작 검사 실패 | 시작 | 없음 | 프로세스 종료. 실행 폴더를 만들지 않음 |
| 감시 중 조회 실패 | 자료 접근기 | 30초 뒤 1회 재시도 | 그 분의 신호 판정을 건너뜀. 실시간 모드는 다음 분에 계속, 재생 모드는 종료 |
| 진단 중 조회 실패 | 도구 함수 | 30초 뒤 1회 재시도 | 실행 실패 `query` |
| 모델 호출 연결, 한도, 서버 오류 | SDK | SDK 자동 재시도 2회 | 실행 실패 `model` |
| 모델 호출 시간 초과 | SDK | 자동 재시도에 포함 | 실행 실패 `model` |
| 거절 | 루프 | 없음 | 실행 실패 `model`. 사유 범주를 `reason`에 남김 |
| 출력 토큰 한도 도달 | 루프 | 없음 | 실행 실패 `model` |
| 제출 없이 글만 돌려줌 | 루프 | 제출 요청 1회 | 두 번째도 미제출이면 실행 실패 `budget` |
| 출력 간 조건 위반 | 보고 검사기 | 위반 회신 1회 | 두 번째 위반이면 실행 실패 `report` |
| 제출 입력 스키마 위반 | 보고 검사기 | 없음 | 실행 실패 `report` |
| 같은 후보의 보고가 이미 있음 | 보고 기록기 | 없음 | 실행 실패 `report`. 기존 파일 유지 |
| 근거 검증 실패 | 보고 검사기 | 없음 | 보고는 기록하고 해당 근거만 `verified` 거짓 |
| 조회 25회 소진 | 진단 실행기 | 제출 요청 1회 | 미제출이면 실행 실패 `budget` |
| 5분 소진 | 진단 실행기 | 없음 | 진행 중 호출을 끊고 실행 실패 `budget` |
| 실행 폴더 쓰기 실패 | 보고 기록기 | 없음 | 프로세스 종료. 표준 오류에 사유 출력 |

실행 실패는 `failures.jsonl`에 한 줄로 남기고 이상 후보는 열린 채 둔다. 같은 이상 후보를 다시 진단하지 않는다.

<br>

### 7-1-3 재시도와 한도

| 복구 | 대상 | 한도 | 대기 |
|---|---|---|---|
| SDK 자동 재시도 | 모델 호출 전송 오류 | 2회 | SDK 기본 |
| 조회 재시도 | OpenSearch, CloudWatch 조회 실패 | 1회 | 30초 |
| 제출 요청 | 미제출, 조회 소진 | 1회 | 없음 |
| 위반 회신 | 출력 간 조건 위반 | 1회 | 없음 |

| 한도 | 값 | 포함 범위 |
|---|---|---|
| 조회 횟수 | 25회 | 재시도는 세지 않음 |
| 진단 시간 | 5분 | 조회 재시도 대기와 모델 재시도를 포함 |
| 모델 호출 시간 제한 | SDK 기본 10분 | 진단 시간 한도가 먼저 걸림 |

<br>

### 7-1-4 최종 실패와 전달

실행 실패에 대체 모델이나 수동 진단 경로는 없다. 운영자는 `failures.jsonl`과 `queries/`를 보고 같은 이상 후보를 다시 돌릴지 정한다. 다시 돌릴 때는 새 실행으로 하며 실패한 실행 폴더를 고치지 않는다.

`reason`에는 예외 종류와 요약만 넣는다. 자격 증명, 요청 본문, 식별자는 넣지 않는다.
