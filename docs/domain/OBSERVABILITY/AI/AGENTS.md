# OBSERVABILITY AI

관측 자료를 감시해 장애를 찾고 원인과 조치를 슬랙으로 보고한 뒤, 스레드에서 운영자와 조율하고 승인받은 설정값 변경을 PR로 올리는 진단 에이전트의 AI 세트다. 작업 티켓은 KNK-1556(상위 KNK-1464)이다.

<br>

### 1. 문서의 역할

| 문서 | 정하는 것 |
|---|---|
| [1 배경](1-BACKGROUND.md) | 관측 도메인, 현재 문제, 범위, 주체, 용어 |
| [2-1 유저 스토리](2-1-USER-STORY.md) | 운영자가 보고와 조율에 기대하는 성질 |
| [2-2 운영 요구사항](2-2-OPERATION-REQUIREMENTS.md) | 품질, 시간, 비용 목표와 운영 제약 |
| [3 태스크 정의](3-TASK-DEFINITION.md) | 처리 단위, 이상 후보, 진단과 조율의 입력과 출력 |
| [4-1 인지 구조](4-1-DESIGN-COGNITIVE-ARCHITECTURE.md) | 신호 규칙, 진단 전략, 모델과 코드의 책임, 세션 종료 |
| [4-2 소프트웨어 설계](4-2-DESIGN-SOFTWARE-ARCHITECTURE.md) | 시스템 경계, 실행 모드, 구성 요소, 세션과 승인의 상태 |
| [5 계약](5-CONTRACT.md) | 자료 원천, 시스템 설명서, 이상 후보와 진단 보고 필드, 실행 폴더, 슬랙 메시지, 조치 PR |
| [6-1 AI 실행](6-1-AI-EXECUTION.md) | 세션 설정, 프롬프트, 도구와 권한, 응답 검사, 조율 턴 |
| [6-2 소프트웨어 구현](6-2-SOFTWARE-IMPLEMENTATION.md) | 실행 흐름, 자료 준비, 조회 구현, 슬랙과 조율 턴, 저장소 작업, 저장, 공통 규칙 |
| [6-3 얼라인먼트](6-3-AI-ALIGNMENT.md) | 개선 대상, 허용 수단, 원인 구분, 채택 |
| [6-4 평가 방법](6-4-AI-EVALUATION-METHOD.md) | 벤치마크, 정답, 채점, 합격 판정 |
| [6-5 평가 구현](6-5-AI-EVALUATION-IMPLEMENTATION.md) | 채점기 입력, 단계, 출력, 재사용 |
| 6-6 성능 리포트 | 실행 결과. 첫 평가 뒤 작성 |
| [7-1 오류 처리](7-1-ERROR-HANDLING.md) | 오류 분류, 처리, 재시도와 한도 |
| [7-2 테스트 케이스](7-2-TEST-CASES.md) | 테스트 범위, 구성 요소별 케이스, 승인과 세션, 통합 |
| [7-3 관측](7-3-OBSERVABILITY.md) | 추적 단위, 기록 항목, 지표 |
| [7-4 배포](7-4-DEPLOYMENT.md) | 실행 단위, 조건, 환경 변수, 설정 변경 |
| [DECISIONS](DECISIONS.md) | 결정의 배경, 채택, 대안, 영향 |

<br>

### 2. 읽는 순서

| 작업 | 먼저 읽을 문서 |
|---|---|
| 에이전트가 무엇을 하는지 알기 | 1 배경, 3 태스크 정의 |
| 탐지 규칙이나 진단 전략을 바꾸기 | 4-1 인지 구조, 2-2 운영 요구사항 |
| 보고 필드나 시스템 설명서를 바꾸기 | 5 계약, 3 태스크 정의 |
| 슬랙 조율이나 승인 흐름을 바꾸기 | 3 태스크 정의, 5 계약, 6-1 AI 실행 |
| 평가를 돌리고 채점하기 | 6-4 평가 방법, 6-5 평가 구현 |
| 구현하기 | 6-1 AI 실행, 6-2 소프트웨어 구현, 7-1 오류 처리 |
| 실행 준비 | 7-4 배포 |
| 결정 이유 찾기 | DECISIONS |
