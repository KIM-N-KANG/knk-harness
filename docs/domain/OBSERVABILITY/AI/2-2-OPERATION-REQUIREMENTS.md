# 2-2 운영 요구사항

이 문서는 진단 에이전트의 품질, 시간, 비용 목표와 운영 제약을 정한다.

운영자의 기대는 2-1 유저 스토리에, 지표의 채점 방법과 정답은 6-4 평가 방법에 있다. ([2-1-2 품질에 대한 기대](2-1-USER-STORY.md#2-1-2-품질에-대한-기대), [6-4 평가 방법](6-4-AI-EVALUATION-METHOD.md))

<br>

### 2-2-1 태스크의 유저

운영 관점의 유저는 에이전트를 만들고 고치는 개발자다. 개발자는 탐지와 진단 품질을 지키면서 진단 한 건의 시간과 모델 비용을 한도 안에 둔다.

<br>

### 2-2-2 핵심 지표 요약

| 구분 | 지표 | 목표값 |
|---|---|---|
| 품질 | 정답 장애 탐지 | 4건 중 4건 |
| 품질 | 의심 구성 요소 1순위 일치 | 4건 중 3건 이상 |
| 품질 | 첫 이상 시각 오차 3분 이내 | 4건 중 3건 이상 |
| 품질 | 원인 가설 사람 채점 평균 | 2점 만점에 1.5점 이상 |
| 품질 | 근거 검증 통과율 | 100% |
| 품질 | 오탐 | 재생 구간 합계 3건 이하 |
| 시간 | 탐지 지연 | 정답마다 5분 이하 |
| 시간 | 진단 시간 | 이상 후보 1건당 3분 이하 |
| 비용 | 진단 비용 | 이상 후보 1건당 $0.20 이하 |
| 비용 | 세션 비용 | 세션 1건당 $2.00 이하. 넘으면 세션을 끝냄 |
| 비용 | 하루 비용 | 실시간 모드 하루 $5.00 이하. 넘으면 그날 남은 시간에는 진단을 부르지 않음 |

<br>

### 2-2-3 품질

놓친 장애가 오탐보다 나쁘다. 놓친 장애는 사용자가 먼저 겪지만 오탐은 운영자가 보고 하나를 읽고 버리면 끝난다. 다만 오탐이 잦으면 운영자가 보고를 읽지 않게 되므로 상한을 둔다.

| 지표 | 계산 | 분모와 제외 |
|---|---|---|
| 정답 장애 탐지 | 정답 구간과 겹치는 첫 이상 후보가 장애로 판정된 정답 수 | 정답 4건 |
| 의심 구성 요소 1순위 일치 | 탐지한 정답 중 첫 번째 의심 구성 요소가 정답과 같은 수 | 정답 4건. 놓친 정답은 불일치 |
| 첫 이상 시각 오차 | 보고의 첫 이상 시각과 정답의 첫 이상 시각의 차이가 3분 이내인 정답 수 | 정답 4건. 놓친 정답은 초과 |
| 원인 가설 사람 채점 | 정답별 원인 가설 점수(맞음 2, 부분 1, 틀림 0)의 평균 | 정답 4건. 놓친 정답은 0점 |
| 근거 검증 통과율 | 보고 검사기의 검증을 통과한 근거 수 / 장애 판정 보고의 전체 근거 수 | 장애로 판정한 보고 전체. 조회 근거와 코드 근거를 함께 셈 |
| 오탐 | 정답과 겹치지 않는 장애 판정 중 사람 검토에서 장애가 아니라고 본 수 | 재생한 전체 구간 |

장애가 아니라고 판정한 이상 후보와 판단 불가 보고는 오탐에 넣지 않는다. 실행에 실패한 진단은 그 정답을 놓친 것으로 센다.

<br>

### 2-2-4 시간

| 지표 | 시작 | 끝 | 목표값 |
|---|---|---|---|
| 탐지 지연 | 정답의 첫 이상 시각 | 이상 후보를 연 감시 시각 | 5분 이하 |
| 진단 시간 | 진단 요청 | 진단 보고 기록 | 3분 이하 |

재생에서 진단하는 동안에는 감시 시각을 멈춘다. 진단 시간은 실제 경과 시간으로 잰다.

<br>

### 2-2-5 비용

진단 비용은 이상 후보 한 건의 진단 턴에 든 모델 호출 비용의 합이다. 세션 비용은 진단 턴과 그 뒤 조율 턴의 모델 호출 비용을 합친 값이다. 하루 비용은 실시간 모드에서 UTC 날짜 하루 동안 끝난 진단 턴과 조율 턴의 모델 호출 비용을 합친 값이다. 관측 저장소 조회 비용과 채점 비용은 넣지 않는다. 판단 불가와 실행 실패로 끝난 진단의 비용도 넣는다.

<br>

### 2-2-6 운영 제약

| 제약 | 내용 |
|---|---|
| 실행 위치 | 재생: 개발자 PC의 명령줄 프로그램<br>실시간: 운영 ECS 클러스터의 Fargate 서비스 하나와 태스크 하나 |
| 대상 환경 | 재생: 보관 자료를 다시 적재한 재생용 OpenSearch와 보관 지표 파일<br>실시간: 운영 환경의 OpenSearch(로그와 스팬)와 CloudWatch |
| 관측 권한 | 관측 저장소를 읽기만 함. 설정, 태스크 수, 데이터를 바꾸는 권한을 갖지 않음 |
| 저장소 권한 | manyak-ai는 읽기만. manyak-server와 manyak-terraform은 clone, 브랜치 push, PR 생성만. 머지 권한을 갖지 않음 |
| 쓰기 승인 | 파일 수정, 파일 생성, 명령 실행은 호출마다 운영자 승인 뒤에만 함 |
| 조치 범위 | 설정값 변경만. manyak-server의 application 설정, manyak-terraform의 변수, manyak-terraform의 오토스케일링 정책<br>원인이 코드 로직이면 보고의 개선 방향에 코드 위치와 수정 방향을 제안으로만 적음 |
| 모델에 보내는 자료 | 집계값, 조회에 필요한 필드, 코드 사본의 코드만 보냄<br>기기 식별자 해시, 세션 ID, 요청 ID, 사용자 입력 원문은 보내지 않음<br>실시간 모드는 운영 로그의 메시지 원문을 보내지 않고 건수만 보냄. 재생 자료는 부하 테스트의 합성 자료라 표본 메시지를 보냄 |
| 자격 분리 | OpenSearch 계정과 AWS 자격 증명은 조회 도구를 실행하는 코드의 변수에만 두고 프로세스 환경 변수에 두지 않음. 모델이 띄우는 명령 실행 환경이 물려받지 않게 함 |
| 비밀 정보 | OpenSearch 비밀번호, 모델 API 키, 슬랙 토큰, GitHub 토큰은 시작 때 읽음<br>실시간: Secrets Manager에서 읽음<br>재생: 비밀 파일에서 읽음<br>보고, 스레드, 로그에 남기지 않음 |

<br>

### 2-2-7 운영 특성과 한계

| 항목 | 내용 |
|---|---|
| 운영 트래픽 | 운영 요청이 적어 진입 지연, 대기 지연, 실패율 신호의 분당 표본 20건 조건을 채우는 분이 드묾<br>탐지 규칙은 loadtest 자료와 같게 두므로 실시간 모드에서는 이상 후보가 거의 열리지 않을 수 있음 |
| 임시 저장 | 실시간 모드는 세션 파일과 실행 폴더를 태스크의 임시 저장소에 둠<br>재배포나 재시작 때 열린 세션, 대기 중인 승인, 그날의 비용 누적값을 잃음. 스레드에는 종료 안내가 남지 않음<br>보고는 슬랙 알림으로 남음<br>실행 실패는 표준 출력을 거쳐 CloudWatch Logs에 남음 |
