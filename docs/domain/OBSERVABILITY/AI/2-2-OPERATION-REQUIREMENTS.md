# 2-2 운영 요구사항

이 문서는 진단 에이전트의 품질, 시간, 비용 목표와 운영 제약을 정한다.

운영자의 기대는 2-1 유저 스토리에, 지표의 채점 방법과 정답은 6-4 평가 방법에 있다. ([2-1-2 품질에 대한 기대](2-1-USER-STORY.md#2-1-2-품질에-대한-기대), [6-4 평가 방법](6-4-AI-EVALUATION-METHOD.md))

<br>

### 2-2-1 태스크의 유저

운영 관점의 유저는 에이전트를 만들고 고치는 개발자다. 개발자는 탐지와 진단 품질을 지키면서 진단 한 건의 시간과 모델 비용을 한도 안에 둔다.

<br>

### 2-2-2 핵심 지표 요약

| 구분 | 지표 | 목표값 |
|---|---|---|
| 품질 | 정답 장애 탐지 | 4건 중 4건 |
| 품질 | 의심 구성 요소 1순위 일치 | 4건 중 3건 이상 |
| 품질 | 첫 이상 시각 오차 3분 이내 | 4건 중 3건 이상 |
| 품질 | 원인 가설 사람 채점 평균 | 2점 만점에 1.5점 이상 |
| 품질 | 근거 검증 통과율 | 100% |
| 품질 | 오탐 | 재생 구간 합계 3건 이하 |
| 시간 | 탐지 지연 | 정답마다 5분 이하 |
| 시간 | 진단 시간 | 이상 후보 1건당 3분 이하 |
| 비용 | 진단 비용 | 이상 후보 1건당 $0.20 이하 |

<br>

### 2-2-3 품질

놓친 장애가 오탐보다 나쁘다. 놓친 장애는 사용자가 먼저 겪지만 오탐은 운영자가 보고 하나를 읽고 버리면 끝난다. 다만 오탐이 잦으면 운영자가 보고를 읽지 않게 되므로 상한을 둔다.

| 지표 | 계산 | 분모와 제외 |
|---|---|---|
| 정답 장애 탐지 | 정답 구간과 겹치는 첫 이상 후보가 장애로 판정된 정답 수 | 정답 4건 |
| 의심 구성 요소 1순위 일치 | 탐지한 정답 중 첫 번째 의심 구성 요소가 정답과 같은 수 | 정답 4건. 놓친 정답은 불일치 |
| 첫 이상 시각 오차 | 보고의 첫 이상 시각과 정답의 첫 이상 시각의 차이가 3분 이내인 정답 수 | 정답 4건. 놓친 정답은 초과 |
| 원인 가설 사람 채점 | 정답별 원인 가설 점수(맞음 2, 부분 1, 틀림 0)의 평균 | 정답 4건. 놓친 정답은 0점 |
| 근거 검증 통과율 | 코드 검증을 통과한 근거 수 / 장애 판정 보고의 전체 근거 수 | 장애로 판정한 보고 전체 |
| 오탐 | 정답과 겹치지 않는 장애 판정 중 사람 검토에서 장애가 아니라고 본 수 | 재생한 전체 구간 |

장애가 아니라고 판정한 이상 후보와 판단 불가 보고는 오탐에 넣지 않는다. 실행에 실패한 진단은 그 정답을 놓친 것으로 센다.

<br>

### 2-2-4 시간

| 지표 | 시작 | 끝 | 목표값 |
|---|---|---|---|
| 탐지 지연 | 정답의 첫 이상 시각 | 이상 후보를 연 감시 시각 | 5분 이하 |
| 진단 시간 | 진단 요청 | 진단 보고 기록 | 3분 이하 |

재생에서 진단하는 동안에는 감시 시각을 멈춘다. 진단 시간은 실제 경과 시간으로 잰다.

<br>

### 2-2-5 비용

비용은 이상 후보 한 건의 진단에 든 모델 호출 비용의 합이다. 관측 저장소 조회 비용과 채점 비용은 넣지 않는다. 판단 불가와 실행 실패로 끝난 진단의 비용도 넣는다.

<br>

### 2-2-6 운영 제약

| 제약 | 내용 |
|---|---|
| 실행 위치 | 개발자 PC의 명령줄 프로그램 |
| 대상 환경 | 재생: 보관 자료를 다시 적재한 재생용 OpenSearch와 보관 지표 파일<br>실시간: loadtest 환경의 OpenSearch와 CloudWatch |
| 권한 | 관측 저장소를 읽기만 함. 설정, 태스크 수, 데이터를 바꾸는 권한을 갖지 않음 |
| 모델에 보내는 자료 | 집계값과 조회에 필요한 필드만 보냄<br>기기 식별자 해시, 세션 ID, 요청 ID, 사용자 입력 원문은 보내지 않음 |
| 비밀 정보 | OpenSearch 계정, AWS 자격 증명, 모델 API 키는 환경 변수로 받고 보고와 로그에 남기지 않음 |
