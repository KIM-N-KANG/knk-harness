# 2-2 운영 요구사항

이 문서는 진단 에이전트의 품질, 시간, 비용 목표와 운영 제약을 정한다.

운영자의 기대는 2-1 유저 스토리에, 식별자 필드 목록은 5 계약에 있다. ([2-1-2 품질에 대한 기대](2-1-USER-STORY.md#2-1-2-품질에-대한-기대), [5-2 설정 파일](5-CONTRACT.md#5-2-설정-파일))

<br>

### 2-2-1 태스크의 유저

운영 관점의 유저는 에이전트를 만들고 고치는 개발자다. 개발자는 진단 품질을 지키면서 진단 한 건의 시간과 모델 비용을 한도 안에 둔다.

<br>

### 2-2-2 핵심 지표 요약

| 구분 | 지표 | 목표값 |
|---|---|---|
| 품질 | 근거 검증 통과율 | 100% |
| 시간 | 탐지 지연 | 장애마다 5분 이하 |
| 시간 | 진단 시간 | 진단 요청 1건당 3분 이하 |
| 비용 | 진단 비용 | 진단 요청 1건당 $0.20 이하 |
| 비용 | 세션 비용 | 세션 1건당 $2.00 이하. 넘으면 세션을 끝냄 |
| 비용 | 하루 비용 | 하루 $5.00 이하. 넘으면 그날 남은 시간에는 진단을 부르지 않음 |
| 비용 | 전체 예산 | 팀이 보유한 Claude API 크레딧 $100 |

<br>

### 2-2-3 품질

놓친 장애가 오탐보다 나쁘다. 놓친 장애는 사용자가 먼저 겪지만 오탐은 운영자가 보고 하나를 읽고 버리면 끝난다.

| 지표 | 계산 | 분모 |
|---|---|---|
| 근거 검증 통과율 | 보고 검사기의 검증을 통과한 근거 수 / 장애 판정 보고의 전체 근거 수 | 장애로 판정한 보고 전체. 조회 근거와 코드 근거를 함께 셈 |

<br>

### 2-2-4 시간

| 지표 | 시작 | 끝 | 목표값 |
|---|---|---|---|
| 탐지 지연 | 장애의 첫 이상 시각 | 이상 후보를 연 시각 | 5분 이하 |
| 진단 시간 | 진단 요청. 운영자 요청은 멘션 메시지를 받은 시각 | 진단 보고 기록 | 3분 이하 |

진단 시간은 실제 경과 시간으로 잰다. 앞 진단이 끝나기를 기다린 시간은 넣지 않는다.

<br>

### 2-2-5 비용

진단 비용은 진단 요청 한 건의 진단 턴에 든 모델 호출 비용의 합이다. 세션 비용은 진단 턴과 그 뒤 대화 턴의 모델 호출 비용을 합친 값이다. 하루 비용은 UTC 날짜 하루 동안 끝난 진단 턴과 대화 턴의 모델 호출 비용을 합친 값이다. 관측 저장소 조회 비용은 넣지 않는다. 판단 불가와 실행 실패로 끝난 진단의 비용도 넣는다.

모델 호출 비용은 전체 예산 $100 안에서 쓴다. 매일 하루 상한 $5.00까지 쓰면 전체 예산은 약 20일 만에 소진된다.

<br>

### 2-2-6 운영 제약

| 제약 | 내용 |
|---|---|
| 실행 위치 | 1단계: 운영자 PC에서 상주 실행. 슬랙은 소켓 모드로 연결<br>2단계: 운영 ECS 클러스터의 Fargate 서비스 하나와 태스크 하나 |
| 대상 환경 | 두 단계 모두 운영 환경의 OpenSearch(로그와 스팬), CloudWatch, AMP(앱 지표) |
| 관측 권한 | 관측 저장소를 읽기만 함. 설정, 태스크 수, 데이터를 바꾸는 권한을 갖지 않음 |
| 저장소 권한 | 코드 저장소를 받아 읽기만 함. 브랜치 push와 PR 생성 권한을 갖지 않음 |
| 도구 범위 | 모델에 읽기 도구만 노출함. 파일 수정, 파일 생성, 명령 실행 도구를 노출하지 않음 |
| 모델에 보내는 자료 | 관측 저장소의 조회 결과와 코드 사본의 내용만 보냄<br>운영 로그의 메시지 원문과 식별자 필드는 OpenSearch 읽기 사용자의 역할이 필드 수준 보안(FLS)으로 빼서 조회 결과에 들어오지 않음. 빼는 필드 목록은 설정 파일의 식별자 제거 목록 |
| 자격 분리 | OpenSearch 비밀번호와 AWS 자격은 에이전트 코드의 변수와 그 자격을 쓰는 MCP 서버 프로세스의 환경에만 둠<br>모델이 쓰는 도구 중 프로세스 환경이나 사본 밖 파일을 읽는 도구가 없음 |
| 비밀 정보 | 모델 API 키, 슬랙 토큰, OpenSearch 비밀번호, 비공개 저장소를 받는 읽기 전용 토큰은 시작 때 읽음<br>1단계: 비밀 파일에서 읽음<br>2단계: Secrets Manager에서 읽음<br>설정 파일, 보고, 스레드, 로그에 두지 않음 |

<br>

### 2-2-7 운영 특성과 한계

| 항목 | 내용 |
|---|---|
| 운영 트래픽 | 운영 요청이 적어 진입 지연, 대기 지연, 실패율 신호의 분당 표본 20건 조건을 채우는 분이 드묾<br>그래서 운영에서는 이상 후보가 거의 열리지 않을 수 있음. 운영자 요청으로 진단을 직접 시작할 수 있음 |
| 임시 저장 | 세션 파일과 실행 폴더를 실행 위치의 폴더에 둠. 2단계는 태스크의 임시 저장소<br>재시작 때 열린 세션, 대기 중인 진단 요청, 그날의 비용 누적값을 잃음. 스레드에는 종료 안내가 남지 않음<br>보고는 슬랙에 남음<br>실행 실패는 표준 출력에 남고 2단계는 CloudWatch Logs로 감 |
| 1단계 가동 | 운영자 PC가 꺼지거나 잠들면 감시와 슬랙 연결이 멈춤 |
