**OBS-AI-014. 실시간 모드는 상주 컨테이너**

| 항목 | 내용 |

| 대안 | 설명서만 입력으로 두는 안(OBS-AI-006). 코드 위치를 줄 수 없어 확장했다.<br>코드 로직 수정까지 PR로 올리는 안. 에이전트 컨테이너에는 코드 변경을 돌려 볼 테스트 환경이 없다. 호출 단위 버튼 승인으로는 코드 변경 전체를 검토하기 어렵다. 그래서 다음 단계로 미뤘다. |
| 영향 | 근거 검증 통과율과 원인 가설 사람 채점에 코드 근거가 들어간다. 재생 구간마다 당시 커밋을 정해야 한다. 코드 읽기로 진단 턴의 입력 토큰이 늘 수 있어 진단 비용 한도를 함께 본다. |

**OBS-AI-019. 설정 외부화와 오픈소스 전제**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-23 |
| 상태 | 채택 |
| 배경 | 김태완 멘토가 진단 에이전트를 오픈소스로 공개하자고 제안했고 개발자가 아래 구조로 반영하기로 정했다. 로그 인덱스 패턴, 필드 이름, 탐지 기준값, 식별자 필드, 저장소, 슬랙 채널, 모델과 한도 같은 마냑 고정값이 코드 상수, 환경 변수, 프롬프트에 흩어져 있어 다른 서비스가 쓰려면 코드를 고쳐야 했다. |
| 채택 | 설정을 세 겹으로 받는다. 구조가 있는 값은 YAML 설정 파일 하나에 둔다. 스칼라 값은 키 경로를 대문자와 밑줄로 바꾼 `DIAG_` 환경 변수로 덮어쓰고 우선순위는 환경 변수, 설정 파일, 코드 기본값 순이다. 비밀값은 설정 파일에 두지 않는다. 코드 기본값은 마냑 값이고 환경마다 다른 값은 필수다.<br>시스템 설명서는 설정 파일의 `system_description`이 가리키는 별도 파일로 둔다. 재생 구간마다 설명서만 다르고 나머지 설정은 같기 때문이다.<br>비밀값 출처는 Secrets Manager(`DIAG_SECRET_ID`)와 비밀 파일(`DIAG_SECRETS_FILE`) 중 하나로 고른다. 실시간은 코드가 Secrets Manager를 직접 읽고 재생은 비밀 파일을 읽는 마냑의 사용은 그대로다. 환경 변수로 비밀값을 직접 받는 출처는 두지 않는다.<br>운영 설정 파일과 운영 시스템 설명서는 manyak-terraform 저장소에 두고 terraform이 Parameter Store 파라미터로 올려 태스크가 시작 때 읽는다. 공개 저장소에는 예시 설정 파일과 재생 구간별 시스템 설명서만 둔다.<br>프롬프트는 서비스 이름과 저장소 이름이 든 자리만 자리표시자와 설정 값으로 바꾸고 문구는 그대로 둔다. `editable_paths`는 시스템 프롬프트로 모델에 알리고 도구 호출 전 훅의 쓰기 범위는 조치 작업 공간 안으로 그대로 둔다. 저장소 이름 `manyak-diagnosis`는 유지한다. |
| 대안 | 시스템 설명서를 설정 파일의 한 절로 두는 안. 재생 구간마다 설정 파일 전체를 복제해야 하고 기준값을 바꿀 때 네 파일이 어긋날 수 있어 채택하지 않았다.<br>환경 변수로 비밀값을 받고 읽은 직후 지우는 안. 지우기를 빠뜨린 경로 하나로 `Bash`가 비밀값을 물려받는다. 비밀 파일 출처로 같은 일을 할 수 있어 채택하지 않았다.<br>운영 설정을 Secrets Manager 옆에 사람이 직접 올리는 안. 변경 검토와 이력이 남지 않아 채택하지 않았다.<br>운영 설정을 이미지에 넣는 안. 설정만 바꿔도 이미지를 다시 빌드해야 해서 채택하지 않았다. |
| 영향 | 탐지 기준값, 모델, 한도, 필드 이름은 코드가 아니라 설정을 고쳐 바꾼다. 기존 환경 변수 이름은 덮어쓰기 규칙에 맞춰 바뀐다(`DIAG_MODEL`은 `DIAG_MODEL_ID`, `AWS_REGION`은 `DIAG_AWS_REGION`). 채점기는 프롬프트 해시와 함께 `system_description`을 뺀 적용 설정 값이 실행 폴더끼리 같은지 확인한다. 운영 태스크 역할에 설정 파라미터 읽기가 더해진다. 영어 README, 라이선스, 프롬프트 영어판, 예시 데이터 정리 같은 공개 준비는 평가 뒤 단계에서 한다. |
