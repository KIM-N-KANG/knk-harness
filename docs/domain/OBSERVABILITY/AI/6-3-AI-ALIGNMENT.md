# 6-3 AI 얼라인먼트

이 문서는 진단 품질을 고칠 때 쓰는 수단과 실패 사례의 원인을 가르는 순서를 정한다.

목표값은 2-2 운영 요구사항에, 실패 사례를 확인하는 기록은 7-3 관측에 있다. ([2-2-2 핵심 지표 요약](2-2-OPERATION-REQUIREMENTS.md#2-2-2-핵심-지표-요약), [7-3-2 기록 항목](7-3-OBSERVABILITY.md#7-3-2-기록-항목))

<br>

### 6-3-1 개선 수단

| 수단 | 허용 | 조건 |
|---|---|---|
| 시스템 프롬프트 수정 | 허용 | 실패 사례의 `queries/` 기록에서 모델이 어디서 잘못 골랐는지 확인한 뒤 고침 |
| 서비스 지도 보강 | 허용 | 구성 요소, 자료 위치, 파일 위치 힌트, 한 줄 설명 같은 구성 사실만 적음. 특정 장애의 원인 문장을 옮겨 적지 않음 |
| 탐지 기준값, 확정 조건, 닫기 조건 변경 | 허용 | 놓친 장애와 오탐을 함께 봄 |
| 모델 교체 | 허용 | 비용 한도 안에서 |
| 추론 강도 변경 | 허용 | 비용 한도 안에서 |
| 파인튜닝 | 안 함 | 학습 데이터로 쓸 진단 사례가 없음 |

변경은 한 번에 하나씩 한다. 바꾼 값은 `run.json`의 적용 설정 값과 프롬프트 해시로 남는다.

<br>

### 6-3-2 원인 구분

실패 사례를 볼 때 아래 순서로 원인을 가른다. 앞 원인이 확인되면 뒤를 보지 않는다.

| 순서 | 원인 | 확인 방법 |
|---|---|---|
| 1 | 자료 누락 | `queries/`의 결과가 비어 있거나 수집이 끊긴 구간임 |
| 2 | 탐지 규칙 | 이상 후보가 안 열렸거나 늦게 열림 |
| 3 | 서비스 지도 부족 | 모델이 구성 요소나 설정 파일을 찾지 못했거나 서비스 지도에 없는 이름을 지목함 |
| 4 | 코드 사본 | 사본 커밋이 운영에 반영된 커밋과 달라 읽은 설정값이 운영과 다름 |
| 5 | 조회 선택 | 분해, 설정, 확장 단계를 건너뛰고 제출함 |
| 6 | 모델 판단 | 자료를 봤는데 틀린 메커니즘을 씀 |
| 7 | 구현 결함 | 조회 번호나 근거 검증이 기록과 다름 |
