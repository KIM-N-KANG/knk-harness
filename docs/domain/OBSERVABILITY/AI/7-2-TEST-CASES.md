# 7-2 테스트 케이스

이 문서는 테스트 범위와 구성 요소별 케이스, 통합 테스트를 정한다. AI 품질은 6-4 평가 방법으로 재고 여기서는 코드의 동작을 확인한다.

신호 규칙은 4-1 인지 구조에, 보고 필드는 5 계약에, 오류 처리는 7-1 오류 처리에 있다. ([4-1-2 이상 후보 추림](4-1-DESIGN-COGNITIVE-ARCHITECTURE.md#4-1-2-이상-후보-추림), [5-5 진단 보고](5-CONTRACT.md#5-5-진단-보고), [5-7 슬랙 메시지](5-CONTRACT.md#5-7-슬랙-메시지), [7-1-2 오류별 처리](7-1-ERROR-HANDLING.md#7-1-2-오류별-처리))

<br>

### 7-2-1 테스트 범위

| 종류 | 확인 범위 | 외부 의존성 | 실행 |
|---|---|---|---|
| 단위 | 탐지기, 후보 관리자, 자료 접근기의 변환, 보고 검사기, 보고 기록기, 세션 관리자, 승인 관문, 슬랙 연결기 | 조회, 모델 세션, 슬랙 호출을 가짜로 대체 | 개발자 PC, CI |
| 조회 통합 | OpenSearch 집계 질의와 결과 변환 | 재생용 OpenSearch에 작은 표본 적재 | 개발자 PC |
| 진단 통합 | 이상 후보 하나의 진단 끝까지 | 실제 모델 호출, 재생용 OpenSearch | 수동. 비용 발생 |
| 조율 통합 | 슬랙 알림부터 조치 PR까지 | 실제 모델 호출, 슬랙 테스트 채널, 코드 저장소 | 수동. 비용 발생 |

실행 명령과 테스트 파일 위치는 저장소 안내 문서에 둔다.

<br>

### 7-2-2 탐지기와 후보 관리자

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 신호 확정 | 진입 지연이 5분 중 3분 기준 초과 | 신호 확정. 첫 시각은 처음 넘은 분 |
| 신호 미확정 | 5분 중 2분만 초과 | 확정 안 됨 |
| 표본 부족 | p95는 기준 초과인데 그 분의 스팬이 19건 | 그 분은 조건 미충족 |
| 지연 기준 없음 | 설명서에 없는 진입 스팬 이름 | 진입 지연 신호를 판정하지 않음 |
| 후보 열기 | 확정 신호가 있고 열린 후보 없음 | 후보 열림. `candidates.jsonl`에 한 줄 |
| 신호 붙이기 | 열린 후보가 있는데 다른 종류 신호 확정 | 같은 후보의 신호 목록에 추가. 진단 요청 없음 |
| 후보 닫기 | 모든 신호가 10분 동안 조건 미충족 | `closed_at` 채운 줄 추가 |
| 닫은 뒤 재발 | 닫은 다음 분에 다시 확정 | 새 ID로 새 후보 |

### 7-2-3 자료 접근기

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 상한 시각 자르기 | `end`가 연 시각보다 뒤 | 연 시각까지만 조회 |
| 식별자 제거 | 표본 메시지에 `device_id_hash` 값이 들어 있음 | 값이 결과에 없음 |
| 나노초 변환 | `durationInNanos` 48,600,000,000 | p95 48.6초 |
| 구성 요소 이름 변환 | `manyak-ai`의 CPU 조회 | 설명서의 지표 차원으로 조회 |
| 차원 없는 구성 요소 | 실행기의 지표 조회 | `결과 없음` |
| 지표 범위 상한 | 3시간 범위 요청 | 끝에서 1시간만 |
| 조회 실패 재시도 | 첫 호출 연결 오류, 둘째 성공 | 결과 반환. 재시도 1회 기록 |
| 재시도 소진 | 두 번 모두 실패 | 예외 전파 |

### 7-2-4 진단 실행기와 보고 검사기

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 조회 번호 | 조회 3회 | 결과 앞에 `[query 1]`~`[query 3]`, `queries/`에 3줄 |
| 근거 검증 통과 | `query_ref` 2, `value`가 그 결과에 있음 | `verified` 참 |
| 근거 검증 실패 | `value`가 결과에 없음 | `verified` 거짓. 보고는 기록됨 |
| 없는 조회 번호 | `query_ref` 9, 조회는 3회 | `verified` 거짓 |
| 출력 간 조건 위반 | `incident`인데 `actions`가 `null` | 위반 회신 1회 |
| 두 번째 위반 | 회신 뒤에도 같은 위반 | 실행 실패 `report` |
| 미제출 | 글만 두 번 | 실행 실패 `budget` |
| 조회 소진 | 25회 뒤 제출 | 보고 기록. `usage.queries` 25 |
| 시간 소진 | 가짜 모델이 6분 걸림 | 실행 실패 `budget` |
| 거절 | 가짜 모델이 `refusal` | 실행 실패 `model` |
| 중복 보고 | 같은 ID의 보고 파일이 이미 있음 | 실행 실패. 기존 파일 유지 |
| 사용량 집계 | 메시지 3개의 토큰 | 합계와 비용이 단가표대로 |
| 제출 전 내장 도구 | 가짜 모델이 보고 제출 전에 `Read` 호출 | 거부 결과가 돌아가고 턴은 계속됨 |
| 제출 뒤 내장 도구 | 보고 제출 뒤 조율 턴에서 `Read` 호출 | 작업 폴더 안이면 실행됨 |

### 7-2-5 세션 관리자, 승인 관문, 슬랙 연결기

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 세션 짝 기록 | 알림 게시 응답의 `thread_ts` | `sessions.jsonl`에 세션 ID와 함께 한 줄 |
| 세션 찾기 | 같은 `thread_ts`의 사람 메시지 | 그 세션 ID로 조율 턴 시작 |
| 봇 메시지 무시 | 봇 사용자 ID의 스레드 메시지 | 조율 턴 없음 |
| 짝 없는 스레드 | `sessions.jsonl`에 없는 `thread_ts` | 종료 안내 1회. 두 번째 메시지는 무응답 |
| 24시간 경과 | 후보를 닫은 지 24시간 1분 | `closed_at` 기록. 이후 메시지에 종료 안내 1회 |
| 승인 | `Edit` 호출에 승인 버튼 | 도구 실행. `approvals.jsonl`에 `approved`와 승인자 |
| 거부 | `Bash` 호출에 거부 버튼 | 미실행. 거부가 도구 결과로 모델에 전달됨. `denied` 기록 |
| 승인 시간 초과 | 2시간 동안 응답 없음 | 미실행. `timeout` 기록 |
| 기본 브랜치 push | `Bash`로 `dev`에 push하는 명령 | 승인 메시지 없이 거부 |
| 작업 폴더 밖 읽기 | `Read`로 작업 폴더 밖 경로 | 거부 |
| 비용 초과 | 누적 $1.95에서 $0.10이 드는 턴 | 턴 뒤 종료 안내. `closed_at`과 누적 비용 기록 |
| 다시 시작 | 열린 세션이 있는 실행 폴더로 재기동 | 같은 `thread_ts` 메시지가 같은 세션으로 이어짐 |
| 알림 실패 | 슬랙 전송이 두 번 실패 | 실행 실패 `notify`. 보고 파일은 있음 |
| PR 기록 | PR 생성 명령이 주소를 출력 | `actions.jsonl`에 저장소와 주소 |

### 7-2-6 통합 테스트

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 조회 통합 | 표본 스팬 200건 적재 후 진입 스팬 이름별 집계 | 건수와 p95가 표본에서 직접 계산한 값과 같음 |
| G1 재생 | R1 구간 재생 | 04:46Z~04:51Z 사이에 후보가 열리고 `verdict`가 `incident` |
| 정상 구간 재생 | 신호가 없는 30분 구간 | 후보 0건, 모델 호출 0회 |
| 조율 통합 | 실시간 모드에서 G1 보고를 테스트 채널에 올린 뒤 질문 1건과 "실행기 동시 실행 수를 8로" 지시 1건 | 질문에 답변 게시. 지시에는 승인 메시지, 승인 뒤 manyak-server에 설정값만 바뀐 PR과 스레드의 PR 주소 |

통합 테스트의 표본은 6-4 벤치마크에서 가져오고 가져온 구간을 기록한다.
