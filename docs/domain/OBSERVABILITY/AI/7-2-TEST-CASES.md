# 7-2 테스트 케이스

이 문서는 테스트 범위와 구성 요소별 케이스, 통합 테스트를 정한다. AI 품질은 6-4 평가 방법으로 재고 여기서는 코드의 동작을 확인한다.

신호 규칙은 4-1 인지 구조에, 설정 항목과 보고 필드는 5 계약에, 오류 처리는 7-1 오류 처리에 있다. ([4-1-2 이상 후보 추림](4-1-DESIGN-COGNITIVE-ARCHITECTURE.md#4-1-2-이상-후보-추림), [5-2 설정 파일](5-CONTRACT.md#5-2-설정-파일), [5-6 진단 보고](5-CONTRACT.md#5-6-진단-보고), [5-8 슬랙 메시지](5-CONTRACT.md#5-8-슬랙-메시지), [7-1-2 오류별 처리](7-1-ERROR-HANDLING.md#7-1-2-오류별-처리))

<br>

### 7-2-1 테스트 범위

| 종류 | 확인 범위 | 외부 의존성 | 실행 |
|---|---|---|---|
| 단위 | 설정 읽기, 탐지기, 후보 관리자, 자료 접근기의 변환, 보고 검사기, 보고 기록기, 세션 관리자, 승인 관문, 슬랙 연결기, 도구 호출 전 훅, 하위 프로세스 환경 | 조회, 모델 세션, 슬랙 호출을 가짜로 대체 | 개발자 PC, CI |
| 조회 통합 | OpenSearch 집계 질의와 결과 변환 | 재생용 OpenSearch에 작은 표본 적재 | 개발자 PC |
| 진단 통합 | 이상 후보 하나의 진단 끝까지 | 실제 모델 호출, 재생용 OpenSearch | 수동. 비용 발생 |
| 조율 통합 | 슬랙 알림부터 조치 PR까지 | 실제 모델 호출, 슬랙 테스트 채널, 코드 저장소 | 수동. 비용 발생 |
| 운영 연결 | 운영 태스크의 조회와 슬랙 연결 | 운영 OpenSearch, CloudWatch, 슬랙 채널 | 수동. 운영 태스크 배포 뒤 |

실행 명령과 테스트 파일 위치는 저장소 안내 문서에 둔다.

### 7-2-2 설정

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 우선순위 환경 변수 | 설정 파일 `limits.queries` 30, `DIAG_LIMITS_QUERIES` 40 | 40 적용. `run.json`에 40과 덮어쓴 환경 변수 이름 |
| 우선순위 설정 파일 | 설정 파일만 `limits.queries` 30 | 30 적용 |
| 우선순위 기본값 | 설정 파일에 `limits.queries`가 없고 `DIAG_LIMITS_QUERIES`도 없음 | 25 적용 |
| 덮어쓰기 이름 변환 | `DIAG_DETECTION_MIN_SAMPLES` 15 | `detection.min_samples` 15 |
| 중첩 키 덮어쓰기 | `DIAG_FIELDS_SPAN_DURATION` `duration_us` | `fields.span.duration` `duration_us` |
| 불리언 덮어쓰기 | 재생 실행에 `DIAG_LOG_SAMPLES` `false` | 로그 집계에 표본 메시지 없음 |
| 배열 덮어쓰기 | `DIAG_REDACT_FIELDS` | 알 수 없는 환경 변수로 시작 검사 실패 |
| 이름이 틀린 환경 변수 | `DIAG_LIMIT_QUERIES` | 시작 검사 실패. 표준 오류에 `DIAG_LIMIT_QUERIES` |
| 타입 변환 실패 | `DIAG_LIMITS_QUERIES` `many` | 시작 검사 실패. 표준 오류에 이름만 있고 값은 없음 |
| 알 수 없는 키 | 설정 파일에 `detecton.min_samples` | 시작 검사 실패 |
| 필수 항목 누락 | 설정 파일에 `opensearch.log_index` 없음 | 시작 검사 실패. 실행 폴더 없음. 표준 오류에 키 이름 |
| 조건부 필수 | 슬랙을 켠 실행에 `slack.channel` 없음 | 시작 검사 실패 |
| 조건부 필수 아님 | 슬랙을 켜지 않은 재생에 `slack.channel`과 `action_repositories` 없음 | 시작함 |
| 문제 여럿 | 필수 항목 둘이 빠짐 | 시작 검사 실패. 표준 오류에 두 키가 한 줄씩 |
| 상대 경로 | 설정 파일이 `examples/`에 있고 `system_description`이 `systems/R1.yaml` | `examples/systems/R1.yaml`을 읽음 |
| Parameter Store 위치 | `DIAG_CONFIG`가 `ssm:`으로 시작함 | 가짜 Parameter Store의 파라미터 값을 설정 파일로 읽음 |
| 비밀값 출처 둘 | `DIAG_SECRET_ID`와 `DIAG_SECRETS_FILE`이 모두 있음 | 시작 검사 실패 |
| 비밀값 출처 없음 | 둘 다 없음 | 시작 검사 실패 |
| 출처와 모드 무관 | 재생 실행에 `DIAG_SECRET_ID`만 있음 | 가짜 Secrets Manager에서 비밀값을 읽음 |
| 서비스 이름 | `service_name` `예시몰` | 시스템 프롬프트 첫 문장이 `너는 예시몰 서비스의 장애 진단 담당자다.` |
| 고칠 수 있는 경로 | `action_repositories` 하나에 `editable_paths` 두 개 | 시스템 프롬프트의 조치 작업 공간 줄에 두 패턴이 쉼표로 이어짐 |

### 7-2-3 탐지기와 후보 관리자

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 신호 확정 | 진입 지연이 5분 중 3분 기준 초과 | 신호 확정. 첫 시각은 처음 넘은 분 |
| 신호 미확정 | 5분 중 2분만 초과 | 확정 안 됨 |
| 표본 부족 | p95는 기준 초과인데 그 분의 스팬이 19건 | 그 분은 조건 미충족 |
| 지연 기준 없음 | 설명서에 없는 진입 스팬 이름 | 진입 지연 신호를 판정하지 않음 |
| 대기 스팬 이름 | `detection.queue_spans`가 `chat.turn.queue` 하나이고 다른 이름의 스팬 p95가 1초 이상 | 그 스팬으로는 대기 지연 신호를 판정하지 않음 |
| 대기 스팬 없음 | `detection.queue_spans`가 빈 배열 | 대기 지연 신호를 판정하지 않음 |
| 기준값 변경 | `detection.confirm_minutes` 2, 5분 중 2분 초과 | 신호 확정 |
| 후보 열기 | 확정 신호가 있고 열린 후보 없음 | 후보 열림. `candidates.jsonl`에 한 줄 |
| 신호 붙이기 | 열린 후보가 있는데 다른 종류 신호 확정 | 같은 후보의 신호 목록에 추가. 진단 요청 없음 |
| 후보 닫기 | 모든 신호가 10분 동안 조건 미충족 | `closed_at` 채운 줄 추가 |
| 닫은 뒤 재발 | 닫은 다음 분에 다시 확정 | 새 ID로 새 후보 |
| 하루 상한 초과 | 실시간 모드에서 그날 누적 $5.01일 때 새 후보가 열림 | 후보 줄에 `skip_reason` `daily_budget_exceeded`. 진단 호출 0회. 채널 안내 1회 |
| 하루 상한 안내 1회 | 같은 날 두 번째 후보도 생략됨 | 채널 안내 없음 |
| 하루 경계 | UTC 0시가 지난 뒤 새 후보 | 진단을 부름 |
| 재생의 하루 상한 | 재생 실행에서 누적 $6 | 상한 없이 진단을 부름 |

### 7-2-4 자료 접근기

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 상한 시각 자르기 | `end`가 연 시각보다 뒤 | 연 시각까지만 조회 |
| 식별자 제거 | 표본 메시지에 `device_id_hash` 값이 들어 있음 | 값이 결과에 없음 |
| 재생 모드 로그 표본 | `log_samples`를 적지 않은 재생 모드에서 로그 집계 | 묶음마다 표본 메시지 최대 5개 |
| 실시간 모드 로그 표본 | `log_samples`를 적지 않은 실시간 모드에서 로그 집계 | 건수만. 질의에 `fields.log.message`를 요청하지 않음 |
| 나노초 변환 | `durationInNanos` 48,600,000,000 | p95 48.6초 |
| 마이크로초 변환 | `fields.span.duration_unit` `microseconds`, 값 48,600,000 | p95 48.6초 |
| 구성 요소 이름 변환 | `manyak-ai`의 CPU 조회 | 설명서의 지표 차원으로 조회 |
| 차원 없는 구성 요소 | 실행기의 지표 조회 | `결과 없음` |
| 지표 범위 상한 | 3시간 범위 요청 | 끝에서 1시간만 |
| 조회 실패 재시도 | 첫 호출 연결 오류, 둘째 성공 | 결과 반환. 재시도 1회 기록 |
| 재시도 소진 | 두 번 모두 실패 | 예외 전파 |

### 7-2-5 진단 실행기와 보고 검사기

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 조회 번호 | 조회 3회 | 결과 앞에 `[query 1]`~`[query 3]`, `queries/`에 3줄 |
| 근거 검증 통과 | `query_ref` 2, `value`가 그 결과에 있음 | `verified` 참 |
| 근거 검증 실패 | `value`가 결과에 없음 | `verified` 거짓. 보고는 기록됨 |
| 없는 조회 번호 | `query_ref` 9, 조회는 3회 | `verified` 거짓 |
| 출력 간 조건 위반 | `incident`인데 `actions`가 `null` | 위반 회신 1회 |
| 두 번째 위반 | 회신 뒤에도 같은 위반 | 실행 실패 `report` |
| 미제출 | 글만 두 번 | 실행 실패 `budget` |
| 조회 소진 | 25회 뒤 제출 | 보고 기록. `usage.queries` 25 |
| 시간 소진 | 가짜 모델이 6분 걸림 | 실행 실패 `budget` |
| 거절 | 가짜 모델이 `refusal` | 실행 실패 `model` |
| 중복 보고 | 같은 ID의 보고 파일이 이미 있음 | 실행 실패. 기존 파일 유지 |
| 진단 턴 비용 한도 | 가짜 SDK가 비용 한도 도달로 끝남 | 실행 실패 `budget` |
| 사용량 집계 | 결과 메시지의 사용량 | 합계와 비용이 단가표대로. SDK의 비용 추정값은 쓰지 않음 |
| 코드 근거 통과 | `code_ref`의 경로가 코드 사본에 있고 `quote`가 줄 범위 안에 있음 | `verified` 참 |
| 코드 근거 범위 밖 인용 | `quote`가 파일에는 있지만 줄 범위 밖에 있음 | `verified` 거짓. 보고는 기록됨 |
| 코드 근거 없는 경로 | 코드 사본에 없는 `path` | `verified` 거짓 |
| 코드 근거 줄 수 초과 | `end_line`이 파일 줄 수보다 큼 | `verified` 거짓 |
| 근거 형식 위반 | 근거 하나에 `query_ref`와 `code_ref`가 둘 다 있음 | 실행 실패 `report` |
| 제출 전 코드 읽기 | 가짜 모델이 보고 제출 전에 코드 사본 안 파일을 `Read` | 실행됨. 조회 횟수는 늘지 않음 |
| 제출 전 사본 밖 읽기 | 보고 제출 전에 조치 작업 공간이나 홈 폴더 경로를 `Read` | 거부 결과가 돌아가고 턴은 계속됨 |
| 제출 전 수정과 명령 | 보고 제출 전에 `Edit`이나 `Bash` 호출 | 거부 결과. 승인 메시지 없음 |
| 제출 뒤 읽기 | 보고 제출 뒤 조율 턴에서 조치 작업 공간 파일을 `Read` | 실행됨 |

### 7-2-6 세션 관리자, 승인 관문, 슬랙 연결기

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 세션 짝 기록 | 알림 게시 응답의 `thread_ts` | `sessions.jsonl`에 세션 ID와 함께 한 줄 |
| 세션 찾기 | 같은 `thread_ts`의 사람 메시지 | 그 세션 ID로 조율 턴 시작 |
| 봇 메시지 무시 | 봇 사용자 ID의 스레드 메시지 | 조율 턴 없음 |
| 짝 없는 스레드 | `sessions.jsonl`에 없는 `thread_ts` | 종료 안내 1회. 두 번째 메시지는 무응답 |
| 24시간 경과 | 후보를 닫은 지 24시간 1분 | `closed_at` 기록. 이후 메시지에 종료 안내 1회 |
| 승인 | `Edit` 호출에 승인 버튼 | 도구 실행. `approvals.jsonl`에 `approved`와 승인자 |
| 거부 | `Bash` 호출에 거부 버튼 | 미실행. 거부가 도구 결과로 모델에 전달됨. `denied` 기록 |
| 승인 시간 초과 | 2시간 동안 응답 없음 | 미실행. `timeout` 기록 |
| 기본 브랜치 push | `default_branch`가 `dev`인 조치 저장소에서 `Bash`로 `dev`에 push하는 명령 | 승인 메시지 없이 거부 |
| 기본 브랜치 push의 다른 표기 | `git push origin HEAD:dev`처럼 글자가 다른 같은 명령 | 승인 메시지 없이 거부 |
| 설정의 기본 브랜치 | `default_branch`를 `main`으로 둔 조치 저장소에서 `main`에 push | 승인 메시지 없이 거부 |
| 코드 사본 수정 | `Edit`로 코드 사본의 manyak-ai 파일 | 승인 메시지 없이 거부 |
| 작업 폴더 밖 읽기 | `Read`로 코드 사본과 조치 작업 공간 밖 경로 | 거부 |
| 자격 미상속 | 조율 턴의 `Bash`로 환경 변수 목록 출력 | OpenSearch 비밀번호, 슬랙 토큰, `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI`가 없음. GitHub 토큰은 있음 |
| 설정 격리 | 조치 작업 공간 저장소에 CLAUDE.md가 있음 | 세션 맥락에 그 내용이 들어가지 않음. 하위 프로세스 환경에 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` |
| 보고 요약 | 조율 턴 시작 | 사용자 메시지 앞에 판정, 1순위 구성 요소와 원인 가설, 근거 앞 3개 |
| 비용 초과 | 누적 $1.95에서 $0.10이 드는 턴 | 턴 뒤 종료 안내. `closed_at`과 누적 비용 기록 |
| 다시 시작 | 열린 세션이 있던 프로세스를 다시 띄운 뒤 그 스레드에 메시지 | 종료 안내 1회. 조율 턴 없음 |
| 다시 시작 뒤 버튼 | 다시 띄우기 전에 올린 승인 메시지의 버튼을 누름 | 무시. 도구 실행 없음 |
| 알림 실패 | 슬랙 전송이 두 번 실패 | 실행 실패 `notify`. 보고 파일은 있음 |
| PR 기록 | PR 생성 명령이 주소를 출력 | `actions.jsonl`에 저장소와 주소 |

### 7-2-7 통합 테스트

| 확인 항목 | 입력과 상황 | 기대 결과 |
