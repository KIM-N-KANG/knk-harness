# 5-2 동시성

이 문서는 MODERATION 도메인의 행 잠금과 잠금 순서, 회차와 1회 반영, 유니크 위반, 선점과 임대, 수용한 경쟁 조건을 정한다.

흐름별 단계와 트랜잭션 경계는 처리 흐름에, 임대 시간과 재시도 간격은 오류 처리에 있다. ([4-1 처리 흐름](4-1-PIPELINES.md), [5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도))

### 5-2-1 행 잠금

접수, 재제출, 취소는 사용자 행에 비관적 잠금을 건다. 수정 접수와 수정본 취소는 이어서 스토리 행을, 재제출과 취소는 제출본 행을 잠근다. 결과 반영은 회원, 스토리, 제출본, 인물 순서로 잠근다. 공개 중단은 스토리의 소유 회원, 스토리, 대기 중 제출본 순서로 잠근다.

| 경로 | 막는 경쟁 조건 |
|---|---|
| 접수 | 탈퇴 커밋 후 대기하던 접수가 탈퇴 회원의 제출본을 남기는 경쟁 조건<br>같은 스토리에 대기 중 제출본이 둘 생기는 경쟁 조건 |
| 재제출 | 실행 중인 회차에 재제출이 끼어들어 판정 필드와 입력이 섞이는 경쟁 조건 |
| 취소 | 승인 적용 중인 제출본을 지우는 경쟁 조건 |
| 결과 반영 | 탈퇴, 스토리 삭제, 이미지 삭제, 수정 접수와 적용이 겹치는 경쟁 조건 |
| 공개 중단 | 두 관리자나 같은 관리자의 거듭된 요청이 공개 중단을 두 번 기록하는 경쟁 조건<br>소유자의 공개 범위 변경, 수정 접수, 삭제와 겹치는 경쟁 조건<br>승인 적용과 겹쳐 공개 중단 직전에 접수된 수정이 표시를 지우는 경쟁 조건<br>탈퇴 커밋 뒤 늦게 끝난 공개 중단이 탈퇴가 지운 알림 내역을 다시 만드는 경쟁 조건 |

모든 경로의 잠금 순서는 회원, 스토리, 제출본, 인물이다. 신규 등록의 승인은 스토리가 없으므로 회원 다음으로 제출본을 잠근 뒤 스토리를 만든다. 수정과 이미지 삭제가 같은 스토리 잠금을 쓰므로 대기 중 존재 확인과 적용이 스토리 단위로 직렬화된다.

### 5-2-2 회차와 1회 반영

| 대상 | 처리 |
|---|---|
| 회차 | 접수 시 1<br>선점과 재제출마다 1 증가 |
| 반영 조건 | 대기 상태이고 회차가 같으며 재시도 예약과 보류 상태가 아닐 때만 결과 기록 |
| 늦은 결과 | 재제출, 재선점, 취소 뒤 도착한 이전 회차의 결과는 무시 |
| 승인 적용 | 등록 저장 또는 수정 적용과 승인 표시를 한 트랜잭션으로 커밋<br>신규 등록은 제출본 행을 잠근 채 스토리를 만들어 중복 생성 차단 |
| 복사 매핑 기록 | 같은 회차의 대기 상태일 때만 기록<br>이미 기록된 원본 키는 기존 복사본을 사용 |
| 완료 이벤트 | 종료 상태 기록과 같은 트랜잭션에서 발행<br>메시지 식별자에 회차가 포함되어 회차별로 한 번 발행 |
| 공개 중단 | 스토리 행을 잠근 뒤 공개 중단 표시가 없을 때만 기록<br>먼저 커밋된 요청만 성공하고 나머지는 이미 공개 중단된 것으로 거절되어 감사 로그와 알림이 한 번만 생김<br>공개 중단 이벤트의 메시지 식별자는 스토리와 공개 중단 시각으로 정해져 같은 공개 중단은 한 번만 알림 |
| 공개 중단과 승인 | 공개 중단이 먼저 커밋되면 대기 중 제출본이 실패로 끝나 승인 결과는 반영 조건을 만족하지 못함<br>승인이 먼저 커밋되면 공개 중단은 반영된 스토리를 다시 비공개로 바꿈 |

### 5-2-3 유니크 위반 처리

| 대상 | 처리 |
|---|---|
| 제출본 `public_id` | 서버가 생성하는 UUID라 충돌이 드러나지 않음 |
| 대기 중 `story_id` | 수정 접수가 스토리 행을 잠근 뒤 대기 중 존재를 확인하므로 위반에 이르지 않음 |
| 미승인 `story_id` | 수정 접수는 기존 미승인 행을 잠그고 덮어쓰므로 위반에 이르지 않음 |

### 5-2-4 선점과 임대

| 상황 | 처리 |
|---|---|
| 선점 | 대기 상태이고 보류가 아니며 다음 시도 시각이 없거나 지났고 임대가 없거나 만료된 행이 대상<br>잠긴 행을 건너뛰며 빈 슬롯 수만큼 선점<br>독립 트랜잭션에서 임대 시작, 회차 증가, 다음 시도 시각 비움을 커밋 |
| 임대 중 종료 | 임대가 만료되면 같은 폴러가 새 회차로 다시 선점<br>별도 회수 스케줄러 없음 |
| 실행기 거부 | 같은 회차의 임대를 반환<br>반환에 실패하면 임대 만료 후 재선점 |
| 임대와 시간 제한 | 임대가 AI 시간 제한보다 길어야 기동<br>이미지 복사 시간까지 포함해 여유를 둠 |
| DB 일시 장애 | 트랜잭션을 롤백하고 대기 상태의 임대를 남겨 재선점 대상으로 둠 |
| 보류 해제 | 대기이고 보류 중일 때만 바꾸는 조건부 갱신<br>두 관리자가 동시에 해제하면 한쪽만 성공<br>해제와 취소가 겹치면 행이 없어 해제가 거절됨 |

<br>

### 5-2-5 수용한 경쟁 조건

| 상황 | 수용 이유 |
|---|---|
| 임대 초과로 두 인스턴스가 같은 제출본을 실행 | 결과는 회차 조건으로 한 번만 반영<br>중복 AI 호출 비용을 수용 |
| 대기 중 제출본 취소 뒤 도착한 결과 | 행이 없어 반영 조건을 만족하지 못하고 무시 |
| 접수 직후 조회에는 대기 상태만 보임 | 실행은 폴링 주기 뒤 시작하며 결과는 알림과 재조회로 전달 |
| 공개 중단으로 끝낸 제출본의 실행이 이미 AI를 호출함 | 결과는 버려지고 호출 비용 한 번을 수용<br>실행 중인 AI 호출을 멈출 수단이 없음 |
| 이미지 복사 뒤 매핑 기록 전 장애 | 복사본 객체가 남지만 다음 회차가 새로 복사<br>남은 객체는 정리하지 않음 |
