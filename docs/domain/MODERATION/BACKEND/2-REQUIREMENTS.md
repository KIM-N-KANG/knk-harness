# 2. 요구사항

이 문서는 MODERATION 도메인 백엔드의 동작, 요구 주체, 다른 주체와의 역할 분담, 제품 제약과 데이터 보존 기준을 정한다.

요청과 응답의 필드는 계약에, 처리 순서는 처리 흐름에, 재시도 간격과 시간 한도는 오류 처리에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도))

<br>

### 2-1 요구 주체

백엔드는 제출본을 접수하고 AI 서버의 판정을 받아 현재 스토리에 반영한다. 각 주체의 역할과 백엔드에 기대하는 동작은 다음과 같다.

| 주체 | 하는 일 | 백엔드에 기대하는 것 |
|---|---|---|
| 클라이언트 | 등록과 수정 폼 제출<br>접수 뒤 화면 이동<br>알림 수신 또는 재진입 시 제출본 조회<br>반려 사유를 입력 위치에 표시하고 재제출 | 웹과 Android가 같은 계약으로 호출할 수 있는 엔드포인트<br>입력 위치에 대응하는 위반 항목과 이미지 오류<br>재제출 폼을 복원할 수 있는 제출본 상세<br>현재 스토리가 없는 신규 등록본을 보여 줄 미승인 목록 |
| AI 서버 | 검수 입력의 텍스트와 이미지를 판정 | 전체 폼 구조의 검수 입력<br>내려받을 수 있는 이미지 URL<br>관측 연결용 제출본 식별자 |
| 스토리 | 등록과 수정 입력 검증, 승인 시 저장과 적용 | 검증을 통과한 입력만 접수<br>승인 시점에 저장과 적용을 한 트랜잭션으로 호출 |
| 알림 | 검수 완료 알림 발송 | 종료 상태를 기록하는 트랜잭션에서 발행한 완료 이벤트 |
| 계정 | 탈퇴 시 제출본 삭제 요청 | 회원의 제출본 전부 삭제 |
| 운영자 | 보류 알림 확인, 원인 조치 | 사용자 원문이 없는 보류 알림 |
| 관리자 페이지 | 보류 목록 확인, 해제 | 사용자 원문이 없는 보류 목록<br>사유를 받는 해제 엔드포인트 |
| 관리자 도메인 | 관리자 판정과 감사 기록, 대시보드 집계 | 보류 중 제출본 수 |

<br>

### 2-2 기능 요구사항

| 기능 | 백엔드가 보장하는 것 |
|---|---|
| 접수 | 일반 제작 등록과 공개 범위 외 필드의 수정은 검수 대상<br>간편 제작 완성본과 공개 범위 단독 변경, 이미지 삭제, 스토리 삭제는 검수 없이 반영<br>입력 검증과 용량 예산을 통과한 뒤 대기 상태로 저장하고 접수 응답 |
| 대기 중 제한 | 스토리당 대기 중인 제출본은 한 건<br>대기 중에는 수정과 이미지 삭제를 거절하고 스토리 삭제와 제출본 취소는 허용 |
| 실행 | 대기 중인 제출본을 인스턴스의 빈 슬롯만큼 선점<br>새 이미지는 변경할 수 없는 복사본으로 검수<br>AI 서버 호출은 트랜잭션 밖 |
| 결과 반영 | 승인은 등록 저장 또는 수정 적용과 제출본 승인 표시를 한 트랜잭션으로 커밋<br>반려와 실패는 현재 스토리를 바꾸지 않고 입력, 위반 항목, 이미지 오류, 오류 코드를 보존<br>종료 상태 기록과 같은 트랜잭션에서 완료 이벤트 발행 |
| 회차 | 선점과 재제출마다 회차를 올리고 같은 회차의 대기 중 제출본에만 결과 반영<br>삭제된 제출본의 결과나 이전 회차의 결과는 무시 |
| 재시도와 보류 | 일시 실패는 대기 상태를 유지한 채 두 번 자동 재시도<br>세 번째 실패는 보류하고 운영자에게 알림<br>내용 위반이나 사용자가 고쳐야 하는 이미지 오류가 있으면 재시도하지 않음 |
| 보류 조회와 해제 | 관리자 API로 보류 중 제출본을 보류 시각 순으로 조회<br>조회 응답에 사용자 입력 원문 없음<br>해제는 보류 상태만, 사유 필수, 감사 로그 대상<br>해제하면 재시도 예산이 초기화되고 다음 폴링에서 새 회차로 선점 |
| 임대 복구 | 실행 중 인스턴스가 사라지면 임대가 끝난 뒤 다른 인스턴스가 다시 선점 |
| 조회 | 소유자만 제출본 상세와 미승인 목록 조회<br>위반 항목과 이미지 오류의 위치는 현재 폼 기준으로 재대응 |
| 재제출 | 신규 등록의 반려본과 실패본만 같은 식별자로 재접수<br>수정본은 수정 요청으로 같은 행을 덮어씀 |
| 취소 | 승인되지 않은 제출본은 대기 중이어도 삭제 |
| 노출 제한 | 승인 전 제출본은 현재 스토리가 아니므로 목록, 검색, 상세, 공개 스냅샷, 채팅에 나타나지 않음 |
| 계정 상태 | 정지 계정의 접수, 재제출, 취소 거절<br>탈퇴 계정의 제출본은 실행하지 않음 |

<br>

### 2-3 다른 주체와의 역할 분담

| 판단과 작업 | 담당 |
|---|---|
| 검수 기준과 위반 판정 | AI 서버<br>백엔드는 기준을 중복 정의하지 않고 응답 형식만 검증 |
| 이미지 내려받기와 형식, 판독 가능 여부 | AI 서버<br>백엔드는 오류 코드로 재시도 여부만 판정 |
| 등록과 수정 입력의 필수값, 길이, 개수, 이미지 객체 검증 | 스토리 도메인<br>백엔드는 통과한 입력을 접수 |
| 승인 결과의 저장과 수정 적용 | 스토리 도메인<br>백엔드는 적용 호출과 승인 표시를 한 트랜잭션으로 묶음 |
| 검수 완료 알림 발송 | 알림 도메인<br>백엔드는 완료 이벤트 발행 |
| 반려 사유의 표시와 재제출 폼 구성 | 클라이언트<br>백엔드는 현재 폼 기준 위치와 사유 제공 |
| 보류 원인 조치 | 운영자<br>AI 서버와 이미지 저장소 상태를 사람이 확인하고 고침 |
| 보류 해제 | 관리자가 관리자 API로 수행<br>백엔드는 보류 필드 초기화와 감사 기록 |
| 관리자 판정과 감사 기록 | 관리자 도메인 |
| 판정 기록 열람 | AI 서버의 관측 도구 |

<br>

### 2-4 제품 제약

**1. 입력**

| 항목 | 규칙 |
|---|---|
| 제출본 식별자 | UUID |
| 재제출 본문 | 일반 제작 등록 요청과 같은 구조 |
| 목록 조회 건수 | 1~100, 기본 100 |
| 해제 사유 | 1~500자 |

<br>

**2. 개수와 한도**

| 항목 | 값 |
|---|---|
| 대기 중 제출본 | 스토리당 1건 |
| 미승인 제출본 | 스토리당 수정 1건, 신규 등록은 등록 건당 1건 |
| 자동 재시도 | 일시 실패당 2회 |
| 용량 예산 | 이미지 base64 예상 크기와 검수 입력 JSON 합계 40MiB |
| 크기를 알 수 없는 유지 이미지 | 장당 5MiB로 계산 |

<br>

**3. 제출본 상태**

| 상태 | 의미 | 다음 상태 |
|---|---|---|
| `PENDING` | 대기, 실행 중, 재시도 예약, 보류 | `APPROVED`, `REJECTED`, `FAILED`, 삭제 |
| `APPROVED` | 승인되어 현재 스토리에 반영됨 | 없음 |
| `REJECTED` | 내용 위반으로 반려 | 재제출로 `PENDING`, 삭제 |
| `FAILED` | 실행 실패 또는 적용 실패 | 재제출로 `PENDING`, 삭제 |

<br>

### 2-5 데이터 보존

| 대상 | 요구사항 |
|---|---|
| 승인본 | 감사용으로 보존<br>이후 수정은 새 제출본 |
| 반려본과 실패본 | 재제출, 취소, 스토리 삭제, 회원 탈퇴까지 보존<br>입력 전체와 위반 항목, 이미지 오류 보존 |
| 대기본 | 취소, 스토리 삭제, 회원 탈퇴 시 삭제 |
| 재제출 | 같은 행을 덮어쓰고 이전 판정은 남기지 않음 |
| 이미지 복사본 | 검수와 승인 저장에 사용<br>삭제하지 않음 |
| 보류 사유 | 제출본에 보존하고 사용자에게 노출하지 않음<br>관리자 보류 목록에는 사유 코드로 노출 |
| 사용자 입력 원문 | 로그, 보류 알림, 관리자 보류 목록에 넣지 않음<br>요청자에게 반환하는 400 메시지에는 인물 이름 등 요청자 입력의 일부가 포함될 수 있음 |
