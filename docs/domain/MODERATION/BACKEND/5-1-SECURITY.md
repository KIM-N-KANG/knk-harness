# 5-1 보안

이 문서는 MODERATION 도메인의 인증 수준, 소유권과 접근 판정, 계정 상태와 동의, 입력 검증, 이미지 보호, 식별자와 개인정보 취급 규칙, 수용한 한계를 정한다.

경로별 인증 수준과 계정 상태별 응답은 계약에, 로그와 알림에 기록하지 않는 데이터는 관측에, 잠금과 회차는 동시성에 있다. ([4-2-1 공통 규칙과 헤더](4-2-CONTRACT.md#4-2-1-공통-규칙과-헤더), [5-4-8 수집 조건과 실패 처리](5-4-OBSERVABILITY.md#5-4-8-수집-조건과-실패-처리), [5-2 동시성](5-2-CONCURRENCY.md))

<br>

### 5-1-1 인증 수준

| 항목 | 처리 |
|---|---|
| 필수 경로 | 제출본 상세, 미승인 목록, 재제출, 취소<br>토큰 없음, 만료, 위조, 주체 형식 오류, 사용자 없음은 인증 실패 |
| 접수 경로 | 등록과 수정 요청의 인증은 STORY 세트가 정하며 모두 인증 필수 |
| 실행 | 요청 없이 폴러가 실행하며 요청자 인증이 없음<br>제출본의 소유 회원 상태를 반영 전에 확인 |

<br>

### 5-1-2 소유권과 접근 판정

| 판정 | 규칙 |
|---|---|
| 제출본 소유 | 소유 회원만 조회, 재제출, 취소<br>타인 소유와 부재를 같은 응답으로 처리해 존재 여부를 드러내지 않음 |
| 수정 접수 | 스토리 소유자만 접수<br>타인 스토리는 권한 없음으로 거절 |
| 재제출 범위 | 신규 등록 종류의 반려 또는 실패본만<br>수정본은 수정 요청으로만 덮어씀 |
| 판정 순서 | 인증, 소유와 존재, 상태 거절, 입력 검증 순서<br>잘못된 본문이라도 타인 제출본에는 부재로 응답 |
| 미승인 노출 | 승인 전 제출본은 소유자의 제출본 조회와 수정 폼에만 나타남<br>목록, 검색, 상세, 공개 스냅샷, 채팅은 현재 스토리만 읽음 |

<br>

### 5-1-3 계정 상태와 동의

| 상태 | 처리 |
|---|---|
| 정지 계정 | 접수, 재제출, 취소 시 사용자 행을 잠근 뒤 계정 상태를 다시 검사해 거절<br>조회는 처리<br>실행 중이던 제출본은 승인 적용 시 계정 상태를 다시 검사해 정지 상태면 적용 실패로 기록 |
| 탈퇴 계정 | 남은 접근 토큰은 공통 필터가 거절<br>탈퇴 시 제출본을 전부 삭제<br>실행 중이던 결과는 반영하지 않음 |
| 재가입 계정 | 새 계정이라 제출본이 없음 |
| 게스트 | 계정 상태 판정의 대상 아님<br>등록과 수정이 인증 필수라 제출본을 만들 수 없음 |
| 미동의 회원 | 동의 게이트가 켜진 환경에서 현행 필수 동의가 없으면 거절<br>허용 목록에 제출본 경로 없음 |

<br>

### 5-1-4 입력 검증

| 대상 | 규칙 |
|---|---|
| 재제출 본문 | STORY 등록 요청과 같은 규칙으로 서비스에서 검증 |
| 이미지 객체 키 | 요청자 소유 업로드 접두어와 허용 형식만 허용<br>검수 전용 복사본 경로를 직접 제출하면 거절 |
| 유지 이미지 식별자 | 현재 스토리에 있거나 이전 검수 폼에 있던 식별자만 허용 |
| 용량 예산 | 이미지 base64 예상 크기와 검수 입력 JSON 합계가 예산을 넘으면 거절<br>합계 계산 시 오버플로를 막아 큰 값이 통과하지 않게 함 |
| 목록 건수 | 정수가 아니면 거절, 범위 밖은 보정 |
| AI 응답 | 전송한 입력의 문자열 경로만 위치로 허용<br>규칙에 어긋나면 응답을 채택하지 않음 |

<br>

### 5-1-5 이미지 보호

| 대상 | 규칙 |
|---|---|
| 복사본 | 새 이미지는 검수 직전에 서버 전용 경로로 복사하고 검수와 승인 저장에 같은 복사본을 사용<br>사용자가 서명 URL로 원본을 다시 올려도 승인된 이미지가 바뀌지 않음 |
| 복사본 경로 | 서명 URL 발급 대상이 아니며 클라이언트가 직접 제출할 수 없음 |
| 원본 대체 금지 | 복사 매핑이 없으면 원본 URL로 대체하지 않고 실행 실패로 처리 |
| 기존 이미지 | 현재 스토리의 기존 이미지는 복사하지 않고 현재 URL을 그대로 검수 |

<br>

### 5-1-6 재시도와 보류의 범위

| 대상 | 규칙 |
|---|---|
| 자동 재시도 | 위반 항목이 없고 사용자가 고쳐야 하는 이미지 오류가 없는 일시 실패에만 적용<br>내용 위반으로 판정된 입력은 반복 호출하지 않음 |
| 형식 오류 응답 | 위반 항목이나 영구 이미지 오류가 담겨 있으면 응답을 채택하지 않더라도 재시도하지 않음 |
| 보류 해제 | 운영자가 SQL로 한 건씩 해제<br>해제 API 없음 |

<br>

### 5-1-7 식별자와 개인정보

| 대상 | 규칙 |
|---|---|
| 입력 원문 | 로그, 오류 메시지, 보류 알림에 넣지 않음 |
| 이미지 URL과 응답 본문 | 로그에 기록하지 않음<br>실행 예외는 종류와 상태 코드만 기록 |
| 보류 알림 | 제출본 공개 식별자, 종류, 사유 코드, 시도 횟수만 전송 |
| 웹훅 주소 | 설정에서만 읽고 로그에 기록하지 않음<br>전송 실패 예외의 메시지도 기록하지 않음 |
| 내부 상태 | 회차, 임대, 재시도 횟수, 다음 시도 시각, 보류 시각과 사유, 검수 폼, 복사 매핑은 응답에 노출하지 않음 |
| AI 전달 | 페르소나를 보내지 않음<br>공개 범위, 최소 턴 수, 폼 안의 식별자, 객체 키, 상태는 검수 입력에서 제외<br>제출본과 스토리의 공개 식별자만 판정 기록 연결용으로 전달 |

<br>

### 5-1-8 수용한 한계

| 한계 | 수용 이유 |
|---|---|
| 임대를 넘긴 실행이 끝나기 전에 다른 인스턴스가 재선점하면 AI를 두 번 호출 | 결과는 회차 조건으로 한 번만 반영<br>임대를 AI 시간 제한보다 길게 둠 |
| 등록에 멱등 키가 없어 중복 제출본이 생김 | 접수 응답 유실 시 사용자가 미승인 목록에서 정리<br>신규 등록은 현재 스토리가 없어 중복 노출이 없음 |
| 보류 알림의 전송을 보장하지 않음 | 보류 상태는 DB에 남아 운영자가 조회할 수 있음<br>실패는 경고 로그 |
