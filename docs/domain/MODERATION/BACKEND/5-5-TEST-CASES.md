# 5-5 테스트 케이스

이 문서는 MODERATION 도메인 코드의 계약과 오류 처리 규칙을 검증할 테스트 범위, 입력과 상황, 기대 결과를 정한다.

실행 명령과 수동 호출 파일 위치는 AGENTS.md에, 기대 결과의 상태 코드는 계약에 있다. ([AGENTS.md](AGENTS.md), [4-2 계약](4-2-CONTRACT.md))

<br>

### 5-5-1 테스트 범위

**1. 테스트 종류**

| 종류 | 확인 범위 | 외부 호출 | 실행 |
|---|---|---|---|
| 단위 | AI 응답 예시별 형식 검증, 재시도 판정, 용량 예산 계산, 보류 알림 본문 | AI 응답은 가짜 HTTP 서버 | CI |
| 통합 | 접수와 제출본 API, 관리자 보류 API, 폴러 선점과 실행, 이미지 복사와 승인 저장, 재시도와 보류, 완료 이벤트 발행, 실행 로그 | AI는 고정 응답 또는 가짜 HTTP 서버<br>이미지 저장소는 호출을 기록하는 구현 | CI<br>H2, 스키마 자동 생성, 마이그레이션 비활성 |
| 선점 PostgreSQL | 실제 DDL의 잠긴 행 건너뛰기 선점, 임대, 회차 | PostgreSQL은 Testcontainers로 실행 | CI |
| 수동 | 엔드포인트 호출, 실제 AI 판정, 보류 알림 | 실행 환경의 실제 의존성 | HTTP 요청 파일 |

테스트 프로파일은 마이그레이션과 폴러의 자동 실행을 비활성화한다. 선점과 실행은 폴러를 직접 호출해 검증한다. 전체 테스트 통과만으로 DB 제약과 실제 판정 품질이 검증되지는 않는다.

<br>

**2. 외부 의존성과 테스트 데이터**

| 대상 | 방법 |
|---|---|
| AI 서버 | 기본은 즉시 승인하는 고정 응답 구현<br>응답 검증과 통신 오류는 가짜 HTTP 서버로 재현 |
| 이미지 저장소 | 복사와 조회를 기록하는 구현으로 교체<br>복사 실패는 예외를 던지는 구현 |
| Slack | 가짜 HTTP 서버로 본문 확인 |
| DB | 통합 테스트는 공유 H2의 PostgreSQL 모드<br>CHECK 제약과 선점 쿼리는 실제 PostgreSQL에서 검증 |
| 시각 | 재시도 간격과 임대는 짧은 설정값으로 검증 |
| 회원 데이터 | 활성, 정지, 탈퇴 계정과 소유 스토리, 반려본과 실패본이 있는 계정 준비 |

### 5-5-2 접수

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 등록 접수 | 유효한 등록 요청 | 202, 대기 상태 제출본 1건, 스토리 없음, 회차 1 |
| 수정 접수 | 유효한 수정 요청 | 202, 수정 종류 제출본, 현재 스토리 불변 |
| 공개 범위 단독 | `visibility`만 담은 수정 | 200 수정 폼, 제출본 없음 |
| 대기 중 수정 | 대기 중 제출본이 있는 스토리에 수정 | 409 |
| 대기 중 이미지 삭제 | 대기 중 제출본이 있는 스토리의 표지, 인물 이미지 삭제 | 409 |
| 미승인 수정본 덮어쓰기 | 반려된 수정본이 있는 스토리에 다시 수정 | 같은 제출본 식별자, 판정 필드 초기화, 회차 증가 |
| 삭제된 이미지 재제출 | 반려 뒤 삭제된 기존 이미지 식별자를 포함한 수정 | 검증 통과, 폼에서 제외 |
| 알 수 없는 이미지 식별자 | 이전 폼에 없던 이미지 식별자 | 400 |
| 용량 초과 | 이미지 합계와 입력 JSON이 예산 초과 | 400 `IMAGES_TOO_LARGE`, 제출본 없음 |
| 유지 이미지 크기 미상 | 저장소 조회 실패 | 장당 상한값으로 계산 |
| 정지와 탈퇴 | 정지 회원, 탈퇴 회원 | 403, 401 |

### 5-5-3 제출본 조회

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 상세 | 본인 제출본 | 200, 복원한 폼, 상태, 위반 항목, 이미지 오류 |
| 타인과 부재 | 타인 제출본, 없는 식별자, 형식 오류 | 404 |

| 위치 재대응 | 반려 뒤 인물 순서가 바뀐 수정 폼 | 위반 항목 경로가 현재 인덱스 |
| 사라진 대상 | 반려 뒤 삭제된 이미지의 오류 | 응답에서 제외 |
| 표지 변경 | 반려 뒤 표지가 바뀜 | 표지 위반 항목 제외 |

| 목록 건수 | `limit` 0, 101, 문자열 | 1, 100, 400 |
| 수정 폼 메타데이터 | 반려된 수정본이 있는 스토리의 수정 폼 | `submission`에 식별자, 상태, 위반 항목 |

### 5-5-6 응답 검증과 결과 반영

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 승인 등록 | 승인 응답, 등록 종류 | 스토리 생성, 복사본 URL 저장, 승인 표시, 완료 이벤트 |
| 승인 수정 | 승인 응답, 수정 종류 | 현재 스토리 적용, 스냅샷 갱신, 승인 표시 |
| 반려 | 위반 항목 1개 | 반려 표시, 위반 항목 보존, 현재 스토리 불변, 완료 이벤트 |
| 이름과 소개 위치 | 위치 `protagonistName`, `characters[0].description`, 종류 `TEXT`인 위반 항목 | 형식 합격, 반려 표시, 두 위반 항목 보존 |
| 영구 이미지 오류 | `IMAGE_INVALID`와 위반 항목 | 실패 표시, 둘 다 보존, 재시도 없음 |
| 형식 오류 | 없는 경로, 알 수 없는 기준, 중복 이미지 경로 | `MODERATION_UNAVAILABLE` 재시도 판정, 위반 항목 미보존 |
| 형식 오류와 위반 항목 | 형식 오류 응답에 위반 항목 포함, 승인인데 위반 항목 있음 | 실패 표시, 재시도 없음 |
| 통신 실패 | 연결 실패, 읽기 시간 초과, 5xx, 빈 본문 | `MODERATION_UNAVAILABLE` 재시도 판정 |
| 적용 실패 | 승인 뒤 적용 검증 예외 | 현재 스토리 변경 롤백, `APPLY_FAILED` 실패, 완료 이벤트 |
| 늦은 결과 | 재제출 뒤 이전 회차의 승인 | 무시 |
| 탈퇴와 삭제 | 실행 중 회원 탈퇴, 스토리 삭제 | 반영 없음 |
| 결과 기록 장애 | 기록 트랜잭션 예외 | 대기 상태와 임대 유지, 지연 경고 |

### 5-5-8 관리자 보류 목록과 해제

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 인증 | 토큰 없음, 앱 접근 토큰, 역할 없는 관리자 토큰 | 401, 401, 403 |
| 목록 | 보류 2건, 재시도 예약 1건, 대기 1건, 반려 1건 | 보류 2건만 보류 시각 오름차순, 사유 코드, 회차, 소유 회원 공개 식별자 포함 |
| 목록 범위 | 응답 본문 | 입력 원문, 검수 폼, 이미지 URL 필드 없음 |
| 목록 페이지 | 보류 3건, `size` 2 | 첫 페이지 2건, `totalPages` 2<br>`page` 0과 `size` 101은 400 |
| 해제 | 보류 제출본 | 200, 보류 필드 비움, 재시도 횟수 0, 임대 없음, 감사 로그 `SUBMISSION_HOLD_RELEASED`에 사유 코드와 회차 |

| 동시 해제 | 같은 제출본에 동시 2건 | 한쪽 200, 다른 쪽 409, 감사 로그 1행 |
| 해제와 취소 | 소유자 취소 뒤 해제 | 404 |
| 감사 기록 실패 | 감사 로그 삽입 예외 | 500<br>보류 유지 |

### 5-5-9 관리자 제출본 목록과 상세

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 인증 | 토큰 없음, 앱 접근 토큰, 역할 없는 관리자 토큰 | 401, 401, 403 |
| 전체 목록 | 대기 1, 보류 1, 승인 1, 반려된 등록 1, 실패 1 | 5건, 접수 시각 내림차순, 상태가 `PENDING`, `HELD`, `APPROVED`, `REJECTED`, `FAILED` |
| 상태 필터 | `status` 각각 | `PENDING`은 보류를 빼고 `HELD`는 보류만, 나머지는 그 상태만 |
| 반려된 등록 | 스토리 행이 없는 반려 등록본 | `story.storyId` `null`, `story.title`이 제출한 제목, `issueRules`와 `firstIssueReason` |
| 수정 제출의 제목 | 수정 제출본, 현재 스토리 제목이 바뀐 뒤 | `story.title`이 현재 스토리 제목 |
| 위반 요약 | 위반 항목 3개(기준 `DRUGS`, `EXTREME_GORE`, `DRUGS`) | `issueCount` 3, `issueRules` `["DRUGS","EXTREME_GORE"]`, `firstIssueReason`이 첫 항목 이유 |
| 보류와 실패 코드 | 보류 1건과 실패 1건 | 보류는 `holdReason`과 `heldAt`, 실패는 `errorCode`와 `decidedAt` |
| 정렬 | `sort=decidedAt&order=asc`, 판정 전 행 포함 | 판정 시각 오름차순, 판정 전 행은 맨 뒤 |
| 동률 정렬 | 같은 접수 시각 3건과 판정 시각이 없는 2건, `size` 2로 `sort=createdAt`과 `sort=decidedAt` | 같은 시각과 값 없는 행이 제출본 공개 식별자 오름차순<br>페이지를 넘겨도 중복과 누락 없음 |
| 필터 | `memberId`, `storyId`, `from`과 `to`, `q`에 제출본 식별자와 제목 일부 | 각각 그 조건의 제출본만 |
| 쿼리 오류 | `status=DRAFT`, `sort=updatedAt`, `memberId=abc`, `page=0` | 400 |
| 목록 범위 | 응답 본문 | 설정 본문, 검수 폼, 이미지 URL, 객체 키 없음 |
| 상세 | 반려된 등록본 | `fields`의 제목, 한 줄 소개, 소개, 기본 주인공 이름, 장르, 공개 범위, 인물 이름, 위반 항목 전체, 이미지 결과 |
| 이미지 검수 상태 | 승인 제출본, 표지에 `IMAGE` 위반이 있는 반려 제출본, 인물 이미지에 `IMAGE_INVALID`가 있는 실패 제출본, 대기와 보류 제출본 | 승인은 모두 `APPROVED`<br>반려는 표지 `REJECTED`, 다른 이미지 `APPROVED`<br>실패는 그 이미지 `ERROR`와 `errorCode`, 다른 이미지 `PENDING`<br>대기와 보류는 모두 `PENDING`<br>폼의 상태 값과 무관 |
| 상세 범위 | 응답 본문 | 설정 본문, 시작 설정, 주요 사건, 인물 설명, 이미지 URL, 객체 키 없음 |
| 상세 재대응 | 대상 인물이 사라진 위반 항목이 있는 수정 제출본 | 상세 `issues`에서 빠지고 목록 `issueCount`는 저장된 수 |
