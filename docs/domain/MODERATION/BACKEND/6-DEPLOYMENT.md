# 6. 배포

이 문서는 MODERATION 도메인이 포함된 서버의 배포 단위와 의존 대상, 배포 경로, 이 도메인이 읽는 환경 변수와 시크릿, 배포 조건, 설정 변경, 적용과 복구 절차를 정한다.

서버 전체 배포 절차 중 MODERATION 도메인과 관련된 항목만 다룬다.

재시도 간격과 시간 한도는 오류 처리에, 관측 스택과 조회 도구는 관측에 있다. ([5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도), [5-4-1 관측 스택](5-4-OBSERVABILITY.md#5-4-1-관측-스택))

<br>

### 6-1 배포 단위와 의존성

배포 단위는 서버 컨테이너 하나다. MODERATION만 따로 배포하지 않는다. 폴러와 실행기는 서버 프로세스 안에서 실행된다. 이 도메인이 기동과 처리에 쓰는 의존 대상은 다음과 같다.

| 의존 대상 | 내용 | MODERATION 도메인이 쓰는 것 |
|---|---|---|
| PostgreSQL | 기동 시 마이그레이션 적용 | 제출본 테이블 |
| AI 서버 | 운영은 별도 ECS 서비스, 개발은 같은 태스크의 컨테이너 | 검수 요청<br>스텁이면 불필요 |
| S3 assets 버킷 | Terraform 관리 | 업로드 원본 HEAD와 검수용 복사 |
| Slack | Incoming Webhook | 보류 알림 |
| Data Prepper | 트레이스를 받아 OpenSearch에 적재 | 트레이스 전송 |

<br>

| 의존 대상 | 연결과 설정 실패 시 동작 |
|---|---|
| AI 서버 주소 | 비어 있으면 기동 실패 |
| AI 시간 제한 | 150초 이하이면 기동 실패 |
| 슬롯 수 | 0 이하이면 기동 실패 |
| 임대 | AI 시간 제한과 같거나 짧으면 기동 실패 |
| 재시도 간격 | 양수 기간 정확히 두 개가 아니면 기동 실패 |
| 용량 예산 | 0 이하이면 기동 실패 |
| PostgreSQL | 연결할 수 없으면 기동 실패 |
| AI 서버 | 호출 실패와 시간 초과는 실행 실패로 분류해 재시도 판정 |
| S3 assets 버킷 | 이미지가 있는 요청은 저장소 미설정 시 사용 불가로 응답하고 제출본을 만들지 않음<br>복사 실패는 실행 실패로 분류 |
| Slack 웹훅 | 비어 있으면 보류 알림 대신 경고 로그 |
| Data Prepper | 추적을 켜고 주소가 비면 기동 실패<br>추적이 꺼지면 스팬을 만들되 전송하지 않음 |

<br>

### 6-2 배포 경로

테스트와 빌드를 마친 뒤 이미지를 게시하고 배포한다. `main` push는 같은 소스 트리의 `dev` 성공 실행이 있으면 테스트를 다시 실행하지 않는다. `dev`로 PR을 올리면 테스트와 빌드만 한다.

| 단계 | 개발 | 운영 |
|---|---|---|
| 자동 시작 | `dev` push | `main` push |
| 머지 규칙 | 기능 브랜치에서 `dev`로 squash | `release/vX.Y.Z`에서 `main`으로 merge commit |
| 이미지 태그 | 커밋 SHA 앞 7자리, 환경 태그 `dev` | 커밋 SHA 앞 7자리, 배포 시 `latest` 태그 지정<br>실패하면 이전 digest로 복원 |
| 상태 검사 | 배포 완료, 서버 컨테이너 정상, health `UP` | 동일 |

<br>

### 6-3 환경 변수와 시크릿

환경 변수가 설정 파일의 값보다 우선한다. 설정은 기동 시 읽으므로 변경 후 새 태스크를 시작해야 적용된다. 환경 변수는 Terraform이 태스크 정의에 주입하고 시크릿은 Secrets Manager에서 주입한다. AWS 자원에는 태스크 역할로 접근하므로 별도 접근 키를 주입하지 않는다. 이 도메인이 읽는 설정만 적는다. 기본값이 "빈 값"이면 변수가 없어도 빈 문자열로 기동한다. "없음"이면 변수가 없을 때 기동에 실패한다.

<br>

**1. 검수 실행**

| 이름 | 기본값 | 주입 출처 | 비고 |
|---|---|---|---|
| `MANYAK_AI_BASE_URL` | 없음 | 운영 태스크 환경 변수, Cloud Map 내부 주소<br>개발 태스크 환경 변수 `http://localhost:8000` | |
| `MANYAK_AI_MODERATION_TIMEOUT` | `180s` | 주입 없음 | 150초보다 길어야 함 |
| `MANYAK_AI_MODERATION_POOL_SIZE` | `4` | 주입 없음 | 인스턴스의 실행 슬롯 수 |
| `MANYAK_AI_MODERATION_RECLAIM_AFTER` | `300s` | 주입 없음 | 임대<br>AI 시간 제한보다 길어야 함 |
| `MANYAK_AI_MODERATION_POLL_INTERVAL` | `1000` | 주입 없음 | 밀리초 |
| `MANYAK_AI_MODERATION_POLL_ENABLED` | `true` | 주입 없음 | |
| `MANYAK_AI_MODERATION_RETRY_DELAYS` | `1m,5m` | 주입 없음 | 양수 기간 두 개 |
| `MANYAK_AI_MODERATION_REQUEST_BUDGET_BYTES` | `41943040` | 주입 없음 | |

AI 클라이언트의 스텁 여부는 환경 변수 없이 설정 파일이 정한다. 개발과 운영은 실제로 호출한다.

<br>

**2. 보류 알림**

| 이름 | 기본값 | 주입 출처 | 비고 |
|---|---|---|---|
| `MANYAK_SLACK_MODERATION_WEBHOOK_URL` | 빈 값 | 주입 없음 | 설정하지 않으면 아래 신고 웹훅을 사용<br>빈 값으로 설정하면 경고 로그만 기록 |
| `MANYAK_SLACK_REPORT_WEBHOOK_URL` | 빈 값 | 운영 Secrets Manager | 개발은 비어 있어 보류 알림 대신 경고 로그만 남음 |

<br>

**3. 관측**

| 이름 | 기본값 | 주입 출처 | 비고 |
|---|---|---|---|
| `MANYAK_TRACING_ENABLED` | `false` | 운영 Terraform 변수 | |
| `MANYAK_OTLP_TRACES_ENDPOINT` | 빈 값 | 추적을 켠 운영 환경에 Data Prepper 내부 주소 주입 | 추적을 켜면 필수 |
| `MANYAK_TRACING_SAMPLING` | `1.0` | 주입 없음 | |
| `MANYAK_OTLP_METRICS_ENABLED` | `false` | 운영 Terraform 변수, 전송 URL과 인증 헤더는 Secrets Manager | Grafana Cloud로 전송 |
| `SENTRY_DSN` | 빈 값 | 개발과 운영 Secrets Manager | |

### 6-4 배포 조건

| 확인 항목 | 기준 | 자동 여부와 한계 |
|---|---|---|
| AI 계약 | 검수 요청과 응답 형식이 AI 서버 배포본과 같음<br>응답 형식이 바뀌면 AI 서버를 먼저 배포 | 수동 검토 |
| 시간 설정 | 임대가 AI 시간 제한보다 길고 AI 시간 제한이 AI 서버의 요청 제한보다 길어야 함 | 기동 시 검증 |
| 와이어 계약 변경 | 제출본 응답이 바뀌면 웹과 앱의 처리를 함께 배포 | 수동 검토 |
| 컬럼 제거 | 해당 컬럼을 읽는 구버전 태스크가 사라진 다음 릴리스에서 제거 | 수동 검토 |
| 마이그레이션 | 기동 시 실행하므로 새 마이그레이션은 해당 코드보다 먼저 적용<br>재실행해도 같은 결과 | 기동 시 자동 적용<br>마이그레이션 경로 변경 PR은 `tbls lint`와 `dbdoc/` 비교를 CI에서 자동 실행 |
| 코드 테스트 | 전체 테스트 통과 | CI 자동 |
| 컨테이너 기동 | 컨테이너 헬스체크와 `/actuator/health` `UP` | CI 자동<br>AI 서버 호출과 S3 복사는 검사하지 않음 |

<br>

### 6-5 설정 변경

| 변경 대상 | 변경 위치와 적용 | 확인 조건 |
|---|---|---|
| 슬롯 수, 임대, 시간 제한, 재시도 간격, 용량 예산 | 환경 변수 추가 후 새 태스크 시작 | 기동 로그에 설정 검증 오류 없음 |
| 폴링 중지 | 환경 변수 변경 후 새 태스크 시작 | 대기본이 선점되지 않음 |
| 보류 웹훅 | Secrets Manager 값 변경 후 새 태스크 시작 | 다음 보류 알림 수신 |
| 보류 해제 | 관리자 API<br>재배포 없음 | 다음 폴링에서 선점, 보류 목록에서 사라짐, 감사 로그 |
| 추적과 지표 전송 | 운영 Terraform 변수 변경 후 apply | |

### 6-6 적용과 복구

**1. 적용 순서**

| 순서 | 작업 | 확인 항목 |
|---|---|---|
| 1 | 설정 확인 | AI 주소, 시간 설정 관계, 마이그레이션 순서 |
| 2 | 동반 배포 확인 | AI 응답 형식 변경 시 AI 서버 먼저<br>제출본 응답 변경 시 클라이언트와 함께 |
| 3 | 배포 실행 | 서버 배포 절차 |
| 4 | 적용 결과 확인 | 배포 후 확인 항목 |

<br>

**2. 진행 중인 요청**

| 상황 | 처리와 한계 |
|---|---|
| 롤링 교체 중 실행 | 종료되는 태스크의 실행은 임대가 끝나면 새 태스크가 새 회차로 재선점<br>이미 받은 판정은 회차가 달라 무시되고 AI 서버를 다시 호출 |
| 롤링 교체 중 접수 | 대기 행만 커밋되므로 어느 태스크든 선점 가능 |
| 개발 stop-then-start | 교체 중 모든 요청 실패<br>실행 중이던 제출본은 임대 만료 뒤 재선점 |

<br>

**3. 복구**

자동 복구가 실행돼도 서비스가 정상으로 돌아오지 않았을 수 있으므로 실제 서버 상태를 확인한다.

| 상황 | 복구 방식 | 한계와 확인 사항 |
|---|---|---|
| 새 태스크 헬스체크 실패 | 직전 배포로 자동 복귀 | 환경 태그가 실패한 이미지를 가리킬 수 있으므로 다음 재배포 전에 태그 확인 |
| 배포는 정상이나 동작 오류 | revert 커밋 릴리스 또는 이전 이미지를 환경 태그로 다시 태깅한 뒤 새 배포 | health 기반 자동 복구는 실행 실패를 탐지하지 않음 |
| 마이그레이션 적용 후 되돌리기 | 적용된 마이그레이션은 되돌리지 않음 | 새 컬럼은 구버전 코드와 호환되도록 추가 |
| AI 서버 장애로 보류 누적 | 원인 해결 뒤 관리자 API로 건별 해제 | 해제 전까지 사용자에게는 대기 상태 |
| 잘못 승인된 제출본 | 되돌리기 없음 | 운영자가 스토리를 비공개로 바꾸거나 삭제 |
| 설정 오류 | 잘못된 값을 이전 값으로 복구 후 새 태스크 시작 | 이미지 복원만으로 설정은 복원되지 않음 |

<br>

### 6-7 배포 후 확인

| 확인 항목 | 자료 | 기준 |
|---|---|---|
| 기동 | 해당 배포 ID의 태스크 상태, 헬스체크 `/actuator/health`, 스모크 테스트 | 의도한 이미지로 기동, `UP` |
| 선점 | 제출본 테이블의 대기본 임대 시작 시각 | 대기본이 폴링 주기 안에 선점됨 |
| 실행 | 로그 `moderation_execution_failed` | 배포 전과 같은 수준 |
| 접수 | 요청 로그의 `/api/v1/stories/general`, `/api/v1/stories/submissions` 상태 분포 | 5xx 없음 |
| 보류 | 제출본 테이블의 보류 행 | 늘지 않음 |

<br>

### 6-8 배포 실패 진단

| 실패 상황 | 확인할 자료와 위치 | 원인별 조치 |
|---|---|---|
| 기동 중 설정 검증 실패 | 시작 로그의 예외 메시지 | AI 주소, 시간 제한과 임대 관계, 재시도 간격, 슬롯 수, 용량 예산 중 해당 값 수정 후 새 태스크 시작 |
| 대기본이 선점되지 않음 | 제출본 테이블, 폴링 설정 | 폴링이 꺼졌거나 보류 또는 예약 상태인지 확인 |
| 실행이 전부 실패 | 로그 `moderation_execution_failed`의 예외 클래스와 HTTP 상태 | 연결 실패면 AI 주소와 보안 그룹<br>시간 초과면 AI 서버 상태<br>4xx면 AI 계약 불일치 |
| 보류가 늘어남 | 보류 알림<br>관리자 보류 목록의 사유 코드 | 사유 코드별로 AI 서버와 이미지 저장소 확인 후 관리자 API로 해제 |
| 승인이 반영되지 않음 | 제출본 `errorCode` `APPLY_FAILED`, 요청 로그 | 적용 단계의 검증 규칙과 접수 검증의 차이 확인 |
