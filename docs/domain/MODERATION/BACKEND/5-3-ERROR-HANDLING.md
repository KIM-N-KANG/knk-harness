# 5-3 오류 처리

이 문서는 MODERATION 도메인의 응답 규칙, 앱 코드, 오류 분류, 복구 규칙, 재시도와 시간 한도, 최종 실패, 전달 실패 처리, 오류 로그 기준을 정한다.

엔드포인트별 실패 조건과 응답 형식은 계약에, 흐름별 처리 순서는 처리 흐름에, 선점과 회차는 동시성에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-2-2 회차와 1회 반영](5-2-CONCURRENCY.md#5-2-2-회차와-1회-반영))

<br>

### 5-3-1 응답 규칙

| 항목 | 규칙 |
|---|---|
| `code` | HTTP 상태 이름이 기본<br>클라이언트 안내가 달라질 때만 앱 코드 사용 |
| `message` | 사용자 안내 문구<br>500은 고정 안내 문구 |
| `details` | 선언적 필드 검증, 타입 변환, 기본 주인공 이름 검증 실패 시 채움<br>그 외 서비스에서 판정한 400은 빈 배열로 응답하고 `message`에 사유 기록 |
| 판정 결과 | 반려와 실행 실패는 접수 응답을 오류로 바꾸지 않고 제출본 상태와 `errorCode`로 전달 |

<br>

### 5-3-2 앱 코드

코드 문자열은 API 계약이므로 유지한다. 제출본의 `errorCode` 값은 HTTP 실패 코드가 아니라 조회 응답의 필드이며 계약에 있다.

| 상태 | `code` | 의미 |
|---|---|---|
| 400 | `IMAGES_TOO_LARGE` | 검수 요청 예상 용량이 예산 초과 |
| 400 | `INVALID_GENRE` | 허용되지 않는 장르 |
| 400 | `UPLOAD_NOT_FOUND` | 객체 키에 아직 파일이 없음 |
| 403 | `CONSENT_REQUIRED` | 동의 게이트가 켜진 환경에서 미동의 회원의 허용 목록 밖 요청 |

<br>

### 5-3-3 오류 분류

| 오류 | 발생 위치 | 처리 |
|---|---|---|
| 입력 오류 | 폼 조립기의 검증 | 400으로 변환 |
| 용량 초과 | 용량 검사 | 앱 코드가 포함된 400 |
| 상태 거절 | 제출 서비스 | 대기 중 수정, 수정본 재제출, 승인본 취소는 409 |
| 소유와 존재 | 제출 서비스 | 타인 소유, 부재, 형식 오류는 404 |
| 계정 상태 | 제출 서비스의 상태 재검사 | 정지는 403, 탈퇴와 사용자 없음은 401 |
| 이미지 복사 실패 | 이미지 복사 | `MODERATION_UNAVAILABLE`로 재시도 판정 |
| AI 통신 실패, 시간 초과, 빈 응답, 오류 상태 응답 | AI 클라이언트 | `MODERATION_UNAVAILABLE`로 재시도 판정<br>AI 서버의 4xx도 같은 분류 |
| AI 응답 형식 오류 | 응답 검증 | `MODERATION_UNAVAILABLE`<br>위반 항목이나 영구 이미지 오류가 담겼으면 재시도 없이 실패 |
| AI 일시 오류 코드 | 판정 결과 | `IMAGE_DOWNLOAD_FAILED`, `MODEL_CALL_FAILED`는 재시도 판정 |
| AI 영구 이미지 오류 | 판정 결과 | `IMAGE_INVALID`, `IMAGE_UNREADABLE`는 즉시 실패<br>검증된 위반 항목과 이미지 오류 보존 |
| 적용 검증 실패 | 승인 적용 | 현재 스토리 변경을 롤백한 뒤 `APPLY_FAILED`로 실패 |
| 복사 매핑 기록 장애, 결과 기록 장애 | DB | 롤백하고 대기 상태의 임대를 남겨 재선점 |
| 실행기 거부 | 폴러 | 임대 반환 뒤 경고<br>반환에 실패하면 임대 만료 뒤 재선점 |
| 보류 알림 전송 실패 | 보류 알림 | 경고만, 보류 상태 유지 |
| 보류 해제 거절 | 보류 관리 | 보류 중이 아니면 409<br>없는 제출본은 404 |
| 공개 중단 거절 | 공개 중단 | 이미 공개 중단, 삭제, 공식 계정 소유, 소유 회원 없음은 409<br>없는 스토리는 404<br>사유 분류, 메모, 경로 형식 오류는 400 |
| 감사 기록 실패 | 관리자 도메인 연산 | 해제나 공개 중단과 함께 롤백<br>500 |
| 공개 중단 알림 기록 실패 | 알림 도메인의 알림 내역과 원격 모드 아웃박스 기록 | 공개 중단과 함께 롤백<br>500 |
| 예상하지 못한 오류 | 어디서든 | 전역 핸들러가 500 고정 문구로 응답하고 Sentry 전송 |

<br>

### 5-3-4 오류별 처리

- 실행 실패의 위반 항목은 AI 응답에서 검증된 것만 보존한다. 서버가 만든 실패에는 위반 항목을 넣지 않는다.
- 형식 오류 응답의 위반 항목과 이미지 오류는 채택하지 않는다. 그 안에 위반 항목이나 영구 이미지 오류가 보이면 사용자 수정 사유가 있다고 보고 재시도하지 않는다.
- 이미지 오류가 있으면 위반 항목과 함께 보존해 사용자가 내용 수정과 이미지 교체 사유를 한 번에 확인할 수 있게 한다.
- 승인 적용 실패는 현재 스토리를 바꾸지 않는다. 사용자가 입력을 확인하고 재제출한다.
- 재시도 예약과 보류는 사용자에게 대기 상태로 보이며 오류 코드와 판정 시각은 비어 있다.

<br>

### 5-3-5 재시도와 시간 한도

**1. 재시도**

- 일시 실패는 정해진 간격으로 두 번 자동 재시도하고 세 번째 실패 시 보류한다. 예약과 보류 모두 대기 상태를 유지하고 임대를 반환한다.
- 내용 위반, 영구 이미지 오류, 적용 실패는 자동 재시도하지 않는다. 사용자가 재제출한다.
- DB 장애와 임대 만료로 인한 재선점은 재시도 예산과 별개다.
- AI 호출에는 애플리케이션 재시도가 없다.
- 보류 알림은 재전송하지 않는다.

<br>

**2. 시간 한도**

| 대상 | 제한 시간 | 적용 범위 |
|---|---|---|
| 폴링 주기 | 1초 고정 지연 | 선점 |
| 임대 | 300초 | 선점부터 결과 기록까지<br>AI 시간 제한보다 길어야 함 |
| AI 연결 | 5초 | 검수 요청 |
| AI 읽기 | 180초 | 검수 요청<br>150초보다 길어야 함 |
| 자동 재시도 간격 | 1분, 5분 | 첫째와 둘째 재시도 |
| 보류 알림 | 연결 2초, 읽기 3초 | Slack 전송 |

<br>

### 5-3-6 최종 실패와 부분 완료

| 결과 | 처리 |
|---|---|
| 반려 | 입력과 위반 항목 보존, 현재 스토리 불변<br>사용자가 재제출 |
| 실패 | 입력, 위반 항목, 이미지 오류, 오류 코드 보존, 현재 스토리 불변<br>사용자가 재제출 |
| 보류 | 대기 상태 유지<br>완료 이벤트 없음<br>운영자가 원인을 조치하고 관리자가 해제하면 새 회차로 실행 |
| 승인 적용 실패 | 현재 스토리 변경 롤백, `APPLY_FAILED` 실패 |
| 공개 중단으로 끝낸 제출본 | `STORY_TAKEN_DOWN` 실패, 입력 보존, 완료 이벤트 없음<br>사용자가 수정 요청으로 다시 접수 |
| 임대 만료 | 다음 폴링에서 새 회차로 재선점<br>이전 회차의 늦은 결과는 무시 |
| 취소, 회원 탈퇴, 스토리 삭제, 회차 불일치 뒤 도착한 결과 | 무시 |

<br>

### 5-3-7 전달 실패 처리

| 상황 | 백엔드 | 클라이언트와의 경계 |
|---|---|---|
| 접수 응답 유실 | 제출본은 접수됨 | 미승인 목록에서 확인<br>등록을 다시 보내면 새 제출본, 수정은 대기 중이면 409 |
| 재제출 응답 유실 | 같은 제출본이 대기 상태 | 재조회로 확인<br>다시 보내면 대기 중이라 409 |
| 취소 응답 유실 | 삭제됨 | 재요청은 404 |
| 공개 중단 응답 유실 | 공개 중단됨 | 재요청은 409<br>관리자 페이지가 스토리 상세를 다시 조회해 확인 |
| 완료 알림 미도달 | 알림 도메인의 범위 | 제출본 조회와 미승인 목록으로 확인 |

<br>

### 5-3-8 로그와 Sentry

경고 로그의 이름과 기록 내용은 관측에 있다. ([5-4-3 구조화 로그 이벤트](5-4-OBSERVABILITY.md#5-4-3-구조화-로그-이벤트))

| 대상 | 규칙 |
|---|---|
| 5xx | 스택트레이스와 함께 ERROR로 기록하고 Sentry 전송 |
| 예상 가능한 4xx | Sentry 미전송<br>원인 예외가 있으면 클래스와 메시지를 한 줄로 WARN, 없으면 DEBUG |
| 실행 실패와 지연 | WARN으로 기록<br>예외 객체와 입력, URL, 응답 본문은 기록하지 않음 |
| 판정 결과 | 요청의 응답으로 전달하지 않으므로 Sentry에 없음 |
