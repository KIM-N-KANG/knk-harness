# 1. 배경

이 문서는 마냑의 게시물 검수, MODERATION 도메인에서 백엔드가 맡는 역할, 관련 주체와 공통 용어를 정한다.

<br>

### 1-1 도메인

MODERATION 도메인은 사용자가 만든 스토리가 공개되기 전에 내용과 이미지를 검수하는 일을 다룬다. 일반 제작으로 등록하거나 수정한 스토리는 바로 반영되지 않고 제출본으로 접수된다. AI 서버가 제출본을 판정하면 승인된 것만 라이브에 반영한다. 반려와 실패는 사유와 함께 보존해 사용자가 고쳐서 다시 제출할 수 있게 한다.

<br>

### 1-2 서비스 배경

마냑은 사용자가 스토리와 세계관을 만들고 채팅으로 AI와 함께 이야기를 이어가는 AI 인터랙티브 스토리 서비스다. 공개 스토리는 다른 사용자가 읽고 플레이하므로 미성년자 성 착취, 노골적 성 표현, 마약, 극단적 폭력 같은 내용을 걸러야 한다. 판정에는 텍스트와 이미지가 함께 필요하며 2분 넘게 걸릴 수 있다. 사용자가 화면에서 기다리지 않도록 비동기로 처리한다.

| 흐름 | 사용자가 하는 일 |
|---|---|
| 등록 | 일반 제작 폼을 제출하면 접수 안내를 받고 화면을 떠남 |
| 결과 확인 | 검수 완료 알림을 받거나 화면에 다시 들어와 승인, 반려, 실패를 확인 |
| 반려 수정 | 반려된 항목의 위치와 사유를 보고 입력을 고쳐 다시 제출 |
| 수정 | 등록된 스토리를 고치면 다시 검수를 거친 뒤 반영됨<br>공개 범위만 바꾸면 즉시 반영 |
| 취소 | 검수 대기, 반려, 실패 상태의 제출본을 버림 |

<br>

### 1-3 백엔드의 역할

검수 판정 기준과 판정 자체는 AI 서버가 맡는다. 접수, 실행, 결과 반영, 재시도와 보류, 사용자에게 보여 줄 사유의 정리는 백엔드가 맡는다.

| 작업 | 역할 |
|---|---|
| 접수 | 등록과 수정 입력을 검증하고 제출본으로 저장<br>스토리당 대기 중인 제출본은 한 건 |
| 용량 예산 | AI에 보낼 이미지와 입력의 예상 크기를 접수 전에 검사 |
| 실행 | 대기 중인 제출본을 선점해 이미지를 복사하고 AI 서버에 검수 요청 |
| 결과 반영 | 승인이면 라이브에 등록하거나 수정을 적용<br>반려와 실패는 사유를 보존 |
| 재시도와 보류 | 일시 실패는 정해진 간격으로 다시 시도하고 재시도 예산이 소진되면 보류해 운영자에게 알림 |
| 조회와 재제출 | 제출본 상태와 사유를 조회하고 반려본과 실패본을 같은 식별자로 다시 접수 |
| 노출 제한 | 승인 전 제출본을 목록, 검색, 상세, 공개 스냅샷에 노출하지 않음 |
| 다른 도메인에 전달 | 스토리: 승인 시 등록 저장과 수정 적용 호출<br>알림: 검수 완료 이벤트 발행 |

<br>

### 1-4 주체

| 주체 | 정의 | 이 도메인에서 하는 일 |
|---|---|---|
| 게스트 | 로그인 없이 서비스를 쓰는 사용자 | 검수 대상 작업 불가 |
| 회원 | 소셜 로그인으로 가입한 사용자 | 등록과 수정 제출, 결과 조회, 재제출, 취소 |
| 클라이언트 | 사용자가 쓰는 웹과 Android 앱 | 접수 응답 처리, 상태와 사유 표시, 재제출 폼 복원 |
| AI 서버 | 게시물을 판정하는 서버 | 텍스트와 이미지 판정, 위반 항목과 이미지 오류 반환 |
| 운영자 | 팀 구성원 | 보류 알림 확인, 원인 조치, 보류 해제 |

<br>

### 1-5 공통 용어

| 용어 | 의미 |
|---|---|
| 라이브 | 승인되어 반영된 현재 스토리<br>목록, 검색, 상세, 채팅이 읽는 데이터 |
| 제출본 | 검수를 위해 등록 또는 수정 입력을 저장한 행<br>라이브와 분리됨 |
| 종류 | 제출본이 신규 등록인지 기존 스토리 수정인지 |
| 접수 | 입력 검증을 통과한 제출본을 대기 상태로 저장하고 응답하는 것 |
| 판정 | AI 서버의 결과<br>승인 또는 반려 |
| 종료 상태 | 승인, 반려, 실패<br>대기는 종료 상태가 아님 |
| 위반 항목 | 반려 사유<br>입력 안의 위치, 종류, 기준, 이유 |
| 이미지 오류 | 이미지를 내려받거나 읽지 못한 실행 오류<br>위치와 오류 코드 |
| 실행 실패 | 판정을 받지 못했거나 승인 결과를 적용하지 못한 것<br>오류 코드로 구분 |
| 일시 실패 | 사용자가 고칠 사유가 없는 실행 실패<br>자동 재시도 대상 |
| 회차 | 제출본의 실행 단위를 구분하는 번호<br>선점, 재제출마다 증가 |
| 선점 | 한 인스턴스가 대기 중인 제출본 하나를 실행 대상으로 확보하는 것 |
| 임대 | 선점한 인스턴스가 실행을 마칠 때까지 다른 인스턴스가 같은 제출본을 선점하지 않는 시간 |
| 재시도 예산 | 일시 실패 시 자동으로 다시 시도하는 횟수 |
| 보류 | 재시도 예산이 소진되어 운영자 조치를 기다리는 대기 상태 |
| 검수 입력 | 제출본에서 AI 서버에 보내는 전체 폼<br>부분 수정이 아니라 적용 결과 전체 |
| 복사본 | 검수와 승인 저장에 쓰려고 서버가 따로 복사한 이미지<br>사용자가 덮어쓸 수 없음 |
| 용량 예산 | AI 서버 요청 본문의 예상 크기 상한 |
| 재제출 | 반려 또는 실패한 제출본을 같은 식별자로 다시 접수하는 것 |
