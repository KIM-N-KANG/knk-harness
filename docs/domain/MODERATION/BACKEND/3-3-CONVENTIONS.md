# 3-3 구현 컨벤션

이 문서는 MODERATION 도메인 코드를 작성하거나 수정할 때 반드시 지킬 규칙과 구현자가 선택할 수 있는 사항을 정한다.

트랜잭션과 잠금은 동시성에, 로그 이벤트 규칙은 관측에, 입력 원문 취급은 보안에, 구현 위치는 AGENTS.md에 있다. ([5-2 동시성](5-2-CONCURRENCY.md), [5-4-3 구조화 로그 이벤트](5-4-OBSERVABILITY.md#5-4-3-구조화-로그-이벤트), [5-1-7 식별자와 개인정보](5-1-SECURITY.md#5-1-7-식별자와-개인정보), [AGENTS.md](AGENTS.md))

<br>

### 3-3-1 이름과 용어

| 대상 | 규칙 |
|---|---|
| 패키지 | 스토리 패키지 아래 제출 패키지에 제출 서비스, 폼 조립기, 용량 검사, 폴러, 선점 저장소, 실행기, 이미지 복사, AI 클라이언트, 재시도 정책, 보류 알림을 둠<br>제출본 API 계층은 스토리 API 계층과 같은 위치 |
| 모델 이름 | 테이블의 단수형 |
| 전송 객체 | 요청은 `Request`, 응답은 `Response`를 접미사로 사용<br>와이어 필드는 camelCase<br>DB 컬럼은 snake_case |
| AI 필드 | 요청은 폼의 camelCase를 유지하고 기본 주인공 이름만 `protagonist_name`<br>응답의 `error_code`, `image_errors`는 클라이언트에 `errorCode`, `imageErrors`로 전달 |
| 상태와 종류 | 대문자 enum |
| 오류 코드 | 대문자 snake_case 문자열<br>AI 코드는 그대로 전달 |
| 용어 | 용어집을 따름 |

<br>

### 3-3-2 계층 책임

| 계층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| API 계층 | 형식 검증, 요청자 식별, 상태 코드 지정 | 비즈니스 판정, 저장 계층 호출 |
| 제출 서비스 | 계정 상태와 소유 판정, 대기 중 제한, 접수와 재제출, 취소, 응답 조립 | 실행, AI 호출 |
| 폼 조립기 | 검증, 수정 결과 전체 조립, 검수 입력 추림, 위치 재대응 | 라이브 변경 |
| 폴러 | 빈 슬롯 계산, 선점, 실행기 제출, 거부 시 임대 반환 | 실행 자체, 결과 반영 |
| 실행기 | 이미지 복사, AI 호출, 응답 검증, 종료 처리 호출 | DB 트랜잭션 안에서 외부 호출 |
| 종료 처리 | 회차 확인, 승인 적용 호출, 상태 기록, 재시도 예약, 보류, 이벤트 발행 | 외부 호출 |
| 저장 계층 | 쿼리 실행<br>잠금이 필요한 조회 메서드는 이름에 잠금 여부 표시 | 비즈니스 판정 |

<br>

### 3-3-3 요청 검증과 오류

| 대상 | 규칙 |
|---|---|
| 재제출 본문 | 등록 요청과 같은 전송 객체로 받고 API 계층의 선검증 없이 서비스에서 검증<br>인증, 소유와 존재, 상태 거절, 입력 검증 순서 |
| 입력 검증 | 등록과 수정의 검증 규칙을 폼 조립기가 그대로 적용 |
| AI 응답 | 역직렬화 뒤 전송한 검수 입력을 기준으로 형식을 검증<br>검증에 실패한 응답의 위반 항목과 이미지 오류는 채택하지 않음 |
| 실행 예외 | 예외 객체를 넘기지 않고 예외 종류와 상태 코드만 기록 |

<br>

### 3-3-4 이벤트와 비동기

| 대상 | 규칙 |
|---|---|
| 접수 | 대기 행만 커밋하고 실행기에 직접 전달하지 않음 |
| 폴러 | 고정 지연 주기<br>선점은 독립 트랜잭션<br>예외를 밖으로 내보내지 않음 |
| 실행기 | 전용 스레드 풀, 대기 큐 0, 스레드 접두어 `story-moderation-`<br>MDC를 워커로 전파 |
| 완료 이벤트 | 종료 상태를 기록하는 트랜잭션 안에서 발행 |
| 보류 이벤트 | 보류 전환 트랜잭션 안에서 발행하고 커밋 후 리스너가 전송<br>기본 비동기 실행기를 쓰지 않음 |
| 외부 호출 | 이미지 복사, AI 호출, Slack 전송은 DB 트랜잭션 밖 |

<br>

### 3-3-5 테스트와 검증 도구

| 대상 | 규칙 |
|---|---|
| 작성 순서 | 동작을 바꾸는 작업은 실패하는 테스트를 먼저 작성 |
| 엔드포인트 변경 | 통합 테스트와 수동 호출 파일을 함께 갱신 |
| 동시성 | 선점, 회차, 잠금 규칙을 바꾸면 실제 PostgreSQL 테스트로 검증 |
| 시각 | 재시도 간격과 임대는 주입한 시계나 짧은 설정값으로 검증 |
| AI 응답 | 응답 검증 규칙을 바꾸면 계약 테스트의 응답 예시를 함께 갱신 |

<br>

### 3-3-6 구현자가 선택할 수 있는 것

| 선택 가능 | 조건 |
|---|---|
| 서비스 내부의 메서드 분할과 이름 | 없음 |
| 테스트 픽스처와 AI 스텁의 구성 | 없음 |
| 조회 쿼리의 작성 방식 | 잠금 여부와 소유자 조건을 유지 |
| 로그 필드 추가 | 입력 원문, 이미지 URL, 응답 본문, 웹훅 주소를 넣지 않음 |
| 스레드 풀 크기 | 설정값으로 바꾸되 선점 건수와 같게 유지 |
