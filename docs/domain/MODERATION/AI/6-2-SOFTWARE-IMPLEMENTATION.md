### 6-2-1 게시물 검수

```mermaid
%%{init: {"flowchart": {"curve": "basis", "htmlLabels": true, "nodeSpacing": 24, "rankSpacing": 48}}}%%
flowchart LR
    A["<b>라우터</b>"] -->|요청| B["<b>검수 서비스</b>"]
    B -->|모델 메시지| C["<b>공통 LLM 호출</b>"]
    C -->|모델 응답| B
    B -->|검수 결과| A
    classDef code fill:#F4F6F4,stroke:#9BA99E,color:#253C2C
    class A,B,C code
```

<br>

**1. 데이터 변환과 담당**

| 담당 | 입력 → 출력 |
|---|---|
| 라우터 | 요청 모델 → camelCase 게시물 JSON<br>검수 결과 → 응답 모델 |
| 입력 준비 | 게시물 JSON → 검수 필드, 필드별 유형, 이미지 주소 목록 |
| 이미지 준비 | 이미지 주소 목록 → 이미지 바이너리와 이미지별 오류 |
| 프롬프트 조립기 | 검수 필드와 이미지 → 역할별 모델 메시지 |
| 공통 LLM 호출 | 메시지와 설정 → 응답 문자열, 모델과 사용량 |
| 응답 검증 | 응답 문자열과 입력 경로 → 내용 위반과 판독 오류 |
| 검수 서비스 | 검증한 판정과 이미지 준비 오류 → 최종 검수 결과 |

<br>

**2. 내부 데이터**

| 데이터 | 구성 |
|---|---|
| 검수 입력 | 게시물, 필드 경로별 텍스트 또는 이미지 유형, 이미지 주소 목록 |
| 준비된 이미지 | 입력 경로, MIME 타입, 바이너리 |
| 모델 판정 | 승인 여부, 위치와 기준 및 이유를 담은 문제 항목 |
| 검수 결과 | 승인 여부, 내용 위반 목록, 실행 오류, 이미지 오류 목록 |
| 호출 기록 | 시도 번호, 모델, 공급자, 토큰 수, 소요 시간, 결과 또는 오류 유형 |

<br>

### 6-2-2 구현 규칙

| 대상 | 규칙 |
|---|---|
| 모델 연동 | 공급자 SDK는 공통 LLM 어댑터에서 사용<br>검수 서비스는 공통 요청과 결과 타입 사용 |
| 데이터 모델 | 외부 요청과 판정 결과는 Pydantic 모델, 준비된 입력과 이미지는 데이터 클래스로 관리 |
| 상태 | 요청별 이미지, 오류와 호출 기록을 분리<br>전처리 시 원본 게시물과 배열 순서 보존 |
| 비동기 | 이미지 다운로드와 모델 호출은 비동기<br>입력 추출, 프롬프트 조립과 응답 검증은 동기 |
| 설정 | 공통 설정 객체에서 모델과 제한값 조회 |
| 자원 | 이미지 HTTP 클라이언트는 요청 범위에서 종료<br>중단한 다운로드 작업은 취소 후 결과 회수 |
| 예외 | 예상한 외부 호출과 응답 오류만 검수 실패로 변환<br>요청 취소와 예상하지 못한 예외는 상위로 전달 |
| 관측 | 라우터는 요청, 서비스는 모델 호출 기록<br>관측용 복사본에서 URL과 base64 제거, 모델 입력은 유지 |
| 테스트 경계 | 라우터 테스트는 검수 서비스, 서비스 테스트는 이미지 준비와 공통 LLM 호출을 대체 |
