# 4-3 Android STORY 상태 관리

기준: [공통 상태](../4-3-STATE-MANAGEMENT.md), [Android 구성](4-2-COMPONENT-ARCHITECTURE.md).

<br>

### 4-3-1 화면과 저장 수명

| 상태 | 기준 |
|---|---|
| 홈 | ViewModel의 조건과 커서. 조건 변경 시 작업 취소. firstPageVersion별 저장 가능한 스크롤 상태로 새 첫 페이지는 맨 위, 구성 변경은 위치 유지 |
| 상세 | 선택, 채팅 생성과 좋아요는 ViewModel. 옵션 열림은 저장 가능한 화면 상태. 이미지 URL은 ViewModel이며 영속 저장과 라우트에는 넣지 않음 |
| 제작 옵션 | ViewModel 대상 카드. 조회로 대상이 없어지거나 상태가 바뀌면 갱신 |
| 인물 접기 | 인물 ID 집합과 삭제 확인 대상. 탭 및 구성 변경에 유지하지만 초안 snapshot과 API에는 제외 |
| 일반 폼 | ViewModel MVI. 탭과 접기 및 크롭은 화면 상태, 프로세스 복원은 서버 초안 또는 접수 제출본 |
| 저장 충돌 | 화면 상태에 현재 충돌 version을 두어 구성 변경에도 유지 |
| 화풍과 공개 | 추가 정보 상태와 진행 미러. 재선택과 재생성에도 유지 |

### 4-3-2 기기 테이블과 서버 연결

| 저장 | 내용 |
|---|---|
| pending_story_creation | Room v6, draftId 기본 키의 다중 편집 및 생성 기록. 현재 ownerId로만 읽고 쓰며 신원이 없으면 빈 조회와 쓰기 실패 |
| story_completion_request | requestId별 완성 명령, ownerId와 최초 저장 시각, serverDraftVersion |
| general_story_draft | ownerId와 draftId 복합 키, 버전 폼 JSON과 최초 시각, 접수 submissionId. 서버 이관 전 기록과 접수 연결만 남음 |
| 서버 초안 목록 | 마지막 성공 목록을 계정 ID와 함께 메모리에 보관. 같은 계정 재조회 실패는 마지막 목록 유지 |

로그아웃 뒤 기기 테이블은 소유 계정별로 남긴다. 탈퇴 후 잔여 행의 물리 삭제는 기존에 미해결인 상태이며 완료된 동작으로 서술하지 않는다.

createdAt은 처음 행을 만들 때만 정하고 기존 null도 유지한다. 조회는 날짜 없는 항목을 뒤로, 날짜 내림차순으로 하고 완성 요청은 submittedAt도 내림차순으로 사용한다.

일반 제작 접수는 JSON을 비우고 제출 ID만 남긴다. 이후 초안 저장을 거부하며 연결 행은 카드에서 제외한다. 진입은 접수 연결, 기기 초안, 서버 상세 순서다. 앱 미리보기 파일은 화면을 닫을 때 지우되 미이관 기기 초안의 참조 파일은 보존하고 이관 때 함께 정리한다.

<br>

### 4-3-3 간편 제작 세션

1. draftId를 모든 단계에 전달하고 저장소가 해당 ID를 맡는다. 다른 초안에 바인딩하면 앞 생성 실행과 메모리를 정리한다.
2. 기기 행이 있으면 우선 사용한다. serverDraftVersion이 있으면 서버 세션, 없으면 이전 기기 세션이다. 행이 없으면 서버 상세를 확인하고 서버 세션으로 정한다. 조회 실패 때는 판정을 끝내지 않는다.
3. 서버 키워드는 서버에만 저장하고 입력이 모두 비면 삭제한다. 생성 중과 결과는 기준 버전과 함께 기기에 보관하며 서버에 아직 없으면 기준 0이다.
4. 사용자 저장이 성공하면 세션의 기기 행을 제거한다. 결과 직후 기기 행은 이미 저장된 것으로 보아 변경 없이 백그라운드가 되었다고 서버에 새로 쓰지 않는다.
5. 표시 결과를 만든 요청과 재시도용 마지막 요청을 따로 보존한다. 스토리라인 선택은 서버 ID로 쓰고 복원할 때 순번으로 되돌린다.
6. 연결된 서버 version이 기기 기준 이하이면 서버 카드를 가린다. 새 서버 카드는 별도 키와 재개 및 삭제를 사용한다.
7. 새 서버 카드로 재개할 때 같은 ID의 기기 행은 새 UUID로 옮기고 서버 연결을 버려 기기 초안으로 보존한다.
8. 완성 기록은 draftId와 서버 연결 및 최초 시각을 이어받는다. 확정 실패는 원 명령의 draftId에 추가 정보 초안으로 복원하며 이전 형식에 ID가 없으면 새 UUID를 사용한다.

### 4-3-4 장르와 가입 안내

장르 검색은 화면 ViewModel 수명으로 전체 카탈로그와 검색 결과를 보관한다. 빈 결과도 성공 캐시에 포함하고 최대 20개에서 가장 먼저 받은 항목부터 제거하며 실패는 보관하지 않는다. 메뉴를 닫으면 검색과 로딩 타이머만 취소하고 대표 칩에 필요한 전체 카탈로그는 완료할 수 있다. 구성 변경은 유지하고 프로세스 종료 뒤에는 초안 입력만 복원한다.

선택 ID와 추가 칩 순서는 초안 JSON에 보존하고 누락 필드는 빈 목록으로 읽는다. 카탈로그와 초안 중 어느 쪽이 먼저 와도 대표 항목은 대표 위치로 정리하되 선택을 유지한다.

가입 온보딩은 회원 귀속 story-onboarding DataStore 표시로 관리하고 로그아웃 정리에 참여한다. 읽기 전 null이면 메인 그래프를 열지 않고 읽기 실패는 온보딩 없음으로 처리한다. 그래프 생성 뒤 표시가 켜지면 셸만 남은 백스택에서만 루트를 바꾼다. 완료는 루트 키를 메인 탭으로 바꾸고 표시를 지우며 같은 실행의 메모리 완료도 유지해 저장 실패가 재생성 시 온보딩을 다시 열지 않게 한다.
