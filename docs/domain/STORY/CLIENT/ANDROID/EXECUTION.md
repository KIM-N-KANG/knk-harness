### 목록과 상세

| 작업 | 실행 |
|---|---|
| 공개 목록 | 토큰 없는 클라이언트. 첫 페이지와 다음 페이지를 한 작업으로 직렬화, 조건 변경은 취소, 중복 ID는 먼저 받은 값 유지 |
| 필터 숨김 | 실제 소비한 스크롤을 누적해 아래 8dp면 숨김, 위 32dp면 표시, 상단 64dp는 항상 표시. 150ms 가속과 300ms 감속 |
| 좋아요 | 상세 재조회 취소 후 낙관 반영. 요청 중 화면 복귀는 새 조회를 시작하지 않음. 실패는 이전 값 복원, 홈으로 수 변화 전달 안 함 |
| 뷰어 | 원본 크기의 Fit 영역과 확대 및 이동 역변환으로 바깥 탭 판정. 바깥은 즉시 닫고 더블 탭 대기는 이미지 위만 적용. 재조회에서 대상이 없어지면 닫음 |
| 푸터 배경 | 메타 위치로 진행률 계산, 200ms로 따라가며 surface와 backgroundNeutral 보간 |
| 온보딩 | 오리지널 채팅순 첫 페이지, single-flight 채팅 시작, 1초 머문 카드 노출 기록. 페이지가 절반을 넘은 currentPage를 선택으로 사용 |

### 저장과 서버 초안

- 저장 버튼과 Activity.onStop을 사용하되 isChangingConfigurations는 제외한다. 저장을 Mutex로 직렬화하고 API 전송 전에 진행 저장을 join한다.
- 서버 저장은 앞 Job 뒤에 새 요청을 이어 붙여 당시에도 내용이 다르면 앞 응답 version을 사용한다. 저장 성공과 덮어쓰기 성공은 해당 기기 행을 정리한다.
- 일반 초안 이관은 서버 목록 조회 후 같은 ID로 PUT한다. 성공 또는 409 항목을 모아 목록을 다시 받은 뒤 기기 원본을 지운다. 상한에 걸리면 중단한다. 삭제는 서버와 기기 행을 함께 처리한다.
- 일반 초안의 제공 장르 ID를 읽을 때 전체 카탈로그로 이름을 찾는다. 실패하면 장르를 잃은 채 되쓰지 않도록 불러오기 실패로 처리한다.
- 간편 초안의 generation이 완료가 아니면 찾지 못한 상태로 처리해 같은 ID의 키워드로 시작한다. 카드로 연 추가 정보 초안은 스토리라인 목적지 위에 추가 정보 목적지를 쌓는다.
- 복원 stack은 키워드, 스토리라인, 스토리라인과 추가 정보 조합이다. 재개만으로 초안을 소비하지 않는다.

### 생성과 완성 복구

| 조건 | 처리 |
|---|---|
| 스토리라인 | 해당 단계 STARTED에서 3초 복구 조회 |
| 내용 거절 | 실패 기록 정리 후 이전 결과가 있으면 기기에 복원하고 Rejected 상태. 같은 세션으로 키워드에 복귀해 요청에서 선택 입력만 채움. 다음 생성은 새 requestId |
| 완성 저장 | 완성 삽입과 해당 draftId 초안 삭제를 DAO 트랜잭션으로 처리. 저장 실패 시 전송하지 않음 |
| 완성 실행 | 앱 수명, requestId별 single-flight, 세션 인증 작업과 commit 경계. 다른 요청을 전역 직렬화하지 않음 |
| POST 성공 | Completed 저장 |
| 네트워크, 401, 403 | 서버 수락을 단정하지 않고 불확실 상태 유지 |
| 원 응답 422 거절 | 조회 없이 추가 정보 초안으로 복원하고 거절 사유 안내 |
| 그 외 실패와 409 | GET 복구. FAILED 또는 404면 추가 정보 초안으로 복원 |
| 사용자의 새로고침 | 미수락 요청이 GET 404이면 저장한 같은 명령과 requestId로 재전송 |
| 제작 카드 | STARTED이며 카드 노출 중 5초 조회. 탭 복귀와 당겨서 새로고침은 즉시 조회 |
| 완료 정리 | 서버 목록에서 storyId 확인 뒤 제거. 없으면 추가 조회와 완료 카드 유지 |
| 실패 복원 | 요청 삭제와 초안 쓰기는 한 트랜잭션. 원 명령과 화풍, 공개 범위, 서버 연결과 최초 시각 유지. 보이는 제작 탭에 실패 이벤트 전달 |

복구 조회만으로 확정한 실패는 상세 사유를 알 수 없으므로 일반 실패 문구를 사용한다. 이전 버전 FAILED 행도 새로고침 때 초안으로 되돌리고 그전에는 실패 카드로 그리지 않는다.

### 일반 제작과 제출본

- 폼 검수 조회는 STARTED에서 1초 간격, 단조 시계로 60초 상한을 적용해 구성 변경으로 대기 시간을 다시 시작하지 않는다.
- 접수와 기록은 퍼널 수명에서 완료하고 세션 세대가 달라진 결과를 반영하지 않는다. 신규 POST 응답 유실은 자동 재전송하지 않는다. 접수 기록만 실패하면 submissionId를 유지해 기록만 재시도한다.
- 등록과 수정 성공은 제출 변경 흐름으로 제작 탭에 알린다. 화면을 닫고 늦게 받은 접수도 반영하고 기존 조회가 진행 중이면 끝난 뒤 새 조회를 예약한다.
- 제출본 목록과 삭제는 한 Mutex로 직렬화해 삭제 전의 늦은 응답이 카드를 되살리지 않게 한다. 직전 성공 목록에서 사라진 제출본이 있으면 내 스토리도 갱신한다.
- 조회 실패는 제출 카드만 숨기고 마지막 검토 중 판정을 유지해 다음 주기에 복구한다. STARTED 이탈 시 진행 중 조회도 취소한다.
- 일반 이미지 업로드는 실제 MIME과 크기 확인, 샘플링 디코딩과 EXIF 보정, 비율 크롭, presign, 별도 무인증 OkHttp PUT 순서다. Bitmap이나 임시 접근 권한을 저장의 기준으로 쓰지 않는다.

### 검색과 표시

- 장르 입력은 250ms 대기 후 요청하고 이전 요청을 취소한다. 실제 요청 200ms 후 로딩을 표시하는 자식 타이머는 응답과 입력 변경, 선택 및 닫기 때 취소한다. 질의와 메뉴 및 요청이 모두 일치해야 결과와 로딩을 반영한다.
- 빈 검색은 전체 카탈로그를 재사용하고 초기 조회 중이면 같은 Deferred를 기다린다. 카탈로그 확인 전에는 장르 선택과 생성 진행을 허용하지 않는다.
- 화풍 조회는 토큰 없는 API와 하나의 Job으로 중복을 막고 늦은 초안 복원이 먼저 받은 목록을 덮지 않게 한다.
- 순환 문구와 제작 시머는 4초, 지연 힌트 시각과 노출은 저장 가능한 화면 상태다. 애니메이션은 Compose 수명에 종속된다.
- 추가 정보 삭제는 퇴장할 입력보다 남은 입력으로 먼저 초점을 옮긴다. 퇴장 중 입력과 삭제 버튼은 비활성화한다.
