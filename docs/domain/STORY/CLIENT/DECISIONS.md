# DECISIONS.md

현재 적용 기준은 각 명세에 두고 결정 당시의 이유와 대체 관계는 이 문서에 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다. 기존 ID, 날짜, 당시 상태와 근거를 유지한다.
- 상태와 구현 설명은 원본의 기록 시점을 기준으로 해석한다. 현재 적용 여부나 배포 완료를 과거 기록만으로 단정하지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체하는 결정과 적용 범위를 명시한다.
- 원문에 구분되지 않은 배경, 대안과 영향은 추측해서 보충하지 않는다.

**C-002. 오리지널 카드 메타를 두 줄로 표시**

**C-004. 편집 초안과 완성 요청의 생명주기 분리**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-09-08 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 단일 편집 슬롯과 완료 대기는 여러 완성 요청과 새 편집을 함께 표현하기 어렵다. |
| 채택 | 편집 초안 한 개와 requestId별 완성 요청을 분리하고 저장 후 제작 탭으로 복귀한다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 완성 대기 중에도 다음 제작을 시작하고 초안 폐기와 요청 결과가 서로 영향을 주지 않도록 하기 위해서이다. |
| 영향 | 자동 채팅 생성이 사라지고 플랫폼별 저장, 실행, 분석 연결의 전환이 필요하다. 웹 적용 시점과 잠정 실패 UX는 이 결정의 승인 범위를 넘겨 추정하지 않는다. |
| 근거 | [이관 원문 C:841](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-1-client.md#L841-L867), [이관 원문 A:1575](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-3-android-app.md#L1575-L1618) |

<a id="c-008"></a>
<a id="c-008-홈-목록-진입-기본-정렬을-서버-기본값최신순으로-통일"></a>

**C-008. 홈 목록 진입 기본 정렬을 서버 기본값(최신순)으로 통일**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-09-26 |
| 상태 | Accepted (원문 기록 기준) |
| 관계 | KNK-1399, KNK-1421에서 정한 홈 진입 기본 정렬(인기순)을 대체한다. 필터 기본값(전체)과 정렬 선택지는 유지한다. |
| 배경 | 홈 목록은 `GET /stories`의 `sort`(`likes`, `latest`, `chats`)를 쓰고 서버 기본값은 `latest`이다. 클라이언트만 인기순으로 열어 두 기본값이 달랐다. |
| 채택 | 웹, Android 모두 홈 진입 기본값을 전체, 최신순으로 한다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 사용자가 서버 기본값을 따르도록 요청했다(KNK-1430 작업 중). 한 기본값만 두면 클라이언트와 서버가 가리키는 "기본 목록"이 같아진다. |
| 영향 | Android는 KNK-1430에서 반영한다. 웹은 `DEFAULT_STORY_LIST_QUERY.sort`와 기본 홈 URL 판정(`/`가 최신순)을 별도 작업으로 맞춰야 하며, 그 전까지 웹은 이 계약과 다르다. |

<a id="c-009-인기순-추가와-홈-기본-정렬-변경"></a>

**C-009. 인기순 추가와 홈 기본 정렬 변경**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-02 |
| 상태 | Accepted (원문 기록 기준) |
| 관계 | [C-008](DECISIONS.md#c-008)의 최신순 기본값과 기존 정렬 선택지 유지를 대체한다. 필터 기본값 전체와 서버 기본값에 맞추는 원칙은 유지한다. |
| 배경 | 서버가 좋아요 수와 누적 턴 수를 함께 반영하는 `popular`를 추가하고 공개 목록의 기본 정렬로 사용한다. ([BE-053](../../../reference/decisions/BACKEND.md#be-053)) |
| 채택 | 웹과 Android의 홈 진입 기본값은 전체, 인기순으로 한다. `popular`는 인기순으로 표시하고 `likes`는 좋아요순으로 구분한다. 드롭다운은 기본값을 먼저 두어 인기순, 최신순, 좋아요순, 채팅순으로 표시한다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 서버와 클라이언트의 기본 목록을 일치시키고 좋아요만 반영하는 정렬과 새 인기순을 구분한다. |
| 영향 | 웹의 쿼리 생략 기본값(`/`)과 알 수 없는 쿼리 값 대체도 전체, 인기순이다. Android는 앱 재시작 시 같은 기본값으로 연다. 클라이언트는 서버 순서를 사용하며 인기 점수 계산이나 가중치에 의존하지 않는다. |
| 출처 | 사용자 확정 결정. ([KNK-1489](https://kimandkang.atlassian.net/browse/KNK-1489)) |
