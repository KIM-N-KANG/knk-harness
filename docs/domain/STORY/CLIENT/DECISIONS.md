## C-002. 오리지널 카드 메타를 두 줄로 표시

- 결정일: 2026-08-24 · 기록 확정 상태: Accepted
- 근거: [이관 원문 C:197](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-1-client.md#L197-L201)
- **맥락:** 오리지널 카드에 플레이 규모를 보여 주는 세 번째 줄을 검토했습니다.
- **결정:** 제목·제작자 두 줄을 사용하고 턴 수·좋아요 수는 썸네일 배지에 둡니다.
- **이유:** 응답에는 채팅 수가 없고 턴 수를 별도 줄에 두면 같은 수치가 중복됩니다.
- **주요 영향:** 플레이 횟수와 누적 턴 수를 같은 지표로 부르지 않습니다.

## C-004. 편집 초안과 완성 요청의 생명주기 분리

- 결정일: 2026-09-08 · 기록 확정 상태: Accepted
- 근거: [이관 원문 C:841](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-1-client.md#L841-L867), [이관 원문 A:1575](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-3-android-app.md#L1575-L1618)
- **맥락:** 단일 편집 슬롯과 완료 대기는 여러 완성 요청과 새 편집을 함께 표현하기 어렵습니다.
- **결정:** 편집 초안 한 개와 requestId별 완성 요청을 분리하고 저장 후 제작 탭으로 복귀합니다.
- **이유:** 완성 대기 중에도 다음 제작을 시작하고 초안 폐기와 요청 결과가 서로 영향을 주지 않도록 하기 위해서입니다.
- **주요 영향:** 자동 채팅 생성이 사라지고 플랫폼별 저장·실행·분석 연결의 전환이 필요합니다. 웹 적용 시점과 잠정 실패 UX는 이 결정의 승인 범위를 넘겨 추정하지 않습니다.

## C-008. 홈 목록 진입 기본 정렬을 서버 기본값(최신순)으로 통일

- 결정일: 2026-09-26 · 기록 확정 상태: Accepted
- 관계: KNK-1399·KNK-1421에서 정한 홈 진입 기본 정렬(인기순)을 대체합니다. 필터 기본값(전체)과 정렬 선택지는 유지합니다.
- **맥락:** 홈 목록은 `GET /stories`의 `sort`(`likes`·`latest`·`chats`)를 쓰고 서버 기본값은 `latest`입니다. 클라이언트만 인기순으로 열어 두 기본값이 달랐습니다.
- **결정:** 웹·Android 모두 홈 진입 기본값을 전체·최신순으로 합니다.
- **이유:** 사용자가 서버 기본값을 따르도록 요청했습니다(KNK-1430 작업 중). 한 기본값만 두면 클라이언트와 서버가 가리키는 "기본 목록"이 같아집니다.
- **영향:** Android는 KNK-1430에서 반영합니다. 웹은 `DEFAULT_STORY_LIST_QUERY.sort`와 기본 홈 URL 판정(`/`가 최신순)을 별도 작업으로 맞춰야 하며, 그 전까지 웹은 이 계약과 다릅니다.

## C-009. 인기순 추가와 홈 기본 정렬 변경

- 결정일: 2026-10-02 · 기록 확정 상태: Accepted
- 관계: [C-008](DECISIONS.md#c-008)의 최신순 기본값과 기존 정렬 선택지 유지를 대체합니다. 필터 기본값 전체와 서버 기본값에 맞추는 원칙은 유지합니다.
- **맥락:** 서버가 좋아요 수와 누적 턴 수를 함께 반영하는 `popular`를 추가하고 공개 목록의 기본 정렬로 사용합니다. ([BE-053](../../../adr/2-backend-server-adr.md#be-053))
- **결정:** 웹과 Android의 홈 진입 기본값은 전체·인기순으로 합니다. `popular`는 인기순으로 표시하고 `likes`는 좋아요순으로 구분합니다. 드롭다운은 기본값을 먼저 두어 인기순, 최신순, 좋아요순, 채팅순으로 표시합니다.
- **이유:** 서버와 클라이언트의 기본 목록을 일치시키고 좋아요만 반영하는 정렬과 새 인기순을 구분합니다.
- **영향:** 웹의 쿼리 생략 기본값(`/`)과 알 수 없는 쿼리 값 대체도 전체·인기순입니다. Android는 앱 재시작 시 같은 기본값으로 엽니다. 클라이언트는 서버 순서를 사용하며 인기 점수 계산이나 가중치에 의존하지 않습니다.
- 출처: 사용자 확정 결정. ([KNK-1489](https://kimandkang.atlassian.net/browse/KNK-1489))
