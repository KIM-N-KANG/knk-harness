# DECISIONS.md

현재 적용 기준은 각 명세에 두고 결정 당시의 이유와 대체 관계는 이 문서에 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다. 기존 ID, 날짜, 당시 상태와 근거를 유지한다.
- 상태와 구현 설명은 원본의 기록 시점을 기준으로 해석한다. 현재 적용 여부나 배포 완료를 과거 기록만으로 단정하지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체하는 결정과 적용 범위를 명시한다.
- 원문에 구분되지 않은 배경, 대안과 영향은 추측해서 보충하지 않는다.

**C-008. 홈 목록 진입 기본 정렬을 서버 기본값(최신순)으로 통일**

| 항목 | 내용 |

| 상태 | Accepted (원문 기록 기준) |
| 관계 | KNK-1399, KNK-1421에서 정한 홈 진입 기본 정렬(인기순)을 대체한다. 필터 기본값(전체)과 정렬 선택지는 유지한다. |
| 배경 | 홈 목록은 `GET /stories`의 `sort`(`likes`, `latest`, `chats`)를 쓰고 서버 기본값은 `latest`이다. 클라이언트만 인기순으로 열어 두 기본값이 달랐다. |
| 채택 | 웹, Android 모두 홈 진입 기본값을 전체, 최신순으로 한다. |

| 영향 | Android는 KNK-1430에서 반영한다. 웹은 `DEFAULT_STORY_LIST_QUERY.sort`와 기본 홈 URL 판정(`/`가 최신순)을 별도 작업으로 맞춰야 하며, 그 전까지 웹은 이 계약과 다르다. |

**C-009. 인기순 추가와 홈 기본 정렬 변경**

| 항목 | 내용 |

| 관계 | [C-008](DECISIONS.md#c-008)의 최신순 기본값과 기존 정렬 선택지 유지를 대체한다. 필터 기본값 전체와 서버 기본값에 맞추는 원칙은 유지한다. |
| 배경 | 서버가 좋아요 수와 누적 턴 수를 함께 반영하는 `popular`를 추가하고 공개 목록의 기본 정렬로 사용한다. ([BE-053](../../../reference/decisions/BACKEND.md#be-053)) |
| 채택 | 웹과 Android의 홈 진입 기본값은 전체, 인기순으로 한다. `popular`는 인기순으로 표시하고 `likes`는 좋아요순으로 구분한다. 드롭다운은 기본값을 먼저 두어 인기순, 최신순, 좋아요순, 채팅순으로 표시한다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 서버와 클라이언트의 기본 목록을 일치시키고 좋아요만 반영하는 정렬과 새 인기순을 구분한다. |
| 영향 | 웹의 쿼리 생략 기본값(`/`)과 알 수 없는 쿼리 값 대체도 전체, 인기순이다. Android는 앱 재시작 시 같은 기본값으로 연다. 클라이언트는 서버 순서를 사용하며 인기 점수 계산이나 가중치에 의존하지 않는다. |

<a id="c-017-홈은-서버-섹션으로-구성하고-탐색을-다섯째-탭으로-둔다"></a>

**C-017. 홈은 서버 섹션으로 구성하고 탐색을 다섯째 탭으로 둔다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-03 |
| 상태 | Accepted |
| 관계 | [C-008](DECISIONS.md#c-008)과 [C-009](DECISIONS.md#c-009)의 홈 필터, 정렬 선택지와 진입 기본값을 대체한다. 홈과 탐색 모두 필터와 정렬을 두지 않는다. |
| 배경 | 서버 v0.14.0이 관리자가 구성하는 홈 목록(`GET /stories/home`)과 공개 스토리 전체를 시드 고정 셔플로 넘기는 탐색 목록(`GET /stories/explore`)을 추가했다. 홈은 가로 목록을 세로로 쌓는 구조로 바꾸고 상단 필터 칩은 빼기로 했다. 섹션이 비어도 빈 배열로 내려오므로 숨김은 화면이 정한다. ([STORY 결정 25, 26](../BACKEND/DECISIONS.md)) |
| 채택 | 하단 탭은 홈, 채팅, 제작, 탐색, 마이 순서로 둔다. 탐색은 다른 탭에서 들어올 때와 당겨서 새로고침할 때만 새로 섞고, 상세에서 돌아오면 보던 순서와 위치를 유지한다. 홈 섹션은 한 화면에 카드 두 장과 셋째 카드의 가장자리가 보이는 가로 줄로 그리고 카드가 없는 섹션은 숨긴다. 탐색은 인스타그램 탐색 탭처럼 제목과 작성자 글 없이 표지만 세 열로 붙인 그리드로 그리고 턴 수 배지도 두지 않는다. 새로 섞을 때 한 번에 바뀌지 않도록 칸마다 대각선 순서로 표지를 겹쳐 바꾼다. 아이콘은 사용자가 준 나침반 outline과 filled를 쓴다. |
| 대안 | 탐색을 홈 다음이나 채팅 다음에 두는 안, 하단 탭을 넷으로 유지하고 홈 상단에서 전환하는 안. 탭을 오가도 순서를 유지하고 새로고침에서만 섞는 안. 섹션 카드를 2.5장이나 3.5장 보이게 하는 안. 탐색을 제목과 작성자가 있는 두 열 카드로 그리는 안. 빈 섹션에 제목과 빈 안내를 보이는 안 |
| 영향 | 홈의 필터와 정렬 URL 쿼리, 필터 바 숨김 동작과 관련 QA는 없어진다. 공개 목록 `GET /stories`는 클라이언트 목록 화면에서 쓰지 않는다. Android도 같은 탭 순서와 탐색 순서 규칙을 따른다. |
| 출처 | 사용자 확정 결정. ([KNK-2001](https://kimandkang.atlassian.net/browse/KNK-2001), [KNK-2003](https://kimandkang.atlassian.net/browse/KNK-2003)) |

<a id="c-018-홈-카드는-작성자-대신-한-줄-소개와-장르를-보인다"></a>

**C-018. 홈 카드는 작성자 대신 한 줄 소개와 장르를 보인다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-03 |
| 상태 | Accepted |
| 관계 | [C-002](DECISIONS.md#c-002)의 제목과 제작자 두 줄을 대체한다. 턴 수의 썸네일 배지와 오리지널 태그는 표지 위에 유지한다. |
| 배경 | 홈이 운영자가 고른 섹션의 가로 줄로 바뀌어 카드가 "이 스토리를 해 볼지" 고르는 자리가 됐다. 홈 카드 대부분이 공식 계정이라 같은 작성자가 반복되고, 게스트 스토리는 작성자가 없어 카드 높이가 달라졌다. 표지 그림에 제목 글씨가 있는 경우가 많아 표지 위 배지가 그림을 가렸다. |
| 채택 | 표지 위에는 오리지널 태그와 턴 수 배지를 둔다. 표지 아래에 제목, 두 줄 높이를 고정한 한 줄 소개, 12px 장르 배지 한 줄을 크기와 굵기, 색을 한 단계씩 낮춰 쌓고, 넘친 장르는 제작 카드와 같이 +N으로 줄인다. 작성자는 홈 카드에 두지 않는다. 잘린 줄을 끝까지 채우도록 제목과 소개는 글자 단위로 줄을 바꾼다. |
| 대안 | 표지 왼쪽 아래에 턴 수를 남기고 한 줄 소개를 한 줄만 두는 표지 중심 안. 탐색 탭이 이미 표지로 고르는 화면이라 홈은 설정을 읽고 고르는 화면으로 나누려고 채택하지 않았다. 턴 수를 표지 아래 글자나 무채색 배지로 두는 안. 화면에서 비교한 뒤 사용자가 턴 수는 표지 배지로 되돌리고 그 자리에 장르를 두기로 했다. 어절 단위 줄바꿈 유지. 말줄임 앞에 빈 공간이 남아 사용자가 글자 단위를 골랐다. |
| 영향 | 홈 카드에서 작성자를 볼 수 없고 상세에서 보인다. 홈 카드만 앱 기본 규칙인 어절 단위 줄바꿈과 다르다. Android 홈 카드도 같은 구성으로 맞춘다. |
| 출처 | 사용자 확정 결정. ([KNK-2003](https://kimandkang.atlassian.net/browse/KNK-2003)) |

<a id="c-019"></a>
<a id="c-019-제작-탭을-진행-중과-내-스토리-두-구역으로-나누고-공개-범위를-표지-배지로-둔다"></a>

**C-019. 제작 탭을 진행 중과 내 스토리 두 구역으로 나누고 공개 범위를 표지 배지로 둔다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-03 |
| 상태 | Accepted |
| 배경 | 초안, 완성 중, 검수 제출본과 완성된 스토리가 한 목록에 섞여 있어 이어서 할 일과 끝난 작품이 구분되지 않았다. 내 스토리 카드는 오른쪽 아래에 공개 범위와 제작일을 함께 두었다. |
| 채택 | 진행 중(초안과 제출본)과 내 스토리(완성 중과 완성 스토리) 두 구역으로 나누고 구역 제목 옆에 개수를 둔다. 완성 중 카드는 내 스토리 구역 맨 위에 두어, 완성되면 구역 제목과 개수가 바뀌지 않은 채 같은 자리에서 스토리 카드로 바뀐다. 공개 범위는 공개와 비공개 모두 표지 왼쪽 위 배지로 옮기고 오른쪽 아래에는 제작일만 둔다. 공개는 밝은 흰 배지와 지구본 아이콘, 비공개는 반투명 검정 배지와 자물쇠로 색 없이 명암만 달리해 구분한다. 카드 크기와 구성은 그대로 둔다. |
| 대안 | 초안과 제출본을 작은 썸네일 행으로 줄이고 내 스토리 표지를 96px로 줄여 홈 카드와 같은 위계로 맞추는 안. 화면에서 본 뒤 썸네일이 너무 작아 사용자가 되돌렸다. 완성 중 카드를 진행 중 구역에 두는 안. 마지막 완성 중 카드가 완성되면 진행 중 구역 제목이 사라져 아래 카드가 위로 튀어 완료 교체의 위치 유지 요구를 어겨 채택하지 않았다. 위 구역 제목을 "만들고 있는 스토리"로 두는 안. 초안 카드 제목과 같은 문구가 반복돼 "진행 중"으로 바꿨다. 비공개만 배지로 보이는 안. 사용자가 공개와 비공개를 모두 배지로 두기로 했다. 공개 배지를 브랜드 초록 배경이나 같은 어두운 배지의 초록 점으로 구분하는 안. 사용자가 색 없이 명암으로 구분하는 안을 골랐다. |
| 영향 | 제작 목록 E2E와 비주얼 기준 이미지가 바뀐다. Android 제작 탭도 같은 구성으로 맞춘다. |
| 출처 | 사용자 확정 결정. ([KNK-2003](https://kimandkang.atlassian.net/browse/KNK-2003)) |

<a id="c-020"></a>
<a id="c-020-스토리-검색은-탐색-검색바로-여는-별도-화면에서-제출할-때만-찾는다"></a>

**C-020. 스토리 검색은 탐색 검색바로 여는 별도 화면에서 제출할 때만 찾는다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-05 |
| 상태 | Accepted |
| 관계 | [C-017](DECISIONS.md#c-017)의 탐색 탭에 검색 진입점을 더한다. 탐색 목록의 필터와 정렬 없음은 유지한다. |
| 배경 | 공개 스토리 검색 API가 있어 탐색 탭에 검색을 넣기로 했다. 서버 검색은 형태소 단위로 제목, 한 줄 소개, 인물 이름과 장르를 찾고 관련도순으로만 돌려주며 자동완성, 인기 검색어, 필터와 정렬, 작성자 검색은 제공하지 않는다. |
| 채택 | 탐색 탭 맨 위 검색바를 누르면 별도 검색 화면을 연다. 검색어는 제출할 때만 찾고 2자 미만은 요청하지 않는다. 결과는 탐색 타일을 그대로 쓴다. 검색 전에는 기기에 남긴 최근 검색어 최대 10개와 대표 장르 칩을 보인다. |
| 대안 | 탐색 목록 자리에서 결과를 바꿔 보이는 안. 사용자가 별도 검색 화면을 골랐다. 입력하는 동안 자동으로 찾는 안. 서버가 접두어 일치를 하지 않아 입력 도중의 결과가 들쭉날쭉하고 요청만 늘어 채택하지 않았다. |
| 영향 | 서버 기능 없이 클라이언트만으로 검색 전 화면을 채운다. 최근 검색어는 기기 단위라 다른 기기와 공유하지 않는다. Android는 미구현이다. |
| 출처 | 별도 화면, 최근 검색어와 대표 장르는 사용자 확정 결정이다. 제출할 때만 찾는 방식과 탐색 타일 재사용은 조사 단계의 제안을 반영했다. ([KNK-2030](https://kimandkang.atlassian.net/browse/KNK-2030)) |

<a id="c-021"></a>
<a id="c-021-스토리-검색-진입점을-탐색-헤더의-검색-버튼으로-옮긴다"></a>

**C-021. 스토리 검색 진입점을 탐색 헤더의 검색 버튼으로 옮긴다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-11-05 |
| 상태 | Accepted |
| 관계 | [C-020](DECISIONS.md#c-020)의 진입점인 탐색 탭 맨 위 검색바만 대체한다. 별도 검색 화면, 제출할 때만 찾는 방식, 최근 검색어와 대표 장르는 유지한다. |
| 배경 | 탐색 목록 위 검색바를 스크롤 방향에 따라 숨기고 보이는 형태로 화면에서 확인했다. |
| 채택 | 탐색 목록 위 검색바를 없애고 헤더 오른쪽 알림 버튼 왼쪽에 검색 아이콘 버튼을 둔다. 버튼 사이는 4px. |
| 대안 | 탐색 목록 위에 스크롤에 따라 숨는 검색바를 두는 C-020의 안. 사용자가 헤더 버튼으로 바꾸기로 했다. |
| 영향 | 탐색 목록이 헤더 바로 아래에서 시작하고 당겨서 새로고침 표시자도 헤더 아래에 나타난다. |
| 출처 | 사용자 확정 결정. ([KNK-2030](https://kimandkang.atlassian.net/browse/KNK-2030)) |
