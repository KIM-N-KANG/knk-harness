# 2-2 요구사항

기준: [사용자 목표](2-1-USER-STORY.md).

<br>

### 2-2-1 적용 범위

| 기능 | 웹 | Android |
|---|---|---|
| 탐색, 상세, 간편 제작 | 회원과 게스트 | 로그인한 회원 |
| 일반 제작과 기존 스토리 수정 | 동의를 마친 회원, 수정은 소유자 | 회원, 수정은 소유자 |
| 서버 초안 | 회원의 새 제작과 서버 초안으로 연 세션 | 회원의 새 제작과 서버 초안으로 연 세션 |
| 기기 안 간편 제작 초안 | 게스트 또는 서버 연동 전 초안으로 연 세션 | 서버 연동 전 초안으로 연 세션 |
| 처음 이용하는 사람 안내 | 간편 제작 단계별 안내, STORY-US-020 | 신규 가입 직후 오리지널 온보딩, STORY-US-021 |
| 일반 제작 저장 계기 | 저장 버튼, 탭 이동, 화면 숨김 | 저장 버튼, 실제 앱 백그라운드 전환 |
| 간편 제작 저장 계기 | 저장 버튼, 화면 숨김. 단계 이동은 제외 | 저장 버튼, 실제 앱 백그라운드 전환. 구성 변경은 제외 |
| 로그아웃한 뒤 기기 제작 기록 | 세션 종료 시 정리하며 늦은 저장 차단 | 소유 계정별 보존, 다른 계정에서 접근 불가 |

권한과 게스트 목록은 [ACCOUNT 요구사항](../../ACCOUNT/CLIENT/2-2-REQUIREMENTS.md), 비용과 체험 및 부족 안내는 [PAYMENT 요구사항](../../PAYMENT/CLIENT/2-2-REQUIREMENTS.md)을 따른다.

### 2-2-2 탐색과 제작 목록

STORY-US-001, STORY-US-002, STORY-US-016.

| 조건 | 요구사항 |
|---|---|
| 홈 | 공개 스토리 탐색에 사용한다. 내 스토리와 새 제작은 제작 탭에서 다룬다 |
| 필터와 정렬 | 전체와 오리지널 중 하나, 인기순과 최신순 및 좋아요순과 채팅순 중 하나를 선택한다. 기본은 전체와 인기순이다 |
| 목록 순서 | 서버 순서를 유지하고 중복 항목은 처음 나온 것을 남긴다. 다음 페이지 실패 때 기존 목록을 유지한다 |
| 메타 | 홈은 턴 수, 제목과 작성자를 보인다. 좋아요 수는 제작 카드와 상세에서 보인다. 오리지널 표시는 해당 스토리에만 붙인다 |
| 제작 목록 | 내 스토리, 편집 초안과 생성 중 기록, 완성 중 요청, 신규 등록 검수 제출본을 구분한다. 같은 완성 스토리를 중복으로 보이지 않는다 |
| 제출본 범위 | 아직 스토리가 없는 신규 등록의 검토 중, 반려, 실패만 보인다. 기존 스토리 수정 제출본은 목록에 넣지 않는다 |
| 부분 실패 | 제출본 조회 실패 때문에 내 스토리를 숨기지 않는다. 서버 초안 조회 실패와 기기 기록 조회 실패의 처리는 플랫폼 범위를 따른다 |
| 빈 목록 | 스토리와 진행 카드가 모두 없을 때만 빈 상태를 보인다. 새 제작은 FAB에서 시작하며 별도 빈 상태 제작 버튼을 중복 제공하지 않는다 |
| 첫 조회 | 내 스토리, 초안과 제출본을 함께 준비해 표시하고 완성 중 요청은 먼저 보일 수 있다. 재진입이나 완료 처리 때 전체를 첫 로딩으로 되돌리지 않는다 |
| 새 제작 상한 | 회원의 만들고 있는 스토리 카드가 5장 이상이면 새 제작을 막는다. 같은 제작의 서버 초안과 기기 기록은 한 장으로 세고, 완성 실패에서 돌아온 초안은 포함하며 완성 중과 검수 제출본은 제외한다 |
| 상한 적용 | 모든 새 제작 진입에 적용하지만 이어서 만들기는 허용한다. 목록을 읽지 못했다고 새 제작을 막지 않으며 게스트에는 적용하지 않는다 |
| 독립성 | 새 제작과 초안 삭제는 다른 초안이나 완성 요청에 영향을 주지 않는다. 이어서 만들기는 선택한 초안만 연다 |

### 2-2-3 상세와 플레이 시작

STORY-US-003부터 STORY-US-006, STORY-US-019.

| 조건 | 요구사항 |
|---|---|
| 상세 | 서버가 허용한 스토리의 제목, 소개, 장르, 주요 내용, 주변 인물과 시작 상황을 표시한다. 소유권은 서버 판정과 허용된 게스트 소유 목록으로 판단한다 |
| 시작 상황 | 첫 설정이 기본이다. 선택한 시작 상황 설명과 엔딩 이름을 보이며 프롤로그, 엔딩 조건과 에필로그는 상세에 노출하지 않는다 |
| 엔딩 이력 | 회원과 게스트의 해당 스토리 도달 이력을 표시한다. 게스트 이력은 ACCOUNT의 소유 목록 범위를 따른다 |
| 인물 | 서버 순서를 유지하며 인물이 여럿이면 선택해 한 명씩 본다. 이미지가 없거나 조회에 실패해도 이름과 설명을 유지한다 |
| 이미지 확대 | 표지와 인물 이미지를 확대하고 이동할 수 있다. 이미지가 없으면 열지 않고, 닫기는 상세 이탈과 구분한다 |
| 페르소나 | 기본 주인공, 내 페르소나, 새 페르소나 순서다. 새로 만들기 자체로 선택을 바꾸지 않는다. 해당 상세에서 생성한 페르소나만 복귀 때 미리 선택한다 |
| 페르소나 제한 | 회원 최대 10개에서 추가를 안내로 막는다. 게스트는 기본만 사용하고 추가 선택 시 로그인 필요 안내를 연다 |
| 채팅 시작 | 고른 시작 상황과 페르소나로 채팅 하나를 생성한다. 중복 조작을 막고, 실패하면 상세와 선택을 유지한다. 게스트 체험 소진으로 채팅 생성 자체를 미리 막지 않는다 |
| 좋아요 | 타인 스토리에만 제공한다. 게스트 조작은 로그인 안내, 소유권 판정 전은 비활성 상태다. 요청 중 잠그고 실패하면 이전 값으로 되돌린다 |
| 삭제 | 소유자에게만 제공하고 확인 뒤 삭제한다. 실패하면 항목과 화면을 유지하며 상세에서 성공하면 제작 탭으로 이동한다 |
| 오류 | 없는 스토리는 재시도 없이 찾을 수 없음을 알린다. 일반 조회 실패는 다시 시도할 수 있어야 한다 |

신고 기준은 MODERATION, 페르소나 생성과 관리는 ACCOUNT의 책임이다.

### 2-2-4 간편 제작 입력

STORY-US-008부터 STORY-US-011.

| 입력 | 조건 |
|---|---|
| 장르 | 제공 장르 1~3개. 직접 입력은 제공하지 않는다 |
| 주인공 | 1명. 이름은 선택이며 30자 이내, 성별 미선택은 랜덤. 특징은 최소 1개, 최대 3개 |
| 주변 인물 | 0~5명. 초기에는 빈 행 하나, 빈 행도 최대 행 수에 포함한다. 이름과 성별은 선택, 특징은 인물당 최대 3개이며 생략 가능 |
| 특징 직접 입력 | 제공 특징과 합쳐 인물당 최대 3개. UI는 15자 이내이며 빈 입력은 추가하지 않는다. 장르는 직접 입력 대상이 아니다 |
| 이름 중복 | 비어 있지 않은 이름을 NFC 정규화하고 공백 제거와 소문자 변환 뒤 비교한다. 주인공을 먼저 두고 뒤에 중복된 인물에 오류를 표시하며 생성하지 않는다 |
| 스토리라인 | 후보 3개를 비교하고 하나를 선택한다. 다시 만들기는 해당 생성에 사용한 입력을 재사용한다 |
| 평가 | 좋아요와 별로예요 중 하나를 선택하거나 다시 눌러 취소한다. 평가 실패는 선택을 복원하고, 평가는 완성 입력이나 진행 조건이 아니다 |
| 추가 정보 | 추천 최대 3개, 자유 입력 최대 10행, 각 100자. 공백 제거 뒤 빈 행은 제외한다 |
| 이미지 스타일 | 제공 화풍에서 하나를 필수로 선택한다. 초기에는 미선택이며 스토리라인 재선택과 재생성에도 유지한다 |
| 공개 범위 | 공개로 시작하며 비공개로 바꿀 수 있다. 회원과 게스트 모두 선택하고 재선택, 재생성과 저장에도 유지한다. 게스트 공개 목록 반영 시점은 서버 계약을 따른다 |
| 재선택 확인 | 공백이 아닌 자유 입력 또는 선택한 추천이 있을 때만 손실을 확인한다. 확정하면 선택 스토리라인과 추가 정보, 추천 선택을 지우고 돌아간다. 화풍과 공개 범위는 유지한다 |
| 삭제 확인 | 입력이 있는 주변 인물은 확인 후 삭제한다. 빈 인물은 즉시 삭제한다. 인물이 없으면 AI가 생성할 수 있음을 알린다 |
| 입력 거절 | 서버가 내용 거절을 확정하면 입력을 보존해 키워드 단계로 돌려보내고 수정하도록 안내한다. 같은 거절 입력을 자동으로 반복 제출하지 않는다 |

### 2-2-5 장르 검색

STORY-US-008, STORY-US-013, STORY-US-014.

| 조건 | 요구사항 |
|---|---|
| 목록 | 대표 장르를 고정 순서로 보이고 검색으로 전체 제공 장르를 선택한다. 빈 검색어는 전체 목록이다 |
| 검색 | 최대 30자. 초성, 별칭, 공백과 대소문자 처리는 서버 기준을 사용한다 |
| 선택 | 칩과 검색 결과는 선택을 공유한다. 대표 밖 장르는 처음 선택한 순서로 칩 뒤에 추가하고 해제해도 자리와 순서를 유지한다 |
| 최대 선택 | 최대 개수에서는 새 선택만 막고 기존 선택 해제는 허용한다 |
| 대기 | 이전 결과를 유지하고 실제 요청이 200ms 이상 걸릴 때 로딩 안내를 보인다. 입력 대기 시간은 포함하지 않는다. 응답 전에 빈 결과를 표시하지 않는다 |
| 실패와 경합 | 실패와 결과 없음을 구분해 재시도를 제공하며 오래된 응답이 최신 질의나 닫힌 메뉴를 바꾸지 않는다 |
| 이전 초안 | 직접 입력 장르 중 공백과 대소문자를 무시한 이름이 제공 목록과 일치하면 복원한다. 나머지 원문은 저장본에 남기되 새 선택과 생성 요청에서 제외하고 재선택을 안내한다 |
| 수정 호환 | 기존 스토리 수정에서는 저장된 비제공 장르도 유지하고 보낼 수 있다. 이미 진행 중인 요청의 복구 입력은 새 카탈로그로 바꾸지 않는다 |

### 2-2-6 일반 제작과 수정 입력

STORY-US-013, STORY-US-014.

| 항목 | 제약 |
|---|---|
| 제목과 한 줄 소개 | 필수. 제목 100자, 한 줄 소개 255자 이내 |
| 커버 | 선택 이미지 1장. 주인공 이미지는 받지 않는다 |
| 세계관과 전개 방식 | 필수. UI 상한 각각 5,000자와 1,000자 |
| 분량 배분 | 묘사 1~9, 대사는 합계가 10이 되는 값. 기본 5:5 |
| 주인공 | 이름은 선택이며 입력 시 1~30자. 성별 남성 또는 여성, 특징 1,000자 이내는 필수. 이름 토큰을 사용하면 기본 주인공 이름이 필요하다 |
| 주변 인물 | 1~5명. 이름 30자 이내와 성별은 필수. 특징 1,000자 이내, 인물 소개 원문 150자 이내 한 줄, 이미지 1장은 선택 |
| 시작 상황 | 1~3개. 이름, 프롤로그, 상황 설명과 추천 입력 3개를 작성한다. 첫 시작 상황은 삭제할 수 없다 |
| 시작 상황 글 | 상황 이름 100자, 프롤로그와 상황 설명 각각 1,000자, 추천 입력 각각 200자 이내 |
| 엔딩 | 시작 상황마다 0~3개. 이름 100자, 달성 조건과 에필로그 각각 500자 이내. 최소 턴 수는 빈 칸에서 시작하고 숫자 0~50을 필수로 입력한다 |
| 주요 사건 | 스토리 전체에 0~10개. 추가한 사건은 이름 100자, 설명 1,000자, 키 문장 200자 이내를 모두 작성한다 |
| 장르와 주요 내용 | 이름이 각각 30자 이내인 제공 장르 1~8개를 선택 순서로 보낸다. 주요 내용은 선택이며 1,000자 이내다 |
| 공개 | 기본 비공개. 공개 스위치로 바꾼다 |
| 이름 중복 | 앞뒤 공백만 제거해 비교한다. 주인공과 주변 인물 전체, 주요 사건 전체, 같은 시작 상황의 엔딩 각각에서 뒤 항목을 오류로 표시한다 |
| 입력 삭제 | 내용이 있으면 확인한다. 인물 이미지는 내용에, 시작 상황의 엔딩은 시작 상황 내용에 포함한다 |
| 이미지 | JPG, PNG, WEBP 및 최대 5MB. 표지는 3:4, 인물은 4:3으로 자른다. 취소나 업로드 실패는 이전 이미지를 유지한다 |
| 글 최소 길이 | 기본 주인공 이름과 숫자 최소 턴 수를 제외한 모든 글은 입력했다면 trim 후 최소 2자다. 선택 입력도 한 글자만 쓰면 오류다. 서버의 한 글자 허용보다 엄격한 클라이언트 제약이다 |
| 검증 | 등록과 반려 후 전체 재제출은 전체 입력을 검증한다. 수정은 전송할 변경 필드를 검증하고 바꾸지 않은 기존 내용을 유지한다. 이름 토큰 조건은 유지해야 한다 |
| 수정 보존 | 알 수 없는 설정 절, 폼 밖 서버 인물과 바꾸지 않은 이미지를 잃지 않는다. 대표 이미지 변경이나 삭제는 나머지 이미지를 유지한다 |
| 반영 결과 | 등록한 스토리는 상세와 채팅에 사용한다. 수정한 설정은 해당 스토리를 참조하는 진행 중 채팅의 다음 턴부터 반영한다 |

길이와 형식의 세부 서버 제약은 [STORY 제공자 계약](../BACKEND/4-2-CONTRACT.md)의 일반 제작과 수정 입력을 따른다. 서버보다 엄격한 위 클라이언트 상한을 완화하지 않는다.

<br>

### 2-2-7 저장과 이탈

STORY-US-015, STORY-US-016, STORY-US-017.

| 조건 | 결과 |
|---|---|
| 서버 초안 | 회원당 5개, 초안 입력 64KB까지. 같은 계정의 다른 기기와 웹에서 이어서 만든다 |
| 저장 충돌 | 다른 곳에서 먼저 저장했음을 알리고 서버 내용을 남기거나 현재 입력으로 덮어쓸 수 있게 한다. 자동 덮어쓰기는 하지 않는다 |
| 저장 실패 | 미저장 상태와 입력을 유지한다. 사용자가 누른 저장 실패는 안내하고 백그라운드 저장 실패는 알리지 않는다 |
| 초안 없음 | 카드로 이어서 연 초안이 사라졌으면 알리고 새 입력으로 연다. 열어 둔 입력을 저장할 때 초안이 사라졌어도 입력을 잃지 않도록 복구한다 |
| 일반 제작 | 회원 서버 초안에 저장한다. 이전 기기 초안은 서버로 옮긴 뒤 기기 원본을 지우고, 상한 때문에 옮기지 못하면 기기에서 이어갈 수 있다 |
| 간편 제작 | 시작할 때 저장 위치를 정하고 세션 중 바꾸지 않는다. 게스트와 서버 연동 전 기기 초안은 일괄 서버 이관하지 않는다 |
| 생성 결과 | 요청한 기기에 즉시 보관하고 사용자의 다음 저장 때 서버 초안으로 옮긴다. 결과를 보기만 하고 떠나면 서버 초안 자리를 새로 차지하지 않는다 |
| 서버와 기기 기록 | 기기 진행 기록 이후 같은 서버 초안이 바뀌지 않았으면 한 카드로 합친다. 다른 기기가 이후 저장한 서버 초안은 별도 카드로 남기고 기기 기록 삭제로 지우지 않는다 |
| 이탈 | 저장하지 않은 입력, 저장 뒤 편집, 저장된 초안과 접수된 입력을 구분해 남는 내용과 사라지는 내용을 알린다. 잃을 내용이 없으면 묻지 않는다 |
| 이탈 확정 | 마지막 저장 이후 편집을 저장하지 않고 나간다. 수정 폼에는 초안을 두지 않으며 변경된 내용이 있을 때만 확인한다 |
| 계정 격리 | 로그아웃과 계정 전환 뒤 이전 계정 기록이나 늦은 결과를 다른 계정에 보이지 않는다 |

<br>

### 2-2-8 제출과 결과 복구

STORY-US-012, STORY-US-017, STORY-US-018.

| 조건 | 결과 |
|---|---|
| 간편 제작 제출 | 복구할 요청을 저장한 뒤 응답을 기다리지 않고 제작 탭으로 이동한다. 저장에 실패하면 전송하지 않고 입력을 유지한다 |
| 중복 방지 | 제출 연타로 요청이 중복 생성되지 않는다. 같은 명령의 재시도는 동일한 요청으로 복구한다 |
| 결과 불명확 | 응답을 놓친 경우를 확정 실패로 처리하지 않는다. 기록을 유지하고 서버 결과를 조회한다 |
| 간편 제작 완료 | 제작 목록 데이터가 준비되면 해당 진행 카드를 완성 스토리로 교체한다. 자동으로 채팅을 만들지 않으며 상세에서 사용자가 시작한다 |
| 간편 제작 확정 실패 | 완성 요청 카드를 제거하고 제출한 입력 그대로 추가 정보 단계 초안으로 되돌린다. 사유를 알면 그 사유로 안내하고, 실패 카드와 별도 재시도 버튼을 남기지 않는다 |
| 일반 제작 접수 | 입력의 기준은 서버 제출본이 된다. 해당 초안을 제거하고 같은 폼을 다시 초안으로 저장하지 않는다 |
| 일반 제작 승인 | 첫 시작 상황으로 채팅을 시작한다. 채팅 생성 실패는 스토리 상세에서 재시도할 수 있게 한다 |
| 일반 제작 지연 | 대기 상한이 지나면 제작 탭에서 후속 결과를 확인하도록 안내한다. 화면을 떠나도 서버 검수는 계속된다 |
| 반려와 실패 | 입력과 사유를 보존해 같은 제출본을 수정하고 다시 제출한다. 칸별 사유와 특정 칸에 연결할 수 없는 사유를 모두 표시한다 |
| 수정 검토 중 | 입력과 저장을 잠그고 탭 내용은 볼 수 있게 한다. 기존 스토리 수정 제출본을 신규 제작 카드로 중복 표시하지 않는다 |
| 수정 결과 | 성공과 대기 상한에는 진입했던 화면으로 돌아간다. 반려와 실패는 입력을 유지해 다시 저장할 수 있게 한다 |
| 취소와 삭제 | 신규 검토 중 제출본은 등록 취소, 반려와 실패는 삭제 확인을 제공한다. 실패하면 항목을 유지한다 |
| 조회 수명 | 화면용 반복 조회는 보이는 동안만 실행한다. 화면 이탈로 서버 접수를 취소하거나 다른 제작을 삭제하지 않는다 |

### 2-2-9 사용 안내와 접근성

STORY-US-020, STORY-US-021.

| 항목 | 요구사항 |
|---|---|
| 웹 제작 안내 | 기기에서 끝까지 보거나 건너뛰지 않은 모든 사용자에게 단계 순서대로 제공한다. 로그인 여부와 제작 이력은 조건이 아니다 |
| 웹 안내 간섭 | 생성 중과 실패, 로그인 안내와 저장 충돌 등 다른 모달이 열린 동안 겹쳐 열지 않는다. 열린 채 이탈하면 같은 단계에서 다시 안내한다 |
| Android 가입 안내 | 신규 가입 직후 오리지널을 고르거나 간편 제작을 시작한다. 기존 회원 로그인과 저장 세션 시작은 홈으로 간다 |
| Android 완료 | 채팅 시작 또는 직접 만들기로 마친다. 완료 전에는 다른 탭으로 넘어가지 않으며 앱 재실행에도 안내로 복귀한다 |
| 키보드 | 새 반복 입력 항목으로 스크롤할 때 초점을 강제로 옮기지 않는다. 키보드가 하단 제작 버튼을 가리면 버튼을 숨기고 입력을 보존한다 |
| 보조 기술과 모션 | 선택 상태와 오류, 이미지와 조작의 이름을 전달한다. 장식은 보조 기술에서 제외하고 동작 줄이기에서 장식 모션을 멈춘다 |

### 2-2-10 미구현 범위

STORY-US-022의 세계관 탭은 미구현이다. 목표는 제공 장르와 배경 키워드를 각각 1~2개 선택하는 것이지만 서버에서 배경 키워드를 제공하지 않는다. 현재 간편 제작에는 2-2-4의 제공 장르 1~3개만 적용하며 장르 직접 입력은 제공하지 않는다. 배경 선택이 이미 가능한 것처럼 화면과 검증을 정의하지 않는다.
