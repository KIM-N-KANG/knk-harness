# STORY 공통 실행

기준: [연동 계약](CONTRACT.md), [상태 관리](STATE-MANAGEMENT.md).

<br>

### 저장과 요청 순서

1. 초안 저장을 한 번에 하나씩 처리하고 앞 응답의 version을 다음 baseVersion으로 사용한다. 저장 중 새 저장이 오면 뒤에 이어 처리한다.
2. 생성이나 완성 명령을 보내기 전에 진행 중 편집 저장을 마치고 복구 기록을 영속화한다. 실패하면 전송하지 않는다.
3. 같은 요청 재시도에는 같은 requestId와 명령을 사용한다. 새 입력이나 화풍 및 공개 범위 변경은 새 명령이다.
4. 완성 요청 삽입과 제출한 초안 제거를 함께 처리한다. 요청을 저장한 뒤 제작 탭으로 복귀한다.
5. 성공 결과의 승격을 실제로 확정한 경로만 계정 목록 갱신과 게스트 ID 및 분석 반영을 수행한다.
6. 확정 실패는 완성 기록 제거와 원 입력의 추가 정보 초안 복원을 함께 처리한다. 다른 제작의 기록을 건드리지 않는다.

<br>

### 충돌과 조회

| 조건 | 처리 |
|---|---|
| 초안 저장 409 | 응답의 현재 버전을 보관하고 사용자 선택을 기다린다. 덮어쓰기 선택은 그 버전으로 현재 입력 저장 |
| 기준 버전 저장 거절 | 상세를 확인해 404이면 같은 ID와 입력을 기준 버전 없이 새 초안으로 저장 |
| 스토리라인 평가 | 300ms 입력 대기 뒤 PUT 또는 DELETE. 실패는 선택 복원과 토스트 |
| 퍼널 복구 | 화면이 보일 때 3초 간격. 다른 초안과 완성 요청은 해당 퍼널이 복구하지 않는다 |
| 제작 진행 카드 | 노출 중 5초 간격. 화면 이탈과 백그라운드에서 반복 조회 중지 |
| 제작 완료 | 목록 재조회 또는 게스트 목록 반영 후 새 storyId를 목록에서 확인할 때 진행 기록 제거 |
| 내용 거절 | 코드로 확정해 입력 단계로 복귀. 스토리라인 재시작은 새 requestId, 완성은 원 명령을 복원하고 사유 안내 |

<br>

### 일반 제작과 검수

1. 일반 제작 POST 또는 제출본 PUT에 해당 draftId를 전달한다. 202 접수 뒤 초안 정리까지 완료하고 같은 폼의 임시 저장을 중단한다.
2. 제출본 상세를 화면이 보이는 동안 1초 간격으로 최대 60초 조회한다. 화면 이탈은 조회만 중지한다.
3. 승인은 신규 등록과 수정의 화면 흐름에 따라 처리하고 관련 목록과 상세를 갱신한다. 반려와 실패는 제출 당시 입력과 사유를 보존한다.
4. 미승인 신규 CREATE 목록은 검토 중 항목이 있을 때 5초 간격으로 조회한다. 목록에서 빠진 항목이 있으면 내 스토리도 다시 조회한다.
5. 신규 재제출 진입에서 이미 PENDING이면 제작 탭, APPROVED면 상세로 보낸다. 실패하면 제작 탭에서 조회 실패를 알린다.
6. 수정은 변경 필드만 PATCH하며 반려 후 전체 재제출은 모든 필드를 보낸다. 표지 삭제가 있으면 DELETE를 먼저 수행한 뒤 남은 변경을 PATCH한다.

검수 판단 기준과 서버의 재시도는 MODERATION 제공자 계약을 따른다. 화면 대기 상한이 서버 작업의 실패를 뜻하지 않는다.
