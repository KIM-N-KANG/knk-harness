# 4-3 STORY 공통 상태 관리

기준: [연동 계약](4-1-CONTRACT.md), [저장과 이탈 요구](2-2-REQUIREMENTS.md#2-2-7-저장과-이탈).

<br>

### 4-3-1 상태의 기준

| 상태 | 기준과 수명 |
|---|---|
| 공개와 소유 목록 | 서버 응답. 게스트 소유 ID는 ACCOUNT의 기기 목록 |
| 상세 권한 | 인증된 상세 응답과 허용된 게스트 목록. 공개 초기값만으로 소유권을 정하지 않는다 |
| 편집 중 입력 | 현재 제작 세션. 사용자의 저장 전에는 마지막 저장본과 구분 |
| 서버 초안 | 회원 저장 입력의 기준. 고정 draftId와 기준 version |
| 기기 진행 기록 | 생성 명령과 결과, 완성 요청, 확정 실패에서 되돌린 입력. 요청한 기기에만 존재 |
| 검수 제출본 | 접수 이후 입력의 기준은 서버다. 임시 저장으로 같은 입력을 다시 신규 제출하지 않는다 |
| 접기와 선택 탭 | 화면 상태. 접기만 바꾼 것을 저장할 내용 변경으로 세지 않는다 |

<br>

### 4-3-2 초안과 진행 기록 병합

1. 제작 진입 때 회원 상태와 재개 기록에 따라 서버 또는 기기 저장 세션을 정하고 고정한다.
2. 진행 기록에는 서버 draftId와 기록 당시의 기준 version을 연결한다. 서버 초안의 최초 저장 시각도 이어받는다.
3. 연결된 서버 초안의 version이 기기 기준 이하이면 서버 카드를 숨기고 한 장으로 센다. 이후 다른 곳에서 저장한 서버 초안은 별도 카드로 보인다.
4. 기기 카드 삭제는 그 카드에 가려진 서버 초안도 지운다. 이후 수정된 서버 초안은 지우지 않는다.
5. 생성 결과는 즉시 기기에 남긴다. 다음 사용자 저장이 성공해야 서버 초안으로 옮기고 해당 기기 기록을 지운다.
6. 서로 다른 제작의 초안, 생성 요청과 완성 요청은 독립적이다. 오래된 편집 저장은 새 진행 요청을 덮지 못한다.

<br>

### 4-3-3 복구에 보존할 값

| 전환 | 보존 |
|---|---|
| 키워드에서 생성 및 재생성 | 세션 draftId, 최초 저장 시각, 명령과 requestId |
| 결과 표시 | 현재 표시 중 결과와 그 결과를 만든 요청. 실패한 재생성 요청과 구분 |
| 완성 제출 | 고른 스토리라인, 추가 정보, 화풍, 공개 범위, 원 생성 요청, 서버 초안 연결과 최초 저장 시각 |
| 완성 실패 후 초안 | 제출한 입력과 같은 명령의 requestId. 이전 요청에서 공개 범위가 없었다면 PRIVATE로 복원 |
| 완료 | 목록에서 같은 storyId를 확인할 때까지 진행 기록 유지, 중복 카드 숨김 |
| 계정 변경 | 이전 계정의 저장과 결과 반영 거부. 정리와 보존 방식은 플랫폼의 적용 범위 유지 |

생성 결과 보기만으로 서버 초안을 새로 만들지 않는다. 수정 화면은 baseline과 서버 ID를 보존해 바꾸지 않은 설정과 이미지를 유지한다.
