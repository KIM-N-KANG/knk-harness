# DECISIONS.md

현재 적용 기준은 각 명세에 두고 결정 당시의 이유와 대체 관계는 이 문서에 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다. 기존 ID, 날짜, 당시 상태와 근거를 유지한다.
- 상태와 구현 설명은 원본의 기록 시점을 기준으로 해석한다. 현재 적용 여부나 배포 완료를 과거 기록만으로 단정하지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체하는 결정과 적용 범위를 명시한다.
- 원문에 구분되지 않은 배경, 대안과 영향은 추측해서 보충하지 않는다.

**W-017. 편집 초안을 같은 키의 목록으로 확장**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-09-22 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 완성 요청은 목록이지만 편집 초안은 슬롯 한 건이라 초안이 있으면 새 제작 전에 이어서/새로 만들기를 골라야 했고 새로 만들면 기존 초안이 사라졌다. |
| 채택 | `manyak:pending-creation-request` 값을 레코드 배열로 바꾸고 구 단일 객체는 1건 목록으로 읽는다. 안정적인 초안 ID를 새로 두지 않고 기존 `requestId`를 목록 키로 유지하며, 퍼널 한 세션이 자기 레코드 한 건만 소유하는 규칙을 퍼널 훅 한 곳(`persistOwnRecord`)에 둔다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 단계 전환은 이미 옛 레코드를 지우고 새 레코드를 넣는 방식이라 목록화만으로 같은 결과가 나며, 서버 복구 조회 키가 `requestId`라 별도 매핑이 필요 없다. 같은 키를 쓰면 배포 시점에 남은 사용자 초안을 파서 호환 한 줄로 보존한다. |
| 영향 | 이어서/새로 만들기 다이얼로그와 `client_storyCreate_resumeDialog_*` 이벤트를 제거한다. 퍼널 직접 진입, FAB은 항상 새 세션이고 재개는 진행 카드에서만 한다. 완성 실패 강등은 다른 초안이 있어도 항상 초안으로 되돌린다. Android는 KNK-1395로 같은 계약을 따른다. |
| 근거 | [제작 카드와 다중 완성 진행](../2-2-REQUIREMENTS.md#2-2-2-탐색과-제작-목록), [웹 제작 흐름](2-2-REQUIREMENTS.md), [게스트 저장소 키](../../../ACCOUNT/CLIENT/WEB/2-2-REQUIREMENTS.md#2-2-1-게스트와-회원) |

**W-019. 제작 로컬 저장을 Dexie 트랜잭션으로 전환**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-09-26 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 한 항목을 바꾸어도 전체 JSON 배열을 동기식으로 다시 썼으며 초안 교체, 완성 제출, 실패 복원 중 일부 쓰기만 성공할 수 있었다. |
| 채택 | Dexie와 IndexedDB로 제작 두 테이블을 저장하고 상태 검사 및 전환을 트랜잭션으로 처리한다. useLiveQuery로 구독하며, 초기 조회와 명시적 이탈 및 제출은 비동기 저장 완료를 기다린다. 제출 전 저장 실패는 공통 계약에 맞춰 입력을 보존하고 요청을 막는다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 영향 | 원문에 별도 항목으로 구분하지 않음 |
| 근거 | [웹 제작 계약](2-2-REQUIREMENTS.md), [제작 저장 구조](../../../ACCOUNT/CLIENT/WEB/2-2-REQUIREMENTS.md#2-2-1-게스트와-회원) |
| 대체 범위 | W-017의 localStorage 배열 저장과 별도 쓰기 방식만 대체한다. requestId, 다중 초안, 새 제작 및 카드 재개 계약은 유지한다. |
| 이관 | 검증된 legacy 입력은 최초 시각과 순서를 보존하고, DB 커밋 후에만 원문을 정리한다. 완료 표시는 같은 원본의 재삽입을 방지한다. 이중 쓰기와 자동 localStorage 폴백은 두지 않는다. |
| 세션 경계 | 본문을 저장하지 않는 동기식 세대값으로 로그아웃 직후 지연 작업을 무효화한다. DB 삭제 실패 시 다음 접근에서 정리를 먼저 수행한다. |
| 한계 | 종료 순간의 비동기 저장, 서버 백업, 기기 간 동기화를 보장하지 않는다. 배포 전에 열린 구버전 탭의 localStorage 쓰기는 자동 병합하지 않는다. 배포 시 구버전 탭 정리 및 데이터 롤백 정책을 확인해야 한다. |

<a id="w-020"></a>
<a id="w-020-간편-제작-편집-저장을-버튼단계-이동화면-숨김으로-제한"></a>

**W-020. 간편 제작 편집 저장을 버튼, 단계 이동, 화면 숨김으로 제한**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-01 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 웹 간편 제작은 마지막 변경 300ms 뒤 자동 저장하고 헤더에 저장 상태 배지를 보였다. Android 간편 제작(A-020)과 웹 일반 제작은 이미 "임시 저장" 버튼 방식이라 같은 앱 안에서 저장 방식이 달랐다. |
| 채택 | 편집은 메모리에 두고 일반 제작과 같은 "임시 저장" 버튼, 단계 이동, 화면 숨김 때만 저장한다. 버튼, 이탈 다이얼로그, 새로고침 확인창은 일반 제작 코드를 함께 쓴다. 스토리라인 생성 요청과 결과는 지금처럼 바로 저장한다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 사용자가 저장 시점을 알 수 있고, 입력 삭제 같은 편집이 말없이 확정되지 않는다. 단계 이동 저장은 일반 제작의 탭 이동 저장과 맞춘다. 생성 결과는 비용이 드는 서버 결과이고 복구 조회에 필요해 버튼을 기다리지 않는다. |
| 영향 | 300ms 디바운스 저장과 저장 상태 배지를 제거한다. Android와 달리 단계 이동 때도 저장한다. 잃을 것이 없으면(입력도 저장본도 없음) 간편, 일반 제작 모두 확인 다이얼로그 없이 나가고, 저장하지 않은 입력이 있으면 키워드 단계에서도 새로고침 확인창을 띄운다. `client_storyCreate_draftSaved`는 세 저장 계기의 쓰기 성공에서만 발생한다. |
| 근거 | [웹 제작 흐름](2-2-REQUIREMENTS.md), [Android 제작과 데이터 보존](../ANDROID/AGENTS.md), [A-020](../ANDROID/DECISIONS.md#a-020) |
| 대체 범위 | W-019 중 명시적 이탈이 편집 저장 완료를 기다리는 부분만 대체한다. 저장소, 트랜잭션, 생성, 완성 요청의 사전 저장은 유지한다. |

<a id="w-021-일반-제작-이미지는-브라우저에서-잘라-jpeg로-올림"></a>

**W-021. 일반 제작 이미지는 브라우저에서 잘라 JPEG로 올림**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-01 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 일반 제작의 커버(3:4)와 주변 인물(4:3) 이미지는 원본 그대로 올라가, 비율이 다르면 목록, 상세에서는 가운데가 임의로 잘리고 채팅의 인물 이미지에는 여백이 생겼다. |
| 채택 | 파일을 고르면 하단 시트에서 칸 비율 프레임에 맞춰 이동, 확대로 영역을 고르고, 브라우저 canvas로 잘라 긴 변 최대 1440px의 JPEG(품질 0.9)로 기존 presign 업로드에 올린다. 크롭 UI는 `react-easy-crop`을 쓴다. 원본의 형식, 5MB 선검사는 유지한다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 서버, presign 계약을 바꾸지 않고 비율을 보장한다. `react-easy-crop`은 고정 프레임과 드래그, 핀치, 휠 확대, 경계 제한을 기본 제공하고 작다(gzip 약 7KB). Safari는 canvas에서 WebP를 만들지 못해 PNG로 바뀌므로 모든 기기에서 같은 결과가 나오는 JPEG를 택했다. PNG는 1440px에서도 5MB에 가까워질 수 있지만, JPEG는 최악(무작위 노이즈)에도 약 1.8MB라 5MB 제한에 여유가 있다. |
| 영향 | 업로드 Content-Type은 항상 `image/jpeg`이고 투명 배경은 흰색이 된다. 이미 올린 이미지를 다시 자르는 편집은 두지 않으며 다시 고르면 된다. 5MB가 넘는 원본은 지금처럼 고르기 전에 막는다. |
| 근거 | [웹 제작 흐름](2-2-REQUIREMENTS.md), [일반 제작 구조](4-4-EXECUTION.md#4-4-3-일반-제작과-이미지) |

<a id="w-024"></a>
<a id="w-024-완성-중-표지를-android와-같은-로고-마스코트-애니메이션으로-바꿈"></a>

**W-024. 완성 중 표지를 Android와 같은 로고 마스코트 애니메이션으로 바꿈**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-06 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | Android가 완성 중 카드 표지를 점 로딩에서 로고 마스코트 애니메이션으로 바꾸면서(A-065) 두 플랫폼의 표지가 갈렸다. 사용자는 완성을 기다리는 동안 같은 카드를 보므로 표현을 맞춘다. |
| 채택 | 웹도 같은 안무를 쓴다. 안무는 시간에서 자세를 계산하는 순수 함수라 Android의 값을 그대로 TypeScript로 옮기고, 그리기는 Canvas 2D로 같은 소품과 붓질을 그린다. 마우스, 트랙패드 환경에서는 기존 점 무리처럼 포인터에 반응하도록 마스코트 눈이 포인터를 바라보고, 동작 줄이기에서는 한 장면으로 정지한다. A-065의 "Android 표현 차이"는 이 결정으로 플랫폼 공통 표현이 된다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | SVG와 motion 컴포넌트로 막마다 요소를 따로 움직이면 소품 수만큼 레이어와 타이밍이 늘고 Android와 값이 갈라진다. 순수 함수 하나를 두 플랫폼이 같은 값으로 따르면 한쪽을 고칠 때 다른 쪽에 같은 수정을 옮기기 쉽고, 순간이동 없음, 표지 안 유지 같은 같은 테스트로 검증할 수 있다. |
| 영향 | 완성 중 표지는 `ImageGeneration`을 쓰지 않는다. 채팅 장면 썸네일 자리는 점 로딩을 유지한다. 테마 토큰이 oklch라 캔버스에서 색을 섞으려고 한 점 캔버스로 sRGB 값을 읽으며, 테마가 바뀌면 다시 읽는다. 안무를 바꿀 때는 Android `StoryCompletingChoreography`와 함께 고친다. |
| 근거 | [웹 제작 탭 진행 카드](../3-3-LAYOUT.md#3-3-6-초안과-제출본-표현), [Android A-065](../ANDROID/DECISIONS.md#a-065) |

<a id="w-026"></a>
<a id="w-026-완성-중-표지-안무를-웹이-먼저-개편하고-android가-같은-값으로-따라옴"></a>

**W-026. 완성 중 표지 안무를 웹이 먼저 개편하고 Android가 같은 값으로 따라옴**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-06 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 완성 중 표지의 그림 막이 능선과 해를 그려 흔한 이미지 아이콘처럼 보였고, 표정이 동그란 눈 하나뿐이었다. 사용자 요청에 따라 채팅 실시간 이미지 로딩(W-025)처럼 붓으로 인물을 그리고, 타자 전 에너지 드링크 막과 다양한 표정을 더한다. |
| 채택 | 웹 안무를 먼저 바꾸고 Android가 같은 값으로 이식한다. 키워드, 스토리라인, 타자, 뛰어다니기 막은 유지하고 표정과 소품을 더하며, 타자 앞에 에너지 드링크 막을 넣고, 그림 막은 베레모와 붓을 챙겨 세로 캔버스에 주인공 인물화를 그린 뒤 소품을 던지는 세리머니로 바꾼다. 새 눈 모양, 베레모, 붓, 붓길 해석, 붓질은 채팅 로딩과 공용 모듈로 함께 쓴다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 채팅 로딩에서 검증한 붓끝 고정 그리기와 SVG path 붓길을 그대로 쓰면 인물화를 좌표만으로 그릴 수 있고 두 무대의 표현이 맞춰진다. 웹 캔버스에서 프레임을 빠르게 확인하며 다듬은 값을 Android가 옮기는 편이 두 플랫폼을 동시에 고치는 것보다 빠르다. |

<a id="w-036-회원-일반-제작-임시-저장본은-서버에만-둔다"></a>

**W-036. 회원 일반 제작 임시 저장본은 서버에만 둔다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-16 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 일반 제작 임시 저장본이 브라우저 IndexedDB에만 있어 다른 기기나 브라우저에서 이어서 만들 수 없고 로그아웃하면 사라졌다. 서버 임시 저장 API(KNK-1641)가 멱등 PUT과 버전 충돌(409)을 제공한다. |
| 채택 | 일반 제작은 회원 전용이므로 임시 저장본을 서버 초안에만 둔다. 기기 안 캐시나 동기화 상태는 두지 않는다. 초안 ID는 화면마다 고정한 기존 `requestId`를 그대로 쓴다. 화면 숨김 저장은 `keepalive` PUT으로 보내고 실패를 알리지 않는다. 서버 연동 전 기기에 남은 일반 제작 저장본은 제작 탭 진입 때 같은 ID로 옮긴다. 간편 제작과 게스트의 IndexedDB 초안, 그리고 [W-017](DECISIONS.md#w-017)의 목록 구조는 바꾸지 않는다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 서버의 같은 내용 재전송 허용과 버전 판정만으로 재시도와 여러 기기 저장을 다룰 수 있어, 기기 안 사본과 서버 사이의 동기화 상태를 따로 관리할 이유가 없다. 일반 제작은 처음부터 한 화면이 한 ID를 쓰므로 단계마다 ID가 바뀌는 간편 제작과 달리 ID 구조를 바꾸지 않아도 된다. |
| 영향 | 오프라인에서는 임시 저장할 수 없고 기존 저장 실패 안내를 띄운다. 새로고침 경고는 그대로 두어 화면 숨김 저장이 끝나지 못한 변경을 지킨다. 옮긴 레거시 초안의 처음 저장 시각은 옮긴 시각으로 바뀐다. |
| 근거 | [2-2-6 일반 제작과 수정 입력](../2-2-REQUIREMENTS.md#2-2-6-일반-제작과-수정-입력), [스토리 제작 임시 저장](../../BACKEND/4-2-CONTRACT.md#4-2-23-초안-목록), [KNK-1667](https://kimandkang.atlassian.net/browse/KNK-1667) |

<a id="w-037-회원-간편-제작-초안은-세션-고정-id로-서버에-두고-진행-기록은-기기-안에-남긴다"></a>

**W-037. 회원 간편 제작 초안은 세션 고정 ID로 서버에 두고 진행 기록은 기기 안에 남긴다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-16 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | [W-036](DECISIONS.md#w-036)은 일반 제작만 서버로 옮기고 간편 제작은 그대로 두었다. 간편 제작은 키워드 초안, 생성 중, 스토리라인 초안, 완성 중이 단계마다 다른 `requestId` 기록으로 바뀌는 구조([W-017](DECISIONS.md#w-017))라 서버 초안 하나에 그대로 대응하지 않는다. 서버는 게스트 때 만든 생성 요청을 회원 초안에 연결하지 않고, 초안은 간편 제작과 일반 제작을 합쳐 회원당 5개까지이다. |
| 채택 | 퍼널을 열 때 세션의 저장 위치를 정한다. 회원이 새로 시작했거나 서버 초안으로 연 세션은 세션마다 고정한 draftId로 키워드 초안과 스토리라인 초안을 서버에 덮어쓰며, 이 세션에서는 [W-017](DECISIONS.md#w-017)의 "안정적인 초안 ID를 두지 않는다"를 대체한다. 생성 중, 생성 결과, 완성 중, 완성 실패 기록은 지금처럼 기기 안에 두고 서버 초안 ID와 기준 버전을 붙인다. 생성 결과는 받자마자 올리지 않고 다음 사용자 저장 때 올린다. 게스트 세션과 서버 연동 전이나 게스트 때 만든 기기 안 초안은 옮기지 않고 기기 안에 계속 저장한다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 진행 기록은 서버 생성 요청 복구 조회와 원 POST 보류 판정에 묶여 있어 기기 안에 두는 편이 기존 복구 흐름을 그대로 쓴다. 생성 결과를 받자마자 올리거나 기존 초안을 한꺼번에 옮기면 보기만 하고 떠난 제작이 5개 상한을 채워 일반 제작 저장까지 막는다. 게스트 때 만든 스토리라인 초안은 서버가 연결을 거절하므로 기기 안 저장을 유지해야 이어서 만들 수 있다. |
| 영향 | 생성 결과는 다음 저장 전까지 그 기기에만 있어 다른 기기는 이전 서버 초안을 본다. 같은 제작의 서버 카드는 기기 안 진행 기록이 있고 그 기록 뒤로 서버 초안이 다시 저장되지 않은 동안 숨기고, 그 기기 안 카드를 지우면 숨긴 서버 초안도 지운다. 기록 뒤에 다른 기기가 저장한 서버 초안은 따로 보이고 남긴다. 완성 요청 때 서버가 지운 초안을 실패 뒤 다시 저장하면 처음 저장 시각이 바뀐다. 기존 기기 안 간편 제작 초안은 다른 기기에서 이어서 만들 수 없다. 저장 훅과 충돌 다이얼로그는 두 제작 방식이 함께 쓰도록 `stories/_shared`로 옮긴다. |
| 근거 | [간편 제작 임시 저장](../4-1-CONTRACT.md#4-1-4-공통-초안-봉투와-버전), [스토리 제작 임시 저장](../../BACKEND/4-2-CONTRACT.md#4-2-23-초안-목록), [KNK-1667](https://kimandkang.atlassian.net/browse/KNK-1667) |

<a id="w-038-회원은-만들고-있는-스토리-카드가-5장이면-새-제작을-막는다"></a>

**W-038. 회원은 만들고 있는 스토리 카드가 5장이면 새 제작을 막는다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-17 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | [W-037](DECISIONS.md#w-037)은 생성 결과를 받자마자 서버에 올리지 않고 기기 안 카드로 둔다. 서버 초안이 5개로 가득 찬 회원도 새 간편 제작을 시작해 스토리라인까지 받을 수 있었고, 그 결과는 서버에 올라갈 자리가 없어 그 기기에만 남았다. 제작 탭 카드는 5장을 넘었고, 결과를 받은 직후의 "임시 저장"은 기기 안 기록을 저장본으로 보고 "임시 저장했어요"를 띄워 다른 기기에서 보이지 않는 저장을 저장된 것처럼 알렸다. |
| 채택 | 회원은 제작 탭에 보이는 만들고 있는 스토리 카드(서버 초안과 이 기기의 진행 기록을 같은 제작 한 장으로 센 병합 결과)가 5장 이상이면 새 제작을 시작하지 않고 토스트로 알린다. 제작 FAB 클릭과 두 제작 화면의 새 세션 판정에서 막아 온보딩, 공유 열람 CTA, 직접 주소 진입까지 덮는다. 이어서 만들기와 목록을 읽지 못한 경우는 막지 않는다. 게스트는 적용하지 않는다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 서버 초안 수만 세면 서버에 없는 생성 결과 카드가 계속 늘어 문제가 남는다. 보이는 카드 수로 세면 서버 초안 하나는 카드 많아야 한 장이라, 상한 아래에서 시작한 제작은 첫 저장에 서버 자리가 있고 카드 수도 사용자가 보는 상한과 맞다. 생성 결과를 받자마자 올리는 방법은 보기만 하고 떠난 제작이 자리를 차지하고, 가득 차면 결국 기기 안에만 남아 이 결정을 대신하지 못한다. 페르소나 10개 상한과 같이 이동하지 않고 토스트로 알린다. |
| 영향 | 이미 5장 이상인 회원은 4장 이하가 될 때까지 새로 만들 수 없다. 완성 실패로 초안이 되돌아오거나 두 기기에서 동시에 시작하면 6장이 될 수 있고, 이때 서버 저장은 기존 상한 토스트로 막힌다. 간편 제작 주소로 바로 들어와 막힌 경우에도 퍼널이 먼저 열려 `client_storyCreate_viewed`는 발생한다(일반 제작은 폼을 열지 않아 조회 이벤트가 없다). |
| 근거 | [제작 카드와 다중 완성 진행](../2-2-REQUIREMENTS.md#2-2-2-탐색과-제작-목록), [스토리 제작 임시 저장](../../BACKEND/4-2-CONTRACT.md#4-2-23-초안-목록), [KNK-1667](https://kimandkang.atlassian.net/browse/KNK-1667) |

**W-039. 간편 제작은 단계를 옮겨도 저장하지 않는다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-17 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 간편 제작 초안이 서버 초안이 되면서([W-037](DECISIONS.md#w-037)) 단계 이동 저장은 스토리라인을 고르거나 다시 고를 때마다 알림 없이 서버 PUT을 보냈다. Android는 처음부터 버튼과 백그라운드 전환에서만 저장해, 같은 초안을 두 플랫폼이 다른 시점에 저장했다. |

| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 사용자가 누른 저장과 앱을 떠날 때의 저장만 남겨 저장 시점이 분명하고, 두 플랫폼의 저장 계기가 같아진다. 단계 이동은 입력을 확정하는 동작이 아니라 알림 없는 서버 저장이 필요하지 않다. |
| 영향 | 스토리라인을 고르고 저장하지 않은 채 닫으면 고른 단계는 남지 않고 확인 다이얼로그가 저장하지 않은 내용을 알린다. `client_storyCreate_draftSaved`는 버튼과 화면 숨김 저장의 쓰기 성공에서만 발생한다. 일반 제작의 탭 이동 저장은 이 기록의 범위가 아니다. |
| 근거 | [웹 제작 흐름](2-2-REQUIREMENTS.md), [Android 제작과 데이터 보존](../ANDROID/AGENTS.md), [KNK-1667](https://kimandkang.atlassian.net/browse/KNK-1667) |
| 대체 범위 | [W-020](DECISIONS.md#w-020)의 저장 계기 중 단계 이동만 대체한다. "임시 저장" 버튼과 화면 숨김 저장, 생성 요청과 결과의 즉시 저장은 유지한다. |
