# 4-3 웹 STORY 상태 관리

기준: [공통 상태](../4-3-STATE-MANAGEMENT.md), [웹 구성](4-2-COMPONENT-ARCHITECTURE.md).

### 4-3-1 저장소와 수명

| 위치 | 값과 수명 |
|---|---|
| URL | 홈 filter와 sort. 기본값은 생략하고 새로고침 및 뒤로가기에 유지 |
| IndexedDB | Dexie `manyak-creation`의 pendingCreations, storyCompletions, metadata |
| 편집 테이블 | KEYWORD_DRAFT, STORY_DRAFT, STORYLINE_GENERATION. GENERAL_DRAFT는 서버 이관 전 레거시만 남음 |
| 완성 테이블 | requestId별 STORY_COMPLETION |
| 서버 초안 | 회원 일반 제작과 회원 간편 제작 서버 세션의 사용자 저장 |
| localStorage | `manyak:creation-epoch` 정수. 세션 종료를 먼저 알리는 세대 표시이며 본문이나 자격 증명이 아님 |
| sessionStorage | `manyak:story-draft-resume-intent` requestId. 이동 전 기록하고 진입 때 한 번 읽어 소비 |
| sessionStorage | `manyak:pending-chat-open`의 storyId, chatId, at. 일반 제작 승인 뒤 상세에서 한 번 읽어 채팅을 열며 30초 초과는 무시 |
| localStorage | `manyak:create-tutorial-stage`, 마지막 마친 단계 또는 done. 서버 렌더는 완료 상태, 접근 실패는 처음 상태 |

이미지 Blob은 기기의 레거시 일반 제작 초안에만 있으며 서버 payload에는 objectKey만 보낸다. 새 폼 미리보기는 blob URL, 서버 초안과 제출본은 imageUrls다. blob URL은 교체, 삭제와 표시 종료 때 해제한다.

### 4-3-2 트랜잭션과 이관

- 초기화는 이관이 끝난 뒤 읽기 전용 구독을 시작한다. 편집과 완성 목록은 같은 읽기 트랜잭션에서 읽고 같은 origin의 변경을 구독한다.
- 기존 localStorage 단일 및 배열 기록을 검증해 한 DB 트랜잭션으로 옮긴다. 기존 DB 레코드는 덮지 않고 metadata 완료 표시로 재이관을 막는다. 손상 항목이 있는 원문은 보존하고, 정상 원문도 커밋 뒤 값이 그대로일 때만 삭제한다.
- storageOrder로 날짜가 없거나 동률인 기록의 순서를 유지한다. createdAt은 첫 upsert 때 정하고 단계 전환, 재생성, 완성 이관과 실패 복원에도 이어받는다.
- 소유 requestId 교체, 완성 삽입과 원 초안 제거, 실패 초안 복원과 완성 제거는 상태 확인부터 변경까지 한 트랜잭션이다. 해당 전환을 실제로 확정한 경로만 후속 효과를 수행한다.
- 세션 종료는 localStorage 세대를 먼저 바꾼 뒤 DB metadata와 두 테이블을 함께 정리한다. 이전 세대 쓰기를 거부한다. 정리 실패는 다음 접근이 먼저 재시도하고 새 세대에서 legacy를 다시 이관하지 않는다. 세대값 쓰기 자체가 실패하면 현재 탭의 저장소 접근도 차단한다.

### 4-3-3 제작 세션

| 상태 | 관리 |
|---|---|
| 소유 기록 | 퍼널은 최대 한 편집 기록을 소유한다. requestId가 바뀌면 기존 삭제와 새 기록 저장을 함께 처리하고 실패하면 기존 유지 |
| 저장 기준 | 현재 레코드 후보의 JSON과 마지막 저장본을 비교해 미저장 상태 및 이탈 확인을 결정한다. 복원과 결과 승격은 다음 렌더의 기준을 맞춘다 |
| 저장 위치 | 회원 판정 완료 후 결정해 ref로 고정한다. 동의 판정 중 회원도 게스트도 아니면 진입을 미룬다 |
| 서버 세션 | 새 회원 세션, 서버 초안, draftId가 연결된 기기 기록. 서버에서 복원한 기록 자체는 기기 소유 기록으로 잡지 않는다 |
| 기기 세션 | 게스트와 서버 연결 없는 기기 초안. 기존 간편 초안은 일괄 서버 이관하지 않는다 |
| 생성 결과 | 결과와 해당 결과를 만든 요청을 함께 보관한다. 실패한 재생성 요청과 구분해 저장 및 완성 입력에 사용 |
| 서버 저장 성공 | 저장을 시작할 때의 기기 기록을 아직 소유한 경우에만 삭제한다. 충돌 덮어쓰기 성공도 동일 |
| 기기와 서버 병합 | 서버 version이 연결된 draftVersion 이하이면 서버 카드 숨김. 연결 없이 같은 ID이면 서버 쪽을 남김 |
| 일반 초안 이관 | 회원의 제작 탭 표시 때 화면마다 한 번 같은 ID로 옮긴다. 성공 또는 이미 존재하면 기기 기록 제거, 상한이면 보존 |
| 완료 기록 | createdStoryId를 확정해도 목록에서 해당 ID를 확인할 때까지 유지. 렌더에서 중복 숨김 뒤 Effect에서 그 요청만 정리 |

### 4-3-4 폼과 안내 상태

일반 제작은 현재 입력과 저장본, 접수한 입력의 스냅숏 키를 구분한다. 접수와 검토 상태는 비동기 흐름과 저장 판단이 같은 값을 사용한다. 수정은 서버 ID와 기존 이미지, 최초 요청 후보 baseline을 보관하고 미승인 제출본이 있으면 전체 재전송 상태를 유지한다.

접기 상태는 폼과 퍼널의 항목 ID별로 보관해 탭을 다시 그려도 유지한다. 검수 경로는 제출 당시 항목 ID에 대응하며 값이 제출한 값과 달라지면 그 칸의 사유를 제거한다.

장르 선택은 선택 ID, 대표 밖 칩 순서와 이전 직접 입력 원문을 보관한다. 화면과 새 요청은 카탈로그에 맞춰 정리하되 키워드 초안은 정리 전 값으로 저장해 카탈로그 도착만으로 미저장 판정이 바뀌지 않게 한다.

제작 안내는 기기에서 완료한 단계와 현재 화면이 받을 수 있는 단계가 맞을 때만 연다. 버튼으로 닫을 때 기록하며 화면 이탈만으로 완료하지 않는다.
