**9. 공개 목록은 keyset 커서와 실시간 집계를 쓴다**

| 항목 | 내용 |
|---|---|
| 날짜 | 미확인 |
| 근거 | 서버 코드, KNK-149, 정렬 추가는 KNK-1398 |
| 상태 | 채택. 인기순 추가는 10번 |
| 배경 | offset은 새 스토리가 끼어들 때 중복과 누락이 생긴다. 좋아요 수와 누적 턴 수를 컬럼으로 두면 좋아요와 턴마다 동기화 비용이 든다. |
| 채택 | 커서는 `정렬 접두:정렬값:public_id`를 Base64URL로 인코딩한 값이다. 디코딩 시 정렬을 검증한다. 2차 키는 내부 PK가 아니라 `public_id`다. 최신순 정렬값은 epoch nanos다. 좋아요 수와 누적 턴 수는 정렬과 커서 조건에서 같은 상관 서브쿼리로 집계하고 `REPEATABLE_READ`로 한 요청 안의 스냅샷을 맞춘다. |
| 대안 | 밀리초 정렬값. PostgreSQL `timestamptz`가 마이크로초를 담아 같은 밀리초의 뒤쪽 행이 페이지 경계에서 사라진다. 비정규화 컬럼. 어긋나면 카드 수치와 정렬이 달라진다. |
| 영향 | 공개 목록 인덱스는 두지 않았고 느려지면 그때 검토한다. |

**18. 화풍 카탈로그는 서버 DB가 관리한다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-12 |
| 근거 | KNK-1481 |
| 상태 | 채택 |
| 배경 | 간편 제작에서 인물 이미지와 표지의 화풍을 고르게 한다. 그릴 수 있는 화풍과 화면에 노출할 화풍의 관리 책임을 나눠 표시 문구와 순서를 배포 없이 바꿀 수 있어야 한다. |
| 채택 | 서버 DB의 `art_styles`를 카탈로그의 기준으로 두고 `code`를 AI 계약값인 문자열 PK로 쓴다. 활성 행만 노출 순서로 반환한다. 완성 요청의 `artStyle`은 누락이면 `ANIME`이다. 활성 코드만 허용한다. AI 컴파일 요청의 `art_style`로 그대로 전달한다. `NONE`은 이미지 생성을 생략하되 차감액은 같다. 선택한 화풍은 스토리에 저장하지 않는다. |
| 대안 | 서버 enum. 이름, 순서, 숨김을 바꿀 때마다 서버 배포가 필요해 기각. AI가 목록 제공. 거의 바뀌지 않는 목록 때문에 AI 장애가 제작 화면을 깨뜨려 기각. |
| 영향 | 신규 화풍은 AI 배포 뒤 행을 활성화하고 제거는 비활성화로 한다. 구버전 AI는 모르는 필드를 무시해 `ANIME`으로 그리므로 배포 순서 제약이 없다. 일반 제작은 범위 밖이다. |

**19. 작성 중 입력은 회원별 초안으로 서버에 보관한다**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-14 |
| 근거 | KNK-1641 |
| 상태 | 채택 |

| 영향 | 초안 API 4종과 등록, 완성, 재제출의 `draftId` 필드가 생겼다. 게스트 초안은 계속 클라이언트 로컬에 보관한다. 참조되지 않는 임시 업로드 이미지 정리는 범위 밖이다. |
