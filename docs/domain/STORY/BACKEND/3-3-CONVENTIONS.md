# 3-3 구현 컨벤션

이 문서는 STORY 도메인 코드를 작성하거나 수정할 때 반드시 지킬 규칙과 구현자가 선택할 수 있는 사항을 정한다.

트랜잭션과 잠금은 동시성에, 로그 이벤트 규칙은 관측에, 이름 토큰 치환은 처리 흐름에, 구현 위치는 AGENTS.md에 있다. ([5-2 동시성](5-2-CONCURRENCY.md), [5-4-5 구조화 로그 이벤트](5-4-OBSERVABILITY.md#5-4-5-구조화-로그-이벤트), [4-1-29 이름 토큰 치환](4-1-PIPELINES.md#4-1-29-이름-토큰-치환), [AGENTS.md](AGENTS.md))

<br>

### 3-3-1 이름과 용어

| 대상 | 규칙 |
|---|---|
| 패키지 | 도메인 패키지 아래에 API, 서비스, 저장, 모델, 전송 객체, AI 호출, 검수 접수, 이벤트를 나눔<br>검색과 이미지 저장소는 별도 패키지 |
| 모델 이름 | 테이블의 단수형 |
| 전송 객체 | 요청은 `Request`, 응답은 `Response`, 제작과 수정에서 공통으로 쓰는 입력은 `Input`을 접미사로 사용<br>와이어 필드는 camelCase<br>DB 컬럼은 snake_case |
| AI 응답 역직렬화 | 알 수 없는 필드는 무시함<br>AI가 필드를 추가해도 역직렬화가 실패하지 않도록 함 |
| 용어 | 용어집을 따름 |

<br>

### 3-3-2 계층 책임

| 계층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| API 계층 | 형식 검증, 요청자 식별, 인증 필수 경로의 인증 거절, 상태 코드 지정 | 비즈니스 판정, 저장 계층 호출 |
| 서비스 | 처리 순서 관리, 소유권과 읽기 권한 판정, 트랜잭션 경계, 이벤트 발행, 응답 직전 이름 토큰 치환 | HTTP 세부 규칙, 직렬화 |
| 저장 계층 | 쿼리<br>잠금이 필요한 조회 메서드는 이름에 잠금 여부 표시 | 비즈니스 판정 |
| 외부 호출 | 호출과 변환<br>AI 호출과 S3 업로드는 DB 트랜잭션 밖에서 수행 | 재시도 정책 결정 |

<br>

### 3-3-3 요청 검증과 오류

| 대상 | 규칙 |
|---|---|
| 개별 필드의 항목 수, 길이, 필수 여부 | 요청 객체의 필드에 애너테이션으로 선언 |
| 여러 필드를 조합하거나 값을 가공한 뒤 검증하는 규칙 | 요청 객체 안의 검증 메서드<br>예: 제공 특징과 직접 입력 특징의 합계 상한, 공백 제거 뒤 길이 |
| 장르 입력 검증, 기본 주인공 이름 검증, 이름 토큰 치환 | 항목별 로직을 한 곳에 두고 호출 |

<br>

### 3-3-4 이벤트와 비동기

| 대상 | 규칙 |
|---|---|
| 발행과 수신 | 검색 색인, 완성 푸시, 신고 알림은 애플리케이션 이벤트로 발행하고 리스너가 커밋 후 수신<br>리스너는 비동기 |
| 실패 | 리스너가 실패하면 로그만 남김<br>사용자 요청의 결과는 바꾸지 않음 |

<br>

### 3-3-5 테스트와 검증 도구

| 대상 | 규칙 |
|---|---|
| 작성 순서 | 동작을 바꾸는 작업은 실패하는 테스트를 먼저 작성 |
| 엔드포인트 변경 | 통합 테스트와 수동 호출 파일을 함께 갱신 |

<br>

### 3-3-6 구현자가 선택할 수 있는 것

| 선택 가능 | 조건 |
|---|---|
| 서비스 내부의 메서드 분할과 이름 | 없음 |
| 테스트 픽스처와 스텁의 구성 | 없음 |
| 조회 쿼리의 작성 방식 | 없음 |
| 로그 필드 추가 | 원문을 넣지 않음 |
