# 5-3 오류 처리

이 문서는 STORY 도메인의 응답 규칙, 앱 코드, 오류 분류, 복구 규칙, 재시도와 시간 한도, 전달 실패 처리, 오류 로그 기준을 정한다.

엔드포인트별 실패 조건과 응답 형식은 계약에, 흐름별 보상 처리는 처리 흐름에, 중단 요청의 회수는 동시성에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-2-1 생성 요청의 멱등과 회수](5-2-CONCURRENCY.md#5-2-1-생성-요청의-멱등과-회수))

<br>

### 5-3-1 응답 규칙

| 항목 | 규칙 |
|---|---|
| `code` | HTTP 상태 이름이 기본<br>사유를 구분해야 하는 곳만 앱 코드 |
| `message` | 사용자 안내 문구<br>스택트레이스와 내부 구현 정보는 포함하지 않음<br>500은 고정 안내 문구 사용 |
| `details` | 필드 검증 실패에 채움<br>서비스에서 판정한 400도 필드가 특정되면 `details`에 그 필드<br>직접 입력 장르는 `customGenreTags`, 기본 주인공 이름은 `protagonistName`, 장르는 원본 인덱스별 `genres[i]` |
| 비동기 검수 | 반려와 실패는 접수 응답 202를 나중에 오류로 바꾸지 않으며 제출본 상태로 조회 |
| 초안 버전 충돌 | `details`를 현재 상태 전달에 사용<br>`field`는 `version`과 `updatedAt` |

<br>

### 5-3-2 앱 코드

코드 문자열은 API 계약이므로 유지한다.

| 상태 | `code` | 의미 |
|---|---|---|
| 400 | `CUSTOM_GENRE_NOT_ALLOWED` | 새 `requestId`의 스토리라인 요청에 `customGenreTags` 값 존재 |
| 400 | `INVALID_GENRE` | 일반 제작과 수정에서 허용되지 않는 장르<br>`details`에 무효 원소의 `genres[i]` |
| 400 | `UPLOAD_NOT_FOUND` | 객체 키에 아직 파일이 없음 |
| 400 | `IMAGES_TOO_LARGE` | 검수 요청 예상 용량 초과 |
| 402 | `INSUFFICIENT_CREDIT` | 회원의 이프 부족, 완성 경로 |
| 402 | `GUEST_TRIAL_LIMIT_EXCEEDED` | 게스트 체험 한도 소진, 스토리라인 생성과 완성 |
| 403 | `CONSENT_REQUIRED` | 동의 게이트가 켜진 환경에서 미동의 회원의 허용 목록 밖 요청 |
| 400 | `DRAFT_PAYLOAD_TOO_LARGE` | 초안 payload 직렬화 크기 64KB 초과 |
| 400 | `DRAFT_LIMIT_EXCEEDED` | 회원의 6번째 신규 초안 |
| 409 | `DRAFT_VERSION_CONFLICT` | 초안 내용이 다른데 `baseVersion` 불일치<br>`details`에 현재 `version`과 `updatedAt` |
| 422 | `CONTENT_REJECTED` | AI가 입력 내용을 이유로 생성을 거절, 스토리라인 생성과 완성 |

<br>

### 5-3-3 오류 분류

| 오류 | 발생 위치 | 처리 |
|---|---|---|
| 입력 오류 | API 계층의 선언적 검증과 본문 파싱 | 400으로 변환<br>선언적 검증은 필드별 `details`, 본문 파싱 실패는 빈 배열 |
| 상태 코드 오류 | 각 서비스의 판정 | 400, 403, 404, 409, 502, 503<br>`code`는 상태 이름 |
| 앱 코드 오류 | 같은 상태에서 사유를 나눠야 하는 서비스 판정 | `code`에 앱 코드를 실음 |
| 잔액 부족 | PAYMENT 도메인 | 완성 경로가 잡아 402 `INSUFFICIENT_CREDIT`으로 변환 |
| 게스트 한도 소진 | PAYMENT 도메인 | 스토리라인 생성과 완성이 잡아 402 `GUEST_TRIAL_LIMIT_EXCEEDED`로 변환 |
| AI 호출 오류 | AI 호출 구성 요소<br>연결 실패, 시간 초과, 내용 거절이 아닌 오류 응답, 빈 본문 | 간편 제작 서비스가 원인을 보존한 채 502로 변환 |
| AI 내용 거절 | AI 호출 구성 요소<br>AI 서버의 422 응답 중 `detail`이 문자열인 응답<br>`detail`이 배열인 스키마 위반은 AI 호출 오류 | 간편 제작 서비스가 원인을 보존한 채 422 `CONTENT_REJECTED`로 변환<br>`message`는 `detail` 문구 그대로 |
| 검색과 이미지 저장소 오류 | 검색 서비스, 이미지 서비스 | 미설정과 장애를 503으로 변환<br>외부 오류 본문은 응답에 싣지 않음 |
| 예상하지 못한 오류 | 어디서든 | 전역 핸들러가 500 고정 문구로 응답하고 Sentry 전송 |

<br>

### 5-3-4 오류별 처리

- 환불은 차감 시도별 멱등 키를 써서 같은 간편 제작 진행을 여러 번 시도해도 각 차감과 해당 환불이 일대일로 연결된다.
- 간편 제작의 요청 행은 콜백 실행 중 예외가 발생하면 `FAILED`로 바꾸고 예외를 다시 던진다. 재요청은 `FAILED` 행을 재실행한다.
- 승인 뒤 적용 중 실패하면 제출본을 `FAILED`로 표시하고 스토리는 바꾸지 않는다. 결과는 제출본 조회로 확인한다.
- 지표 기록 실패는 격리해 성공한 생성 결과가 500으로 바뀌지 않도록 한다.

<br>

### 5-3-5 재시도와 시간 한도

**1. 재시도**

- 백엔드는 AI 호출을 재시도하지 않는다. AI 서버 내부의 보완 호출 횟수는 `meta.retry_count`로 받는다.
- 호출 실패 시 다른 모델이나 AI 서버로 전환하지 않는다. 스텁 클라이언트는 환경 설정이며 폴백이 아니다.
- 이미지 업로드는 재시도하지 않고 해당 이미지만 제외한다.
- 요청 재실행은 클라이언트가 같은 `requestId`로 다시 보낼 때만 일어난다.

| 복구 방식 | 대상 | 한도 |
|---|---|---|
| 같은 `requestId` 재요청 | `FAILED` 요청 행 | 횟수 제한 없음<br>매번 차감과 환불을 쌍으로 기록 |
| `PENDING` 회수 재실행 | 회수 기준 시간이 지난 `PENDING` 요청 행 | 재요청 시 1회 재실행, 저장된 결과가 있으면 재구성 |

<br>

**2. 시간 한도**

| 단계 | 제한 시간 | 적용 범위 |
|---|---|---|
| AI 연결 | 5초 | 스토리라인과 컴파일 공통 |
| 스토리라인 호출 | 읽기 90초 | 초과 시 502 |
| 컴파일 호출 | 읽기 180초 | 초과 시 502 |
| 이미지 단계 | 30초 | 컴파일 응답의 인물 이미지와 표지 업로드 합계<br>개별 저장소 호출은 10초<br>제한 시간 소진 시 남은 이미지 제외 |
| `PENDING` 회수 기준 | 300초 | 설정값 |

<br>

### 5-3-6 최종 실패와 부분 완료

- 이미지 실패는 부분 완료다. 스토리는 정상 저장된다. 실패한 이미지에 대응하는 인물의 `imageUrl` 또는 표지만 `null`이다.
- 응답 쓰기 실패는 서비스 밖에서 일어나므로 성공 경로로 정산된다.

| 결과 | 처리 |
|---|---|
| 최종 실패 | 이프 환불과 게스트 카운터 복원, 요청 행 `FAILED`<br>AI 내용 거절도 같음 |
| 부분 완료 | 누락 이미지를 로그로 남기고 스토리 저장 |

<br>

### 5-3-7 전달 실패 처리

백엔드는 간편 제작 결과를 요청 행에 저장하므로 응답 전달에 실패해도 결과를 되찾을 수 있다. 등록과 수정은 접수 즉시 제출본이 생기므로 제출본 조회로 확인한다.

| 상황 | 백엔드 | 클라이언트와의 경계 |
|---|---|---|
| AI 대기 중 클라이언트 연결 종료 | 처리를 계속해 결과를 요청 행에 저장 | 클라이언트는 복구 조회로 결과 수신 |
| 생성 완료 후 응답 쓰기 실패 | 성공으로 정산, 요청 행 `COMPLETED` | 복구 조회의 `result`가 원래 응답 |
| 같은 `requestId` 중복 수신 | 멱등 규칙에 따라 재전송 또는 409 | 중복 실행과 중복 차감 없음 |
| 등록과 수정의 응답 쓰기 실패 | 제출본은 이미 접수됨 | 제출본 조회로 상태 확인<br>등록을 다시 요청하면 새 제출본 생성<br>수정은 대기 중인 제출본이 있으면 409 |

<br>

### 5-3-8 로그와 Sentry

| 대상 | 규칙 |
|---|---|
| 5xx | 스택트레이스와 함께 ERROR로 기록 |
| 예상 가능한 4xx | Sentry 미전송<br>원인 예외가 있으면 클래스와 메시지를 한 줄로 WARN에 기록<br>원인 예외가 없으면 DEBUG에 기록 |
| 매핑되지 않은 경로 | 404로 처리해 500 오류와 불필요한 Sentry 보고 방지 |
