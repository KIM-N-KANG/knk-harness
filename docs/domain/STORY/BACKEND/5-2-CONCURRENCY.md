# 5-2 동시성

이 문서는 STORY 도메인의 동시 요청 처리 규칙을 정한다. 생성 요청의 멱등성과 중단 요청 회수, 간편 제작 완료의 경쟁 조건, 스토리 행 잠금, 유니크 제약 위반, 집계와 커서, 이미지 업로드 실패 시 보상 처리를 다룬다.

흐름별 단계와 트랜잭션 경계는 처리 흐름에, 회수 기준 시간은 오류 처리에 있다. ([4-1 처리 흐름](4-1-PIPELINES.md), [5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도))

<br>

### 5-2-1 생성 요청의 멱등과 회수

같은 `requestId`로 요청이 동시에 들어오면 하나만 실행한다.

| 상황 | 처리 |
|---|---|
| 동시 삽입 | 요청 행 삽입과 기존 행 상태 확인을 각각 독립 트랜잭션에서 수행<br>삽입에 실패한 요청은 유니크 위반으로 삽입 트랜잭션만 롤백<br>별도 트랜잭션에서 먼저 삽입된 행을 비관적 잠금으로 다시 읽어 상태 확인 |
| `FAILED` 재실행 | 같은 잠금으로 직렬화<br>두 요청의 동시 통과와 중복 실행 없음 |
| `PENDING` | 진행 중으로 거절<br>`updated_at`이 회수 기준 시간보다 오래됐으면 실행 중인 프로세스가 중단된 것으로 보고 회수해 재실행<br>회수 여부는 콜백에 넘겨 완성 경로가 저장된 스토리를 재구성할지 판단 |
| `COMPLETED` JSON 비호환 | 저장 JSON을 현재 응답 타입으로 읽지 못하면 한 호출만 `PENDING`으로 바꿔 재생성 권한 확보<br>그 사이 다른 호출이 결과를 갱신했으면 최신 결과 반환 |
| 저장 커밋 후 완료 표시 전 중단 | 요청 행의 상태 갱신은 생성 결과 저장과 별도 트랜잭션이므로 행이 결과 없이 `PENDING`으로 남음<br>회수 시 스토리라인 경로는 `storyline_request_id`로 진행을, 완성 경로는 `creation_request_id`가 일치하는 `STORY_CREATED` 진행을 찾아 응답 재구성<br>AI 재호출과 과금 없음 |

<br>

### 5-2-2 간편 제작 완료의 경쟁 조건

같은 간편 제작 진행에 서로 다른 `requestId`의 완성 요청이 동시에 들어올 수 있다.

| 단계 | 처리 |
|---|---|
| 잠금 없는 사전 검사 | 둘 다 `STORYLINES_GENERATED`를 보고 컴파일 진입 |
| 저장 트랜잭션 | 진행 행을 비관적 쓰기 잠금으로 다시 읽고 상태 재판정<br>나중에 잠금을 획득한 요청은 충돌로 거절하고 롤백, 이프 환불, 업로드한 이미지 삭제 |

<br>

### 5-2-3 스토리 행 잠금

다음 경로는 공개 식별자 기준의 쓰기 잠금 조회로 스토리 행을 잠근다. 수정과 이미지 삭제가 같은 잠금을 쓰므로 두 경로가 스토리 단위로 직렬화된다. 스냅샷은 잠금을 유지한 상태에서 하위 데이터 교체를 마친 뒤 갱신한다. 승인 적용의 잠금 순서는 회원, 스토리, 제출본, 인물이다. 신규 등록은 회원과 제출본을 잠근 뒤 스토리를 만든다.

| 경로 | 막는 경쟁 조건 |
|---|---|
| 삭제 | 소유권 검사와 `deleted_at` 기록 사이에 게스트 이관이 `user_id`를 채우는 경쟁 조건 |
| 승인된 수정 | 하위 컬렉션 교체와 시작 설정 동기화의 유니크 충돌<br>동시 수정을 스토리 단위로 직렬화 |
| 공개 범위 단독 변경 | 위와 같음 |
| 표지 삭제, 인물 이미지 삭제 | 동시에 커밋된 비공개 전환을 반영하지 못한 채 이전 공개 판정으로 스냅샷을 덮어쓰는 경쟁 조건 |

<br>

### 5-2-4 유니크 위반 처리

| 대상 | 처리 |
|---|---|
| 좋아요, 신고 | `(user_id, story_id)` 유니크 제약으로 멱등성 보장<br>사전 조회 없이 삽입하고 유니크 제약 위반을 처리해 성공으로 응답<br>삽입은 짧은 독립 트랜잭션에서 수행<br>유니크 위반은 해당 트랜잭션 밖에서 처리 |
| 직접 입력 특징 태그 | 마스터 행은 독립 트랜잭션에서 생성<br>동시 생성으로 유니크 충돌이 나면 기존 행을 다시 조회<br>외부 트랜잭션이 실패해도 공용 태그의 마스터 행은 유지 |
| 엔딩 도달 집계 | CHAT 도메인이 독립 트랜잭션에서 유니크 위반을 성공 처리 |
| 초안 신규 저장 | 회원 행을 잠가 개수 검사와 같은 ID의 버전 판정을 직렬화<br>삽입만 허용해 다른 회원이 같은 UUID를 먼저 넣었으면 덮어쓰지 않고 없는 것으로 응답 |

<br>

### 5-2-5 집계와 커서

| 대상 | 규칙 |
|---|---|
| 공개 목록 트랜잭션 | `REPEATABLE_READ` 읽기 전용<br>인기순, 좋아요순, 채팅순은 1차 키가 집계값이므로 정렬 쿼리와 카드 매핑의 일괄 집계가 서로 다른 시점의 데이터를 읽으면 커서 값과 정렬이 어긋남<br>같은 트랜잭션의 스냅샷을 공유해 한 요청 안의 중복 노출 방지 |
| 최신순 커서 | 키셋 페이지네이션을 사용하므로 페이지 사이에 새 스토리가 추가되어도 중복과 누락 없음 |
| 집계 정렬 커서 | 페이지 요청 사이에 집계값이 바뀌면 다음 페이지 조회 시 중복과 누락 가능<br>인기순 가중치 변경 전 커서가 한 번 어긋날 수 있음을 수용 |
| 검색 커서 | 색인 변경으로 생기는 중복과 누락 허용 |

<br>

### 5-2-6 이미지 업로드와 보상

| 상황 | 처리 |
|---|---|
| 업로드 시점 | 인물 이미지와 표지는 저장 트랜잭션보다 먼저 S3에 업로드<br>저장에 실패하면 참조되지 않는 객체가 남으므로 보상 삭제 |
| 보상 삭제 전 확인 | 트랜잭션 밖에서 스토리 존재 확인<br>커밋 후 응답만 유실된 경우 스토리가 그 객체를 가리키므로 삭제하지 않음<br>확인이 실패해도 삭제하지 않음 |
| 제한 시간 소진 | 이미지 단계의 제한 시간을 소진하면 삭제도 건너뜀<br>객체 정리로 요청 처리 시간이 늘어나지 않도록 제한 |
