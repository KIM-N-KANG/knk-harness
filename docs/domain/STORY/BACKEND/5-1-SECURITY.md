# 5-1 보안

이 문서는 STORY 도메인 백엔드의 인증과 권한 판정, 입력과 업로드 검증, 식별자와 개인정보 취급 규칙, 수용한 한계를 정한다.

경로별 허용 규칙과 실패 응답은 계약에, 로그와 지표에 싣지 않는 데이터는 관측에 있다. ([4-2-1 공통 규칙과 헤더](4-2-CONTRACT.md#4-2-1-공통-규칙과-헤더), [5-4-10 수집 조건과 실패 처리](5-4-OBSERVABILITY.md#5-4-10-수집-조건과-실패-처리))

<br>

### 5-1-1 인증 수준

| 항목 | 처리 |
|---|---|
| 인증 불필요 경로 | 토큰 검사를 건너뜀<br>클라이언트가 자동으로 붙인 만료 토큰이 로그아웃 상태의 화면 동작을 방해하지 않게 함 |
| 인증 선택 경로 | 유효한 토큰은 회원으로 처리<br>토큰이 없거나 무효이면 익명으로 처리 |

<br>

### 5-1-2 소유권과 읽기 판정

| 판정 | 규칙 |
|---|---|
| 판정 순서 | 스토리 존재 여부를 먼저 확인한 뒤 소유권 판정 |
| 읽기 위반 | 부재, 삭제, 형식 오류와 같은 응답으로 처리해 비공개 스토리의 존재를 드러내지 않음<br>일괄 조회는 오류 없이 제외 |
| 소유권 위반 | 존재하는 스토리에 대한 소유자 전용 요청은 소유자가 아니면 거절 |
| 게스트 소유 스토리 | 익명 요청만 삭제 가능<br>게스트의 등록과 수정은 허용하지 않음<br>회원과 게스트 사이의 교차 접근은 양방향으로 거절 |
| 복구 조회 | 회원 요청은 회원 일치, 게스트 요청은 디바이스 해시 일치<br>소유권이 일치하지 않으면 존재하지 않는 요청과 같은 응답 반환 |
| 게스트 스토리의 노출 | 상세 조회는 가능하지만 목록과 검색에는 싣지 않음 |
| 게스트의 공개 지정 | 거절<br>현재는 게스트가 등록과 수정을 할 수 없어 레거시 데이터에만 해당 |

<br>

### 5-1-3 계정 상태와 동의

| 상태 | 처리 |
|---|---|
| 정지 계정 `SUSPENDED` | 쓰기와 소모 요청은 권한 없음으로 거절<br>완성, 좋아요, 신고, presign, 이미지 삭제는 처리 시작 시 계정 상태 검사<br>초안 API는 조회도 거절<br>정지 사유는 노출하지 않음 |
| 탈퇴 계정 `DELETED` | 유효한 토큰이 남아 있어도 인증 단계에서 거절 |
| 게스트 | 계정 상태 판정의 대상 아님 |
| 미동의 회원 | 동의 게이트가 켜진 환경에서 현행 필수 동의가 없으면 거절<br>`GET /stories/simple/tags`, `GET /stories/genres`, `GET /stories/art-styles`는 허용 목록 |

<br>

### 5-1-4 입력 검증

| 대상 | 규칙 |
|---|---|
| 개수, 길이, 필수, 형식 | 요청 객체에 선언한 제약으로 검증하고 위반 시 거절 |
| 제공 태그 ID | 존재, 활성, 제공 여부를 확인하고 하나라도 무효면 거절 |
| 장르 이름 | 일반 제작과 수정은 활성 제공 장르의 정식 이름과 정규화 비교<br>별칭, 비활성, 존재하지 않는 장르는 거절<br>수정은 현재 스토리에 반영된 기존 장르만 예외 |
| 직접 입력 장르 | 간편 제작의 `customGenreTags`에 값이 있으면 거절 |
| 이름 식별자 | 인물 이름은 스토리 안, 엔딩 이름은 시작 설정 안, 주요 사건 이름은 스토리 안, 이미지 이름은 인물 안에서 유일<br>요청 안의 중복은 거절 |
| 기본 주인공 이름 | 앞뒤 공백 제거 후 1~30자<br>저장할 본문에 `{username}`이 있는데 이름이 없으면 거절 |
| 인물 소개 | 앞뒤 공백 제거 후 150자 이하<br>CR, LF, 탭 금지 |
| 화풍 코드 | 누락과 `null`은 활성 여부를 확인하지 않고 `ANIME`<br>값이 있으면 활성 코드가 아닐 때 거절 |
| 공개 범위 | 발행되지 않은 스토리의 공개 지정은 거절<br>값이 같으면 통과 |
| AI 응답 | 신뢰 경계 밖의 값<br>컬럼 길이 상한에 맞춰 이름 토큰이 잘리지 않도록 텍스트 길이 제한<br>사건이나 엔딩 이름이 중복되거나 이름 토큰에 대응하는 주인공 이름이 없으면 실패로 처리<br>엔딩 빈 배열은 정상<br>이름도 토큰도 없으면 이름은 `null`<br>인물은 이름 정리와 중복 제거 뒤 5명까지<br>인물 소개는 이름으로 연결<br>인물 이름에서 파일명에 사용할 수 없는 문자를 제거해 객체 키 생성 |

<br>

### 5-1-5 업로드 검증

| 대상 | 규칙 |
|---|---|
| 객체 키 | 서버가 정함<br>클라이언트가 정하면 다른 사용자의 스토리 경로를 덮어쓸 수 있음 |
| 서명 | `Content-Type`과 `Content-Length` 고정<br>10분 뒤 만료 |
| 접두어 확인 | 스토리에 이미지를 연결할 때 먼저 확인<br>해당 스토리의 업로드 접두어 또는 요청자의 임시 업로드 접두어로 시작하지 않으면 거절<br>접두어 검증에 실패하면 HEAD를 호출하지 않음<br>다른 사용자의 객체 존재 여부를 HEAD로 확인하지 못하도록 차단 |
| HEAD 확인 | 객체 존재, 5MB 이하, 허용 형식 3종 |
| 승인 저장 | 원본 대신 검수 직전 만든 복사본 URL 저장<br>원본 객체를 다시 업로드해도 승인된 이미지가 바뀌지 않음 |
| 초안의 이미지 키 | presign이 발급하는 형식 전체와 일치해야 함<br>UUID는 소문자<br>`.`, `..`, 빈 세그먼트, 백슬래시, `%`, `?`, `#`가 있는 경로 변형은 거절<br>요청자의 임시 업로드 접두어 아래만 허용하고 객체 존재는 확인하지 않음 |
| 저장소 미설정 | presign을 생략하지 않고 실패로 응답 |

<br>

### 5-1-6 식별자와 개인정보

| 대상 | 규칙 |
|---|---|
| 외부 식별자 | 무작위 공개 UUID라 추측과 열거가 어려움<br>자동 증가 PK는 응답, 로그, 분석 프로퍼티에 싣지 않음<br>형식 오류, 부재, 삭제, 읽기 불가를 같은 응답으로 처리해 존재 여부를 드러내지 않음 |
| 카탈로그 예외 | 장르, 태그, 로어북, 스토리라인 ID는 정수를 그대로 노출<br>정수 식별자 노출은 소유권 검사 면제를 의미하지 않음<br>스토리라인 평가에는 간편 제작 진행의 소유권 규칙 적용 |
| 디바이스 ID | `X-Manyak-Device-Id` 원문은 저장하지 않음<br>해시로 바꿔 MDC와 생성 요청 행에 남기고 AI 서버에는 해시만 전달 |
| 작성자 | 카드의 `author.id`는 항상 `null` |
| 초안 식별자 | 클라이언트가 만든 UUID를 그대로 사용<br>타인의 ID와 형식 오류는 같은 응답으로 처리 |
| 검수 전달 | 검수 입력에는 토큰 원문과 이름 토큰이 포함되지 않은 기본 주인공 이름을 보내고 페르소나는 보내지 않음 |

<br>

### 5-1-7 수용한 한계

| 한계 | 수용 이유 |
|---|---|
| 게스트끼리 UUID를 알면 다른 게스트의 스토리를 읽거나 삭제할 수 있음 | 콘텐츠에 디바이스 식별자를 저장하면 개인정보 취급 범위를 벗어남<br>차단할 수 있는 게스트와 회원 간 교차 접근만 양방향으로 막음 |
| 디바이스 헤더를 바꾸거나 기기를 바꿔 체험 한도를 우회할 수 있음 | 디바이스 식별자 외에 게스트를 구분할 수단이 없음<br>우회 징후는 호출량과 카운터 키의 증가 추이로 확인 |
| 미인증 쓰기 경로에 요청량 제한이 없음 | 현재 등록량에서 이득이 운영 비용보다 작음 |
