# 7-1 오류 처리

오류 유형별로 처리 위치, 복구 한도와 최종 출력을 정한다. 같은 오류를 여러 계층에서 중복 처리하지 않도록 SDK, AI 서버와 백엔드의 책임을 구분한다.

생성과 보완 과정은 AI 실행 문서, 구성 요소의 책임과 데이터 변환은 소프트웨어 구현 문서를 따른다. ([6-1 AI 실행](6-1-AI-EXECUTION.md), [6-2 소프트웨어 구현](6-2-SOFTWARE-IMPLEMENTATION.md))

<br>

### 7-1-1 오류 분류

| 오류 | 구분 기준 | 처리 원칙 |
|---|---|---|
| 입력 오류 | 요청 스키마 위반 또는 인물 이름 중복 | 모델 호출 전에 거부 |
| 설정 오류 | 미등록 모델, API 키 누락 또는 잘못된 호출 설정 | 공급자 장애와 구분하고 생성 재시도로 복구하지 않음 |
| 텍스트 전송 오류 | 모델 호출의 시간 초과, 호출량 제한, 요청 거부 또는 연결 실패 | 공급자 어댑터에서 공통 오류로 변환 <br> 진단에 필요한 오류 메시지, 공급자와 모델 정보 유지 |
| 텍스트 출력 오류 | 빈 본문, JSON 파싱 실패 또는 출력 형식 위반 | 전송 오류와 구분하고 태스크별 재생성과 보완 규칙 적용 |
| 내용 거절 | 공급자의 안전 필터가 생성을 중단(`finish_reason`이 `safety`)했거나, 본문이 JSON 객체로 시작하지 않는 평문 | 출력 오류보다 먼저 판정 <br> 같은 입력은 다시 거절되므로 재생성과 보완 없이 종료 |
| 이미지 생성 오류 | 이미지 호출 실패, 빈 데이터 또는 디코딩 실패 | 시간 초과, 호출량 제한과 요청 거부를 구분 <br> 나머지는 일반 생성 실패로 처리 |
| 예상하지 못한 오류 | 코드 결함 등 위 분류로 처리하지 않은 예외 | 원래 예외 유지 <br> 공급자 오류나 출력 형식 오류로 바꾸지 않음 <br> 이미지 결과로의 변환은 스토리 서비스 경계에서만 수행 |

<br>

### 7-1-2 오류별 처리

- 공급자 어댑터는 시간 초과를 일반 연결 실패에 포함하지 않고 별도로 분류한다.
- 텍스트 공급자의 400은 요청 거부, 429는 호출량 제한으로 분류한다. 401, 403, 404, 422와 5xx는 공급자 연동 오류로 분류한다.
- 요청 취소는 상위 호출로 전파한다. 이미지 생성 실패 객체로 바꾸지 않는다. 백엔드 연결 종료에 따른 동작은 전달 실패 처리에서 구분한다. ([7-1-6 전달 실패 처리](#7-1-6-전달-실패-처리))

| 오류 조건 | 적용 대상 | 담당 계층 | 복구 | 최종 출력 |
|---|---|---|---|---|
| 서버 시작 시 모델, 키 또는 템플릿 설정 오류 | 공통 | 시작 검사와 템플릿 로딩 | 설정 수정 후 재배포 | 서버 시작 실패 |
| 입력 스키마 위반, 이름 중복 | 스토리라인, 컴파일 | 입력 검증과 API 응답 계층 | 백엔드가 입력 수정 | 422 |
| 모델 시간 초과, 호출량 제한, 연결 실패 등 | 스토리라인, 컴파일 | 공급자 어댑터에서 분류, 텍스트 생성 계층에서 실패 응답으로 변환 | SDK 정책에 따른 재시도 | 복구 실패 시 502 |
| 공급자가 입력을 거부(400) | 스토리라인, 컴파일 | 공급자 어댑터에서 분류, 텍스트 생성 계층에서 실패 응답으로 변환 | 없음 | 502 |
| 내용 거절 | 스토리라인, 컴파일 | 텍스트 생성 계층에서 판정하고 실패 응답으로 변환 | 없음 | 422 |
| 호출 중 설정 오류 | 스토리라인, 컴파일 | 공통 LLM 호출 모듈 | 없음. 공급자 실패로 변환하지 않음 | 500 |
| JSON 파싱 실패 또는 후보 형식 위반 | 스토리라인 | 텍스트 생성과 후보 검증 | 전체 재생성 | 복구 시 200, 한도 소진 시 502 |
| 이름을 입력한 주변 인물 누락 | 스토리라인 | 스토리 서비스의 후보 검사와 보완 | 해당 후보만 보완 | 누락이 남아도 형식이 유효한 현재 결과로 200, 경고 기록 |
| 최초 출력의 JSON 파싱 실패 | 컴파일 | 텍스트 생성과 검증 | 없음 | 502 |
| 필수 블록 또는 인물 필드 누락 | 컴파일 | 스토리 서비스의 명세 검사와 병합 | 부분 보완 | 복구 시 200, 필수 내용이 여전히 비어 있으면 502 |
| 보완 후에도 엔딩 불완전 | 컴파일 | 스토리 서비스의 명세 정리 | 빈 배열로 대체. 추가 호출 없음 | 200, 엔딩 빈 배열 |
| 출력 모델로 변환 실패 | 컴파일 | 명세 검증과 출력 변환 | 없음 | 502 |
| 보완 호출의 전송 오류 또는 유효하지 않은 출력 | 스토리라인, 컴파일 | 텍스트 생성과 스토리 서비스의 보완 처리 | 추가 보완 없이 전체 실패 | 502 |
| 인물 외형 부족 | 인물 이미지 | 인물별 이미지 생성 | 호출 생략 | 200, 해당 이미지 `appearance_missing` |
| 이미지 모델 호출 실패 | 인물 이미지, 썸네일 | 이미지 생성 모듈에서 실패 전달, 스토리 서비스에서 이미지 오류 출력으로 변환 | SDK 정책에 따른 재시도 | 200, 해당 이미지 `error` |
| 이미지 로직의 예상하지 못한 예외 | 인물 이미지, 썸네일 | 이미지 생성 모듈에서 전파, 스토리 서비스에서 보고와 부분 실패 변환 | 인물 이미지 묶음은 미완료 호출도 취소 | 200, 인물 이미지 빈 배열 또는 썸네일 `generation_failed` |
| 관측 기록 전송 실패 | 공통 | 공통 관측 모듈 | 별도 복구 없음 | 생성 결과에 영향 없음 |
| 처리하지 않은 내부 예외 | 공통 | 오류 발생 계층에서 전파, API 응답 계층에서 종료 | 없음 | 500 |

### 7-1-3 재시도와 시간 한도

**1. 재시도와 보완 횟수**

- 폴백 모델이 없으므로 다른 모델로 바꿔 다시 호출하지 않는다. ([6-1 AI 실행](6-1-AI-EXECUTION.md))
- 서비스는 전송 오류가 난 요청을 다시 호출하지 않는다. SDK 재시도로도 복구하지 못하면 요청은 실패한다.
- 서비스는 재시도 사이에 별도 대기 시간을 두지 않는다. 대기는 SDK의 기본 동작에 맡긴다.
- 큐 없이 동기 요청으로 처리하므로 메시지를 다시 꺼내 처리하지 않는다.

| 복구 방식 | 대상 | 한도 | 서비스 재호출 횟수 포함 여부 |
|---|---|---|---|
| OpenAI와 Anthropic SDK 자동 재시도 | 텍스트 모델 전송 오류 | 최대 2회 | 포함하지 않음 |
| Google SDK 자동 재시도 | 텍스트 모델 전송 오류 | 서비스에서 별도 횟수를 지정하지 않음 | 포함하지 않음 |
| 스토리라인 전체 재생성 | 형식이 유효하지 않은 모델 응답 | 최대 2회 | 포함 |
| 스토리라인 부분 보완 | 이름을 입력한 주변 인물이 빠진 후보 | 최대 2회 | 포함 |
| 컴파일 부분 보완 | 필수 블록, 엔딩 또는 인물 필드 누락 | 최대 2회 | 포함 |
| 불완전한 엔딩 대체 | 보완 뒤에도 엔딩이 불완전함 | 추가 호출 없음 | 포함하지 않음 |
| 이미지 SDK 자동 재시도 | 이미지 모델 전송 오류 | 최대 2회 | 포함하지 않음 |
| 이미지 실패 처리 | 이미지 생성 실패 | 서비스의 별도 재호출 없음 | 포함하지 않음 |

<br>

**2. 시간과 호출 한도**

- 호출 횟수는 AI 서버의 호출만 세며 SDK 재시도는 제외한다.
- 제한 시간은 SDK의 시도마다 적용되므로 재시도하면 총시간은 더 길어진다.
- 백엔드가 기다리기를 끝내도 AI 서버는 생성을 계속할 수 있다.

| 단계 | 제한 시간 | 적용 범위 |
|---|---|---|
| 백엔드의 스토리라인 응답 대기 | 90초 | 스토리라인 요청 전체 |
| 백엔드의 컴파일 응답 대기 | 180초 | 컴파일 요청 전체 |
| 스토리라인 최초 생성과 형식 재생성 | 90초 | 최초 생성과 형식 재생성에 함께 적용 <br> 60초가 지나면 새 형식 재생성을 시작하지 않음 |
| 스토리라인 인물 누락 보완 | 호출마다 90초 | 후보 부분 보완 최대 2회 |
| 컴파일 최초 생성 | 90초 | 최초 모델 호출 |
| 컴파일 부분 보완 | 호출마다 90초 | 누락 부분 보완 최대 2회 |
| 이미지 생성 | 호출마다 60초 | 인물 이미지와 썸네일의 각 생성 호출 |

<br>

| 요청 | 텍스트 호출 | 이미지 호출 |
|---|---|---|
| 스토리라인 | 최초 1회, 전체 재생성 2회, 인물 보완 2회로 최대 5회 | 없음 |
| 컴파일 | 최초 1회, 부분 보완 2회로 최대 3회 | 인물 이미지 최대 5장과 썸네일 1장 |

### 7-1-4 최종 실패와 부분 완료

- 빠진 필수 내용을 임의로 채워 정상 결과로 반환하지 않는다.
- 컴파일에서 허용한 예외는 두 가지다. 엔딩은 빈 배열로 반환하고 이미지 실패는 200 응답의 `error`로 전달한다.
- 공급자가 요청을 거부했거나 내용을 거절했다면 같은 입력으로 다시 요청해도 거부될 수 있다.

| 주체 | 하는 일 |
|---|---|
| AI 서버 | 내용 거절 시 422, 모델 호출이나 출력 검증의 최종 실패 시 502와 정해진 메시지 출력 |
| 백엔드 | 자동 재호출 안 함 <br> 생성 실패 기록 및 사용자 오류 안내 <br> 내용 거절은 입력 수위를 낮추라는 안내로 구분 <br> 회원의 컴파일 실패 시 지불한 이프 환불 |
| 사용자 | 재요청 <br> 같은 요청 식별자 사용 시 백엔드가 실패한 요청 재실행 |

<br>

### 7-1-5 실패 출력

| 상태 | 조건 | 본문 | 설명 |
|---|---|---|---|
| 422 | 요청 스키마 위반 또는 인물 이름 중복 | `detail` 배열<br>항목별 `type`, `loc`, `msg` | 백엔드가 입력 수정 후 재호출. `detail`은 사용자에게 직접 노출하지 않음 |
| 422 | 내용 거절 | `detail` 문자열<br>아래 422 메시지 | 백엔드는 `detail`의 타입으로 스키마 위반과 구분<br>사용자에게 표시 가능한 한국어 문구만 사용 |
| 500 | 요청 처리 중 설정 오류 또는 처리하지 않은 내부 예외 | 공통 JSON 형식을 보장하지 않음 | AI 보완 없이 종료, 담당자가 오류 확인<br>백엔드는 본문을 파싱하거나 직접 노출하지 않고 자체 오류 안내 |
| 502 | 모델 호출 실패<br>보완 후에도 형식이나 필수 항목 위반 | `detail` 문자열<br>아래 메시지 중 하나 | 사용자에게 표시 가능한 한국어 문구만 사용<br>공급자 오류 원문 제외 |

| 422 메시지 | 뜻 | 사용자 재요청 |
|---|---|---|
| `입력 내용이 안전 정책에 맞지 않아 생성할 수 없습니다.` | 공급자 필터 또는 모델이 내용을 이유로 거절 | 같은 입력은 불필요, 수위를 낮춰 재요청 |

| 502 메시지 | 뜻 | 사용자 재요청 |
|---|---|---|
| `LLM 응답 시간이 초과되었습니다.` | 모델이 시간 안에 응답하지 않음 | 가능 |
| `LLM 요청이 일시적으로 제한되었습니다.` | 공급자가 호출량을 제한 | 잠시 뒤 가능 |
| `LLM 요청이 거부되었습니다.` | 공급자가 요청을 거부 | 같은 입력은 불필요 |
| `LLM 연동 중 오류가 발생했습니다.` | 공급자 연결 또는 서버 오류 | 가능 |
| `LLM이 올바른 형식의 응답을 반환하지 않았습니다.` | 보완 후에도 형식이나 필수 항목 위반 | 가능 |
| `재호출 후에도 컴파일 결과에 필수 필드가 비어 있습니다.` | 컴파일 보완 후에도 필수 값이 비어 있음 | 가능 |
| `컴파일 결과가 스토리 명세 형식과 맞지 않습니다.` | 컴파일 결과를 응답 형식으로 바꿀 수 없음 | 가능 |

<br>

이미지 실패는 HTTP 200과 `error` 코드로 전달하며 공급자 오류 원문은 제외한다.

- 인물 이미지: 모두 실패해도 인물별 오류 항목을 유지한다. 생성 로직 전체의 예외일 때만 `character_images`를 빈 배열로 출력한다.
- 썸네일: `thumbnail_image` 객체를 유지하고 `error`를 채운다.

| 이미지 `error` | 뜻 |
|---|---|
| `appearance_missing` | 외형 부족으로 호출하지 않음 |
| `timeout` | 이미지 모델 응답 시간 초과 |
| `rate_limited` | 공급자가 호출량을 제한(429) |
| `rejected` | 공급자가 요청을 거부(400) |
| `generation_failed` | 그 밖의 SDK 오류, 빈 응답 또는 Base64 디코딩 실패 |

### 7-1-6 전달 실패 처리

AI 서버는 상태를 저장하지 않으므로 수신 확인과 재전송을 하지 않는다. 중복 방지, 결과 저장과 재요청은 백엔드가 맡는다. ([5-5 요청 헤더와 메타데이터](5-CONTRACT.md#5-5-요청-헤더와-메타데이터))

| 상황 | AI 서버 | 백엔드 |
|---|---|---|
| 생성 중 백엔드 연결 종료 | 진행 중인 호출 취소 안 함 <br> 결과 폐기, 비용 발생 | 시간 초과 처리 |
| 동일 요청 중복 수신 | 요청마다 별도 처리 <br> 결과가 다를 수 있음 | 요청 식별자로 중복 방지 <br> 결과 저장 |
| 사용자와 백엔드 연결 종료 | 관여하지 않음 | 복구 조회로 결과 제공 |
