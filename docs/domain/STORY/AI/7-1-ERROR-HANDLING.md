# 7-1 오류 처리

오류 유형별로 처리 위치, 복구 한도와 최종 출력을 정한다. 같은 오류를 여러 계층에서 중복 처리하지 않도록 SDK, AI 서버와 백엔드의 책임을 구분한다.

생성과 보완 과정은 AI 실행 문서, 함수와 데이터 모델은 소프트웨어 구현 문서를 따른다. ([6-1 AI 실행](6-1-AI-EXECUTION.md), [6-2 소프트웨어 구현](6-2-SOFTWARE-IMPLEMENTATION.md))

<br>

### 7-1-1 오류 분류와 클래스

| 오류 | 예외 클래스 | 정의 위치 (`manyak-ai` 기준) | 역할 |
|---|---|---|---|
| 입력 오류 | `RequestValidationError` | FastAPI | 스키마 위반과 이름 중복을 422로 출력 |
| 설정 오류 | `LlmConfigError` | `src/services/llm/base.py` | 미등록 모델과 API 키 누락 등을 구분. `LlmError`를 상속하지 않음 |
| 텍스트 전송 오류 | `LlmTimeout`, `LlmRateLimited`, `LlmBadRequest`, `LlmUnavailable` | `src/services/llm/base.py` | `LlmError`를 상속하며 오류 메시지, `provider`와 `model` 보관 |
| 텍스트 출력 오류 | `json.JSONDecodeError`, `_InvalidAiResponse` | 표준 라이브러리, `src/services/story_llm.py` | JSON 파싱 실패, 빈 본문과 출력 형식 위반 구분 |
| 이미지 생성 오류 | `ImageTimeout`, `ImageRateLimited`, `ImageBadRequest` | `src/services/image/base.py` | `ImageGenerationError`를 상속. 그 밖의 생성 실패는 상위 클래스로 전달 |
| 예상하지 못한 오류 | 원래 예외 유지 | 오류가 발생한 코드 | 코드 결함을 공급자 오류나 출력 형식 오류로 바꾸지 않음 |

<br>

### 7-1-2 오류별 처리

- 시간 초과는 연결 오류보다 먼저 검사한다. SDK에서 시간 초과가 연결 오류의 하위 클래스이기 때문이다.
- 공급자의 401, 403, 404, 422와 5xx는 `LlmUnavailable`로 분류한다. 400은 `LlmBadRequest`, 429는 `LlmRateLimited`로 분류한다.
- 요청 취소는 상위 호출로 전파한다. 이미지 생성 실패 객체로 바꾸지 않는다.

| 오류 조건 | 적용 대상 | 처리 위치 | 복구 | 최종 출력 |
|---|---|---|---|---|
| 서버 시작 시 모델, 키 또는 템플릿 설정 오류 | 공통 | 시작 검사와 템플릿 로더 | 설정 수정 후 재배포 | 서버 시작 실패 |
| 입력 스키마 위반, 이름 중복 | 스토리라인, 컴파일 | 입력 스키마 검증기, FastAPI | 백엔드가 입력 수정 | 422 |
| 모델 시간 초과, 호출량 제한, 연결 실패 등 | 스토리라인, 컴파일 | 공급자 어댑터 → `_complete_json` | SDK 정책에 따른 재시도 | 복구 실패 시 502 |
| 공급자가 입력을 거부(400) | 스토리라인, 컴파일 | 공급자 어댑터 → `_complete_json` | 없음 | 502 |
| 호출 중 설정 오류 | 스토리라인, 컴파일 | 공통 LLM 호출 모듈 | 없음. 502로 변환하지 않음 | 500 |
| JSON 파싱 실패 또는 후보 형식 위반 | 스토리라인 | `_complete_json`, `_validate_storylines` | 전체 재생성 최대 2회 | 복구 시 200, 실패 시 502 |
| 이름을 입력한 주변 인물 누락 | 스토리라인 | `_missing_name_indexes`, `generate_storylines` | 해당 후보만 최대 2회 보완 | 누락이 남아도 현재 결과로 200 |
| 최초 출력의 JSON 파싱 실패 | 컴파일 | `_complete_json` | 없음 | 502 |
| 필수 블록 또는 인물 필드 누락 | 컴파일 | `compile_story`의 검사와 병합 함수 | 부분 보완 최대 2회 | 복구 시 200, 필수 내용이 여전히 비어 있으면 502 |
| 보완 후에도 엔딩 불완전 | 컴파일 | `_endings_incomplete`, `compile_story` | 빈 배열로 대체. 추가 호출 없음 | 200, 엔딩 빈 배열 |
| 출력 모델로 변환 실패 | 컴파일 | `compile_story`의 명세 검증과 출력 변환 | 없음 | 502 |
| 보완 호출의 전송 오류 또는 유효하지 않은 출력 | 스토리라인, 컴파일 | `_complete_json`, 보완 호출부 | 추가 보완 없이 전체 실패 | 502 |
| 인물 외형 부족 | 인물 이미지 | `generate_characters.py`의 인물별 생성 함수 | 호출 생략 | 200, 해당 이미지 `appearance_missing` |
| 이미지 모델 호출 실패 | 인물 이미지, 썸네일 | 생성 모듈 → `_generate_character_images_safe`, `_generate_thumbnail_image_safe` | SDK 정책에 따른 재시도 | 200, 해당 이미지 `error` |
| 이미지 로직의 예상하지 못한 예외 | 인물 이미지, 썸네일 | 각 `_safe` 함수 | 오류 보고. 인물 이미지 묶음은 미완료 호출도 취소 | 200, 인물 이미지 빈 배열 또는 썸네일 `generation_failed` |
| 관측 기록 전송 실패 | 공통 | Sentry, Langfuse 기록 모듈 | 별도 복구 없음 | 생성 결과에 영향 없음 |
| 처리하지 않은 내부 예외 | 공통 | 오류 발생 지점 → FastAPI | 없음 | 500 |

### 7-1-3 재시도와 시간 한도

**1. 재시도와 보완 횟수**

- 폴백 모델이 없으므로 다른 모델로 바꿔 다시 호출하지 않는다. ([6-1 AI 실행](6-1-AI-EXECUTION.md))
- 전송 오류가 난 요청은 코드에서 다시 호출하지 않는다. SDK 재시도로도 복구하지 못하면 요청은 실패한다.
- 코드는 재시도 사이에 대기 시간을 두지 않는다. 대기는 SDK의 기본 동작에 맡긴다.
- 큐 없이 동기 요청으로 처리하므로 메시지를 다시 꺼내 처리하지 않는다.

| 복구 방식 | 대상 | 한도 | 서비스 재호출 횟수 포함 여부 |
|---|---|---|---|
| OpenAI와 Anthropic SDK 자동 재시도 | 텍스트 모델 전송 오류 | 최대 2회 | 포함하지 않음 |
| Google SDK 자동 재시도 | 텍스트 모델 전송 오류 | 코드에서 별도 횟수를 지정하지 않음 | 포함하지 않음 |
| 스토리라인 전체 재생성 | 형식이 유효하지 않은 모델 응답 | 최대 2회 | 포함 |
| 스토리라인 부분 보완 | 이름을 입력한 주변 인물이 빠진 후보 | 최대 2회 | 포함 |
| 컴파일 부분 보완 | 필수 블록, 엔딩 또는 인물 필드 누락 | 최대 2회 | 포함 |
| 컴파일 폴백 | 보완 뒤에도 엔딩이 불완전함 | 추가 호출 없음 | 포함하지 않음 |
| 이미지 SDK 자동 재시도 | 이미지 모델 전송 오류 | 최대 2회 | 포함하지 않음 |
| 이미지 실패 처리 | 이미지 생성 실패 | 코드의 별도 재호출 없음 | 포함하지 않음 |

<br>

**2. 시간과 호출 한도**

- 호출 횟수는 AI 서버의 호출만 세며 SDK 재시도는 제외한다.
- 제한 시간은 SDK의 시도마다 적용되므로 재시도하면 총시간은 더 길어진다.
- 백엔드가 기다리기를 끝내도 AI 서버는 생성을 계속할 수 있다.

| 단계 | 제한 시간 | 적용 범위 |
|---|---|---|
| 백엔드의 스토리라인 응답 대기 | 90초 | 스토리라인 요청 전체 |
| 백엔드의 컴파일 응답 대기 | 180초 | 컴파일 요청 전체 |
| 스토리라인 최초 생성과 형식 재생성 | 90초 | 최초 생성과 형식 재생성에 함께 적용 <br> 60초가 지나면 새 형식 재생성을 시작하지 않음 |
| 스토리라인 인물 누락 보완 | 호출마다 90초 | 후보 부분 보완 최대 2회 |
| 컴파일 최초 생성 | 90초 | 최초 모델 호출 |
| 컴파일 부분 보완 | 호출마다 90초 | 누락 부분 보완 최대 2회 |
| 이미지 생성 | 호출마다 60초 | 인물 이미지와 썸네일의 각 생성 호출 |

<br>

| 요청 | 텍스트 호출 | 이미지 호출 |
|---|---|---|
| 스토리라인 | 최초 1회, 전체 재생성 2회, 인물 보완 2회로 최대 5회 | 없음 |
| 컴파일 | 최초 1회, 부분 보완 2회로 최대 3회 | 인물 이미지 최대 5장과 썸네일 1장 |

<br>

### 7-1-4 최종 실패와 부분 완료

- 빠진 필수 내용을 코드에서 지어내 정상 결과로 반환하지 않는다.
- 컴파일에서 허용한 예외는 두 가지다. 엔딩은 빈 배열로 반환하고 이미지 실패는 200 응답의 `error`로 전달한다. 둘 다 태스크 정의의 부분 완료에 해당한다. ([3 태스크 정의](3-TASK-DEFINITION.md))
- 공급자가 요청을 거부했다면 같은 입력으로 다시 요청해도 거부될 수 있다.

| 주체 | 하는 일 |
|---|---|
| AI 서버 | 모델 호출이나 출력 검증의 최종 실패 시 502와 정해진 메시지 출력 |
| 백엔드 | 자동 재호출 안 함 <br> 생성 실패 기록 및 사용자 오류 안내 <br> 회원의 컴파일 실패 시 지불한 이프 환불 |
| 사용자 | 재요청 <br> 같은 요청 식별자 사용 시 백엔드가 실패한 요청 재실행 |

<br>

### 7-1-5 실패 출력

| 상태 | 조건 | 본문 | 설명 |
|---|---|---|---|
| 422 | 요청 스키마 위반 또는 인물 이름 중복 | `detail` 배열<br>항목별 `type`, `loc`, `msg` | 백엔드가 입력 수정 후 재호출. `detail`은 사용자에게 직접 노출하지 않음 |
| 500 | 요청 처리 중 설정 오류 또는 처리하지 않은 내부 예외 | 공통 JSON 형식을 보장하지 않음 | AI 보완 없이 종료, 담당자가 오류 확인<br>백엔드는 본문을 파싱하거나 직접 노출하지 않고 자체 오류 안내 |
| 502 | 모델 호출 실패<br>보완 후에도 형식이나 필수 항목 위반 | `detail` 문자열<br>아래 메시지 중 하나 | 사용자에게 표시 가능한 한국어 문구만 사용<br>공급자 오류 원문 제외 |

<br>

| 502 메시지 | 뜻 | 사용자 재요청 |
|---|---|---|
| `LLM 응답 시간이 초과되었습니다.` | 모델이 시간 안에 응답하지 않음 | 가능 |
| `LLM 요청이 일시적으로 제한되었습니다.` | 공급자가 호출량을 제한 | 잠시 뒤 가능 |
| `LLM 요청이 거부되었습니다.` | 공급자가 요청을 거부 | 같은 입력은 불필요 |
| `LLM 연동 중 오류가 발생했습니다.` | 공급자 연결 또는 서버 오류 | 가능 |
| `LLM이 올바른 형식의 응답을 반환하지 않았습니다.` | 보완 후에도 형식이나 필수 항목 위반 | 가능 |
| `재호출 후에도 컴파일 결과에 필수 필드가 비어 있습니다.` | 컴파일 보완 후에도 필수 값이 비어 있음 | 가능 |
| `컴파일 결과가 스토리 명세 형식과 맞지 않습니다.` | 컴파일 결과를 응답 형식으로 바꿀 수 없음 | 가능 |

<br>

이미지 실패는 HTTP 200과 `error` 코드로 전달하며 공급자 오류 원문은 제외한다.

- 인물 이미지: 모두 실패해도 인물별 오류 항목을 유지한다. 생성 로직 전체의 예외일 때만 `character_images`를 빈 배열로 출력한다.
- 썸네일: `thumbnail_image` 객체를 유지하고 `error`를 채운다.

| 이미지 `error` | 뜻 |
|---|---|
| `appearance_missing` | 외형 부족으로 호출하지 않음 |
| `timeout` | 이미지 모델 응답 시간 초과 |
| `rate_limited` | 공급자가 호출량을 제한(429) |
| `rejected` | 공급자가 요청을 거부(400) |
| `generation_failed` | 그 밖의 SDK 오류, 빈 응답 또는 Base64 디코딩 실패 |

### 7-1-6 전달 실패 처리

AI 서버는 상태를 저장하지 않으므로 수신 확인과 재전송을 하지 않는다. 중복 방지, 결과 저장과 재요청은 백엔드가 맡는다. ([5-5 요청 헤더와 메타데이터](5-CONTRACT.md#5-5-요청-헤더와-메타데이터))

| 상황 | AI 서버 | 백엔드 |
|---|---|---|
| 생성 중 백엔드 연결 종료 | 진행 중인 호출 취소 안 함 <br> 결과 폐기, 비용 발생 | 시간 초과 처리 |
| 동일 요청 중복 수신 | 요청마다 별도 처리 <br> 결과가 다를 수 있음 | 요청 식별자로 중복 방지 <br> 결과 저장 |
| 사용자와 백엔드 연결 종료 | 관여하지 않음 | 복구 조회로 결과 제공 |
