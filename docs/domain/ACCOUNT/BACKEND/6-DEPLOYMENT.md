# 6. 배포

이 문서는 ACCOUNT 도메인이 포함된 서버의 배포 단위와 의존 대상, 배포 경로, 이 도메인이 읽는 환경 변수와 시크릿, 설정 변경, 적용과 복구 절차를 정한다.

서버 전체 배포 절차 중 ACCOUNT 도메인과 관련된 항목만 다룬다.

코드와 토큰의 수명은 오류 처리에, 관측 스택과 조회 도구는 관측에 있다. ([5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도), [5-4-1 관측 스택](5-4-OBSERVABILITY.md#5-4-1-관측-스택))

<br>

### 6-1 배포 단위와 의존성

배포 단위는 서버 컨테이너 하나다. ACCOUNT만 따로 배포하지 않는다. 이 도메인이 기동과 요청 처리에 쓰는 의존 대상은 다음과 같다.

| 의존 대상 | 내용 | ACCOUNT 도메인이 쓰는 것 |
|---|---|---|
| PostgreSQL | 기동 시 마이그레이션 적용 | 회원, 소셜 연동, 동의, 페르소나 테이블 |
| Redis | ElastiCache 비클러스터 | 세션, 핸드오프, 동의 대기 코드, 링크 코드<br>체험 카운터는 PAYMENT 경유 |
| Google, Kakao | 공개 키 집합 | 신원 증명 서명 검증 |
| 프로필 프리셋 자산 | 서버 이미지에 포함된 정적 파일 | 가입 배정, 프리셋 목록, 무인증 제공 |
| Secrets Manager | Terraform이 태스크 정의에 참조 주입 | 대칭키, 제공자 client ID, 디바이스 pepper |
| Data Prepper | 트레이스를 받아 OpenSearch에 적재 | 트레이스 전송 |

<br>

| 의존 대상 | 연결과 설정 실패 시 동작 |
|---|---|
| 대칭키 | 비어 있거나 32바이트 미만이면 기동 실패 |
| 제공자 client ID | 비어 있으면 그 제공자의 로그인, 재인증, 연동이 전부 거절<br>기동은 정상 |
| Google, Kakao 공개 키 | 조회 실패는 로그인 실패로 응답<br>분석 이벤트는 `network` |
| PostgreSQL | 연결할 수 없으면 기동 실패 |
| Redis | 필요한 시점에 연결하므로 서버는 기동<br>토큰 저장소 장애는 로그인, 회전, 로그아웃, 탈퇴가 서버 오류<br>핸드오프 조회와 체험 스냅샷은 폴백하고 로그인 계속 |
| 프리셋 자산 | 파일이 없는 명사는 기동 시 경고 뒤 이미지 없이 배정 |
| 법적 문서 버전 | 설정 파일 기본값으로 기동 |
| Data Prepper | 추적을 켜고 주소가 비면 기동 실패<br>추적이 꺼지면 스팬을 만들되 전송하지 않음 |

<br>

### 6-2 배포 경로

테스트와 빌드를 마친 뒤 이미지를 게시하고 배포한다. `main` push는 같은 소스 트리의 `dev` 성공 실행이 있으면 테스트를 다시 실행하지 않는다. `dev`로 PR을 올리면 테스트와 빌드만 한다.

| 단계 | 개발 | 운영 |
|---|---|---|
| 자동 시작 | `dev` push | `main` push |
| 머지 규칙 | 기능 브랜치에서 `dev`로 squash | `release/vX.Y.Z`에서 `main`으로 merge commit |
| 이미지 태그 | 커밋 SHA 앞 7자리, 환경 태그 `dev` | 커밋 SHA 앞 7자리, 배포 시 `latest` 승격<br>실패하면 이전 digest로 복원 |
| 상태 검사 | 배포 완료, 서버 컨테이너 정상, health `UP` | 동일 |

<br>

### 6-3 환경 변수와 시크릿

환경 변수가 설정 파일의 값보다 우선한다. 설정은 기동 시 읽으므로 변경 뒤 새 태스크를 시작해야 적용된다. 값은 Terraform이 태스크 정의에 주입하고 시크릿은 Secrets Manager에서 주입한다. 이 도메인이 읽는 설정만 적는다. 기본값이 "빈 값"이면 변수가 없어도 빈 문자열로 기동한다. "없음"이면 변수가 없을 때 기동에 실패한다.

<br>

**1. 인증**

| 이름 | 기본값 | 주입 출처 | 비고 |
|---|---|---|---|
| `MANYAK_AUTH_JWT_SECRET` | 없음 | 개발과 운영 Secrets Manager | 32바이트 이상 |
| `MANYAK_GOOGLE_CLIENT_IDS` | 빈 값 | 개발과 운영 Secrets Manager | 콤마 구분<br>클라이언트가 서버 client ID를 `aud`로 지정한 ID 토큰에 `azp`가 실리면 그 값도 목록에 포함 |
| `MANYAK_KAKAO_CLIENT_IDS` | 빈 값 | 개발과 운영 Secrets Manager | 단일 카카오 앱의 REST API 키와 네이티브 앱 키만 |
| `MANYAK_AUTH_CONSENT_TOKEN_TTL` | `PT10M` | 주입 없음 | |
| `MANYAK_AUTH_CONSENT_GATE_ENABLED` | `false` | 주입 없음 | 미동의 회원 서버 게이트 |

발급자, 접근 토큰과 갱신 토큰 수명, 회전 유예, 재인증 허용 범위는 설정 파일의 고정값이다. 핸드오프와 링크 코드 수명은 코드 기본값이다. 해당 환경 변수는 없다.

<br>

**2. 법적 문서 버전**

| 이름 | 기본값 | 주입 출처 | 비고 |
|---|---|---|---|
| `MANYAK_LEGAL_TERMS_VERSION` | `v1.4` | 주입 없음 | 웹 콘텐츠의 `version`과 같은 값 |
| `MANYAK_LEGAL_PRIVACY_VERSION` | `v1.7` | 주입 없음 | 웹 콘텐츠의 `version`과 같은 값 |
| `MANYAK_LEGAL_GUEST_PRIVACY_VERSION` | `v1.0` | 주입 없음 | 게스트 발췌문 버전 |

<br>

**3. 자산과 식별자**

| 이름 | 기본값 | 주입 출처 | 비고 |
|---|---|---|---|
| `MANYAK_ASSET_BASE_URL` | `https://api.manyak.app` | 주입 없음 | 프리셋 이미지 URL의 앞부분<br>저장된 URL은 전체 값이라 변경해도 기존 회원은 그대로 |
| `MANYAK_ANALYTICS_DEVICE_ID_PEPPER` | 빈 값 | 주입 없음 | 디바이스 해시 pepper<br>없으면 `MANYAK_ANALYTICS_ANONYMOUS_ID_PEPPER` 값을 씀<br>바꾸면 게스트 동의와 체험 카운터의 키가 달라짐 |
| `MANYAK_ANALYTICS_ANONYMOUS_ID_PEPPER` | 빈 값 | 운영 Secrets Manager | 위 변수가 없을 때의 pepper |

<br>

**4. 관측**

| 이름 | 기본값 | 주입 출처 | 비고 |
|---|---|---|---|
| `MANYAK_ANALYTICS_AMPLITUDE_ENABLED` | `false` | 운영 Terraform 변수 | |
| `MANYAK_AMPLITUDE_API_KEY` | 빈 값 | 운영 Secrets Manager | 비어 있으면 발행 생략 |
| `MANYAK_TRACING_ENABLED` | `false` | 운영 Terraform 변수 | |
| `MANYAK_OTLP_METRICS_ENABLED` | `false` | 운영 Terraform 변수, 전송 URL과 인증 헤더는 Secrets Manager | Grafana Cloud로 전송 |
| `MANYAK_OTLP_TRACES_ENDPOINT` | 빈 값 | 추적을 켠 운영 환경에 Data Prepper 내부 주소 주입 | 추적을 켜면 필수 |
| `SENTRY_DSN` | 빈 값 | 개발과 운영 Secrets Manager | |

### 6-4 배포 조건

| 확인 항목 | 기준 | 자동 여부와 한계 |
|---|---|---|
| 법적 문서 개정 | 웹 콘텐츠의 버전과 서버 설정값을 같은 릴리스에서 올림 | 수동 검토 |
| 동의 게이트 활성화 | 웹과 Android가 새 소셜 인증 경로로 전환된 뒤에 켬 | 수동 결정 |
| 제공자 client ID 변경 | 카카오는 같은 앱의 키인지 콘솔의 앱 ID를 대조<br>변경 PR에 앱 ID와 검증 결과를 남김 | 수동 검토<br>서버는 키 문자열로 같은 앱인지 판별할 수 없음 |
| 와이어 계약 변경 | 응답 형식이 바뀌면 서버와 클라이언트를 함께 배포 | 수동 검토 |
| 컬럼 제거 | 그 컬럼을 읽는 구버전 태스크가 사라진 다음 릴리스에서 제거 | 수동 검토 |
| 마이그레이션 | 기동 시 실행하므로 새 마이그레이션은 해당 코드보다 먼저 적용<br>재실행해도 같은 결과 | 기동 시 자동 적용<br>마이그레이션 경로 변경 PR은 `tbls lint`와 `dbdoc/` 비교를 CI에서 자동 실행 |
| 코드 테스트 | 전체 테스트 통과 | CI 자동 |
| 컨테이너 기동 | 컨테이너 헬스체크와 `/actuator/health` `UP` | CI 자동<br>실제 제공자 공개 키 조회는 검사하지 않음 |

<br>

### 6-5 설정 변경

| 변경 대상 | 변경 위치와 적용 | 확인 조건 |
|---|---|---|
| 대칭키 | Secrets Manager 값 변경 후 새 태스크 시작 | 기존 접근 토큰이 전부 무효가 되어 회전으로 복구<br>롤링 교체 중 구버전과 신버전이 서로의 토큰을 거부 |
| 제공자 client ID | Secrets Manager 값 변경 후 새 태스크 시작 | 각 플랫폼의 로그인 성공 |
| 동의 게이트 | 환경 변수 추가 후 새 태스크 시작 | 미동의 회원의 허용 목록 밖 요청 거절 |
| 법적 문서 버전 | 환경 변수 또는 설정 파일 변경 후 새 태스크 시작 | 회원 동의 조회의 `requiredVersion`, 재동의 유도 |
| 토큰과 코드 수명 | 설정 파일 또는 코드 기본값 변경 후 재빌드 | 회전 유예를 0으로 두면 동시 회전이 재사용 탐지로 바뀜 |
| 프리셋 이미지 | 정적 자산과 명사 풀을 함께 변경 후 재빌드 | 기동 로그의 적재 수가 명사 수와 같음 |
| 가입과 초대 보상액, 월 상한 | PAYMENT 정책값 | 세션 조회와 초대 조회의 응답 값 |
| 추적과 지표 전송 | 운영 Terraform 변수 변경 후 apply | |

### 6-6 적용과 복구

**1. 적용 순서**

| 순서 | 작업 | 확인 항목 |
|---|---|---|
| 1 | 설정과 시크릿 확인 | 새 시크릿 키의 주입 참조, 법적 문서 버전, 마이그레이션 순서 |
| 2 | 동반 배포 확인 | 클라이언트와 함께 배포해야 하는 변경인지와 순서<br>동의 게이트는 클라이언트 전환 뒤 |
| 3 | 배포 실행 | |
| 4 | 적용 결과 확인 | 배포 후 확인 항목 |

<br>

**2. 진행 중인 요청**

| 상황 | 처리와 한계 |
|---|---|
| 롤링 교체 중 세션 | 토큰은 Redis와 대칭키에만 의존하므로 태스크 교체와 무관<br>대칭키를 바꾸면 예외 |
| 롤링 교체 중 핸드오프와 코드 | Redis에 있어 새 태스크가 이어받음 |
| 태스크 강제 종료 중 로그인 | 계정 생성 뒤 끊기면 다음 로그인 시 보상과 스냅샷 복구 |
| 개발 stop-then-start | 교체 중 모든 요청 실패<br>데이터 컨테이너 재시작 |

<br>

**3. 복구**

자동 복구가 실행돼도 서비스가 정상으로 돌아오지 않았을 수 있으므로 실제 서버 상태를 확인한다.

| 상황 | 복구 방식 | 한계와 확인 사항 |
|---|---|---|
| 새 태스크 헬스체크 실패 | 직전 배포로 자동 복귀 | 환경 태그가 실패한 이미지를 가리킬 수 있으므로 다음 재배포 전에 태그 확인 |
| 배포는 정상이나 동작 오류 | revert 커밋 릴리스 또는 이전 이미지를 환경 태그로 다시 태깅한 뒤 새 배포 | health 기반 자동 복구는 로그인 실패를 탐지하지 않음 |
| 마이그레이션 적용 후 되돌리기 | 적용된 마이그레이션은 되돌리지 않음 | 새 컬럼은 구버전 코드와 호환되도록 추가 |
| 설정 오류 | 잘못된 시크릿을 이전 값으로 복구 후 새 태스크 시작 | 이미지 태그 복원만으로 설정은 복원되지 않음 |

<br>

### 6-7 배포 후 확인

| 확인 항목 | 자료 | 기준 |
|---|---|---|
| 기동 | 해당 배포 ID의 태스크 상태, 헬스체크 `/actuator/health`, 스모크 테스트 | 의도한 이미지로 기동, `UP` |
| 로그인 | 제공자별 로그인 성공과 실패 이벤트 | 실패 `error_type` 비율이 배포 전과 같은 수준 |
| 세션 | 요청 로그의 `/api/v1/auth/me`와 `/api/v1/auth/token/refresh`의 인증 실패 비율 | 배포 전과 같은 수준 |
| 회전 유예 | 로그 `refresh_reuse_grace_applied`와 재사용 탐지 WARN | 탐지 WARN이 급증하지 않음 |
| 프리셋 | 기동 로그의 프리셋 적재 수 | 명사 수와 같음 |
| 동의 | 회원 동의 조회의 `requiredVersion` | 릴리스한 문서 버전 |

<br>

### 6-8 배포 실패 진단

| 실패 상황 | 확인할 자료와 위치 | 원인별 조치 |
|---|---|---|
| 기동 중 설정 검증 실패 | 시작 로그의 예외 메시지 | 대칭키 길이, 추적 주소 누락 중 해당 값 수정 후 새 태스크 시작 |
| health 정상, 특정 제공자 로그인 전부 실패 | 로그인 실패 이벤트의 `error_type`, 해당 제공자 client ID 시크릿 | 빈 값이면 주입 참조 확인<br>`validation`이면 대상 목록과 `azp`, 카카오 앱 키 확인<br>`network`면 공개 키 주소 연결 확인 |
| 로그인은 되는데 모든 요청이 인증 실패 | 대칭키 시크릿의 변경 이력, 롤링 교체 중 두 버전 공존 | 교체 완료 대기 또는 이전 키 복구 |
| 회전 실패 급증 | 재사용 탐지 WARN, Redis 연결 상태 | Redis 장애면 복구, 유예 설정이 0인지 확인 |
| 핸드오프 확인이 전부 없는 코드로 응답 | Redis 키 존재, 외부 랜딩의 헤더 주입 | 웹 BFF의 쿠키와 헤더 변환 확인 |
| 재동의 요구가 전면 발생 | 법적 문서 버전 설정값과 웹 콘텐츠 버전 | 값을 같은 릴리스 버전으로 맞춤 |
