# 5-5 테스트 케이스

이 문서는 ACCOUNT 도메인 코드의 계약과 오류 처리 규칙을 검증할 테스트 범위, 입력과 상황, 기대 결과를 정한다.

실행 명령과 수동 호출 파일 위치는 AGENTS.md에, 기대 결과의 상태 코드는 계약에 있다. ([AGENTS.md](AGENTS.md), [4-2 계약](4-2-CONTRACT.md))

<br>

### 5-5-1 테스트 범위

| 종류 | 확인 범위 | 외부 호출 | 실행 |
|---|---|---|---|
| 단위 | 신원 증명 검증기, 접근 토큰 발급과 검증, 닉네임 규칙과 발급, 프리셋 적재, 소셜 인증 분기, 재가입 승계, 연동 판정, 초대 자격, 탈퇴 파기 범위, 토큰 저장소 계약 | 없음 | CI |
| 통합 | 컨트롤러부터 저장까지, 보안 필터, 동의 게이트, 핸드오프 전 과정 | 신원 검증기는 고정 신원을 돌려주는 구성으로 대체 | CI<br>H2, 스키마 자동 생성, 마이그레이션 비활성 |
| 동시성 | 동시 첫 로그인, 끊긴 연동을 재사용한 재가입 경쟁, 닉네임 경쟁, 페르소나 상한, 이관 1회, 동시 회전 | 없음 | CI |
| 수동 | 엔드포인트 호출 | 실행 환경의 실제 의존성 | 서버 저장소의 HTTP 요청 파일 |

테스트 프로파일은 마이그레이션을 건너뛴다. 전체 테스트를 통과해도 DB 제약을 검증했다고 볼 수 없다.

**외부 의존성과 테스트 데이터**

| 대상 | 방법 |
|---|---|
| 소셜 제공자 | 통합 테스트는 제공자별 고정 신원을 돌려주는 검증기를 등록<br>단위 테스트는 테스트용 키로 서명한 증명으로 서명, 발급자, 대상, `azp` 검사 |
| Redis | 토큰 저장소는 인메모리 구현과 Redis 통합 테스트가 같은 계약 테스트를 통과<br>핸드오프와 코드 저장소는 테스트 Redis 사용 |
| DB | 통합 테스트는 공유 H2의 PostgreSQL 모드<br>CHECK 제약과 부분 유니크 인덱스는 실제 PostgreSQL에서 DB 문서 생성 스크립트로 검증 |
| 비밀값 | 테스트 프로파일이 고정 대칭키와 테스트용 client ID 사용 |
| 회원 데이터 | 활성, 정지, 탈퇴, 재가입 계정과 두 제공자가 연동된 계정을 각각 준비 |
