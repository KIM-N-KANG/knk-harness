# 5-5 테스트 케이스

이 문서는 ACCOUNT 도메인 코드의 계약과 오류 처리 규칙을 검증할 테스트 범위, 입력과 상황, 기대 결과를 정한다.

실행 명령과 수동 호출 파일 위치는 AGENTS.md에, 기대 결과의 상태 코드는 계약에 있다. ([AGENTS.md](AGENTS.md), [4-2 계약](4-2-CONTRACT.md))

<br>

### 5-5-1 테스트 범위

| 종류 | 확인 범위 | 외부 호출 | 실행 |
|---|---|---|---|
| 단위 | 신원 증명 검증기, 접근 토큰 발급과 검증, 닉네임 규칙과 발급, 프리셋 적재, 소셜 인증 분기, 재가입 승계, 연동 판정, 초대 자격, 탈퇴 파기 범위, 토큰 저장소 계약 | 없음 | CI |
| 통합 | 컨트롤러부터 저장까지, 보안 필터, 동의 게이트, 관리자 정지와 해제 | 신원 검증기는 고정 신원을 돌려주는 구성으로 대체 | CI<br>H2, 스키마 자동 생성, 마이그레이션 비활성 |
| 동시성 | 동시 첫 로그인, 끊긴 연동을 재사용한 재가입 경쟁, 닉네임 경쟁, 페르소나 상한, 이관 1회, 동시 회전 | 없음 | CI |
| 수동 | 엔드포인트 호출 | 실행 환경의 실제 의존성 | 서버 저장소의 HTTP 요청 파일 |

테스트 프로파일은 마이그레이션을 건너뛴다. 전체 테스트를 통과해도 DB 제약을 검증했다고 볼 수 없다.

**외부 의존성과 테스트 데이터**

| 대상 | 방법 |
|---|---|
| 소셜 제공자 | 통합 테스트는 제공자별 고정 신원을 돌려주는 검증기를 등록<br>단위 테스트는 테스트용 키로 서명한 증명으로 서명, 발급자, 대상, `azp` 검사 |
| Redis | 토큰 저장소는 인메모리 구현과 Redis 통합 테스트가 같은 계약 테스트를 통과<br>코드 저장소는 테스트 Redis 사용 |
| DB | 통합 테스트는 공유 H2의 PostgreSQL 모드<br>CHECK 제약과 부분 유니크 인덱스는 실제 PostgreSQL에서 DB 문서 생성 스크립트로 검증 |
| 비밀값 | 테스트 프로파일이 고정 대칭키와 테스트용 client ID 사용 |
| 회원 데이터 | 활성, 정지, 탈퇴, 재가입 계정과 두 제공자가 연동된 계정을 각각 준비 |

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 오류 응답 형식 | 필수 입력이 빠진 400 | `status`, `code`, `message`, `path`, `details` 필드 포함 |
| 인증 경로 파싱 실패 | 깨진 JSON | 400과 빈 `details`, 로그에 본문 없음 |
| 토큰 검증 실패 로그 | 만료된 접근 토큰으로 필수 경로 호출, 만료된 ID 토큰으로 호환 로그인 | 두 요청 모두 401, 로그에 검증 라이브러리의 메시지와 원인 체인 없음 |
| Sentry 요청 필드 | 소셜 인증 경로의 500 | 본문, 헤더, 쿠키, 쿼리 제거 |
| 인증 경로 DB 오류 | 저장 예외 | 500 고정 문구, 원인 체인 없음, ORM 로그 억제 |
| 내 콘텐츠 목록 | 소유 스토리 3개, 삭제 1개, `limit` 0, 101, 문자열 | 2개를 생성 시각이 최신인 순으로 반환, 1개, 100개 상한, 400 |
| 요청 ID 헤더 | 64자, 65자, 공백 포함 | 그대로 반환, 서버 생성 ID 반환, 서버 생성 ID 반환 |
| 게스트 이벤트 기기 식별자 | 게스트 로그인 실패 요청에 `X-Manyak-Device-Id` 있음, 없음 | `device_id`는 헤더 원본, `unknown`<br>두 경우 모두 로그 MDC와 Sentry `identity`는 해시, 이벤트 프로퍼티 `device_id_hash`는 해시 또는 생략, 원본은 `device_id` 외에 없음 |
| 앱 요청 플랫폼 | 로그인 성공 요청에 `X-Manyak-App-Version: 1.4.0`<br>헤더 없음<br>51자 값 | Amplitude 이벤트의 `platform` `Android`, `app_version` `1.4.0`<br>`platform`과 `app_version` 생략<br>`platform` `Android`, `app_version` 생략 |
| 회원 이벤트 기기 식별자 | 회원 로그인 성공 요청에 `X-Manyak-Device-Id` 있음, 없음 | `device_id`는 헤더 원본이고 `device_id_hash`는 해시, 둘 다 생략<br>두 경우 모두 `user_id`는 공개 식별자, 로그 MDC와 Sentry `identity`는 해시 |

### 5-5-10 계정 정지와 해제

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 인증 | 토큰 없음, 앱 접근 토큰, 역할 없는 관리자 토큰 | 401, 401, 403 |
| 정지 | 활성 회원 | 200과 `SUSPENDED`<br>감사 로그 `MEMBER_SUSPENDED`에 전후 상태와 사유 |
| 정지 집행 | 정지 뒤 그 회원의 세션 조회, 프로필 수정, 토큰 회전 | 200과 `SUSPENDED`, 403, 403과 세션 폐기 |
| 해제 | 정지 회원 | 200과 `ACTIVE`, 감사 로그 `MEMBER_UNSUSPENDED`, 다음 프로필 수정 200 |
| 상태 거절 | 정지 회원 정지, 활성 회원 해제, 탈퇴 회원 정지와 해제 | 전부 409 `CONFLICT` |
| 관리자 보호 | 관리자 역할 있는 회원 정지<br>자기 자신 정지 | 409 `ADMIN_ACCOUNT_PROTECTED`<br>상태 불변 |
| 역할 회수 뒤 정지 | 역할 행 삭제 뒤 같은 회원 정지 | 200 |
| 입력 오류 | 사유 누락, 501자 사유, UUID 아닌 식별자, 없는 회원 | 400, 400, 400, 404 |
| 동시 정지 | 같은 회원에 동시 2건 | 한쪽 200, 다른 쪽 409, 감사 로그 1행 |
| 정지와 탈퇴 경쟁 | 정지 처리 중 탈퇴 커밋 | 잠금 뒤 재검사로 탈퇴 계정은 409 |
| 재가입 승계 | 정지 뒤 탈퇴한 회원의 재가입 | 정지로 시작 |
| 감사 기록 실패 | 감사 로그 삽입 예외 | 500<br>상태 불변 |
