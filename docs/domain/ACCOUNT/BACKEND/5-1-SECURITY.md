# 5-1 보안

이 문서는 ACCOUNT 도메인 백엔드의 인증과 권한 판정, 신원 증명 검증, 입력 검증, 비밀값과 개인정보 취급 규칙, 수용한 한계를 정한다.

경로별 인증 수준과 계정 상태별 응답은 계약에, 로그와 분석에 싣지 않는 데이터는 관측에, 잠금과 경쟁 조건은 동시성에 있다. ([4-2-1 공통 규칙과 헤더](4-2-CONTRACT.md#4-2-1-공통-규칙과-헤더), [5-4-8 수집 조건과 실패 처리](5-4-OBSERVABILITY.md#5-4-8-수집-조건과-실패-처리), [5-2 동시성](5-2-CONCURRENCY.md))

<br>

### 5-1-1 인증 수준과 토큰

| 항목 | 처리 |
|---|---|
| 공개 인증 경로 | 소셜 인증, 동의 완료, 호환 로그인, 토큰 회전, 로그아웃, 핸드오프 3종, 게스트 동의 2종<br>토큰을 읽지 않아 자동 첨부된 만료 토큰으로 거절되지 않음 |
| 필수 경로 | 그 외 모든 ACCOUNT 경로<br>토큰 없음, 만료, 위조, 주체 형식 오류, 사용자 없음은 인증 실패 |
| 선택 경로 | ACCOUNT에는 없음<br>다른 도메인의 선택 경로에 유효 토큰을 회원으로 바꾸는 필터를 제공 |
| 탈퇴 거부 | 인증이 확정된 직후 공통 필터가 토큰 주체의 계정을 읽어 탈퇴면 거절<br>엔드포인트가 요청자를 읽는 방식과 무관하게 적용 |

| 토큰 | 규칙 |
|---|---|
| 접근 토큰 | HS256 JWT, 대칭키 고정으로 알고리즘 변경 차단<br>클레임은 발급자 `manyak`, 주체는 회원 공개 식별자, 발급 시각, 만료<br>검증은 서명, 만료, 발급자 일치 |
| 갱신 토큰 | 256비트 무작위 값의 base64url 문자열<br>저장소에는 해시만 두고 동시 회전 유예 동안만 새 원문을 보관 |
| 세션 계열 | 로그인마다 새 계열<br>회전은 계열의 현재 토큰만 받고 과거 토큰의 재사용은 유예 조건 밖이면 계열 전체 폐기<br>로그아웃은 계열 전체 폐기 |
| 회전 시 상태 검사 | 정상 회전과 유예 재응답 모두 계정을 다시 읽어 탈퇴와 정지면 새 토큰까지 계열째 폐기 |

<br>

### 5-1-2 소유권과 접근 판정

| 판정 | 규칙 |
|---|---|
| 게스트와 회원의 교차 | 소유자 없는 콘텐츠는 익명 요청만, 회원 소유 콘텐츠는 소유자만<br>회원은 이관으로 소유권을 얻은 뒤 접근 |
| 이관 | 요청자가 원래 게스트였는지 증명할 수 없어 제출된 식별자를 신뢰<br>소유자 없는 항목만 설정하고 성공 1회와 시도 상한으로 열거 규모를 제한 |
| 페르소나 | 본인 것만<br>형식 오류, 없음, 삭제, 타인 소유를 같은 결과로 응답해 존재를 드러내지 않음 |
| 핸드오프 | 없는 코드와 만료된 코드를 같은 결과로 응답<br>확인 응답에 제목과 본문 같은 콘텐츠를 싣지 않음 |
| 링크 코드 | 발급받은 회원만 사용<br>다른 회원의 코드, 만료, 소비됨을 같은 결과로 응답 |
| 재인증 | 실패 사유를 구분하지 않아 어떤 소셜 계정이 연동돼 있는지 드러내지 않음 |
| 연동 충돌 | 타인 소유, 내 것, 끊긴 연동을 구분해 응답<br>그 소셜 계정의 유효한 신원 증명이 필요하므로 열거 오라클이 되지 않음 |
| 로그인 실패 | 검증 실패 사유를 구분하지 않아 계정 존재를 드러내지 않음 |
| 초대 코드 | 코드 없음과 초대자 상태를 구분해 응답<br>사용자가 직접 입력하는 값이라 안내가 필요 |

<br>

### 5-1-3 계정 상태와 동의

| 상태 | 처리 |
|---|---|
| 정지 계정 | 쓰기 경로는 사용자 행을 잠근 뒤 상태를 다시 확인해 거절<br>토큰 회전은 거절하고 계열을 폐기해 남은 세션 종료<br>정지 사유는 노출하지 않음 |
| 탈퇴 계정 | 남은 접근 토큰은 공통 필터가 거절<br>갱신 토큰은 탈퇴 시 전부 폐기<br>같은 소셜 계정의 로그인은 재가입 |
| 재가입 계정 | 이전 소유자가 정지였거나 탈퇴 직전 상태가 정지였으면 정지로 시작 |
| 게스트 | 계정 상태 판정의 대상 아님 |
| 미동의 회원 | 동의 게이트가 켜진 환경에서 현행 필수 동의 중 하나라도 없으면 허용 목록 밖 요청 거절<br>유효 토큰이 있는 선택 경로 요청도 대상 |

동의 게이트 허용 목록은 메서드와 정확한 경로로 판정한다. 허용 목록을 통과해도 인증, 탈퇴, 정지, 소유권 검사는 면제하지 않는다.

| 메서드 | 경로 | 목적 |
|---|---|---|
| GET, POST | `/users/me/consents` | 동의 상태 조회와 재동의 |
| GET | `/auth/me` | 로그인 상태와 계정 상태 확인 |
| DELETE | `/users/me` | 탈퇴 |
| DELETE | `/users/me/push-tokens` | 로그아웃 시 기기 토큰 정리 |
| GET | `/credits/policies` | 이프 정책 조회 |
| GET | `/credits/products` | 충전 상품 조회 |
| GET | `/profile-presets` | 프리셋 목록 조회 |
| GET | `/stories/simple/tags` | 간편 제작 태그 조회 |
| GET | `/stories/genres` | 장르 조회 |
| GET | `/stories/art-styles` | 그림체 조회 |

### 5-1-4 신원 증명 검증

| 대상 | 규칙 |
|---|---|
| 공개 키 | 제공자별 고정 주소에서 조회<br>Google `https://www.googleapis.com/oauth2/v3/certs`, Kakao `https://kauth.kakao.com/.well-known/jwks.json` |
| 허용 대상 | 제공자별 client ID 목록을 환경 변수로 주입 |
| Kakao 대상 | 같은 카카오 앱의 REST API 키와 네이티브 앱 키만<br>Kakao의 제공자 쪽 식별자는 앱마다 달라 다른 앱의 키를 함께 허용하면 다른 사람이 같은 계정에 귀속될 수 있음<br>운영자가 카카오 콘솔의 앱 ID를 대조해 확인 |
| 재인증 신선도 | 발급 시각이 없으면 거절<br>허용 범위를 넘은 증명은 거절해 보관해 둔 증명의 재제출을 막음 |
| Kakao 동의항목 | 요청하지 않음<br>제공자 쪽 식별자만 쓰므로 이메일과 프로필을 받지 않음 |
| 미지원 제공자 | 검증기가 없는 제공자는 증명을 보지 않고 거절 |

<br>

### 5-1-5 입력 검증

| 대상 | 규칙 |
|---|---|
| 길이, 필수, 허용값 | 요청 객체에 선언한 제약으로 검증하고 위반 시 거절 |
| 닉네임 | 입력값 그대로 2~20자, 완성형 한글, 영문, 숫자만<br>공백과 자모 단독, 특수문자, 이모지 거절<br>탈퇴 익명화 이름과 정규화 기준으로 같은 값 거절 |
| 페르소나 | 앞뒤 공백 제거 후 길이 검사<br>검수를 거치지 않음 |
| 초대 코드 | 앞뒤 공백 제거와 대문자 변환 후 대문자와 숫자 8자 |
| 핸드오프 복귀 경로 | `/`로 시작하고 `//`와 `/\`로 시작하지 않으며 제어 문자가 없는 512자 이내<br>외부 주소로의 이동을 막음 |
| 핸드오프 식별자 | 공개 식별자 형식만 허용<br>인증 없는 경로라 항목당 크기를 고정해 저장소 증폭을 막음 |
| 이관 식별자 | 공개 식별자 형식 오류는 요청 전체 거절 |
| 동의 버전 | 현행 버전과 정확히 일치하지 않으면 거절<br>서버 값으로 덮어쓰지 않음 |
| 프리셋 키 | 메모리에 올린 키 집합에 있어야 함 |

<br>

### 5-1-6 비밀값과 코드 취급

| 대상 | 규칙 |
|---|---|
| 코드 전달 | 핸드오프, 동의 대기, 링크 코드는 헤더로만 받음<br>요청 경로는 로그와 오류 보고에 남으므로 경로와 쿼리에 싣지 않음 |
| 코드 생성 | 256비트 무작위 값<br>원문은 발급 응답에서만 노출 |
| 저장 키 | 코드의 SHA-256 해시<br>저장소가 유출돼도 원문이 드러나지 않음 |
| 신원 증명 | 어디에도 저장하지 않음<br>동의 대기에는 검증된 식별자만 보관 |
| 갱신 토큰 | 해시만 저장<br>유예 원문은 유예 동안만 |
| 대칭키 | 환경 변수로 주입, 32바이트 이상<br>비어 있으면 기동 실패 |
| 오류 응답 | 검증 라이브러리의 원인 메시지에 토큰이나 클레임이 들어갈 수 있어 고정 문구로 대체 |
| 인증 경로의 오류 보고 | 소셜 인증과 동의 완료 요청의 본문, 헤더, 쿠키, 쿼리를 오류 보고에서 제거<br>DB 오류는 원인 체인 없는 안전한 예외로 변환하고 ORM 로그를 그 스레드에서 막음 |

<br>

### 5-1-7 식별자와 개인정보

| 대상 | 규칙 |
|---|---|
| 외부 식별자 | 회원과 페르소나는 무작위 공개 식별자<br>자동 증가 PK는 응답에 싣지 않음 |
| 소셜 프로필 | 이름과 사진을 쓰지 않고 랜덤 닉네임과 프리셋 이미지를 발급<br>이메일은 소셜 연동에 저장만 하고 읽지 않음 |
| 이메일 중복 | 판정하지 않음<br>계정 식별은 제공자와 제공자 쪽 식별자뿐 |
| 탈퇴 파기 | 닉네임 익명화, 프로필 이미지 제거, 이메일 삭제, 세션 폐기<br>제공자 쪽 식별자는 제공자 없이는 식별할 수 없고 재가입 판정의 유일한 키라 보존 |
| 동의 기록 | 탈퇴 뒤에도 보존<br>계약 종료 뒤 동의 증빙 |
| 디바이스 ID | 콘텐츠에 저장하지 않음<br>원문은 핸드오프와 동의 대기의 수명 동안만 보관하고 소비 시 삭제<br>게스트 동의와 로그에는 pepper 해시만 |
| 분석 이벤트 | 회원은 공개 식별자, 대기 단계는 회원 식별자를 싣지 않음<br>제공자 쪽 식별자, 이메일, 코드는 싣지 않음 |

<br>

### 5-1-8 수용한 한계

| 한계 | 수용 이유 |
|---|---|
| 공개 식별자를 아는 회원 누구나 소유자 없는 콘텐츠를 이관할 수 있음 | 게스트 식별 수단이 없음<br>시도 상한 5회와 항목 100개로 열거 규모를 최대 1,000개로 제한 |
| 계정을 읽은 뒤 토큰 발급 전에 탈퇴가 커밋되면 거부될 토큰이 발급됨 | 로그인 시 사용자 행을 잠그면 잠금 순서가 탈퇴와 반대가 됨. 가장 많이 호출되는 경로에 항상 잠금이 걸림<br>결과는 데이터 손상이 아니라 거부되는 토큰 |
| 초대자 행을 잠그지 않아 상태 확인 뒤 초대자가 탈퇴하거나 정지될 수 있음 | 초대자 행까지 잠그면 서로의 코드를 동시에 제출한 두 계정이 교차 대기<br>겹치는 경우 1건만 통과 |
| 초대자 월 상한이 재가입과 겹치면 1건 초과할 수 있음 | 집계는 보상 신원 전체이고 직렬화는 현재 지갑 단위<br>공통 잠금은 새 교차 대기 경로를 만듦 |
| 좋아요, 신고, 엔딩 도달 집계는 재가입마다 새로 셈 | 이프와 체험에 무관한 집계라 별도 정책 없이 수용 |
| 끊긴 연동 보존 도입 전에 탈퇴한 계정은 재가입 판정의 키가 없음 | 소셜 행이 이미 물리 삭제돼 과거 재가입의 중복 보상을 회수할 수 없음 |
| 연동 해제를 제공하지 않음 | 해제 뒤 로그인이 새 계정을 만들어 다시 갈라지고 되돌릴 병합이 없음 |
| 계정 병합을 제공하지 않음 | 이프 로트, 초대 관계, 도달 집계, 이관 잠금의 병합 정책이 모두 필요<br>계정이 갈라지기 전에 연동하는 방식으로 대신함 |
