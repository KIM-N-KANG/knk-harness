# 2. 요구사항

이 문서는 ACCOUNT 도메인의 백엔드가 처리해야 하는 동작, 요구 주체, 다른 주체와의 역할 분담, 제품 제약과 데이터 보존 기준을 정한다.

요청과 응답의 필드는 계약에, 처리 순서는 처리 흐름에, 코드와 토큰의 수명은 오류 처리에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도))

<br>

### 2-1 요구 주체

백엔드는 소셜 제공자가 증명한 신원을 계정에 연결한다. 그 계정의 세션과 소유권을 관리한다. 각 주체의 역할과 백엔드에 기대하는 동작은 다음과 같다.

| 주체 | 하는 일 | 백엔드에 기대하는 것 |
|---|---|---|
| 클라이언트 | 소셜 제공자에게서 신원 증명을 받아 전달<br>토큰을 보관하고 만료 전에 갱신<br>게스트가 만든 스토리와 채팅의 식별자를 기기에 보관<br>약관 문서를 표시하고 사용자가 동의한 버전을 제출 | 웹과 Android가 같은 계약으로 호출할 수 있는 엔드포인트<br>동의가 필요한지와 어떤 버전이 필요한지 응답으로 알 수 있음<br>신규 가입 여부를 응답으로 알 수 있음<br>이관 결과를 항목별로 받아 기기에서 무엇을 지울지 알 수 있음 |
| 웹 BFF | 토큰을 브라우저에 노출하지 않고 쿠키로 보관<br>접근 토큰 만료 전에 선제 갱신<br>핸드오프 코드를 쿠키에서 헤더로 주입 | 같은 갱신 토큰의 동시 회전을 짧은 유예 안에서 같은 결과로 응답 |
| 소셜 제공자 | 서명된 신원 증명 발급<br>서명 검증용 공개 키 공개 | 신원 증명을 공개 키로 검증하고 그 외 제공자 호출은 하지 않음 |
| 스토리 | 회원 소유 스토리의 카드 조회, 닉네임 변경 시 재색인, 탈퇴 시 초안과 제출본 삭제 | 이관 시 스토리와 간편 제작 진행의 소유권 설정 요청<br>회원 식별자와 계정 상태 |
| 채팅 | 회원 소유 채팅의 카드 조회 | 이관 시 채팅 소유권 설정과 엔딩 도달 집계 보정 요청<br>페르소나 스냅샷, 계정 상태 |
| 이프 | 지갑과 보상 원장, 체험 카운터, 정책값 관리 | 가입과 초대 보상 요청<br>가입 시 게스트 체험 사용량의 회원 이전 요청<br>세션 조회에 실을 잔액과 당일 출석 여부 |
| 알림 | 푸시 토큰과 수신 동의 관리 | 탈퇴 시 푸시 토큰 삭제 요청 |

### 2-2 기능 요구사항

| 기능 | 백엔드가 보장하는 것 |
|---|---|
| 소셜 인증 | Google과 Kakao의 신원 증명을 같은 흐름으로 검증<br>제공자와 제공자 쪽 식별자의 조합으로 계정을 찾거나 만듦<br>검증 실패 사유를 구분하지 않고 거절해 계정 존재 여부를 드러내지 않음 |
| 동의 후 가입 | 필수 동의가 없으면 계정을 만들지 않고 대기 코드만 발급<br>동의 제출 시 계정, 소셜 연동, 동의를 한 번에 저장<br>현행 버전과 다른 동의는 기록하지 않음<br>기존 회원의 재동의는 같은 계정에 기록 |
| 로그인 후속 처리 | 가입 보상은 보상 신원당 1회<br>게스트 체험 사용량을 회원 계정으로 1회 이전<br>핸드오프가 있으면 같은 요청에서 이관까지 처리<br>로그인이 여러 번 반복돼도 결과는 1회와 같음 |
| 세션 | 접근 토큰과 갱신 토큰 발급<br>갱신 토큰은 1회용이며 회전 뒤 재사용은 세션 계열 전체 폐기<br>같은 갱신 토큰의 동시 회전은 짧은 유예 안에서 같은 결과<br>로그아웃은 그 계열 전체 폐기<br>회전 시 계정 상태를 다시 확인 |
| 세션 조회 | 회원 식별자, 닉네임, 프로필 이미지, 계정 상태, 이프 잔액, 당일 출석 여부, 연동된 제공자를 한 번에 제공 |
| 핸드오프 | 이미 발급된 외부 브라우저 전환 링크를 복구하기 위해 유지<br>게스트 데이터 식별자와 기기 식별자를 1회용 코드로 보관<br>외부 브라우저는 코드로 건수와 복귀 경로를 확인<br>로그인 시 코드를 소비하고 결과를 인앱 복귀 때까지 보관<br>이미 소비된 코드는 다시 이관하지 않음 |
| 이관 | 소유자 없는 스토리와 채팅에만 요청자의 소유권 설정<br>항목별로 결과를 응답하고 일부 실패가 나머지를 막지 않음<br>계정당 성공 1회, 시도 횟수 상한<br>닫힌 계정의 재호출은 오류가 아니라 빈 결과 |
| 계정 연동 | 이미 연동된 제공자로 본인을 다시 확인한 뒤에만 추가<br>새 계정이나 새 세션을 만들지 않음<br>다른 회원에게 연동된 소셜 계정과 탈퇴 계정의 소셜 계정은 거절<br>연동 해제는 제공하지 않음 |
| 프로필 | 가입 시 랜덤 닉네임과 명사에 대응하는 프리셋 이미지 발급<br>닉네임은 대소문자와 공백을 무시한 기준으로 유일<br>프로필 이미지는 프리셋 선택만<br>닉네임이 바뀌면 소유 스토리의 재색인 요청 |
| 페르소나 | 회원당 최대 개수 안에서 생성, 수정, 삭제<br>본인 것만 접근하고 타인 것은 없는 것으로 응답<br>채팅 시작 시 이름과 설명 스냅샷 제공 |
| 회원 동의 | 현행 버전별 동의 필요 여부 제공<br>보낸 항목만 기록하고 같은 버전의 재제출은 최초 시각 유지<br>미동의 회원은 서버 게이트가 켜진 환경에서 허용 목록 밖 요청 거절 |
| 게스트 동의 | 기기 단위로 게스트 개인정보 수집 동의 기록<br>회원 동의로 옮기지 않음 |
| 탈퇴 | 계정을 삭제 상태로 전환하고 닉네임 익명화, 프로필 이미지 제거, 소셜 연동의 이메일 삭제<br>세션 전부 폐기<br>소유 스토리의 공개 상태 유지<br>정지 계정도 탈퇴 가능 |
| 재가입 | 탈퇴한 소셜 계정의 로그인은 새 계정 생성<br>보상 신원, 초대 코드 제출 여부, 이관 시도 횟수, 정지 상태를 이어받음<br>회원 체험은 부여하지 않음 |
| 초대 | 회원마다 초대 코드 1개를 처음 조회 때 발급<br>코드 제출은 계정당 평생 1회<br>자기 코드, 탈퇴와 정지 회원의 코드, 나중에 가입한 회원의 코드는 거절<br>초대자와 제출자 양쪽에 보상 요청 |
| 내 콘텐츠 목록 | 회원 소유 스토리와 채팅 카드를 상한 안에서 제공<br>삭제된 항목 제외 |
| 계정 상태 집행 | 정지 계정의 쓰기 요청 거절<br>탈퇴 계정은 남은 접근 토큰으로도 모든 요청 거절 |

### 2-3 다른 주체와의 역할 분담

| 판단과 작업 | 담당 |
|---|---|
| 사용자 인증과 신원 증명 발급 | 소셜 제공자 |
| 신원 증명의 서명, 발급자, 대상 검증 | 백엔드 |
| 약관 문서 원문과 표시 | 클라이언트 |
| 동의 필요 여부 판정 | 백엔드 |
| 토큰 보관과 갱신 시점 | 클라이언트와 웹 BFF |
| 핸드오프 코드의 쿠키 보관과 헤더 주입 | 웹 BFF |
| 게스트 데이터 식별자 보관 | 클라이언트 |
| 이관 대상의 원래 소유자 증명 | 불가능<br>백엔드는 제출된 식별자를 신뢰 |
| 가입과 초대 보상의 적립과 월 상한 판정 | 이프 도메인<br>백엔드는 자격과 멱등 키를 정해 요청 |
| 계정 정지 | 운영자가 저장소에서 직접 변경<br>백엔드는 정지 상태의 집행만 담당 |

### 2-4 제품 제약

**1. 입력**

| 항목 | 규칙 |
|---|---|
| 닉네임 | 2~20자, 완성형 한글, 영문, 숫자만<br>공백, 자모 단독, 특수문자, 이모지 불가<br>탈퇴 익명화 이름 불가 |
| 페르소나 이름 | 앞뒤 공백 제거 후 1~20자 |
| 페르소나 설명 | 앞뒤 공백 제거 후 1~1,000자 |
| 초대 코드 입력 | 앞뒤 공백 제거와 대문자 변환 후 대문자와 숫자 8자 |
| 핸드오프 복귀 경로 | 앱 내 상대 경로, 512자 이내 |
| 핸드오프 출처 앱 | `kakaotalk`, `instagram`, `threads` |
| 동의 버전 | 현행 버전 문자열과 정확히 일치 |

<br>

**2. 개수와 한도**

| 항목 | 값 |
|---|---|
| 핸드오프와 이관의 식별자 | 스토리와 채팅 각 100개 |
| 이관 성공 | 계정당 1회 |
| 이관 시도 | 계정당 5회 |
| 페르소나 | 회원당 10개 |
| 내 콘텐츠 목록 | 최대 100개 |
| 초대 코드 제출 | 계정당 평생 1회 |
| 초대자 보상 | KST 월 단위 상한<br>값은 이프 정책 |
| 가입 보상 | 보상 신원당 1회<br>값은 이프 정책 |
| 프리셋 이미지 | 40종 |

### 2-5 데이터 보존

| 대상 | 요구사항 |
|---|---|
| 회원 계정 | 탈퇴해도 행을 보존하고 삭제 상태로 표시<br>스토리 작성자 참조와 집계를 유지 |
| 소셜 연동 | 탈퇴 시 연결을 끊되 제공자 쪽 식별자는 보존<br>재가입 판정의 유일한 키 |
| 이메일 | 소셜 연동에만 저장하고 어디서도 읽지 않음<br>탈퇴 시 삭제 |
| 소셜 프로필의 이름과 사진 | 저장하지 않음 |
| 회원 동의 | 문서 버전별 최초 동의 시각을 추가 전용으로 보존<br>탈퇴 뒤에도 유지하고 재가입 계정에 승계하지 않음 |
| 게스트 동의 | 기기 해시 단위로 보존<br>회원 동의로 이관하지 않음 |
| 페르소나 | 삭제해도 행을 보존하고 조회에서만 제외 |
| 갱신 토큰 | 원문은 저장하지 않고 해시만 보존<br>동시 회전 유예 동안만 새 원문 보관 |
| 핸드오프, 동의 대기, 링크 코드 | 수명이 지나면 소멸<br>원문은 발급 응답에서만 노출 |
| 기기 식별자 원문 | 핸드오프 수명 동안만 보관하고 소비 시 삭제 |
