# 보안

이 문서는 ACCOUNT 도메인 백엔드의 인증과 권한 판정, 신원 증명 검증, 입력 검증, 비밀값과 개인정보 취급 규칙, 수용한 한계를 정한다.

경로별 인증 수준과 계정 상태별 응답은 계약에, 로그와 분석에 기록하지 않는 데이터는 관측에, 잠금과 경쟁 조건은 동시성에 있다. ([공통 규칙과 헤더](CONTRACT.md#공통-규칙과-헤더), [수집 조건과 실패 처리](OBSERVABILITY.md#수집-조건과-실패-처리), [동시성](CONCURRENCY.md))

<br>

### 인증 수준과 토큰

| 항목 | 처리 |
|---|---|
| 공개 인증 경로 | 소셜 인증, 동의 완료, 호환 로그인, 토큰 회전, 로그아웃, 게스트 동의 2종<br>토큰을 읽지 않아 자동 첨부된 만료 토큰으로 거절되지 않음 |
| 필수 경로 | 그 외 모든 ACCOUNT 경로<br>토큰 없음, 만료, 위조, 주체 형식 오류, 사용자 없음은 인증 실패 |
| 선택 경로 | ACCOUNT에는 없음<br>다른 도메인의 선택 경로에 유효 토큰을 회원으로 바꾸는 필터를 제공 |
| 탈퇴 거부 | 인증이 확정된 직후 공통 필터가 토큰 주체의 계정을 읽어 탈퇴면 거절<br>엔드포인트가 요청자를 읽는 방식과 무관하게 적용 |

| 토큰 | 규칙 |
|---|---|
| 접근 토큰 | HS256 JWT, 대칭키 고정으로 알고리즘 변경 차단<br>클레임은 발급자 `manyak`, 주체는 회원 공개 식별자, 발급 시각, 만료<br>검증은 서명, 만료, 발급자 일치<br>만료 판정은 시계 오차 60초 허용 |
| 갱신 토큰 | 256비트 무작위 값의 base64url 문자열<br>저장소에는 해시만 두고 동시 회전 유예 동안만 새 원문을 보관 |
| 세션 | 로그인마다 새 세션<br>회전은 세션의 현재 토큰만 받고 과거 토큰을 유예 조건 밖에서 재사용하면 세션 전체를 폐기<br>로그아웃 시 세션 전체를 폐기 |
| 회전 시 상태 검사 | 정상 회전과 유예 재응답 모두 계정을 다시 읽어 탈퇴와 정지면 새 토큰을 포함한 세션 전체를 폐기 |

### 소유권과 접근 판정

| 판정 | 규칙 |
|---|---|
| 게스트와 회원의 교차 | 소유자 전용 요청에서 소유자 없는 콘텐츠는 익명 요청만, 회원 소유 콘텐츠는 소유자만<br>회원은 이관으로 소유권을 얻은 뒤 접근<br>공개 스토리 읽기와 공유 열람은 각 도메인 계약의 예외 |
| 이관 | 요청자가 원래 게스트였는지 증명할 수 없어 제출된 식별자를 신뢰<br>소유자 없는 항목만 설정 |
| 페르소나 | 본인 것만<br>형식 오류, 없음, 삭제, 타인 소유를 같은 결과로 응답해 존재를 드러내지 않음 |
| 링크 코드 | 발급받은 회원만 사용<br>다른 회원의 코드, 만료, 소비됨을 같은 결과로 응답 |
| 재인증 | 실패 사유를 구분하지 않아 어떤 소셜 계정이 연동돼 있는지 드러내지 않음 |
| 연동 충돌 | 타인 소유, 내 것, 끊긴 연동을 구분해 응답<br>그 소셜 계정의 유효한 신원 증명이 필요하므로 열거 오라클이 되지 않음 |
| 로그인 실패 | 검증 실패 사유를 구분하지 않아 계정 존재를 드러내지 않음 |
| 초대 코드 | 코드 없음과 초대자 상태를 구분해 응답<br>사용자가 직접 입력하는 값이라 안내가 필요 |

<br>

### 계정 상태와 동의

| 상태 | 처리 |
|---|---|
| 정지 계정 | 쓰기 경로는 사용자 행을 잠근 뒤 상태를 다시 확인해 거절<br>토큰 회전은 거절하고 세션을 폐기<br>정지 사유는 노출하지 않음 |
| 탈퇴 계정 | 남은 접근 토큰은 공통 필터가 거절<br>갱신 토큰은 탈퇴 시 전부 폐기<br>같은 소셜 계정의 로그인은 재가입 |
| 재가입 계정 | 이전 소유자가 정지였거나 탈퇴 직전 상태가 정지였으면 정지로 시작 |
| 게스트 | 계정 상태 판정의 대상 아님 |
| 미동의 회원 | 동의 게이트가 켜진 환경에서 현행 필수 동의 중 하나라도 없으면 허용 목록 밖 요청 거절<br>유효 토큰이 있는 선택 경로 요청도 대상 |

동의 게이트 허용 목록은 메서드와 정확한 경로로 판정한다. 허용 목록을 통과해도 인증, 탈퇴, 정지, 소유권 검사는 면제하지 않는다.

| 메서드 | 경로 | 목적 |
|---|---|---|
| GET, POST | `/users/me/consents` | 동의 상태 조회와 재동의 |
| GET | `/auth/me` | 로그인 상태와 계정 상태 확인 |
| DELETE | `/users/me` | 탈퇴 |
| DELETE | `/users/me/push-tokens` | 로그아웃 시 기기 토큰 정리 |
| GET | `/credits/policies` | 이프 정책 조회 |
| GET | `/credits/products` | 충전 상품 조회 |
| GET | `/profile-presets` | 프리셋 목록 조회 |
| GET | `/stories/simple/tags` | 간편 제작 태그 조회 |
| GET | `/stories/genres` | 장르 조회 |
| GET | `/stories/art-styles` | 그림체 조회 |

### 신원 증명 검증

| 대상 | 규칙 |
|---|---|
| 공개 키 | 제공자별 고정 주소에서 조회<br>Google `https://www.googleapis.com/oauth2/v3/certs`, Kakao `https://kauth.kakao.com/.well-known/jwks.json` |
| 허용 대상 | 제공자별 client ID 목록을 환경 변수로 주입 |
| Kakao 대상 | 같은 카카오 앱의 REST API 키와 네이티브 앱 키만<br>Kakao의 제공자 쪽 식별자는 앱마다 달라 다른 앱의 키를 함께 허용하면 다른 사람이 같은 계정에 연결될 수 있음 |
| 재인증 신선도 | 발급 시각이 없으면 거절<br>허용 범위를 넘은 증명은 거절해 보관해 둔 증명의 재제출을 막음 |
| Kakao 동의항목 | 요청하지 않음<br>제공자 쪽 식별자만 쓰므로 이메일과 프로필을 받지 않음 |
| 미지원 제공자 | 검증기가 없는 제공자는 증명을 보지 않고 거절 |

<br>

### 입력 검증

| 대상 | 규칙 |
|---|---|
| 길이, 필수, 허용값 | 요청 객체에 선언한 제약으로 검증하고 위반 시 거절 |
| 닉네임 | 탈퇴 익명화 이름과 정규화 기준으로 같은 값 거절 |
| 페르소나 | 검수를 거치지 않음 |
| 이관 식별자 | 공개 식별자 형식 오류는 요청 전체 거절 |
| 동의 버전 | 현행 버전과 정확히 일치하지 않으면 거절<br>서버 값으로 덮어쓰지 않음 |
| 프리셋 키 | 메모리에 올린 키 집합에 있어야 함 |

### 비밀값과 코드 취급

| 대상 | 규칙 |
|---|---|
| 코드 전달 | 동의 완료와 연동은 코드를 헤더로 받음<br>요청 경로는 로그와 오류 보고에 남으므로 경로와 쿼리에 포함하지 않음 |
| 코드 생성 | 256비트 무작위 값<br>원문은 발급 응답에서만 노출 |
| 저장 키 | 코드의 SHA-256 해시<br>저장소가 유출돼도 원문이 드러나지 않음 |
| 신원 증명 | 어디에도 저장하지 않음<br>동의 대기에는 검증된 식별자만 보관 |
| 갱신 토큰 | 해시만 저장<br>유예 원문은 유예 동안만 |
| 대칭키 | 환경 변수로 주입, 32바이트 이상 |
| 오류 응답 | 검증 라이브러리의 원인 메시지에 토큰이나 클레임이 들어갈 수 있어 고정 문구로 대체 |
| 인증 경로의 DB 오류 | 원인 체인 없는 안전한 예외로 변환하고 오류가 발생한 스레드의 ORM 로그를 막음<br>소셜 식별자와 이메일이 로그와 오류 보고에 노출되지 않게 함 |

<br>

### 식별자와 개인정보

| 대상 | 규칙 |
|---|---|
| 외부 식별자 | 회원과 페르소나는 무작위 공개 식별자<br>자동 증가 PK는 응답에 포함하지 않음 |
| 이메일 중복 | 판정하지 않음<br>계정 식별은 제공자와 제공자 쪽 식별자뿐 |
| 디바이스 ID | 콘텐츠에 저장하지 않음<br>게스트 동의, 로그, 오류 보고, AI 서버 전달에는 pepper 해시만<br>원문은 서버 분석 이벤트의 `device_id`로만 Amplitude에 전달 |

### 수용한 한계

| 한계 | 수용 이유 |
|---|---|
| 공개 식별자를 아는 회원 누구나 소유자 없는 콘텐츠를 이관할 수 있음 | 게스트 식별 수단이 없음<br>시도 상한 5회와 항목 100개로 열거 규모를 최대 1,000개로 제한 |
| 좋아요, 신고, 엔딩 도달 집계는 재가입마다 새로 집계 | 이프와 체험에 무관한 집계라 별도 정책 없이 수용 |
