# 3-3 구현 컨벤션

이 문서는 ACCOUNT 도메인 코드를 작성하거나 수정할 때 반드시 지킬 규칙과 구현자가 선택할 수 있는 사항을 정한다.

트랜잭션과 잠금은 동시성에, 로그 이벤트 규칙은 관측에, 비밀값 취급은 보안에, 구현 위치는 AGENTS.md에 있다. ([5-2 동시성](5-2-CONCURRENCY.md), [5-4-3 구조화 로그 이벤트](5-4-OBSERVABILITY.md#5-4-3-구조화-로그-이벤트), [5-1-6 비밀값과 코드 취급](5-1-SECURITY.md#5-1-6-비밀값과-코드-취급), [AGENTS.md](AGENTS.md))

<br>

### 3-3-1 이름과 용어

| 대상 | 규칙 |
|---|---|
| 패키지 | 인증 패키지 아래에 소셜 인증, 동의 완료, 토큰, 핸드오프, 연동, 설정을 나눔<br>회원 패키지 아래에 프로필, 페르소나, 동의, 탈퇴, 내 콘텐츠를 나눔<br>이관과 초대는 별도 패키지 |
| 모델 이름 | 테이블의 단수형 |
| 전송 객체 | 요청은 `Request`, 응답은 `Response`를 접미사로 사용<br>와이어 필드는 camelCase<br>DB 컬럼은 snake_case |
| 제공자 표기 | 경로값과 응답은 소문자 `google`, `kakao`<br>저장과 내부 enum은 대문자 |
| 신규 가입 여부 | 와이어 필드 이름은 `isNewUser`로 고정<br>직렬화 설정에 따라 `newUser`로 바뀌지 않게 명시 |
| 용어 | 용어집을 따름 |

<br>

### 3-3-2 계층 책임

| 계층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| API 계층 | 형식 검증, 요청자 식별, 상태 코드 지정, 제공자 경로값 해석 | 비즈니스 판정, 저장 계층 호출<br>세션 조회 시 회원 조회만 예외 |
| 보안 필터 | 공개 인증 경로의 토큰 무시, 선택 인증, 탈퇴 거부, 동의 게이트 | 소유권 판정 |
| 서비스 | 처리 순서 관리, 자격과 상태 판정, 다른 도메인 호출, 분석 이벤트 | HTTP 세부 규칙, 직렬화 |
| 계정 등록 | 독립 트랜잭션 경계, 끊긴 연동 재사용, 잠금 순서 | 토큰 발급, 보상 |
| 저장 계층 | 쿼리 실행<br>잠금이 필요한 조회 메서드는 이름에 잠금 여부 표시<br>조건부 단일 컬럼 갱신은 영향 행 수 반환 | 비즈니스 판정 |
| 코드 저장소 | Redis 키 조립, 해시, 발급과 소비 | 소유권 판정, 사유 구분 |
| 신원 검증기 | 공개 키 조회, 서명과 클레임 검증, 결과 변환 | 계정 조회 |

<br>

### 3-3-3 요청 검증과 오류

| 대상 | 규칙 |
|---|---|
| 개별 필드의 길이, 필수 여부, 허용값 | 요청 객체의 필드에 애너테이션으로 선언<br>페르소나 이름과 설명은 앞뒤 공백 제거 후 길이를 확인하므로 서비스에서 검증 |
| 유니크 위반 | 트랜잭션 밖에서 포착하고 재조회로 사유를 확정한 뒤 변환 |

<br>

### 3-3-4 이벤트와 비동기

| 대상 | 규칙 |
|---|---|
| 분석 이벤트 | 트랜잭션 안에서 발행할 때는 리스너가 커밋 후 처리<br>롤백되면 발행하지 않음 |
| 재색인 요청 | 스토리별 애플리케이션 이벤트로 발행<br>STORY 도메인에서 처리 |
| 로그인 부가 작업 | 체험 스냅샷, 핸드오프 소비, 분석 이벤트가 실패해도 로그인 응답이 바뀌지 않도록 예외 처리 |

<br>

### 3-3-5 테스트와 검증 도구

| 대상 | 규칙 |
|---|---|
| 작성 순서 | 동작을 바꾸는 작업은 실패하는 테스트를 먼저 작성 |
| 엔드포인트 변경 | 통합 테스트와 수동 호출 파일을 함께 갱신 |
| 동시성 | 잠금, 멱등 키, 끊긴 연동 재사용 규칙을 바꾸면 동시 요청 테스트로 검증 |

<br>

### 3-3-6 구현자가 선택할 수 있는 것

| 선택 가능 | 조건 |
|---|---|
| 서비스 내부의 메서드 분할과 이름 | 없음 |
| 테스트 픽스처와 검증기 스텁의 구성 | 없음 |
| 조회 쿼리의 작성 방식 | 잠금 여부와 조건부 갱신 의미를 유지 |
| 로그 필드 추가 | 코드 원문, 신원 증명, 이메일, 제공자 쪽 식별자를 넣지 않음 |
| 닉네임 단어 풀의 단어 | 공백 없는 단일 토큰<br>명사를 추가하면 프리셋 이미지도 추가 |
