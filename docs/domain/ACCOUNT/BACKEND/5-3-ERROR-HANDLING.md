# 5-3 오류 처리

이 문서는 ACCOUNT 도메인의 응답 규칙, 앱 코드, 오류 분류, 복구 규칙, 재시도와 시간 한도, 전달 실패 처리, 오류 로그 기준을 정한다.

엔드포인트별 실패 조건과 응답 형식은 계약에, 흐름별 처리 순서는 처리 흐름에, 멱등과 1회 처리는 동시성에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-2-2 멱등과 1회 처리](5-2-CONCURRENCY.md#5-2-2-멱등과-1회-처리))

<br>

### 5-3-1 응답 규칙

| 항목 | 규칙 |
|---|---|
| `code` | HTTP 상태 이름이 기본<br>클라이언트 안내가 갈릴 때만 앱 코드 사용 |
| `message` | 사용자 안내 문구<br>신원 증명 검증 라이브러리의 원인 메시지는 싣지 않음<br>500은 고정 안내 문구 |
| `details` | 페르소나 필드 검증 실패에만 채움<br>서비스에서 판정한 400은 `details` 없이 `message`에 사유 기록 |
| 인증 실패의 통일 | 토큰 검증 실패, 주체 형식 오류, 사용자 없음, 탈퇴를 같은 문구로 응답 |
| 연동 경로의 401 | 회원 세션이 유효하면 재인증이나 연동 작업의 실패를 401로 응답하지 않음<br>클라이언트가 세션 만료로 오해해 로그아웃하는 것을 막음 |

<br>

### 5-3-2 앱 코드

코드 문자열은 API 계약이므로 유지한다.

| 상태 | `code` | 의미 |
|---|---|---|
| 400 | `CONSENT_VERSION_MISMATCH` | 제출한 동의 버전이 현행과 다름. 동의 완료, 회원 동의, 게스트 동의에 적용 |
| 400 | `CONSENT_REQUIRED_MISSING` | 동의 완료에 필요한 항목 누락 |
| 401 | `CONSENT_TOKEN_INVALID` | 동의 대기 코드 누락, 없음, 만료, 소비됨 |
| 403 | `CONSENT_REQUIRED` | 동의 게이트가 켜진 환경에서 미동의 회원의 허용 목록 밖 요청 |
| 403 | `REAUTH_FAILED` | 재인증 실패, 링크 코드 무효 |
| 403 | `SOCIAL_TOKEN_INVALID` | 연동할 제공자의 신원 증명 검증 실패 |
| 409 | `SOCIAL_ACCOUNT_LINKED_TO_OTHER_USER` | 다른 회원에게 연동된 소셜 계정 |
| 409 | `PROVIDER_ALREADY_LINKED` | 이미 연동된 소셜 계정이거나 제공자 |
| 409 | `SOCIAL_ACCOUNT_WITHDRAWN` | 탈퇴 계정의 끊긴 연동에 해당하는 소셜 계정 |
| 409 | `NICKNAME_TAKEN` | 정규화 기준 닉네임 중복 |
| 409 | `INVITE_ALREADY_REDEEMED` | 초대 코드를 이미 제출한 계정 |
| 409 | `INVITE_SELF_CODE` | 자기 초대 코드 |
| 409 | `INVITE_INVITER_WITHDRAWN` | 초대자 탈퇴 |
| 409 | `INVITE_INVITER_UNAVAILABLE` | 초대자 정지 |
| 409 | `INVITE_INVITER_NEWER` | 초대자가 나중 가입 |

<br>

### 5-3-3 오류 분류

| 오류 | 발생 위치 | 처리 |
|---|---|---|
| 입력 오류 | API 계층의 선언적 검증과 본문 파싱 | 400으로 변환<br>본문 파싱 실패는 빈 `details` |
| 신원 증명 검증 실패 | 검증기 | 서명, 만료, 발급자, 대상, 공개 키 조회 실패를 모두 401 또는 재인증 실패로 통일<br>분석 이벤트만 네트워크와 검증으로 구분 |
| 상태 코드 오류 | 각 서비스의 판정 | 401, 403, 404, 409<br>`code`는 상태 이름 또는 앱 코드 |
| 유니크 위반 | DB | 재조회로 사유를 확정해 409 또는 정상 처리로 변환 |
| 새 인증 경로의 DB 오류 | 소셜 인증과 동의 완료 | 원인 체인 없는 500 고정 문구 |
| Redis 장애, 핸드오프 조회 | 로그인 | 코드 없음으로 보고 헤더의 디바이스 ID로 로그인 계속 |
| Redis 장애, 핸드오프 확인과 상태 | 핸드오프 | 500 |
| Redis 장애, 체험 스냅샷 | 로그인 후속 처리 | 미완료로 남기고 로그인 계속 |
| Redis 장애, 토큰 저장소 | 로그인, 회전, 로그아웃, 탈퇴 | 500 |
| 보상 요청 실패 | PAYMENT | 로그인 실패로 전파<br>계정은 이미 생성됐으며 다음 로그인 시 복구 |
| 예상하지 못한 오류 | 어디서든 | 전역 핸들러가 500 고정 문구로 응답하고 Sentry 전송 |

<br>

### 5-3-4 오류별 처리

- 체험 스냅샷에 실패하면 핸드오프를 소비하지 않는다. 핸드오프를 소비하면 보관된 원래 기기 식별자가 지워져 다음 로그인 시 외부 브라우저의 기기 식별자로 스냅샷을 만들게 되기 때문이다. 다음 로그인 시 보관된 원래 기기 식별자로 스냅샷 생성을 다시 시도한다.
- 동의 완료 중 코드 소비에 실패하면 토큰이 발급됐어도 실패로 응답하고 코드를 남긴다.
- 이관의 식별자 형식 오류는 트랜잭션을 롤백해 시도 횟수를 늘리지 않는다.

<br>

### 5-3-5 재시도와 시간 한도

**1. 재시도**

- 소셜 제공자 공개 키 조회는 라이브러리 기본 동작에 맡기고 백엔드가 추가로 재시도하지 않는다.
- 계정 생성이 유니크 위반으로 실패하면 호환 로그인에서는 재조회 뒤 1회 더 생성한다. 동의 완료에서는 2회 더 시도한다.
- 핸드오프 결과 저장은 Redis 장애 시 3회 시도한다.
- 초대 코드 발급은 사전 중복 확인을 10회까지 한다.
- 그 외 재시도는 클라이언트가 같은 요청을 다시 보내는 것뿐이다.

<br>

**2. 시간 한도**

| 대상 | 제한 시간 | 적용 범위 |
|---|---|---|
| 접근 토큰 | 30분 | 만료 후 회전 |
| 갱신 토큰과 세션 | 14일 | 회전마다 재설정 |
| 회전 재사용 유예 | 10초 | 0이면 유예 없음 |
| 동의 대기 코드 | 10분 | 소셜 인증부터 재시작 |
| 핸드오프 | 30분 | 생성부터 소비까지 |
| 핸드오프 소비 결과 | 24시간 | 인앱 복귀 정리용 |
| 링크 코드 | 5분 | 재인증부터 재시작 |
| 재인증 신원 증명 | 발급 후 10분, 시계 오차 60초 | 재인증 요청 |

<br>

### 5-3-6 최종 실패와 부분 완료

| 결과 | 처리 |
|---|---|
| 로그인 중 보상이나 토큰 발급 실패 | 계정 유지, 토큰 없음<br>클라이언트는 로그인을 다시 시도 |
| 핸드오프 소비 중 이관 실패 | 로그인 성공, 이관 미완료<br>소비권을 반납하고 이관 트랜잭션이 롤백되므로 시도 횟수는 소모되지 않음<br>코드 수명 안에 다시 로그인하면 소비 재시도 |
| 핸드오프 결과 저장 실패 | 소유권 이전 완료, 상태는 대기<br>인앱은 이관된 식별자를 받지 못함. 해당 콘텐츠의 게스트 조회는 거절됨 |
| 이관 일부 충돌 | 충돌 항목만 제외하고 나머지 설정<br>성공이 한 건이라도 있으면 이관 닫힘 |
| 프리셋 이미지 파일 누락 | 해당 명사를 배정받은 회원은 이미지 없이 가입<br>클라이언트 기본 아바타 |

<br>

### 5-3-7 전달 실패 처리

| 상황 | 백엔드 | 클라이언트와의 경계 |
|---|---|---|
| 로그인 응답 유실 | 계정, 보상, 스냅샷, 핸드오프 소비는 멱등 | 같은 신원 증명으로 다시 로그인하면 새 세션 |
| 회전 응답 유실 | 유예 안의 같은 갱신 토큰 재제시에 같은 결과 | 유예가 지나면 재사용 탐지로 세션 폐기, 재로그인 |
| 동의 완료 응답 유실 | 코드는 소비됨 | 같은 코드 재제출은 거절, 소셜 인증부터 재시작 |
| 이관 응답 유실 | 소유권 설정됨 | 재호출은 닫힌 응답 또는 이미 소유 |
| 연동 응답 유실 | 연동 행 삽입됨 | 재요청은 이미 연동됨으로 거절, 세션 조회로 확인 |
| 초대 제출 응답 유실 | 관계와 적립 완료 | 재제출은 이미 제출로 거절, 잔액은 이프 조회 |
| 탈퇴 응답 유실 | 탈퇴 완료 | 재요청은 인증 실패 |

<br>

### 5-3-8 로그와 Sentry

| 대상 | 규칙 |
|---|---|
| 5xx | 스택트레이스와 함께 ERROR로 기록하고 Sentry 전송 |
| 예상 가능한 4xx | Sentry 미전송<br>원인 예외가 있으면 클래스와 메시지를 한 줄로 WARN, 없으면 DEBUG |
| 인증 경로 본문 파싱 실패 | 경로, 예외 종류, 요청 ID만 DEBUG |
