# 4-1 ACCOUNT 데이터 계약

서버 요청과 응답의 형식, 권한과 판정은 BACKEND 계약을 기준으로 한다. ([ACCOUNT BACKEND](../BACKEND/AGENTS.md))

<br>

### 4-1-1 프로필 변경 입력

- **요청**: `PATCH /users/me`에 바뀐 필드만 담는다. 닉네임은 입력값 그대로 `nickname`에, 바꾼 프리셋은 키를 `profileImagePreset`에 넣는다.

<br>

### 4-1-2 페르소나 입력

- **요청**: `POST /users/me/personas {name, description}`. `name`은 앞뒤 공백을 뺀 이름이다. 페르소나를 고른 채팅에서는 `description`이 스토리의 주인공 설정을 통째로 대신하므로([백엔드 채팅 계약](../../CHAT/BACKEND/4-2-CONTRACT.md#4-2-2-채팅-생성)), 일반 제작 `userRoleSetting`과 같은 형식으로 `# 주인공`, `## 성별`, 성별 값("남성", "여성"), 앞뒤 공백을 뺀 특징을 줄바꿈으로 이어 보낸다.

클라이언트 입력 칸의 20자와 500자 제한은 화면 계약이다. 서버의 허용 길이나 다른 클라이언트의 원문을 이 제한으로 덮어쓰지 않는다. 기존 소개의 폼 변환은 입력 요구사항을 적용한다. ([2-2-3 프로필과 페르소나](2-2-REQUIREMENTS.md#2-2-3-프로필과-페르소나))

<br>

### 4-1-4 응답과 실패의 변환

| 응답 | 클라이언트 반영 |
|---|---|
| `COMPLETED`, 가입 완료 토큰 | 플랫폼 세션 확정 후 필수 동의 확인 |
| `CONSENT_REQUIRED` | `needsConsent: true`인 항목과 `requiredVersion`으로 시트 구성. 이미 동의한 항목은 제출에서 제외 |
| 회원 동의 기록 | 필수 항목의 `needsConsent`가 모두 `false`일 때만 완료 |
| 가입 완료의 401 `CONSENT_TOKEN_INVALID`, 400 `CONSENT_VERSION_MISMATCH` 또는 `CONSENT_REQUIRED_MISSING` | 가입 대기 종료와 재로그인 안내 |
| 회원 기록의 `CONSENT_VERSION_MISMATCH` | 최신 상태 재조회와 체크 초기화. 자동 제출 없음 |
| 회원 동의 401, 403, 네트워크 및 5xx | 각각 세션 만료, 이용 제한, 일시 실패로 변환 |
| 프로필 200 | 응답으로 회원 정보 갱신. 플랫폼 세션도 서버 값으로 맞춤 |
| 프로필 409 `NICKNAME_TAKEN`, 400, 기타 실패 | 각각 중복 필드 오류, 입력 필드 오류, 실패 토스트 |
| 페르소나 생성 201, 409 | 목록 갱신과 생성 항목 전달 / 10개 상한 안내 |
| 페르소나 수정과 삭제 성공 | 목록 갱신. 수정은 `{name, description}`으로 제출 |
| 연동 409 `PROVIDER_ALREADY_LINKED` | 중복 안내와 회원 정보 재조회 |
| 연동 409 `SOCIAL_ACCOUNT_LINKED_TO_OTHER_USER` | 다른 계정 안내 다이얼로그, 현재 세션 유지 |
| 연동 403 `REAUTH_FAILED`, `SOCIAL_TOKEN_INVALID` | 실패 안내, 코드 만료 전 재시도. 세션 만료와 재발급으로 처리하지 않음 |
| 탈퇴 204 | 탈퇴 성공 후 정리 시작. 이미 무효화된 refresh 토큰의 로그아웃 실패는 정리를 막지 않음 |

실패의 사용자 결과와 문구는 앞 단계에 정의되어 있다. ([2-2-6 실패와 복구 결과](2-2-REQUIREMENTS.md#2-2-6-실패와-복구-결과), [3-3 ACCOUNT 화면 배치](3-3-LAYOUT.md))
