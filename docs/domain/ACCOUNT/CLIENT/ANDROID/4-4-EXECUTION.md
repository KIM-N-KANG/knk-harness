# 4-4 ACCOUNT Android 실행

<br>

### 4-4-1 인증과 동의

| 단계 | 실행 |
|---|---|
| SDK 초기화 | Google Credential Manager와 Kakao SDK 사용. Kakao는 Activity 전 Application에서 초기화 |
| 소셜 인증 | SDK 신원 인증과 서버 로그인 분리. Kakao 폴백은 앱 미설치와 미로그인만, 사용자 취소는 제외 |
| 가입 대기 | `CONSENT_REQUIRED`이면 토큰 저장 없이 대기 공개. 프로세스 사망 후 인증 진행 표시 복원 금지 |
| 가입 완료 | 서버 완료 → 토큰 저장 → 회원 공개 → 대기 해제 → 서버 회원 동의 재확인 |
| 대기 실패 | 401 무효 코드, 400 버전 불일치와 필수 누락은 대기 폐기 및 만료/갱신 안내. 자동 인증 안 함. 그 밖은 대기 유지 |
| 회원 동의 오류 | 401은 만료 흐름, 403은 이용 제한과 로그아웃. 네트워크 및 5xx는 재시도 |
| 저장 세션 시작 오류 | 시작 화면의 실패 콘텐츠에 로그아웃 콜백을 주입하지 않음. 재시도만 제공 |
| 동의 완료 | 회원 그래프 → 권한 요청 → 선택 광고 동의 저장 → 해당 접속의 초대 안내 → 광고 재질문 |
| 계정 연동 | 현재 공급자 새 인증 → 메모리 link code → 대상 공급자 새 인증. Google nonce 사용, 403과 409 사유 유지 |

명시적인 `ACCOUNT_SUSPENDED`만 정지 사유로 중앙 종료한다. 모든 403을 세션 종료로 처리하지 않는다. ([2-2-1 진입과 동의](2-2-REQUIREMENTS.md#2-2-1-진입과-동의))

<br>

### 4-4-2 재발급

1. 앱 전체 single-flight로 요청을 합치고 무인증 클라이언트로 재발급한다.
2. 새 토큰 쌍을 저장한 뒤 대기 요청을 깨운다.
3. 원 요청의 401에는 같은 generation에서 재발급 한 번, 재전송 한 번만 허용한다.

| 결과 | 실행 |
|---|---|
| 재발급 401 또는 명시적 정지 403 | 중앙 종료 |
| 네트워크 실패 | 기존 세션 유지 |
| 회전 토큰 저장 실패 | `LocalTokenPersistenceFailed`로 종료, 메모리 새 토큰으로 서버 로그아웃 시도. 이전 refresh 재사용 금지 |
| 서버 회전 후 저장 전 프로세스 종료 | 다음 기동에서 재로그인 필요 가능 |

토큰 만료와 결과 반영 조건은 상태 관리에 있다. ([4-3-1](4-3-STATE-MANAGEMENT.md#4-3-1-세션과-토큰))

<br>

### 4-4-3 중앙 로그아웃과 복구

사용자 로그아웃은 푸시 등록을 닫고 cancel/join한 뒤, 정상 인증 게이트가 열린 동안 현재 FCM 토큰 DELETE를 최대 3초 시도한다. 강제 종료와 재기동 정리에서는 생략한다. 삭제 실패는 종료를 막지 않는다. 늦은 PUT이 복구할 수 있으므로 이 삭제만으로 계정 격리를 보장하지 않는다.

1. generation, 단계와 새 device ID 후보를 journal에 원자 기록하고 barrier를 닫는다. 인증 작업을 cancel/join한다. 기록 실패면 파괴적 정리를 시작하지 않는다.
2. 메모리 토큰으로 서버 로그아웃을 가능한 범위에서 시도한다.
3. 토큰과 만료 앵커를 삭제한다.
4. 사용자 범위의 프로필, 초대, 표시 알림과 페르소나 목록을 정리한다. 제작 두 테이블은 ownerId로 격리한다.
5. Google `clearCredentialState`와 Kakao 로컬 상태를 정리한다. Google 실패는 완료를 막고, Kakao는 원격 실패와 로컬 결과를 구분한다.
6. 분석 사용자와 Crashlytics 사용자 정보를 해제한다. journal의 새 device ID를 저장하고 SDK에 주입한다.
7. journal 삭제 후 Guest와 인증 그래프를 공개한다.

성공 단계 checkpoint, 재시작과 실패 상태는 종료 상태를 적용한다. ([4-3-4](4-3-STATE-MANAGEMENT.md#4-3-4-초대와-종료-상태))
