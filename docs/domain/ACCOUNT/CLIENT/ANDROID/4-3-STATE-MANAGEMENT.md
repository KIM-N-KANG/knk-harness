# 4-3 상태 관리: 안드로이드

<br>

### 4-3-1 세션과 토큰

| 상태와 저장 | 처리 |
|---|---|
| 세션 | `Pending`, `Guest`, 회원, `CleanupFailed`. 복호화 가능한 토큰 쌍으로 회원 판정, `/auth/me` 성공을 로그인 성립 조건으로 삼지 않음 |
| 토큰 저장 | Keystore 키로 암호화한 DataStore. 상호작용 필요한 키와 하드웨어 보안 저장소를 필수로 하지 않음 |
| 노출과 백업 | auth/data와 network 포트 안에서만 취급. UI와 로그 전달 금지. `allowBackup=false`, 토큰과 정리 journal 백업 제외 |
| 읽기 결과 | 없음, 사용 가능, 손상, 일시 실패. 일시 실패 유한 재시도, 손상은 중앙 정리. 무한 Pending 금지 |
| 만료 스냅샷 | 토큰 쌍, `expiresIn`, `elapsedRealtime`, wall clock, `BOOT_COUNT` 또는 `UNAVAILABLE`을 함께 저장 |
| 만료 판정 | 60초 여유. 같은 부팅의 음수 아닌 두 경과 시간 중 큰 값. 음수, 앵커 누락과 부팅 변경은 재발급 |
| 부팅 식별 불가 | 재발급 성공 후 프로세스 내 확인과 새 monotonic 앵커 사용. 프로세스 재시작 시 다시 확인 |
| 계정 격리 | generation 검사, 결과 commit, 종료 barrier 전환을 같은 잠금 경계에 둠. 취소만으로 늦은 결과 반영을 막지 않음 |

<br>

### 4-3-2 가입 대기와 회원 동의

| 대상 | 수명과 조건 |
|---|---|
| 가입 대기 코드 | 저장소의 프로세스 메모리 필드만 사용. 엔티티, 디스크, 로그, Crashlytics와 분석에 포함 금지 |
| 대기 항목 | 필요한 항목과 요구 버전만 공개. 새 로그인 시 이전 대기 폐기, 새 대기 공개 시 직전 종료 안내 제거 |
| 가입 완료 반영 | 같은 인증 작업에서 토큰 저장 → 회원 공개 → 대기 해제. 선택 동의 답을 가입 취소로 오인해 지우지 않음 |
| 회원 동의 | 필수 항목 모두 `needsConsent: false`일 때 완료. 필드 누락은 직렬화 실패, 미완료 유지 |
| 완료 저장 | 메모리만 유지, 영속 완료 플래그 없음. 사용자 범위 정리에서 제거 |
| 동의 조회 | 회원 전환마다 별도 작업, 회원 아니면 비움. 조회가 세션 수집을 막지 않음 |
| 늦은 응답 | 세션 generation과 commit으로 거부 |
| 요구 변경 | 버전 불일치 또는 기록 뒤 `needsConsent` 잔존 시 재조회와 체크 초기화 |
| 선택 동의 | OS 권한과 무관하게 체크 항목 제공. 루트 수명에서 답 유지, 권한 응답 뒤 알림 저장 경로에 전달하고 소비 |
| 시작 경로 | 로그인 화면 진입 전 복원 회원과 로그인 후 전환 구분. Activity 재생성에서 유지, 프로세스 재시작 때 재판정 |

동의 시트는 끌어내리기와 배경을 막고, 제출 중 뒤로가기를 막는다. 종료 조작은 회원이면 세션 종료, 가입 대기이면 대기 취소이다.

### 4-3-3 프로필과 페르소나

| 대상 | 갱신과 수명 |
|---|---|
| 회원 자동 조회 | 세션과 동의 완료를 결합해 프로필과 체험 잔여 조회. 조건 해제 시 취소 |
| 프로필 갱신 | 로그인, 토큰 기동, 연동, 마이 노출과 출석 및 초대 성공. 마이 재노출은 5초 간격 제한 |
| 갱신 중 | 기존 프로필 유지. 캐시 없으면 연동 Chip 골격 2개, 비거나 실패하면 연동 버튼 추정 금지 |
| 프로필 편집 | 캐시에서 초기값 한 번, 없으면 조회. 입력과 프리셋, 시트 및 이탈창은 구성 변경 유지 |
| 저장 응답 | 같은 generation일 때만 프로필 캐시에 반영. 프리셋은 첫 시트 열기 때 조회해 화면 수명 동안 사용 |
| 작성자 표시 | 최초 값 이후 닉네임 변경 시 홈 첫 페이지 조용히 재조회. 상세는 진입 때 서버 조회 |
| 페르소나 목록 | 회원 메모리 StateFlow. 진입 때 재조회, 변경 성공 응답을 먼저 반영 후 목록 재조회 |
| 생성 항목 전달 | 목록 재조회 실패에도 새 항목의 상세 미리 선택 유지. 로그아웃 정리에 참여 |
| 상세 선택 | 직접 고른 값은 컨트롤에서 즉시 읽음. 없는 ID는 기본 주인공. 다른 선택 또는 채팅 시작 시 생성 미리 선택 소비 |
| 채팅 복귀 | 시작할 때 직접 선택값으로 확정해 백스택 상세의 선택 유지 |
| 목록 표시 상태 | 펼침은 `rememberSaveable`, 옵션과 삭제 대상은 ViewModel. 입력은 프로세스 종료 뒤 복원 안 함 |

### 4-3-4 초대와 종료 상태

| 대상 | 저장과 복구 |
|---|---|
| 초대 대기 | 디스크의 미완료 안내와 메모리의 가입 실행 여부 결합. 가입 실행은 미표시, 다음 실행부터 대기 |
| 닫기 기록 | 저장 성공 여부 반환. DataStore I/O 실패는 false, 코루틴 취소는 전파 |
| 보상과 닫기 | 지급 결과와 닫기 기록 별도 상태. 현재 실행의 dismissed로 재표시 및 재제출 차단 |
| 종료 journal | generation, 단계, 새 device ID 후보 원자 기록. 성공 단계만 checkpoint |
| 정리 중 | 공개 상태 Pending, barrier 닫힘. 이전 계정 결과 반영 금지 |
| 정리 실패 | 유한 backoff 후 `CleanupFailed`, journal 유지, 새 로그인 차단 |
| 재기동 | 같은 device ID 후보로 성공 단계 다음부터 멱등 재개 |
| 제작 데이터 | 두 제작 테이블은 삭제하지 않고 ownerId로 격리 |
