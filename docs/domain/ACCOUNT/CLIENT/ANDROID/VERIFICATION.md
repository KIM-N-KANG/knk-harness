# ACCOUNT Android 검증

변경 범위에 맞춰 앱의 `checkModuleArchitecture`, 루트 `check`와 기존 단위 테스트를 사용한다. 기기 검증은 구성 변경과 프로세스 재시작을 구분한다. 이 문서는 검증 절차이며 실행 결과는 PR과 CI에 기록한다. ([Android 지침](../../../../../../manyak-android/AGENTS.md))

<br>

### 기존 검증 경계

| 경계 | 필수 확인 |
|---|---|
| 인증 | 동시 401 단일 재발급, 회전 토큰 저장 실패, 손상, 시계, 부팅 식별 불가, 늦은 응답 generation 차단 |
| 로그아웃 | 각 단계 실패, 프로세스 종료 후 journal 재개, 공급자 정리 실패 시 새 로그인 차단 |

<br>

| ACCOUNT-ANDROID-04 | 회원, 프로필 변경 | 저장 실패, 회전, 성공과 뒤로가기 | 입력 유지와 이탈 확인. 성공 응답은 같은 세션 세대에만 반영. 마이와 작성자 정보 갱신 | 수동 기기 검증 |

| ACCOUNT-ANDROID-06 | 가입 직후, 초대 안내 대기 | 같은 실행 홈 이동, 앱 종료 후 홈 진입 | 가입 실행에서는 미표시, 다음 실행의 홈에서 표시 | 수동 기기 검증 |

| ACCOUNT-ANDROID-08 | 세션 종료 각 단계에서 실패 가능 | 로그아웃 중 프로세스 종료 후 재시작 | journal의 성공 단계 이후부터 같은 device ID 후보로 재개. 미완료 동안 새 로그인 차단 | 단위 테스트와 수동 기기 검증 |
| ACCOUNT-ANDROID-09 | 로그인 전 또는 동의 시트 | 법적 문서 열기, 외부 링크, 닫기 | 같은 본문, 허용 경로 제한, 외부 브라우저 없으면 실패 안내. 시트로 돌아오면 체크 유지 | 수동 기기 검증 |

실제 테스트 목록과 빌드 명령은 구현 저장소를 기준으로 선택한다. 새로 정리한 시나리오의 자동화 완료를 가정하지 않는다.
