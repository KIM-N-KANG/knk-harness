# DECISIONS.md

현재 적용 기준은 각 명세에 두고 결정 당시의 이유와 대체 관계는 이 문서에 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다. 기존 ID, 날짜, 당시 상태와 근거를 유지한다.
- 상태와 구현 설명은 원본의 기록 시점을 기준으로 해석한다. 현재 적용 여부나 배포 완료를 과거 기록만으로 단정하지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체하는 결정과 적용 범위를 명시한다.
- 원문에 구분되지 않은 배경, 대안과 영향은 추측해서 보충하지 않는다.

**C-010. 필수 동의 시트에 동의하지 않고 나가는 로그아웃 버튼을 둠**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-07 |
| 상태 | Accepted (원문 기록 기준) |
| 관계 | 필수 동의 시트에 동의 없이 나가는 버튼을 두지 않던 공통 계약(2026-09-19)을 대체한다. 배경 탭, 스와이프, Escape로 닫지 않는 규칙과 뒤로가기를 동의하지 않음으로 보는 규칙은 유지한다. |
| 배경 | 시트를 거절하는 경로가 뒤로가기뿐이었다. 웹에서는 Chrome의 history manipulation intervention이 사용자 조작 없이 히스토리 항목을 쌓은 화면을 뒤로가기 버튼에서 건너뛰어, OAuth 직후 자동으로 열린 시트에서 뒤로가기를 누르면 시트가 닫히지 않고 Google 계정 선택 화면으로 이동했다. 화면에는 거절 수단이 보이지 않아 사용자가 시트에 갇혔다. ([Chromium 문서](https://chromium.googlesource.com/chromium/src/+/127.0.6533.99/docs/history_manipulation_intervention.md)) |
| 채택 | "동의하기" 아래에 보조 버튼 "로그아웃"을 두고, 조회 실패 단계에도 같은 버튼을 둔다. 동작은 뒤로가기와 같아 가입 전이면 가입을 취소하고 이미 로그인한 세션이면 로그아웃한다. 웹과 Android가 같은 계약을 따른다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 버튼은 브라우저의 히스토리 정책과 무관하게 동작한다. 사용자는 소셜 로그인을 마친 상태로 인식하므로 가입 전에도 "로그아웃"이 결과를 가장 잘 설명하고, 403 안내 시트의 기존 문구와도 같다. Android는 시스템 뒤로가기가 확실히 처리되지만 거절 수단이 화면에 보이지 않는 문제는 같아 계약을 함께 바꾼다. |
| 영향 | 동의 시트의 비주얼 기준 이미지가 바뀐다. Android는 [KNK-1602](https://kimandkang.atlassian.net/browse/KNK-1602)로 따라오며 그 전까지 두 플랫폼의 시트 구성이 다르다. 웹의 히스토리 재진입 정리는 [W-028](WEB/DECISIONS.md#w-028)에 둔다. |
| 근거 | [공통 동의 모델](3-2-INTERACTION-FLOWS.md#3-2-1-로그인과-필수-동의) |
| 출처 | 사용자 확정 결정. ([KNK-1600](https://kimandkang.atlassian.net/browse/KNK-1600)) |
