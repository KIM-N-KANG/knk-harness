# 4-3 ACCOUNT 웹 상태 관리

<br>

### 4-3-1 저장 위치와 수명

| 저장 위치 | 값과 정리 |
|---|---|
| HttpOnly, SameSite 쿠키 | 백엔드 access, refresh와 Auth.js 세션. 토큰은 브라우저 JS와 로그에 노출하지 않음 |
| `manyak_session_expires_at` | 만료 시각, JS 읽기 허용. 자격증명이 아니며 재발급 시작 힌트로만 사용 |
| `manyak_signup_consent` | 대기 코드, 만료 시각과 동의 상태를 HttpOnly로 보관. 코드 만료까지, URL과 BFF 응답에 코드 노출 금지 |
| localStorage | `manyak:created-story-ids`, `manyak:created-chat-ids` 최신순 JSON 배열 |
| 이전 sessionStorage | `manyak:guest-chat-ids`는 기존 탭 채팅 ID, 이관에 포함. 신규 채팅은 localStorage |
| `manyak:chat-login-draft:{chatId}` | 로그인 시트 또는 이프 부족 시트의 충전 이동 전 전송 형식으로 저장. 채팅방 마운트 때 두 컴포저에 복원 후 삭제 |
| `manyak:pending-login` | OAuth 직전 탭에 `'1'`. 완료, 취소, 재로그인 안내, 로그아웃, 히스토리 복원과 OAuth 오류에서 제거. 대기 조회 404만으로 지우지 않음 |
| 초대 안내 | 세션 `inviteOnboardingPending`과 첫 관측 회원 ID의 localStorage, 첫 탭의 sessionStorage로 가입 접속 구분. 경로와 무관하게 기록 |

탭 표시의 복제나 복원은 가능하므로 보안 경계로 사용하지 않는다. 동의 완료 여부는 localStorage에 저장하지 않는다. 제작과 결제의 저장소는 각 기능의 공용 저장소 계약을 적용한다. ([웹 저장소](2-2-REQUIREMENTS.md#2-2-1-게스트와-회원))

<br>

### 4-3-2 게스트 목록

| 상태 | 처리 |
|---|---|
| `null` | SSR 또는 미하이드레이션, 로딩 |
| `[]` | 읽기 완료, 빈 상태 |
| `string[]` | 비어 있지 않으면 배치 조회 |
| ID 변경과 재조회 | 이전 카드 유지, 현재 ID에 없는 카드 제외. 전체 골격으로 되돌리지 않음 |
| 새 생성 완료 | `unauthenticated` 확정 때만 로컬 ID 쓰기. 회원과 `loading`은 회원 목록 무효화만 수행 |

폴링 완료가 세션 판정보다 먼저 도착해도 회원 콘텐츠를 게스트 서재에 기록하지 않는다. 채팅 미리보기 필터는 CHAT 공용 구조를 사용한다. ([채팅 목록](4-3-STATE-MANAGEMENT.md#4-3-2-게스트-목록))

### 4-3-3 회원 동의 상태

| 상태 | 의미와 표시 |
|---|---|
| `guest` | 비로그인 확정, 대기 없음 |
| `checking` | 세션 판정, 동의 조회 또는 401 만료 처리 중 |
| `required` | 로그인한 회원의 동의 필요. 탭 표시와 무관 |
| `blocked` | 법적 문서에서 동의 필요. 시트 없이 회원 기능만 차단 |
| `satisfied` | 서버가 모든 필수 동의 완료 확인. `isMember`만 이때 참 |
| `load-error`, `forbidden` | 회원 조회의 일시 실패 또는 403 |
| `signup-required`, `signup-load-error` | 세션 없는 가입 대기 또는 대기 조회 일시 실패 |

| 상태 자료 | 수명과 갱신 |
|---|---|
| 회원 동의 | 사용자 ID를 포함한 쿼리 키, `staleTime: Infinity`. 기록 응답 반영 또는 사용자의 재시도로 갱신 |
| 선시작 조회 | 마운트 시 만료 시각 쿠키가 있으면 세션 판정과 병렬 조회. 회원 확정 시 한 번 인계, 게스트 확정 시 폐기 |
| 가입 대기 조회 | 비로그인, 탭 표시 있음, 법적 문서 아님일 때 페이지당 한 번. 자동 재시도 없음 |
| OAuth 오류 URL | 요청 직전 `/login?error=...` 확인, 대기 HTTP 조회 없이 `null` |
| 가입 종료 | 완료 이외 결과에서는 대기 쿼리를 `null`로 정리 |
| 체크 상태 | 요구 버전 묶음에 연결. 변경 시 초기화 |
| 선택 동의 답 | 가입 성공 후 선택 동의 스토어로 전달 |

쿠키는 선시작 힌트일 뿐 회원 판정의 근거가 아니다. 가입 전에 보낸 응답을 가입 완료 뒤 재사용하지 않는다.

<br>

### 4-3-4 프로필과 초대

| 대상 | 반영 조건 |
|---|---|
| 회원 정보 | 서버 `GET /auth/me`가 기준. UI 세션 상태와 동의 완료 상태를 구분 |
| 프로필 저장 | 성공 응답을 회원 캐시에 먼저 반영 |
| Auth.js 표시 정보 | `profileRefresh: true` 업데이트로 서버 회원 재조회. 응답 ID가 세션 사용자와 같을 때만 `name`, `image` 변경. 브라우저 입력은 신뢰하지 않음 |
| 프로필 재조회 실패 | 기존 세션 클레임 유지. 화면은 저장 응답 캐시를 우선하고 새로고침 첫 표시만 세션 값 사용 |
| 초대 안내 표시 | 가입 접속이 아니고 홈(`/`)일 때. 저장소 불가 시 미루지 않음 |
| 광고 동의 재질문 | 초대 안내 대기라도 가입 접속으로 미룬 상태이면 표시 가능 |
