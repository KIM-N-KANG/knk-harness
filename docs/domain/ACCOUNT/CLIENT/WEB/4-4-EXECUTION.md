# 4-4 ACCOUNT 웹 실행

<br>

### 4-4-1 소셜 인증과 가입

| 단계 또는 결과 | 실행 |
|---|---|
| 기본 로그인 | 공급자 인증 → Auth.js `signIn`의 서버 소셜 인증 → 회원 조회 검증 → 토큰 쿠키 확정 |
| `COMPLETED` | 토큰 기록, 같은 `account` 객체를 키로 `WeakMap`에 프로필 전달, `jwt` 콜백에서 사용 |
| `CONSENT_REQUIRED` | 세션 생성 없이 대기 쿠키 저장. 이전 BFF와 Auth.js 쿠키 정리 후 Auth.js `callbackUrl`로 복귀 |
| 가입 완료 | `signup-consent` Credentials에서 대기 코드를 `X-Manyak-Consent-Token`으로 전달 → 회원 검증 → 토큰 기록 → 대기 삭제 → 세션 생성 |
| 가입 실패 | `CredentialsSignin.code`: `expired`는 대기 없음 또는 401, `outdated`는 버전 또는 필수 항목 오류, `retryable`은 그 밖. 앞 두 경우만 대기 쿠키 삭제 |
| 소셜 호출 실패 | Auth.js `/login?error=AccessDenied` 복귀 |
| 회원 기능 시작 | 세션 확정 → 회원 동의 조회 → 필요 시 기록 → `satisfied` → 분석 식별, 이관, 초대 및 자동 조회 |

`@auth/core 0.41.2`가 `signIn`, `jwt`에 같은 `account`를 넘기는 전제를 사용한다. Auth.js 버전 변경 시 이 전달 경계를 확인한다.

| 공급자 | 인증 설정 |
|---|---|
| Google와 `link-google` | `checks: ['pkce', 'state', 'nonce']`. 팝업과 redirect에 같은 콜백, 기존 클라이언트 ID와 secret 사용 |
| Kakao | issuer `https://kauth.kakao.com`, `client_secret_post`, scope `openid` |
| 콜백 | `/api/auth/callback/{provider}`를 콘솔 등록과 일치시킴 |

<br>

### 4-4-2 토큰 재발급과 종료

| 조건 | 실행 |
|---|---|
| 유효 access 또는 재발급 성공 | BFF가 Authorization에 access 주입 |
| access 없음, refresh 있음 | 재발급 |
| 토큰과 세션 모두 없음 | 게스트 요청 |
| refresh 4xx 또는 유효 토큰 없이 Auth.js 세션만 남음 | 쿠키와 청크 정리, 401과 만료 헤더. 익명으로 통과시키지 않음 |
| 재발급 네트워크 오류와 5xx | 쿠키 유지. 기존 access가 있으면 전달 시도, 없으면 503 |
| 회원 요청의 서버 401 | 강제 재발급 한 번. 새 access이면 버퍼링한 본문으로 원 요청 한 번 재전송 |
| 위 강제 재발급 4xx | 쿠키 정리와 만료 응답 |
| 일시 실패로 같은 access 반환 | 재전송 없이 기존 401 전달. 게스트 401은 그대로 전달 |

1. 브라우저의 일반 API와 SSE는 만료 2분 전부터 단일 재발급 결과를 함께 기다린다.
2. 한 만료 시각에는 한 번만 시도한다. 시계 차이나 일시 실패 뒤에는 BFF의 만료 1분 전 재발급에 맡긴다.
3. 확정 만료이면 대기 요청도 401로 종료하고 능동 로그아웃을 시작한다. 만료 쿠키 없는 게스트는 호출하지 않는다.

BFF 중복 억제는 인스턴스 안에서만 유효하다. 탭 간 요청과 이미 진행 중인 요청은 서버의 직전 refresh 10초 유예를 사용한다.

| 종료 항목 | 처리 |
|---|---|
| 세션 쿠키 판정 | 값이 있는 쿠키와 청크만 세션으로 판단. 빈 쿠키와 토큰 없음은 게스트 |
| `__Secure-` 쿠키 삭제 | 운영 여부와 무관하게 `Secure` 포함. HTTPS 개발 환경도 동일 |
| 명시적 종료, 탈퇴, 만료 | 공통 로컬 정리로 기기 푸시 등록 삭제 및 폐기, 분석 식별, 탭 표시, 제작 복구와 완성 요청, 결제 확인 기록 정리 |
| 필수 동의 전 종료 | 회원 자료를 열지 않은 별도 종료 경로. 가입 대기이면 취소만 실행 |
| 서버 종료 실패 | 로컬 정리 계속. 탈퇴 정리는 204 이후 |

회원 상태와 저장 수명을 적용한다. ([4-3 ACCOUNT 웹 상태 관리](4-3-STATE-MANAGEMENT.md))

### 4-4-3 동의 게이트와 이관

| 처리 | 실행 |
|---|---|
| 회원 시트 잠금 | Drawer의 포인터 해제 금지, `onOpenChange` 무동작, 핸들 숨김과 swipe-ignore, 초기 초점 시트 |
| 뒤로가기 | 기본 래퍼 닫기를 끄고 직접 수신. 회원은 동의 거절 종료, 가입은 대기 DELETE와 탭 표시 삭제 |
| 히스토리 복원 | 마운트의 `back_forward` 또는 `pageshow.persisted`에서 미완료 표시와 대기 취소. bfcache 복원은 정리 후 다시 불러옴 |
| 게스트 동의 | 한 동작 대기, 회원 완료이면 통과, 세션 판정 중이면 차단. 동작별 마운트마다 서버 조회 |
| 게스트 조회 수명 | 사용하지 않는 캐시 즉시 제거, 포커스 복귀 자동 재조회 없음 |
| 응답 검증 | 비어 있지 않은 버전과 boolean `needsConsent`. 저장 응답은 제출 버전 일치 및 `false` 확인 |
| 버전 충돌 | 상세 표시와 재조회. 자동 제출 없음 |
| 게스트 시트 히스토리 | 공용 히스토리의 close 레이어, 제작 가드보다 위. 승인과 거절 시 레이어를 먼저 소비, 승인된 대기 요청만 재개 |
| 게스트 취소 | 경로, 인증 변경과 언마운트 뒤 응답 무시. 열린 상태를 투어에 전달 |
| 기기 식별 | 기존 `X-Manyak-Device-Id` 사용. 운영은 Amplitude 또는 기존 쿠키, 개발은 기존 폴백. 동의 전용 ID 생성 안 함 |
| 이전 동의 기록 | `manyak:guest-consent`와 메모리 폴백 읽기 및 쓰기 중단. 서버의 다른 게스트 API 권한 검사를 대신하지 않음 |
| 제작 진입 | 회원 또는 게스트 확정이면 퍼널, 판정 중 스피너. 진입용 게스트 동의 화면 없음 |
| 이관 정리 | `MIGRATED`, `ALREADY_OWNED`, `CONFLICT`, `NOT_FOUND`만 제거. `migrationClosed`는 보존과 계정별 재시도 중단 |
| 이관 입력 400 | 유효 UUID만 한 번 재제출, 손상 ID 폐기. 평가 전 실패는 다음 방문 재시도 |

로그인 callback은 현재 pathname, search와 hash를 앱 내부 경로로 검증한다. 인앱도 같은 시작 함수와 이관 경로를 사용한다.

### 4-4-4 계정 연동

1. 확인 후 현재 공급자를 새로 인증하고 `/auth/links/reauth`로 링크 코드를 받는다.
2. 링크 코드를 HttpOnly 쿠키에 두고 `/my/link/continue?target=`에서 대상 공급자를 인증한다.
3. `/auth/links/{provider}`에 `X-Manyak-Link-Code`를 전달하고 회원 정보를 다시 읽는다.

| 조건 | 실행 |
|---|---|
| 연동 공급자 | 자격증명을 명시한 `link-google`, `link-kakao`. 전용 콜백 등록 필요 |
| Google 재인증 | 현재 세션의 `login_hint` 사용 가능 |
| 연동 콜백 | 기존 세션 쿠키를 복호화해 원래 클레임 반환. 세션 없으면 실패, 새 OAuth 프로필로 교체 금지 |
| 단계 판정 | 서버가 콜백 공급자의 기존 연동 상태로 판정 |
| 연동 실패 | 공통 응답 변환 적용, 403과 409를 재발급이나 세션 종료로 처리하지 않음 |
| 현재 연동 방식 | 같은 탭의 두 인증. 연동 완료 확인용 팝업 미지원으로 인앱 진입 제한 |

<br>

### 4-4-5 인증 팝업

1. 클릭 중 빈 팝업을 열고 Auth.js에서 인가 URL을 받는다. 허용 호스트는 `accounts.google.com`, `kauth.kakao.com`이다.
2. 같은 문서에서 중복 시작을 막는다. Google은 별도 SDK나 Credentials 공급자 없이 Auth.js의 PKCE, state, nonce를 사용한다.
3. 완료 알림의 origin, source와 시도 UUID를 모두 확인한다.
4. Auth.js 세션과 인증용 회원 응답 ID가 일치하면 검증된 상대 경로로 `location.replace`한다. 가입 대기이면 회원 조회 없이 원래 탭으로 돌아가 동의 절차를 잇는다.

| 상황 | 실행 |
|---|---|
| 완료 응답 | 루트 레이아웃 미실행, `no-store`, `no-referrer`, 인라인 스크립트 nonce와 프레임 차단 CSP |
| 원래 탭 확인 | 닫힘, focus, visibility 복귀를 확인 계기로 사용. 알림 자체를 자격증명으로 사용하지 않음 |
| COOP로 참조 단절 | `closed`만으로 취소 확정 안 함. 완료 또는 5분 만료까지 대기 |
| 명시적 실패와 OAuth 오류 | 팝업 정리와 실패 반환 |
| 5분 만료 | 리스너, 타이머와 UI 잠금 정리. 인증창 유지 |
| 재시도 | 가능한 이전 창 정리. 이전 시작 HTTP 응답 전에는 새 시작 금지 |
| 늦은 응답 | 세션 및 회원 조회의 await 뒤 시도 종료 검사. 종료된 시도로 이동 금지 |
| opener 없음 | 수동 복귀 안내. 분리된 쿠키 저장소에는 메시지만으로 세션 생성 불가 |
| bfcache 복원 | 로그인 진행 잠금 해제 |

문서 범위의 잠금은 분리된 창이나 서버의 진행 중 인증을 취소하지 않는다. 외부 핸드오프와 `/login/continue`는 제공하지 않는다. ([2-2-4 인앱과 인증 팝업](2-2-REQUIREMENTS.md#2-2-4-인앱과-인증-팝업))
