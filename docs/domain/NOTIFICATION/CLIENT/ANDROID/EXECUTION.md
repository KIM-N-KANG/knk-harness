# Android NOTIFICATION 실행

기준: [연동 계약](../CONTRACT.md), [Android 상태](STATE-MANAGEMENT.md).

<br>

### 조회와 읽음

- 셸 ON_RESUME마다 공지 첫 페이지를 다시 읽고 기기 읽음 흐름과 합쳐 마이 배지를 갱신한다. 회원 헤더 점은 별도의 안 읽은 알림 수 조회로 정한다.
- 공지 목록은 커서를 이어 붙이며 상세 성공이 읽음 기록을 추가한다. 상세 404는 기록하지 않는다.
- 알림 목록 조회와 읽음 요청은 하나의 Mutex로 순서를 맞춰 이전 응답이 읽음 표시를 되돌리지 않게 한다. 한 건은 결과와 관계없이 이동하고 모두 읽음만 실패 때 전체 스냅숏을 복원한다. 구성 변경으로 읽음 요청을 재실행하지 않는다.

<br>

### 등록과 수신

1. 회원 세션과 MemberConsent.isSatisfied를 확인한다. getToken과 onNewToken을 같은 직렬 등록 경로로 처리한다.
2. 조회 중 동의가 초기화되면 취소하고 요청 직전에도 다시 확인한다. 같은 세션에서 성공한 같은 토큰은 건너뛰며 새 토큰과 새 세션은 PUT한다.
3. 네트워크와 5xx는 다음 등록 계기에 재시도한다. 403은 generation을 확인하는 세션 commit에서 ACCOUNT_SUSPENDED 종료로 넘긴다. 401 재발급은 공용 인증 경계다.
4. 로그아웃은 등록기를 차단하고 합류한 뒤 세션 장벽 전에 제한 시간 안에서 토큰 삭제를 시도한다. 삭제 성공과 관계없이 표시 및 탭 수신자 검증을 유지한다.
5. 수신 recipientId를 현재 회원과 비교한다. Pending과 프로필 대기는 합계 최대 5초이며 확인하지 못하면 버린다. 표시 직전에도 다시 확인한다.
6. 서비스 채널은 HIGH와 PRIVATE, 마케팅은 DEFAULT와 PUBLIC이다. type와 target으로 안정 ID를 만들며 검수 알림 target은 submissionId다.
7. 검수는 APPROVED, REJECTED, FAILED만 수신하고 서버 제목 및 본문을 쓴다. 제목이 없으면 표시하지 않으며 표시 직전 검수 화면의 관찰 정보를 질의해 중복을 억제한다.

<br>

### 탭 진입과 동의

- deepLink가 있으면 허용 URL 해석 결과만 사용하고 실패해도 type 매핑으로 되돌아가지 않는다. 없는 이전 payload만 스토리 완성은 storyId 상세, 검수 완료는 submissionId 필수의 제작 탭, 출석은 이프, 프로모션 및 미지원과 누락은 홈으로 대응한다.
- onCreate와 onNewIntent의 진입을 SavedStateHandle로 전달한다. 회원과 프로필을 확인하고 recipient가 일치할 때 소비하며 다른 계정이면 홈으로 보낸다.
- 앱 열기 전용 스킴 진입은 공용 앱 링크 경계에서 처리한다. 푸시 extra가 함께 있으면 푸시가 우선이다.
- Android 13 이상 권한 안내는 설치당 한 번이며 거부해도 세션과 토큰 등록은 유지한다.
- 첫 선택 동의 허용은 GET으로 서비스 값을 읽고 광고만 켠 PUT 뒤 통지한다. 저장과 통지의 busy 동안 새 권한 및 초대 안내를 시작하지 않는다.
- 루트가 권한과 필수 동의, 초대 코드 pending 종료를 기다린 뒤 재질문을 허용한다. claimPrompt, 기기 알림 활성과 서버 marketingPush false를 모두 확인한다.
- 첫 거절 뒤 재진입을 세어 세 번째부터 질문 대상으로 삼는다. 두 번째 거절과 허용은 닫힘 단계로 저장한다. 답한 뒤 기록하고 저장 실패는 시트를 유지한다. 회원 세션이 아니게 되면 준비 상태를 초기화해 같은 프로세스 재로그인도 판정한다.
- 처리 결과 시각은 의사 표시 시점이며 재질문과 설정이 같은 다이얼로그를 사용한다.
