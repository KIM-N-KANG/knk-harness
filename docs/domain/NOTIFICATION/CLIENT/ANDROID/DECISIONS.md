## A-032. 푸시 삭제와 수신자 검증을 분리

- 결정일: 2026-09-08 · 기록 확정 상태: Accepted
- 근거: [이관 원문 A:1363](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-3-android-app.md#L1363-L1374)
- **맥락:** 등록·삭제가 경합하고 세션 장벽 이후에는 필요한 재발급이 차단됩니다.
- **결정:** 등록기를 차단하고 합류한 뒤 세션 장벽 전에 제한 시간 안에서 삭제를 시도합니다.
- **이유:** 원격 삭제 성공만으로 이미 접수된 등록과 계정 격리를 보장할 수 없습니다.
- **주요 영향:** 이전 계정 표시·탭은 recipientId·세션 검증으로 차단하며 삭제 실패 잔존을 수용합니다.

## A-033. 알림 권한 요청은 메인 그래프 첫 진입

- 결정일: 2026-09-08 · 기록 확정 상태: Accepted
- 근거: [이관 원문 A:1376](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-3-android-app.md#L1376-L1383)
- **맥락:** 알림 권한을 요청할 사용자 흐름을 선택해야 했습니다.
- **결정:** 회원 메인 그래프에 처음 진입할 때 권한을 요청합니다.
- **이유:** 요청 시점을 루트 한 곳에서 관리하는 초기 선택입니다.
- **주요 영향:** 허용률을 보고 후속 결정으로 변경할 수 있으나 기존 기록은 덮어쓰지 않습니다.

## A-040. 광고 알림 동의는 첫 진입 시트로 묻고 즉시 통지

- 결정일: 2026-09-11 · 상태: Accepted
- 대체 관계: 첫 질문 자리와 "물었음" 단일 플래그는 [A-044](../../../ACCOUNT/CLIENT/ANDROID/DECISIONS.md#a-044)가 대체합니다. 즉시 통지·야간 분리·고지 정본 결정은 유지합니다.
- **맥락:** 서버와 설정 화면은 광고·야간 동의를 옵트인으로 저장하지만 먼저 묻는 흐름과 처리 결과 통지가 없었습니다. 정보통신망법 제50조는 앱 푸시 광고에 사전 동의, 야간 별도 동의, 14일 이내 처리 결과 통지, 2년 주기 재확인을 요구하며 OS 알림 권한 허용은 동의로 인정되지 않습니다. 로그인 버튼을 약관 동의로 간주하는 현재 모델에 광고 동의를 끼우면 무효입니다.
- **선택:** 회원 그래프 첫 진입에서 권한 응답과 초대 코드 안내가 끝난 뒤 바텀 시트로 한 번 묻습니다. "물었음"은 사용자 귀속 DataStore에 두고 로그아웃에 정리하며, 서버가 이미 동의 상태이거나 기기 알림이 꺼져 있으면 묻지 않습니다. 동의·철회를 처리한 즉시 전송자·일시·처리 내용을 다이얼로그로 통지하고 일시는 의사 표시 시점의 기기 시각을 씁니다. 고지 정본은 개인정보 처리방침의 광고성 정보 수신 동의 절이며 시트에는 고지를 싣지 않고 설정 화면의 광고 행이 문서를 엽니다.
- **이유:** 시트는 알림의 가치를 이해한 뒤 묻는 자리이고, 즉시 통지는 별도 발송 경로 없이 14일 기한을 충족합니다. 서버에 "물었음"을 두지 않은 것은 API 계약을 늘리지 않기 위해서이며, 대신 재로그인 시 거절자에게 한 번 더 묻는 한계를 받아들였습니다.
- **주요 영향:** 2년 재확인 발송과 광고 페이로드의 전송자 연락처·수신 거부 문구는 서버 과제로 남습니다. 반복 노출이 문제되면 서버 필드로 올리는 후속 결정으로 대체할 수 있으며 이 기록은 보존합니다.
- 근거: [KNK-1254](https://kimandkang.atlassian.net/browse/KNK-1254), [Android 계획](../../../../../../manyak-android/docs/plans/marketing-consent.md)

## A-045. 알림 진입 목적지는 서버 deepLink를 정본으로 해석

- 결정일: 2026-09-20 · 기록 확정 상태: Accepted
- 대체 관계: [A-034](DECISIONS.md#a-034)의 수신자 재검증은 유지하고, 그 뒤의 목적지 결정만 `type` 매핑에서 URL 해석으로 바꿉니다. `type` 매핑은 `deepLink`가 없는 payload의 하위 호환으로 남습니다.
- **맥락:** 서버가 스토리 완성·출석 리마인드 payload에 `deepLink`를 싣기 시작했습니다(KNK-1335, v0.5.1). 앱은 `type`·식별자로 목적지를 정하고 있어 두 알림 모두 이미 올바른 화면에 도착하지만, 서버가 목적지를 바꾸거나 새 알림을 추가할 때마다 앱 매핑을 갱신해야 했습니다. 서버 스펙은 "앱이 호스트·경로 허용 목록으로 검증한 뒤 이동, 허용하지 않으면 홈"을 앱 계약으로 두었습니다.
- **결정:** `deepLink`가 있으면 `:navigation`의 `DeepLink`가 `https` + `manyak.app`·`www.manyak.app`의 `/stories/{id}`·`/my/credits`만 내부 라우트로 바꾸고 그 외는 홈입니다. 해석에 실패해도 `type` 매핑으로 되돌아가지 않습니다. `deepLink`가 없을 때만 기존 `type` 매핑을 씁니다. `PushEntry`는 `deepLink` 문자열을 extra 하나로 더 싣고 기존 extra는 유지합니다. 이프 충전의 `tab` 쿼리는 읽지 않습니다.
- **이유:** URL을 정본으로 두면 서버가 목적지를 옮겨도 허용 목록 안에서는 앱 업데이트 없이 따라갑니다. 실패 시 `type`으로 되돌리면 서버가 목적지를 바꾼 뒤에도 구 매핑으로 가 서버 의도와 어긋나므로 홈으로 떨어뜨립니다. `type` 매핑을 남기는 것은 업데이트 전에 만든 PendingIntent와 `deepLink`가 없는 프로모션 때문입니다. 파서를 `java.net.URI`로 두는 것은 `android.net.Uri`가 JVM 유닛 테스트에서 빈 스텁이라서이고, 같은 파서를 뒤의 공유 URL App Links(KNK-927·928)가 재사용합니다. 탭 파라미터는 무료 탭이 기본이라 두 번째 사용처가 생기기 전에는 라우트에 싣지 않습니다.
- **주요 영향:** 사용자에게 보이는 동작은 바뀌지 않습니다. App Links(HTTPS intent-filter·`assetlinks.json`)는 이 결정에 포함하지 않습니다. 웹 이프 충전 화면은 `?tab=` 쿼리를 아직 읽지 않습니다(웹 몫).
- 근거: [KNK-1348](https://kimandkang.atlassian.net/browse/KNK-1348), [Android 계획](../../../../../../manyak-android/docs/plans/push-deeplink.md)

## A-079. 공지 읽음 기록을 기기 DataStore에 두고 안 읽음 판정을 셸 수명 ViewModel 하나에 모으기

- 결정일: 2026-10-24 · 기록 확정 상태: Accepted
- **맥락:** 공지사항(KNK-1817)은 서버에 읽음 기록이 없고, 공통 계약은 "상세를 연 공지 ID 목록(최근 100개)과 게시 30일"로 안 읽음을 판정해 헤더 점, 마이 배지, 목록 줄 점이 같은 값을 보게 했습니다. 웹은 `localStorage`의 JSON 배열과 `useSyncExternalStore`로 구현했습니다. Android는 헤더를 `app`의 셸이, 마이 메뉴를 `my`가, 목록을 새 `notice`가 그려 세 곳이 한 판정을 봐야 했습니다.
- **결정:** 읽은 ID는 `notice`의 `NoticeReadStore`가 기기 귀속 `@DeviceDataStore`의 `notice_read_ids` 키에 최신순 JSON 배열 문자열로 둡니다. 회원 귀속이 아니라 `UserScopedStore`에 참여하지 않습니다. 안 읽음 판정은 `NoticeUnreadViewModel`이 목록 첫 페이지와 읽은 ID 흐름으로 계산하고 `app`의 `MainTabsScreen`이 셸 수명으로 들어 `ON_RESUME`마다 다시 읽으며, 헤더 버튼은 `designsystem` 헤더의 `actions` 슬롯으로, 마이 배지는 `MyScreen`의 Boolean 인자로 내립니다. 공개 API는 `@PlainClient`로 토큰 없이 부릅니다.
- **이유:** Preferences의 문자열 집합은 순서가 없어 "최근 100개"를 지킬 수 없고, Room 테이블은 ID 목록 하나에 과합니다. 웹과 같은 기기 단위라 로그아웃에 지우면 같은 기기의 다음 사용자에게 읽은 공지가 다시 새 공지로 보여 계약과 어긋납니다. 판정을 `common` 계약으로 올려 `my`가 직접 관찰하게 하면 두 번째 소비처 전에 공유 계약이 생기고, 셸이 이미 마이에 콜백 여럿을 내리는 자리라 값 하나를 더 내리는 것이 가장 짧습니다. 공지 조회에 인증 클라이언트를 쓰면 만료 토큰 재발급이 공지 요청에 엮입니다.
- **주요 영향:** 안 읽음 판정은 첫 페이지 20건 안에서만 봅니다. 그 뒤 공지는 대개 30일을 넘겼고, 넘기지 않았어도 점이 꺼질 뿐 목록에는 그대로 있습니다. 읽음 저장 실패는 조용히 무시해 다음에 점이 한 번 더 보입니다. 회원별 알림함이 생기면 헤더 버튼의 목적지만 바꾸면 됩니다.
- 근거: [FE-SCREEN-014](../2-2-REQUIREMENTS.md#2-2-2-공지사항), [Android 공지사항](../../../../client/ANDROID/3-3-LAYOUT.md#3-3-1-셸과-조작), [KNK-1819](https://kimandkang.atlassian.net/browse/KNK-1819), [KNK-1819 계획](../../../../../../manyak-android/docs/plans/knk-1819-notices.md)
