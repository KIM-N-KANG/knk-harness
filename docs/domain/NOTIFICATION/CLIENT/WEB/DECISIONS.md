# DECISIONS.md

현재 적용 기준은 각 명세에 두고 결정 당시의 이유와 대체 관계는 이 문서에 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다. 기존 ID, 날짜, 당시 상태와 근거를 유지한다.
- 상태와 구현 설명은 원본의 기록 시점을 기준으로 해석한다. 현재 적용 여부나 배포 완료를 과거 기록만으로 단정하지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체하는 결정과 적용 범위를 명시한다.
- 원문에 구분되지 않은 배경, 대안과 영향은 추측해서 보충하지 않는다.

**W-018. 웹 푸시는 Firebase 토큰 SDK와 제작 직후 프롬프트로 도입**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-09-22 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 서버는 `platform=WEB` 토큰 등록과 webpush notification 발송을 이미 지원했지만 웹에는 매니페스트, 서비스 워커, 토큰 등록이 없었다. Next.js PWA 가이드는 순수 Web Push(`PushSubscription`+VAPID 서버 액션)를 쓰는데 서버는 FCM 토큰으로 발송한다. |
| 채택 | Firebase JS SDK의 `getToken`/`deleteToken`으로 FCM 등록 토큰을 받아 기존 토큰 API에 등록하고, 서비스 워커는 compat SDK 초기화만 두어 표시, 클릭을 브라우저와 SDK에 맡긴다. 오프라인 캐싱, next-pwa, Serwist, 커스텀 push 핸들러는 두지 않는다. 알림 권한은 Android처럼 회원 화면이 처음 열릴 때 기기당 한 번 자동으로 묻되, 신규 회원은 필수 동의 시트의 제출 클릭(사용자 제스처) 직전에 묻는다. 광고 동의는 필수 동의 시트의 "[선택]" 항목으로 먼저 받고 첫 거절 뒤 세 번째 재진입(페이지 로드)에서 재질문 시트로 한 번 더 묻는다. 설정은 마이 > 알림 설정에서 서비스, 광고, 야간을 전체 교체 PUT으로 저장하고 광고, 야간 변경마다 처리 결과 다이얼로그를 표시한다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 토큰 기반이 서버, Android와 같은 계약이라 서버 변경 없이 동작한다. SDK 12가 권고하는 FID 기반 `register`는 서버 발송 대상과 토큰 테이블 계약을 함께 바꿔야 하므로 미룬다. Android와 같은 시점, 문구로 맞춰 두 플랫폼의 동의 규칙을 하나로 유지한다. 브라우저는 제스처 없는 권한 요청을 무시할 수 있어(Safari) 동의 시트의 제출 클릭과 알림 설정의 버튼을 제스처 경로로 둔다. 정보통신망법 제50조의 사전 동의, 야간 별도 동의, 처리 결과 통지는 Android와 같은 문구, 규칙을 쓴다. |
| 영향 | Firebase 웹 앱 설정 5개가 Vercel, `.env.local`에 필요하며 비면 전체가 꺼진다. E2E는 VAPID 키를 비워 푸시를 끄므로 권한 요청, 토큰 등록, 재질문 시트는 실기기 수동 검증이다. 백그라운드 알림은 `recipientId`를 대조할 수 없어 로그아웃 토큰 삭제가 방어선이다. 개인정보 처리방침의 푸시, 광고 동의 고지가 Android 앱 기준이라 웹 푸시 포함 개정(서버 요구 버전 상향과 같은 릴리스)이 선행돼야 한다. |
