# 1. 배경

이 문서는 마냑의 푸시 알림, NOTIFICATION 도메인에서 백엔드가 맡는 역할, 관련 주체와 공통 용어를 정한다.

<br>

### 1-1 도메인

NOTIFICATION 도메인은 회원의 기기로 푸시 알림을 보내는 일을 다룬다. 앱과 웹이 받은 푸시 토큰을 회원과 연결하고 회원의 수신 동의에 따라 알림을 보낸다. 서비스 알림에는 스토리 완성과 검수 완료가 있다. 광고 알림에는 출석 리마인드와 프로모션이 있다.

<br>

### 1-2 서비스 배경

마냑은 사용자가 스토리와 세계관을 만들고 채팅으로 AI와 함께 이야기를 이어가는 AI 인터랙티브 스토리 서비스다. 간편 제작과 검수는 시간이 걸려 사용자가 앱을 떠난 뒤 끝나는 일이 많다. 결과를 알리려면 푸시가 필요하다. 광고성 알림에는 법에 따라 사전 동의와 야간 별도 동의, 광고 표기가 필요하다. 푸시는 회원 전용이고 게스트는 받지 않는다.

| 흐름 | 사용자가 하는 일 |
|---|---|
| 알림 권한과 동의 | 가입 시 광고성 알림 수신 동의를 선택하고 기기의 알림 권한에 응답<br>동의하면 처리 결과를 안내받음 |
| 토큰 등록 | 앱이나 웹을 열면 기기의 푸시 토큰이 계정에 등록됨<br>로그아웃하면 그 기기의 토큰이 삭제됨 |
| 스토리 완성 알림 | 간편 제작이 끝나면 알림을 받고 눌러서 스토리로 이동 |
| 검수 완료 알림 | 제출한 스토리의 검수가 끝나면 통과, 반려, 실패를 알림으로 받고 내 제작 목록으로 이동 |
| 출석 리마인드 | 광고 수신에 동의한 회원은 아침에 출석 보상 안내를 받음 |
| 프로모션 | 광고 수신에 동의한 회원은 운영자가 예약한 소식을 받음 |
| 알림 설정 | 서비스 알림, 광고 알림, 야간 광고 알림을 각각 켜고 끔<br>광고 알림과 야간 광고 알림 설정을 바꾸면 처리 결과를 안내받음 |

<br>

### 1-3 백엔드의 역할

기기의 알림 권한과 표시는 클라이언트와 플랫폼이 맡는다. 백엔드는 발송 대상과 자격을 판정하고 발송 요청과 결과를 관리한다.

| 작업 | 역할 |
|---|---|
| 토큰 관리 | 회원마다 기기 토큰을 저장하고 같은 기기에서 계정이 바뀌면 소유자를 옮김<br>회원당 기기 수를 제한하고 탈퇴 시 전부 삭제 |
| 수신 동의 | 서비스 알림과 광고 알림, 야간 광고 알림의 동의를 저장<br>광고 동의는 동의 시각을 증빙으로 보존 |
| 발송 자격 | 발송 직전에 계정 상태, 종류별 동의, 토큰 보유를 판정 |
| 발송 요청 | 완성과 검수 결과를 저장할 때, 예약 발송 회차에 발송 요청을 기록하고 큐로 중계 |
| 예약 발송 | 출석 리마인드와 프로모션 대상을 조회해 회원마다 발송 요청을 기록 |
| 문구 | 출석 리마인드 문구를 릴리스 없이 바꾸는 오버라이드 제공<br>광고 알림에 광고 표기를 붙임 |
| 발송 실행 | 알림 서비스가 큐를 소비해 멱등하게 FCM으로 보냄<br>무효 토큰은 삭제 |
| 수신자 식별 | 모든 푸시에 수신 회원 식별자를 실어 기기를 공유해도 다른 회원의 알림이 보이지 않게 함 |
| 다른 도메인에 전달 | 계정: 탈퇴 시 토큰 삭제<br>스토리와 검수: 완성과 검수 완료 알림 발행<br>이프: 출석 미수령 판정 |

<br>

### 1-4 주체

| 주체 | 정의 | 이 도메인에서 하는 일 |
|---|---|---|
| 게스트 | 로그인 없이 서비스를 쓰는 사용자 | 알림 대상 아님 |
| 회원 | 소셜 로그인으로 가입한 사용자 | 토큰 등록, 수신 동의 설정, 알림 수신 |
| 클라이언트 | 사용자가 쓰는 웹과 Android 앱 | 알림 권한 요청, 토큰 발급 요청, 등록과 삭제, 알림 표시와 이동, 수신자 대조 |
| FCM | 푸시 전달 제공자 | 토큰 발급, 기기로 메시지 전달, 무효 토큰 통지 |
| 운영자 | 팀 구성원 | 프로모션 예약, 문구 변경, 실패 메시지 확인 |

<br>

### 1-5 공통 용어

| 용어 | 의미 |
|---|---|
| 푸시 토큰 | FCM이 기기의 앱 설치본마다 발급하는 주소<br>전역 유일 |
| 설치본 | 한 기기에 설치된 앱 또는 브라우저 하나<br>토큰 하나에 대응 |
| 서비스 알림 | 사용자가 유발한 작업의 결과 통지<br>스토리 완성, 검수 완료<br>기본 켜짐이며 끌 수 있음 |
| 광고 알림 | 재이용을 유도하는 알림<br>출석 리마인드, 프로모션<br>사전 동의가 있어야 보냄 |
| 야간 광고 알림 | KST 21:00부터 08:00 전까지 보내는 광고 알림<br>별도 동의가 있어야 보냄 |
| 수신 동의 | 회원이 알림 종류별로 정한 수신 여부<br>광고 동의는 최초 동의 시각으로 저장 |
| 발송 자격 | 발송 직전에 판정하는 조건<br>활성 계정, 종류별 동의, 등록 토큰 |
| 발송 요청 | 어느 회원에게 어떤 알림을 보낼지 담은 메시지<br>동의와 토큰은 담지 않음 |
| 아웃박스 | 완성과 검수 결과를 저장할 때 함께 남기는 발송 요청 기록<br>릴레이가 큐로 옮김 |
| 메시지 큐 | 서버의 발송 요청을 알림 서비스로 전달하는 큐 |
| 릴레이 | 아웃박스의 미발행 행을 선점해 큐에 발행하는 주기 작업 |
| 소비자 | 큐에서 발송 요청을 받아 처리하는 알림 서비스의 구성 요소 |
| 멱등 기록 | 같은 발송 요청을 두 번 처리하지 않게 메시지 식별자별로 남기는 기록 |
| 메시지 식별자 | 시나리오별 규칙으로 만든 발송 요청의 고유 값<br>재발행과 재전달에도 바뀌지 않음 |
| 재전달 | 큐가 처리되지 않은 메시지를 소비자에게 다시 주는 것 |
| 실패 메시지 큐 | 재전달 상한을 넘긴 메시지를 보존하는 큐<br>운영자가 확인하고 되돌림 |
| 수신자 식별자 | 모든 푸시에 싣는 수신 회원의 공개 식별자<br>앱이 현재 회원과 대조 |
| 딥링크 | 알림을 눌렀을 때 열 주소<br>운영 웹 주소에 시나리오 경로를 붙임 |
| 문구 템플릿 | 출석 리마인드 제목과 본문의 오버라이드 행<br>적용 기간이 있음 |
| 캠페인 | 운영자가 예약한 프로모션 1건<br>문구, 예약 시각, 상태, 발송 결과가 있음 |
| 무효 토큰 | FCM이 더 이상 유효하지 않다고 알린 토큰<br>즉시 삭제 |
| 광고 표기 | 광고 알림 제목 앞에 붙이는 `(광고)` |
