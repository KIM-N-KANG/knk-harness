# 3-3 구현 컨벤션

이 문서는 NOTIFICATION 도메인 코드를 작성하거나 수정할 때 반드시 지킬 규칙과 구현자가 선택할 수 있는 사항을 정한다.

트랜잭션과 잠금은 동시성에, 로그 이벤트 규칙은 관측에, 비밀값 취급은 보안에, 구현 위치는 AGENTS.md에 있다. ([5-2 동시성](5-2-CONCURRENCY.md), [5-4-3 구조화 로그 이벤트](5-4-OBSERVABILITY.md#5-4-3-구조화-로그-이벤트), [5-1-7 비밀값과 개인정보](5-1-SECURITY.md#5-1-7-비밀값과-개인정보), [AGENTS.md](AGENTS.md))

<br>

### 3-3-1 이름과 용어

| 대상 | 규칙 |
|---|---|
| 패키지 | 서버는 푸시 패키지 아래에 API 계층, 전송 객체, 모델, 저장 계층, 서비스, 이벤트, 아웃박스, 스케줄러, 설정을 나눔<br>관리자 API 계층은 같은 패키지에 두고 이름에 관리자임을 드러냄<br>알림 서비스는 소비자, 클라이언트, 서비스, API 계층, 설정 |
| 모델 이름 | 테이블의 단수형 |
| 전송 객체 | 요청은 `Request`, 응답은 `Response`를 접미사로 사용<br>와이어 필드는 camelCase<br>DB 컬럼은 snake_case |
| 시나리오 식별자 | 푸시 데이터의 `type`과 큐 메시지의 `type`은 같은 대문자 값 |
| 알림 종류 | `SERVICE`, `MARKETING`의 대문자 enum<br>캠페인 종류도 같은 enum |
| 메시지 식별자 | `{시나리오}:{식별자}` 형식의 소문자 접두부 |
| 템플릿 키 | 저장은 snake_case<br>코드는 enum |
| 용어 | 용어집을 따름 |

<br>

### 3-3-2 계층 책임

| 계층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| API 계층 | 형식 검증, 요청자 식별, 상태 코드 지정 | 비즈니스 판정, 저장 계층 호출 |
| 캠페인 관리 서비스 | 상태 전이 판정, 공지 알림 캠페인 생성, 대상 수 집계, 감사 기록 호출 | 발송, 회차 실행 |
| 내부 인증 필터 | 공유 시크릿 비교, 미설정 시 숨김 | 요청자 식별 |
| 토큰과 동의 서비스 | 사용자 행 잠금, 상태 재검사, 소유자 판정 | 발송 |
| 발송 자격 서비스 | 상태, 동의, 야간, 토큰 판정 | 발송, 토큰 변경 |
| 리스너 | 모드에 따른 발송 경로 선택 | 발송 결과로 도메인 상태 변경 |
| 릴레이와 어댑터 | 선점, 발행, 결과 기록 | 메시지 본문 변경 |
| 발송기 | 플랫폼별 메시지 구성, FCM 호출, 결과 분류<br>FCM 호출은 도메인 트랜잭션 밖에서 수행<br>무효 토큰 삭제만 예외([4-1-13 발송과 무효 토큰 정리](4-1-PIPELINES.md#4-1-13-발송과-무효-토큰-정리)) | 토큰과 동의 변경 |
| 소비자 | 검증, 멱등 선점, 결과 판정 | 브로커별 확인 방식 |
| 저장 계층 | 쿼리 실행<br>잠금이 필요한 조회 메서드는 이름에 잠금 여부 표시<br>소유자 조건은 삭제문 안에 둠 | 비즈니스 판정 |

<br>

### 3-3-3 요청 검증과 오류

| 대상 | 규칙 |
|---|---|
| 개별 필드의 길이, 필수 여부, 허용값 | 요청 객체의 필드에 애너테이션으로 선언 |
| 동의 변경의 세 필드 | 요청 객체를 널 불허 타입으로 선언해 역직렬화 단계에서 거절 |
| 검증 정책 | 거절 조건과 큐 메시지 검증은 [5-1-5 입력 검증](5-1-SECURITY.md#5-1-5-입력-검증)에 있음 |

<br>

### 3-3-4 이벤트와 비동기

| 대상 | 규칙 |
|---|---|
| 완성과 검수 이벤트 | 도메인 상태를 기록하는 트랜잭션 안에서 발행<br>로컬 모드 리스너는 커밋 후 전용 실행기에서 발송<br>원격 모드 리스너는 같은 트랜잭션에 참여하고 트랜잭션이 없으면 거부 |
| 전용 실행기 | 푸시 발송은 전용 스레드 풀<br>요청의 상관 식별자를 워커로 전파<br>포화 시 발송을 버리고 경고 |
| 스케줄러 | 예외를 밖으로 내보내지 않음 |
| 정책값과 문구 | 회차 시작 시 한 번만 읽어 같은 회차에 두 문구가 섞이지 않게 함 |

<br>

### 3-3-5 테스트와 검증 도구

| 대상 | 규칙 |
|---|---|
| 작성 순서 | 동작을 바꾸는 작업은 실패하는 테스트를 먼저 작성 |
| 엔드포인트 변경 | 통합 테스트와 수동 호출 파일을 함께 갱신 |
| 동시성 | 잠금, 선점, 멱등 규칙을 바꾸면 동시 요청 테스트로 검증 |
| 시각 | KST 야간 경계와 유효 기한은 주입한 시계로 검증 |
| 재시도 설정 | 간격을 줄인 테스트는 처리 중 선점 시간과 처리 예산도 함께 줄임 |

<br>

### 3-3-6 구현자가 선택할 수 있는 것

| 선택 가능 | 조건 |
|---|---|
| 서비스 내부의 메서드 분할과 이름 | 없음 |
| 테스트 픽스처와 FCM 스텁의 구성 | 없음 |
| 조회 쿼리의 작성 방식 | 잠금 여부와 소유자 조건을 유지 |
| 로그 필드 추가 | 토큰 원문, 동의 시각, 공유 시크릿, FCM 자격 증명을 넣지 않음 |
| 스레드 풀과 폴링 크기 | 알림 서비스의 처리 예산과 선점 시간 관계를 유지 |
