# 5-5 테스트 케이스

이 문서는 NOTIFICATION 도메인 코드의 계약과 오류 처리 규칙을 검증할 테스트 범위, 입력과 상황, 기대 결과를 정한다.

실행 명령과 수동 호출 파일 위치는 AGENTS.md에, 기대 결과의 상태 코드는 계약에 있다. ([AGENTS.md](AGENTS.md), [4-2 계약](4-2-CONTRACT.md))

<br>

### 5-5-1 테스트 범위

**1. 테스트 종류**

| 종류 | 확인 범위 | 외부 호출 | 실행 |
|---|---|---|---|
| 서버 단위 | 토큰 서비스의 상한 초과 삭제와 소유 이동, 문구 템플릿 해석, FCM 설정 해석, 발송기 결과 분류 | 없음 | CI |
| 서버 통합 | 토큰과 동의 API, 내부 API와 인증, 결과 보고 API, 관리자 API, 알림 통계, 완성, 검수, 공개 중단 알림의 두 경로, 출석, 이프 만료 예정, 캠페인 회차, 공지를 연결한 캠페인 예약, 아웃박스와 릴레이, 알림 내역 기록과 API | FCM은 고정 응답 발송기로 대체<br>Redis는 테스트 JVM의 임베디드 서버 | CI<br>H2, 스키마 자동 생성, 마이그레이션 비활성 |
| 아웃박스 PostgreSQL | 실제 DDL의 선점과 잠금, Kafka 장애와 복구 | PostgreSQL과 Kafka는 Testcontainers | CI |
| 알림 서비스 단위 | 메시지 검증, 소비 결과 판정, FCM 메시지 구성, 라이브러리 재시도 비활성 | 없음 | CI |
| 알림 서비스 통합 | 메시지 큐 소비와 멱등, 동기 API와 내부 인증, 자격 클라이언트, 결과 보고 클라이언트 | Redis와 Kafka는 Testcontainers<br>서버 API와 FCM은 가짜 서버 | CI |
| 동시성 | 동시 첫 등록, 교차 등록, 캠페인 동시 선점, 릴레이 동시 선점, 소비자 동시 처리 | 없음 | CI |
| 수동 | 엔드포인트 호출, 원격 모드 발행, 실기기 도달 | 실행 환경의 실제 의존성 | 두 저장소의 HTTP 요청 파일 |

테스트 프로파일은 마이그레이션과 네 스케줄러를 비활성화한다. 회차는 서비스를 직접 호출해 검증한다. 전체 테스트를 통과해도 DB 제약과 실기기 도달을 검증했다고 볼 수 없다.

<br>

**2. 외부 의존성과 테스트 데이터**

| 대상 | 방법 |
|---|---|
| FCM | 서버는 발송기를 고정 응답 구현으로 교체<br>알림 서비스는 라이브러리 클라이언트를 가짜 HTTP 서버로 대체해 오류 코드별 분기 검증 |
| 큐 | 서버 릴레이는 발행 포트를 기록 구현으로 교체<br>알림 서비스는 Testcontainers Kafka로 재시도와 실패 토픽 검증<br>SQS 어댑터는 단위 검증 |
| Redis | 서버는 임베디드 서버<br>알림 서비스는 Testcontainers<br>장애는 연결할 수 없는 포트로 재현 |
| DB | 통합 테스트는 공유 H2의 PostgreSQL 모드<br>CHECK 제약은 실제 PostgreSQL에서 DB 문서 생성 스크립트로 검증 |
| 서버 내부 API | 알림 서비스 테스트는 자격 응답을 돌려주고 결과 보고를 기록하는 가짜 서버 등록 |
| 시각 | 주입한 고정 시계로 야간 경계, 유효 기한, 선점 수명 검증 |
| 회원 데이터 | 활성, 정지, 탈퇴 계정과 동의 조합별 계정, 토큰 10개를 보유한 계정, 만료 창 안과 밖의 로트를 가진 계정 준비 |

### 5-5-2 토큰 등록과 삭제

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 등록 | 새 토큰 | 204, 행 1개, 소유자는 요청자 |
| 재등록 | 같은 토큰, 같은 플랫폼 | 204, 행 그대로, 소유자와 플랫폼 유지, 갱신 시각 증가 |
| 소유 이동 | 다른 회원이 등록한 토큰 | 204, 소유자가 요청자로 바뀜 |
| 기기 상한 | 토큰 10개 보유 뒤 새 토큰 | 가장 오래 갱신되지 않은 토큰 삭제, 10개 유지 |
| 소유 이동과 상한 | 10개 보유 회원이 타인 토큰 등록 | 옮겨온 행은 남기고 가장 오래된 행 삭제 |
| 입력 오류 | 빈 토큰, 513자, 플랫폼 누락, `IOS` | 400 |
| 정지와 탈퇴 | 정지 회원, 탈퇴 회원 | 403, 401 |
| 삭제 | 본인 토큰, 타인 토큰, 없는 토큰 | 204와 행 삭제, 204와 행 유지, 204 |
| 탈퇴 정리 | 토큰 3개 회원 탈퇴 | 3개 모두 삭제 |
| 동시 첫 등록 | 같은 새 토큰 동시 2건 | 행 1개, 한쪽은 500 |
| 삭제와 등록 경쟁 | 삭제 커밋 전 다른 회원의 등록 | 등록이 삭제를 기다린 뒤 새 행 삽입 |

### 5-5-3 수신 동의

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 기본값 | 신규 회원 조회 | 서비스 `true`, 광고 `false`, 야간 `false` |
| 광고 켬 | 광고 `true` | 동의 시각 기록, 응답 `true` |
| 재동의 | 이미 동의한 회원이 다시 `true` | 동의 시각 유지 |
| 철회 | 광고와 야간이 켜진 회원이 광고 `false`, 야간 `false` | 두 시각 모두 비움 |
| 야간 단독 | 광고 `false`, 야간 `true` | 400 `NIGHT_PUSH_REQUIRES_MARKETING`, 저장값 변경 없음 |
| 필드 누락 | 두 필드만 전송, `null` 전송 | 400 |
| 정지와 탈퇴 | 정지 회원 조회와 변경, 탈퇴 회원 | 403, 401 |

### 5-5-4 발송 자격과 내부 API

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 서비스 허용 | 활성, 서비스 켜짐, 토큰 있음 | `allowed` true, 토큰 목록 |
| 서비스 거절 | 서비스 꺼짐 | `SERVICE_PUSH_DISABLED`, 토큰 없음 |
| 광고 허용과 야간 | 광고만 동의, 주간 시각과 야간 시각 | 허용, `MARKETING_NOT_AGREED` |
| 야간 동의 | 광고와 야간 동의, 야간 시각 | 허용 |
| 계정 상태 | 정지, 탈퇴, 없는 회원 | `NOT_ACTIVE`, `NOT_ACTIVE`, `USER_NOT_FOUND` |
| 토큰 없음 | 동의는 있으나 토큰 없음 | `NO_TOKENS` |
| 내부 인증 | 시크릿 일치, 불일치, 누락, 미설정 환경 | 200, 401, 401, 404 |
| 무효 토큰 삭제 | 있는 토큰, 없는 토큰 | 204와 토큰 삭제, 204 |

### 5-5-5 완성, 검수, 공개 중단 알림

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 로컬 모드 완성 | 회원 완성, 서비스 켜짐 | 커밋 후 발송기 1회, 데이터에 `type`, `storyId`, `title`, `deepLink`, `recipientId`<br>`deepLink`가 `/stories/{storyId}?utm_source=push&utm_medium=push&utm_campaign=story_completed&utm_content=story_completed` |
| 서비스 꺼짐 | 서비스 알림 끈 회원 | 발송 없음 |
| 게스트 완성 | 게스트 제작 | 이벤트 없음 |
| 재처리 | 같은 요청 ID 재요청 | 발송 없음 |
| 롤백 | 완료 표시 트랜잭션 롤백 | 발송 없음 |
| 실행기 포화 | 실행기 대기열이 가득 찬 상태 | 경고 기록, 제작 응답 정상 |
| 원격 모드 완성 | 회원 완성 | 같은 트랜잭션에 아웃박스 행, 발송기 호출 없음 |
| 원격 모드 재처리 | 같은 요청 ID 재요청 | 행 수 그대로 |
| 원격 모드 기록 실패 | 아웃박스 삽입 예외 | 완료 표시도 롤백 |
| 검수 완료 | 통과, 반려, 실패 | 결과별 문구, `deepLink`는 내 제작 목록, 메시지 식별자에 회차 |
| 검수 재회차 | 같은 제출본의 다른 회차 | 별도 메시지 |
| 공개 중단 로컬 모드 | 서비스 켜진 소유 회원의 스토리 공개 중단, 사유 `HATE_SPEECH` | 커밋 후 발송기 1회, 데이터에 `type` `STORY_TAKEN_DOWN`, `storyId`, `title` `스토리 공개가 제한됐어요`, 본문에 이름 토큰을 치환한 스토리 제목과 `혐오 표현`, `recipientId`<br>`deepLink`가 `/studio?utm_source=push&utm_medium=push&utm_campaign=story_taken_down&utm_content=story_taken_down`<br>메모 없음 |
| 공개 중단 문구 | 제목이 "달빛 아래의 약속", "푸른 바다", "Love 2"인 스토리<br>`ETC`와 입력 사유 "실존 인물 비방" | 본문이 `」은`, `」는`, `」은(는)`으로 이어짐<br>본문의 사유 자리에 "실존 인물 비방", 기타라는 말 없음 |
| 공개 중단 제목 길이 | 이름 토큰 치환 뒤 100자인 제목<br>치환 뒤 101자 이상인 제목(원문 100자에 `{username}` 반복, 기본 주인공 이름 30자)<br>99번째와 100번째 코드포인트가 이모지(서로게이트 쌍)인 101자 이상 제목 | 본문에 100자 그대로, 조사는 마지막 글자로 판정<br>앞 99자와 `…`로 줄이고 `」은(는)`, 저장된 제목은 그대로<br>99번째 이모지까지 온전히 남기고 그 뒤에 `…` |
| 공개 중단 본문 상한 | 치환 뒤 300자인 제목, `ETC`와 입력 사유 100자 | 본문 300자 이하, 알림 내역 기록과 공개 중단 성공 |
| 공개 중단 서비스 꺼짐 | 서비스 알림 끈 소유 회원 | 발송 없음, 알림 내역 1행 |
| 공개 중단 원격 모드 | 소유 회원의 스토리 공개 중단 | 같은 트랜잭션에 아웃박스 행, `kind` `SERVICE`, 메시지 식별자 `story-taken-down:{스토리 공개 식별자}:{epoch 밀리초}` |
| 공개 중단 기록 실패 | 원격 모드 아웃박스 삽입 예외 | 공개 중단, 감사 로그, 알림 내역 모두 롤백 |
| 다시 공개 중단 | 재검수 승인으로 해제된 스토리를 다시 공개 중단 | 앞과 다른 메시지 식별자의 새 메시지 |
| 서비스 알림 문구 | 완성, 검수 완료 | 제목에 광고 표기 없음, 본문에 수신거부 안내 없음 |

### 5-5-6 출석 리마인드와 프로모션

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 대상 선정 | 활성, 광고 동의, 토큰 보유, 출석 미수령을 모두 충족한 회원<br>출석 수령, 동의 없음, 토큰 없음, 정지인 회원 | 모두 충족한 회원만 대상 |
| 재가입 미수령 | 최초 계정이 출석 수령한 재가입 계정 | 대상 아님 |
| 회차 선점 | 두 인스턴스 동시 실행 | 한쪽만 실행 |
| 선점 Redis 장애 | 연결 불가 | 요청 기록 없음, 선점 실패 로그 |
| 원격 모드 기록 | 대상 3명 | 아웃박스 행 3건, `sent` 3, 메시지 식별자는 회원과 날짜 |
| 같은 날 재기록 | 이미 기록된 회원 | 행 수 그대로 |
| 로컬 모드 재확인 | 대상 조회 뒤 철회 | 발송 없음 |
| 문구 | 오버라이드 없음, 유효한 행, 만료된 행, 예약된 두 행 | 기본 문구, 행 문구, 기본 문구, 늦게 시작한 행 |
| 광고 표기 | 제목에 표기 없음, 이미 표기 있음 | 한 번만 붙음 |
| 수신거부 안내 | 기본 본문, 오버라이드 본문, 캠페인 본문 | 발송 데이터 `body` 끝에 줄바꿈 뒤 안내 한 번 |
| 수신거부 안내 중복 | 이미 안내로 끝나는 오버라이드 본문과 캠페인 본문, 안내 뒤에 공백과 탭, 줄바꿈이 있는 본문 | 안내 한 번, 본문 그대로, 같은 변환을 다시 적용해도 변화 없음 |
| 광고 표기와 안내 함께 | 광고 표기 있는 제목과 안내로 끝나는 본문 | 표기와 안내가 각각 한 번 |
| 300자 본문 | 300자 원문의 오버라이드와 캠페인 | 알림 내역은 원문 300자, 발송 데이터 `body`는 317자에 안내가 온전히 포함, 회차 성공 |
| 서비스 공지 캠페인 | 종류 `SERVICE` 캠페인 | 제목과 본문 그대로, 광고 표기와 수신거부 안내 없음 |
| 모드별 발송 데이터 | 출석과 `MARKETING` 캠페인의 원격 모드와 로컬 모드 | 아웃박스 발송 요청의 `data.body`와 발송기에 전달하는 `body`에 안내 한 번 |
| 재실행 안내 수 | 같은 캠페인 재실행, 메시지 재전달 | 안내 한 번 그대로 |
| 유효 기한 | 09:00 KST 실행 | 요청의 만료 시각은 당일 자정, 로컬 모드의 TTL은 자정까지 남은 시간 |
| 캠페인 선점 | 도래한 예약 2건, 두 인스턴스 | 각 캠페인은 한쪽만 처리 |
| 취소 | 선점 전 취소 상태 | 처리 없음 |
| 야간 캠페인 | 21:30 KST 소비, 야간 동의자와 미동의자 | 동의자만 발송, 미동의자는 자격 거절로 폐기 |
| 회차 결과 | 정상 종료, 대상 조회 예외 | `SENT`와 대상 수, 요청 수, `FAILED` |
| 실패 캠페인 재실행 | 관리자가 재실행 | 기록되지 않은 회원만 추가 기록 |
| 전송 중 시간 초과 | 선점 시각이 시간 한도보다 오래된 전송 중 캠페인, 한도 안인 전송 중 캠페인 | 다음 폴링에서 `FAILED`와 시간 초과 WARN, 그대로 `SENDING` |
