# 5-3 오류 처리

이 문서는 NOTIFICATION 도메인의 응답 규칙, 앱 코드, 오류 분류, 복구 규칙, 재시도와 시간 한도, 최종 실패, 전달 실패 처리, 오류 로그 기준을 정한다.

엔드포인트별 실패 조건과 응답 형식은 계약에, 흐름별 처리 순서는 처리 흐름에, 선점과 멱등은 동시성에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-2-2 멱등과 1회 처리](5-2-CONCURRENCY.md#5-2-2-멱등과-1회-처리))

<br>

### 5-3-1 응답 규칙

| 항목 | 규칙 |
|---|---|
| `code` | HTTP 상태 이름이 기본<br>클라이언트 안내가 달라질 때만 앱 코드 사용 |
| `message` | 사용자 안내 문구<br>500은 고정 안내 문구 |
| `details` | 선언적 필드 검증과 타입 변환 실패 시 채움<br>서비스에서 판정한 400은 `details` 없이 `message`에 사유 기록 |
| 발송 결과 | 알림 발송 API는 자격 조회 실패만 502<br>거절, 만료, 발송 실패는 200 본문에 결과를 담음 |

<br>

### 5-3-2 앱 코드

코드 문자열은 API 계약이므로 유지한다.

| 상태 | `code` | 의미 |
|---|---|---|
| 400 | `NIGHT_PUSH_REQUIRES_MARKETING` | 광고 동의 없이 야간 광고 동의만 켜는 요청 |
| 403 | `CONSENT_REQUIRED` | 동의 게이트가 켜진 환경에서 미동의 회원의 허용 목록 밖 요청 |

<br>

### 5-3-3 오류 분류

| 오류 | 발생 위치 | 처리 |
|---|---|---|
| 입력 오류 | API 계층의 선언적 검증과 본문 파싱 | 400으로 변환 |
| 야간 단독 동의 | 동의 서비스 | 앱 코드를 가진 400 |
| 내부 API 인증 실패 | 내부 API 인증 필터 | 시크릿 미설정은 404, 불일치는 401<br>사유를 구분하지 않음 |
| 상태 코드 오류 | 토큰과 동의 서비스 및 알림 내역 서비스의 상태 재검사 | 정지는 403, 탈퇴와 사용자 없음은 401 |
| 유니크 위반 | DB | 동시 첫 등록의 한쪽이 500<br>재시도는 성공 |
| FCM 무효 토큰 | 발송기 | 토큰 삭제 후 다음 기기에 계속 발송 |
| FCM 영구 오류 | 발송기 | 잘못된 인자, 인증과 권한, 없음, 발신자 불일치는 실패로 집계하고 토큰은 유지 |
| FCM 일시 오류 | 발송기 | 서버 안 발송기는 라이브러리 재시도 뒤 실패로 집계<br>알림 서비스는 재시도 집계로 재전달 |
| 자격 조회 실패 | 알림 서비스 | 허용으로 대체하지 않음<br>동기 API는 오류 응답, 메시지 큐 소비는 재전달 |
| 큐 메시지 검증 실패 | 소비자 | 확인하지 않고 재전달 상한 뒤 실패 메시지 큐로 이동 |
| 큐 발행 실패 | 릴레이 | 지수 백오프로 재시도<br>포기 시각이 지나면 포기 |
| Redis 장애, 출석과 이프 만료 예정 회차 선점 | 스케줄러 | 그날 회차를 건너뜀 |
| Redis 장애, 쿨다운 조회 | 이프 만료 예정 회차 | 내역과 요청을 기록하지 않고 회차 실패로 기록 |
| Redis 장애, 쿨다운 기록 | 이프 만료 예정 회차 | 회차 실패로 기록<br>커밋한 내역과 요청은 유지되어 원격 모드는 발행됨 |
| 발송 결과 보고 실패 | 알림 서비스, 로컬 모드 발송기 | 경고만 남기고 소비와 발송 결과를 바꾸지 않음 |
| Redis 장애, 소비자 | 알림 서비스 | 발송을 계속하지 않고 재전달<br>자기 선점만 해제 |
| 문구 템플릿 적재 실패 | 템플릿 서비스 | 경고 기록 뒤 직전 스냅샷 유지 |
| 발송 실행기 포화 | 로컬 모드 리스너 | 그 알림을 버리고 경고<br>제작 응답은 유지 |
| 아웃박스 기록 실패 | 원격 모드 리스너 | 도메인 트랜잭션과 함께 롤백 |
| 아웃박스 기록 실패, 예약 발송 | 출석, 이프 만료 예정, 프로모션 회차 | 회차 트랜잭션을 롤백하고 회차 실패로 기록 |
| 예상하지 못한 오류 | 어디서든 | 전역 핸들러가 500 고정 문구로 응답하고 Sentry 전송 |

<br>

### 5-3-4 오류별 처리

- 잘못된 인자 오류는 서버가 만든 페이로드 오류일 수 있어 토큰을 지우지 않는다. 지우면 서버 결함 하나가 회원 전체의 토큰을 삭제한다.
- 한 기기의 실패와 무효 토큰 삭제 실패는 다른 기기의 발송을 막지 않는다.
- 회차 내 한 회원의 발송 실패는 나머지 회원 발송을 막지 않는다.
- 프로모션 회차가 예외로 끝나면 실패로 기록하고 자동으로 재실행하지 않는다. 같은 실패를 반복하지 않기 위해서다. 재실행은 운영자가 예약 상태로 되돌릴 때만 한다.
- 알림 서비스는 처리 예산을 넘기면 새 기기 발송을 시작하지 않고 재전달에 맡긴다.

<br>

### 5-3-5 재시도와 시간 한도

**1. 재시도**

- 서버 안 발송기는 FCM 라이브러리의 내부 재시도에 맡기고 애플리케이션 재시도를 두지 않는다.
- 알림 서비스는 FCM 라이브러리의 내부 재시도를 끄고 메시지 큐 재전달로만 재시도한다.
- 아웃박스 발행은 횟수 상한 없이 포기 시각까지 지수 백오프로 재시도한다.
- 메시지 큐는 가시성 시간이 지나면 재전달하며 5회 수신 뒤 실패 메시지 큐로 보낸다. 재전달마다 만료와 자격을 다시 확인한다.
- 출석, 이프 만료 예정, 프로모션의 회차 실패는 재시도하지 않는다.
- 그 외 재시도는 클라이언트가 같은 요청을 다시 보내는 것뿐이다.

<br>

**2. 시간 한도**

| 대상 | 제한 시간 | 적용 범위 |
|---|---|---|
| 출석 회차 선점 키 | 24시간 | 출석 리마인드 회차 |
| 출석 리마인드 유효 기한 | 당일 KST 자정 | 소비자의 만료 검사와 Android TTL |
| 이프 만료 예정 회차 선점 키 | 24시간 | 이프 만료 예정 알림 회차 |
| 이프 만료 예정 알림 유효 기한 | 회원의 창 안 로트 중 가장 늦은 만료 시각 | 소비자의 만료 검사와 Android TTL |
| 이프 만료 예정 쿨다운 | 회차 기록 후 7일 | 회원별 대상 제외 |
| 프로모션 폴링 | 60초 간격 | 도래한 예약 조회 |
| 문구 템플릿 갱신 | 직전 갱신이 끝난 뒤 300초 | 오버라이드 반영 지연 |
| 아웃박스 폴링 | 2초 간격 | 릴레이<br>배치당 100건 |
| 아웃박스 임대 | 60초 | 선점한 배치의 발행 |
| 아웃박스 전송 제한 | 배치당 20초 | 임대보다 짧아야 함 |
| 아웃박스 브로커 호출 | 10초 | SQS 발행 호출 1회 |
| 아웃박스 백오프 | 5초에서 두 배씩, 최대 5분 | 발행 실패 |
| 아웃박스 포기 | 기록 후 24시간 | 발행 실패 |
| 큐 가시성 | 60초 | 재전달 간격 |
| 실패 메시지 큐 보존 | 14일 | 재전달 상한을 넘긴 메시지 |
| 소비자 처리 중 선점 | 2분 | 재전달 가능 시간 4분보다 짧게 유지 |
| 소비자 처리 예산 | 10초 | 새 기기 발송 시작 |
| 알림 서비스 FCM 호출 | 연결 1초, 읽기 5초, 쓰기 1초 | 라이브러리 재시도 없음 |
| 자격 조회 | 연결 1초, 읽기 2초 | 알림 서비스가 서버 호출 |
| 멱등 기록 | 7일 | 완료 표시는 완료 후, 성공 기기 집합은 기록할 때마다 갱신 |
| Android TTL 상한 | 4주 | 유효 기한이 더 길면 상한으로 제한 |

### 5-3-6 최종 실패와 부분 완료

| 결과 | 처리 |
|---|---|
| 발송 요청이 포기 시각까지 발행되지 못함 | 릴레이가 선점 뒤 발행 전에 판정<br>포기 상태로 기록하고 경고<br>알림은 발송되지 않음 |
| 메시지가 재전달 상한을 넘김 | 실패 메시지 큐에 보존<br>운영자가 확인하고 되돌림 |
| 일부 기기만 성공 | 성공 기기를 기록하고 재시도할 기기가 있으면 재전달<br>영구 실패만 남으면 완료 |
| 자격 거절 | 발송 없이 완료 기록 |
| 만료된 요청 | 발송 없이 폐기 기록 |
| 로컬 모드의 발송 실패 | 로그와 지표만<br>사용자는 복귀 조회로 결과 확인 |
| 출석 회차의 선점 실패나 Redis 장애 | 그날 발송 없음 |
| 이프 만료 예정 회차의 선점 실패, 커밋 전 쿨다운 조회 실패, 기록 실패 | 그날 내역과 발송 없음 |
| 이프 만료 예정 회차의 커밋 뒤 쿨다운 기록 실패 | 내역은 남고 원격 모드는 요청이 발행됨<br>회차 실패 이벤트만 남고 다음 회차에 중복 가능 |
| 프로모션 회차 실패 | 실패 상태 기록<br>운영자가 원인 해결 뒤 같은 행을 예약 상태로 되돌림 |

<br>

### 5-3-7 전달 실패 처리

| 상황 | 백엔드 | 클라이언트와의 경계 |
|---|---|---|
| 토큰 등록 응답 유실 | 등록 또는 갱신 완료 | 재등록은 갱신 |
| 토큰 삭제 응답 유실 | 삭제 완료 | 재요청은 같은 응답 |
| 동의 변경 응답 유실 | 변경 완료 | 재요청은 같은 값이면 동의 시각 유지 |
| 알림 읽음 응답 유실 | 읽음 변경이 완료됐을 수 있음 | 재요청해도 최초 읽음 시각 유지<br>모두 읽음 재요청은 그 사이 생긴 안 읽은 내역에도 적용 |
| 푸시 미도달 | FCM 이후는 관여하지 않음 | 복귀 조회로 결과 확인 |
| 알림 발송 API 응답 유실 | 발송이 완료됐을 수 있음 | 재요청은 중복 발송 가능<br>검증 경로에만 사용 |

### 5-3-8 로그와 Sentry

경고 로그의 이름과 기록 내용은 관측에 있다. ([5-4-3 구조화 로그 이벤트](5-4-OBSERVABILITY.md#5-4-3-구조화-로그-이벤트))

| 대상 | 규칙 |
|---|---|
| 서버의 5xx | 스택트레이스와 함께 ERROR로 기록하고 Sentry 전송<br>알림 서비스는 Sentry 미전송 |
| 예상 가능한 4xx | Sentry 미전송<br>원인 예외가 있으면 클래스와 메시지를 한 줄로 WARN, 없으면 DEBUG |
| FCM 실패 | WARN으로 기록 |
| 발송 실패 | 요청 응답에 전파하지 않으므로 Sentry에 없음 |
