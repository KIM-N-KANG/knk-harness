# 5-1 보안

이 문서는 NOTIFICATION 도메인의 인증 수준, 소유권과 접근 판정, 계정 상태, 동의와 법적 요건, 입력 검증, 내부 경로 보호, 비밀값과 개인정보 취급 규칙, 수용한 한계를 정한다.

경로별 인증 수준과 계정 상태별 응답은 계약에, 로그와 지표에 기록하지 않는 데이터는 관측에, 잠금과 경쟁 조건은 동시성에 있다. ([4-2-1 공통 규칙과 헤더](4-2-CONTRACT.md#4-2-1-공통-규칙과-헤더), [5-4-8 수집 조건과 실패 처리](5-4-OBSERVABILITY.md#5-4-8-수집-조건과-실패-처리), [5-2 동시성](5-2-CONCURRENCY.md))

<br>

### 5-1-1 인증 수준

| 항목 | 처리 |
|---|---|
| 필수 경로 | 토큰 등록과 삭제, 수신 동의 조회와 변경<br>토큰 없음, 만료, 위조, 주체 형식 오류, 사용자 없음은 인증 실패 |
| 내부 경로 | 발송 자격 조회, 무효 토큰 삭제, 알림 발송<br>공유 시크릿 헤더를 상수 시간으로 비교<br>시크릿이 설정되지 않은 환경에서는 경로를 숨김 |
| 큐 메시지 | 운영은 서버 태스크 역할만 발행하고 알림 태스크 역할만 수신과 삭제<br>개발은 같은 태스크 역할이 모두 수행<br>본문에 인증 정보 없음 |

<br>

### 5-1-2 소유권과 접근 판정

| 판정 | 규칙 |
|---|---|
| 토큰 소유 | 토큰은 전역 유일이며 마지막으로 등록한 회원의 것<br>다른 회원이 등록하면 소유자가 바뀌어 이전 회원의 알림이 그 기기로 가지 않음 |
| 토큰 삭제 | 요청자 소유 조건을 삭제문 안에 두어 조회와 삭제 사이에 소유자가 바뀐 행을 지우지 않음<br>없는 토큰과 타인 소유 토큰을 같은 응답으로 처리해 존재 여부를 드러내지 않음 |
| 수신 동의 | 본인 것만 조회하고 변경 |
| 발송 대상 | 발송 직전 자격 판정을 통과한 회원의 최근 갱신 토큰 10개<br>거절된 회원의 토큰은 조회하지 않고 응답에 싣지 않음 |
| 수신자 대조 | 모든 푸시에 수신자 식별자를 실어 앱이 현재 회원과 비교<br>다르면 표시하지 않음 |

<br>

### 5-1-3 계정 상태와 동의

| 상태 | 처리 |
|---|---|
| 정지 계정 | 토큰 등록과 삭제, 동의 조회와 변경을 사용자 행 잠금 뒤 재검사해 거절<br>발송 대상에서 제외 |
| 탈퇴 계정 | 남은 접근 토큰은 공통 필터가 거절<br>탈퇴 시 토큰을 전부 삭제<br>발송 대상에서 제외 |
| 재가입 계정 | 새 계정이라 토큰과 광고 동의가 없고 서비스 알림은 기본 켜짐<br>출석 미수령 판정만 보상 신원으로 최초 계정과 묶임 |
| 게스트 | 계정 상태 판정의 대상 아님<br>토큰을 등록할 수 없어 어떤 푸시도 받지 않음 |
| 미동의 회원 | 동의 게이트가 켜진 환경에서 현행 필수 동의가 없으면 거절<br>`DELETE /users/me/push-tokens`는 허용 목록 |

<br>

### 5-1-4 수신 동의와 법적 요건

| 대상 | 규칙 |
|---|---|
| 서비스 알림 | 사용자가 유발한 작업의 결과 통지라 사전 동의 없이 기본 켜짐<br>끄면 보내지 않음 |
| 광고 알림 | 사전 동의가 있어야 보냄<br>동의 시각을 증빙으로 저장하고 재동의는 최초 시각 유지 |
| 야간 광고 알림 | KST 21:00부터 08:00 전까지는 야간 동의까지 있어야 보냄<br>광고 동의 없이 야간만 켤 수 없음 |
| 철회 | 다음 발송부터 반영<br>회차 중에도 회원마다 발송 직전에 다시 읽음 |
| 광고 표기 | 광고 알림 제목 앞에 `(광고)`를 서버가 붙임<br>저장된 문구에 맡기지 않음 |
| 토픽 금지 | 광고 발송에 FCM 토픽을 쓰지 않음<br>서버가 수신자 명단을 알아야 동의 증빙이 가능 |

<br>

### 5-1-5 입력 검증

| 대상 | 규칙 |
|---|---|
| 길이, 필수, 허용값 | 요청 객체에 선언한 제약으로 검증하고 위반 시 거절 |
| 수신 동의 변경 | 세 필드의 누락과 `null`을 역직렬화에서 거절<br>야간 광고 동의만 켜는 요청은 저장소에 접근하기 전에 거절 |
| 내부 API 쿼리 | 종류와 시각을 필수로 검증 |
| 큐 메시지 | 스키마 버전, 필수 필드, 시나리오와 종류의 대응을 소비 직전에 검증<br>실패는 확인하지 않고 재전달 상한 뒤 실패 메시지 큐로 보냄 |
| 푸시 데이터 | 호출자가 넣은 수신자 식별자는 서버 값으로 덮어씀 |

<br>

### 5-1-6 내부 경로 보호

| 대상 | 규칙 |
|---|---|
| 공유 시크릿 | 서버와 알림 서비스에 같은 값을 주입<br>빈 값은 저장하지 않음 |
| 공개 경로 차단 | 운영의 공개 ALB는 내부 경로가 없는 것으로 응답 |
| 네트워크 | 운영 알림 서비스는 서버 내부 API, Redis, 트레이스 수집기, 외부 HTTPS로만 연결<br>개발은 서버와 같은 태스크라 별도 제한 없음 |

<br>

### 5-1-7 비밀값과 개인정보

| 대상 | 규칙 |
|---|---|
| 푸시 토큰 | 요청 경로, 큐 메시지, 아웃박스 본문에 싣지 않음<br>로그에는 앞 12자만<br>멱등 기록에는 SHA-256 해시만 |
| 동의 시각 | 응답에 싣지 않음<br>로그에 기록하지 않음 |
| FCM 자격 증명 | 설정에서만 읽음<br>해석에 실패하면 기동이 실패하며 자격 증명 값은 로그에 남지 않음 |
| 공유 시크릿 | 설정에서만 읽고 로그에 기록하지 않음 |
| 기기 식별자 | 알림 서비스는 해시만 받아 전달하고 원문을 다루지 않음 |
| 푸시 데이터 | 스토리 제목만 사용자 콘텐츠<br>반려 사유와 채팅 본문은 싣지 않음 |

<br>

### 5-1-8 수용한 한계

| 한계 | 수용 이유 |
|---|---|
| 토큰 회전으로 남은 이전 토큰 | 다음 발송에서 무효 통지로 정리되고 상한 초과 시에도 갱신이 멈춘 행부터 삭제 |
| 발송 직전 재확인과 실제 발송 사이의 짧은 시간에 철회된 동의 | 외부 호출을 트랜잭션에 묶을 수 없음<br>철회가 반영되지 않는 시간을 회차 길이에서 밀리초로 줄임 |
| 웹 백그라운드 알림은 수신자 대조를 할 수 없음 | 브라우저가 표시<br>로그아웃 시 토큰 삭제로 보호 |
| 내부 API를 호출하는 자격 조회가 서버 장애 시 실패 | 허용으로 대체하지 않고 재전달<br>상한을 넘기면 실패 메시지 큐에 보존 |
