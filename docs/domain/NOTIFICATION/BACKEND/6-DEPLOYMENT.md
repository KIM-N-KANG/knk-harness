# 6. 배포

이 문서는 NOTIFICATION 도메인이 포함된 서버와 알림 서비스의 배포 단위와 의존 대상, 배포 경로, 환경 변수와 시크릿, 배포 조건, 설정 변경, 적용과 복구 절차를 정한다.

서버 전체 배포 절차 중 NOTIFICATION 도메인과 관련된 항목만 다룬다.

재시도와 시간 한도는 오류 처리에, 관측 스택과 조회 도구는 관측에 있다. ([5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도), [5-4-1 관측 스택](5-4-OBSERVABILITY.md#5-4-1-관측-스택))

<br>

### 6-1 배포 단위와 의존성

| 단위 | 개발 | 운영 |
|---|---|---|
| 서버 | 서버 컨테이너 | 서버 컨테이너 |
| 알림 서비스 | 서버와 같은 태스크의 컨테이너, 포트 8081, 메모리 제한 512MB | 별도 ECS 서비스, 태스크 2개, 0.25 vCPU와 1GB, FireLens 사이드카 포함 |

| 의존 대상 | 내용 | NOTIFICATION이 쓰는 것 |
|---|---|---|
| PostgreSQL | 기동 시 마이그레이션 적용 | 토큰, 동의 컬럼, 템플릿, 캠페인, 아웃박스 |
| Redis | 서버와 알림 서비스가 같은 인스턴스 | 출석 회차 선점, 멱등 기록 |
| 메시지 큐 | SQS 표준 큐와 실패 큐 | 발송 요청 전달 |
| FCM | 서비스 계정 인증 | 발송 |
| 서버 내부 API | 개발은 로컬 주소, 운영은 사설 DNS | 자격 조회, 무효 토큰 삭제 |
| Secrets Manager | Terraform이 태스크 정의에 참조 주입 | 공유 시크릿, FCM 자격 증명 |
| 공개 ALB | 운영 | 내부 경로 차단 |

<br>

| 의존 대상 | 연결과 설정 실패 시 동작 |
|---|---|
| FCM 자격 증명 | 비어 있으면 기동은 정상이고 발송만 비활성<br>비어 있지 않은데 해석할 수 없으면 기동 실패 |
| 큐 주소 | 원격 모드와 알림 서비스에서 비어 있으면 기동 실패 |
| 공유 시크릿 | 비어 있으면 내부 API가 없는 경로로 응답<br>알림 서비스의 자격 조회가 전부 실패 |
| 서버 내부 주소 | 비어 있으면 알림 서비스는 기동하되 자격 조회 실패로 발송 없음 |
| 아웃박스 설정 | 임대가 전송 제한보다 짧거나 전송 제한이 브로커 클라이언트 제한보다 짧으면 기동 실패 |
| 소비자 시간 설정 | 선점 수명이 재전달 창 이상이거나 처리 예산이 선점 수명 이상이면 기동 실패 |
| 문구 기본값 | 설정에 없으면 기동 실패 |
| PostgreSQL | 연결할 수 없으면 서버 기동 실패 |
| Redis | 필요한 시점에 연결<br>서버는 출석 회차를 건너뜀, 알림 서비스는 재전달 |
| 큐 | 서버는 아웃박스에 보존하고 백오프, 알림 서비스는 수신 중단 |

<br>

### 6-2 배포 경로

| 단계 | 서버 | 알림 서비스 개발 | 알림 서비스 운영 |
|---|---|---|---|
| 자동 시작 | `dev` push, `main` push | `dev` push | `main` push |
| 이미지 | 서버 저장소 워크플로 | GHCR의 커밋 SHA 태그를 `dev`로 승격 | 운영 ECR의 커밋 SHA 태그 |
| 배포 | 서버 배포 절차 | 최신 `dev` SHA 확인 뒤 같은 태스크 전체 재시작 | 별도 서비스 배포, 실패 시 이전 digest 복원 |
| 상태 검사 | health `UP` | 서버, AI, 알림 컨테이너 모두 정상 | 배포 완료와 health `UP` |

개발 환경의 알림 서비스 배포는 서버와 DB를 포함한 태스크 전체를 재시작하므로 짧은 중단이 있다.

<br>

### 6-3 환경 변수와 시크릿

환경 변수가 설정 파일의 값보다 우선한다. 설정은 기동 시 읽으므로 변경 뒤 새 태스크를 시작해야 적용된다. 값은 Terraform이 태스크 정의에 주입하고 시크릿은 Secrets Manager에서 주입한다. 이 도메인이 읽는 설정만 적는다. 기본값이 "빈 값"이면 변수가 없어도 빈 문자열로 기동한다. "없음"이면 변수가 없을 때 기동에 실패한다.

<br>

**1. 서버**

| 이름 | 기본값 | 주입 출처 | 비고 |
|---|---|---|---|
| `MANYAK_PUSH_MODE` | `local` | 개발과 운영 Terraform 변수, 둘 다 `remote` | 실행 주체 |
| `MANYAK_PUSH_QUEUE_URL` | 빈 값 | 개발과 운영 Terraform | 원격 모드 필수 |
| `AWS_REGION` | `ap-northeast-2` | ECS | 큐 클라이언트 리전 |
| `MANYAK_FCM_SERVICE_ACCOUNT_JSON` | 빈 값 | 개발과 운영 Secrets Manager | 출석과 프로모션 발송에 필요<br>완성과 검수는 원격 모드에서 쓰지 않음 |
| `MANYAK_INTERNAL_SHARED_SECRET` | 빈 값 | 개발과 운영 Secrets Manager | 알림 서비스와 같은 값 |
| `MANYAK_PUSH_WEB_BASE_URL` | `https://manyak.app` | 주입 없음 | 딥링크 앞부분 |
| `MANYAK_PUSH_WEB_ICON_URL` | `https://manyak.app/icons/icon-192.png` | 주입 없음 | 웹 알림 아이콘 |
| `MANYAK_PUSH_ATTENDANCE_REMINDER_ENABLED` | `true` | 주입 없음 | |
| `MANYAK_PUSH_ATTENDANCE_REMINDER_CRON` | `0 0 9 * * *` | 주입 없음 | KST 기준 |
| `MANYAK_PUSH_ATTENDANCE_REMINDER_TITLE` | 설정 파일의 기본 문구 | 주입 없음 | 광고 표기 없이 |
| `MANYAK_PUSH_ATTENDANCE_REMINDER_BODY` | 설정 파일의 기본 문구 | 주입 없음 | |
| `MANYAK_PUSH_PROMOTION_ENABLED` | `true` | 주입 없음 | |
| `MANYAK_PUSH_PROMOTION_INTERVAL_MS` | `60000` | 주입 없음 | |
| `MANYAK_PUSH_TEMPLATE_REFRESH_ENABLED` | `true` | 주입 없음 | |
| `MANYAK_PUSH_TEMPLATE_REFRESH_INTERVAL_MS` | `300000` | 주입 없음 | |

아웃박스의 폴링 간격, 배치 크기, 임대, 전송 제한, 포기 기준, 백오프는 설정 파일의 고정값이다. 해당 환경 변수는 없다.

<br>

**2. 알림 서비스**

| 이름 | 기본값 | 주입 출처 | 비고 |
|---|---|---|---|
| `SPRING_PROFILES_ACTIVE` | 없음 | Terraform | `dev` 또는 `prod`에서 SQS 소비 |
| `SERVER_PORT` | `8080` | 개발 Terraform은 `8081` | |
| `MANYAK_INTERNAL_SHARED_SECRET` | 빈 값 | 개발과 운영 Secrets Manager | 서버와 같은 값 |
| `MANYAK_SERVER_INTERNAL_BASE_URL` | 빈 값 | Terraform | 개발 `http://localhost:8080`, 운영 사설 DNS 주소 |
| `MANYAK_FCM_SERVICE_ACCOUNT_JSON` | 빈 값 | 개발과 운영 Secrets Manager | 서버와 같은 Firebase 프로젝트 |
| `MANYAK_PUSH_QUEUE_URL` | 빈 값 | Terraform | 필수 |
| `MANYAK_PUSH_CONSUMER_RETRY_DELAY_MS` | `60000` | Terraform, 큐 가시성과 같은 값 | |
| `MANYAK_PUSH_CONSUMER_RETRY_ATTEMPTS` | `5` | Terraform, 큐 수신 상한과 같은 값 | |
| `MANYAK_PUSH_CONSUMER_PROCESSING_TTL_MS` | `120000` | 주입 없음 | 재전달 창보다 짧게 |

| `SPRING_DATA_REDIS_HOST`, `SPRING_DATA_REDIS_PORT` | 없음 | Terraform | 개발은 로컬, 운영은 서버와 같은 Redis |
| `MANYAK_PUSH_WEB_BASE_URL`, `MANYAK_PUSH_WEB_ICON_URL` | 서버와 같음 | 주입 없음 | |
| `JAVA_TOOL_OPTIONS` | 없음 | Terraform | 힙 상한 |

### 6-4 배포 조건

| 확인 항목 | 기준 | 자동 여부와 한계 |
|---|---|---|
| 큐와 소비자 설정 | 큐의 가시성과 수신 상한을 소비자 재전달 값에 같은 값으로 주입 | Terraform이 같은 지역 변수로 주입 |
| 공유 시크릿 | 서버와 알림 서비스에 같은 값<br>빈 값 거부 | 수동 확인<br>길이만 검사하고 값은 기록하지 않음 |
| Firebase 프로젝트 | 서버와 알림 서비스의 자격 증명이 앱과 같은 프로젝트 | 수동 확인 |
| 실행 주체 전환 | 알림 서비스가 큐를 소비하는 것을 확인한 뒤 서버를 원격 모드로 전환 | 수동 결정 |
| 시나리오 추가 | 큐 메시지 검증의 허용 시나리오를 알림 서비스에 먼저 배포 | 수동 검토 |
| 와이어 계약 변경 | 푸시 데이터가 바뀌면 앱과 웹의 처리를 함께 배포 | 수동 검토 |
| 마이그레이션 | 기동 시 실행하므로 새 마이그레이션은 해당 코드보다 먼저 적용 | 기동 시 자동 적용 |
| 코드 테스트 | 두 저장소의 전체 테스트 통과 | CI 자동 |
| 컨테이너 기동 | 헬스체크 `UP` | CI 자동<br>FCM과 큐 연결은 검사하지 않음 |

<br>

### 6-5 설정 변경

| 변경 대상 | 변경 위치와 적용 | 확인 조건 |
|---|---|---|
| 출석 리마인드 문구 | 템플릿 행 추가<br>갱신 주기 안에 반영, 재배포 없음 | 다음 회차의 발송 문구 |
| 프로모션 예약과 취소 | 캠페인 행 추가, 선점 전 취소 상태 변경 | 캠페인 행의 결과 컬럼 |
| 실행 주체 | Terraform 변수 변경 후 새 태스크 시작 | 원격이면 아웃박스 행과 소비 지표, 로컬이면 서버 발송 지표 |
| 공유 시크릿 | Secrets Manager 값 변경 후 서버와 알림 서비스 모두 새 태스크 시작 | 교체 중에는 자격 조회가 실패해 재전달됨 |
| FCM 자격 증명 | Secrets Manager 값 변경 후 새 태스크 시작 | 발송 지표의 `failure`가 늘지 않음 |
| 출석 발송 시각 | 환경 변수 변경 후 새 태스크 시작 | 야간 구간으로 옮기면 야간 동의자에게만 감 |
| 소비자 시간 설정 | Terraform 변경 후 apply | 큐 설정과 함께 바꿈 |

### 6-6 적용과 복구

**1. 적용 순서**

| 순서 | 작업 | 확인 항목 |
|---|---|---|
| 1 | 설정과 시크릿 확인 | 두 단위의 시크릿 일치, 큐 주소, 서버 내부 주소 |
| 2 | 동반 배포 확인 | 새 시나리오는 알림 서비스 먼저<br>푸시 데이터 변경은 클라이언트와 함께 |
| 3 | 배포 실행 | 알림 서비스 뒤 서버 |
| 4 | 적용 결과 확인 | 배포 후 확인 항목 |

<br>

**2. 진행 중인 요청**

| 상황 | 처리와 한계 |
|---|---|
| 롤링 교체 중 아웃박스 | 임대가 끝나면 새 태스크의 릴레이가 이어받음 |
| 롤링 교체 중 큐 소비 | 처리 중 메시지는 가시성이 지나면 재전달<br>선점 수명이 지나면 새 소비자가 처리 |
| 알림 서비스 중단 | 큐에 적체되고 서버는 영향 없음<br>재기동 뒤 소비 |
| 서버 중단 | 알림 서비스의 자격 조회가 실패해 재전달<br>상한을 넘기면 실패 큐 |
| 출석 회차 중 교체 | 두 태스크가 걸쳐도 선점 키로 한 번<br>회차 도중 종료되면 남은 회원은 그날 받지 못함 |
| 프로모션 회차 중 교체 | 전송 중 상태로 남으며 운영자가 재예약 |
| 개발 stop-then-start | 교체 중 모든 요청 실패 |

<br>

**3. 복구**

| 상황 | 복구 방식 | 한계와 확인 사항 |
|---|---|---|
| 새 태스크 헬스체크 실패 | 직전 배포로 자동 복귀 | 알림 서비스는 서킷 브레이커 롤백 |
| 실패 큐 적체 | 원인 해결 뒤 본 큐로 되돌림 | 되돌린 메시지는 멱등 기록이 남아 있으면 발송 없이 확인 |
| 원격 모드 장애 | 서버를 로컬 모드로 되돌림 | 서버에 FCM 자격 증명이 있어야 함<br>아웃박스의 미발행 행은 그대로 남음 |
| 잘못 보낸 광고 | 회수 불가 | 캠페인 취소는 선점 전에만 유효 |
| 설정 오류 | 잘못된 값을 이전 값으로 복구 후 새 태스크 시작 | 이미지 복원만으로 설정은 복원되지 않음 |

<br>

### 6-7 배포 후 확인

| 확인 항목 | 자료 | 기준 |
|---|---|---|
| 기동 | 두 단위의 헬스체크 | `UP` |
| 큐 소비 | 소비 지표, 큐의 가시 메시지 수 | 적체가 늘지 않음 |
| 발송 | 발송 지표의 `failure` | 배포 전과 같은 수준 |
| 아웃박스 | 아웃박스 지표의 `retry`와 `abandoned` | 늘지 않음 |
| 내부 API | 요청 로그의 내부 경로 상태 | 없음 응답과 인증 실패 응답이 없음 |
| 실패 큐 | 경보 | 발생 없음 |

<br>

### 6-8 배포 실패 진단

| 실패 상황 | 확인할 자료와 위치 | 원인별 조치 |
|---|---|---|
| 알림 서비스 기동 실패 | 시작 로그의 설정 검증 메시지 | 큐 주소, 소비자 시간 설정, FCM 자격 증명 해석 중 해당 값 수정 |
| 자격 조회가 전부 실패 | 알림 서비스의 조회 실패 WARN, 서버 내부 경로 요청 로그 | 404면 시크릿 미설정, 401이면 불일치, 연결 실패면 사설 DNS와 보안 그룹 |
