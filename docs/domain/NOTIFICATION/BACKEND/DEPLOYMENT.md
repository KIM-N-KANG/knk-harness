# 배포

이 문서는 NOTIFICATION 도메인이 포함된 서버와 알림 서비스의 배포 단위와 의존 대상, 배포 경로, 환경 변수와 시크릿, 배포 조건, 설정 변경, 적용과 복구 절차를 정한다.

서버 전체 배포 절차 중 NOTIFICATION 도메인과 관련된 항목만 다룬다.

재시도와 시간 한도는 오류 처리에, 관측 스택과 조회 도구는 관측에 있다. ([재시도와 시간 한도](ERROR-HANDLING.md#재시도와-시간-한도), [관측 스택](OBSERVABILITY.md#관측-스택))

<br>

### 배포 단위와 의존성

배포 단위는 서버 컨테이너와 알림 서비스 컨테이너다. 개발에서는 알림 서비스가 서버와 같은 태스크에서 실행된다. 운영에서는 알림 서비스가 별도 ECS 서비스로 실행된다. 이 도메인이 기동과 요청 처리에 쓰는 의존 대상은 다음과 같다.

| 의존 대상 | 내용 | NOTIFICATION 도메인이 쓰는 것 |
|---|---|---|
| PostgreSQL | 기동 시 마이그레이션 적용 | 토큰, 동의 컬럼, 템플릿, 캠페인, 아웃박스, 알림 내역, 발송 결과 |
| Redis | 서버와 알림 서비스가 같은 인스턴스 | 회차 선점, 쿨다운, 멱등 기록 |
| 메시지 큐 | SQS 표준 큐와 실패 메시지 큐 | 발송 요청 전달 |
| FCM | 서비스 계정 인증 | 발송 |
| 서버 내부 API | 개발은 같은 태스크 안의 주소, 운영은 사설 DNS | 자격 조회, 무효 토큰 삭제 |
| Secrets Manager | Terraform이 태스크 정의에 참조 주입 | 공유 시크릿, FCM 자격 증명 |
| 공개 ALB | 운영 | 내부 경로 차단 |
| Data Prepper | 트레이스를 받아 OpenSearch에 적재 | 두 단위의 트레이스 전송 |

<br>

| 의존 대상 | 연결과 설정 실패 시 동작 |
|---|---|
| FCM 자격 증명 | 비어 있으면 기동은 정상이고 발송만 비활성<br>비어 있지 않은데 해석할 수 없으면 기동 실패 |
| 큐 주소 | 개발과 운영 프로파일의 원격 모드 서버와 알림 서비스에서 비어 있으면 기동 실패 |
| 공유 시크릿 | 비어 있으면 내부 API가 없는 경로로 응답<br>알림 서비스의 자격 조회가 전부 실패 |
| 서버 내부 주소 | 비어 있으면 알림 서비스는 기동하되 자격 조회 실패로 발송 없음 |
| 아웃박스 설정 | 임대가 전송 제한과 같거나 짧거나, 시간 값이 0 이하이거나, 백오프 상한이 초기값보다 작으면 기동 실패 |
| 소비자 시간 설정 | 선점 수명이 재전달 가능 시간 이상이거나, 처리 예산이 선점 수명 이상이거나, 재전달 횟수가 2 미만이거나, 시간 값이 0 이하면 기동 실패 |
| 문구 기본값 | 설정에 없으면 기동 실패 |
| PostgreSQL | 연결할 수 없으면 서버 기동 실패 |
| Redis | 필요한 시점에 연결<br>서버: 출석과 이프 만료 예정 회차의 선점 실패는 건너뜀, 이프 만료 예정 회차의 커밋 뒤 쿨다운 기록 실패는 내역과 요청 유지<br>알림 서비스: 재전달 |
| 큐 | 서버: 아웃박스에 보존하고 백오프<br>알림 서비스: 수신 중단 |
| Data Prepper | 추적을 켜고 주소가 비면 기동 실패<br>추적이 꺼지면 스팬을 만들되 전송하지 않음 |

<br>

### 배포 경로

두 저장소가 각자 테스트와 빌드를 마친 뒤 이미지를 게시하고 배포한다.

| 단계 | 개발 | 운영 |
|---|---|---|
| 자동 시작 | `dev` push | `main` push |
| 이미지 태그 | 커밋 SHA, 환경 태그 `dev` | 커밋 SHA<br>알림 서비스는 실패하면 이전 digest로 복원 |
| 배포 | 서버: 서버 배포 절차<br>알림 서비스: 최신 `dev` SHA 확인 뒤 같은 태스크 전체 재시작 | 서버: 서버 배포 절차<br>알림 서비스: 별도 서비스 배포 |
| 상태 검사 | 서버, AI, 알림 컨테이너 모두 정상, health `UP` | 배포 완료와 health `UP` |

<br>

### 환경 변수와 시크릿

환경 변수가 설정 파일의 값보다 우선한다. 설정은 기동 시 읽으므로 변경 뒤 새 태스크를 시작해야 적용된다. 값은 Terraform이 태스크 정의에 주입하고 시크릿은 Secrets Manager에서 주입한다. AWS 자원에는 태스크 역할로 접근하므로 별도 접근 키를 주입하지 않는다. 이 도메인이 읽는 설정만 적는다. 기본값이 "빈 값"이면 변수가 없어도 빈 문자열로 기동한다. "없음"이면 변수가 없을 때 기동에 실패한다.

### 배포 조건

| 확인 항목 | 기준 | 자동 여부와 한계 |
|---|---|---|
| 메시지 큐와 소비자 설정 | 메시지 큐의 가시성과 수신 상한을 소비자 재전달 설정에 그대로 주입 | Terraform이 같은 지역 변수로 주입 |
| 공유 시크릿 | 서버와 알림 서비스에 같은 값<br>빈 값 거부 | 수동 검토<br>길이만 검사하고 값은 기록하지 않음 |
| Firebase 프로젝트 | 서버와 알림 서비스의 자격 증명이 앱과 같은 프로젝트 | 수동 검토 |
| 발송 모드 전환 | 알림 서비스가 메시지 큐를 소비하는 것을 확인한 뒤 서버를 원격 모드로 전환 | 수동 결정 |
| 시나리오 추가 | 큐 메시지 검증의 허용 시나리오를 알림 서비스에 먼저 배포<br>서버는 발송 결과 보고의 `type`, 알림 내역의 `type` CHECK 마이그레이션, 템플릿 키를 같은 릴리스에 포함 | 수동 검토 |
| 와이어 계약 변경 | 푸시 데이터가 바뀌면 앱과 웹의 처리를 함께 배포 | 수동 검토 |
| 컬럼 제거 | 그 컬럼을 읽는 구버전 태스크가 사라진 다음 릴리스에서 제거 | 수동 검토 |
| 마이그레이션 | 기동 시 실행하므로 새 마이그레이션은 해당 코드보다 먼저 적용<br>재실행해도 같은 결과 | 기동 시 자동 적용<br>마이그레이션 경로 변경 PR은 `tbls lint`와 `dbdoc/` 비교를 CI에서 자동 실행 |
| 코드 테스트 | 두 저장소의 전체 테스트 통과 | CI 자동 |
| 컨테이너 기동 | 컨테이너 헬스체크와 `/actuator/health` `UP` | CI 자동<br>FCM과 메시지 큐 연결은 검사하지 않음 |

<br>

### 설정 변경

| 변경 대상 | 변경 위치와 적용 | 확인 조건 |
|---|---|---|
| 출석 리마인드와 이프 만료 예정 알림 문구 | 템플릿 행 추가<br>갱신 주기 안에 반영, 재배포 없음 | 다음 회차의 발송 문구 |
| 프로모션 예약과 취소 | 캠페인 행 추가, 선점 전 취소 상태 변경 | 캠페인 행의 결과 컬럼 |
| 발송 모드 | Terraform 변수 변경 후 새 태스크 시작 | 원격이면 아웃박스 행과 메시지 큐의 가시 메시지 수, 로컬이면 서버 발송 지표 |
| 공유 시크릿 | Secrets Manager 값 변경 후 서버와 알림 서비스 모두 새 태스크 시작 | 교체 중에는 자격 조회가 실패해 재전달됨 |
| FCM 자격 증명 | Secrets Manager 값 변경 후 새 태스크 시작 | 발송 지표의 `failure`가 늘지 않음 |
| 출석 발송 시각 | 환경 변수 변경 후 새 태스크 시작 | 야간 구간으로 옮기면 야간 동의자에게만 발송 |
| 이프 만료 예정 발송 시각 | 환경 변수 변경 후 새 태스크 시작 | 옮긴 시간만큼 만료 창이 겹치거나 비어 그 구간의 로트가 두 번 들거나 빠짐<br>겹침의 중복은 쿨다운이 막음 |
| 소비자 시간 설정 | Terraform 변경 후 apply | 메시지 큐 설정과 함께 바꿈 |
| 추적과 지표 전송 | 운영 Terraform 변수 변경 후 apply | 지표는 서버만 해당 |

### 적용과 복구

**1. 적용 순서**

| 순서 | 작업 | 확인 항목 |
|---|---|---|
| 1 | 설정과 시크릿 확인 | 두 단위의 시크릿 일치, 큐 주소, 서버 내부 주소, 마이그레이션 순서 |
| 2 | 동반 배포 확인 | 새 시나리오는 알림 서비스 먼저<br>푸시 데이터 변경은 클라이언트와 함께 |
| 3 | 배포 실행 | 알림 서비스 뒤 서버 |
| 4 | 적용 결과 확인 | 배포 후 확인 항목 |

<br>

**2. 진행 중인 요청**

| 상황 | 처리와 한계 |
|---|---|
| 롤링 교체 중 아웃박스 | 임대가 끝나면 새 태스크의 릴레이가 이어받음 |
| 롤링 교체 중 큐 소비 | 처리 중 메시지는 가시성 시간이 지나면 재전달<br>선점 수명이 지나면 새 소비자가 처리 |
| 알림 서비스 중단 | 메시지 큐에 적체되고 서버는 영향 없음<br>재기동 뒤 소비 |
| 서버 중단 | 알림 서비스의 자격 조회가 실패해 재전달<br>상한을 넘기면 실패 메시지 큐 |
| 출석과 이프 만료 예정 회차 중 교체 | 두 태스크가 동시에 실행돼도 선점 키로 한 번만 실행<br>커밋 전에 종료되면 그날 요청이 남지 않음 |
| 프로모션 회차 중 교체 | 전송 중 상태로 남으며 운영자가 예약으로 되돌리면 다시 실행 |
| 개발 stop-then-start | 알림 서비스 배포도 서버와 같은 태스크 전체를 재시작<br>교체 중 모든 요청 실패<br>데이터 컨테이너 재시작 |

<br>

**3. 복구**

자동 복구가 실행돼도 서비스가 정상으로 돌아오지 않았을 수 있으므로 실제 서버 상태를 확인한다.

| 상황 | 복구 방식 | 한계와 확인 사항 |
|---|---|---|
| 새 태스크 헬스체크 실패 | 직전 배포로 자동 복귀 | 환경 태그가 실패한 이미지를 가리킬 수 있으므로 다음 재배포 전에 태그 확인 |
| 배포는 정상이나 동작 오류 | revert 커밋 릴리스 또는 이전 이미지를 환경 태그로 다시 태깅한 뒤 새 배포 | health 기반 자동 복구는 발송 실패를 탐지하지 않음 |
| 마이그레이션 적용 후 되돌리기 | 적용된 마이그레이션은 되돌리지 않음 | 새 컬럼은 구버전 코드와 호환되도록 추가 |
| 실패 메시지 큐 적체 | 원인 해결 뒤 본 큐로 되돌림 | 되돌린 메시지는 멱등 기록이 남아 있으면 발송 없이 확인 |
| 원격 모드 장애 | 서버를 로컬 모드로 되돌림 | 서버에 FCM 자격 증명이 있어야 함<br>릴레이가 멈춰 아웃박스의 미발행 행은 그대로 남음<br>원격으로 다시 전환하면 포기 시각이 지난 행은 발행 없이 포기로 기록되고 나머지만 발행됨 |
| 잘못 보낸 광고 | 회수 불가 | 캠페인 취소는 선점 전에만 유효 |
| 설정 오류 | 잘못된 값을 이전 값으로 복구 후 새 태스크 시작 | 이미지 복원만으로 설정은 복원되지 않음 |

<br>

### 배포 후 확인

| 확인 항목 | 자료 | 기준 |
|---|---|---|
| 기동 | 두 단위의 해당 배포 ID 태스크 상태, 헬스체크 `/actuator/health`, 스모크 테스트 | 의도한 이미지로 기동, `UP` |
| 메시지 큐 소비 | 메시지 큐의 가시 메시지 수, 실패 메시지 큐 경보 | 적체가 늘지 않고 경보 없음 |
| 발송 | 발송 지표의 `failure` | 배포 전과 같은 수준 |
| 아웃박스 | 아웃박스 지표의 `retry`와 `abandoned` | 늘지 않음 |
| 내부 API | 요청 로그의 내부 경로 상태 | 경로 없음 응답과 인증 실패 응답이 없음 |
| 실패 메시지 큐 | 경보 | 발생 없음 |

<br>

### 배포 실패 진단

| 실패 상황 | 확인할 자료와 위치 | 원인별 조치 |
|---|---|---|
| 기동 중 설정 검증 실패 | 시작 로그의 예외 메시지 | 서버: 원격 모드의 큐 주소, 아웃박스 설정, 문구 기본값, FCM 자격 증명 해석, 추적 주소 누락 중 해당 값 수정 후 새 태스크 시작<br>알림 서비스: 큐 주소, 소비자 시간 설정, FCM 자격 증명 해석 중 해당 값 수정 후 새 태스크 시작 |
| 자격 조회가 전부 실패 | 알림 서비스의 조회 실패 WARN, 서버 내부 경로 요청 로그 | 없는 경로 응답이면 시크릿 미설정<br>인증 실패 응답이면 시크릿 불일치<br>연결 실패면 사설 DNS와 보안 그룹 확인 |
| 메시지 큐가 적체되고 소비가 없음 | 알림 서비스 태스크 상태, 큐 주소 | 태스크 수와 주소 확인 |
| 발송이 전부 실패 | 발송 지표, 발송 실패 WARN의 오류 코드 | 인증 오류면 자격 증명과 Firebase 프로젝트 확인 |
| 아웃박스가 발행되지 않음 | 아웃박스 지표의 `retry`, 릴레이 로그 | 메시지 큐 권한과 주소 확인 |
| 출석 리마인드가 나가지 않음 | 회차 로그, 선점 실패 로그, 아웃박스 지표 | 회차 로그가 없으면 Redis 연결과 스케줄러 활성화 확인<br>요청은 기록됐는데 발송이 없으면 아웃박스 발행과 큐 소비 확인 |
| 이프 만료 예정 알림이 나가지 않음 | 회차 로그, 선점 실패 로그, 아웃박스 지표, 알림 내역 행 | `targets`가 0이면 창 안 로트 보유 회원이 없고 `targets`와 `cooldown`이 같으면 전부 쿨다운<br>내역은 있는데 푸시가 없으면 발송 결과의 `reason` 확인<br>회차 로그가 없으면 Redis 연결과 스케줄러 활성화 확인 |
| 발송 결과가 기록되지 않음 | 알림 서비스의 `push_delivery_report_failed` WARN | 요청 거절 응답이면 서버의 `type` 목록 미확장 |
| 실패 메시지 큐 경보 | 실패 메시지 큐의 메시지 본문 | 검증 실패면 메시지 형식 확인<br>재전달 초과면 자격 조회나 FCM 장애 확인 |
