# 5-2 동시성

이 문서는 NOTIFICATION 도메인의 행 잠금과 잠금 순서, 멱등과 1회 처리, 유니크 위반, 회차와 발송 요청의 선점, 소비자 선점, 수용한 경쟁 조건을 정한다.

흐름별 단계와 트랜잭션 경계는 처리 흐름에, 선점 시간과 재전달 간격은 오류 처리에 있다. ([4-1 처리 흐름](4-1-PIPELINES.md), [5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도))

<br>

### 5-2-1 사용자 행 잠금

토큰 등록과 삭제, 수신 동의 조회와 변경은 사용자 행에 비관적 잠금을 건다. 토큰 등록은 이어서 토큰 행을 잠근다.

| 경로 | 막는 경쟁 조건 |
|---|---|
| 토큰 등록 | 탈퇴가 토큰을 지우고 커밋한 뒤 대기하던 등록이 탈퇴 회원에게 토큰을 남기는 경쟁 조건<br>커밋 전 삭제 중인 토큰 행을 읽어 갱신이 0건이 되는 경쟁 조건 |
| 토큰 삭제 | 정지와 탈퇴 커밋 후의 요청 |
| 수신 동의 조회와 변경 | 탈퇴 커밋 후에 동의가 바뀌는 경쟁 조건 |
| 완성 알림 내역 기록 | 탈퇴 커밋 뒤 늦게 끝난 완성이 탈퇴가 지운 내역을 다시 만드는 경쟁 조건<br>완성 요청 행 다음에 사용자 행을 잠그며 탈퇴는 완성 요청 행을 잠그지 않아 교차 대기가 없음 |
| 공개 중단 알림 내역 기록 | 탈퇴 커밋 뒤 늦게 끝난 공개 중단이 탈퇴가 지운 내역을 다시 만드는 경쟁 조건<br>MODERATION이 소유 회원 행을 스토리 행보다 먼저 잠그고 탈퇴는 스토리 행을 잠그지 않아 교차 대기가 없음 |

잠금 순서는 사용자 행 다음 토큰 행이다. 탈퇴 처리의 순서도 사용자 행이 먼저이므로 탈퇴와는 교차 대기가 생기지 않는다. 상한 초과 삭제는 소유자 조건을 삭제문 안에 두어 후보를 뽑은 뒤 소유자가 바뀐 행을 지우지 않는다.

### 5-2-2 멱등과 1회 처리

| 대상 | 처리 |
|---|---|
| 토큰 등록 | 같은 토큰은 갱신 |
| 토큰 삭제 | 없는 토큰도 같은 응답 |
| 수신 동의 변경 | 같은 값의 반복 요청은 동의 시각을 바꾸지 않음 |
| 스토리 완성 요청 | 완성 요청 행의 완료 표시에 한 번만 도달<br>메시지 식별자가 요청 ID라 아웃박스 유니크가 중복 기록을 막음 |
| 검수 완료 요청 | 제출본 식별자와 회차로 식별자 구성<br>같은 회차는 한 번만 |
| 공개 중단 요청 | 스토리 공개 식별자와 공개 중단 시각으로 식별자 구성<br>공개 중단 한 번에 한 번만 |
| 큐 소비 | 메시지 식별자별 완료 기록이 있으면 발송 없이 확인<br>성공한 토큰은 재전달 때 제외 |
| 출석 회차 | 날짜 키 선점에 성공한 인스턴스만 실행<br>메시지 식별자가 회원과 날짜로 구성되어 회원당 하루 한 건만 기록 |
| 이프 만료 예정 회차 | 날짜 키 선점에 성공한 인스턴스만 실행<br>메시지 식별자가 회원과 날짜로 구성되어 알림 내역과 발송 요청이 회원당 하루 한 건<br>쿨다운 키로 회원당 7일에 한 번만 대상 |
| 발송 결과 보고 | 메시지 식별자 유니크로 첫 보고만 기록<br>재보고와 동시 보고는 저장 없이 성공 |
| 캠페인 회차 | 캠페인 행의 조건부 갱신으로 선점에 성공한 인스턴스만 실행<br>원격 모드는 메시지 식별자가 캠페인과 회원으로 구성되어 재실행해도 회원당 한 건만 기록<br>로컬 모드는 회원별 기록이 없어 재실행 시 중복 발송을 수용 |
| 캠페인 취소와 재실행 | 상태 조건이 붙은 조건부 갱신<br>선점과 취소가 겹치면 한쪽만 성공 |
| 공지 알림 캠페인 | 공지 식별자 유니크로 공지당 한 건 |
| 문구 템플릿 변경 | 행 추가라 반복하면 같은 문구의 행이 늘어남<br>시작이 같으면 나중에 추가된 행이 적용되므로 결과는 같음 |
| 알림 내역 기록 | 회원과 메시지 식별자 유니크로 회원당 한 행<br>완성 재처리, 회차 재실행, 모드 전환 뒤에도 중복 없음 |
| 알림 읽음과 모두 읽음 | 요청자 소유이며 `read_at IS NULL`인 행만 조건부 갱신<br>반복하거나 겹쳐도 최초 읽음 시각 유지 |

### 5-2-3 유니크 위반 처리

| 대상 | 처리 |
|---|---|
| 푸시 토큰 `token` | 같은 새 토큰을 동시에 처음 등록하면 한쪽이 서버 오류로 실패<br>중복 행은 생기지 않으며 재시도는 갱신으로 성공 |
| 아웃박스 `message_id` | 충돌 무시 삽입이라 위반이 드러나지 않음 |
| 발송 결과 `message_id` | 충돌을 무시하고 삽입하므로 위반이 드러나지 않음 |
| 알림 내역 `user_id`, `message_key` | 충돌을 무시하고 삽입하므로 위반이 드러나지 않음 |
| 캠페인 `notice_id` | 공지 도메인이 게시 잠금 안에서 1회 판정하므로 위반에 이르지 않음<br>위반이 나면 게시 트랜잭션이 롤백 |

<br>

### 5-2-4 발송 요청의 선점과 임대

| 상황 | 처리 |
|---|---|
| 릴레이 선점 | 잠긴 행을 건너뛰며 미발행 행을 선점하고 다음 시도 시각을 임대 만료로 옮긴 뒤 커밋<br>발행은 트랜잭션 밖 |
| 임대 중 종료 | 임대가 끝나면 다른 릴레이가 다시 선점 |
| 늦은 결과 | 다음 시도 시각이 자기 임대 시각일 때만 결과를 기록<br>재선점된 행의 새 시도 결과를 덮어쓰지 않음 |
| 임대와 전송 제한 | 임대는 배치 전체의 전송 제한보다 길고 브로커 클라이언트의 제한은 전송 제한보다 짧음 |
| 중복 발행 | 발행 성공과 완료 기록 사이에 장애가 나면 재발행하며 소비자 멱등 처리가 중복 처리를 막음 |

<br>

### 5-2-5 소비자 선점

| 상황 | 처리 |
|---|---|
| 처리 중 선점 | 메시지 식별자 키를 소유자 값과 선점 수명으로 선점<br>완료 표시가 있으면 확인, 다른 소유자면 재전달 |
| 선점 연장 없음 | 처리 중 소비자가 종료돼도 재전달 가능 시간 안에 다른 소비자가 다시 선점하도록 수명을 늘리지 않음 |
| 소유자 확인 | 완료 기록, 해제, 성공 기기 기록은 자기 소유자 값일 때만 반영<br>이전 소유자의 늦은 완료 기록이 새 처리 결과를 덮어쓰지 않음 |
| 가시성 만료 재수신 | 처리가 큐 가시성 시간을 넘겨 다른 소비자가 받아도 처리 중 키가 남아 발송 없이 재전달<br>먼저 처리한 소비자의 삭제가 반영되지 않으면 다음 수신에서 완료 키로 확인 |
| 동시 처리 수 | 인스턴스당 2건 |

### 5-2-6 수용한 경쟁 조건

| 상황 | 수용 이유 |
|---|---|
| 상한에 찬 두 회원의 교차 등록 | 삭제 시 잠금 순서가 교차해 한쪽이 실패<br>재시도로 성공하고 손상 없음<br>발생 빈도에 비해 삭제 후보까지 정렬해 잠그는 비용이 큼 |
| 처리 시간이 선점 수명을 넘김 | 정확히 한 번 도달은 보장하지 않음<br>유실보다 중복을 택함<br>소유자 비교가 완료와 삭제의 충돌만 막음 |
| 멱등 기록 제거 | 운영 Redis는 메모리가 부족하면 수명이 있는 키를 먼저 제거<br>멱등 기록 수명 안에도 드물게 중복 가능 |
| 회차 커밋과 쿨다운 기록 사이의 장애 | 내역과 요청은 남고 쿨다운이 없어 다음 회차에 한 번 더 받을 수 있음<br>일부 회원만 쿨다운이 걸린 상태도 가능<br>정보성 알림이라 수용 |
| 회차 중간의 인스턴스 종료 | 커밋 전이면 요청이 남지 않음<br>출석과 이프 만료 예정은 날짜 키가 잡혀 있어 그날 누락되고 다음 날 회차로 넘어감<br>캠페인은 전송 중으로 남았다가 시간 한도 뒤 스케줄러가 실패로 바꾸고 관리자가 재실행<br>식별자 유니크로 이미 기록된 회원은 다시 기록되지 않음 |
| 전송 중 시간 초과 전환과 늦게 끝난 회차 | 조건부 갱신으로 한쪽만 성공<br>회차가 먼저 결과를 기록하면 전환이 0행이고, 전환이 먼저면 회차의 늦은 결과 기록은 전송 중 조건에 걸려 무시됨<br>전환 뒤 재실행으로 새 회차가 전송 중이 되어도 옛 회차의 결과 기록은 선점 시각이 달라 0행 |
| 두 소비자가 선점 수명을 넘겨 같은 메시지를 각각 완료 | 보고도 두 건이지만 유니크로 한 행만 남음<br>먼저 도착한 보고의 기기 수가 남음 |
| 탈퇴와 겹친 내역 기록 | 회차의 조회 삽입이 탈퇴 커밋 전의 활성 상태를 읽으면 탈퇴 회원의 행이 남을 수 있음<br>탈퇴 계정은 조회할 수 없고 행에 알림 사본만 있어 사용자 행 잠금을 회차에 더하지 않음 |
| 모두 읽음과 새 내역 기록 | 갱신 뒤 커밋된 행은 안 읽음으로 남음<br>요청 시점까지의 내역만 읽음으로 보는 것이 의도와 같음 |
| 취소 요청과 선점이 같은 순간 | 조건부 갱신으로 한쪽만 성공<br>선점에 성공하면 취소는 거절되고 발송됨 |
