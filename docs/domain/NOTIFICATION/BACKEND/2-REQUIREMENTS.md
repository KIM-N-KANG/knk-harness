# 2. 요구사항

이 문서는 NOTIFICATION 도메인의 백엔드가 처리해야 하는 동작, 요구 주체, 다른 주체와의 역할 분담, 제품 제약과 데이터 보존 기준을 정한다.

요청과 응답의 필드는 계약에, 처리 순서는 처리 흐름에, 재시도와 시간 한도는 오류 처리에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도))

<br>

### 2-1 요구 주체

백엔드는 회원의 토큰과 동의를 보관하고 발송 요청을 만든다. 알림 서비스는 요청을 소비해 보낸다. 각 주체의 역할과 백엔드에 기대하는 동작은 다음과 같다.

| 주체 | 하는 일 | 백엔드에 기대하는 것 |
|---|---|---|
| 클라이언트 | FCM에서 토큰을 받아 등록하고 로그아웃 때 삭제<br>알림 권한 요청과 광고 동의 안내<br>받은 푸시를 표시하고 눌렀을 때 이동<br>수신자 식별자를 현재 회원과 대조 | 웹과 Android가 같은 계약으로 호출할 수 있는 엔드포인트<br>같은 토큰을 반복 등록해도 되는 멱등 등록<br>시나리오를 구분할 수 있는 푸시 데이터<br>동의 상태를 토글 값으로 조회 |
| FCM | 토큰 발급과 회전, 기기로 전달, 무효 토큰 통지 | 플랫폼별 메시지 구성<br>무효 토큰 정리 |
| 알림 서비스 | 큐를 소비해 자격을 조회하고 FCM으로 발송<br>멱등 기록 관리 | 발송 직전 자격과 토큰을 돌려주는 내부 API<br>무효 토큰 삭제 내부 API<br>큐 메시지 스키마 |
| 메시지 큐 | 발송 요청 전달과 재전달, 실패 메시지 보존 | 재전달 간격과 상한에 맞는 소비자 선점 시간 |
| 스토리 | 간편 제작 완성 시 알림 요청 | 완성 기록과 같은 트랜잭션에 발송 요청 기록<br>발송 실패가 제작 응답을 바꾸지 않음 |
| 검수 | 제출본 종료 시 알림 요청 | 결과별 문구와 이동 대상<br>같은 제출본의 회차를 구분하는 메시지 식별자 |
| 계정 | 탈퇴 시 토큰 삭제 요청 | 회원의 토큰 전부 삭제 |
| 이프 | 출석 보상의 멱등 키 보유 | 당일 출석 미수령 회원 판정 |
| 운영자 | 프로모션 예약과 취소, 문구 변경, 실패 메시지 확인 | 릴리스 없이 반영되는 예약과 문구<br>회차 결과 기록 |

<br>

### 2-2 기능 요구사항

| 기능 | 백엔드가 보장하는 것 |
|---|---|
| 토큰 등록 | 같은 토큰 재등록은 갱신<br>다른 회원이 같은 토큰을 등록하면 소유자 이동<br>회원당 기기 상한을 넘으면 가장 오래 갱신되지 않은 토큰부터 삭제<br>게스트는 등록 불가 |
| 토큰 삭제 | 요청자 소유 토큰만 삭제<br>없거나 타인 소유면 아무 일 없이 성공<br>탈퇴는 회원의 토큰 전부 삭제 |
| 수신 동의 | 서비스, 광고, 야간 광고의 세 값을 조회하고 전체 교체<br>광고 동의를 켜면 최초 동의 시각 보존, 끄면 야간도 함께 철회<br>광고 동의 없이 야간만 켜는 요청 거절 |
| 발송 자격 | 활성 계정, 종류별 동의, 등록 토큰 보유를 발송 직전에 판정<br>거절 시 토큰을 돌려주지 않음<br>광고는 판정 시각의 야간 여부까지 확인 |
| 스토리 완성 알림 | 회원의 간편 제작 완성 기록과 같은 트랜잭션에서 발송 요청 생성<br>같은 요청의 재처리에는 다시 만들지 않음 |
| 검수 완료 알림 | 제출본의 통과, 반려, 실패 기록과 같은 트랜잭션에서 발송 요청 생성<br>결과별 문구와 내 제작 목록 이동 |
| 출석 리마인드 | 매일 아침 광고 동의 회원 중 당일 출석 미수령자에게 발송<br>하루 1회<br>회원마다 발송 직전 자격 재확인 |
| 프로모션 | 운영자가 예약한 시각 이후 광고 동의 회원 전원에게 발송<br>한 캠페인은 한 인스턴스만 처리<br>야간에는 야간 동의자에게만<br>회차 결과를 캠페인에 기록 |
| 문구 템플릿 | 유효한 오버라이드가 있으면 그 문구, 없으면 기본 문구<br>적용 기간이 지나면 즉시 기본 문구<br>광고 표기는 서버가 붙임 |
| 발송 요청 기록 | 원격 모드에서 도메인 커밋과 같은 트랜잭션에 기록<br>기록 실패는 도메인 커밋도 되돌림 |
| 큐 중계 | 미발행 요청을 선점해 발행<br>실패는 지수 백오프로 재시도<br>24시간이 지나면 포기하고 기록 |
| 큐 소비 | 메시지 식별자별로 한 번만 처리<br>만료된 요청은 발송 없이 폐기<br>처리 중 종료되면 재전달에서 이어서 처리 |
| 발송 | 허용된 토큰마다 FCM 호출<br>플랫폼별 메시지 구성<br>성공한 기기는 재전달 때 제외 |
| 무효 토큰 정리 | FCM이 무효라고 알린 토큰만 삭제<br>페이로드 오류와 구분 |
| 수신자 식별 | 모든 푸시 데이터에 수신 회원의 공개 식별자 포함<br>호출자가 같은 키를 넣어도 서버 값이 우선 |
| 계정 상태 | 정지 계정의 토큰 등록과 삭제, 동의 조회와 변경 거절<br>정지와 탈퇴 계정에 발송하지 않음 |

### 2-3 다른 주체와의 역할 분담

| 판단과 작업 | 담당 |
|---|---|
| 기기의 알림 권한 요청과 상태 | 클라이언트 |
| 토큰 발급, 회전, 기기 전달 | FCM |
| Android 알림 문구 조립과 표시 | 앱<br>서버는 데이터만 보냄 |
| 웹 알림 표시 | 브라우저<br>서버가 제목, 본문, 아이콘, 클릭 링크를 실음 |
| 알림을 눌렀을 때의 이동과 딥링크 검증 | 클라이언트 |
| 수신자 식별자와 현재 회원 대조 | 클라이언트<br>웹 백그라운드 수신은 대조할 수 없어 로그아웃 시 토큰 삭제가 방어선 |
| 광고 동의의 안내와 처리 결과 통지 | 클라이언트 |
| 캠페인 예약과 취소, 문구 변경 | 운영자가 저장소에서 직접 변경 |
| 큐의 재전달과 실패 메시지 보존 | 메시지 큐 |
| 실패 메시지의 확인과 되돌리기 | 운영자 |
| 출석 미수령 판정의 기준 | 이프 도메인의 출석 보상 멱등 키 |

### 2-4 제품 제약

**1. 입력**

| 항목 | 규칙 |
|---|---|
| 토큰 | 1~512자, 공백 불가 |
| 플랫폼 | `ANDROID`, `WEB` |
| 수신 동의 변경 | 세 필드 모두 필수 |
| 수신자 식별자 | 회원 공개 식별자 UUID |
| 발송 요청의 데이터 | 문자열 값만 |

<br>

**2. 개수와 한도**

| 항목 | 값 |
|---|---|
| 회원당 기기 | 10개 |
| 발송 대상 토큰 | 회원당 최근 갱신 10개 |
| 문구 제목과 본문 | 100자, 300자 |
| 야간 | KST 21:00부터 08:00 전까지 |
| 출석 리마인드 | 매일 09:00 KST, 하루 1회 |
| 발송 요청 포기 | 기록 후 24시간 |
| 큐 재전달 | 60초 간격, 최대 5회 수신 |
| 처리 기록 보존 | 7일 |

<br>

**3. 알림 종류**

| 시나리오 | 분류 | 동의 | Android 우선순위 | 유효 기한 | 딥링크 |
|---|---|---|---|---|---|
| 스토리 완성 | 서비스 | 서비스 알림 켜짐 | 높음 | 없음 | 스토리 상세 |
| 검수 완료 | 서비스 | 서비스 알림 켜짐 | 높음 | 없음 | 내 제작 목록 |
| 출석 리마인드 | 광고 | 광고 동의, 야간이면 야간 동의 | 보통 | 당일 KST 자정 | 이프 화면의 무료 탭 |
| 프로모션 | 광고 | 광고 동의, 야간이면 야간 동의 | 보통 | 없음 | 없음 |

<br>

### 2-5 데이터 보존

| 대상 | 요구사항 |
|---|---|
| 푸시 토큰 | 회원 소유 동안 보존<br>삭제 요청, 탈퇴, 무효 통지, 기기 상한 초과 시 삭제 |
| 수신 동의 | 회원 행에 현재 상태만 보존<br>광고와 야간은 최초 동의 시각, 철회는 비움<br>이력 표는 두지 않음 |
| 문구 템플릿 | 운영자가 지울 때까지 보존 |
| 캠페인 | 영구 보존<br>회차 결과를 같은 행에 기록 |
| 발송 요청 | 발행 뒤에도 보존<br>정리 작업 없음 |
| 멱등 기록 | 처리 완료 후 7일 |
| 실패 메시지 | 실패 메시지 큐에 14일 |
| 토큰 원문 | 로그에는 앞 12자만<br>요청 경로와 큐 메시지에 싣지 않음 |
| FCM 자격 증명과 내부 공유 시크릿 | 설정에만 두고 저장소와 로그에 기록하지 않음 |
