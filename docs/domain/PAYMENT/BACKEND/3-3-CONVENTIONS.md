# 3-3 구현 컨벤션

이 문서는 PAYMENT 도메인 코드를 작성하거나 수정할 때 반드시 지킬 규칙과 구현자가 선택할 수 있는 사항을 정한다.

트랜잭션과 잠금은 동시성에, 로그 이벤트 규칙은 관측에, 비밀값 취급은 보안에, 구현 위치는 AGENTS.md에 있다. ([5-2 동시성](5-2-CONCURRENCY.md), [5-4-3 구조화 로그 이벤트](5-4-OBSERVABILITY.md#5-4-3-구조화-로그-이벤트), [5-1-7 비밀값과 개인정보](5-1-SECURITY.md#5-1-7-비밀값과-개인정보), [AGENTS.md](AGENTS.md))

<br>

### 3-3-1 이름과 용어

| 대상 | 규칙 |
|---|---|
| 패키지 | 이프 패키지 아래에 설정, API 계층, 전송 객체, 모델, 저장 계층, 서비스, 스케줄러를 나눔 |
| 모델 이름 | 테이블의 단수형 |
| 전송 객체 | 요청은 `Request`, 응답은 `Response`를 접미사로 사용<br>와이어 필드는 camelCase<br>DB 컬럼은 snake_case |
| 사유와 상태 | 원장 사유, 주문 상태, 결제 제공자는 대문자 enum을 와이어에 그대로 노출 |
| 정책 키 | 저장과 환경 변수는 snake_case, 응답은 camelCase<br>코드는 enum으로 묶어 컴파일 시 오타를 탐지 |
| 상품 ID | `if_{총량}` |
| 용어 | 용어집을 따름 |

<br>

### 3-3-2 계층 책임

| 계층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| API 계층 | 형식 검증, 요청자 식별, 상태 코드 지정 | 비즈니스 판정, 저장 계층 호출 |
| 지갑 서비스 | 잠금, 원장과 로트 기록, 잔액 계산, 멱등과 월 상한 판정 | HTTP 상태 결정, 사유별 자격 판정 |
| 보상, 주문, 웹훅 서비스 | 자격과 상태 판정, 멱등 키 조립, 지갑 서비스 호출 | 원장과 로트 직접 기록 |
| 정책 서비스 | 스냅샷 보관과 유효값 계산 | 요청 경로에서 저장소 조회 |
| 스케줄러 | 주기 실행, 겹침 방지, 예외 전파 차단 | 비즈니스 판정 |
| 저장 계층 | 쿼리 실행<br>잠금이 필요한 조회 메서드는 이름에 잠금 여부 표시 | 비즈니스 판정 |

<br>

### 3-3-3 요청 검증과 오류

| 대상 | 규칙 |
|---|---|
| 개별 필드의 길이, 필수 여부 | 요청 객체의 필드에 애너테이션으로 선언 |
| 잔액 부족 | HTTP에 결합하지 않은 도메인 예외로 던지고 소모 엔드포인트를 가진 도메인이 변환 |
| 체험 소진 | 체험 한도 서비스가 앱 코드를 가진 예외로 던짐 |
| 유니크 위반 | 트랜잭션 밖에서 포착하고 다시 조회해 멱등하게 응답 |

<br>

### 3-3-4 이벤트와 비동기

| 대상 | 규칙 |
|---|---|
| 스케줄러 | 예외를 밖으로 내보내지 않음<br>한 번의 예외로 이후 실행이 멈추지 않게 함 |
| 지표 카운트 | 트랜잭션을 가진 별도 빈의 커밋이 끝난 뒤 기록 |
| 체험 복원 | 호출자의 응답과 스트림 종료를 막지 않도록 Redis 장애 예외를 전파하지 않고 성공 여부를 반환 |

<br>

### 3-3-5 테스트와 검증 도구

| 대상 | 규칙 |
|---|---|
| 작성 순서 | 동작을 바꾸는 작업은 실패하는 테스트를 먼저 작성 |
| 엔드포인트 변경 | 통합 테스트와 수동 호출 파일을 함께 갱신 |
| 동시성 | 잠금, 멱등 키, 유니크 제약 규칙을 바꾸면 동시 요청 테스트로 검증 |
| 시각 | KST 날짜 경계와 만료 판정은 주입한 시계로 검증 |

<br>

### 3-3-6 구현자가 선택할 수 있는 것

| 선택 가능 | 조건 |
|---|---|
| 서비스 내부의 메서드 분할과 이름 | 없음 |
| 테스트 픽스처의 구성 | 없음 |
| 조회 쿼리의 작성 방식 | 잠금 여부와 정렬 순서를 유지 |
| 로그 필드 추가 | 웹훅 시크릿, 기기 식별자 원문을 넣지 않음 |
| 상품 구성 변경 | 6종 유지, ID 유일, 기본 이프와 가격은 양수, 보너스는 0 이상 |
