# 5-1 보안

이 문서는 PAYMENT 도메인 백엔드의 인증과 권한 판정, 결제 통지 검증, 입력 검증, 비밀값과 개인정보 취급 규칙, 수용한 한계를 정한다.

경로별 인증 수준과 계정 상태별 응답은 계약에, 로그와 분석에 기록하지 않는 데이터는 관측에, 잠금과 경쟁 조건은 동시성에 있다. ([4-2-1 공통 규칙과 헤더](4-2-CONTRACT.md#4-2-1-공통-규칙과-헤더), [5-4-8 수집 조건과 실패 처리](5-4-OBSERVABILITY.md#5-4-8-수집-조건과-실패-처리), [5-2 동시성](5-2-CONCURRENCY.md))

<br>

### 5-1-1 인증 수준

| 항목 | 처리 |
|---|---|
| 불필요 경로 | 상품 목록, 정책값 조회, 체험 조회<br>토큰을 읽되 만료되거나 위조된 토큰은 익명으로 처리해 로그인 전 화면 표시 유지<br>유효한 토큰은 회원으로 식별하고 탈퇴 계정의 남은 토큰은 거절 |
| 서명 경로 | 그로블 웹훅<br>토큰을 읽지 않고 서명으로 인증 |
| 필수 경로 | 그 외 모든 PAYMENT 경로 |
| 다른 도메인의 소모 경로 | 요청자 판정은 그 도메인의 선택 인증을 따름<br>유효한 토큰이면 회원으로 지갑을 쓰고 아니면 게스트로 기기 카운터를 씀 |

<br>

### 5-1-2 소유권과 접근 판정

| 판정 | 규칙 |
|---|---|
| 지갑과 원장 | 요청자 본인 것만<br>다른 회원의 잔액과 내역을 조회하는 경로 없음 |
| 주문 | 본인 주문만<br>없는 주문과 타인의 주문을 같은 결과로 응답해 존재를 드러내지 않음 |
| 이용내역 커서 | 순차 내부 ID가 들어 있어 봉인<br>두 커서의 차이로 서비스 전체 거래량이 추정되는 것을 막음<br>변조된 커서와 다른 키로 만든 커서는 같은 결과로 거절 |
| 게스트 체험 | 기기 식별자만으로 판정<br>백엔드는 게스트를 식별할 수 없음 |

<br>

### 5-1-3 계정 상태

| 상태 | 처리 |
|---|---|
| 정지 계정 | 충전 주문 생성과 출석 보상은 처리 전에 상태를 읽어 요청 거절<br>조회는 처리 |
| 탈퇴 계정 | 남은 접근 토큰은 공통 필터가 거절<br>지갑과 원장은 보존 |
| 재가입 계정 | 보상 신원이 최초 계정이라 가입과 출석, 초대의 1회성 자격이 초기화되지 않음<br>회원 체험은 소진 상태로 시작 |
| 게스트 | 계정 상태 판정의 대상 아님 |

<br>

### 5-1-4 결제 통지 검증

| 대상 | 규칙 |
|---|---|
| 웹훅 서명 | 수신한 원본 바이트로 `{타임스탬프}.{본문}`의 HMAC-SHA256을 계산해 16진수 서명과 상수 시간 비교<br>이전 서명 헤더도 같은 방식으로 허용 |
| 웹훅 시각 | 타임스탬프가 현재 시각 기준 앞뒤 5분 밖이면 거절<br>재전송 공격이 가능한 시간 범위를 제한 |
| 검증 순서 | 서명 검증 전에 본문을 해석하지 않음 |
| 웹훅 멱등 키 | 헤더의 멱등 키는 서명 대상이 아니라 위조 가능하므로 쓰지 않음<br>서명된 본문의 이벤트 ID를 멱등 키로 사용 |
| 웹훅 금액 | 결제 금액과 환불 금액이 주문 가격과 같을 때만 적립과 회수 |

<br>

### 5-1-5 입력 검증

길이와 범위는 제품 제약을 따른다. 이 절에는 거절과 무시의 구분처럼 보안 관점의 규칙만 적는다. ([2-4 제품 제약](2-REQUIREMENTS.md#2-4-제품-제약))

| 대상 | 규칙 |
|---|---|
| 이용내역 커서 | 복호화 성공 여부만 판정<br>형식 오류, 변조, 다른 키를 구분하지 않고 같은 응답 |
| 주문 식별자 | UUID 형식 |
| 기기 헤더 | 게스트의 체험 경로에서 공백이 아닌 값 |
| 웹훅 본문 | 이벤트 ID 248자 이내, 거래 식별자 255자 이내, 금액은 정수<br>검증 규칙에 맞지 않으면 무시 |
| 정책 오버라이드 | 범위 밖 값은 저장소 제약이 거부하고 키별 최솟값 미만은 적재 시 제외 |

<br>

### 5-1-6 재화 보호

| 대상 | 규칙 |
|---|---|
| 적립 | 대사 환불을 제외한 모든 적립에 멱등 키가 있음<br>구매 적립의 멱등 키는 제공자가 서명한 이벤트 ID<br>대사 환불은 지갑 잠금 뒤 환불 수 재확인으로 1회 보장 |
| 차감 | 잔액 부족이면 아무것도 기록하지 않음<br>잔액 캐시가 음수가 되지 않도록 제약 |
| 환불 | 차감 금액을 그대로 사용<br>대사는 부족분만 발행해 초과 환불 없음 |
| 회수 | 구매 로트의 남은 수량만 회수<br>잔액을 음수로 만들지 않고 부족분은 기록 |
| 정책값 | 잘못된 값은 무시하고 기본값을 적용해 서비스 요청 처리 실패 방지<br>원장이 불변이라 잘못 지급한 이프를 회수할 수 없으므로 변경은 사람이 검토 |
| 체험 | 기기 헤더가 없는 가입은 소진 상태로 시작해 무료 체험을 다시 받지 못함<br>재가입도 소진 상태 |

<br>

### 5-1-7 비밀값과 개인정보

| 대상 | 규칙 |
|---|---|
| 웹훅 시크릿 | 설정에서만 읽고 저장소와 로그에 기록하지 않음 |
| 기기 식별자 | 카운터 키는 pepper를 더한 해시<br>원문은 저장하지 않음 |
| 이용내역 제목 | 요청자가 읽을 수 없는 스토리는 마지막 공개 스냅샷의 제목만 노출 |
| 로그 | 웹훅 무시 사유와 주문 내부 ID는 기록<br>본문 원문과 거래 식별자는 기록하지 않음 |

<br>

### 5-1-8 수용한 한계

| 한계 | 수용 이유 |
|---|---|
| 기기 헤더 변조와 기기 교체로 게스트 한도를 다시 받음 | 백엔드는 게스트를 식별할 수 없음<br>한도를 가입 전 가치 확인에 필요한 최소한으로 줄여 파밍 1건의 가치를 낮춤 |
| 정책값이 바뀐 시점을 걸친 차감 그룹은 대사에서 차액만큼 덜 돌려받음 | 초과 환불보다 미보상이 안전<br>경고 로그로 탐지 |
| 이미 소진한 구매의 환불 통지는 남은 수량만 회수 | 잔액을 음수로 만들지 않음<br>부족분은 주문에 기록해 운영자가 확인 |
| 결제를 마치지 않은 대기 주문이 쌓임 | 적립이 없어 재화에 영향 없음 |
| 정책 저장소가 끊긴 동안 상시 오버라이드를 철회할 수 없음 | 요청을 막지 않는 것을 우선<br>종료 시각이 있는 오버라이드는 장애 중에도 만료 |
| 체험 카운터에 만료가 없어 기기 식별자가 바뀔 때마다 키가 늘어남 | 키 수명과 총량 상한은 두지 않음 |
