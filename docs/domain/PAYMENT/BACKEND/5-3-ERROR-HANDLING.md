# 5-3 오류 처리

이 문서는 PAYMENT 도메인의 응답 규칙, 앱 코드, 오류 분류, 복구 규칙, 재시도와 시간 한도, 전달 실패 처리, 오류 로그 기준을 정한다.

엔드포인트별 실패 조건과 응답 형식은 계약에, 연산별 처리 순서는 처리 흐름에, 멱등과 1회 처리는 동시성에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-2-2 멱등과 1회 처리](5-2-CONCURRENCY.md#5-2-2-멱등과-1회-처리))

<br>

### 5-3-1 응답 규칙

| 항목 | 규칙 |
|---|---|
| `code` | HTTP 상태 이름이 기본<br>클라이언트 안내가 달라질 때만 앱 코드 사용 |
| `message` | 사용자 안내 문구<br>웹훅 검증의 원인은 포함하지 않음<br>500은 고정 안내 문구 |
| `details` | 선언적 필드 검증, 쿼리와 경로 변수의 타입 변환 실패 시 채움<br>서비스에서 판정한 400은 `details` 없이 `message`에 사유 기록 |
| 웹훅 응답 | 처리와 무시를 구분하지 않고 200<br>검증 실패만 4xx와 503 |

<br>

### 5-3-2 앱 코드

코드 문자열은 API 계약이므로 유지한다. 공통 필터의 `CONSENT_REQUIRED`는 공통 실패 응답에 있다.

| 상태 | `code` | 의미 |
|---|---|---|
| 409 | `IDEMPOTENCY_KEY_CONFLICT` | 관리자 이프 조정에서 같은 멱등 키에 다른 요청 |

다음 코드는 PAYMENT가 던진 예외를 소모 엔드포인트를 가진 도메인이 변환할 때 쓴다.

| 상태 | `code` | 의미 |
|---|---|---|
| 402 | `INSUFFICIENT_CREDIT` | 회원의 활성 잔액이 소모액 미만 |
| 402 | `GUEST_TRIAL_LIMIT_EXCEEDED` | 게스트 카운터가 한도에 도달 |

<br>

### 5-3-3 오류 분류

| 오류 | 발생 위치 | 처리 |
|---|---|---|
| 입력 오류 | API 계층의 선언적 검증과 본문 파싱 | 400으로 변환 |
| 상품과 설정 오류 | 주문 서비스 | 없는 상품은 400, 미설정은 503 |
| 주문 존재와 소유 | 주문 서비스 | 없는 주문과 타인의 주문은 404, 식별자 형식 오류는 400 |
| 잔액 부족 | 지갑 서비스 | HTTP에 결합하지 않은 예외로 던지고 호출 도메인이 402로 변환 |
| 한도 소진 | 체험 한도 서비스 | 앱 코드를 가진 402 예외 |
| 웹훅 검증 실패 | 웹훅 검증 | 시각과 서명은 401, 본문 형식은 400, 시크릿 미설정은 503<br>사유를 구분하지 않는 문구 |
| 웹훅 본문 불일치 | 이벤트 처리 | 무시하고 경고 기록, 200 |
| 유니크 위반 | DB | 지갑 생성은 재조회해 계속 처리. 원장 멱등 키는 오류로 응답하고 재시도는 멱등하게 처리 |
| Redis 장애, 게스트 예약과 복원 | 체험 한도 | 예외 전파<br>소모 요청은 서버 오류 |
| Redis 장애, 회원 예약 | 체험 한도 | 미예약으로 보고 이프 차감으로 진행 |
| Redis 장애, 회원 복원 | 체험 한도 | 예외를 전파하지 않고 실패를 반환<br>호출 도메인이 환불 실패로 기록 |
| Redis 장애, 스냅샷 | 체험 한도 | 미완료를 반환하고 계정 도메인이 다음 로그인에 재시도 |
| Redis 장애, 체험 조회 | 체험 한도 | 500<br>0으로 바꾸면 소진한 체험을 다시 제공하게 됨 |
| 정책 적재 실패 | 정책 서비스 | 경고 기록 뒤 직전 스냅샷 유지 |
| 멱등 키 재사용 | 이프 조정 | 같은 키에 다른 요청은 앱 코드가 있는 409 |
| 관리자 입력 오류 | 이프 조정과 정책 관리 서비스 | 범위 밖 값, 범위 밖 유효기간, 과거 종료 시각은 400, 없는 정책 키와 회원은 404, 탈퇴 계정과 잔액 0 회수는 409 |
| 감사 기록 실패 | 관리자 도메인 연산 | 변경과 함께 롤백<br>500 |
| 예상하지 못한 오류 | 모든 위치 | 전역 핸들러가 500 고정 문구로 응답하고 Sentry 전송 |

<br>

### 5-3-4 오류별 처리

- 차감이 잔액 부족으로 실패하면 만료 정리를 포함해 아무것도 기록하지 않는다. 부족 판정을 만료 정리보다 먼저 하기 때문이다.
- 웹훅 완료 처리가 주문을 찾지 못하거나 금액 오류로 끝나면 먼저 도착한 환불 금액은 표식에 남긴다. 잠금용으로만 만든 표식 행은 지운다.
- 대사의 한 그룹이나 한 차감 행이 실패하면 그것만 기록하고 나머지를 계속 처리한다.
- 기본 정책값이 최솟값 미만이면 기동을 실패시킨다. 환경 변수 실수가 배포 시점에 드러나게 한다.

<br>

### 5-3-5 재시도와 시간 한도

**1. 재시도**

- 그로블 웹훅의 재전송은 그로블이 한다. 백엔드는 같은 통지를 다시 받아도 같은 결과로 처리한다.
- 선차감 대사의 그룹별 실패는 다음 실행에서 다시 시도한다.
- 정책 적재 실패는 다음 갱신 주기에 다시 시도한다.
- 그 외에는 클라이언트가 같은 요청을 다시 보내 재시도한다.

<br>

**2. 시간 한도**

| 대상 | 제한 시간 | 적용 범위 |
|---|---|---|
| 보상과 환불 로트 | 적립 시점부터 30일 | 가입, 초대, 출석 보상, 환불 |
| 관리자 지급 로트 | 적립 시점부터 요청 일수<br>1~365일, 생략하면 30일 | 관리자 지급 |
| 구매 로트 | 적립 시점부터 5년 | 그로블 구매 |
| 승계 로트 | 없음 | 로트 도입 전 잔액 |
| 체험 카운터 | 없음 | 게스트와 회원 |
| 웹훅 타임스탬프 | 현재 시각 기준 앞뒤 5분 | 그로블 웹훅 |
| 정책 스냅샷 갱신 | 직전 갱신이 끝난 뒤 60초 | 오버라이드 반영 지연은 이 대기에 적재 시간을 더한 값 |
| 선차감 대사 | 15분 간격, 기동 뒤 첫 실행은 60초 뒤 | 마지막 차감이 15분보다 오래된 그룹만 대상 |

<br>

### 5-3-6 최종 실패와 부분 완료

| 결과 | 처리 |
|---|---|
| 선차감 뒤 환불 코드 미실행 | 대사가 기준 시각 뒤 보정<br>채팅 턴은 저장도 환불도 없는 차감 행을 그 금액으로, 간편 제작은 그룹 부족분을 보정<br>채팅 이미지 소모는 대사 대상이 아님 |
| 환불 복원의 Redis 실패 | 회원이 소진한 체험 1회가 돌아오지 않음<br>호출 도메인이 환불 실패로 관측 |
| 웹훅 완료가 왔으나 주문이 없음 | 적립 없이 무시<br>운영자가 경고 로그와 제공자 콘솔로 확인 |
| 환불 통지가 완료보다 먼저 도착 | 표식에 보관했다가 완료 때 적립 없이 환불 상태로 전이 |
| 이미 소진한 구매의 환불 | 남은 수량만 회수하고 부족분을 주문에 기록 |
| 잔액보다 큰 관리자 회수 | 잔액만큼만 회수하고 부족분을 응답과 감사 로그에 기록 |
| 관리자 지급 응답 유실 | 적립 완료<br>같은 멱등 키의 재요청은 적용 없이 같은 결과 |
| 정책 첫 적재 실패 | 기본값으로 기동<br>다음 갱신에서 반영 |
| 단가가 섞인 그룹의 대사 | 간편 제작과 참조 종류 `CHAT`인 채팅 턴 그룹만 해당<br>최소 차감액으로 환불해 차액 미보상<br>경고 기록 |

<br>

### 5-3-7 전달 실패 처리

| 상황 | 백엔드 | 클라이언트와의 경계 |
|---|---|---|
| 출석 보상 응답 유실 | 적립 완료 | 재호출은 적립 없이 200, 잔액으로 확인 |
| 주문 생성 응답 유실 | 대기 주문 생성됨 | 재호출은 새 주문<br>결제하지 않은 주문은 영향 없음 |
| 웹훅 응답 유실 | 처리 완료 | 그로블 재전송은 멱등 키와 주문 상태로 무시 |
| 결제 복귀 실패 | 웹훅은 복귀와 무관하게 처리 | 주문 조회로 상태 확인 |

<br>

### 5-3-8 로그와 Sentry

경고 로그의 이름과 기록 내용은 관측에 있다. ([5-4-3 구조화 로그 이벤트](5-4-OBSERVABILITY.md#5-4-3-구조화-로그-이벤트))

| 대상 | 규칙 |
|---|---|
| 5xx | 스택트레이스와 함께 ERROR로 기록하고 Sentry 전송 |
| 예상 가능한 4xx | Sentry 미전송<br>원인 예외가 있으면 클래스와 메시지를 한 줄로 WARN 기록. 없으면 DEBUG 기록 |
| 웹훅 검증 | 원인 예외를 기록하지 않음<br>고정 문구의 예외로 바꿔 전파 |
