# 4-1 처리 흐름

이 문서는 PAYMENT 도메인의 요청 수신부터 응답까지의 처리 단계와 다른 도메인이 호출하는 연산의 처리 단계를 정한다.

요청 필드, 응답 필드와 실패 응답은 계약에, 로트 수명과 배치 주기, 복구 규칙은 오류 처리에, 잠금과 멱등은 동시성에 있다. ([4-2 계약](4-2-CONTRACT.md), [5-3 오류 처리](5-3-ERROR-HANDLING.md), [5-2 동시성](5-2-CONCURRENCY.md))

<br>

### 4-1-1 공통 처리

모든 요청은 상관관계 필터에서 요청 ID를 받는다. 이어서 보안 필터가 경로의 인증 수준에 따라 요청자를 정한다. 상품 목록, 정책값 조회, 체험 조회는 토큰이 없어도 처리한다. 유효한 토큰이 있으면 회원으로 식별하고 탈퇴 계정은 거절한다. 그로블 웹훅은 토큰을 읽지 않고 서명으로 인증한다. 그 외 경로는 토큰이 없거나 무효이면 거절한다.

충전 주문 생성과 출석 보상은 처리 전에 계정 상태를 읽어 정지 계정의 요청을 거절한다. 조회는 정지 계정도 처리한다.

정책값은 메모리 스냅샷에서 읽는다. 한 요청 안에서 차감과 환불, 양쪽 적립처럼 같은 값을 두 번 써야 하는 경로는 요청 시작 때 한 번만 읽어 재사용한다.

잔액을 바꾸는 모든 연산은 지갑 행에 비관적 쓰기 잠금을 건 뒤 원장, 로트, 잔액을 한 트랜잭션에 기록한다. 잠금 순서는 환불 표식, 주문, 지갑, 로트 순이다.

흐름도에서 Redis, AI 서버, 다른 도메인을 호출하는 단계는 주황색이다.

<br>

### 4-1-2 적립

보상, 구매, 요청 내 환불은 같은 적립 연산을 쓴다. 호출자가 금액, 사유, 멱등 키, 참조를 정한다.

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 40}}}%%
flowchart LR
    A{"`**멱등 키가
이미 있는가**`"} -->|예| Z["`**적립 없이 응답**
현재 잔액`"]
    A -->|아니오| B["`**지갑 확인**
없으면 독립 트랜잭션으로 생성`"]
    B --> C["`**지갑 행 잠금**`"]
    C --> D["`**만료 로트 정리**
EXPIRE 행`"]
    D --> E{"`**멱등 키 재확인**`"}
    E -->|있음| Z
    E -->|없음| F{"`**월 상한 조건이 있고
상한에 도달했는가**`"}
    F -->|예| Y["`**적립 없이 응답**
상한 도달 표시`"]
    F -->|아니오| G["`**원장 행과 로트 기록**
잔액 증가`"]
    G --> H["`**응답**
적립 여부와 잔액`"]
    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D

```

- 로트의 만료 시각은 사유로 정한다. 구매는 적립 시점부터 5년, 그 외 보상과 환불은 30일이다.
- 월 상한 판정은 잠금 안에서 집계한다. 집계 조건은 사유, 기간, 멱등 키의 접두부와 접미부 패턴이다. 초대자 월 상한은 초대자 역할의 키 패턴에 해당하는 행만 센다. 집계 단위는 보상 신원이다.
- 잠금 전 멱등 확인은 이미 처리된 재시도를 잠금 없이 통과시키는 빠른 경로다. 동시 요청은 잠금 뒤 재확인과 원장 유니크 제약이 막는다.
- 지갑 생성의 유니크 위반은 독립 트랜잭션 안에서 처리한다. 바깥 트랜잭션은 이미 있는 지갑을 잠근다.

<br>

### 4-1-3 차감

간편 제작과 채팅은 차감 연산을 선차감에 쓴다. 채팅은 턴과 이미지를 항목 목록으로 한 번에 넘긴다.

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 40}}}%%
flowchart LR
    A["`**지갑 행 잠금**
지갑이 없으면 잔액 0으로 부족`"] --> B["`**활성 로트 조회**
잠금, 소진 순서 정렬`"]
    B --> C{"`**미만료 잔여 합이
합계 이상인가**`"}
    C -->|아니오| X["`**잔액 부족 예외**
아무것도 쓰지 않음`"]
    C -->|예| D["`**만료 로트 정리**
EXPIRE 행`"]
    D --> E["`**로트 소진**
만료 임박순`"]
    E --> F["`**항목별 소모 행 기록**
잔액 감소`"]
    F --> G["`**응답**
잔액과 소모 행`"]
    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D
    class A,B,C,D,E,F,G,X comp
```

- 부족 판정은 만료 정리보다 먼저 한다. 부족한 차감이 같은 트랜잭션의 만료 정리를 롤백시켜 만료분을 반복 처리하는 것을 막는다.
- 소모 행에는 멱등 키가 없다. 재시도마다 실제로 차감된다. 호출자는 시도별 환불 키로 각 차감과 환불을 연결한다.
- 응답의 소모 행은 호출자가 환불 키 `refund:charge:{소모 행 ID}`를 만드는 데 쓴다.

<br>

### 4-1-4 체험 예약, 복원, 스냅샷

체험 카운터는 Redis의 정수다. 사용 횟수를 쌓는 값이며 남은 횟수는 한도에서 뺀 파생값이다. 예약은 "한도 미만이면 1 증가"를 원자적 스크립트로 실행한다. 복원은 카운터가 0 아래로 내려가지 않도록 감소시킨다.

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 40}}}%%
flowchart LR
    A{"`**요청자**`"} -->|게스트| B["`**기기 헤더 검증**
없으면 거절`"]
    B --> C["`**게스트 카운터 예약**
Redis`"]
    C --> D{"`**한도 미만인가**`"}
    D -->|예| E["`**무료 처리**`"]
    D -->|아니오| X["`**한도 소진 예외**`"]
    A -->|회원| F["`**회원 카운터 예약**
Redis`"]
    F --> G{"`**예약됐는가**`"}
    G -->|예| E
    G -->|아니오, 소진 또는 장애| H["`**이프 선차감**`"]
    E -.->|처리 실패| R["`**카운터 복원**
Redis`"]
    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D
    classDef task fill:#F5D9C9,stroke:#B97450,color:#452B1D
    class A,B,D,E,G,H,X comp
    class C,F,R task
```

| 연산 | 처리 |
|---|---|
| 게스트 예약 | 기기 헤더가 없거나 공백이면 거절<br>한도 소진이면 앱 코드를 가진 예외<br>성공하면 복원에 쓸 기기 식별자 반환 |
| 회원 예약 | 계정 카운터로 판정<br>Redis 장애는 예약 실패로 보고 이프 차감으로 진행 |
| 복원 | 게스트는 기기 카운터, 회원은 계정 카운터를 1 감소<br>회원 복원의 Redis 장애 예외는 전파하지 않고 실패를 반환 |
| 스냅샷 | 계정 도메인이 로그인 시 요청<br>간편 제작, 채팅 턴, 채팅 이미지 카운터에 기기 사용량을 값이 없을 때만 기록<br>기기 식별자가 없으면 한도값을 기록해 소진 상태로 시작<br>사용 이력이 없는 카운터는 기록하지 않아 체험 한도 전량이 남음<br>Redis 장애면 미완료를 반환하고 계정 도메인이 다음 로그인에 재시도 |

<br>

### 4-1-5 소모와 환불

간편 제작과 채팅 도메인이 과금 연산을 호출하는 순서다. 과금과 환불의 시점은 각 도메인이 정한다. PAYMENT는 연산을 제공한다.

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 40}}}%%
flowchart LR
    A["`**정책값 읽기**
요청당 1회`"] --> B["`**체험 예약**
회원 카운터 또는 게스트 카운터`"]
    B --> C{"`**회원이고 체험으로
덮이지 않은 항목이 있는가**`"}
    C -->|예| D["`**선차감**
항목 합산, 지갑 잠금 1회`"]
    C -->|아니오| E["`**AI 처리**`"]
    D --> E
    E --> F{"`**저장이 확정됐는가**`"}
    F -->|예| G["`**소모 확정**`"]
    F -->|아니오| H["`**환불과 복원**
차감 금액 그대로, 요청당 1회`"]
    H -.->|환불 코드 미실행| I["`**선차감 대사**`"]
    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D
    classDef task fill:#F5D9C9,stroke:#B97450,color:#452B1D
    class A,C,F,G,H,I comp
    class B,D,E task
```

| 호출 도메인 | 참조 | 환불 키 |
|---|---|---|
| 간편 제작 | `STORY`, 간편 제작 진행 ID | `refund:story:{차감 시도별 UUID}` |
| 채팅 턴 | `CHAT`, 채팅 내부 ID | `refund:charge:{소모 행 ID}`<br>체험으로 처리된 턴은 `refund:chatturn:{요청별 UUID}` |
| 채팅 이미지 | `CHAT_IMAGE`, 채팅 내부 ID | `refund:charge:{소모 행 ID}` |

- 잔액 부족과 한도 소진은 AI 처리를 시작하기 전에 예외로 드러난다. 호출 도메인이 동기 응답으로 변환한다.
- 환불은 차감 때 쓴 금액으로 한다. 환불 시점에 정책값을 다시 읽지 않는다.
- 체험으로 처리된 요청이 실패하면 이프를 환불하지 않고 카운터를 복원한다.

### 4-1-7 정책값 조회와 스냅샷 갱신

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 40}}}%%

    end
    subgraph REF["갱신"]
        direction LR
        D["`**오버라이드 전체 조회**

        E --> F["`**스냅샷 교체**

    end
    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D
    classDef task fill:#F5D9C9,stroke:#B97450,color:#452B1D
    class A,B,C,E,F comp
    class D task
```

- 한 응답의 7종은 같은 스냅샷과 같은 시각으로 계산한다. 키마다 따로 읽으면 갱신이 끼어들어 옛 값과 새 값이 섞인다.
- 종료 시각은 읽는 시점에 판정한다. 갱신 주기를 기다리지 않고 즉시 기본값으로 돌아간다.
- 갱신에 실패하면 직전 스냅샷을 유지한다. 기동 시 첫 적재가 실패하면 기본값으로 시작한다.
- 기본값이 최솟값 미만이면 기동에 실패한다. 기본값을 대체할 값이 없기 때문이다.

### 4-1-9 잔액 조회

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 40}}}%%
flowchart LR
    A["`**활성 로트 잔여 합산**

    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D

```

- 잔액은 지갑의 캐시 값이 아니라 로트 합이다. 아직 만료 행으로 정리되지 않은 만료 로트도 제외한다. 세션 조회의 잔액도 같은 방식으로 계산한다.

| 커서 | 마지막 항목의 기록 시각과 내부 ID를 AES-GCM으로 봉인한 문자열<br>시각은 초와 나노초로 보존<br>키는 접근 토큰 대칭키에서 용도 문자열로 파생 |
| 다음 페이지 판정 | 페이지 크기보다 한 건 더 조회해 초과분이 있을 때만 커서 발급 |
| 분류 | 사유를 소모, 획득, 소멸의 세 가지로 분류<br>환불과 구매는 획득, 만료와 결제 환불 회수는 소멸 |
| 제목 | 채팅 참조는 채팅에서 스토리를 찾음. 간편 제작 참조는 진행에서 스토리를 찾음<br>요청자가 지금 읽을 수 있는 스토리는 현재 제목, 아니면 마지막 공개 스냅샷의 제목<br>삭제된 스토리와 보상, 만료, 회수 행은 제목 없음 |
| 만료일 | 획득 행은 그 적립이 만든 로트의 만료 시각, 만료 행은 회수된 로트의 만료 시각 |
| 조회 횟수 | 제목과 만료일은 페이지 단위 배치 조회 |

### 4-1-14 그로블 웹훅 수신

```mermaid
%%{init: {"flowchart": {"curve": "basis", "nodeSpacing": 24, "rankSpacing": 40}}}%%
flowchart LR
    A["`**시크릿, 시각, 서명 검증**
원본 바이트`"] --> B["`**본문 해석**`"]
    B --> C{"`**이벤트 종류**`"}
    C -->|완료| D["`**거래별 잠금**
환불 표식 행`"]
    D --> E["`**대기 주문 잠금**
금액 대조`"]
    E --> F{"`**선도착 환불 금액이
주문가와 같은가**`"}
    F -->|예| G["`**적립 없이 환불 상태**`"]
    F -->|아니오| H["`**구매 적립**
멱등 키는 이벤트 ID`"]
    H --> I["`**주문 완료**
거래 식별자 기록`"]
    C -->|환불| J["`**거래별 잠금**
환불 표식 행`"]
    J --> K{"`**완료된 주문이
있는가**`"}
    K -->|아니오| L["`**표식에 금액 보관**`"]
    K -->|예| M["`**로트 회수**
주문 환불 상태`"]
    C -->|그 외| N["`**무시**`"]
    classDef comp fill:#E8F2E8,stroke:#527A59,color:#182D1D
    classDef task fill:#F5D9C9,stroke:#B97450,color:#452B1D
    class A,B,C,D,E,F,G,H,I,J,K,L,M,N comp
```

| 단계 | 처리 |
|---|---|
| 검증 | 시크릿이 비어 있으면 처리 불가로 응답<br>타임스탬프는 현재 시각 기준 앞뒤 5분 안<br>서명은 `{타임스탬프}.{원본 본문}`의 HMAC-SHA256을 현재 서명 또는 이전 서명과 상수 시간 비교<br>검증 전에는 본문을 해석하지 않음 |
| 완료 | 판매자 참조가 주문 공개 식별자<br>참조 없음, 형식 오류, 주문 없음, 금액 불일치, 거래 식별자 오류, 이벤트 ID 오류는 무시<br>대기 상태가 아닌 주문은 무시<br>적립 뒤 멱등 키의 원장 행이 이 주문의 것인지 확인하고 아니면 무시 |
| 환불 | 거래 식별자로 주문 조회<br>부분 환불과 금액 불일치는 무시<br>완료 상태가 아닌 주문은 무시<br>주문이 없으면 표식에 첫 환불 금액만 보관 |
| 표식 | 처리 끝에 삭제<br>완료 처리가 주문을 찾지 못하거나 금액 오류로 끝나면 먼저 도착한 환불 금액은 남기고 잠금용 행만 정리 |
| 응답 | 처리와 무시 모두 성공으로 응답<br>결과는 지표에 기록 |
| 이벤트 | 적립과 회수가 커밋된 뒤 주문 소유자 기준으로 구매와 환불 이벤트 발행 |
