# 2. 요구사항

이 문서는 PAYMENT 도메인의 백엔드가 처리해야 하는 동작, 요구 주체, 다른 주체와의 역할 분담, 제품 제약과 데이터 보존 기준을 정한다.

요청과 응답의 필드는 계약에, 처리 순서는 처리 흐름에, 로트 수명과 배치 주기는 오류 처리에 있다. ([4-2 계약](4-2-CONTRACT.md), [4-1 처리 흐름](4-1-PIPELINES.md), [5-3-5 재시도와 시간 한도](5-3-ERROR-HANDLING.md#5-3-5-재시도와-시간-한도))

<br>

### 2-1 요구 주체

백엔드는 재화의 증감을 원장에 기록하고 잔액의 정합성을 지킨다. 결제 제공자의 결제와 환불 통지를 재화에 반영한다. 각 주체의 역할과 백엔드에 기대하는 동작은 다음과 같다.

| 주체 | 하는 일 | 백엔드에 기대하는 것 |
|---|---|---|
| 클라이언트 | 잔액, 내역, 수치를 표시<br>충전 화면에서 상품을 고르고 결제 제공자로 이동<br>결제 복귀 뒤 주문 상태를 확인<br>앱에는 인앱 결제 화면이 없음 | 웹과 Android가 같은 계약으로 호출할 수 있는 엔드포인트<br>잔액 부족과 체험 소진을 구분할 수 있는 응답<br>수치를 하드코딩하지 않아도 되는 현재 값 조회<br>결제 복귀만으로 적립을 단정하지 않고 확인할 수 있는 주문 조회 |
| 그로블 | 상품별 결제창 제공<br>결제 완료와 환불을 서명된 웹훅으로 통지<br>통지는 재전송되거나 순서가 바뀔 수 있음 | 서명과 시각을 검증한 뒤에만 처리<br>같은 통지를 다시 받아도 적립과 회수는 각각 한 번만 수행<br>환불이 완료보다 먼저 와도 적립하지 않음 |
| 계정 | 가입, 초대의 자격을 판정하고 보상 신원을 정함<br>로그인 시 체험 스냅샷을 요청 | 멱등 키로 1회만 적립<br>초대자 월 상한 판정<br>기기 사용량을 계정 카운터로 1회 복사<br>세션 조회에 넣을 잔액과 당일 출석 여부 |
| 스토리 | 간편 제작 시작 전 과금, 실패 시 환불 | 체험 예약, 선차감, 같은 금액의 환불<br>잔액 부족과 한도 소진을 예외로 구분 |
| 채팅 | 턴과 이미지 시작 전 과금, 실패 시 환불<br>턴 가격을 채팅의 모델로 정함 | 턴과 이미지를 한 번의 잠금으로 합산 차감<br>항목별 원장 행<br>정책값 응답에 라이트(`BASIC`)의 턴 가격 반영 |
| 운영자 | 정책값을 바꾸고 환불 자격을 확인해 제공자 콘솔에서 환불을 실행 | 릴리스 없이 반영되는 정책값<br>잘못된 값은 무시하고 기록<br>환불 통지가 오면 자동 회수 |

<br>

### 2-2 기능 요구사항

| 기능 | 백엔드가 보장하는 것 |
|---|---|
| 잔액 | 만료되지 않고 남은 로트 수량의 합<br>지갑이 없으면 0 |
| 적립 | 멱등 키가 같은 적립은 1회만 기록<br>적립마다 로트를 만들고 사유에 따라 만료 시각 부여<br>지갑은 첫 적립 때 생성 |
| 가입 보상 | 계정 도메인이 요청하면 보상 신원당 1회 적립 |
| 출석 보상 | KST 자정 기준 하루 1회<br>이미 받았으면 적립 없이 성공 응답<br>재가입 계정은 최초 계정의 출석과 같은 날로 판정 |
| 초대 보상 | 초대자와 제출자에게 각각 적립<br>초대자 몫만 KST 월 상한을 적용하고 상한이면 초대자 적립만 건너뜀<br>세션 조회에 넣을 이번 달 초대자 보상 횟수 제공 |
| 게스트 체험 | 기기 식별자별 카운터 4종<br>한도 안에서만 예약하고 실패하면 복원<br>기기 헤더가 없으면 거절 |
| 회원 체험 | 간편 제작, 채팅 턴, 채팅 이미지는 계정 카운터를 먼저 쓰고 소진 뒤 이프 차감<br>가입 시 기기 사용량을 1회 복사하고 기기 헤더가 없거나 재가입이면 소진 상태로 시작<br>카운터를 읽을 수 없으면 이프 차감으로 진행 |
| 선차감 | 처리 시작 전에 차감하고 잔액이 부족하면 아무것도 기록하지 않고 거절<br>여러 항목의 합계를 한 번의 잠금으로 판정 |
| 환불 | 차감 때 쓴 금액을 그대로 되돌림<br>같은 환불 키는 1회만 기록 |
| 만료 | 로트는 사유별 수명이 지나면 만료<br>만료 수량은 원장에 음수 행으로 남기고 잔액에서 제외<br>소진은 만료가 가까운 로트부터 |
| 이용내역 | 원장을 최신순으로 페이지 조회<br>분류 필터, 관련 스토리 제목, 만료 예정일 포함<br>순차 내부 ID를 드러내지 않는 커서 |
| 정책값 | 유효한 오버라이드가 있으면 해당 값을 적용하고 없으면 기본값 적용<br>종료 시각이 지나면 즉시 기본값으로 복귀<br>잘못된 키와 범위 밖 값은 무시<br>한 요청 안에서는 같은 값을 사용 |
| 상품 | 설정에 정의한 상품 6종을 무인증으로 제공 |
| 웹 충전 | 주문을 대기 상태로 만들고 결제창 주소를 응답<br>주문 생성만으로 적립하지 않음<br>본인 주문만 조회 |
| 그로블 웹훅 | 서명과 시각을 검증한 뒤 본문 해석<br>완료는 금액이 주문과 같을 때만 적립<br>전체 환불만 회수<br>같은 통지의 재전송과 순서 역전에도 결과가 같음 |
| 환불 회수 | 완료된 주문만 회수<br>구매 로트의 남은 수량만 회수하고 부족분을 주문에 기록<br>잔액은 음수가 되지 않음 |
| 대사 | 환불이 누락된 차감을 주기적으로 찾아 보정<br>채팅 턴은 저장도 환불도 없는 차감 행을 그 금액으로 환불<br>간편 제작은 그룹의 부족한 환불만 추가<br>초과 환불하지 않음 |
| 계정 상태 | 정지 계정의 충전과 출석 보상 거절<br>탈퇴 계정은 모든 요청 거절 |

<br>

### 2-3 다른 주체와의 역할 분담

| 판단과 작업 | 담당 |
|---|---|
| 결제 승인과 돈의 이동 | 결제 제공자 |
| 웹훅의 재전송과 전달 보장 | 그로블 |
| 환불 자격 판정과 환불 실행 | 운영자가 결제일 7일 이내와 미사용 여부를 확인하고 제공자 콘솔에서 실행<br>백엔드는 통지를 받아 회수만 담당 |
| 가입과 초대의 보상 자격 | 계정 도메인<br>백엔드는 멱등 키와 월 상한으로 적립 |
| 소모 대상과 환불 시점 | 스토리와 채팅 도메인<br>백엔드는 차감, 환불, 예약, 복원의 연산 제공 |
| 채팅 턴의 소모액 | 채팅 도메인의 모델 표<br>백엔드는 전달받은 금액을 차감 |
| 잔액 부족과 한도 소진의 응답 변환 | 소모 엔드포인트를 가진 도메인 |
| 정책값 변경 | 운영자가 저장소에서 직접 변경 |
| 사유와 분류의 한국어 라벨 | 클라이언트 |

### 2-4 제품 제약

**1. 입력**

| 항목 | 규칙 |
|---|---|
| 상품 ID | 1~32자, 설정에 있는 값 |
| 이용내역 분류 | `ALL`, `SPEND`, `EARN`, `EXPIRE`, 대소문자 무시 |
| 이용내역 페이지 크기 | 1~100으로 보정, 기본 50 |
| 이용내역 커서 | 서버가 발급한 값 그대로 |
| 기기 식별자 | 게스트의 체험 대상 요청과 체험 조회에 필수 |

<br>

**2. 개수와 한도**

| 항목 | 값 |
|---|---|
| 게스트 체험 | 스토리라인 생성 5회, 간편 제작 1회, 채팅 턴 5회, 채팅 이미지 5회<br>기기 식별자별 누적, 리셋 없음 |
| 회원 체험 | 간편 제작, 채팅 턴, 채팅 이미지의 3종<br>가입 시 기기 사용량을 이어받음 |
| 출석 보상 | 보상 신원당 KST 하루 1회 |
| 초대자 보상 | 보상 신원당 KST 월 단위 횟수 상한<br>값은 정책값 |
| 충전 상품 | 6종 |
| 정책값 범위 | 오버라이드는 0 이상 10,000 이하<br>보상액 3종과 소모액 2종은 1 이상, 초대 월 상한과 이미지 비용은 0 허용 |
| 결제 환불 | 결제일 7일 이내, 구매 로트 미사용, 전액 환불만<br>부분 환불은 회수하지 않음 |

<br>

**3. 기본 정책값**

기본 정책값은 운영 중 바뀔 수 있다. 현재 값은 정책값 조회가 기준이다. ([4-2-3 정책값 조회](4-2-CONTRACT.md#4-2-3-정책값-조회))

| 정책값 | 기본값 |
|---|---|
| 가입 보상 | 1,000 |
| 초대 보상 | 양쪽 각 2,000 |
| 초대자 월 상한 | 10회 |
| 출석 보상 | 250 |
| 간편 제작 소모 | 250 |
| 채팅 턴 소모 | 모델별, 재생성 포함<br>정책값이 아니라 채팅 도메인의 모델 목록이 기준 (CHAT 세트 [4-2-14 모델 목록](../../CHAT/BACKEND/4-2-CONTRACT.md#4-2-14-모델-목록)) |
| 채팅 이미지 소모 | 0 |

<br>

**4. 충전 상품**

기본 이프 수량은 웹 가격과 수치가 같다. 기본 이프와 보너스 이프는 합쳐서 로트 하나로 적립한다.

| 상품 ID | 기본 이프 | 보너스 | 총량 | 가격 |
|---|---|---|---|---|
| `if_2000` | 2,000 | 0 | 2,000 | 2,000원 |
| `if_5000` | 4,800 | 200 | 5,000 | 4,800원 |
| `if_10000` | 9,400 | 600 | 10,000 | 9,400원 |
| `if_30000` | 27,500 | 2,500 | 30,000 | 27,500원 |
| `if_50000` | 45,000 | 5,000 | 50,000 | 45,000원 |
| `if_100000` | 88,000 | 12,000 | 100,000 | 88,000원 |

### 2-5 데이터 보존

| 대상 | 요구사항 |
|---|---|
| 원장 | 영구 보존, 수정과 삭제 없음 |
| 지갑과 로트 | 회원 행이 있는 동안 보존<br>탈퇴해도 회원 행이 남으므로 유지 |
| 주문 | 영구 보존<br>결제를 마치지 않은 대기 주문도 삭제하지 않음 |
| 환불 표식 | 잠금용 행은 처리가 끝나면 삭제<br>완료보다 먼저 온 환불 금액이 있는 행은 주문과 맞는 완료 처리까지 보존 |
| 정책 오버라이드 | 운영자가 지울 때까지 보존<br>종료 시각이 지나도 행은 남음 |
| 체험 카운터 | 만료 없음 |
| 웹훅 본문 | 저장하지 않음<br>구매 적립의 이벤트 ID만 멱등 키로 원장에 보존 |
| 웹훅 시크릿 | 설정에만 두고 저장소와 로그에 기록하지 않음 |
