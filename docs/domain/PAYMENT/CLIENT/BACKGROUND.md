# PAYMENT 클라이언트 배경

<br>

### 사용자와 목적

회원은 잔액과 소모량을 확인하고 보상이나 웹 결제로 이프를 얻는다. 소모할 수 없는 상태에서도 작성한 내용을 유지하며 다음 행동을 선택한다. 웹 게스트는 가입 전에 남은 체험 한도를 확인한다.

| 사용자 | 필요한 경험 |
|---|---|
| 회원 | 현재 잔액, 적용 비용, 적립과 소모 내역 확인 |
| 이프가 부족한 회원 | 입력 보존, 출석 또는 충전 후 이용 재개 |
| 웹에서 구매하는 회원 | 결제 결과와 실제 적립 확인 |
| 웹 게스트 | 남은 체험과 소진 후 로그인 안내 |

<br>

### 도메인 경계

| 도메인 | 책임 |
|---|---|
| PAYMENT | 정책 수치, 잔액과 체험 표시, 출석, 내역, 부족 안내, 웹 충전 |
| ACCOUNT | 로그인과 회원 동의, 가입 및 초대 자격, 초대 코드와 안내 흐름 |
| CHAT | 채팅 모델과 턴 가격, 턴과 이미지의 적용가 계산, 실패한 입력 복구 |
| STORY | 제작 적용가, 초안 저장, 완성 요청과 복구 |
| NOTIFICATION | 출석과 만료 알림, 충전 화면으로의 진입 전달 |
| BACKEND | 보상과 소모 판정, 원장, 주문과 결제 통지의 정합성 |

<br>

### 용어

| 용어 | 의미 |
|---|---|
| 이프 | 회원의 AI 기능 사용에 소모하는 서비스 재화 |
| 정가 | 체험 적용 전 소모량 |
| 적용가 | 해당 동작과 체험 잔여에 따라 실제로 적용할 소모량 |
| 체험 잔여 | 서버가 제공한 한도에서 사용량을 뺀 값 |
| 결제 복귀 | 외부 결제창에서 서비스 화면으로 돌아오는 것. 적립 확정과 구분 |
| 내역 | 서버가 기록한 이프 증감 목록. 화면에서 잔액을 재계산하는 자료로 사용하지 않음 |
