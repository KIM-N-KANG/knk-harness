# 2-2 PAYMENT 요구사항

<br>

### 2-2-1 적용 범위

| 기능 | 웹 | Android | 유저 스토리 |
|---|---|---|---|
| 회원 잔액, 출석, 내역, 부족 안내 | 적용 | 적용 | PAYMENT-US-001, PAYMENT-US-002, PAYMENT-US-004, PAYMENT-US-006 |
| 회원 체험과 적용 비용 | 적용 | 적용 | PAYMENT-US-003 |
| 게스트 체험 | 이용 동의 후 적용 | 비적용, 로그인 필수 | PAYMENT-US-005 |
| 유료 구매 | 웹 결제창 제공 | 구매 탭과 인앱 결제 없음 | PAYMENT-US-007 |
| 충전 탭 | 구매, 무료 충전, 내역. 기본 구매 | 무료 충전, 내역. 기본 무료 충전 | PAYMENT-US-006, PAYMENT-US-007 |
| 완성 제출 후 제작 탭에서 확정된 이프 부족 | 부족 토스트, 시트 없음 | 일반 완성 실패 안내, 시트 없음 | PAYMENT-US-004 |

가입과 초대의 자격 및 계정 종료는 ACCOUNT가 정한다. ([ACCOUNT 요구사항](../../ACCOUNT/CLIENT/2-2-REQUIREMENTS.md))

<br>

### 2-2-2 잔액과 비용

| 요구 | 조건과 결과 | 유저 스토리 |
|---|---|---|
| 잔액 | 회원 정보의 잔액을 표시. 내역 합산이나 임의 차감으로 만들지 않음 | PAYMENT-US-001 |
| 정책값 | 서버가 제공한 현재 값 사용. 고정 금액을 대체값으로 사용하지 않음. 서비스 안내에 금액을 복제하지 않음 | PAYMENT-US-002, PAYMENT-US-003 |
| 미수신 | 문구 골격 유지, 숫자 자리만 자리표시. 모르는 값을 0원이나 무료로 확정하지 않음 | PAYMENT-US-003 |
| 사용 지점 | 잔액, 완성 비용, 채팅 비용, 상품 기본 이프에 이프 마크 표시. 장식 이미지로 접근성 이름 없음 | PAYMENT-US-001, PAYMENT-US-003 |
| 일회성 문구 | 토스트와 공유 제목은 동작 시점의 서버 값 사용 | PAYMENT-US-002 |
| 채팅 모델 가격 | CHAT의 모델 목록과 선택 모델이 기준. 정책의 기존 턴 비용으로 모든 모델을 계산하지 않음 | PAYMENT-US-003 |
| 실패한 소모 | 입력 보존, 낙관적 채팅 버블 제거. 성공 표시와 임의 잔액 차감 없음 | PAYMENT-US-003, PAYMENT-US-004 |

제작과 채팅의 정가 및 적용가 표시는 해당 동작의 계약에서 구체화한다. ([추가 정보](../../../spec/3-1-client-spec.md#추가-정보-진입스토리라인-재선택), [채팅 비용](../../../spec/3-1-client-spec.md#fe-screen-005-채팅-화면))

<br>

### 2-2-3 체험

| 요구 | 조건과 결과 | 유저 스토리 |
|---|---|---|
| 한도와 사용량 | 서버 값으로 계산. 기기 카운터를 별도 기준으로 사용하지 않음 | PAYMENT-US-003, PAYMENT-US-005 |
| 무제한 | 한도가 없는 항목은 무제한으로 해석 | PAYMENT-US-003, PAYMENT-US-005 |
| 회원 체험 | 계정의 잔여를 사용. 다른 계정에 이전 사용자의 잔여를 표시하지 않음 | PAYMENT-US-003 |
| 게스트 소진 | 잔여 0인 유료 동작은 요청 전 로그인 안내. 서버가 소진으로 거절해도 입력 유지 | PAYMENT-US-005 |
| 무료 진입 | 채팅방 생성과 제작 입력 화면 진입을 잔액이나 체험 한도로 막지 않음 | PAYMENT-US-005 |
| 잔여 미확인 | 적용가를 확정하지 않고 서버 판정 사용 | PAYMENT-US-003, PAYMENT-US-005 |
| 이용 동의 | 웹의 게스트 동의와 회원 필수 동의는 별개 | PAYMENT-US-005 |

로그인 후 콘텐츠와 체험 사용량을 이어받는 목표는 ACCOUNT에서 관리한다. ([ACCOUNT-US-003과 ACCOUNT-US-004](../../ACCOUNT/CLIENT/2-1-USER-STORY.md#2-1-1-가입과-서비스-이용))

### 2-2-4 보상과 내역

| 요구 | 조건과 결과 | 유저 스토리 |
|---|---|---|
| 출석 | KST 자정 기준 하루 한 번. 이미 출석했으면 추가 적립 없이 완료 | PAYMENT-US-002 |
| 보상 사용 기간 | 적립일로부터 30일. 실제 만료일은 서버 내역으로 확인 | PAYMENT-US-002, PAYMENT-US-006 |
| 출석 중 | 중복 요청 차단. 실패 시 재시도 가능 | PAYMENT-US-002 |
| 출석 성공 | 지급 결과 안내 후 잔액과 출석 여부 재조회. 응답 금액을 잔액에 직접 더하지 않음 | PAYMENT-US-001, PAYMENT-US-002 |
| 초대 보상 | 서버 보상액과 초대자 월 적립 횟수 상한 표시. 코드와 자격 판정은 ACCOUNT | PAYMENT-US-002 |
| 내역 순서 | 서버 최신순 유지. 다음 커서로 이어 읽고 끝이면 중단 | PAYMENT-US-006 |
| 내역 날짜 | 발생일과 실제 만료일을 KST로 구분. 만료 회수 기록일을 실제 만료일로 사용하지 않음 | PAYMENT-US-006 |
| 첫 조회 실패 | 목록 영역에서 재시도 제공 | PAYMENT-US-006 |
| 다음 페이지 실패 | 기존 목록 유지, 자동 재요청 중단과 재시도 제공 | PAYMENT-US-006 |
| 알 수 없는 사유 | 해당 행을 일반 변동으로 표시. 목록 전체를 실패시키지 않음 | PAYMENT-US-006 |

### 2-2-5 이프 부족과 입력 보존

| 상황 | 조건과 결과 |
|---|---|
| 선검사 | 채팅 전송, 재생성, 간편 제작 완성에 적용. 잔액, 비용, 체험을 모두 알고 적용가보다 잔액이 적을 때만 요청 전 차단 |
| 서버 판정 | 서버의 잔액 부족 응답이 최종 판정. 선검사에 필요한 값이 하나라도 없으면 요청 허용 |
| 현재 화면에서 확인 | 부족 시트 표시, 입력 유지. 시트를 열 때 잔액과 당일 출석 여부 재조회 |
| 출석 여부 미확인 또는 출석 완료 | 부족 시트의 출석 버튼 미표시 |
| 시트 출석 성공 | 보상 지급과 이미 출석한 결과 모두 안내 후 시트 닫기 |
| 시트 출석 실패 | 오류 안내와 시트 유지 |
| 충전 이동 | 채팅 입력 보관. 간편 제작은 초안 저장 성공 뒤 이동 |
| 초안 저장 실패 또는 충돌 | 충전으로 이동하지 않고 시트와 편집 화면 유지 |
| 출석 또는 이동 준비 중 | 중복 조작과 닫기 잠금 |
| 시트 닫기 | 입력과 기존 콘텐츠 유지 |
| 제출 후 실패 | 이미 제작 탭으로 떠났으면 시트를 다시 열지 않음. 플랫폼별 결과 안내 적용 |

PAYMENT-US-004의 공통 결과다. 채팅과 제작의 재개 위치는 플랫폼 화면 흐름에서 구체화한다.
