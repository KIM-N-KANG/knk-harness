# 4-4 PAYMENT Android 실행

<br>

### 4-4-1 조회와 출석

| 작업 | 실행 |
|---|---|
| 정책 | 루트 초기화 때 한 번 조회. 화면마다 재요청하지 않음 |
| 체험 | 회원 세션이 될 때 조회. 채팅 턴 완료와 스토리 완성 확정 뒤 재조회 |
| 화면 진입 | 프로필 재조회. 구성 변경의 반복 요청은 5초 최소 간격으로 제한 |
| 내역 최초 조회 | 보유 항목이 없으면 첫 페이지 요청 |
| 명시적 새로고침 | 최소 간격을 적용하지 않음. 무료 탭은 프로필, 내역 탭은 프로필과 첫 페이지 |
| 내역 갱신 실패 | 보던 목록 유지, 실패 Effect |
| 다음 페이지 | 커서가 있고 첫 페이지와 다음 페이지가 조회 중이 아닐 때 요청. 실패 뒤 자동 재요청 중단 |
| 출석 | 중복 요청 차단, 지급 또는 이미 출석 결과 안내, 프로필 재조회 |
| 출석 실패 | 잠금 해제와 오류 Effect |

<br>

### 4-4-2 부족 시트

1. 동작의 ViewModel이 잔액, 비용과 체험을 모두 아는지 확인한다. 간편 제작은 체험 소진과 잔액 부족을 모두 확인할 때만 요청 전에 막는다.
2. 공용 절차가 시트를 열고 회원 프로필을 재조회한다. 당일 출석 여부를 모르면 출석 버튼을 숨긴다.
3. 출석 요청은 공용 인터페이스로 실행한다. 성공하면 시트를 닫고 프로필을 갱신하며 실패하면 시트를 유지한다.
4. 충전 이동 동안 중복 요청과 닫기를 잠근다. 채팅은 입력을 든 ViewModel을 백스택에 둔다.
5. 간편 제작은 저장 완료를 기다리고 성공한 경우에만 퍼널을 제거한다. 앱 조립 계층이 제작 탭 위에 충전을 쌓는다.

동작을 아는 ViewModel이 부족 안내와 출석 및 충전 버튼 분석 이벤트를 보낸다. 공용 절차에 분석 모듈 의존을 추가하지 않는다. ([4-2 구성](4-2-COMPONENT-ARCHITECTURE.md), [2-2-2](2-2-REQUIREMENTS.md#2-2-2-부족-안내와-수명))
