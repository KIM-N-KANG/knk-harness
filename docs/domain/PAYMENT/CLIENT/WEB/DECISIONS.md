# DECISIONS.md

현재 적용 기준은 각 명세에 두고 결정 당시의 이유와 대체 관계는 이 문서에 기록한다.

<br>

### 1. 기록 규칙

- 결정 하나를 표 하나로 기록한다. 기존 ID, 날짜, 당시 상태와 근거를 유지한다.
- 상태와 구현 설명은 원본의 기록 시점을 기준으로 해석한다. 현재 적용 여부나 배포 완료를 과거 기록만으로 단정하지 않는다.
- 결정이 바뀌면 새 ID로 기록하고 대체하는 결정과 적용 범위를 명시한다.
- 원문에 구분되지 않은 배경, 대안과 영향은 추측해서 보충하지 않는다.

<br>

**W-023. 결제 복귀 화면은 결제 전 충전 화면까지 히스토리를 되감음**

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-10-05 |
| 상태 | Accepted (원문 기록 기준) |
| 배경 | 그로블 결제창 이동과 그로블의 복귀 이동이 모두 히스토리 항목을 쌓아, 결제 후 충전 화면에서 뒤로가기를 누르면 그로블 결제 완료 화면이 다시 열렸다. 웹은 지나온 항목을 지울 수 없고 그로블의 이동 방식도 바꿀 수 없다. |
| 채택 | 결제창으로 나가기 직전 같은 주소를 한 칸 쌓아 앞으로 항목을 자르고 그 길이를 탭 단위 sessionStorage에 남긴 뒤, 그 칸을 결제창으로 바꾼다. 그로블의 이동, 진입 페이지인 `/my/credits/return`은 길이 차이로 거리를 구해 `history.go`로 결제 전 충전 화면까지 되감는다. 기록이 없거나 길이가 상한(50)에 닿으면 되감지 않고 `/my/credits`로 바꿔 끼운다. 복귀 화면은 앱 셸 없는 정적 문서로 응답한다. |
| 대안 | 원문에 별도 항목으로 구분하지 않음 |
| 이유 | 새 창(팝업) 결제는 원래 탭 히스토리를 깨끗하게 두지만, 모바일과 인앱 브라우저에서 카드사, 간편결제 앱을 다녀온 뒤 팝업으로 돌아오지 못할 위험이 있어 택하지 않았다. Navigation API의 `entries()`는 다른 출처를 지나면 그 이전 항목을 보여 주지 않아 결제 전 항목을 찾을 수 없다. 앞으로 항목을 자르지 않으면 결제창에서 뒤로 돌아왔다 다시 결제한 경우 길이 차이가 실제 거리보다 작아진다. 복귀 화면에 앱 셸을 띄우면 WebKit이 되감기 시작과 함께 진행 중인 요청을 끊고, 그 실패로 열린 동의 시트가 히스토리 칸을 쌓아 되감기를 깨뜨렸다. |
| 영향 | 그로블 상품 설정의 이동 페이지와 진입 페이지를 `/my/credits/return`으로 등록해야 한다. 되감기 직전 복귀 화면이 잠깐 빈 화면으로 보인다. 결제창에서 뒤로 돌아오면 결제 전 충전 화면이 bfcache 대신 새로 로드될 수 있다. 다른 탭에서 결제를 마치거나 히스토리가 상한에 닿은 경우에는 뒤로가기가 결제창으로 갈 수 있다. |
