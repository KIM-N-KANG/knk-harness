# 4-4 실행: 웹

<br>

### 4-4-1 정책과 체험, 내역

| 작업 | 실행 |
|---|---|
| 정책 | 200 본문만 사용. 미수신은 `undefined`, 수치 자리표시는 `000`과 쉬머 |
| 일회성 문구 | 이벤트 시점 캐시 스냅샷 사용. 캐시 도착을 보장한다고 가정하지 않음 |
| 체험 | 세션 판정이 `loading`이면 조회하지 않음. 세션 상태를 쿼리 키에 포함 |
| 체험 무효화 | 채팅 턴 완료, 스토리라인 생성, 스토리 완성 때 체험 기본 키로 세션별 조회 무효화 |
| 출석 | 성공 뒤 회원 정보 무효화. 지급과 중복 응답을 모두 완료로 전달 |
| 내역 | `useInfiniteQuery` 사용. `type`과 `limit`은 생략해 서버 기본 전체와 50건 적용 |
| 페이지 끝 | sentinel의 초기 in-view는 false. 조회 중과 실패 중 자동 요청 중단 |
| 내역 오류 | 첫 페이지 실패만 전체 오류. 다음 페이지 실패는 하단 오류로 기존 항목 유지 |
| 잔액 | 회원 정보는 `refetchOnMount: 'always'`로 재조회 |

<br>

### 4-4-2 주문 생성과 히스토리

1. 선택 상품의 `productId`로 주문을 생성한다. 201과 `paymentUrl`을 확인하지 못하면 실패로 종료한다.
2. 반환된 `orderId`와 기록 시각을 localStorage에 보관한다. 복귀 URL에는 주문 ID가 없다.
3. 같은 주소를 `pushState`로 한 칸 쌓아 앞으로 항목을 자른 뒤 히스토리 길이를 sessionStorage에 기록한다.
4. 해당 칸을 `location.replace(paymentUrl)`로 외부 결제창으로 바꾼다.
5. 복귀 문서는 기록을 읽고 지운다. 길이 차이로 결제 전 충전 화면까지 `history.go`로 되감는다.
6. 기록이 없거나 손상됐거나 길이가 상한 50에 닿았으면 `/my/credits`로 교체한다.

`pageshow`의 `persisted`가 참이면 주문 mutation을 초기화하여 bfcache 복원 뒤 버튼 잠금을 해제한다. 복귀 문서는 앱 셸과 인증 조회를 실행하지 않는다.

<br>

### 4-4-3 주문 확인

| 결과 | 처리 |
|---|---|
| 유효한 대기 기록 없음 | 확인 카드와 폴링 없음 |
| `PENDING` | 2초 간격 최대 30회 조회 |
| `COMPLETED` | `totalCredits`로 완료 표시, 회원 정보 재조회, 대기 기록 삭제 |
| `REFUNDED` 또는 404 | 결과 표시와 대기 기록 삭제 |
| 30회 뒤 대기 | 자동 조회 중단. 기록 유지와 다시 확인 |
| 네트워크 또는 서버 오류 | 자동 조회 중단. 기록 유지와 다시 확인 |
| 다시 확인 | 시도 횟수 초기화 후 조회 재개 |
| 카드 닫기 | 카드와 보관한 주문 제거 |
| 로그아웃, 만료, 탈퇴 | 대기 주문 정리. 다음 계정에 이전 카드 노출 금지 |
