# 5-5 테스트 케이스

이 문서는 NOTICE 도메인 코드의 계약과 오류 처리 규칙을 검증할 테스트 범위, 입력과 상황, 기대 결과를 정한다.

실행 명령과 수동 호출 파일 위치는 AGENTS.md에 있으며 기대 결과의 상태 코드는 계약에 있다. ([AGENTS.md](AGENTS.md), [4-2 계약](4-2-CONTRACT.md))

<br>

### 5-5-1 테스트 범위

| 종류 | 확인 범위 | 외부 호출 | 실행 |
|---|---|---|---|
| 단위 | 커서 해석 | 없음 | CI |
| 통합 | 공개 조회, 관리자 작성과 수정, 게시, 게시 해제, 삭제, 알림 연결, 감사 기록 | 알림 도메인은 같은 서버의 서비스 | CI<br>H2, 스키마 자동 생성, 마이그레이션 비활성 |
| 동시성 | 동시 게시, 게시와 해제의 경쟁, 알림 연결과 해제의 경쟁 | 없음 | CI |
| 수동 | 엔드포인트 호출과 실기기 알림 도달 | 실행 환경의 실제 의존성 | 서버 저장소의 HTTP 요청 파일 |

테스트 프로파일은 마이그레이션을 건너뛴다. 전체 테스트를 통과해도 DB 제약을 검증했다고 볼 수 없다.

**외부 의존성과 테스트 데이터**

| 대상 | 방법 |
|---|---|
| 관리자 | 관리자 역할이 있는 활성 계정과 발급한 관리자 토큰 |
| 알림 도메인 | 관리자 캠페인 예약 API로 공지를 연결하고 캠페인 행과 공지의 알림 요청 시각을 저장 계층으로 확인 |
| DB | 통합 테스트는 공유 H2의 PostgreSQL 모드<br>CHECK 제약은 실제 PostgreSQL에서 DB 문서 생성 스크립트로 검증 |
| 공지 데이터 | 초안, 게시, 게시 해제, 알림을 요청한 초안을 각각 준비<br>알림을 요청한 초안은 게시 뒤 캠페인에 연결하고 게시 해제해 만듦 |

<br>

### 5-5-2 공개 조회

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 목록 | 게시 3건, 초안 1건, `limit` 2 | 게시만 게시 시각 내림차순 2건, 커서 있음, 둘째 페이지 1건 |
| 목록 본문 | 목록 응답 | `body`와 작성자 정보 없음 |
| 상세 | 게시된 공지 | 200<br>제목, 본문, 태그 |
| 부재 | 초안, 게시 해제된 공지, 없는 식별자, UUID 아님 | 전부 404 |
| 토큰 무시 | 토큰 없음, 만료된 접근 토큰, 유효한 접근 토큰으로 목록과 상세 조회 | 모두 200, 같은 공개 결과 |
| 태그 필터 | `SERVICE` 2건, `MAINTENANCE` 1건, `EVENT` 1건 게시, `tag=MAINTENANCE`, `tag=NOTICE` | 1건, 400 |
| 커서 오류 | 변조된 커서 | 400 |
| 페이지 한도와 종료 | `limit` 0, 100, `abc`, 마지막 페이지와 빈 목록 | 1과 50으로 보정, 타입 오류는 400, 마지막과 빈 목록의 `nextCursor`는 `null` |

<br>

### 5-5-3 작성과 수정

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 작성 | 유효한 제목, 본문, 태그 `UPDATE`, 사유 | 201, `DRAFT`, `tag` `UPDATE`, 작성자는 요청 관리자, 감사 로그 `NOTICE_CREATED`의 변경 후 값은 `title`, `tag`, `status` |
| 입력 오류 | 빈 제목, 101자 제목, 5,001자 본문, 공백으로만 구성된 본문, 태그 누락, 모르는 태그, 사유 누락 | 400 |
| 예전 알림 문구 필드 | 작성 본문에 `notificationTitle` 101자와 `notificationBody` 공백만<br>수정 본문에 `title`과 `notificationTitle`<br>수정 본문에 `notificationTitle`과 `notificationBody`만 | 201, 응답과 공지 행에 알림 문구 없음<br>200, 제목만 바뀜<br>400 |
| 수정 | 제목만, 본문만, 태그만, 셋 다 | 보낸 필드만 바뀜<br>감사 로그에 전후 값 |
| 수정 오류 | 세 필드 모두 없음, 모두 `null`, 모르는 태그, 사유 누락 | 400 |
| 연결 뒤 수정 | 캠페인에 연결한 공지의 `title`과 `body` 수정 | 200, 캠페인 제목과 본문은 그대로 |
| 연결 뒤 태그 수정 | 태그 `SERVICE`로 연결해 발송을 마친 캠페인과 예약 상태 캠페인이 있는 공지를 `EVENT`로 수정 | 200, 발송한 캠페인의 종류 `SERVICE`와 공지 태그 `SERVICE` 유지, 예약 캠페인은 선점 전까지 예약 때 값, 캠페인 추가 없음 |
| 게시 중 수정 | 게시된 공지 수정 | 200, 공개 상세에 즉시 반영, 캠페인 추가 없음 |
| 관리자 목록 | `status` 필터 없음, `DRAFT`, `PUBLISHED`, `ARCHIVED` | 전체, 초안만, 게시만, 400 |
| 관리자 목록 검색과 정렬 | 제목 일부 `q`, `sort=notifiedAt` | 제목 일치 건만, 알림 없는 공지가 마지막 |

### 5-5-4 게시, 게시 해제, 삭제

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 게시 | 태그 `SERVICE`, `EVENT` 초안 각각 | 200, `PUBLISHED`, `publishedAt` 기록, 감사 로그 `NOTICE_PUBLISHED`<br>캠페인 없음, `notifiedAt` `null`, 응답에 `notified` 없음 |
| 예전 게시 본문 | 태그 `SERVICE` 초안에 `notify` true와 `notificationKind` `MARKETING` | 200, 캠페인 없음 |
| 알림 문구 없는 공지 | 알림 문구 열이 `null`이고 `notifiedAt`이 `null`인 초안 게시 | 200, `PUBLISHED`, 캠페인 없음 |
| 연결 뒤 재게시 | 캠페인에 연결한 공지를 수정한 뒤 해제하고 재게시 | 수정과 재게시 모두 캠페인 추가 없음, `notifiedAt` 유지, 재게시는 200 |
| 연결 없던 공지 재게시 | `notifiedAt`이 없는 게시 해제 공지를 재게시 | 200, 캠페인 없음, `notifiedAt` `null` |
| 게시 오류 | 게시된 공지, 사유 누락 | 409, 400 |
| 기존 공지 태그 | 마이그레이션 전에 만든 공지 | `tag` `SERVICE` |
| 광고성 원문 제목 | 태그 `EVENT` 공지 게시와 캠페인 연결 뒤 공개 목록과 상세 | 공개 목록과 상세의 `title`에 `(광고)` 없음 |
| 게시 해제 | 게시된 공지<br>초안 | 200과 `DRAFT`와 `publishedAt` 유지<br>409 |
| 삭제 | 알림 요청 없는 초안, 게시된 공지, 캠페인에 연결한 뒤 게시 해제한 초안 | 204와 행 삭제와 감사 로그 `NOTICE_DELETED`, 409, 409 |
| 동시 게시 | 같은 초안에 동시 2건 | 한쪽 200, 다른 쪽 409, 감사 로그 `NOTICE_PUBLISHED` 1건 |
| 공개 반영 | 게시 뒤 공개 상세<br>해제 뒤 공개 상세 | 200<br>404 |

### 5-5-5 알림 연결

| 확인 항목 | 입력과 상황 | 기대 결과 |
|---|---|---|
| 첫 연결 | 게시된 태그 `UPDATE` 공지를 연결 | 공지 내부 참조와 태그 `UPDATE` 반환, `notifiedAt` 기록, `updatedAt` 그대로, 공지 대상의 감사 로그 없음 |
| 다시 연결 | 이미 연결한 공지를 다른 캠페인에 연결 | 연결 성공, `notifiedAt`은 처음 값 유지 |
| 연결 불가 | 초안, 게시 해제된 공지, 없는 공개 식별자 | 연결 불가 결과, `notifiedAt` 그대로 |
| 연결 롤백 | 연결 뒤 같은 트랜잭션의 캠페인 삽입 예외 | `notifiedAt` `null`로 남음 |
| 트랜잭션 밖 호출 | 트랜잭션 없이 연결 연산 호출 | 거부 |
| 연결과 게시 해제 경쟁 | 연결 트랜잭션이 공지 행을 잠근 동안 게시 해제 요청 | 게시 해제가 커밋 뒤까지 기다림, 캠페인 1건과 `notifiedAt` 기록, 이어서 `DRAFT` |
| 게시 해제 뒤 연결 | 게시 해제가 공지 행을 잠근 동안 연결 요청 | 게시 해제 커밋 뒤 연결 불가, 캠페인 없음 |
| 예약 뒤 게시 해제 | 공지를 연결한 미래 예약 캠페인이 있는 공지를 게시 해제 | 200, `DRAFT`, 캠페인은 `SCHEDULED` 그대로이고 선점 때 실패([NOTIFICATION 5-5-6](../../NOTIFICATION/BACKEND/5-5-TEST-CASES.md#5-5-6-출석-리마인드와-프로모션)) |
| 기존 연결 유지 | 유니크 제거 마이그레이션 전에 `notifiedAt`과 캠페인 1건이 생긴 게시 해제 공지 | 마이그레이션 뒤 `notifiedAt`과 캠페인의 공지 참조 그대로, 삭제 409, 재게시 200과 캠페인 추가 없음, 재게시 뒤 새 캠페인에 연결 가능 |
