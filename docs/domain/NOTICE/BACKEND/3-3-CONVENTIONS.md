# 3-3 구현 컨벤션

이 문서는 NOTICE 도메인 코드를 작성하거나 수정할 때 반드시 지킬 규칙과 구현자가 선택할 수 있는 사항을 정한다.

트랜잭션과 잠금은 동시성에, 로그 이벤트 규칙은 관측에, 개인정보 취급은 보안에, 구현 위치는 AGENTS.md에 있다. ([5-2 동시성](5-2-CONCURRENCY.md), [5-4-3 구조화 로그 이벤트](5-4-OBSERVABILITY.md#5-4-3-구조화-로그-이벤트), [5-1-5 식별자와 개인정보](5-1-SECURITY.md#5-1-5-식별자와-개인정보), [AGENTS.md](AGENTS.md))

<br>

### 3-3-1 이름과 용어

| 대상 | 규칙 |
|---|---|
| 패키지 | 공지 패키지 아래에 API 계층, 전송 객체, 모델, 저장 계층, 서비스를 나눔<br>공개 API 계층과 관리자 API 계층은 별도 클래스 |
| 경로 | 공개 조회는 `/api/v1/notices`, 관리자는 `/api/v1/admin/notices` |
| 모델 이름 | 테이블의 단수형 |
| 전송 객체 | 요청은 `Request`, 응답은 `Response`를 접미사로 사용<br>와이어 필드는 camelCase<br>DB 컬럼은 snake_case |
| 상태와 유형 | 대문자 enum을 와이어에 그대로 노출 |
| 용어 | 용어집을 따름 |

<br>

### 3-3-2 계층 책임

| 계층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 공개 API 계층 | 형식 검증, 상태 코드 | 요청자 식별 |
| 관리자 API 계층 | 형식 검증, 관리자 요청자 식별, 상태 코드 | 비즈니스 판정, 저장 계층 호출 |
| 공지 서비스 | 상태 전이 판정, 알림 1회 판정, 알림 도메인과 감사 기록 호출 | 알림 대상 판정, 광고 표기 |
| 저장 계층 | 쿼리 실행<br>잠금이 필요한 조회 메서드는 이름에 잠금 여부 표시 | 비즈니스 판정 |

<br>

### 3-3-3 요청 검증과 오류

| 대상 | 규칙 |
|---|---|
| 개별 필드의 길이, 필수 여부, 허용값 | 요청 객체의 필드에 애너테이션으로 선언 |
| 공백만인 제목과 본문 | 선언적 검증으로 거절 |
| 상태 거절 | 초안이 아닌 공지의 게시와 삭제, 게시되지 않은 공지의 게시 해제는 서비스에서 판정 |
| 공개 상세의 부재 | 없는 공지와 초안을 같은 결과로 응답 |

<br>

### 3-3-4 이벤트와 비동기

| 대상 | 규칙 |
|---|---|
| 알림 요청 | 게시 트랜잭션 안에서 알림 도메인의 연산을 동기 호출<br>비동기 발행이나 커밋 후 처리를 쓰지 않음 |

<br>

### 3-3-5 테스트와 검증 도구

| 대상 | 규칙 |
|---|---|
| 작성 순서 | 동작을 바꾸는 작업은 실패하는 테스트를 먼저 작성 |
| 엔드포인트 변경 | 통합 테스트와 수동 호출 파일을 함께 갱신 |
| 동시성 | 게시 잠금과 알림 1회 규칙을 바꾸면 동시 요청 테스트로 검증 |

<br>

### 3-3-6 구현자가 선택할 수 있는 것

| 선택 가능 | 조건 |
|---|---|
| 서비스 내부의 메서드 분할과 이름 | 없음 |
| 테스트 픽스처의 구성 | 없음 |
| 조회 쿼리의 작성 방식 | 게시 조건과 정렬 순서를 유지 |
| 로그 필드 추가 | 공지 본문과 사유를 넣지 않음 |
