# 5-2 동시성

이 문서는 NOTICE 도메인의 행 잠금, 멱등과 1회 처리, 유니크 위반, 수용한 경쟁 조건을 정한다.

흐름별 단계와 트랜잭션 경계는 처리 흐름에 있다. ([4-1-4 게시](4-1-PIPELINES.md#4-1-4-게시), [4-1-8 알림 연결](4-1-PIPELINES.md#4-1-8-알림-연결))

<br>

### 5-2-1 공지 행 잠금

수정, 게시, 게시 해제, 삭제, 알림 연결은 공지 행에 비관적 쓰기 잠금을 건 뒤 상태를 다시 확인한다.

| 경로 | 막는 경쟁 조건 |
|---|---|
| 게시 | 두 관리자가 같은 초안을 동시에 게시해 게시 시각과 감사 기록이 두 번 남는 경쟁 조건 |
| 게시 해제와 게시 | 해제와 재게시가 겹쳐 상태와 게시 시각이 섞이는 경쟁 조건 |
| 삭제 | 게시 중인 공지를 지우는 경쟁 조건 |
| 알림 연결 | 게시 상태를 확인한 뒤 게시 해제가 먼저 커밋되어 게시 해제된 공지에 새 캠페인이 생기는 경쟁 조건<br>게시 해제와 삭제가 이어져 캠페인이 지워진 공지를 가리키는 경쟁 조건<br>캠페인 생성 트랜잭션이 끝날 때까지 잠금을 유지 |
| 수정 | 같은 공지의 동시 수정<br>나중에 커밋된 변경이 적용됨 |

잠금 순서는 공지 행 하나뿐이다. 알림 연결에서는 공지 행을 먼저 잠근 뒤 알림 도메인이 캠페인 행과 감사 로그를 추가한다. 둘 다 잠금 없는 추가라 교차 대기가 생기지 않는다.

<br>

### 5-2-2 멱등과 1회 처리

| 대상 | 처리 |
|---|---|
| 알림 요청 시각 | 공지 행의 알림 요청 시각이 비어 있을 때만 기록<br>잠금 안에서 판정하고 캠페인 생성과 같은 트랜잭션에 기록 |
| 알림 연결 | 멱등 키 없음<br>같은 공지의 연결 요청마다 알림 도메인이 새 캠페인을 만듦 |
| 게시 | 초안일 때만 전이<br>재요청은 거절 |
| 작성 | 멱등 키 없음<br>재시도는 새 초안을 만들고 관리자가 목록에서 정리 |
| 수정 | 같은 값의 반복은 결과가 같음<br>감사 로그는 요청마다 남음 |

<br>

|---|---|

### 5-2-4 수용한 경쟁 조건

| 상황 | 수용 이유 |
|---|---|
| 공개 목록 조회 중 게시 해제 | 목록에 있던 공지의 상세가 부재로 응답됨<br>클라이언트가 목록을 다시 읽음 |
| 두 관리자의 동시 수정 | 나중에 커밋된 변경이 먼저 커밋된 변경을 덮어씀<br>두 변경 모두 감사 로그에 남아 복원 가능 |
