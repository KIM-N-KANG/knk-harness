# 5-1 보안

이 문서는 NOTICE 도메인의 인증 수준, 접근 판정, 계정 상태, 입력 검증, 식별자와 개인정보 취급 규칙, 수용한 한계를 정한다.

경로별 인증 수준과 공통 실패는 계약에, 관리자 토큰과 권한 판정은 관리자 세트에, 잠금과 알림 연결은 동시성에 있다. ([4-2-1 공통 규칙과 헤더](4-2-CONTRACT.md#4-2-1-공통-규칙과-헤더), [ADMIN 5-1 보안](../../ADMIN/BACKEND/5-1-SECURITY.md), [5-2 동시성](5-2-CONCURRENCY.md))

<br>

### 5-1-1 인증 수준

| 항목 | 처리 |
|---|---|
| 불필요 경로 | 공개 목록과 상세<br>토큰을 읽지 않아 자동 첨부된 만료 토큰으로 거절되지 않음 |
| 관리자 경로 | 관리자 목록과 상세, 작성, 수정, 게시, 게시 해제, 삭제<br>관리자 판정 필터를 통과한 요청만 |

<br>

### 5-1-2 접근 판정

| 판정 | 규칙 |
|---|---|
| 공개 조회 | 게시 상태만 읽음<br>없는 공지와 초안을 같은 결과로 응답해 초안의 존재를 드러내지 않음 |
| 관리자 작업 | 모든 관리자가 모든 공지를 작성, 수정, 게시, 삭제<br>작성자 제한 없음 |
| 알림 연결 | 게시 상태인 공지만 캠페인에 연결<br>초안과 게시 해제된 공지는 새 알림의 대상이 되지 않음<br>연결 연산은 관리자 API 경로가 아니라 알림 도메인의 관리자 캠페인 예약 안에서만 호출됨 |

<br>

### 5-1-3 계정 상태

| 상태 | 처리 |
|---|---|
| 게스트와 회원 | 공개 조회는 계정 상태를 판정하지 않음 |
| 관리자의 정지와 탈퇴 | 관리자 판정 필터가 거절 |

<br>

### 5-1-4 입력 검증

| 대상 | 규칙 |
|---|---|
| 제목과 본문 | 길이를 벗어나거나 공백으로만 구성된 값은 선언적 검증으로 거절<br>마크업을 해석하지 않고 평문으로 저장 |
| 태그 | 다섯 값만 허용<br>알림 유형은 요청으로 받지 않고 태그에서 정함 |
| 공지 식별자 | UUID 형식<br>공개 상세는 형식 오류도 부재로 응답 |
| 커서 | 복호화 성공 여부만 판정 |

<br>

### 5-1-5 식별자와 개인정보

| 대상 | 규칙 |
|---|---|
| 외부 식별자 | 공지는 공개 식별자<br>자동 증가 PK는 응답과 딥링크에 포함하지 않음 |
| 작성자 | 관리자 응답에만 닉네임과 공개 식별자<br>공개 조회에는 작성자 없음 |
| 본문 | 운영자가 쓰는 글이라 사용자 개인정보가 들어가면 안 됨<br>서버는 판정하지 않음 |
| 로그 | 제목, 본문, 사유를 기록하지 않음<br>공지 공개 식별자만 |

<br>

### 5-1-6 수용한 한계

| 한계 | 수용 이유 |
|---|---|
| 게시된 공지의 수정이 바로 공개됨 | 오타 수정이 가장 흔한 작업<br>수정 이력은 감사 로그에 남음 |
| 본문에 개인정보가 들어가도 서버가 막지 못함 | 작성자가 관리자뿐이고 감사 로그로 추적 가능 |
| 알림 캠페인에 연결한 뒤 게시 해제해도 이미 선점한 회차는 멈추지 않음 | 예약 상태 캠페인은 선점 때 게시 상태를 확인해 실패로 끝남<br>선점 판정 직후의 게시 해제는 그 회차에 반영되지 않음<br>눌렀을 때 공지가 없음을 보여 주는 것은 클라이언트 |
