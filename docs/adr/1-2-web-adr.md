## W-001. SSE를 fetch와 ReadableStream으로 수신

- 결정일: 원문 미기재 · 기록 확정 상태: Accepted
- 근거: [이관 원문 W:87](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-2-web-app.md#L87-L99)
- **맥락:** 채팅 턴은 사용자 입력을 POST 본문에 실어 보내고 SSE로 응답받습니다.
- **결정:** `fetch`와 `ReadableStream`으로 수신합니다.
- **이유:** 표준 EventSource는 GET만 지원해 해당 POST 본문 계약을 충족하지 못합니다.
- **주요 영향:** 이벤트 파싱·EOF 처리를 직접 소유하고 일반 요청 타임아웃과 스트림 수명을 구분합니다.

## W-002. 게스트 서재 초기 상태를 세 가지로 구분

- 결정일: 원문 미기재 · 기록 확정 상태: Accepted
- 근거: [이관 원문 W:102](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-2-web-app.md#L102-L120)
- **맥락:** SSR 시점에는 localStorage를 읽을 수 없습니다.
- **결정:** `null`은 미확정, 빈 배열은 빈 서재, 값이 있는 배열은 조회 대상으로 구분합니다.
- **이유:** 빈 배열 하나로 초기화하면 데이터가 있는 사용자에게도 빈 서재가 먼저 깜빡입니다.
- **주요 영향:** 목록과 온보딩은 저장소 확인 뒤에 판정합니다.

## W-003. BFF를 백엔드 호출과 토큰 보관의 단일 창구로 사용

- 결정일: 원문 미기재 · 기록 확정 상태: Accepted
- 근거: [이관 원문 W:370](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-2-web-app.md#L370-L407)
- **맥락:** 브라우저 직접 호출과 토큰 저장 위치를 선택해야 했습니다.
- **결정:** 동일 출처 BFF를 사용하고 access·refresh는 httpOnly 쿠키로 보관합니다.
- **이유:** 백엔드 주소와 인증 토큰을 브라우저 JavaScript에 노출하지 않기 위해서입니다.
- **주요 영향:** BFF가 스트리밍 전달·선제 재발급을 소유하고 회원 판정은 별도 응답에 의존합니다.

## W-004. 이관 제출 뒤 게스트 ID를 일괄 정리

- 결정일: 원문 미기재 · 기록 확정 상태: Accepted
- 근거: [이관 원문 C:582](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-1-client.md#L582-L590)
- **맥락:** 회원 이관의 일부 항목이 실패할 때 로컬 ID를 남길지 선택해야 했습니다.
- **결정:** 이관 결과와 무관하게 게스트 배열을 정리하고 성공한 수만 안내합니다.
- **이유:** 회원 서재의 정본은 서버이며 실패 ID를 남기면 로그아웃 뒤 게스트 데이터와 혼합될 수 있습니다.
- **주요 영향:** 실패 항목을 자동 재시도 목록으로 남기지 않습니다.

## W-005. 로그인 핸드오프 데이터를 ID 스냅숏으로 식별

- 결정일: 원문 미기재 · 기록 확정 상태: Accepted
- 근거: [이관 원문 W:524](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-2-web-app.md#L524-L542)
- **맥락:** 인앱 브라우저에서 만든 데이터를 외부 브라우저 로그인으로 전달해야 했습니다.
- **결정:** 핸드오프 발급 시 ID 스냅숏을 사용하고 복귀 정리는 서버 상태 조회 결과로 판정합니다.
- **이유:** 기존 이관·원자 클레임을 재사용하고 브라우저 간 로컬 상태 추측을 피하기 위해서입니다.
- **주요 영향:** 핸드오프 뒤 새로 만든 콘텐츠는 보존하며, 상태 조회가 이관·만료·종결 계측의 기준이 됩니다.

## W-006. 공유 진입을 헤더 버튼으로 표시

- 결정일: 원문 미기재 · 기록 확정 상태: Accepted
- 근거: [이관 원문 C:1021](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-1-client.md#L1021-L1027)
- **맥락:** 공유 진입이 옵션 메뉴에 있으면 발견하기 어려웠습니다.
- **결정:** 헤더의 홈 버튼 자리에 공유 아이콘을 둡니다.
- **이유:** 공유가 화면 안에서 직접 발견되도록 하기 위해서입니다.
- **주요 영향:** 아이콘의 접근성 이름을 제공하고 발급 전 확인을 유지합니다. 이 기록의 당시 메뉴 구성은 후속 신고 기능의 현재 구성을 덮어쓰지 않습니다.

## W-007. 계정 연동에 별도 NextAuth 공급자 사용

- 결정일: 2026-08-01 · 기록 확정 상태: Accepted
- 근거: [이관 원문 W:418](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-2-web-app.md#L418-L427)
- **맥락:** 계정 연동은 현재 회원 세션을 유지한 채 신선한 ID 토큰을 받아야 합니다.
- **결정:** 연동 전용 공급자 변형과 콜백을 사용합니다.

- **주요 영향:** 연동 콜백·자격증명·SDK 세션 처리를 로그인과 구분하고 추가 콜백 URL을 운영 설정에 등록합니다.

## W-008. 제작 재개 의도를 URL 대신 세션스토리지에 기록

- 결정일: 2026-08-27 · 기록 확정 상태: Accepted
- 근거: [이관 원문 C:835](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-1-client.md#L835-L836), [이관 원문 W:139](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-2-web-app.md#L139-L142)
- **맥락:** 재개 쿼리 파라미터가 라우터 캐시 재진입 시 마운트보다 늦게 반영될 수 있었습니다.

- **이유:** 컴포넌트 마운트와 히스토리 URL 반영의 순서에 의존하지 않기 위해서입니다.
- **주요 영향:** 재개와 새로 만들기의 의도를 라우팅 전에 확정합니다.

## W-009. 인앱 진입 차단을 로그인 시점 핸드오프로 대체

- 결정일: 원문 미기재 · 기록 확정 상태: Accepted
- 근거: [이관 원문](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-2-web-app.md#L466-L505)
- **맥락:** 인앱과 외부 브라우저의 저장소가 격리됩니다.

## W-010. 인앱 복귀 정리는 핸드오프 상태 조회로 판정

- 결정일: 원문 미기재 · 기록 확정 상태: Accepted
- 근거: [이관 원문](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-2-web-app.md#L522-L542)
- **맥락:** 인앱과 외부 브라우저의 저장소가 격리됩니다.
- **결정:** 상태 API 한 번으로 이관 성공 ID만 정리합니다.
- **이유:** 리소스별 403은 요청 수가 늘고 이관·타인 클레임·삭제를 구분하지 못합니다.
- **주요 영향:** 생성 이후 새 게스트 콘텐츠와 이관 실패 ID를 보존합니다. W-005의 ID 스냅숏 선택과 연결됩니다.
