## AR-1. 일정 전제와 리스크

앱 개발 완료 목표가 2026-08-28이라 **Phase 2 개발 스프린트(8/5~8/18)를 넘어 검증 스프린트(8/19~9/1) 기간까지 개발이 이어집니다.**

**개발 조건** — 1인 개발이며 Phase 2 기간에는 안드로이드를 최우선으로 두고 웹은 추가 기능이 있을 때만 진행합니다. **범위를 고정하고 일정을 조정합니다** — v1 범위([`3-3-android-app.md §3-3-3`](../product-specs/3-3-android-app.md#3-3-3-내비게이션화면-구조-대응) 매트릭스의 `v1`·`v1 · 앱 선행` 항목)를 줄이는 대신, 필요하면 출시일을 미룹니다.

**개인 개발자 계정 요건** — 정식 출시 전에 비공개 테스트에서 일정 인원의 테스터를 연속 기간 유지해야 합니다(최신 수치는 Play Console 안내를 직접 확인). 이 요건은 코드 완성도와 무관하게 달력 시간을 소비하므로, 비공개 테스트 배포(**M1**)를 개발 완료보다 앞당겨 배치합니다. **기산점은 트랙 배포가 아니라 테스터 옵트인 완료입니다** — 배포만 해 두고 테스터가 참여하지 않으면 하루도 쌓이지 않습니다. 따라서 절대 기한으로 관리하는 대상은 M1 배포가 아니라 **8/14 옵트인 완료**이며(§AR-3), 여기가 밀리면 정식 출시 신청(M2)도 같은 기간만큼 밀립니다. M1 빌드는 완성본이 아니어도 됩니다 — 요건은 테스터 유지이지 기능 완성이 아니므로, 로그인과 기본 루프만 동작하면 배포하고 이후 빌드를 같은 트랙에 계속 올립니다.

**이 일정에는 버퍼가 없습니다.** 8/14 옵트인 완료에서 M2(8/28 심사 등록)까지가 **정확히 14일**이라, 통상적인 "연속 14일" 요건을 이론적 최솟값으로 채우는 계획입니다. 옵트인이 하루라도 밀리거나 유지 기간 중 테스터 수가 요건 아래로 떨어지면 M2가 그만큼 밀립니다. 대응은 둘입니다 — 테스터를 **요건 인원보다 여유 있게** 모집해 이탈을 흡수하고(8/8 명단), 요건 인원·기간 수치를 명단 확정 시점에 Play Console 안내로 **한 번 더 실측**합니다. 실측한 요건 기간이 14일과 다르면 8/14 옵트인 기한도 함께 재도출합니다. 그래도 밀리면 위 개발 조건대로 범위가 아니라 출시일을 조정합니다. 비공개 테스트 트랙의 **첫 업로드 자체도 심사를 거치며, 신규 계정의 첫 심사는 수일이 걸릴 수 있습니다.** 이 대기도 8/14 기한 앞에 놓이므로 첫 빌드는 W1이 끝나는 대로 지체 없이 업로드합니다(완성본이 아니어도 되는 이유는 위 개인 개발자 계정 요건).

### W1 (8/5 ~ 8/11) — 골격과 로그인

**목표**

- **모듈 구조** — `settings.gradle.kts`에 12개 모듈 `include`(`:app` + `:core` 6 + `:feature` 5)와 모듈 간 의존 규칙 적용(§3-3-2). `:core:domain`·`:core:common`은 `kotlin-jvm` 모듈로 만들어 안드로이드 참조를 컴파일 단계에서 차단합니다. Version Catalog를 모든 모듈이 공유합니다.
- **프로젝트 골격** — `:core:domain`에 앱 스코프 헬퍼 인터페이스 2종과 라우트 마커, `:core:ui`에 `MviViewModel` 베이스 클래스와 `MessageHelper` 구현, `:core:navigation`에 `NavigationHelper` 구현(둘 다 `Channel(BUFFERED)`)과 타입 안전 라우트 단일 등록처·`auth`·`main` 그래프, Hilt 배선(스코프 2종), `:core:ui` 테마(웹 토큰 이식·라이트/다크 2벌·폰트 2종)와 **문자열 리소스 중앙화**, 오류 타입 → 문자열 매핑 배치, 루트 `compose_stability.conf`와 Compose 모듈별 등록, Retrofit·OkHttp 클라이언트와 인터셉터 3종(식별 헤더 → 인증 → 로깅), DataStore 3종(암호화 토큰·Preferences·퍼널 슬롯 직렬화 준비).
- **식별자** — 첫 실행 시 `device_id` UUID 생성·보관, 모든 요청 헤더 주입.
- **로그인 화면**(앱 전용) — 로고·소개·가입 보상 고지·기존 계정 안내·프로바이더 버튼 2종·진행 중 잠금·실패 표시.
- **소셜 로그인 2종** — 구글 Credential Manager, 카카오 SDK(앱 간 로그인·계정 로그인 폴백). 로그인 응답으로 세션 수립, `isNewUser` 판정 준비.
- **토큰 세션** — Keystore 암호화 저장, 선제 재발급(만료 여유 60초·**이중 시계 앵커**), 전역 단일 비행과 회전 저장 순서, 반응형 401 재시도, 실패 분기 3종(401·403·네트워크), 앱 수준 세션 상태 `Flow`와 그래프 전환 배선, **로그아웃 절차 5단계**(§3-3-4 — FCM 해제는 W3에 붙습니다).
- **홈·채팅 목록** — 회원 서재 API 연동, 카드·썸네일·빈 상태·오류 상태, 하단 3탭과 탭 상태 보존, 당겨서 새로고침. **Room 배선(엔티티·DAO)과 목록 캐시** — 진입 시 캐시 선표시와 응답 교체, 갱신 중 표시, 목록별 최신 1벌 유지(상한 없음), 로그아웃 전삭제(§3-3-4).
- **빌드 구성** — 빌드 타입별 `API_BASE_URL` 주입, 시크릿 주입, 백업 비활성, 평문 통신 금지, `minSdk`를 제품 지원 선언과 같은 26으로 정렬(§3-3-5), `versionName`을 0.1.0으로 정렬(§3-3-7 빌드·배포 구성). **릴리스 R8 코드·리소스 축소를 활성화합니다** — 기준 코드는 현재 `optimization { enable = false }`로 꺼져 있어 매핑 파일이 생성되지 않으며, Crashlytics 매핑 업로드(§3-3-6)의 선행 조건입니다.
- **Firebase** — `google-services.json` 배치(`.gitignore` + CI 시크릿 주입), Crashlytics 연동과 디버그 수집 비활성, 매핑 업로드 배선(§3-3-6).

**완료 조건**

- 실기기에서 로그인 화면 → 구글·카카오 각각 로그인 → 홈 진입이 동작하고, 앱을 재실행하면 로그인 화면을 건너뜁니다.
- 첫 로그인 요청에 `X-Manyak-Device-Id`가 실려 있습니다.
- 난독화를 켠 릴리스 빌드가 정상 동작합니다(난독화 빌드에서만 재현되는 오류를 이 시점에 걸러냅니다).

### W2 (8/12 ~ 8/18) — 비공개 테스트 배포와 채팅

**목표**

- **M1 배포**(주 초반 우선) — 비공개 테스트 트랙 업로드, 심사 통과 확인, 테스터 옵트인 완료. 이후 빌드는 같은 트랙에 계속 올립니다.
- **스토리 상세** — 썸네일 히어로와 풀스크린 이미지 뷰어(`BackHandler` 닫기), 시작 설정 선택, 채팅 시작 CTA, 삭제, 본 엔딩 배지. **상세 캐시** — 소유 판정(서재에 있는 `storyId`만), 배지 스켈레톤, 서재 갱신 시 사라진 상세 삭제(§3-3-4).
- **채팅 화면** — SSE 스트리밍 수신과 부분 렌더, 강조 마크업, 스크롤 앵커와 하단 이동 버튼, 헤더 show/hide, 입력 모드 2종과 선택지, 추천 입력 토글, 전송 잠금과 대기 스피너, 응답 재생성, 엔딩 도달 턴 배지, 삭제, 공유 발급(OS 공유 시트).
- **입력 출처 판별** — `userSource`(`choice`·`edited_choice`·`typed`) 규칙 구현.
- **오류 처리** — EOF 실패 확정과 상세 재조회, 402 공통 분기, 실패 안내.
- **채팅 방 캐시** — 완료된 턴 기록(`completed` 후 재조회 결과만)과 진입 시 선표시·응답 교체, **최근 진입 방 30개 보관 상한**(초과 시 오래된 방 제거), 404 시 캐시 삭제(§3-3-4).

**완료 조건**

- **스토어 서명본**(비공개 테스트 트랙 설치본)에서 구글·카카오 로그인이 완주합니다. 로컬 빌드만 확인하면 Play 앱 서명 키 지문 누락을 놓치고, 그 경우 스토어 설치본에서만 로그인이 실패해 발견이 늦어집니다.
- 테스터 옵트인이 완료되어 유지 기간 기산이 시작됐습니다(등록만으로는 요건을 채우지 못합니다).
- 채팅 턴이 전송부터 서버 확정본 반영까지 동작하고, 스트림이 끊긴 경우에도 화면이 복구됩니다.
- 이미 들어간 적 있는 채팅 방에 재진입할 때 빈 화면이나 스피너 없이 직전 대화가 즉시 보입니다.

### W3 (8/19 ~ 8/25) — 퍼널과 마이

**목표**

- **생성 퍼널** — 4단계 전환, 키워드 선택과 커스텀 키워드, 스토리라인 생성·재생성·평가, 추가 정보 입력, 완성과 채팅 진입, 단계별 로딩·오류 처리.
- **퍼널 상태 보존** — DataStore 슬롯 저장·복구, `onStop` 저장, 복구 폴링(포그라운드 한정), 완성 재시도 멱등, 이어서 만들기 배너, `BackHandler` 이탈 가드(임시 저장 또는 경고).
- **마이 전체** — 프로필·로그아웃, 크레딧 잔액, 출석 체크, 친구 초대(코드 발급·입력·카카오 공유), 계정 연동(재인증 → 대상 프로바이더), 테마 선택, 약관·개인정보·서비스 안내 인앱 브라우저 열람.
- **회원 탈퇴 진입점** — 8/15에 확정되는 B26 결정을 **이 주차에 구현합니다.** 최소 대응(웹 탈퇴 요청 페이지를 인앱 브라우저로 열기)이면 마이 메뉴 한 줄이고, 셀프서브 탈퇴를 택하면 확인 다이얼로그·API 연동·탈퇴 후 세션 정리(§3-3-4 로그아웃 절차 재사용)까지 이 주차 범위입니다. 결정이 늦어질 때의 폴백 규칙은 [`3-3-android-app.md §3-3-4`](../product-specs/3-3-android-app.md#3-3-4-api-연동인증-세션) 회원 탈퇴 절을 따릅니다.
- **신규 가입 흐름** — `isNewUser` 판정 후 초대 코드 입력 스텝.
- **피드백**(`platform: ANDROID` 고정)과 **채팅 첫 진입 안내 투어**·인라인 힌트.
- **관측 배선** — Amplitude 이벤트 발화(공통 카탈로그 재사용), 로그인·로그아웃 식별자 처리, Crashlytics 크래시·ANR과 R8 매핑 업로드(디버그 수집 비활성), Timber 디버그 전용 로깅.
- **FCM 완료 알림**(§3-3-5) — 토큰 등록·해제, 퍼널 완성 시점의 권한 요청, 수신 서비스와 포그라운드 억제, 탭 시 스토리 상세 랜딩. **서버의 토큰 등록 API와 발송 트리거([`4-backend.md §4-3-12`](../product-specs/4-backend.md))가 선행 조건이며, 확보되지 않으면 이 항목 전체를 v1에서 제외합니다.**

**완료 조건**

- [`3-3-android-app.md §3-3-3`](../product-specs/3-3-android-app.md#3-3-3-내비게이션화면-구조-대응) 매트릭스에서 목표 범위가 `v1`·`v1 · 앱 선행`인 항목을 모두 구현했습니다.
- 필수 단위 테스트 목록([`3-3-android-app.md §3-3-7`](../product-specs/3-3-android-app.md) 테스트 범위)의 전 항목이 존재하고 통과합니다.
- 계정 삭제 진입점이 마이 화면에서 동작합니다(B26 결정 결과 기준). 이 항목이 W3에 남지 않으면 W4에서 만회할 수 없습니다.
- 수동 검수 체크리스트 1차를 완주했습니다.
- 앱을 백그라운드로 보낸 상태에서 스토리 생성이 끝나면 알림이 도착하고, 탭하면 해당 스토리 상세로 이동합니다(서버 선행 조건 충족 시).

### W4 (8/26 ~ 8/28) — 검수와 심사 등록

**목표**

- 수동 검수 완주와 결함 수정, 접근성·글꼴 배율·대화면 비파손 확인.
- 스토어 자산 — 앱 아이콘, 폰 스크린샷, 짧은 설명·자세한 설명.
- 정책 제출물 — 데이터 안전 양식, 개인정보처리방침 URL, 계정 삭제 요청 경로(B26 결정 결과 반영).
- 최종 빌드 업로드와 테스터 유지 요건 충족 확인, **정식 출시 접근 신청과 심사 등록**.

**완료 조건**

- [`3-3-android-app.md`](../product-specs/3-3-android-app.md) Definition of Done 전 항목을 충족했습니다.

## AR-3. 선행 작업 (코드 외)

다음 네 가지는 코드로 해결되지 않으며 개발과 병렬로 진행해야 합니다. 늦어지면 개발 진척과 무관하게 마일스톤이 막힙니다.

| 선행 작업 | 목표 기한 | 막는 것 |
| --- | --- | --- |
| 업로드 keystore 생성과 Play Console 앱 등록 | 8/6 | 서명 키 지문이 없으면 소셜 로그인 콘솔 등록을 진행할 수 없습니다 |
| 구글·카카오 콘솔 등록(지문·키 해시 **3종** — 디버그 키·업로드 키·Play 앱 서명 키, 카카오 OIDC 활성 확인) | 8/7 | 로그인 구현을 검증할 수 없습니다. Play 앱 서명 키 지문을 빠뜨리면 스토어 설치본에서만 로그인이 실패합니다 |
| 테스터 모집과 옵트인 | 8/8 명단(요건 인원 + 이탈 여유) · **8/14 옵트인 완료 — 절대 기한** | 유지 기간의 기산이 시작되지 않아 M2가 같은 기간만큼 밀립니다. 8/28 M2까지 정확히 14일이라 버퍼가 없습니다(§AR-1) |
| 회원 탈퇴 대응 방식 결정([`4-backend.md §4-8`](../product-specs/4-backend.md) B26) | **8/15 결정 · W3(~8/25) 구현** | 계정 삭제 요건 미충족은 심사 거절 사유입니다. 결정이 늦어질 때의 폴백 규칙은 [`3-3-android-app.md §3-3-4`](../product-specs/3-3-android-app.md#3-3-4-api-연동인증-세션) 회원 탈퇴 절을 따릅니다 |
