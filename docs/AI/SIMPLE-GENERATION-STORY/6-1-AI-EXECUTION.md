# 6-1 AI 실행

| 항목 | 값 |
|---|---|
| 적용 태스크 | 간편 제작 스토리 생성(스토리라인 생성, 컴파일, 인물 이미지와 썸네일 생성) |
| 버전 | 0.1 |

<br>

**프로덕션 모델 현황**

| 용도 | 모델 | 공급자 | 설정 출처 |
|---|---|---|---|
| 스토리라인 생성 | `deepseek-flash` | DeepSeek | `STORYLINES_MODEL` |
| 컴파일 | `gemini-3.7-flash` | Google | `STORY_COMPILE_MODEL` |
| 인물 이미지·썸네일 | `gpt-image-2.5-flare` | OpenAI | `IMAGE_MODEL` 기본값 |

이 문서는 태스크 정의의 입력을 계약의 결과로 바꾸는 현재 실행 순서와 분기를 설명한다. ([3 태스크 정의](3-TASK-DEFINITION.md), [5 계약](5-CONTRACT.md))

판단 단계의 목표는 인지 구조, 구성 요소의 책임은 소프트웨어 구조에서 확인한다. ([4-1 인지 구조](4-1-DESIGN-COGNITIVE-ARCHITECTURE.md), [4-2 소프트웨어 구조](4-2-DESIGN-SOFTWARE-ARCHITECTURE.md))

<br>

### 6-1-1 진입과 종료

| 실행 | 진입 | 입력 | 반환 | 종료 |
|---|---|---|---|---|
| 스토리라인 생성 | 라우터의 스토리라인 요청 | 스토리라인 요청 [5-2](5-CONTRACT.md#5-2-스토리라인-요청과-결과) | 후보 3편, 호출 기록 | 성공 또는 요청 실패 |
| 컴파일 | 라우터의 컴파일 요청 | 컴파일 요청 [5-3](5-CONTRACT.md#5-3-컴파일-요청과-결과) | 스토리 설정, 외형, 이미지 결과, 호출 기록 | 성공 또는 요청 실패 |
| 인물 이미지 생성 | 컴파일 내부 | 검증한 인물 카드, 장르 태그 | 인물별 이미지 결과 | 예외 없이 결과 반환 |
| 썸네일 생성 | 컴파일 내부 | 검증한 인물 카드, 장르 태그 | 썸네일 결과 1개 | 예외 없이 결과 반환 |

실패 시 HTTP 상태 코드, 응답 메시지와 이미지 오류 코드는 실패 계약의 표를 따른다. ([5-4 실패 계약](5-CONTRACT.md#5-4-실패-계약))

<br>

**실행 순서**

| 실행 | 순서 |
|---|---|
| 스토리라인 생성 | 요청 검증 → 프롬프트 조립 → 후보 생성·검증 → 번호 정리 → 인물 누락 보완 → 응답 |
| 컴파일 | 요청 검증 → 프롬프트 조립·명세 생성 → 입력값 복원·누락 보완 → 엔딩·외형 정리 → 명세 파싱 → 이미지 병렬 생성 → 응답 |

백엔드 연결이 끊겨도 AI 서버는 진행 중인 호출을 중단하지 않고 남은 보완 호출까지 실행한다. 자원 관리는 소프트웨어 설계의 기준을 따른다. ([4-2-5 상태와 자원](4-2-DESIGN-SOFTWARE-ARCHITECTURE.md#4-2-5-상태와-자원))

<br>

모델, 프롬프트와 실행 설정은 요청별로 선택할 수 없다.

<br>

### 6-1-2 입력 검증과 취득

필수값, 성별과 특징 태그는 스토리라인과 컴파일의 요청 계약을 따른다. ([5-2 스토리라인 요청과 결과](5-CONTRACT.md#5-2-스토리라인-요청과-결과), [5-3 컴파일 요청과 결과](5-CONTRACT.md#5-3-컴파일-요청과-결과))

규칙을 위반한 요청은 거부한다.

AI 서버는 정규화한 주인공과 주변 인물 이름을 대소문자 구분 없이 비교하고, 중복 이름이 있으면 요청을 거부한다. 이름을 입력하지 않은 인물은 비교하지 않는다.

스키마를 검증하면서 다음 값을 정규화한다. 정규화 자체는 거부 사유가 아니다.

| 대상 | 정규화 |
|---|---|
| 인물 이름 | NFC 정규화 <br> 앞뒤 공백 제거 <br> 안쪽의 연속 공백과 개행을 한 칸으로 변경 <br> 결과가 비면 미입력으로 처리 |
| 특징 태그 | 각 문자열을 NFC 정규화하고 앞뒤 공백 제거 <br> 빈 항목 제거 <br> `null`은 빈 배열로 처리 |
| 주변 인물 목록 | 생략하거나 `null`이면 빈 배열로 처리 |
| 로어북 목록 | 생략, 빈 배열, `null`이면 로어북 없음으로 처리 |

이름 검사와 본문 대조에는 정규화한 이름을 쓴다.

<br>

### 6-1-3 전처리

<br>

**인물 표기**

```text
이름: 서린 / 성별: 여성 / 특징: 냉정함, 검술
이름: (미정) / 성별: (미정) / 특징: (미정)
```

주인공과 주변 인물은 한 명씩 한 줄로 적는다. 빈 값은 `(미정)`으로 적어 모델이 정하게 한다. 성별은 계약 값 대신 한국어로 적는다.


<br>

**입력별 변환**

| 입력 | 스토리라인 생성 | 컴파일 |
|---|---|---|
| 장르 | 태그를 쉼표와 공백으로 연결 | 같음 |
| 주인공 | 인물 표기 한 줄 | 같음 |
| 주변 인물 | 각 줄에 `1) `, `2) ` 순번 추가 | 각 줄에 `[input_character_id: input-1] ` 형식의 식별자 추가 |
| 주변 인물 없음 | 모델에게 구성을 맡기는 고정 문구 한 줄 | 같음 |
| 선택한 스토리라인 | 해당 없음 | 받은 값 그대로 |
| 추가 정보 | 해당 없음 | 빈 문자열이면 `(없음)` |
| 로어북 | 해당 없음 | 항목마다 `### 이름`과 내용 배치 <br> 이름과 내용의 앞뒤 공백 제거 <br> 항목 사이는 빈 줄 <br> 없으면 `(없음)` |

<br>

**내부 식별자**

주변 인물에는 요청 순서대로 `input-1`부터 내부 식별자를 붙인다. AI가 입력 이름 `도윤`을 `도윤 사서`처럼 잘못 바꿔도 코드는 `input-1`로 같은 인물을 찾아 이름을 `도윤`으로 덮어쓴다. 내부 식별자는 최종 응답에서 제거한다.

<br>

입력은 자르거나 요약하지 않는다. 입력 이미지가 없어 이미지 전처리도 하지 않는다.

<br>

### 6-1-4 프롬프트 조립

<br>

**템플릿과 버전**

| 버전 키 | 템플릿 | 사용 조건 |
|---|---|---|
| `STORYLINES` | `prompt/story/STORYLINES-TEMPLATE.md` | 스토리라인 생성과 보완 |
| `COMPILE` | `prompt/story/COMPILE-TEMPLATE.md` | 컴파일 모델 공급자가 Google이 아닐 때 |
| `COMPILE_GEMINI` | `prompt/story/COMPILE-TEMPLATE-gemini.md` | 컴파일 모델 공급자가 Google일 때 |
| `CHARACTER_IMAGE` | `prompt/image/CHARACTER-IMAGE-TEMPLATE.md` | 인물 이미지 생성 |
| `THUMBNAIL_IMAGE` | `prompt/image/THUMBNAIL-IMAGE-TEMPLATE.md` | 썸네일 생성 |

<br>

**텍스트 프롬프트**

| 순서 | 역할 | 내용 |
|---|---|---|
| 1 | `system` | `## [SYSTEM]` 블록 전체 <br> 역할, 작성 규칙, 출력 형식, 출력 전 점검 <br> 요청값이 없는 고정 문장 |
| 2 | `user` | `## [USER]` 블록의 자리에 전처리 결과를 넣은 문장 [6-1-3 전처리](#6-1-3-전처리) |

사용자 블록에는 다음 순서로 입력을 넣는다.

| 실행 | 입력 순서 |
|---|---|
| 스토리라인 생성 | 장르 → 주인공 → 입력 주변 인물 수 → 주변 인물 목록 |
| 컴파일 | 선택 스토리라인 → 추가 정보 → 장르 → 주인공 → 입력 주변 인물 수 → 주변 인물 목록 → 로어북 |

템플릿의 `{{자리}}`는 한 번만 치환한다. 치환한 값은 다시 검사하지 않으므로 사용자 입력에 같은 모양의 문자열이 있어도 바뀌지 않는다.

별도 정책 원본은 없다. 작성 규칙은 시스템 블록에 직접 관리한다. 규칙을 바꾸면 템플릿의 `version`을 올린다.

<br>

**보완 프롬프트**

보완 호출은 기존 시스템 지시를 유지하고, 사용자 메시지에 기존 입력·직전 결과·수정 지시를 순서대로 넣는다.

| 보완 대상 | 지시 기준 | 반환 형식 |
|---|---|---|
| 스토리라인의 인물 누락 | 인물이 빠진 후보 번호 | 고친 후보만 담은 `stories` 배열 <br> `id`는 후보 번호 |
| 컴파일 필수 블록 누락 | 누락된 블록 이름 | 같은 이름의 최상위 키에 블록 전체 반환 |
| 컴파일 인물 필드 누락, 이름 중복 | 인물 카드 위치와 필드 이름 | `character_updates` 배열 <br> 항목마다 `index`와 요청한 필드만 포함 |

<br>

**스토리라인 보완 응답 예시**

두 번째 후보에서 도윤이 빠졌을 때 받는 응답이다.

```json
{
  "stories": [
    {
      "id": 2,
      "storyline": "서린은 백 년 전에 자신이 쓴 편지를 발견하고, 편지의 비밀을 아는 사서 도윤과 함께 발신인을 추적한다.",
      "recommended_infos": [
        "편지는 보름달이 뜨는 밤에만 읽을 수 있다.",
        "도윤의 스승이 같은 편지를 보관하고 있었다.",
        "편지를 읽을 때마다 도서관의 방 하나가 과거 모습으로 바뀐다."
      ]
    }
  ]
}
```

<br>

**컴파일 보완 응답 예시**

첫 선택지 블록과 도윤의 머리 모양을 함께 보완하는 응답이다.

```json
{
  "suggested_inputs": ["기록장을 빛에 비춰 본다", "도윤에게 푸른 흔적을 가리킨다", "기록장의 보관 위치를 확인한다"],
  "character_updates": [
    { "index": 0, "hair": "짧은 검은 머리" }
  ]
}
```

<br>

**이미지 프롬프트**

| 대상 | 입력 | 조립 조건 |
|---|---|---|
| 인물 이미지 | 장르 태그, 성별, 외형 값 6개 | 외형 정보 6개가 모두 있어야 프롬프트를 만들어 이미지를 생성 <br> 하나라도 비면 `appearance_missing` 반환 |
| 썸네일 | 장르 태그, 인물 최대 2명의 성별과 외형 | 외형 정보가 부족하거나 인물이 없어도 프롬프트를 만들어 썸네일을 생성 <br> 인물은 썸네일의 인물 선정 기준에 따라 선택 [3-4 썸네일 생성](3-TASK-DEFINITION.md#3-4-썸네일-생성) <br> 빈 외형은 태그와 함께 제외 <br> 인물이 없으면 `없음` 한 줄 사용 |

이미지 프롬프트는 `<image_prompt>` 블록만 쓴다. 인물 이름은 넣지 않는다.

프롬프트의 토큰 수는 계산하지 않으며 길이에 맞춰 자르지 않는다. 공급자가 길이 때문에 거부하면 요청 거부로 끝낸다. ([5-4 실패 계약](5-CONTRACT.md#5-4-실패-계약))

<br>

### 6-1-5 모델 호출

<br>

**텍스트 모델**

| 항목 | 스토리라인 생성 | 컴파일 |
|---|---|---|
| 설정 출처 | `STORYLINES_MODEL` | `STORY_COMPILE_MODEL` |
| 추론 | 끔 | `medium` |
| 출력 한도 | 6,144 토큰 | 16,384 토큰 <br> 추론 토큰과 본문이 함께 사용 |
| temperature | 0.75 | 0.75 |
| 응답 형식 | JSON 객체 | JSON 객체 |
| 호출 방식 | 단발, 스트리밍 사용 안 함 | 단발, 스트리밍 사용 안 함 |
| 폴백 모델 | 없음 | 없음 |

- 보완 호출은 본 호출의 모델·출력 한도·temperature를 그대로 쓴다.
- 첫 시도는 90초이며, 유효하지 않은 응답을 다시 호출할 때는 경과 시간을 뺀다.

코드는 공급자 장애나 모델 종료 시 다른 모델로 자동 전환하지 않는다. 운영자가 환경 변수의 모델 이름을 등록부에 있는 다른 모델로 바꾸고 서버를 재시작한다. 컴파일 모델의 공급자가 바뀌면 프롬프트 조립의 조건에 따라 템플릿도 함께 바뀐다. ([6-1-4 프롬프트 조립](#6-1-4-프롬프트-조립))

<br>

**텍스트 호출 요청**

호출부는 모델 통로에 모델 이름, 메시지 목록, 출력 한도, 제한 시간, temperature, JSON 응답 요구를 전달한다. 메시지는 `system` 하나와 `user` 하나이며, 스토리라인·컴파일과 보완 호출은 모두 `json_mode=True`를 지정한다. JSON 요구를 공급자 인자로 강제할 수 있는지는 아래 표를 따른다.

스토리라인 첫 호출의 요청 예시다. `system_prompt`와 `user_prompt`는 앞 절에서 조립한 문자열이다.

```python
LlmRequest(
    model="deepseek-flash",
    messages=[
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_prompt},
    ],
    max_tokens=6144,
    timeout=90.0,
    temperature=0.75,
    json_mode=True,
)
```

호출부는 모델 게이트웨이 계약에 맞는 요청만 보낸다. ([5-8 모델 게이트웨이 계약](5-CONTRACT.md#5-8-모델-게이트웨이-계약))

공급자별 인자는 어댑터가 정하며 지원하지 않는 옵션은 보내지 않는다.

| 공급자 | JSON 응답 강제 | 추론 설정 | 출력 한도 인자 |
|---|---|---|---|
| DeepSeek | `response_format`의 `json_object` | 추론을 끄는 인자 | `max_tokens` |
| OpenAI | `response_format`의 `json_object` | `reasoning_effort` | `max_completion_tokens` |
| Anthropic | 보내지 않음 <br> 프롬프트 지시에 의존 | 추론 끔 | `max_tokens` <br> 없으면 설정 오류 |
| Google | `response_mime_type`의 `application/json` | `thinking_level` | `max_output_tokens` |

- temperature를 받지 않는 모델에는 해당 값을 보내지 않는다.
- 출력 한도가 등록부의 모델 최대값을 넘으면 설정 오류로 끝낸다.

<br>

**공급자 주소와 전송 재시도**

DeepSeek는 `DEEPSEEK_API_URL`의 기본값 `https://api.deepseek.com`을 쓴다. OpenAI와 Anthropic은 각각 `OPENAI_API_URL`, `ANTHROPIC_API_URL`을 지정하지 않으면 SDK 기본 주소를 쓴다. Google은 `GEMINI_API_URL`이 설정에 있어도 현재 클라이언트 생성 시 전달하지 않아 SDK 기본 주소를 쓴다. 주소만 바꿔도 모델·프롬프트·호출 파라미터는 바뀌지 않는다.

OpenAI 호환·Anthropic SDK는 전송 실패를 최대 2회 재시도한다. 제한 시간은 시도마다 적용되므로 90초 호출은 최대 3번 시도로 270초까지 이어질 수 있다. Google SDK에는 재시도 횟수를 별도로 설정하지 않는다.

<br>

**실행 설정**

| 대상 | 변경 방법 | 반영 시점 |
|---|---|---|
| 텍스트 모델 | 환경 변수 `STORYLINES_MODEL`, `STORY_COMPILE_MODEL` | 서버 재시작 |
| 이미지 모델, 화질, 크기, 제한 시간 | 환경 변수 `IMAGE_MODEL`, `IMAGE_QUALITY`, `IMAGE_SIZE`, `IMAGE_TIMEOUT` | 서버 재시작 |
| 공급자 주소 | 환경 변수 `DEEPSEEK_API_URL`, `OPENAI_API_URL`, `ANTHROPIC_API_URL` | 서버 재시작 |
| 프롬프트 | `prompt/story`, `prompt/image`의 템플릿 | 배포 |
| 모델별 추론 설정, 허용 인자 | 모델 등록부 | 코드 변경 후 배포 |
| 출력 한도, temperature, 보완 횟수, 시간 한도 | 스토리 서비스 상수 | 코드 변경 후 배포 |

등록부에 있는 모델만 선택할 수 있다.

<br>

**이미지 모델**

| 항목 | 인물 이미지 | 썸네일 |
|---|---|---|
| 화질 | `IMAGE_QUALITY` <br> 기본값 `low` | 같음 |
| 크기 | `IMAGE_SIZE` <br> 기본값 `1024x768` | `768x1024` 고정 |
| 출력 형식 | WebP | WebP |
| 호출당 생성 수 | 1장 | 1장 |
| 제한 시간 | `IMAGE_TIMEOUT` <br> 기본값 60초, 연결 10초 | 같음 |
| 동시 실행 | 최대 5건 | 인물 이미지와 별도로 1건 |
| 코드 재호출 | 없음 | 없음 |
| SDK 전송 재시도 | 최대 2회 | 최대 2회 |

코드는 이미지를 다시 요청하지 않지만 OpenAI SDK가 전송 실패를 최대 2회 재시도한다. 제한 시간은 시도마다 적용되므로 이미지 한 장의 호출은 최대 3번 시도로 180초까지 이어질 수 있다.

인물 이미지 묶음에서 예상하지 못한 예외가 나면, 같은 묶음에서 아직 끝나지 않은 인물 이미지 호출만 취소한다.

<br>

### 6-1-6 검증과 복구

이 절은 현재 코드가 형식, 필수값, 입력값 보존을 검사하고 복구하는 방법을 설명한다.

<br>

**공통 응답 파싱**

모든 텍스트 응답을 다음 순서로 검사한다.

1. 본문이 비었는지 확인한다.
2. 본문을 감싼 코드 펜스를 제거한다.
3. JSON으로 파싱한다.
4. 최상위 값이 객체인지 확인한다.
5. 호출별 계약을 검증한다.

하나라도 실패하면 유효하지 않은 응답이다. 전송 오류는 별도로 분류하고 SDK 재시도에 맡긴다. 코드는 유효하지 않은 응답만 다시 호출한다. 출력이 한도에서 잘렸는지는 따로 검사하지 않으며 JSON 파싱 실패로 처리한다.

스토리라인과 컴파일의 보완 호출에서 전송 오류가 나거나 응답이 유효하지 않으면 요청 전체를 실패로 끝낸다. 컴파일 보완 대상이 엔딩이나 외형뿐이어도 같다.

<br>

**스토리라인 생성**

| 순서 | 검사 | 통과 기준 | 실패 시 |
|---|---|---|---|
| 1 | 후보 수 | `stories`가 정확히 3편 | 전체 재생성 |
| 2 | 후보 형식 | 모든 후보가 객체이며 줄거리와 추천 정보 타입이 맞음 | 전체 재생성 |
| 3 | 추천 정보 수 | 후보마다 정확히 3개 | 전체 재생성 |
| 4 | 줄거리 | 공백만 있는 값이 아님 | 전체 재생성 |
| 5 | 후보 번호 | 검사하지 않음 | 1, 2, 3으로 덮어씀 |
| 6 | 주변 인물 등장 | 이름을 입력한 주변 인물이 후보마다 등장 <br> NFC 정규화 후 부분 문자열로 대조 | 해당 후보만 보완 |

- 전체 재생성은 최대 2회다. 최초 생성부터 60초가 지나면 새 재생성을 시작하지 않는다.
- 주인공 이름은 검사하지 않는다. 줄거리가 1인칭이기 때문이다.
- 이름을 입력하지 않은 인물은 모델이 정한 이름을 알 수 없어 검사하지 않는다.
- 보완 응답은 요청한 후보 번호에만 반영한다. 요청하지 않았거나 범위를 벗어난 번호는 무시한다.
- 보완 결과가 1번부터 4번 검사를 통과하지 못하면 기존 후보를 유지한다.
- 보완 2회 뒤에도 인물이 빠졌으면 현재 결과를 반환하고 경고를 기록한다.

<br>

**컴파일**

최초 생성의 공통 파싱이 실패하면 다시 생성하지 않고 요청을 실패로 끝낸다. 파싱한 스토리 명세는 다음 순서로 처리한다.

| 순서 | 단계 | 기준 |
|---|---|---|
| 1 | 입력값 덮어쓰기 | 장르는 입력 태그로 변경 <br> 입력한 주인공 이름과 성별만 변경 <br> 내부 식별자가 있는 인물 카드는 입력 이름으로 변경 |
| 2 | 필수 블록 검사 | 필수값과 개수 확인 |
| 3 | 입력 인물 검사 | 각 입력 인물의 내부 식별자가 카드 하나에만 있음 <br> 이름을 입력한 인물이 모두 있음 <br> 실패하면 인물 카드 블록 전체를 보완 대상으로 지정 |
| 4 | 인물 필드 검사 | 이름이 비었거나 다른 카드와 겹치는지 확인 <br> 외형 값 6개가 모두 있는지 확인 |
| 5 | 부분 보완 | 2번부터 4번의 문제를 한 번에 요청 <br> 최대 2회 <br> 병합한 뒤 1번부터 다시 검사 |
| 6 | 엔딩 폴백 | 파싱 가능한 엔딩 3개가 아니면 빈 배열로 변경 |
| 7 | 최종 판정 | 엔딩을 제외한 필수 블록이 비었거나 인물 이름이 비거나 겹치면 요청 실패 |
| 8 | 외형 정리 | 남은 빈 외형 값을 빈 문자열로 변경 |
| 9 | 명세 파싱 | 내부 스토리 명세 모델로 파싱 <br> 파싱 실패 시 요청 실패 |

인물 카드 블록 전체를 다시 받는 차수에는 카드 위치가 바뀌므로 인물 필드 수정을 함께 요청하지 않는다.

`null`, 공백만 있는 문자열, 빈 배열, 빈 객체는 빈 값이다. 객체 자리에 다른 타입이 와도 빈 값으로 본다.

| 필수 항목 | 기준 |
|---|---|
| `meta` | `title`, `one_line_intro`, `description` |
| `prompt_settings` | `world_setting`, `rule_setting`, `tone_setting`, `length_ratio` <br> `plot_setting`의 `premise`, `conflict` |
| `prompt_settings.character_setting` | 1명에서 5명 <br> 카드마다 `gender`, `personality`, `tone`, `motivation`, `attitude_to_user` |
| `prompt_settings.user_role_setting` | `name`, `gender`, `role`, `background`, `personality` <br> `preference`는 선택 |
| `start` | `name`, `prologue`, `start_situation` |
| `suggested_inputs` | 정확히 3개, 빈 값 없음 |
| `main_events` | 3개에서 5개 <br> 사건마다 `name`, `description`, `key_sentence` |
| `endings` | 정확히 3개 <br> 엔딩마다 `name`, `achievement_condition`, `epilogue`, 1 이상의 정수인 `min_turns` |

- 이름이 겹치면 입력 인물 카드를 유지하고 다른 카드의 이름을 고친다. 입력 인물이 없으면 앞쪽 카드를 유지한다.
- 인물 필드 보완에서는 요청한 위치와 필드에 있는 비어 있지 않은 문자열만 반영한다.
- 코드는 필수 내용을 새로 만들지 않는다. 입력값, 후보 번호, 빈 배열처럼 확정할 수 있는 값만 넣는다.

<br>

**이미지**

이미지 내용은 검증하지 않는다. Base64 데이터가 있고 올바르게 디코딩되는지만 확인한다. 실패는 정해진 이미지 `error`로 분류한다. ([5-4 실패 계약](5-CONTRACT.md#5-4-실패-계약))

### 6-1-7 후처리와 기록

<br>

**통글 변환**

| 응답 필드 | 구성 |
|---|---|
| `world_setting` | 세계관, 전제, 갈등 |
| `character_setting` | 인물별 이름, 성별, 성격, 말투, 동기, 주인공을 대하는 태도 |
| `user_role_setting` | 호칭, 성별, 역할, 배경, 성격, 입력 선호 |
| `rule_setting` | 전개 규칙, 문체 톤, 분량 배분 |

통글은 마크다운 제목으로 항목을 나눈다. 장르는 백엔드가 입력 태그로 관리하므로 제외한다. 시작 설정, 추천 입력, 주요 사건, 엔딩은 통글로 바꾸지 않는다.

<br>

**이미지 결과**

성공한 WebP 바이너리를 Base64 문자열로 인코딩해 응답에 포함한다. 이미지 이름·결과 순서·성공과 실패 표현은 컴파일 응답 계약을 따르고, 오류는 실패 계약에 맞게 변환한다. ([5-3 컴파일 요청과 결과](5-CONTRACT.md#5-3-컴파일-요청과-결과), [5-4 실패 계약](5-CONTRACT.md#5-4-실패-계약))

<br>

호출 정보를 응답에 포함하고 실행 내역을 기록한다. 응답 필드와 집계는 계약에 정한 기준을 따른다. ([5-5 식별과 전달](5-CONTRACT.md#5-5-식별과-전달))
