# 2-2 운영 요구사항

본 문서는 ([2-1 유저 스토리](2-1-USER-STORY.md))에서 정의한 사용자 기대를 충족하기 위한 품질, 처리 시간과 비용의 요구 수준을 정한다.

생성 실패와 낮은 품질이 사용자에게 미치는 영향을 구분하고, 어떤 결과를 허용할지와 무엇을 우선할지 정한다. 이를 바탕으로 품질 지표의 목표값, 처리 시간과 동시 요청 수, 요청 한 건의 생성 비용 한도를 정의한다. 합의하지 않은 값은 미정으로 남긴다.

<br>

### 2-2-1 태스크의 유저

운영 관점에서 이 태스크의 요구사항을 정하고 결과를 확인하는 주체는 AI 담당자와 제품 정책 담당자다. 이들은 사용자가 기대하는 결과를 제공하면서 품질, 처리 시간과 생성 비용을 운영 가능한 수준으로 유지해야 한다. 스토리를 제작하고 채팅하는 사용자의 기대는 [2-1 유저 스토리](2-1-USER-STORY.md)에서 다룬다.

<br>

| 구분 | 지표 | 목표값 | 상한 |

| 시간 | 스토리라인 생성 처리 시간 | p95 30초 이하 | 90초 |

### 2-2-3 품질

**스토리라인 생성의 품질 지표**

| 기준 | 측정 방법 | 목표값 |
|---|---|---|
| 요청 실패율 | 실패한 스토리라인 생성 요청 수 / 전체 스토리라인 생성 요청 수 | 1% 이하 |
| 스토리라인 후보가 사용자 마음에 듦 | 'GOOD' 평가 수 / 전체 평가 수 | 70% 이상 |
| 스토리라인 재생성률 | 스토리라인을 다시 생성한 제작 진행 수 / 스토리라인을 생성한 제작 진행 수 | 30% 이하 |

<br>

**컴파일의 품질 지표**

| 기준 | 측정 방법 | 목표값 |
|---|---|---|
| 요청 실패율 | 실패한 컴파일 요청 수 / 전체 컴파일 요청 수 | 1% 이하 |
| 인물 이미지의 생성 실패율 | 실패한 인물 이미지 생성 수 / 시도한 인물 이미지 생성 수 | 3% 이하 |
| 썸네일의 생성 실패율 | 실패한 썸네일 생성 수 / 시도한 썸네일 생성 수 | 5% 이하 |

<br>

### 2-2-4 시간

처리 시간 상한은 백엔드가 AI 서버의 응답을 기다리는 한도이다.


| 단계 | 처리 시간 상한 | 사용자 대기 시간 목표 | 처리해야 할 동시 요청 수 |
|---|---|---|---|
| 스토리라인 생성 | 90초 | p90 30초 이하 | 10건 |
| 컴파일 | 180초 | p90 120초 이하 | 5건 |

<br>

### 2-2-5 비용

비용은 스토리라인 요청과 컴파일 요청별로 1건당 측정한다. 컴파일 비용에는 스토리 설정, 인물 이미지와 썸네일의 생성 비용을 모두 포함한다.

사용자의 이프 지불과 이용 한도는 제품 정책을 따른다. 회원은 컴파일마다 이프를 지불한다. 게스트는 스토리라인 생성과 재생성을 합쳐 최대 5회, 컴파일은 최대 1회 이용할 수 있다.

| 단계 | 항목 | 1건당 비용 상한 | 1건당 비용 측정 방법 |
|---|---|---|---|
| 스토리라인 생성 | 텍스트 비용 | $0.005 | Langfuse `스토리라인 생성` 트레이스의 총비용 |
| 컴파일 | 텍스트 비용 | $0.10 | Langfuse `스토리 컴파일` 트레이스의 텍스트 호출 비용 합 |
| 컴파일 | 인물 이미지 생성 비용 | $0.12 | Langfuse `이미지 생성:인물` 호출 비용 합 |
| 컴파일 | 썸네일 생성 비용 | $0.03 | Langfuse `이미지 생성:썸네일` 호출 비용 |
| 컴파일 | 총비용 | $0.25 | 위 세 항목의 합. Langfuse `스토리 컴파일` 트레이스의 총비용과 같음 |
