# 7-1 오류 처리

| 항목 | 값 |
|---|---|
| 적용 태스크 | 간편 제작 스토리 생성(스토리라인 생성, 컴파일, 인물 이미지와 썸네일 생성) |
| 버전 | 0.1 |

본 문서는 ([6-1 AI 실행](6-1-AI-EXECUTION.md))에서 정의한 실행을 완료하지 못했을 때의 복구 범위와 최종 실패 전달 방식을 정한다.

입력 검증, 모델 호출, 결과 검증과 이미지 생성에서 발생하는 오류를 분류하고 단계별 대응을 정한다. 재시도와 보완의 한도, 복구 후 반환할 수 있는 부분 결과, 복구하지 못한 실패의 응답과 담당자를 명시한다. 사용자에게 노출할 정보와 내부 기록도 구분한다.

<br>

### 7-1-1 오류 분류

오류가 발생한 단계에 따라 복구 방법과 최종 결과가 달라진다.

- 내용물 오류는 코드가 다시 호출하고, 전송 오류는 SDK가 재시도한다.
- 코드 결함을 전송 오류나 내용물 오류로 분류하지 않는다. 잘못 분류하면 결함의 원인을 찾기 어렵고, 불필요한 재호출 비용이 든다.
- 외부 파일이나 이미지를 가져오지 않으므로 데이터 수집 오류는 다루지 않는다.
- 결과 전송 오류는 AI 서버가 다루지 않는다. 응답은 요청을 받은 HTTP 연결로 돌려준다. 연결이 끊긴 뒤에는 전달 실패 규칙을 따른다. ([7-1-6 오류 처리](#7-1-6-전달과-노출))

| 분류 | 뜻 | 예 |
|---|---|---|
| 입력 오류 | 요청이 계약에 맞지 않음 | 필수 필드 누락, 허용하지 않는 성별 값, 인물 이름 중복 |
| 설정 오류 | 서버 설정이 잘못됐음 | 등록부에 없는 모델, 선택한 모델의 키 없음 |
| 전송 오류 | 모델의 응답을 받지 못했음 | 시간 초과, 호출량 제한, 요청 거부, 연결 실패 |
| 내용물 오류 | 응답을 받았지만 사용할 수 없음 | 빈 본문, 깨진 JSON, 후보 수 부족, 필수 항목 누락 |
| 이미지 오류 | 이미지 한 장을 만들지 못했음 | 외형 부족, 이미지 모델의 시간 초과와 거부, 디코딩 실패 |
| 관측 오류 | 기록을 남기지 못했음 | Langfuse나 Sentry 전송 실패 |
| 예상하지 못한 오류 | 위 분류에 없는 코드 결함 | 타입 실수, 처리하지 않은 예외 |

<br>

### 7-1-2 처리 기준

- 502의 메시지와 이미지 `error`의 값은 실패 계약의 표를 그대로 쓴다. ([5-4 계약](5-CONTRACT.md#5-4-실패-계약))
- 인증(401), 권한(403), 없는 경로(404)는 4xx지만 요청 거부가 아니라 `provider_unavailable`로 분류한다. 분류 기준을 바꾸면 같은 오류라도 사용자에게 보여 주는 문구가 달라진다.
- 시간 초과는 연결 오류보다 먼저 검사한다. SDK에서 시간 초과가 연결 오류의 하위 분류이기 때문이다.
- 스토리라인과 컴파일의 보완 호출에서 전송 오류가 나거나 응답이 유효하지 않으면 요청 전체를 실패로 끝낸다.
- 재호출로 복구된 실패도 Sentry에 보고한다. 요청이 성공했더라도 실패 빈도를 기록해 프롬프트와 모델 개선에 쓴다.

| 단계 | 탐지 조건 | Sentry 분류 | 외부 결과 | 복구 | 담당 |
|---|---|---|---|---|---|
| 서버 시작 | 모델, 키, 템플릿 설정이 맞지 않음 | 없음 | 서버 시작 실패 | 없음 <br> 설정을 고쳐 다시 배포 | 배포 담당 |
| 입력 검증 | 스키마 위반, 인물 이름 중복 | 없음 | 422 | 없음 | 백엔드가 요청을 고침 |
| 모델 호출 | 시간 초과 | `provider_timeout` | 502 | SDK 재시도 | SDK, 이후 백엔드 |
| 모델 호출 | 호출량 제한 | `provider_rate_limited` | 502 | SDK 재시도 | SDK, 이후 백엔드 |
| 모델 호출 | 공급자가 요청을 거부(400) | `provider_bad_request` | 502 | 없음 | AI 담당자가 원인 확인 |
| 모델 호출 | 연결 실패, 인증과 권한 오류, 5xx, 그 밖의 공급자 오류 | `provider_unavailable` | 502 | SDK 재시도 | SDK, 이후 백엔드 |
| 모델 호출 | 요청 중 설정 오류 | 분류 없이 자동 보고 | 500 | 없음 <br> 502로 바꾸지 않음 | AI 담당자 |
| 응답 검증 | 스토리라인의 형식 위반 | `invalid_ai_response` | 복구되면 200, 아니면 502 | 전체 재생성 최대 2회 | AI 서버 |
| 응답 검증 | 이름을 입력한 주변 인물이 후보에서 빠짐 | `invalid_ai_response`, 경고 수준 | 200 | 해당 후보만 최대 2회 보완 <br> 누락이 남아도 현재 결과 반환 | AI 서버 |
| 응답 검증 | 컴파일 최초 응답의 파싱 실패 | `invalid_ai_response` | 502 | 없음 | 백엔드 |
| 응답 검증 | 컴파일의 필수 블록이나 인물 필드 누락 | `invalid_ai_response` | 복구되면 200, 아니면 502 | 부분 보완 최대 2회 | AI 서버 |
| 응답 검증 | 컴파일의 엔딩이 불완전함 | 없음 | 200, 엔딩 빈 배열 | 빈 배열로 대체 <br> 추가 호출 없음 | AI 서버 |
| 후처리 | 컴파일 결과를 응답 모델로 바꿀 수 없음 | `schema_validation_failed` | 502 | 없음 | 백엔드 |
| 이미지 생성 | 외형 값이 부족함 | 없음 | 200, `appearance_missing` | 호출하지 않음 | AI 서버 |
| 이미지 생성 | 이미지 모델 오류 | 공급자 오류 분류 | 200, 이미지 `error` | SDK 재시도 | AI 서버 |
| 이미지 생성 | 이미지 로직의 예상하지 못한 오류 | `unexpected_error` | 200, 인물 이미지 빈 배열 또는 썸네일 `error` | 없음 | AI 서버 |
| 관측 | 기록 전송 실패 | 없음 | 응답에 영향 없음 | 없음 | AI 서버 |
| 전 단계 | 처리하지 않은 예외 | 분류 없이 자동 보고 | 500 | 없음 | AI 담당자 |

### 7-1-3 복구 구분

전송 오류가 나면 OpenAI 호환 SDK와 Anthropic SDK가 자동으로 재시도한다. Google 어댑터는 재시도 횟수를 따로 지정하지 않는다.

전체 재생성은 스토리라인 형식 오류에만 사용한다. 인물이 빠진 스토리라인은 해당 후보만, 컴파일은 누락된 부분만 보완한다.

| 복구 방식 | 대상 | 한도 | 4-1 반복 횟수 포함 여부 |
|---|---|---|---|
| OpenAI와 Anthropic SDK 자동 재시도 | 텍스트 모델 전송 오류 | 최대 2회 | 포함하지 않음 |
| Google SDK 자동 재시도 | 텍스트 모델 전송 오류 | 코드에서 별도 횟수를 지정하지 않음 | 포함하지 않음 |
| 스토리라인 전체 재생성 | 형식이 유효하지 않은 모델 응답 | 최대 2회 | 포함 |
| 스토리라인 부분 보완 | 이름을 입력한 주변 인물이 빠진 후보 | 최대 2회 | 포함 |
| 컴파일 부분 보완 | 필수 블록, 엔딩 또는 인물 필드 누락 | 최대 2회 | 포함 |
| 컴파일 폴백 | 보완 뒤에도 엔딩이 불완전함 | 추가 호출 없음 | 포함하지 않음 |
| 이미지 SDK 자동 재시도 | 이미지 모델 전송 오류 | 최대 2회 | 포함하지 않음 |
| 이미지 실패 처리 | 이미지 생성 실패 | 코드의 별도 재호출 없음 | 포함하지 않음 |

다음 복구 방식은 사용하지 않는다.

- 백엔드는 AI 호출을 자동으로 재시도하지 않는다.

- 폴백 모델이 없으므로 다른 모델로 바꿔 다시 호출하지 않는다.
- 전송 오류가 난 요청은 코드에서 다시 호출하지 않는다. SDK 재시도로도 복구하지 못하면 요청은 실패한다.
- 코드는 재시도 사이에 대기 시간을 두지 않는다. 대기는 SDK의 기본 동작에 맡긴다.
- 큐 없이 동기 요청으로 처리하므로 메시지를 다시 꺼내 처리하지 않는다.

<br>

### 7-1-4 단계별 시간 한도

**시간 한도의 적용 범위**

AI 서버는 요청 전체에 90초 또는 180초 제한을 두지 않는다. 최초 생성과 각 보완 호출에 제한 시간을 따로 적용한다. 따라서 전체 실행 시간이 백엔드의 응답 대기 시간을 넘을 수 있다. 백엔드가 연결을 끊어도 AI 서버는 진행 중인 모델 호출을 취소하지 않는다.

SDK는 호출을 시도할 때마다 제한 시간을 적용한다.

- 텍스트: OpenAI 호환 SDK와 Anthropic SDK는 90초 호출을 최초 시도와 재시도 2회를 합쳐 최대 270초까지 실행할 수 있다.
- 이미지: 기본 설정에서는 60초 호출을 최대 3번 시도한다. 따라서 실제 호출 시간은 60초를 넘을 수 있다.

| 단계 | 제한 시간 | 적용 범위 |
|---|---|---|
| 백엔드의 스토리라인 응답 대기 | 90초 | 스토리라인 요청 전체 |
| 백엔드의 컴파일 응답 대기 | 180초 | 컴파일 요청 전체 |
| 스토리라인 최초 생성과 형식 재생성 | 90초 | 최초 생성과 형식 재생성에 함께 적용 <br> 60초가 지나면 새 형식 재생성을 시작하지 않음 |
| 스토리라인 인물 누락 보완 | 호출마다 90초 | 후보 부분 보완 최대 2회 |
| 컴파일 최초 생성 | 90초 | 최초 모델 호출 |
| 컴파일 부분 보완 | 호출마다 90초 | 누락 부분 보완 최대 2회 |
| 이미지 생성 | 호출마다 60초 | 인물 이미지와 썸네일의 각 생성 호출 |

<br>

**요청별 호출 횟수 한도**

요청 한 건의 비용 한도는 정하지 않았다. 비용의 상한이 미정이기 때문이다. ([2-2-4 운영 요구사항](2-2-OPERATION-REQUIREMENTS.md#2-2-4-비용))

호출 수 한도가 비용의 상한 역할을 한다.

코드에서 모델을 호출하는 횟수는 요청 한 건당 다음과 같이 제한한다. SDK 재시도는 포함하지 않는다.

| 요청 | 텍스트 호출 | 이미지 호출 |
|---|---|---|
| 스토리라인 | 최초 1회, 전체 재생성 2회, 인물 보완 2회로 최대 5회 | 없음 |
| 컴파일 | 최초 1회, 부분 보완 2회로 최대 3회 | 인물 이미지 최대 5장과 썸네일 1장 |

<br>

### 7-1-5 최종 실패

AI 서버는 502를 반환한 뒤 그 요청을 다시 처리하지 않는다. 오류 안내와 재요청은 백엔드와 사용자가 맡는다.

- 빠진 필수 내용을 코드에서 지어내 정상 결과로 반환하지 않는다.
- 허용한 예외는 두 가지다. 엔딩은 빈 배열로 반환하고 이미지 실패는 200 응답의 `error`로 전달한다. 둘 다 태스크 정의의 부분 완료에 해당한다.
- 공급자가 요청을 거부했다면 같은 입력으로 다시 요청해도 거부될 수 있다. AI 담당자가 Sentry에서 원인을 확인한다.
- 결과를 미리 검수하는 사람이 없으므로 수동 검토나 보류 절차는 두지 않는다.

| 주체 | 하는 일 |
|---|---|
| AI 서버 | 502와 정해진 메시지를 반환하고 끝냄 <br> 실패한 시도를 Sentry에 보고함 |
| 백엔드 | 자동으로 다시 호출하지 않음 <br> 생성 요청을 실패로 기록하고 사용자에게 오류를 돌려줌 <br> 회원의 컴파일이 실패하면 지불한 이프를 환불함 |
| 사용자 | 다시 요청함 <br> 같은 요청 식별자로 다시 요청하면 백엔드가 실패한 요청을 다시 실행함 |

<br>

### 7-1-6 전달과 노출

**사용자 안내와 내부 진단의 분리**

422의 `detail`에는 잘못된 필드와 이유를 담는다. 백엔드가 이 정보를 받으며 사용자에게 그대로 보여 주지 않는다.

| 정보 | 응답 | Sentry | Langfuse |
|---|---|---|---|
| 정해진 한국어 실패 메시지 | 실음 | 해당 없음 | 해당 없음 |
| 오류 분류, 공급자, 모델, 프롬프트 버전, 재호출 횟수, 소요 시간 | 싣지 않음 | 실음 | 재호출 횟수와 버전만 실음 |
| 공급자 오류 원문 | 싣지 않음 | 실음 | 싣지 않음 |
| 프롬프트와 생성 결과 원문, 사용자 입력 원문 | 싣지 않음 | 싣지 않음 | 운영 조건에서만 실음 |
| API 키 | 싣지 않음 | 싣지 않음 | 싣지 않음 |

<br>

**계산 실패와 전달 실패**

AI 서버는 상태를 저장하지 않으므로 수신 확인과 재전송을 하지 않는다. 중복 방지, 결과 저장과 재요청은 백엔드가 맡는다. ([5-5 계약](5-CONTRACT.md#5-5-식별과-전달))

| 상황 | AI 서버 | 백엔드 |
|---|---|---|
| 계산 실패 | 502 또는 500을 반환함 | 실패로 기록하고 사용자에게 오류를 돌려줌 |
| 계산은 끝났는데 백엔드가 먼저 연결을 끊음 | 진행 중인 호출을 취소하지 않음 <br> 결과는 버려지고 비용은 발생함 | 시간 초과로 처리함 |
| 같은 요청을 두 번 받음 | 두 번 처리함 <br> 결과가 다를 수 있음 | 요청 식별자로 중복을 막고 결과를 저장함 |
| 사용자와 백엔드의 연결이 끊김 | 관여하지 않음 | 복구 조회로 결과를 되찾게 함 |

### 7-1-7 연결

테스트 경로는 `manyak-ai` 저장소 루트 기준이다. 기록 항목은 관측, 사례별 입력과 기대 결과는 테스트 케이스에서 정한다. ([7-3 관측](7-3-OBSERVABILITY.md), [7-2 테스트 케이스](7-2-TEST-CASES.md))

| 오류 | 관측 | 테스트 |
|---|---|---|
| 입력 오류 | 기록하지 않음 | `tests/test_request_validation.py` <br> `tests/unit/test_story_schemas.py` |
| 설정 오류 | 서버 시작 실패 로그 | `tests/unit/test_config.py`, `tests/unit/test_llm_registry.py` <br> `tests/unit/test_story_llm_faults.py`의 `test_unregistered_model_is_not_disguised_as_502` |
| 전송 오류 | Sentry 오류 보고 | `test_story_llm_faults.py`의 `test_provider_error_returns_502`, `test_provider_error_is_not_retried` <br> 어댑터별 `tests/unit/test_llm_openai_sdk.py`, `test_llm_anthropic_sdk.py`, `test_llm_google_sdk.py` |
| 내용물 오류 | Sentry 오류 보고, 응답 `meta`의 `retry_count` | `test_story_llm_faults.py`의 재호출, 재호출 횟수 소진과 제한 시간 테스트 <br> `tests/unit/test_storylines_refill.py`, `tests/unit/test_story_compile.py` |
| 인물 누락 | Sentry 경고 보고 | `tests/unit/test_storylines_characters.py` |
| 이미지 오류 | Sentry 오류 보고, Langfuse 이미지 호출 기록 | `tests/unit/test_compile_images.py`, `tests/unit/test_compile_thumbnail.py` <br> `tests/unit/test_image_generation.py` |
| 관측 오류 | 없음 | `tests/unit/test_langfuse.py`, `tests/unit/test_sentry.py` |
