# 6-5 AI 평가 구현

| 항목 | 값 |
|---|---|
| 적용 태스크 | 간편 제작 스토리 생성(스토리라인 생성, 컴파일, 인물 이미지와 썸네일 생성) |
| 버전 | 0.1 |

본 문서는 ([6-4 AI 평가 방법](6-4-AI-EVALUATION-METHOD.md))에서 정의한 평가 방법을 운영 코드와 프롬프트를 공유해 반복 실행할 소프트웨어 구조로 구체화한다.

CLI에서 평가 입력을 준비하고 운영의 생성 함수를 호출한 뒤 결과를 채점하는 절차를 정한다. 실행 설정, 동시 실행과 재시도, 중단과 재개, 결과 저장 및 재사용 방법을 구체화한다. 평가 도구의 배포 분리와 아직 결정하지 않은 구현 항목도 명시한다.

<br>

### 6-5-1 CLI 진입점

아래 명령과 파일 구조는 **구현 예정 기준**이며, 평가 CLI는 아직 구현되지 않았다. 공통 생성 함수는 현재 `manyak-ai` 코드에 있다.

CLI는 `manyak-ai` 저장소 루트에서 실행하는 Python 모듈로 만든다. 아래는 구현할 명령 형식이며, 지금 실행할 수 있는 명령은 아니다.

```text
python -m evaluation run --task storylines --dataset <입력 파일> --config <실행 설정> --output <결과 디렉터리>
python -m evaluation run --task compile --dataset <입력 파일> --config <실행 설정> --output <결과 디렉터리>
python -m evaluation resume --run <실행 디렉터리>
python -m evaluation score --run <실행 디렉터리> --config <채점 설정>
```

`run`에 `--dry-run`을 주면 입력·설정·저장 경로를 검사하고 예상 작업 수와 비용을 출력한다. 모델 API는 호출하지 않는다. 코드 평가와 LLM 채점은 `score`에서 분리해 기록한다. 사람 평가는 별도 검토 결과를 연결한다.

| 명령 | 역할 |
|---|---|
| `run` | 입력을 검증하고 새 실행 ID로 생성 결과를 저장 |
| `resume` | 기존 실행에서 끝나지 않은 작업을 같은 조건으로 재개 |
| `score` | 저장된 생성 결과를 바꾸지 않고 별도의 채점 실행으로 평가 |

<br>

**파일 구조**

다음은 새로 만들 평가 전용 패키지다. 운영 생성 코드는 `src/`에서 가져온다.

```text
evaluation/
├── __main__.py       명령과 인자 처리
├── dataset.py        입력 세트 읽기와 검증
├── runner.py         공통 서비스 호출, 동시 실행과 중단 관리
├── scoring.py        코드 평가와 LLM 채점 연결
└── records.py        실행 정보와 사례별 결과 저장·조회
```

<br>

### 6-5-2 공통 실행 코드

CLI는 요청 모델을 만들어 서비스 함수에 전달한다. 프롬프트 조립, 모델 호출, 검증, 보완과 응답 조립은 서비스가 맡는다. 평가 코드에 같은 처리를 복사하지 않는다.

- FastAPI 앱과 HTTP 라우터를 실행하지 않는다. 백엔드 저장과 화면 표시도 평가 경로에 넣지 않는다.
- 서버 시작 시 사용하는 모델·공급자 설정 검사를 CLI에서도 재사용한다. 설정이 잘못되면 유료 호출 전에 종료한다.
- 생성 모델과 호출 옵션은 모델 호출의 설정 경로를 따른다. ([6-1-5 AI 실행](6-1-AI-EXECUTION.md#6-1-5-모델-호출))

  실행 도중 전역 설정을 바꾸지 않는다. 다른 조건을 비교할 때는 별도 프로세스와 실행 ID를 쓴다.
- 현재 `compile_story`는 인물 이미지와 썸네일도 생성한다. 컴파일 실행 비용에 이미지 호출을 포함한다. 텍스트만 평가하기 위해 함수를 복제하거나 이미지 결과를 임의로 대체하지 않는다.

| 평가 단위 | 호출 함수 | 입력 | 결과 |
|---|---|---|---|
| 스토리라인 | `src.services.story_llm.generate_storylines` | `StorylinesRequest` | `StorylinesResponse` |
| 컴파일 | `src.services.story_llm.compile_story` | `StoryCompileRequest` | `StoryCompileResponse` |

<br>

### 6-5-3 데이터 처리

모델 호출 전에 입력 세트 전체를 검사한다. 잘못된 사례를 조용히 제외하고 실행하지 않는다.

위 검사는 파일을 읽어 사례별 요청을 얻은 뒤 적용하는 기준이다. 컴파일 단독 평가에서는 같은 스토리라인 입력을 유지한다.

입력은 합성 데이터를 기본으로 한다. 운영 원문을 쓰는 경우의 접근·보존·삭제 조건은 피드백과 검수를 따른다. ([6-3-2 AI 정렬](6-3-AI-ALIGNMENT.md#6-3-2-피드백과-검수))

원문 보관 방식을 정하지 않은 상태에서 운영 원문을 로컬 결과 파일로 복사하지 않는다.

| 검사 | 처리 |
|---|---|
| 세트 식별 | 이름과 버전 확인, 입력 파일 내용의 해시 기록 |
| 사례 식별 | 사례 ID의 누락과 중복 검사 |
| 요청 형식 | 스토리라인은 `StorylinesRequest`, 컴파일은 `StoryCompileRequest`로 검증 |
| 정답 분리 | 생성 모델에는 요청 필드만 전달 <br> 정답과 채점 문항은 채점 단계에서만 사용 |
| 입력 고정 | 실행을 시작한 뒤 세트를 바꾸지 않음 <br> 내용이 바뀌면 새 실행으로 처리 |

<br>

### 6-5-4 실행 관리

| 항목 | 구현 기준 |
|---|---|
| 작업 단위 | 사례 ID와 반복 번호로 구분 <br> 생성과 채점 상태는 별도로 관리 |
| 동시 실행 | 실행 설정의 한도로 제한 <br> 시간 비교 실험은 한 번에 요청 하나만 실행 |
| 반복 횟수 | 실행 설정에 명시 <br> 평가 방법에서 정하지 않은 횟수를 CLI가 임의로 선택하지 않음 |
| 재시도 | 운영 서비스와 SDK의 재시도를 재사용 <br> 평가 실행기가 같은 전송 오류를 다시 재시도하지 않음 |
| 평가용 재생성 | 평가 방법에서 정한 형식 실패 보충은 별도 시도로 기록 <br> 앞선 실패 기록을 덮어쓰지 않음 |
| 결과 저장 | 사례별 시도가 끝날 때마다 저장 <br> 전체 실행이 끝날 때까지 메모리에만 보관하지 않음 |
| 실행 잠금 | 같은 실행 디렉터리에 두 프로세스가 동시에 기록하지 못하게 함 |

참고: ([6-4 AI 평가 방법](6-4-AI-EVALUATION-METHOD.md))

<br>

**비용과 시작 전 확인**

실행 전 사례 수, 반복 횟수, 모델, 이미지 포함 여부와 예상 비용을 보여준다. 생성 비용과 LLM 채점 비용은 나누어 계산한다. 실제 유료 호출은 개선 과정의 승인 범위 안에서 실행한다. ([6-3-4 AI 정렬](6-3-AI-ALIGNMENT.md#6-3-4-개선-과정))

비용 상한값은 실행 설정으로 받는다. 누적 비용과 실행 중인 작업의 예상 비용을 확인해 다음 작업을 시작할지 결정한다. 단가나 사용량이 없어 비용을 계산할 수 없으면 0으로 보지 않고 새 작업을 중단한다. 이미 전송한 요청과 SDK 재시도 비용 때문에 설정한 상한을 넘을 수 있으므로, 이를 공급자 청구액의 절대 상한으로 표시하지 않는다.

<br>

**중단과 재개**

- 중단 요청이나 비용 상한 도달 시 새 작업을 시작하지 않는다. 진행 중인 작업은 호출 제한 시간 안에서 마무리하고 결과를 저장한다.
- 강제 종료로 완료 여부를 알 수 없는 작업은 성공이나 미실행으로 간주하지 않는다. 상태를 따로 남긴다. 같은 요청을 다시 보내면 비용이 중복될 수 있으므로 재개 전에 확인한다.
- 재개할 때 코드, 입력 세트, 프롬프트, 모델과 설정이 같은지 검사한다. 다르면 기존 실행에 이어 쓰지 않고 새 실행을 만든다.
- 완료된 작업은 재개 시 다시 실행하지 않는다. 확정된 실패를 다시 시도할 때는 별도 시도로 기록한다.

<br>

### 6-5-5 채점과 기록

생성과 채점을 별도로 저장한다. 생성에 성공했어도 채점이 없으면 미채점이며, 채점 실패를 생성 실패로 바꾸지 않는다.

재현에 필요한 설정만 기록하고 API 키와 인증 정보는 제외한다. 합성 입력으로 생성한 결과와 이미지 파일은 지정한 결과 디렉터리에 보관한다. 로그에는 실행·사례 식별자와 상태를 남기며 프롬프트 전문이나 결과 원문을 출력하지 않는다.

| 기록 단위 | 기록 내용 |
|---|---|
| 실행 | 실행 ID, 시작·종료 시각, 평가 단위, 명령 종류, 원본 실행 ID, 전체 상태 |
| 코드와 설정 | 코드 SHA, 로컬 변경 여부와 변경 내용의 해시, 프롬프트 버전·내용 해시, 모델, 공급자, 실제 호출 옵션 |
| 입력 세트 | 세트 이름·버전·내용 해시, 사례 수, 반복 횟수 |
| 생성 시도 | 사례 ID, 반복 번호, 시도 번호, 성공·실패·완료 여부 불명, 결과 위치, 소요 시간, 토큰, 비용, 오류 분류 |
| 채점 실행 | 채점 실행 ID, 원본 생성 결과 식별자, 채점 주체, 기준 버전, LLM 모델·설정, 채점 결과·실패, 시간과 비용 |
| 집계 | 예정·완료·실패·누락 건수, 계산한 지표, 미채점 항목, 품질 판정 상태 |

<br>

**결과 저장 구조**

아래는 구현할 로컬 저장 구조다.

```text
<결과 디렉터리>/<실행 ID>/
├── run.json                 실행 조건과 상태
├── cases/                   사례·반복·시도별 생성 결과와 오류
├── assets/                  생성 이미지
├── scores/                  채점 실행별 결과
└── summary.json             완료·실패·누락 집계와 평가 요약
```

파일은 임시 파일에 쓴 뒤 교체해 저장 중 강제 종료로 기존 결과가 깨지지 않게 한다. 재개 시 읽을 수 없는 결과는 완료로 집계하지 않는다.

코드 지표는 평가 방법에서 정한 기준을 따른다. ([6-4-4 AI 평가 방법](6-4-AI-EVALUATION-METHOD.md#6-4-4-코드-기반-평가))

정하지 않은 점수나 미측정 비용을 0으로 채우지 않는다.

<br>

### 6-5-6 결과 재사용

입력, 코드, 프롬프트, 생성 모델이나 호출 옵션이 바뀌면 새 생성 실험으로 구분한다. 채점 기준이나 채점 모델만 바뀌면 기존 생성 결과를 재채점할 수 있다. 서로 다른 기준의 점수를 같은 집계에 섞지 않는다.

재사용한 결과의 생성 비용과 이번에 발생한 채점 비용을 구분한다. 재채점했다고 생성 비용을 다시 청구된 비용처럼 합산하지 않는다.

| 실행 종류 | 생성 결과 | 채점 결과 | 기록 방식 |
|---|---|---|---|
| 새 생성 | 새로 생성 | 필요 시 별도 채점 | 새 실행 ID |
| 재채점 | 저장된 결과를 그대로 사용 | 새 기준이나 모델로 채점 | 새 채점 실행 ID와 원본 생성 결과 연결 |
| 중단 후 재개 | 완료된 결과 유지, 남은 작업 실행 | 완료된 채점 유지 | 기존 실행 ID와 재개 시각 기록 |

<br>

### 6-5-7 격리와 완료

평가 결과는 지정한 결과 디렉터리에만 저장한다. 백엔드의 스토리 저장 API, 사용자 알림과 운영 이미지 저장소에는 보내지 않는다. 운영용 Sentry·Langfuse 설정을 그대로 물려받지 않도록 평가 환경을 분리한다. 관측을 켤 경우 별도의 평가용 연결을 사용한다.

생성 모델과 SDK를 호출하는 데 필요한 설정은 사용하되, FastAPI 앱을 가져오면서 운영 초기화가 실행되게 하지 않는다. 평가가 끝나면 남은 파일 기록과 평가용 관측 기록을 저장하고 클라이언트 자원을 정리한다.

실행 완료를 품질 합격으로 표시하지 않는다. 합격선이나 평가 기준이 없으면 해당 항목은 판정 불가로 남긴다. CLI 종료 코드는 실행 상태를 나타내고 품질 판정은 보고서에 따로 기록한다.

| 구분 | 상태 | 뜻 |
|---|---|---|
| 실행 상태 | 완료 | 계획한 작업을 모두 처리하고 결과 저장을 마침 <br> 사례별 실패가 있을 수 있음 |
| 실행 상태 | 중단 | 사용자 요청이나 비용 한도로 멈춤 <br> 남은 작업이 있음 |
| 실행 상태 | 오류 | 설정·입력·저장 오류 등으로 실행을 계속할 수 없음 |
| 품질 판정 | 통과·미달·판정 불가 | 합격 판정에 따라 별도로 판단 ([6-4-8 AI 평가 방법](6-4-AI-EVALUATION-METHOD.md#6-4-8-합격-판정)) |


<br>

### 6-5-8 미정 항목

아래 항목은 아직 결정하지 않았다. 앞 절의 구현 계획이 정해졌더라도 이 항목의 값이나 형식을 임의로 채우지 않는다. **미정은 결정되지 않은 상태, 미구현은 결정한 기능을 아직 코드로 만들지 않은 상태**를 뜻한다.

| 항목 | 미정인 내용 | 결정 기준과 영향 |
|---|---|---|
| 연결 평가 | 컴파일에 넘길 후보 선택 규칙, 연결 평가의 CLI 옵션 | 평가 방법에서 후보 선택 규칙을 정한 뒤 CLI에 반영 |
| 이미지 평가 | 이미지 단독 평가의 호출 경계와 CLI 옵션, 컴파일에서 이미지 호출을 분리하는 방법 | 운영 이미지 생성 코드를 재사용하도록 설계 |
| 벤치마크 | 파일의 최종 형식과 정답 필드, 실제 입력 세트와 표본 수 | 평가 데이터 구성을 확정한 뒤 읽기·검증 구현 |
| 데이터 보관 | 공용 보관 위치와 접근 권한, 운영 원문을 쓸 때의 구체적인 보관 방식 | 원문 처리 조건과 평가 데이터 기준 적용 ([6-3 AI 개선](6-3-AI-ALIGNMENT.md)) |
| 실행 설정 | 설정 파일의 구체적인 형식, 일반 실험의 동시 실행 수·반복 횟수·비용 상한값 | 실행 전에 명시 <br> 시간 비교 실험의 동시 실행 수는 1로 정해져 있음 |
| LLM 채점 | 채점 문항·모델·설정과 채점 결과의 상세 형식 | 6-4 확정 후 채점 코드에 반영 |
| 사람 평가 | 세부 평가 기준·점수 척도·입력 양식, LLM 판정과 비교할 방법·표본 수 | 6-4 확정 후 검토 결과 연결 방식에 반영 |
| 합격 판정 | 품질·비용 합격선과 이를 적용할 판정 로직 | 6-4 확정 후 구현 <br> 실행 완료와 품질 합격은 계속 구분 |
| 종료 코드 | 완료·중단·오류에 대응하는 숫자 | CLI 구현 시 지정 <br> 품질 판정은 별도로 기록 |
