# QA Sheet

이 디렉터리는 **수동 QA와 E2E 테스트 설계의 기준이 되는 화면·기능별 QA 케이스**를 담습니다. 유저 스토리([`2-user-stories.md`](../product-specs/2-user-stories.md))와 화면 스펙의 검수 기준([`3-1-client.md`](../product-specs/3-1-client.md))을 씨앗으로 삼아, 실제 구현(`../manyak-web` dev 브랜치)에서 확인한 동작으로 케이스를 전개·보강합니다. 별도 유스케이스 문서는 만들지 않으며, 각 케이스가 US-x-y ID를 직접 참조합니다.

| 항목      | 값                                                                    |
| --------- | --------------------------------------------------------------------- |
| 기준 코드 | `manyak-web` dev 브랜치 HEAD                                          |
| 대상      | 마냑 웹 프론트엔드                                                    |
| 작성 목적 | 릴리스 전 수동 QA 체크리스트 제공, E2E 테스트 케이스 설계의 원천 문서 |

## 문서 목록

| 문서                               | 화면                                           | 상태   |
| ---------------------------------- | ---------------------------------------------- | ------ |
| [`chats.md`](./chats.md)           | 채팅 목록 · 채팅 화면 · 공유 열람              | 작성됨 |
| [`stories.md`](./stories.md)       | 스토리 목록 · 상세 · 생성 퍼널                 | 작성됨 |
| [`auth.md`](./auth.md)             | 로그인 · 세션 · 데이터 이관 · 로그아웃         | 작성됨 |
| [`my.md`](./my.md)                 | 마이 · 회원 탈퇴 · 피드백 · 초대 · 서비스 안내 · 하단 탭 | 작성됨 |
| [`onboarding.md`](./onboarding.md) | 게스트 온보딩 · 신규 가입 초대 코드 다이얼로그 | 작성됨 |
| [`legal.md`](./legal.md)           | 약관 · 개인정보 처리방침                       | 작성됨 |

여러 문서에 걸치는 기능은 한 문서가 케이스를 소유하고 나머지는 참조 스텁을 둡니다(예: 신규 가입 초대 코드 다이얼로그 → `onboarding.md`).

## 케이스 표 읽는 법

각 케이스는 다음 컬럼으로 구성합니다.

| 컬럼      | 의미                                                                                                             |
| --------- | ---------------------------------------------------------------------------------------------------------------- |
| ID        | `{도메인}-{섹션}-{번호}` 형식의 고유 ID. 섹션 내 추가는 뒤 번호를 이어 붙이고, 삭제된 번호는 재사용하지 않습니다 |
| P         | 우선순위. 아래 기준 참고                                                                                         |
| 사전조건  | 케이스 실행 전 준비 상태(세션·로컬 데이터·서버 응답 등)                                                          |
| 절차      | 사용자가 수행하는 행동                                                                                           |
| 기대 결과 | 확인해야 하는 화면·데이터 동작                                                                                   |
| 자동화    | `✅ e2e {스펙 경로}` = 자동화됨, `◐` = 일부만 자동화, `수동` = 사람 확인 필요                                    |
| 근거      | 참조 유저 스토리(US-x-y)·스펙 섹션(§)                                                                            |

### 우선순위 기준

| P   | 기준                                                        | 릴리스 전             |
| --- | ----------------------------------------------------------- | --------------------- |
| P0  | 핵심 플레이 경로가 끊기거나 사용자 데이터가 손실되는 케이스 | 반드시 확인           |
| P1  | 주요 기능·에러 안내가 어긋나 사용성이 크게 떨어지는 케이스  | 시간이 허락하면 확인  |
| P2  | 엣지 케이스·표시 품질. 어긋나도 우회 가능한 케이스          | 회귀 의심 영역만 확인 |

### 크로스커팅 항목

다크 모드·인앱 브라우저·레이아웃 러버밴드 같은 화면 공통 관심사는 도메인 QA 문서의 케이스로 두지 않습니다. 다만 다크 모드는 `manyak-web`의 비주얼 회귀 스펙이 대표 화면 4장(채팅방·스토리 목록·스토리 상세·마이 회원)을 고정해 시맨틱 토큰 회귀를 감지합니다. 나머지 화면의 다크 모드는 여전히 수동 확인 대상입니다.

### ⚠️ 확인 필요

케이스 작성 중 스펙과 구현이 어긋나거나 의도가 불분명한 동작은 각 문서 하단의 "확인 필요" 섹션에 모읍니다. 이 항목들은 **현재 동작의 기록이지 정답 명세가 아니므로**, 팀 확인 후 스펙 반영 또는 수정 이슈로 전환합니다.

## 유지보수 규칙

- 화면 동작을 바꾸는 PR은 해당 도메인 QA 문서의 케이스를 함께 갱신합니다(추가·수정·삭제).
- E2E 스펙을 추가하면 대응 케이스의 자동화 컬럼을 갱신합니다.
- 기준 코드는 dev HEAD입니다. 릴리스 QA 시점에는 릴리스 브랜치에 포함되지 않은 케이스(문서 내 `미배포` 표기)를 건너뜁니다.
