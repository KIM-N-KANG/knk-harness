## MY-MENU — 마이 메뉴 `/my`

게스트/회원 분기는 next-auth 세션 상태(`useSession`)로 판정하고, 회원의 닉네임·프로필 이미지·크레딧 잔액·출석 여부는 `GET /auth/me` 응답(`nickname`·`profileThumbnailBase64`·`creditBalance`·`attendedToday`)을 진입마다 재조회해 사용합니다. 메뉴 섹션은 이벤트(친구 초대, 회원 전용) / 화면(테마 변경, 공통) / 기타(서비스 안내 `미배포`·피드백, 공통) / 계정(로그아웃, 회원 전용)으로 구성됩니다.

## ⚠️ 확인 필요

작성 중 스펙과 구현이 어긋나거나 판단이 필요한 항목입니다. 팀 확인 후 스펙 갱신 또는 수정 이슈로 전환합니다.

1. **스펙 라벨 드리프트 — 서비스 안내.** `3-frontend.md`는 FE-SCREEN-011과 `/my/about` 라우트를 `계획`(Phase 미배정)으로 라벨링하지만, #72로 dev에 구현되어 있습니다(`미배포`). §3-1 구현 상태 라벨 표·§3-3 라우팅 테이블·FE-SCREEN-008/010/011의 `계획` 표기 갱신이 필요합니다.
2. **출석 체크 API 라벨 드리프트.** §3-8은 `POST /users/me/credits/attendance`를 `Phase 1 · 계획`으로 라벨링하지만 dev에 구현되어 있고 v0.2.2에도 포함되어 있습니다(MY-MENU-09~12). 또한 잔액·출석 여부 조회는 `GET /users/me/credits`가 아니라 `GET /auth/me` 응답(`creditBalance`·`attendedToday`)을 사용합니다 — §3-8 화면별 API 표의 갱신이 필요합니다.
3. **소모량 사전 고지(US-10-3) 미구현.** 마이 크레딧 카드와 각 소모 지점(스토리 완성 CTA·채팅 전송)에 소모량·게스트 잔여 체험 횟수 표시가 없어(`Phase 1 · 계획` 유지) 이 문서의 QA 범위에서 제외했습니다. 단 서비스 안내 페이지(`미배포`)가 크레딧·한도 수치를 먼저 고지하게 되므로, 사전 고지 구현 시 두 화면의 수치 정합(MY-INFO-02·03)을 함께 확인해야 합니다.
4. **뒤로가기 헤더 폴백 비일관.** `/my/about`만 히스토리가 없을 때 `/my`로 폴백하는 `fallbackHref`를 지정하고, `/my/feedback`·`/my/invite`는 `router.back()`만 호출합니다. URL 직접 진입(공유 링크 등) 후 뒤로가기가 동작하지 않을 수 있어 의도인지 확인이 필요합니다.
5. **US-8-1 문구 드리프트.** 유저 스토리는 "홈·채팅·피드백 화면을 빠르게 오가고 싶다"이지만 현재 탭은 홈·채팅·마이입니다(§3-3에는 피드백의 마이 이동이 반영됨). 유저 스토리 문구 갱신이 필요합니다.
