## AUTH-SESSION — BFF 토큰 세션·세션 만료

## AUTH-MIGRATE — 게스트 데이터 자동 이관

로그인 성공 직후 루트 레이아웃의 감시 컴포넌트가 `localStorage`의 스토리·채팅 ID 배열을 `POST /auth/migrate`로 사용자 확인 없이 제출합니다. 서버가 항목을 실제로 평가한 응답(MIGRATED·ALREADY_OWNED·CONFLICT·NOT_FOUND)에서는 제출한 ID를 로컬에서 제거하지만(회원 서재는 서버 정본), 이관 잠금(`migrationClosed` — 계정당 1회, 서버 계약 B15) 응답은 어떤 항목도 평가하지 않으므로 로컬 ID를 유지합니다 — 리소스는 `user_id` NULL로 살아 있고 로컬 ID가 유일한 접근 수단이라, 지우면 로그아웃 후에도 게스트 서재를 복원할 수 없습니다.

## AUTH-ONBOARD — 신규 가입 온보딩(초대 코드 다이얼로그)

신규 가입 첫 로그인 직후의 초대 코드 다이얼로그 케이스는 [`onboarding.md`](./onboarding.md)의 ONBD-INVITE 섹션이 소유합니다. 로그인·가입 흐름 QA 시 해당 섹션을 함께 확인하세요.

## ⚠️ 확인 필요

작성 중 스펙과 구현이 어긋나거나 판단이 필요한 항목입니다. 팀 확인 후 스펙 갱신 또는 수정 이슈로 전환합니다.

1. **스펙 라벨 드리프트 — 회원 모드 데이터 소스·재로그인 안내.** FE-SCREEN-008 "회원 모드 데이터 소스"와 §3-8 검수 기준의 "재발급 실패 시 재로그인 안내"는 `Phase 1 · 계획` 라벨이지만, dev에는 둘 다 구현되어 있습니다(회원 목록은 `GET /users/me/stories`·`/users/me/chats` 사용 — e2e `chats/chat-list`·`stories/story-list`로 확인, 세션 만료 시 `/login?expired` 이동 + 만료 토스트 — AUTH-SESSION-04). 스펙 본문의 "현재는 로그인 후에도 게스트 배치 조회를 그대로 사용" 서술과 §3-1 라벨 표의 갱신이 필요합니다.
2. **로그인·온보딩 문구 드리프트.** 스펙이 따옴표로 인용한 문구와 구현 문자열이 다릅니다 — 이관 1회 안내(스펙 "로그인하면 이 기기에서 만든 스토리·채팅이 계정으로 자동 이관됩니다. …" ↔ 구현 "처음 로그인하면 이 기기의 스토리와 채팅이 계정에 저장돼요 / 이 과정은 계정당 한 번만 진행돼요"), 약관 고지 어미(스펙 "간주합니다" ↔ 구현 "간주해요"), 온보딩 스킵 버튼(스펙 "건너뛰기" ↔ 구현 "나중에 하기"). 이 문서의 기대 결과는 구현 문자열을 기준으로 썼으며, 정본 확정 후 스펙 또는 구현의 갱신이 필요합니다.
3. **로그인 성공 복귀 경로.** 스펙(FE-SCREEN-008 완료 피드백)은 "홈으로 이동"만 정의하지만, 구현은 `callbackUrl` 쿼리가 있으면 원래 화면으로 복귀합니다(AUTH-LOGIN-07 — 게스트 한도 다이얼로그 진입 경로에서 사용, 오픈 리다이렉트 가드 포함). 의도된 확장으로 보이나 스펙 반영이 필요합니다.
4. **회원 상태에서 `/login` 진입 가드 없음.** 로그인된 회원이 `/login`에 직접 진입하면 리다이렉트 없이 로그인 화면이 그대로 표시되고 Google 버튼도 동작합니다(재로그인 시도 가능). 스펙에 정의가 없어 의도(허용/홈 리다이렉트)를 확인하기 전까지 케이스로 굳히지 않았습니다.
