## AUTH-MIGRATE — 게스트 데이터 자동 이관

로그인 성공 직후 루트 레이아웃의 감시 컴포넌트가 `localStorage`의 스토리·채팅 ID 배열을 `POST /auth/migrate`로 사용자 확인 없이 제출합니다. 서버가 항목을 실제로 평가한 응답(MIGRATED·ALREADY_OWNED·CONFLICT·NOT_FOUND)에서는 제출한 ID를 로컬에서 제거하지만(회원 서재는 서버 정본), 이관 잠금(`migrationClosed` — 계정당 1회, 서버 계약 B15) 응답은 어떤 항목도 평가하지 않으므로 로컬 ID를 유지합니다 — 리소스는 `user_id` NULL로 살아 있고 로컬 ID가 유일한 접근 수단이라, 지우면 로그아웃 후에도 게스트 서재를 복원할 수 없습니다.

## AUTH-HANDOFF — 인앱 게스트 허용·로그인 핸드오프

SNS 인앱 브라우저(카카오톡·인스타그램·쓰레드)에서 전면 차단을 제거해 게스트 기능을 그대로 허용하고, **로그인 시점에만** 서버 핸드오프를 거쳐 외부 브라우저로 전환합니다(§3-10). 인앱에서 로그인을 누르면(카카오톡 인앱의 카카오 버튼은 예외 — 핸드오프 없이 인앱에서 직접 로그인, AUTH-HANDOFF-13) 게스트 스토리·채팅 로컬 ID로 핸드오프를 생성(`POST /auth/handoffs`)하고 현재 주소를 `/login/continue?handoff=`로 바꿔 외부 전환을 시도합니다. 외부 브라우저 랜딩은 코드를 HttpOnly 쿠키로 옮긴 뒤(`X-Manyak-Handoff-Code` 헤더 계약, §4-3-5) `handoffCode`를 실은 로그인 한 번으로 회원 체험 시드와 게스트 데이터 이관을 원자 처리합니다. 인앱으로 돌아오면 상태 조회로 **실제 이관된 ID만** 로컬에서 차감하며, 인앱 웹뷰는 리마운트 없이 복귀하는 경우가 많아 문서가 다시 보일 때마다 재확인합니다. 핸드오프 코드는 비밀값이라 로그·분석 이벤트에 남기지 않습니다(분석은 `handoff_id`만). 인앱 안내 화면은 외부 전환에 주소를 넘겨야 해 코드를 URL에 유지하므로, 그 노출 경로를 막는 장치를 함께 둡니다 — 분석 전송 직전 URL 프로퍼티의 코드 치환, 랜딩 응답의 `no-referrer`·`no-store`, 수령 BFF의 동일 출처 JSON 요청 강제(CSRF 차단).

2. **로그인·온보딩 문구 드리프트.** 스펙이 따옴표로 인용한 문구와 구현 문자열이 다릅니다 — 이관 1회 안내(스펙 "로그인하면 이 기기에서 만든 스토리·채팅이 계정으로 자동 이관됩니다. …" ↔ 구현 "처음 로그인하면 이 기기의 스토리와 채팅이 계정에 저장돼요 / 이 과정은 계정당 한 번만 진행돼요"), 약관 고지 어미(스펙 "간주합니다" ↔ 구현 "간주해요"). 온보딩 스킵 버튼 드리프트(스펙 "건너뛰기" ↔ 구현 "나중에 하기")는 KNK-715에서 신규 가입 초대 다이얼로그에 "나중에 하기" 버튼을 추가하고 스펙 문구를 구현에 맞춰 해소했습니다. 이 문서의 기대 결과는 구현 문자열을 기준으로 썼으며, 정본 확정 후 스펙 또는 구현의 갱신이 필요합니다.
3. **로그인 성공 복귀 경로.** 스펙(FE-SCREEN-008 완료 피드백)은 "홈으로 이동"만 정의하지만, 구현은 `callbackUrl` 쿼리가 있으면 원래 화면으로 복귀합니다(AUTH-LOGIN-07 — 게스트 한도 다이얼로그 진입 경로에서 사용, 오픈 리다이렉트 가드 포함). 의도된 확장으로 보이나 스펙 반영이 필요합니다.
4. **회원 상태에서 `/login` 진입 가드 없음.** 로그인된 회원이 `/login`에 직접 진입하면 리다이렉트 없이 로그인 화면이 그대로 표시되고 Google 버튼도 동작합니다(재로그인 시도 가능). 스펙에 정의가 없어 의도(허용/홈 리다이렉트)를 확인하기 전까지 케이스로 굳히지 않았습니다.
