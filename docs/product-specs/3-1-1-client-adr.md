```text
기록 규칙
결정 목록
C-001~C-005  결정별 맥락·선택·이유·영향
```

### 읽는 순서

- **처음 보는 사람** — 기록 규칙을 읽고, 결정 목록에서 관련 주제의 기록으로 이동합니다. 문서 작성일·수정일은 개별 결정일과 구분합니다.
- **구현자** — [현재 스펙](./3-1-client-spec.md)과 해당 설계를 먼저 확인하고, 선택 이유가 필요한 지점의 ADR을 읽습니다. 과거 기록을 현재 동작의 기준으로 사용하지 않습니다.
- **리뷰·변경 작성자** — 관련 결정과 후속 대체 관계를 함께 확인합니다. 확정된 본문은 보존하고 새 기록에 대체하는 ID·범위를 남깁니다.

## 기록 규칙

- 이 파일 하나에 결정을 추가합니다. 식별자 `C-NNN`은 재사용·재번호하지 않습니다. 새 기록은 아래에 추가하고 제목·목록에서 찾습니다.
- 작성 중 상태는 Proposed, 확정 시 Accepted 또는 Rejected입니다. 확정된 기록의 당시 상태·본문은 보존합니다. 결정 변경·폐기는 새 기록에서 이전 ID와 대체 범위를 명시합니다.
- 현재 효력은 후속 기록의 대체 관계로 판단합니다. 일부 변경이면 부분 대체로 표시하고 나머지 결정까지 폐기하지 않습니다. 목록의 효력 표기는 이 관계의 요약일 뿐 별도 정본이 아닙니다.
- 공통 결정을 구체화하는 플랫폼 ADR은 공통 ID를 참조합니다. 플랫폼 방식 선택만으로 공통 계약을 대체하지 않습니다.
- 한 절은 독립적으로 바꿀 수 있는 결정 하나를 다룹니다. 전체 구현 설명·진행 일지·Jira 상태를 누적하지 않습니다.
- 아래 과거 기록의 이관일은 2026-09-09입니다. 기준 커밋의 원문에 확인되는 선택과 근거만 요약했습니다. 날짜가 없는 기록은 미상으로 남겼으며 번호로 과거 결정 순서를 추정하지 않습니다. 당시 사실과 현재 코드가 다를 수 있습니다.

## C-001. 인물 이미지를 수신 위치에 즉시 표시

- 결정일: 원문 미기재 · 기록 확정 상태: Accepted
- 근거: [이관 원문 C:965](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-1-client.md#L965-L999)
- **맥락:** 인물 이미지가 스트리밍 도중 도착하지만 완료 이벤트에서 한꺼번에 표시하는 선택지가 있었습니다.
- **결정:** `character_image`는 수신 위치에 즉시 표시하고 저장된 턴은 마커로 복원합니다.
- **이유:** 완료까지 기다리면 이미지가 한꺼번에 나타나 읽는 위치와 순서가 바뀝니다.
- **주요 영향:** 진행 중 조각과 확정 본문은 같은 순서를 유지하고 오류 후에도 수신된 이미지를 임의로 재배치하지 않습니다.

<a id="c-002"></a>

## C-002. 오리지널 카드 메타를 두 줄로 표시

- 결정일: 2026-08-24 · 기록 확정 상태: Accepted
- 근거: [이관 원문 C:197](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-1-client.md#L197-L201)
- **맥락:** 오리지널 카드에 플레이 규모를 보여 주는 세 번째 줄을 검토했습니다.
- **결정:** 제목·제작자 두 줄을 사용하고 턴 수·좋아요 수는 썸네일 배지에 둡니다.
- **이유:** 응답에는 채팅 수가 없고 턴 수를 별도 줄에 두면 같은 수치가 중복됩니다.
- **주요 영향:** 플레이 횟수와 누적 턴 수를 같은 지표로 부르지 않습니다.

<a id="c-003"></a>

## C-003. 이프 수치는 서버 정책에서 표시

- 결정일: 2026-09-01 · 기록 확정 상태: Accepted
- 근거: [이관 원문 C:696](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-1-client.md#L696-L706), [이관 원문 C:1213](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-1-client.md#L1213-L1223)
- **맥락:** 화면에 복제한 이프 수치가 운영 정책 변경과 어긋날 수 있었습니다.
- **결정:** 사용 지점은 서버 정책값을 표시하고 서비스 안내에는 이프 적립·소모 수치를 모아 두지 않습니다.
- **이유:** 서버와 여러 화면에 같은 수치를 수동 관리하지 않기 위해서입니다.
- **주요 영향:** 조회 전·실패 시 확정된 기본값 대신 자리표시를 사용합니다.

## C-004. 편집 초안과 완성 요청의 생명주기 분리

- 결정일: 2026-09-08 · 기록 확정 상태: Accepted
- 근거: [이관 원문 C:841](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-1-client.md#L841-L867), [이관 원문 A:1575](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-3-android-app.md#L1575-L1618)
- **맥락:** 단일 편집 슬롯과 완료 대기는 여러 완성 요청과 새 편집을 함께 표현하기 어렵습니다.
- **결정:** 편집 초안 한 개와 requestId별 완성 요청을 분리하고 저장 후 제작 탭으로 복귀합니다.
- **이유:** 완성 대기 중에도 다음 제작을 시작하고 초안 폐기와 요청 결과가 서로 영향을 주지 않도록 하기 위해서입니다.
- **주요 영향:** 자동 채팅 생성이 사라지고 플랫폼별 저장·실행·분석 연결의 전환이 필요합니다. 웹 적용 시점과 잠정 실패 UX는 이 결정의 승인 범위를 넘겨 추정하지 않습니다.

<a id="c-005"></a>

## C-005. 클라이언트 문서의 책임과 수명 분리

- 결정일: 2026-09-09 · 기록 확정 상태: Accepted
- 관계·승인 근거: 이 기록은 문서 작성·상태 정본 규칙을 대체합니다. 근거: KNK-1236 작업 대화에서 사용자가 구조와 전체 갱신을 승인했습니다.
- 근거: [이관 원문 C:83](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-1-client.md#L83-L141)
- **맥락:** 현재 계약, 설계, 결정 이유, 일회성 작업과 상태가 세 클라이언트 문서에 혼재했습니다.
- **결정:** 공통 스펙·ADR, 웹 스펙·설계·ADR, Android 스펙·설계·ADR의 8개 문서를 같은 product-specs 폴더에 둡니다. ADR은 영역별 한 파일에 누적합니다.
- **이유:** 문서 수를 기능마다 늘리지 않으면서 규범·현재 구조·과거 이유·진행 정보를 구분하기 위해서입니다.
- **주요 영향:** 스펙에는 Phase·구현 표시·Jira·작업 순서를 넣지 않습니다. 기능 계획·기존 QA를 재사용하고 추적은 별도 인덱스에 연결합니다.
