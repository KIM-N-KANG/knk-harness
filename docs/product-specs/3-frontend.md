## 3-1. 문서 목적·범위와 관련 문서

### 목적

이 문서는 마냑 웹 프론트엔드 개발자가 화면, 라우팅, 상태 관리, API 연동, 검수 기준을 구현하는 기준입니다. 프론트엔드는 이 문서를 기준으로 구현하고, QA는 이 문서를 기준으로 검수합니다.

### 범위

- 화면 구조, 라우팅, 공통 셸과 네비게이션
- 스토리 생성 퍼널과 채팅 SSE 스트리밍
- 게스트(익명) 데이터 모델과 클라이언트 상태 관리
- API 연동 방식(프록시, 헤더, 상태 코드 분기, 에러 처리)
- UI 상태(로딩, 빈 상태, 에러), 입력 검증
- 컴포넌트 기준, 반응형·접근성, 관측 연동
- 테스트·검수 기준, 배포·환경 변수

### 제외 범위

- 백엔드 내부 구현과 API 상세 스키마 (원천: [`4-backend.md`](./4-backend.md))
- AI 요청·응답 계약과 프롬프트 (원천: [`5-ai-server.md`](./5-ai-server.md))
- 이벤트 카탈로그, 식별자 정책, 지표 (원천: [`6-analytics.md`](./6-analytics.md))
- 로그인, 스토리 탐색, 좋아요·댓글·공유, 일반·전문가 제작 모드, 크레딧, 관리자 (MVP 제외, [§3-20](#3-20-mvp-제외-범위와-스펙-구현-간극))

- 화면과 흐름에 US ID와 e2e 스펙을 연결합니다.

> React Compiler를 사용하므로 `useMemo`, `useCallback`을 직접 작성하지 않습니다. `<form onSubmit>` 핸들러는 `SubmitEvent<HTMLFormElement>`를 사용합니다.

### 아키텍처 5대 특징

이 앱을 규정하는 축입니다. 일반적인 인증형 대시보드 SPA와 다른 지점이며, 각 항목은 지정한 섹션에서 상세합니다.

| # | 특징 | 요지 | 상세 |
| --- | --- | --- | --- |
| 1 | 전원 게스트(익명) | 로그인·회원가입·권한이 없습니다. 사용자 식별은 Amplitude `device_id`뿐입니다. | [§3-15](#3-15-인증세션-현황과-향후) |
| 2 | BFF 프록시 | 브라우저는 백엔드를 직접 호출하지 않고 `/api/[...path]`가 `API_BASE_URL`로 전달합니다. | [§3-10](#3-10-api-연동-계약) |
| 3 | 게스트 데이터 모델 | "내 스토리·채팅"은 `localStorage`의 공개 ID 배열을 `POST /…/batch`로 재조회해 구성합니다. | [§3-9](#3-9-게스트-데이터-모델) |
| 4 | 생성 퍼널 | `/stories/new` 단일 라우트에서 로컬 상태로 4단계를 전환합니다. | [§3-7](#3-7-스토리-생성-퍼널-심화) |
| 5 | 채팅 SSE 스트리밍 | `fetch`+`ReadableStream`으로 AI 응답을 토큰 단위로 스트리밍합니다. | [§3-8](#3-8-채팅-플레이와-sse-스트리밍-심화) |

### 요청 흐름 개요

```text
브라우저 (컴포넌트 → TanStack Query 훅 → customInstance 뮤테이터)
   │  요청 경로를 /api/* 로 재작성, X-Manyak-* 헤더 주입
   ▼
Next.js 라우트 핸들러  src/app/api/[...path]/route.ts   (서버 전용, force-dynamic)
   │  host 헤더 제거, API_BASE_URL 로 그대로 전달, cache: no-store
   ▼
백엔드 API (API_BASE_URL)   — 스키마 원천은 4-backend.md
```

`API_BASE_URL`은 `NEXT_PUBLIC_` 접두사가 없는 서버 전용 변수라 클라이언트 번들에 노출되지 않습니다. 브라우저는 항상 동일 출처의 `/api`만 호출합니다.

### 디렉터리 구조

```text
src/
├── app/                 App Router (라우트·레이아웃·에러·프록시)
│   ├── (main)/          홈·채팅목록·피드백 (헤더+하단탭 chrome)
│   ├── (story)/         스토리 상세·생성 (chrome 없음)
│   ├── (chat)/          채팅방 (chrome 없음)
│   └── api/[...path]/   BFF 프록시 라우트 핸들러
├── api/                 Orval 생성 코드(generated) + 요청 뮤테이터(mutator)
├── features/            도메인 기능 모듈 (stories, chats, feedback, onboarding)
├── components/          공용 컴포넌트 (ui, common, layout, providers)
├── hooks/               공용 훅
├── lib/                 유틸 (fetch, query-client, analytics, monitoring, format)
└── constants/           앱 경로·네비게이션·토스트 상수
```

## 3-3. 라우팅·레이아웃·화면 목록

| `/` | FE-SCREEN-001 | `(main)` | 스토리 목록(홈) | 헤더 + 하단탭 | 불필요(게스트) |

### 라우팅 규칙

- **접근 제어가 없습니다.** 모든 경로는 인증 없이 접근 가능합니다. 가드·미들웨어·리다이렉트가 존재하지 않습니다.
- **라우트 그룹은 권한이 아니라 chrome을 가릅니다.** `(main)`은 상단 헤더와 하단 탭을 두르는 탭 화면, `(story)`·`(chat)`은 헤더·하단탭이 없는 전체 화면입니다.
- 존재하지 않는 경로는 Not Found 화면을 표시하고 홈(`/`)으로 돌아가는 링크를 제공합니다.

### 화면 전환 규칙

`replace`와 `push`의 선택이 히스토리 동작을 결정하므로 규칙을 고정합니다. 모든 경로는 `APP_PATH` 상수(`src/constants/app-path.ts`)를 사용합니다.

| 출발 → 도착 | 트리거 | 방식 | 근거 |
| --- | --- | --- | --- |
| 스토리 카드 → 상세 | 카드 탭 | `Link` | — |
| 목록 FAB·빈 상태 → 퍼널 | 탭 | `Link` | — |
| 상세 CTA → 채팅방 | "채팅 시작하기" | `router.replace` | 뒤로가기로 재진입해 채팅 중복 생성 방지 |
| 퍼널 완료 → 채팅방 | 스토리·채팅 생성 완료 | `router.replace` | 동상 |
| 채팅방 뒤로 | 헤더 back | `router.push('/chats')` | 진입 경로와 무관하게 채팅 목록으로 복귀 |
| 상세 뒤로 | 헤더 back | `router.back()` | 히스토리 기반 복귀 |
| 스토리 삭제(상세) | 삭제 성공 | `router.replace('/')` | 삭제된 상세로 되돌아오지 않도록 |
| 하단 탭 이동 | 탭 클릭 | `Link replace` | 탭 전환을 히스토리에 쌓지 않음 |
| 온보딩 CTA → 퍼널 | "첫 스토리 만들기" | `router.push` | — |

### 레이아웃 구조

- **루트 레이아웃**(`src/app/layout.tsx`) — 유일하게 프로바이더를 두는 레이아웃입니다. 중첩 순서는 바깥→안 `AmplitudeProvider → QueryProvider → MotionProvider → ThemeProvider`이며, 전역 `Toaster`(sonner)를 포함합니다. 콘텐츠를 `mx-auto w-full max-w-md h-svh flex-col overflow-hidden` 모바일 셸로 감쌉니다. `lang="ko"`, Pretendard·MaruBuri 폰트, 뷰포트 `viewportFit: cover`를 설정합니다.
- **`(main)` 레이아웃**(`src/app/(main)/layout.tsx`) — 상단 `MainHeader`, 스크롤 콘텐츠 영역, 하단 `BottomNavigationBar`, `OnboardingDialog`를 렌더합니다. 스크롤 상태는 `MainScrollProvider`로 공유해 헤더 보더와 FAB 라벨 축소에 사용합니다.
- **`(story)`·`(chat)` 그룹** — 레이아웃 파일이 없습니다. 루트 레이아웃만 상속하며, 각 화면이 자체 헤더(`StoryDetailHeader`, `ChatRoomHeader`, `StoryCreateHeader`)를 렌더합니다.

| P0 | MVP 출시에 반드시 필요한 화면 |

## 3-4. 공통 셸과 네비게이션

탭 화면 3개가 공유하는 뼈대입니다. 화면별로 반복하지 않도록 한 곳에 모읍니다.

### 모바일 셸

- 루트 레이아웃이 콘텐츠를 `max-w-md`(중앙 정렬) × `h-svh`(전체 뷰포트 높이) 단일 컬럼으로 고정합니다.
- 뷰포트는 `width=device-width`, `viewportFit=cover`(노치 대응), `interactiveWidget=resizes-content`(키보드 대응)입니다.
- 하단 고정 요소는 `env(safe-area-inset-bottom)`로 안전 영역을 확보합니다.
- 다크 모드는 OS 설정을 따르며 인앱 토글은 없습니다([§3-16](#3-16-반응형접근성브라우저-지원)).

### 상단 헤더 (`MainHeader`)

- `(main)` 화면에서만 표시하는 고정 헤더(`h-14`)입니다. 로고와 현재 섹션 라벨을 표시합니다.
- 섹션 라벨은 `getMainNavigationLabel(pathname)`로 결정하며, 탭이 아닌 경로에서는 빈 문자열을 반환합니다.
- 스크롤이 발생한 뒤에만 하단 보더를 표시합니다.

### 하단 네비게이션 (`BottomNavigationBar`)

- `(main)` 그룹에서만 노출하는 고정 3탭입니다. 소스는 `MAIN_NAVIGATION_ITEMS`(`src/constants/main-navigation.ts`)입니다.

| 순서 | 라벨 | 경로 | `APP_PATH` | 아이콘 |
| --- | --- | --- | --- | --- |
| 1 | 스토리 | `/` | `MAIN.STORIES` | `ClipboardIcon` |
| 2 | 채팅 | `/chats` | `MAIN.CHATS` | `Chatting01Icon` |
| 3 | 피드백 | `/feedback` | `MAIN.FEEDBACK` | `MailEdit01Icon` |

### 검수 기준

- 하단 탭으로 스토리·채팅·피드백을 오갈 수 있어야 합니다. (US-8-1, e2e `smoke/navigation`)

- 모바일 안전 영역에서 하단 탭과 고정 CTA가 잘리지 않아야 합니다.

| 화면 ID | 테스트·이슈·PR 참조 |
| 경로·라우트 그룹 | 라우팅과 chrome 결정 |

## 3-6. 핵심 사용자 흐름

화면을 연결하는 MVP 핵심 흐름입니다. 개별 화면 스펙([§3-5](#3-5-화면별-상세-스펙))과 US ID를 잇습니다.

| 흐름 ID | 이름 | 관련 US | 우선순위 |
| --- | --- | --- | --- |
| FLOW-001 | 첫 방문 온보딩 | US-2-5, US-8-3 | P0 |
| FLOW-002 | 스토리 생성 | US-3 | P0 |
| FLOW-003 | 스토리 탐색 → 플레이 시작 | US-2-1·2, US-4-1·2 | P0 |
| FLOW-004 | 채팅 플레이(턴 진행·스트리밍) | US-6 | P0 |
| FLOW-005 | 채팅 이어가기 | US-5-1·2 | P0 |
| FLOW-006 | 스토리·채팅 삭제 | US-2-4, US-4-3, US-5-3 | P0 |
| FLOW-007 | 피드백 제출 | US-7 | P0 |
| FLOW-008 | 잘못된 경로 접근 | — | P0 |

### FLOW-001. 첫 방문 온보딩

1. 처음 온 사용자가 `/`에 진입합니다.
2. 저장된 스토리·채팅이 0이고 온보딩 미열람이면 온보딩 다이얼로그가 표시됩니다.
3. "첫 스토리 만들기"를 누르면 온보딩 열람을 저장하고 `/stories/new`로 이동합니다.

**완료 기준** — 최초 1회만 표시되고, 이후 재노출되지 않아야 합니다.

### FLOW-002. 스토리 생성

1. FAB 또는 온보딩 CTA로 `/stories/new`에 진입합니다.
2. 키워드 선택 → 스토리라인 생성·선택 → 추가 정보 입력 → 완성을 진행합니다.
3. 스토리와 채팅이 생성되면 채팅방으로 `replace` 이동합니다.

**예외** — 생성·완성 실패 시 해당 단계에 인라인 오류를 표시하고 입력을 유지합니다(상세 [§3-7](#3-7-스토리-생성-퍼널-심화)).

**완료 기준** — 완성 직후 채팅방에 진입해야 합니다. (US-3-13)

### FLOW-003. 스토리 탐색 → 플레이 시작

1. 홈에서 스토리 카드를 선택해 상세로 이동합니다.
2. 설정을 확인하고 "채팅 시작하기"를 누릅니다.
3. 채팅이 생성되고 채팅방으로 `replace` 이동합니다.

**예외** — 채팅 생성 실패 시 "채팅 시작에 실패했어요" 토스트를 표시하고 상세에 머무릅니다.

### FLOW-004. 채팅 플레이 (턴 진행·스트리밍)

1. 채팅방에서 프롤로그와 이전 대화를 읽습니다.
2. 입력창에 텍스트를 적거나 추천 선택지를 눌러 전송합니다.
3. AI 응답이 토큰 단위로 스트리밍되어 화면에 누적됩니다.
4. 응답이 완료되면 상세를 다시 불러와 확정된 턴과 새 선택지를 표시합니다.

**예외** — 스트리밍 실패 시 "응답 생성에 실패했어요" 토스트를 표시하고 낙관적 입력 버블을 제거합니다. 자동 재시도는 없습니다(상세 [§3-8](#3-8-채팅-플레이와-sse-스트리밍-심화)).

### FLOW-005. 채팅 이어가기

1. 하단 탭 "채팅"에서 진행 중 채팅 목록을 확인합니다.
2. 채팅 카드를 눌러 채팅방으로 이동합니다.
3. 이전 이력을 확인하고 FLOW-004로 대화를 이어갑니다.

### FLOW-006. 스토리·채팅 삭제

1. 카드 또는 상세의 옵션 메뉴에서 "삭제하기"를 선택합니다.
2. 확인 다이얼로그("삭제하면 목록에서 사라지며 되돌릴 수 없어요")에서 확정합니다.
3. 로컬 목록에서 즉시 제거(낙관적)한 뒤 삭제 API를 호출합니다.

**예외** — 404는 이미 삭제된 것으로 간주해 성공 처리합니다. 그 외 오류는 로컬 목록을 롤백하고 실패 토스트를 표시합니다.

### FLOW-007. 피드백 제출

1. 하단 탭 "피드백"에서 본문(필수)과 이메일(선택)을 입력합니다.
2. 제출하면 성공 토스트 후 폼이 초기화됩니다.

**예외** — 실패 시 실패 토스트를 표시하고 입력값을 유지합니다.

### FLOW-008. 잘못된 경로 접근

1. 존재하지 않는 경로에 접근하면 Not Found 화면("페이지를 찾을 수 없어요")을 표시합니다.
2. "홈으로 돌아가기"로 `/`로 이동합니다.

## 3-7. 스토리 생성 퍼널 심화

FE-SCREEN-002의 상세입니다. `/stories/new` 단일 라우트에서 로컬 상태로 4단계를 전환합니다. URL 쿼리로 단계를 표현하지 않습니다.

### 단계 구성

단계 순서는 `keyword → storyline-select → additional-info → complete`입니다. 진행 표시기는 앞의 3단계만 노출하고 `complete`는 종료 로딩 상태입니다.

| # | 단계 | 목적 | 진행(다음) 조건 |
| --- | --- | --- | --- |
| 1 | 키워드 선택 | 장르·주인공·주변 인물 키워드 수집 | 장르 1개 이상 **그리고** 주인공 1개 이상 |
| 2 | 스토리라인 선택 | AI 생성 스토리라인 3개 중 택1(선택·재생성·평가) | 활성 스토리라인 선택 완료 |
| 3 | 추가 정보 입력 | 추천 태그·자유 텍스트로 디테일 보강 | 숫자형 `simpleCreationId`와 선택 스토리라인 `id` 존재 |
| 4 | 완료 | 스토리·채팅 생성 | (종료) 성공 시 채팅방으로 `replace` |

### 상태 모델

- 오케스트레이터 훅(`useStoryCreateFunnel`)이 로컬 상태로 `step`, 생성 요청·결과, 활성 인덱스, 선택 스토리라인, 생성된 스토리 ID를 보유합니다. 상태 머신 라이브러리나 URL은 사용하지 않습니다.
- 키워드 선택 상태는 별도 훅(`useTagSelection`)이 카테고리별 3개 레코드(선택 태그 ID·선택 커스텀 ID·커스텀 키워드 객체)로 관리합니다. 키워드 단계를 벗어나면 언마운트됩니다.
- 단계 간에는 원본 선택 상태가 아니라 **빌드된 생성 요청**(`{selectedTagIds, customTags}`)만 상위로 전달됩니다.

### 키워드 선택 규칙

| 카테고리 | 라벨 | 필수 | 최대 선택 |
| --- | --- | --- | --- |
| GENRE | 장르 | 예 | 3 |
| PROTAGONIST | 주인공 특징 | 예 | 3 |
| SUPPORTING_CHARACTER | 주변 인물 특징 | 아니오 | 5 |

- 태그 목록은 `GET /stories/simple/tags`로 조회하며, 로딩 시 스켈레톤 칩을 표시합니다.
- 최대 선택 수에 도달하면 미선택 칩과 "키워드 추가" 트리거를 비활성화합니다(선택·커스텀 합산 기준).
- 커스텀 키워드는 "키워드 추가" 다이얼로그로 입력합니다. 클라이언트 최대 15자(서버 스키마는 30자), 공백 제거 후 빈 값은 무시, IME 조합 중 Enter는 제출하지 않습니다.
- 카테고리 탭은 앞선 필수 카테고리가 완료되어야 잠금 해제됩니다.

### 스토리라인 생성·평가

- **생성** — `POST /stories/simple/storylines {selectedTagIds, customTags}`. 요청과 동시에 `storyline-select` 단계로 전환해 로딩을 그 자리에 표시합니다. 응답은 스토리라인 3개(`{id, story, recommendedInfos[3]}`)와 `simpleCreationId`를 포함합니다. 로딩 중에는 타자기형 문구와 15초·30초 시점 힌트를 표시합니다.
- **재생성** — "다시 만들기"는 저장된 생성 요청을 재호출합니다. 생성 요청 이벤트는 최초 1회만 발화하고 재생성 시에는 발화하지 않습니다.
- **평가** — 스토리라인별 좋아요·별로예요를 토글합니다. 300ms 디바운스 후 `PUT`(설정)·`DELETE`(해제) `/stories/simple/storylines/{id}/rating`으로 동기화합니다. 동일 평가를 다시 누르면 해제됩니다. 실패 시 상태를 되돌리고 실패 토스트를 표시합니다. **평가는 보조 신호이며 완성 페이로드에 포함되지 않고 진행을 막지 않습니다.**

### 완성(finalize)

추가 정보는 `[선택한 추천 태그 텍스트, ...공백 제거한 자유 텍스트]`로 구성합니다. 완성은 두 경로로 나뉩니다.

1. **최초 완성** — `POST /stories/simple {simpleCreationId, storylineId, additionalInfos}` → 성공 시 스토리 ID를 `localStorage`·상태·ref에 저장 → `POST /chats {storyId}` → 성공 시 채팅 ID 저장·완료 이벤트·상세 prefetch·완료 토스트 후 채팅방으로 `replace`.
2. **재시도** — 스토리가 이미 생성된 경우(저장된 스토리 ID 존재) 스토리 생성을 건너뛰고 저장된 `storyId`로 채팅 생성만 재호출합니다.

이 분기로 완성 재시도 시 스토리가 중복 생성되지 않습니다. 클라이언트 ID(`create-client-id`)는 React 리스트 key 용도이며 API로 전송하지 않습니다.

### 예외와 이탈 가드

| 상황 | 처리 |
| --- | --- |
| 태그 로드 실패 | "키워드를 불러오지 못했어요" 인라인 오류 |
| 생성·재생성 실패 | 스토리라인 선택 단계에 인라인 오류, "다시 만들기"로 재시도 |
| 생성 결과 0개 | "생성된 스토리라인이 없어요" 안내 |
| 완성 실패(스토리·채팅) | `additional-info` 단계로 복귀 + "스토리를 완성하지 못했어요" 오류, 스토리라인·`creationId` 유지 |
| 완성 로딩 | "스토리를 만들고 있어요" 전체 화면 + 15·30·60초 힌트 |
| 이탈 시도(키워드 이후) | 확인 다이얼로그("스토리를 그만 만들까요? 지금 나가면 만들고 있는 내용이 사라져요") |

- 이탈 가드는 키워드 단계를 제외한 모든 단계에서 활성입니다.
- 새로고침·탭 닫기·URL 이동은 `beforeunload`로, 브라우저·모바일 뒤로가기는 더미 히스토리 엔트리를 재삽입하는 `popstate` 트래핑으로 잡아 커스텀 다이얼로그를 띄웁니다. 확정 시 더미와 현재 페이지를 건너뛰어 퍼널 진입 전 화면으로 복귀합니다.

### 관측(발화 이벤트)

이벤트 정의·프로퍼티는 [`6-analytics.md`](./6-analytics.md)를 따릅니다. 발화 지점만 정리합니다.

### 검수 기준

- 키워드 → 스토리라인 → 추가정보 → 완성 시 채팅방으로 이동해야 합니다. (US-3, e2e `stories/story-create`)
- 필수 카테고리 미충족 시 생성 버튼이 비활성화되어야 합니다.
- 완성 실패 시 입력을 유지한 채 재시도할 수 있어야 하며, 재시도가 스토리를 중복 생성하지 않아야 합니다.
- 키워드 이후 단계에서 뒤로가기 시 이탈 확인 다이얼로그가 떠야 합니다.

## 3-8. 채팅 플레이와 SSE 스트리밍 심화

FE-SCREEN-005의 상세입니다. 실시간 AI 응답이 이 앱에서 가장 복잡한 경로이므로 스트리밍 계약과 렌더 규칙을 명확히 정의합니다.

### 턴 모델

- 채팅은 스토리 상세 또는 퍼널 완료에서 `POST /chats {storyId}`로 생성됩니다. 채팅 목록에서는 생성하지 않습니다.
- **턴** = 사용자 입력 + AI 출력 + 다음 선택지입니다. 사용자 입력과 AI 출력은 응답이 완료될 때 한 턴으로 저장됩니다.
- 채팅방은 `GET /chats/{id}`로 `storyTitle`, `prologue`, `turns[]`, `suggestedInputs[]`를 조회합니다.
- 렌더 순서: 헤더 높이만큼의 스페이서 → 프롤로그 버블 → 각 턴(사용자 버블 → AI 버블) → 진행 중 스트리밍 블록.
- 선택지는 **마지막 턴에만** 표시합니다. 턴이 0개면 시작 화면의 `suggestedInputs`를 선택지로 표시합니다.

### SSE 스트리밍 아키텍처

`EventSource`는 POST를 못 하므로 `fetch`+`ReadableStream`으로 직접 구현합니다. 3계층입니다.

1. **전송** — `POST /api/v1/chats/{id}/turns/stream`, 헤더 `Content-Type: application/json` · `Accept: text/event-stream` · `X-Manyak-*`(식별자), 본문 `{userInput}`(최대 3000자). 응답 `ReadableStream`을 반환합니다.
2. **파서** — `AsyncGenerator`로 스트림을 읽어 `\r\n`을 정규화하고 SSE 레코드 구분자 `\n\n`로 분할해 이벤트를 방출합니다.
3. **React 훅** — `streamingTurn {userInput, output}` 상태를 두고, 이벤트에 따라 갱신합니다.

**이벤트 계약** (원천: [`5-ai-server.md`](./5-ai-server.md))

| 이벤트 | 데이터 필드 | 프론트 처리 |
| --- | --- | --- |
| `started` | — | 수신만(무동작) |
| `token` | `text` | `output`에 누적(부분 렌더) |
| `completed` | `aiOutput` | 상세 refetch로 확정 턴 반영 후 스트리밍 블록 제거 |
| `error` | `message` | 예외 발생 → 실패 토스트 |

- `token`은 `data: {"text":"..."}`(JSON) 또는 원문 텍스트를 모두 허용합니다.
- `completed` 수신 시 누적한 `output`은 버리고 상세 재조회 결과(서버 확정본)를 표시합니다. 완료 후 채팅 목록 배치 쿼리를 무효화해 미리보기·시각을 갱신합니다.
- 프록시 라우트는 응답 본문을 그대로 스트리밍 전달(`Response(response.body)`, `cache: no-store`)하므로 SSE 청크가 버퍼링되지 않습니다.
- **주의**: 스트리밍 경로는 공용 뮤테이터를 우회하므로 120초 클라이언트 타임아웃이 적용되지 않습니다. 긴 생성이 클라이언트에서 강제 종료되지 않습니다([§3-20](#3-20-mvp-제외-범위와-스펙-구현-간극)).

### 입력창과 선택지

- **입력창** — 자동 높이 확장 텍스트에어리어(최대 `20dvh`), placeholder "이야기를 어떻게 이어갈까요?". 전송 가능 조건은 공백 제거 후 1자 이상이고 비활성 상태가 아닐 때입니다. `Enter`(Shift 없이, IME 조합 아님) 또는 폼 제출로 전송합니다.
- **선택지** — 각 선택지에 "채우기"(입력창에 채워 편집) 버튼과 "전송"(바로 제출) 버튼을 둡니다. 선택지 텍스트도 강조 마크업으로 렌더합니다.
- **강조 삽입** — "상황 추가" 버튼이 선택 영역을 `*...*`로 감쌉니다.
- **전송 잠금(다중 방어)** — 스트리밍 중에는 컴포저 핸들러가 조기 종료하고, 입력창·버튼이 비활성화되며, 전송 가능 조건이 거짓이 됩니다.

### 렌더와 스크롤

- **부분 렌더** — 토큰이 누적되는 동안 AI 버블에 실시간으로 텍스트를 표시하고, 첫 토큰 전에는 스트림 로딩 표시("답변을 작성하고 있어요")를 노출합니다.
- **강조 마크업** — `**볼드**`는 굵게, `*...*`는 서술·독백 강조(보조 색)로 렌더합니다.
- **하단 고정 스크롤** — 하단 64px 이내이면 새 콘텐츠에 맞춰 자동으로 따라갑니다. 사용자가 위로 스크롤하면 고정이 해제되어 토큰이 누적돼도 화면이 끌려 내려가지 않습니다. 입력창이 커지면(리사이즈) 다시 고정합니다. 턴이 0개로 시작한 방은 프롤로그가 보이도록 상단에서 시작합니다.
- **헤더 show/hide** — 상단 8px 이내면 표시, 아래로 스크롤하면 숨김, 위로 스크롤하면 표시합니다. 숨김 시 `aria-hidden`·`inert`를 적용합니다. 헤더 back은 브라우저 뒤로가기가 아니라 `/chats`로 이동합니다.

### 예외 처리

| 상황 | 처리 |
| --- | --- |
| 방 이탈·언마운트 | 진행 중 스트림을 abort. abort는 조용히 종료(토스트 없음) |
| 네트워크 실패(스트림 중) | 실패 토스트 + 낙관적 입력 버블 제거. 자동 재시도 없음 |
| 서버 `error` 이벤트 | `message` 또는 기본 문구로 실패 토스트 |
| 상세 로드 실패 | `RetryListStatus` "채팅을 불러오지 못했어요" + 다시 시도 |
| 재진입 | 서버 재개 스트림은 없음. 상세를 다시 조회해 완료된 턴만 표시 |

### 검수 기준

- 프롤로그와 추천 입력을 표시해야 합니다. (US-6-1)
- 메시지를 전송하면 응답이 스트리밍되어 누적되어야 합니다. (US-6-2·6-3)
- 추천 입력의 수정 버튼은 입력창을 채우고, 본문 탭은 바로 전송해야 합니다. (US-6-4)
- 스트리밍이 실패하면 오류 안내가 떠야 합니다. (US-6-8, e2e `chats/chat-room`)

## 3-9. 게스트 데이터 모델

로그인이 없으므로 "내 스토리·채팅"은 서버의 사용자 소유 목록이 아니라 **브라우저가 보관한 공개 ID 배열**로 구성합니다. 이 앱의 최대 차별점이자 제품 리스크의 근원이라 별도 섹션으로 정의합니다. 식별자 정책은 [`6-analytics.md §6-2`](./6-analytics.md)를 따릅니다.

### 저장 구조

| 키 | 내용 | 형식 |
| --- | --- | --- |
| `manyak:created-story-ids` | 생성한 스토리의 공개 ID | JSON 문자열 배열, 최신순 |
| `manyak:created-chat-ids` | 생성한 채팅의 공개 ID | JSON 문자열 배열, 최신순 |
| `manyak:onboarding-seen` | 온보딩 열람 여부 | `'1'` |

- 공통 팩토리(`createCreatedIdListStorage`)가 두 목록의 로직을 동일하게 제공합니다.
- **상한 100개**. 저장 시 맨 앞에 추가하고 중복을 제거한 뒤 100개로 자릅니다. 101번째를 만들면 가장 오래된 ID가 로컬 목록에서 밀려납니다(서버 레코드는 유지).
- 파싱은 방어적입니다. JSON이 아니거나 배열이 아니면 `[]`를 반환하고 유효하지 않은 항목을 걸러냅니다.
- 모든 쓰기는 `window`가 없을 때(SSR) no-op입니다.

### React 연동과 SSR 3-state

- `useSyncExternalStore`로 스토어를 구독합니다. 서버 스냅샷은 Symbol sentinel을 반환하고, 훅은 이를 `null`로 매핑합니다.
- 상태는 3가지로 구분합니다: `null`(SSR·미하이드레이션, 알 수 없음) / `[]`(하이드레이션됨, 비어 있음) / `string[]`(데이터). 이 구분으로 하이드레이션 직후 빈 상태가 깜빡이는 문제를 막습니다.
- 로딩 판정: `ids == null || (ids.length > 0 && query.isPending)`.

### 배치 재조회

- 스토리: `POST /api/v1/stories/batch {storyIds}`, 채팅: `POST /api/v1/chats/batch {chatIds}`. ID가 비어 있으면 요청하지 않습니다(`enabled` 게이트).
- 배열이 커질 수 있어 `GET`이 아닌 `POST` 본문으로 전달합니다. 서버 스키마 상한도 100입니다.
- **정렬 기준이 목록마다 다릅니다.** 스토리 목록은 로컬 저장 순서(최신 생성순)로 재정렬하고, 채팅 목록은 서버 응답 순서(최근 활동순)를 유지합니다.
- 서버가 반환하지 않은 ID(삭제됨 등)는 목록에서 조용히 제외됩니다.

### 쓰기·삭제

- **쓰기** — 스토리 생성 성공 시 스토리 ID, 채팅 생성 성공 시 채팅 ID를 저장합니다.
- **삭제(낙관적)** — 현재 ID를 스냅샷한 뒤 로컬에서 먼저 제거하고 삭제 API를 호출합니다. 404는 성공으로 간주하고, 그 외 오류는 로컬 목록을 롤백하고 실패 토스트를 표시합니다.
- **동기화** — 같은 탭은 커스텀 이벤트로, 다른 탭은 `storage` 이벤트로 목록이 즉시 갱신됩니다.

### 한계와 리스크

| 한계 | 영향 |
| --- | --- |
| 기기·브라우저 종속 | 다른 기기·브라우저에서 내 서재가 보이지 않음 |
| 스토리지 삭제 시 소실 | 사이트 데이터 삭제·시크릿 모드·ITP 제거 시 서재가 비어 보임(서버 레코드는 남아 접근 불가) |
| 상한 100 | 101번째 생성 시 오래된 항목이 서재에서 밀려남 |
| 복구·공유 불가 | 잃어버린 ID를 되찾거나 다른 사용자와 공유할 수 없음 |

온보딩 다이얼로그의 알파 고지("이 브라우저에만 저장")는 이 한계를 사용자에게 알리는 장치입니다. 향후 로그인 도입 시 서재 이관 전략이 필요합니다([§3-15](#3-15-인증세션-현황과-향후)).

## 3-10. API 연동 계약

API 상세 명세의 원천은 [`4-backend.md`](./4-backend.md)입니다. 여기서는 프론트엔드가 어떻게 호출하고 무엇에 의존하며 실패를 어떻게 처리하는지 정의합니다.

### BFF 프록시

- 브라우저는 항상 동일 출처 `/api/*`만 호출합니다. `src/app/api/[...path]/route.ts`(서버 전용, `force-dynamic`, Node 런타임)가 `API_BASE_URL`로 전달합니다.
- 프록시는 `host` 헤더를 제거하고 나머지 헤더(식별자 포함)를 그대로 전달하며, `cache: no-store`로 요청합니다. `API_BASE_URL`이 없으면 500을 반환합니다.
- 모든 HTTP 메서드(GET/HEAD/POST/PUT/PATCH/DELETE)를 단일 핸들러가 처리합니다.

### 요청 인스턴스와 헤더

- 데이터 요청은 Orval 뮤테이터(`customInstance`)를 통해 나갑니다. 응답은 `{data, status, headers}` 형태라 호출부는 HTTP 상태로 분기합니다(예: `response.status === 200 ? response.data : []`).
- 모든 요청에 익명 식별 헤더를 주입합니다. 값·정책은 [`6-analytics.md §6-6-2`](./6-analytics.md)를 따릅니다.

| 헤더 | 필수 | 값 |
| --- | --- | --- |
| `X-Manyak-Device-Id` | 필수 | Amplitude `device_id` |
| `X-Manyak-Session-Id` | 필수 | Amplitude `session_id` |
| `X-Manyak-Request-Id` | 권장 | 요청 단위 ID(없으면 백엔드 생성) |

- 요청에 인증 토큰(`Authorization`)은 붙지 않습니다([§3-15](#3-15-인증세션-현황과-향후)).
- 데이터 요청 타임아웃은 120초입니다. 단, 채팅 스트리밍은 이 경로를 우회하므로 클라이언트 타임아웃이 없습니다([§3-8](#3-8-채팅-플레이와-sse-스트리밍-심화)).

### 화면별 API 사용

| 화면 | API | 호출 시점 | 성공 처리 | 실패 처리 |
| --- | --- | --- | --- | --- |
| 스토리 목록 | `POST /stories/batch` | 저장 ID 하이드레이션 후 | 로컬 순서로 재정렬 표시 | 재시도 상태 |
| 스토리 상세 | `GET /stories/{id}` | 진입 | 본문 표시 | 인라인 오류 + 재시도 |
| 스토리 상세 | `POST /chats` | "채팅 시작하기" | 채팅 ID 저장·prefetch·채팅방 `replace` | "채팅 시작에 실패했어요" 토스트 |
| 채팅 목록 | `POST /chats/batch` | 진입 | 서버 순서 유지 표시 | 재시도 상태 |
| 채팅방 | `GET /chats/{id}` | 진입·완료 후 refetch | 프롤로그·턴 표시 | 재시도 상태 |
| 채팅방 | `POST /chats/{id}/turns/stream` | 전송·선택지 | 토큰 누적 → 완료 시 refetch | 실패 토스트 |
| 퍼널 | `GET·POST /stories/simple/*` | [§3-7](#3-7-스토리-생성-퍼널-심화) 참조 | 단계 전환 | 인라인 오류 |
| 피드백 | `POST /feedbacks` | 제출 | 성공 토스트 + 초기화 | 실패 토스트 + 값 유지 |
| 삭제(공통) | `DELETE /stories/{id}` · `DELETE /chats/{id}` | 옵션 메뉴 확인 | 완료 토스트 | 404=성공, 그 외 롤백 + 토스트 |

### 에러 형태와 처리 정책

- 백엔드 에러는 `ApiErrorResponse {timestamp, status, code, message, path, details[]}` 형태이며 `details`는 `{field, message}[]`입니다. 클라이언트는 이 본문을 파싱해 오류 객체에 보관합니다.
- TanStack Query 기본값: `retry: false`, `staleTime: 60초`, `gcTime: 5분`, `refetchOnWindowFocus: false`, `throwOnError: false`. 오류를 던지지 않고 상태로 반환하므로 컴포넌트가 인라인 처리합니다.
- HTTP 상태 계열별 정책은 [§3-12](#3-12-ui-상태로딩빈에러-처리)의 에러 표를 따릅니다. 서버 원본 메시지·스택은 사용자에게 그대로 노출하지 않습니다.

## 3-11. 클라이언트 상태 관리 기준

상태의 저장 위치를 구분해 구현 복잡도를 낮춥니다. 이 앱은 전역 상태 라이브러리(예: Zustand)를 사용하지 않습니다.

| 상태 유형 | 예시 | 저장 위치 | 도구 |
| --- | --- | --- | --- |
| 서버 상태 | 스토리·채팅 상세, 배치 목록 | 쿼리 캐시 | TanStack Query |
| 게스트 서재 | 생성한 스토리·채팅 ID | `localStorage` 외부 스토어 | `useSyncExternalStore` |
| URL 상태 | 스토리·채팅 ID | 라우트 파라미터 | App Router `[id]` |
| 퍼널 상태 | 단계·선택 키워드·선택 스토리라인 | 로컬 컴포넌트 상태 | 오케스트레이터 훅 |
| 폼 상태 | 피드백·채팅 입력값 | 로컬 컴포넌트 상태 | `useState` |
| 영속 UI 플래그 | 온보딩 열람 | `localStorage` | 온보딩 스토어 |

### 원칙

- 서버에서 가져온 데이터는 서버 상태로 관리하고, 완료·삭제 후 관련 쿼리를 무효화·refetch합니다.
- 게스트 서재는 `localStorage` 외부 스토어로 관리하며 SSR 3-state를 구분합니다([§3-9](#3-9-게스트-데이터-모델)).
- 퍼널 단계는 URL이 아니라 로컬 상태로 관리합니다(단일 라우트).
- 민감 정보·토큰을 `localStorage`에 저장하지 않습니다(현재 토큰 자체가 없음).
- React Compiler를 사용하므로 `useMemo`·`useCallback`을 직접 작성하지 않습니다.

## 3-12. UI 상태·로딩·빈·에러 처리

정상 상태보다 예외 상태 처리에서 품질이 갈립니다. 공통 프리미티브로 일관성을 확보합니다.

### 공통 상태 프리미티브

| 프리미티브 | 용도 |
| --- | --- |
| `ListStatus` | 중앙 정렬 빈/상태 블록(제목·설명·CTA 슬롯) |
| `RetryListStatus` | `ListStatus` + "다시 시도" 버튼(목록 레벨 에러 표준) |
| `Skeleton` | 로딩 자리 표시(`animate-pulse`) |
| `Spinner` | 인라인 진행 표시(`role=status`) |
| `useDelayedLoading` | 지연 100ms 후 스켈레톤 표시, 최소 300ms 유지(깜빡임 방지) |

### 로딩 처리

| 상황 | 처리 |
| --- | --- |
| 목록·상세 최초 로딩 | `useDelayedLoading`으로 게이트한 스켈레톤. 지연 전에는 아무것도 표시하지 않음 |
| 버튼 클릭 후 요청 중 | 버튼 비활성화 + `Spinner`(예: 삭제 확인, "채팅 시작하는 중...") |
| 채팅 스트림 첫 토큰 전 | 스트림 로딩 표시("답변을 작성하고 있어요") |
| 스토리 생성·완성 중 | 전체 화면 로딩 + 타이머형 힌트([§3-7](#3-7-스토리-생성-퍼널-심화)) |

### 빈 상태 처리

| 화면 | 문구 | 액션 |
| --- | --- | --- |
| 스토리 목록 | "아직 만든 스토리가 없어요" | "스토리 만들기" |
| 채팅 목록 | "아직 진행중인 채팅이 없어요" | 스토리 유무에 따라 목록 또는 생성으로 안내 |

### 에러 처리

| 계열 | 조건 | UI |
| --- | --- | --- |
| 네트워크·목록 조회 실패 | 요청 실패 | `RetryListStatus` + 다시 시도 |
| 뮤테이션 실패 | 생성·삭제·전송 실패 | 토스트(토스트 카탈로그) |
| 라우트·렌더 오류 | 세그먼트 오류 | `error.tsx` → "문제가 발생했어요" + 재시도 |
| 루트 오류 | 최상위 오류 | `global-error.tsx` → Sentry 보고 + 재시도 화면 |
| 리소스 없음 | 존재하지 않는 경로 | `not-found.tsx` → "페이지를 찾을 수 없어요" + 홈 링크 |

### 에러 메시지 원칙

- 서버 원본 오류·스택을 그대로 노출하지 않고 사용자 친화 문구로 변환합니다.
- 사용자가 복구할 수 있는 오류(재시도 가능)는 재시도 수단을 함께 제공합니다.
- 인증 만료 개념이 없으므로 401 전용 리다이렉트 처리는 하지 않습니다([§3-15](#3-15-인증세션-현황과-향후)).

## 3-13. 입력·폼과 검증 규칙

이 앱의 입력은 피드백·키워드·추가 정보·채팅 입력입니다. 로그인·회원가입 폼은 없습니다.

### 피드백 폼

| 필드 | 타입 | 필수 | 제약 | 비고 |
| --- | --- | --- | --- | --- |
| body | textarea | 예 | 최대 500자(초과 입력 차단), 글자 수 카운터 | 서버 스키마 상한은 2000자 |
| email | email | 아니오 | 최대 320자 | 미입력 시 `null` 전송 |

- 제출 가능 조건: `body`의 공백 제거 후 길이 ≥ 1. 이메일은 필수가 아닙니다.
- `platform`은 UI에서 수집하지 않고 `WEB`으로 고정 전송합니다.
- 제출 중에는 입력·버튼을 비활성화합니다.

### 키워드·커스텀 키워드 (퍼널)

- 카테고리별 최대 선택: 장르 3, 주인공 3, 주변 인물 5. 상한 도달 시 미선택 칩·추가 트리거 비활성화.
- 커스텀 키워드: 클라이언트 최대 15자, 공백 제거 후 빈 값 무시, IME 조합 중 Enter 미제출.
- 생성 가능 조건: 장르 1개 이상 그리고 주인공 1개 이상([§3-7](#3-7-스토리-생성-퍼널-심화)).

### 추가 정보 (퍼널)

- 추천 태그 토글 + 자유 텍스트 행(추가·삭제). 자유 텍스트는 공백 제거 후 비어 있지 않은 값만 전송합니다.

### 채팅 입력

- 최대 3000자. 전송 가능 조건: 공백 제거 후 1자 이상이고 스트리밍 중이 아닐 때.
- `Enter`(Shift 없이, IME 조합 아님) 또는 폼 제출로 전송. "상황 추가"로 선택 영역을 `*...*` 강조로 감쌉니다.

### 검증 표시 원칙

- 필드 단위 오류는 해당 필드 근처에, 폼·요청 단위 오류는 토스트로 표시합니다.
- 컴포넌트는 `aria-invalid`와 `FieldError`(`role=alert`)로 오류를 노출합니다([§3-14](#3-14-컴포넌트디자인-시스템-기준)).
- 비밀번호·토큰 등 민감 입력은 없으며, 자유 입력 원문은 로그·이벤트에 수집하지 않습니다([`6-analytics.md §6-7`](./6-analytics.md)).

## 3-14. 컴포넌트·디자인 시스템 기준

### 기반

- UI 컴포넌트는 Base UI 프리미티브 위에 shadcn 스타일로 감싼 래퍼입니다. 변형은 CVA로 정의하고 `cn()`(clsx + tailwind-merge)으로 병합합니다.
- 각 컴포넌트는 `data-slot` 속성을 부여합니다. 색상은 테마 토큰(`--primary`, `--destructive`, `--muted` 등)으로 구동합니다.
- 드로어는 vaul, 토스트는 sonner, 애니메이션은 motion을 사용합니다.

### 공용 컴포넌트

| `Input`·`Textarea` | 입력 | focus 링, `disabled`, `aria-invalid`; Textarea 자동 높이 |

- `components/common`: `ListStatus`, `RetryListStatus`, `OptionsMenu`(삭제 + 확인 다이얼로그), `TextContent`(강조·서체 파싱).
- `components/layout`: `MainHeader`, `BottomNavigationBar`([§3-4](#3-4-공통-셸과-네비게이션)).

### 작성 원칙

- 공통 UI는 재사용 컴포넌트로 만들고 화면 고유 로직을 넣지 않습니다.
- 비동기 상태는 `loading`·`disabled`·`error`를 명확히 분리합니다(공통 규약: `disabled:opacity-50 disabled:pointer-events-none`, `aria-invalid` 링, `focus-visible` 링).
- 접근성 속성(`aria-*`, label 연결, focus 이동)을 고려합니다([§3-16](#3-16-반응형접근성브라우저-지원)).

## 3-15. 인증·세션 현황과 향후

### 현황: 인증 없음(전원 게스트)

- MVP는 로그인이 없는 익명 서비스입니다. 사용자 식별은 Amplitude `device_id`뿐이며, 프론트엔드에 인증 토큰·세션·가드·리다이렉트가 없습니다.
- 요청에 `Authorization` 헤더를 붙이지 않고, 401을 특별 처리하지 않습니다(일반 오류로 취급).
- Google 로그인·`/me`·토큰 갱신·로그아웃 API는 Orval이 생성했으나 **현재 어디서도 호출하지 않는 미사용 코드**입니다. 생성 모델의 사용자 상태(`ACTIVE`·`SUSPENDED`·`DELETED`)도 UI에서 사용하지 않습니다.

### 보안 원칙

- 사용자 입력값은 화면 출력 시 안전하게 렌더링합니다.
- 민감 정보를 URL 쿼리·`localStorage`·로그에 저장하지 않습니다.
- 브라우저 저장 데이터(게스트 서재)는 공개 식별자만 담습니다.

### 향후 로그인 도입 시 고려

- 익명 서재(로컬 ID 목록)를 로그인 계정으로 이관하는 전략이 필요합니다([§3-9](#3-9-게스트-데이터-모델)).
- `device_id`를 유지하고 로그인 시점부터 `user_id`를 연결합니다([`6-analytics.md §6-2`](./6-analytics.md)).
- 이때 이 섹션과 라우팅·상태 관리 섹션을 갱신합니다.

## 3-16. 반응형·접근성·브라우저 지원

### 반응형: 모바일 전용

- 레이아웃은 `max-w-md` 단일 컬럼으로 고정한 모바일 전용입니다. 데스크톱 다단 레이아웃을 제공하지 않습니다.
- e2e는 Mobile Chrome(Pixel 5) 단일 프로젝트로 실행합니다.
- 안전 영역(`env(safe-area-inset-bottom)`)과 `viewportFit: cover`를 사용합니다.

### 모바일 검수 기준

- 주요 CTA가 첫 화면에서 확인 가능해야 합니다.
- 가로 스크롤이 발생하지 않아야 합니다.
- 입력 폼 사용 중 화면이 깨지지 않아야 합니다(`interactiveWidget: resizes-content`).

### 접근성 기준

- 클릭 가능한 요소는 키보드로 접근 가능하고 focus가 시각적으로 확인되어야 합니다(`focus-visible` 링).
- 폼 입력에 label을 연결하고 오류는 `aria-invalid`·`FieldError`(`role=alert`)로 노출합니다.
- 다이얼로그는 열릴 때 포커스를 내부로 이동합니다(온보딩은 콘텐츠에 초기 포커스).
- 로딩·상태 영역은 `role=status`와 `aria-label`로 안내합니다(스피너, 스트림 로딩).
- 색상만으로 상태를 구분하지 않습니다.

### 테마·서체

- 다크 모드는 `next-themes`로 OS 설정을 따릅니다(`defaultTheme: system`). 인앱 토글은 없습니다.
- 기본 서체는 Pretendard(`font-sans`), 서사 텍스트(프롤로그·대화)는 MaruBuri를 선택 적용합니다.

### 브라우저 지원

| 브라우저 | 지원 |
| --- | --- |
| 모바일 Chrome 최신 | 필수(e2e 기준) |
| 모바일 Safari 최신 | 필수 |
| 데스크톱 Chrome·Safari 최신 | 권장(모바일 셸 그대로 표시) |

## 3-17. 관측 연동(애널리틱스·에러)

이벤트 카탈로그·프로퍼티·식별자 정책·Sentry 수집 기준은 [`6-analytics.md`](./6-analytics.md)가 소유합니다. 이 섹션은 프론트엔드가 이벤트를 **어떻게 발화하는지**만 정의합니다.

### 애널리틱스 배선

- 초기화는 `AmplitudeProvider`에서 수행합니다. 자동 수집은 페이지뷰·세션만 켜고 UI 상호작용·폼은 끕니다. 세션 리플레이는 비활성입니다.
- 활성 조건은 `NODE_ENV === production`이고 API 키가 있을 때입니다. 그 외에는 전송하지 않고 콘솔 디버그만 남깁니다.
- 모든 수동 이벤트는 단일 진입점 `track()`을 통합니다. `track()`은 이벤트 이름에서 `screen_name`을 도출해 병합하고, 항상 Sentry breadcrumb를 남긴 뒤(비활성이어도) 활성 시 Amplitude로 전송합니다.

### 세 가지 발화 경로

| 경로 | 훅·수단 | 발화 시점 |
| --- | --- | --- |
| 화면 진입 | `useTrackOnView(name, props)` | 마운트 시 `*_viewed` 발화, 직렬화 props 변경 시 재발화 |
| 노출(impression) | `useImpression(...)` | 50% 이상 1000ms 노출 시 발화, 동일 키 30초 중복 억제 |
| 액션 | 핸들러 내 `track(...)` | 클릭·제출 등 |

### 식별자·에러 상관관계

- 초기화 후 Amplitude `device_id`를 Sentry user로 설정합니다.
- API 요청에 `X-Manyak-Device-Id`·`X-Manyak-Session-Id`를 주입해 서버 로그와 익명 식별을 잇습니다([§3-10](#3-10-api-연동-계약), [`6-analytics.md §6-6`](./6-analytics.md)).
- 프론트엔드 Sentry 수집 기준(복구 가능한 4xx 제외 등)은 [`6-analytics.md §6-6-4`](./6-analytics.md)를 따릅니다.

## 3-18. 테스트와 검수 기준

스펙이 테스트로 연결되도록 정의합니다. 이 앱은 이미 e2e 스펙에 US ID를 태깅합니다.

### e2e ↔ US 매핑

현재 e2e 스펙은 화면별로 조직되어 있고 US ID로 태깅됩니다. 스펙은 이 매핑의 허브 역할을 합니다.

| `stories/story-create` | 생성 퍼널 완주 → 채팅방 | US-3 |
| `chats/chat-list` | 채팅 목록·재개·삭제·빈 상태 | US-5-1·2·3·4 |

### Definition of Done

- 모든 P0 화면과 P0 흐름이 정상 동작해야 합니다.
- 화면별 로딩·빈 상태·에러 처리가 스펙대로 구현되어야 합니다.
- 게스트 서재 저장·재조회·삭제(낙관적·롤백)가 동작해야 합니다.
- 스토리 생성 퍼널이 완주 시 채팅방으로 진입하고, 완성 재시도가 스토리를 중복 생성하지 않아야 합니다.
- 채팅 스트리밍이 토큰 누적·완료 반영·실패 안내를 스펙대로 처리해야 합니다.
- 주요 폼 검증 규칙이 스펙과 일치해야 합니다.
- 핵심 e2e가 Mobile Chrome에서 통과해야 합니다.
- API 실패 시 사용자 친화 메시지가 표시되어야 합니다.

| `NEXT_PUBLIC_SENTRY_DSN` | 클라이언트 | 아니오 | 비우면 Sentry 미전송 |
| `NEXT_PUBLIC_SENTRY_FORCE_ENABLE` | 클라이언트 | 아니오 | 로컬에서 Sentry 연동 확인 시 `true` |

- Vite가 아니므로 `VITE_*` 규약을 사용하지 않습니다. 서버 전용 값은 접두사 없이, 클라이언트 노출 값은 `NEXT_PUBLIC_`으로 구분합니다.
- API 코드는 백엔드 OpenAPI 스펙(`/v3/api-docs`)에서 `pnpm api:generate`로 생성하며 `src/api/generated`는 직접 수정하지 않습니다.

### 활성화 게이팅

- Amplitude·Sentry는 프로덕션에서만 기본 전송합니다. 로컬에서는 강제 플래그로만 활성화합니다.

### 배포 검수 기준

- 프로덕션 빌드가 성공해야 합니다.
- `API_BASE_URL` 누락 시 프록시가 명확한 오류(500)를 반환해야 합니다.
- 배포 후 주요 라우트에 직접 접근해도 화면이 정상 표시되어야 합니다.

### 스펙-구현 간극 (반드시 확인)

문서와 코드가 다른 지점입니다. 스펙은 구현을 기준으로 작성했으며, 아래는 팀이 조정할 항목입니다.

| # | 간극 | 현황 | 방향 |
| --- | --- | --- | --- |
| G1 | 인증 | Google 로그인·`/me`·refresh·logout이 미사용 생성 코드 | 로그인 도입 시 [§3-15](#3-15-인증세션-현황과-향후) 갱신 |
| G2 | 체험 플레이·공개 흐름 | 배경 문서의 "3턴 후 공개 여부 질문 → 공개/비공개 등록"은 미구현. 퍼널은 생성 직후 채팅방 진입 | 후속 과제로 검토 |

| G5 | 스트리밍 타임아웃 | 채팅 스트림은 120초 클라이언트 타임아웃 미적용 | 장시간 무응답 대비 정책 검토 |
