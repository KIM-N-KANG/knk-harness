## A-001. 제작 진행을 Preferences DataStore에 저장

- 결정일: 원문 미기재 · 기록 확정 상태: Accepted
- 근거: [이관 원문 A:1627](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-3-android-app.md#L1627-L1634)
- **맥락:** 제작 진행은 화면 밖에서도 읽고 앱 재실행 이후 복원해야 했습니다.
- **결정:** 초기에는 Preferences DataStore의 단일 슬롯으로 저장했습니다.
- **이유:** 원문에 슬롯 하나는 키-값으로 충분했다고 기록되어 있습니다.
- **주요 영향:** 세부 도입일은 원문에 없으며 후속 Room 전환으로 대체됩니다.

## A-002. 로그인 필수 사용자 모델

- 결정일: 2026-08-03 · 기록 확정 상태: Accepted
- 근거: [이관 원문 A:34](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-3-android-app.md#L34-L59)
- **맥락:** 앱에도 웹의 게스트 우선 모델을 둘지 검토했습니다.
- **결정:** 앱은 로그인 후 사용하고 법적 문서만 로그인 전에 엽니다.
- **이유:** 웹이 게스트 유입을 담당하며 앱에 서재·사용량·이관·device_id 한도 처리를 중복 도입하는 범위를 줄입니다.
- **주요 영향:** 2026-08-22 재확인. 인증·회원 그래프를 구분하며 앱 단독 게스트 체험은 없습니다.

- **주요 영향:** 의존·소유 경계는 유지하되 구체 현재 규칙은 모듈 설계가 소유합니다.

- **주요 영향:** 중앙 종료 흐름과 저장소 참여 계약을 유지해야 합니다.

## A-006. Crashlytics로 앱 크래시 수집

- 결정일: 2026-08-22 · 기록 확정 상태: Accepted
- 근거: [이관 원문 A:269](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-3-android-app.md#L269-L286)

- **주요 영향:** API 24~29 ANR 공백을 수용하며 event-local request_id·release 수집·R8 매핑 업로드를 관리합니다.

- **결정:** 미저장 편집·저장본이나 진행만 존재·보존할 내용 없음의 세 경고로 구분합니다.
- **이유:** 실수로 닫았을 때 돌아올 기회와 잃는 대상에 대한 예측 가능성을 제공합니다.
- **주요 영향:** 저장본만 있는 경우 경고 없이 이탈하던 규칙을 대체합니다.

<a id="a-032"></a>

## A-032. 푸시 삭제와 수신자 검증을 분리

- 결정일: 2026-09-08 · 기록 확정 상태: Accepted
- 근거: [이관 원문 A:1363](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-3-android-app.md#L1363-L1374)
- **맥락:** 등록·삭제가 경합하고 세션 장벽 이후에는 필요한 재발급이 차단됩니다.
- **결정:** 등록기를 차단하고 합류한 뒤 세션 장벽 전에 제한 시간 안에서 삭제를 시도합니다.
- **이유:** 원격 삭제 성공만으로 이미 접수된 등록과 계정 격리를 보장할 수 없습니다.
- **주요 영향:** 이전 계정 표시·탭은 recipientId·세션 검증으로 차단하며 삭제 실패 잔존을 수용합니다.

## A-033. 알림 권한 요청은 메인 그래프 첫 진입

- **결정:** 회원 메인 그래프에 처음 진입할 때 권한을 요청합니다.
- **이유:** 요청 시점을 루트 한 곳에서 관리하는 초기 선택입니다.
- **주요 영향:** 허용률을 보고 후속 결정으로 변경할 수 있으나 기존 기록은 덮어쓰지 않습니다.

- **이유:** 토큰 삭제 여부만으로 계정 격리를 증명할 수 없기 때문입니다.
- **주요 영향:** recipientId 없는 메시지는 버리고 표시·탭 양쪽에서 검증합니다.

## A-035. 로그아웃 후 제작 데이터를 계정별 보존

- 결정일: 2026-09-08 · 기록 확정 상태: Accepted
- 대체 관계: [A-014](#a-014)의 로그아웃 삭제 범위 부분 대체
- 공통 결정 구체화: [C-004](./3-1-1-client-adr.md#c-004)
- 근거: [이관 원문 A:1610](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-3-android-app.md#L1610-L1614)
- **맥락:** 같은 회원이 재로그인하면 완성 알림은 오지만 진행 카드가 사라지는 문제가 있었습니다.
- **결정:** 두 제작 테이블을 로그아웃 삭제에서 제외하고 ownerId로 격리합니다.
- **이유:** 같은 계정의 진행 복구와 다른 계정의 데이터 비노출을 함께 보장하기 위해서입니다.
- **주요 영향:** DB v3 소유자 이전과 세션 장벽이 필요합니다. 편집 슬롯은 기기당 한 행이고 탈퇴 회원 행의 물리 삭제는 별도 과제입니다.

## A-036. 완성 요청을 편집 행에서 분리하고 보존 이전

- 결정일: 2026-09-08 · 기록 확정 상태: Accepted
- 대체 관계: [A-014](#a-014)의 완성 저장과 마이그레이션 방식 부분 대체
- 근거: [이관 원문 A:1575](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-3-android-app.md#L1575-L1603)
- **맥락:** 단일 행은 여러 완성 요청과 새 초안을 함께 표현할 수 없습니다.

- **이유:** 편집·요청 생명주기를 분리하고 이미 제출한 요청과 입력을 잃지 않기 위해서입니다.

## A-037. 보이는 완성 카드만 주기 조회

- 결정일: 2026-09-09 · 기록 확정 상태: Accepted
- 공통 결정 구체화: [C-004](./3-1-1-client-adr.md#c-004)
- 근거: [이관 원문 A:1604](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/product-specs/3-3-android-app.md#L1604-L1610)
- **맥락:** 완성이 끝나도 수동 새로고침 전에는 카드가 계속 회전할 수 있었습니다.
- **결정:** 완성 중 카드가 보이고 STARTED인 동안만 5초 주기로 조회합니다.

## A-038. 기능 단위 모듈과 내부 패키지 계층

- 결정일: 2026-09-05 · 상태: Accepted
- **맥락:** 중앙 core에 업무 소유권과 계층별 Gradle 모듈이 모여 있었습니다.
- **선택:** 기능을 최상위 모듈로, entity/domain/data/presentation을 내부 패키지로 둡니다. 공유 신고는 report가 소유합니다.
- **이유:** common에 신고를 두면 network/designsystem 역참조가 생기고 화면별 복제는 제출·분석 규칙을 중복시킵니다.
- **주요 영향:** 계층의 컴파일 격리 대신 PSI 경계 검사·리뷰가 필요합니다. 이전 core 배치 규칙을 대체하며 API·저장 형식 변경은 포함하지 않습니다.
- 근거: [이관 전 원문](https://github.com/KIM-N-KANG/knk-harness/blob/2d77abce078b75e168d8f924e3759e3bb624515a/docs/planning/android-module-architecture.md#L11-L23)
