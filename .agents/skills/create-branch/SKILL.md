# 브랜치 생성

## 범위와 이름

- 브랜치명은 `{tag}/{JIRA_KEY}-{title-slug}` 형식입니다(예: `feat/KNK-12-add-google-login`). Jira 키는 대문자, 제목은 짧은 영어 kebab-case를 사용합니다.
- Jira 키는 사용자 명시 → 현재 작업에 대해 대화에서 확정된 키 → 현재 브랜치 순서로 찾습니다. 사용자가 명시적으로 키를 교체했다면 새 키를 따릅니다. 키가 없거나 충돌이 해소되지 않았거나 작업과 무관한 키로 확인되면 필요한 키만 질문합니다. 임의의 키를 만들지 않습니다.
- 사용자가 지정한 태그를 우선하고, 나머지는 작업 목적에 따라 아래에서 선택합니다. 영어 표현이나 태그 선택만을 이유로 멈추지 않습니다. 작업 의미 자체가 불분명할 때만 질문합니다.

| 작업 | 태그 |
| --- | --- |
| 새 기능 | `feat` |
| 버그 수정 | `fix` |
| 문서 수정 | `docs` |
| UI·스타일·디자인 | `design` |
| 배포·CI/CD | `cicd` |
| 동작을 유지하는 구조 개선 | `refactor` |
| 설정·의존성·유지보수 | `chore` |

## 작업 흐름

1. **대상 서비스 저장소**에서 `git rev-parse --show-toplevel`과 `git status --short --branch`를 확인합니다. 스크립트는 파일이 놓인 하네스가 아니라 현재 작업 디렉터리의 저장소를 변경합니다.
2. Jira 키와 작업 범위를 확인합니다. Jira 도구가 있으면 요약·현재 상태·유형을 조회합니다. 이슈가 없으면 키를 확인하고, 접근 불가라면 그 사실을 알린 뒤 대화에서 확정된 키와 작업 내용이 충분한 경우 계속합니다.
3. 브랜치명을 미리봅니다. 미리보기만 요청했다면 여기서 마칩니다.
4. 추적 파일·미추적 파일을 포함한 기존 변경사항을 보존합니다. 변경을 새 브랜치로 가져가겠다는 사용자 의사가 이미 확인된 경우에만 `--allow-dirty`를 사용합니다. 임의로 stash·reset·discard·clean하거나 덮어쓰지 않습니다.
5. 새 브랜치는 기본적으로 **fetch한 `origin/dev`**에서 만듭니다. fetch가 실패하면 오래된 로컬 `dev`로 자동 대체하지 않습니다. 사용자가 다른 기준이나 오프라인 작업을 지정한 경우에는 확인한 Git ref를 `--base`로 전달합니다.
6. 사용자가 기존 브랜치를 쓰려는 경우 `--checkout-existing`을 사용합니다. 로컬 대상 브랜치가 있으면 기준 브랜치 조회나 fetch 없이 전환합니다. 이 옵션은 브랜치가 없으면 새로 생성하므로, 기존 브랜치만 전환하는 요청은 존재 여부를 먼저 확인합니다. 체크아웃 충돌을 강제로 해결하지 않습니다.
7. 생성·체크아웃 성공 후 `git branch --show-current`, `git status --short`와 스크립트 결과를 확인합니다. 실패하면 Jira 상태를 변경하지 않습니다.
8. Jira 상태 전환이 요청 범위에 포함되면 이슈를 다시 조회합니다. 현재 상태가 `해야 할 일`일 때만 전환 목록에서 **목표 상태가 `진행 중`인 전환 ID**를 찾아 실행하고 결과를 재조회합니다. 이미 진행 중이거나 다른 상태이면 그대로 둡니다. 브랜치만 요청하면서 Jira 변경을 제외했다면 전환하지 않습니다.
9. Jira 접근·전환 실패 시 이유를 보고하고, 생성한 브랜치를 되돌리거나 삭제하지 않습니다.

## 실행 예시

아래 예시는 형제 서비스 저장소 루트에서 실행합니다. 하네스 자체를 작업할 때만 경로를 `.agents/skills/create-branch/scripts/create_branch.py`로 바꿉니다. `.claude/skills/`는 호환 링크이며 정본은 `.agents/skills/`입니다.

```bash
python3 ../knk-harness/.agents/skills/create-branch/scripts/create_branch.py --ticket KNK-12 --tag feat --title "Add Google Login" --json
```

- 새 브랜치 생성: 위 명령에 `--create`를 추가합니다. 기본 fetch는 `origin/dev`만 갱신하며 로컬 `dev`는 변경하지 않습니다. 새 브랜치가 기준 브랜치를 upstream으로 자동 추적하지 않도록 생성합니다.
- 기존 브랜치 전환: `--create --checkout-existing`을 추가합니다.
- 명시적으로 선택한 로컬 기준: `--create --base dev`처럼 지정합니다. `--base`는 기존 ref를 그대로 사용하며 fetch하지 않습니다. 원격 ref를 명시했다면 필요한 fetch를 먼저 수행합니다.
- 기존 변경을 가져가기로 확인된 경우에만 `--allow-dirty`를 추가합니다.

이 스킬은 브랜치 준비와 Jira 작업 시작까지 수행합니다. 커밋·push·PR 생성·릴리스는 해당 요청과 전용 절차를 따릅니다.

## 검증과 보고

스크립트를 수정했다면 하네스 루트에서 다음 회귀 검증을 실행합니다. 임시 저장소와 로컬 원격만 사용합니다.

```bash
python3 -m unittest discover -s .agents/skills/create-branch/tests -v
```

완료 시 브랜치·Jira 키·실제 분기 기준, Jira 전환 결과, 남은 변경사항을 간결하게 보고합니다. 미리보기나 기존 브랜치 전환은 새 분기 기준을 확인한 것처럼 보고하지 않습니다.
